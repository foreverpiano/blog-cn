Prompt Engineering（也称为 In-Context Prompting）是指如何与大型语言模型（LLM）进行沟通，以引导其行为达到预期结果，而无需更新模型权重的方法。它是一门实证科学，不同提示工程方法在不同模型上的效果差异很大，因此需要大量实验和启发式经验。

本文仅关注自回归语言模型的提示工程，不涉及完形填空测试、图像生成或多模态模型。其核心目标是实现对齐（alignment）和模型可控性（model steerability）。可参考我之前写的。可控神经文本生成

[个人辣评] 我认为有些提示工程论文并不值得写成 8 页长文，因为那些技巧一两句话就能讲清楚，剩下的主要都是基准测试。一个易用且共享的基准测试基础设施对社区会更有价值。迭代式提示或外部工具调用并不容易搭建起来，让整个研究社区统一采用也绝非易事。

基础提示#

零样本（Zero-shot）和少样本（Few-shot）学习是提示模型最基础的两种方法，由众多 LLM 论文率先提出，并常用于评估 LLM 的性能。

零样本#

零样本学习就是直接将任务文本输入模型并要求其给出结果。

少样本#

少样本学习会在提示中提供一组高质量的示范，每个示范都包含输入和期望的输出。由于模型首先看到优质示例，它能更好地理解人类的意图和判断答案优劣的标准。因此，少样本学习通常比零样本取得更好的性能，但代价是消耗更多 token，当输入输出文本较长时还可能达到上下文长度上限。

Text: (lawrence bounces) all over the stage, dancing, running, sweating, mopping his face and generally displaying the wacky talent that brought him fame in the first place.
Sentiment: positive

Text: despite all evidence to the contrary, this clunker has somehow managed to pose as an actual feature movie, the kind that charges full admission and gets hyped on tv and purports to amuse small children and ostensible adults.
Sentiment: negative

Text: for the first time in years, de niro digs deep emotionally, perhaps because he's been stirred by the powerful work of his co-stars.
Sentiment: positive

Sentiment:

许多研究探讨了如何构建上下文示例以最大化性能，发现提示格式、训练示例的选择以及示例的顺序都可能导致性能出现巨大差异——从接近随机猜测到接近当前最优（SoTA）。

Zhao et al. (2021) 研究了少样本分类的情况，并提出 LLM（他们在实验中使用 GPT-3）的几种偏差导致了这种高方差：(1) 当示例中标签分布不均衡时，会出现多数标签偏差（Majority label bias）；(2) 近期偏差（Recency bias）指模型倾向于重复最后一个标签；(3) 常见 token 偏差（Common token bias）指 LLM 更倾向于生成常见 token 而非稀有 token。为了克服这些偏差，他们提出了一种方法，在输入为 N/A 时将模型输出的标签概率校准为均匀分布。

示例选择技巧#

  • 使用嵌入空间中的 k-最近邻聚类，选择与测试样本语义相似的示例（Liu et al., 2021）
  • 为了选择多样且具有代表性的示例集，Su et al. (2022) 提出了一种基于图的方法：(1) 首先基于样本间的嵌入余弦相似度（例如使用 SBERT 或 其他 embedding 模型）构建有向图 G=(V, E)，每个节点指向其 k 个最近邻居；(2) 从已选择的样本集 \mathcal{L}=\emptyset 和剩余样本集 \mathcal{U} 开始，每个样本 u \in \mathcal{U} 通过 __MATHBLOCK_2__ 进行打分，使得当 v 的许多邻居已被选中时 s(v) 较低，从而鼓励选择多样化的样本。
  • Rubin et al. (2022) 提出通过针对特定训练数据集的来训练嵌入，用于上下文学习样本选择。对于每个训练对 (x, y)，一个示例 e_i（格式化的输入-输出对）的质量可由语言模型赋予的条件概率衡量：\text{score}(e_i) = P_\text{LM}(y \mid e_i, x)。我们可以为每个训练对找出得分最高 k 和最低 k 的其他示例作为正负候选集，并用于对比学习。
  • 部分研究者尝试使用强化学习简史（长文）进行样本选择。（Zhang et al. 2022）
  • 受基于不确定性的启发，Diao et al. (2023) 建议找出在多次采样中存在高分歧或高熵的示例，然后对这些示例进行标注，用于少样本提示。对比表示学习数据不足时的学习（二）：主动学习

示例顺序技巧#

  • 一般建议是保持示例选择具有多样性、与测试样本相关，并且采用随机顺序，以避免多数标签偏差和近期偏差。
  • 增大模型规模或增加更多训练示例并不能减少上下文示例不同排列顺序之间的方差。相同的顺序可能对某个模型效果很好，对另一个模型却很差。当验证集有限时，应选择不会导致模型产生极不平衡预测或过于自信的顺序。（Lu et al. 2022）

指令提示#

在提示中给出少样本示例的目的是向模型解释我们的意图；换句话说，就是以示范的形式向模型描述任务指令。然而，少样本在 token 用量上较为昂贵，而且受限于上下文长度会限制输入长度。那么，为什么不直接给出指令呢？

指令型语言模型（例如 InstructGPT、natural instruction）使用高质量的（任务指令、输入、真实输出）三元组对预训练模型进行微调，使其更好地理解用户意图并遵循指令。可控神经文本生成（基于人类反馈的强化学习）是一种常用方法。这种指令跟随风格的微调能让模型与人类意图更好地对齐，并大幅降低沟通成本。

与指令模型交互时，我们应当详细描述任务要求，力求具体和精确，避免说“不要做什么”，而是明确指出要做什么。

Please label the sentiment towards the movie of the given movie review. The sentiment label should be "positive" or "negative". 
Text: i'll bet the video game is a lot more fun than the film. 
Sentiment:

说明期望的受众是另一种聪明的指令方式。

  • 例如，要生成给儿童的教育材料，
Describe what is quantum physics to a 6-year-old.
  • 以及生成安全内容，
... in language that is safe for work.

上下文指令学习（Ye et al. 2023) 将少样本学习与指令提示相结合。它在提示中加入来自不同任务的多个示范示例，每个示范包含指令、任务输入和输出。注意他们的实验仅针对分类任务，且指令提示中包含了所有标签选项。

Definition: Determine the speaker of the dialogue, "agent" or "customer".
Input: I have successfully booked your tickets.
Ouput: agent

Definition: Determine which category the question asks for, "Quantity" or "Location".
Input: What's the oldest building in US?
Ouput: Location

自洽性采样#

自洽性采样（Wang et al. 2022a）是指使用温度大于 0 的设置采样多个输出，然后从这些候选结果中选出最好的一个。选择最佳候选的标准因任务而异。一种通用方案是采用多数投票。对于容易验证的任务（如带有单元测试的编程问题），我们可以直接通过解释器运行并用单元测试验证正确性。

思维链 (CoT)#

思维链（Chain-of-Thought，CoT）提示（Wei et al. 2022）会生成一系列简短句子，按步骤描述推理逻辑（称为推理链或 rationale），最终得出答案。CoT 的优势在复杂推理任务上更为明显，尤其在使用大型模型（例如参数超过 500 亿）时。简单任务从 CoT 提示中获得的收益相对较小。

CoT 提示的类型#

CoT 提示主要有两种类型：

  • 少样本 CoT。它会向模型提供少量示范，每个示范包含人工编写（或模型生成）的高质量推理链。

（以下所有数学推理示例均来自 GSM8k）

Answer: It takes Tom 30*4 = <<30*4=120>>120 minutes to climb the hill.
It takes Tom 120/60 = <<120/60=2>>2 hours to climb the hill.
So the answer is 2.
===

The total cost of the socks and the shoes is $19 + $92 = $<<19+92=111>>111.
Jack need $111 - $40 = $<<111-40=71>>71 more.
So the answer is 71.

  • 零样本 CoT。使用类似“Let’s think step by step”的自然语言陈述，明确鼓励模型先生成推理链，然后再用“Therefore, the answer is”来引导模型给出答案（Kojima et al. 2022）。或者使用类似的“Let’s work this out in a step by step to be sure we have the right answer”（Zhou et al. 2022）。

技巧与扩展#

  • 自洽性采样可以通过采样多个多样化的答案并进行多数投票来提升推理准确率。（Wang et al. 2022a）
  • 另一种集成学习方法是改变示例顺序，或使用模型生成的 rationale 替代人工编写的 rationale，以在多次采样中引入随机性。然后通过多数投票聚合模型输出得到最终答案。（Wang et al. 2022b）
  • 如果训练示例只关联正确答案（易于验证！）而没有 rationale，可以采用 STaR（Self-Taught Reasoner；Zelikman et al. 2022）方法：(1) 让 LLM 生成推理链，只保留那些能得出正确答案的；(2) 使用生成的 rationale 对模型进行微调，并重复该过程直至收敛。注意较高的温度更容易生成答案正确但 rationale 错误的样本。如果训练示例没有真实答案，可以考虑使用多数投票作为“正确”答案。
  • 包含更高推理复杂度的示范提示通常能获得更好性能，这里复杂度以推理链中的推理步骤数量衡量。在分隔推理步骤时，使用换行符 \n 比使用“step i.”、句号 . 或分号 ; 效果更好。（Fu et al. 2023）
  • 基于复杂度的自洽性是指仅在所有生成结果中最复杂的 k 条推理链上进行多数投票，从而显式地偏好复杂链。（Fu et al. 2023）
  • 随后，Shum et al. (2023) 发现，在他们的实验中，仅使用复杂示例的 CoT 提示能提高复杂问题的准确率，但在简单问题上表现较差；该现象在 GSM8k 上得到了验证。
  • 将 “Q:” 改为 “Question:” 被发现是有帮助的。（Fu et al. 2023）
  • Ye & Durrett (2022) 发现，对于涉及文本推理的 NLP 任务（即 QA 和 NLI），在提示中加入解释的收益较小到中等，且效果随模型而异。他们观察到解释更可能是非事实性的而非不一致的（即解释是否蕴含预测）。非事实性解释最可能导致错误预测。
  • Self-Ask（Press et al. 2022）是一种反复提示模型提出后续问题、从而迭代构建思考过程的方法。后续问题可通过搜索引擎结果来回答。类似地，IRCoT（Interleaving Retrieval CoT；Trivedi et al. 2022）和 ReAct（Reason + Act；Yao et al. 2023）将迭代式 CoT 提示与对 Wikipedia API 的查询相结合，搜索相关实体和内容并将其添加回上下文。
  • Tree of Thoughts（Yao et al. 2023）对 CoT 进行了扩展，在每一步探索多种推理可能性。它首先将问题分解为多个思考步骤，并在每个步骤生成多个想法，从而形成树状结构。搜索过程可以是 BFS 或 DFS，每个状态由分类器（通过提示）或多数投票进行评估。

自动提示设计#

Prompt 是一串前缀 token，用于在给定输入时提高得到期望输出的概率。因此我们可以将其视为可训练参数，并在嵌入空间中通过梯度下降直接，例如 AutoPrompt（Shin et al., 2020）、Prefix-Tuning（Li & Liang (2021)）、P-tuning（Liu et al. 2021）和 Prompt-Tuning（Lester et al. 2021）。对它们有很好的总结。从 AutoPrompt 到 Prompt-Tuning 的趋势是设置逐渐简化。可控神经文本生成可控神经文本生成

APE（Automatic Prompt Engineer；Zhou et al. 2022）是一种在模型生成的指令候选池中进行搜索的方法，然后根据选定的评分函数过滤候选集，最终选出得分最高的候选。

  1. 提示 LLM 基于少量输入-输出对示范生成指令候选。例如 {{Given desired input-output pairs}}\n\nThe instruction is.
  2. 给定一个包含 \mathcal{D}_\text{train} = \{(x, y)\} 的数据集，我们希望找到一条指令 \rho 使得 \rho^* = \arg\max_\rho \mathbb{E}_{(x, y) \in \mathcal{D}_\text{train}} [f(\rho, x, y)]，其中 f(.) 是每个样本的评分函数，例如执行准确率 \mathbb{1}[\text{LM}(.\vert \rho, x)=y] 或对数概率：p_\text{LM}(y \mid \rho, x)。
  3. 使用迭代的蒙特卡洛搜索方法，通过类似“Generate a variation of the following instruction while keeping the semantic meaning.\n\nInput: ...\n\nOutput:...”的提示来生成语义相似的变体，从而改进最佳候选。

为了自动构建思维链提示，Shum et al. (2023) 提出了一种三步的 augment-prune-select 方法：

  1. Augment：使用少样本或零样本 CoT 提示，针对问题生成多个伪思维链；
  2. Prune：根据生成的答案是否匹配真实答案对伪思维链进行剪枝。
  3. Select：采用方差减少的策略梯度方法，学习所选示例的概率分布，将示例的概率分布视为策略，将验证集准确率视为奖励。

Zhang et al. (2023) 则采用聚类技术对问题进行采样，然后生成思维链。他们观察到 LLM 容易犯某些类型的错误。同一类型的错误在嵌入空间中往往相似，因此会被聚到一起。通过仅从频繁错误聚类中采样一个或少数几个示例，我们可以避免出现过多同一错误类型的错误示范，从而收集到多样化的示例集。

  1. 问题聚类：对问题进行嵌入，然后运行 k-means 聚类。
  2. 示范选择：从每个聚类中选择一组有代表性的问题，即每个聚类选择一个示范。每个聚类内的样本按到聚类中心的距离排序，距离中心更近的优先选择。
  3. 推理链生成：对选出的问题使用零样本 CoT 生成推理链，并构建少样本提示用于推理。

检索#

我们经常需要完成那些要求模型预训练截止时间之后最新知识或内部/私有知识库的任务。在这种情况下，如果不在提示中明确提供上下文，模型将无法知晓。许多方法都依赖于先在知识库中进行检索，再将检索到的内容作为提示的一部分。该过程的准确率取决于检索和生成两个步骤的质量。如何构建开放域问答系统？

Lazaridou et al. (2022) 研究了如何使用 Google Search 进行文档检索以增强 LLM。给定一个问题 q，从 Google 返回的 20 个 URL 中提取干净文本，得到一组文档。由于这些文档较长，每个文档被拆分为每段 6 句话的段落 \{p\}。段落通过证据段落与查询之间的 TF-IDF 余弦相似度进行排序。只有最相关的段落会被放入提示中以生成答案 a。

对于闭卷问答（closed-book QA），每个示范按以下方式格式化来构建少样本提示。将问题与证据交换（使问题和答案距离更远）被发现会在所有数据集上一致地导致更差的结果。

Evidence: ...
Question: ...
Answer: ...

答案概率通过三种方式计算：

  1. 如何构建开放域问答系统？ 风格，p(a_i \mid q) = \sum_{i=1}^n p_\text{tf-idf} (p_i \mid q) \cdot p_\text{LM}(a_i \mid q, p_i)，其中 p_\text{tf-idf} (p_i \mid q) 是 TF-IDF 段落与问题表示之间归一化的余弦相似度。
  2. 噪声信道推理，p(a_i\mid q) = \frac{p_\text{LM}(q \mid a_i, p_i) \cdot p_\text{LM}(a_i \mid p_i)}{p_\text{LM}(q \mid p_i)}
  3. Product-of-Experts (PoE)，将上述所有概率以及 p_\text{LM}(p_i \mid q) 组合起来。

根据他们在生成和分类任务上的实验，在三种答案重排序分数中——PoE > 噪声信道 > RAG。在单个概率中，p_\text{LM}(a \mid q, p_i) 和 p_\text{LM}(q \mid p_i, a) 被认为最有信息量。p_\text{LM}(q \mid p_i, a) 捕捉了在给定证据段落和答案的情况下，问题被语言模型解释得有多好，可靠地用于对答案候选进行重排序。

在 SituatedQA 数据集上针对不同日期的 grounding 问题的观察发现，尽管 LLM（预训练截止年份为 2020 年）可以通过 Google Search 获得最新信息，但它在 2020 年之后的问题上的表现仍然远差于 2020 年之前的问题。这表明上下文信息与模型内部知识之间存在某种差异或冲突的参数化知识。

有趣的是，即使仅使用“内部检索”（即在回答问题前先生成关于某个主题的知识）也被发现是有益的（Liu et al. 2022）。首先我们可以使用以下模板提取知识：

Generate some knowledge about the input. Examples:

Input: What type of water formation is formed by clouds?
Knowledge: Clouds are made of water vapor.

Input: {question}
Knowledge:

然后使用模型生成的知识，进一步提示 LM 得到答案。

编程语言#

PAL（Program-aided language models；Gao et al. 2022）和 PoT（Program of Thoughts prompting；Chen et al. 2022）都要求 LLM 生成编程语言语句来解决自然语言推理问题，从而将求解步骤卸载到 Python 解释器等运行时。这种设置将复杂计算与推理解耦。它依赖于编码能力足够强的语言模型。

外部 API#

TALM（Tool Augmented Language Models；Parisi et al. 2022）是一种通过文本到文本 API 调用进行增强的语言模型。LM 被引导根据任务输入文本生成 |tool-call 和工具输入文本，以构建 API 调用请求。当出现 |result 时，调用指定的工具 API，并将返回的结果追加到文本序列中。最终输出在 |output token 之后生成。

TALM 采用自博弈（self-play）方法迭代地扩充工具使用示例数据集，并据此对 LM 进行微调。这种自博弈定义为模型与工具 API 进行交互，根据新添加的工具 API 是否能改进模型输出，迭代地扩展数据集。Toolformer 也采用了相同思路，下文会更详细描述。该流程大致模拟了一个强化学习过程，其中 LM 是策略网络，通过带二元奖励信号的策略梯度进行训练。

Toolformer（Schick et al. 2023）是一种能够通过简单 API 使用外部工具的语言模型，它以自监督的方式构建，每个 API 只需少量示范。Toolformer 的工具箱包括：

  • 计算器，帮助 LM 弥补精确数学能力的不足；
  • 问答系统，帮助处理不忠实内容和幻觉；
  • 搜索引擎，提供预训练截止时间之后的最新信息；
  • 翻译系统，提升低资源语言上的性能；
  • 日历，让 LM 感知时间进展。

Toolformer 的训练流程如下：

  1. Prompting to annotate potential API calls. Ask a pre-trained LM to annotate a dataset via few-shot learning with API call usage examples. Formatting example: How dataset is annotated to do API calls.(Image source: Schick et al. 2023).
- Each API call is represented as a tuple of (API name, corresponding input), $c=(a_c, i_c)$ and its corresponding result is denoted as $r$. The API call sequences with and without results are labeled as follows, respectively:

    <div>
    $$
    \begin{aligned}
    e(c) &= \langle\texttt{API}\rangle a_c(i_c) \langle\texttt{/API}\rangle \\
    e(c, r) &= \langle\texttt{API}\rangle a_c(i_c) \to r \langle\texttt{/API}\rangle
    \end{aligned}
    $$
    </div>

- Sample API calls based on the probabilities $p_\text{LM}(\langle\texttt{API}\rangle \mid \text{prompt}(\mathbf{x}), \mathbf{x}_{1:i})$ and select top $k$ candidate positions for doing API calls at position $i$ if the probability is larger than a threshold.

- Then we sample potential API calls from the LM given the sequence $[\text{prompt}(\mathbf{x}), x_1, \dots, x_{i-1}, \langle\texttt{API}\rangle]$ as prefix and $\langle\texttt{/API}\rangle$ as suffix.
  1. Filter annotations based on whether API calls help model predict future tokens. Use a self-supervised loss to decide which API calls are actually helpful. Execute each API call c_i to get corresponding result r_i. Compute weighted cross entropy loss for the LM over tokens x_i, \dots, x_n when the model is prefixed with the prompt. Two versions are computed, one with API result and the other with empty sequence \varepsilon. __MATHBLOCK_36__ Only API calls with L^-_i - L^+_i larger than a threshold are kept, meaning that adding this API call and its results help the model predict future tokens.
  2. Fine-tune LM on this annotated dataset. The new training sequences are constructed as \mathbf{x}^* = x_{1:i-1}, e(c_i, r_i), x_{i:n} . The training data is a combination of the original dataset (e.g. a subset of CCNet, as in the paper) and its augmented version.

在推理时，解码会一直运行直到模型生成“\to ” token，表示它接下来期待来自 API 调用的响应。

Toolformer 目前还不支持链式工具使用（即把一个工具的输出作为另一个工具的输入）或交互式使用（即在人工选择后采用 API 响应）。两者都是未来扩展模型的有趣方向。
