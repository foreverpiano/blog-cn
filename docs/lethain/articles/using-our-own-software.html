使用我们自己的软件

2008-02-04 · 阅读原文

昨晚我迷迷糊糊快要睡着时，满脑子都是最近对 LifeFlow 所做的修改，同时也在思考使用自己开发的软件给我带来了多大的快乐。使用一款软件并且清楚地知道它背后每一处具体在做什么，这件事本身就让我感到格外有趣。当你坐在那里想着：“当我把光标从这个文本框移开时，它会在后台发起一个 XMLHttpRequest 来保存新的修改。”或者当你注意到标签页加载得特别慢，然后不由自主地喃喃自语，说终于要抽时间去把那个糟糕透顶的实现改掉。

是的，我知道随意重写那些其实不需要重写的软件有多么糟糕。但那种清楚知道自己要做什么就能轻松添加新功能，或者更高效地适配个人工作流的感觉，确实让使用软件这件事变得更加愉快。

为了结束这篇内容，让我们简单地浏览一下我编写过、并且目前还在经常使用的那些软件。按照时间顺序来：

DulyNoted

在我本科毕业那年的寒假，我决定要认真地用 Common Lisp 写一个真正有用的程序。当时作为学生，我花大量时间记笔记，于是 DulyNoted 就在接下来的一个月里逐渐成型了。

我使用 Steel Bank Common Lisp 和 Ltk 图形工具包（一个 Lisp 对 Wish/tk 的接口）来开发的。

它是一个足够简单却相当实用的应用。所有内容都基于一个简单的树形结构。每个节点都可以关联文本，并且拥有任意数量的子节点。它使用简单的链表来保存树状结构。每个节点会保存其原始文本、子节点以及格式化数据。每次加载时，它都会将格式化数据应用到原始文本上。（文本格式化部分无疑是最具挑战性的，我觉得很大程度上是因为我对 tk 文本部件存在一个关键的误解，花了很长时间才终于搞明白。）

它有一个简单的小型模块系统来扩展功能，其中一个例子是我写的“导出为 HTML”模块，它能将节点结构导出为相互链接的网页，并完整保留所有格式。

我现在已经不怎么使用这个小项目了，但我在大学最后一个学期确实用它来记笔记。它是我写的第一个功能足够完整、可以实际使用的程序，因此在我心里有着特殊的位置。

未命名的日语词典

我编写的第二个至今仍在使用（而且是每天都在用）的程序，是我的日语词典应用。我曾暂时给它取名为 Nihongo Flow，后来觉得这个名字可能有点蠢过头了。不过，“Unnamed Japanese Dictionary”这个名字也实在没有多大吸引力。

我使用 PyObjC 在 OSX 10.4 上开发的。数据库则是从 XML 解析而来的 JMDict 词典文件，并存入 SQLite3 数据库。这是我第一个 PyObjC 项目，所以代码经历了好几轮迭代才变得条理清晰。我可能需要在继续开发之前重写大部分代码（不过我目前已经暂时放弃 PyObjC 了，因为那里的很多工作似乎都和 OSX 10.5 紧密绑定，而 10.5 已经默认包含了 PyObjC）。

我是在本科毕业那年春季学期，用两三周的时间写完的。

它支持英日和日英查询。它不会询问你想用哪种语言进行查找，而是通过输入文本来推断（好吧，“推断”这个词在这里可能显得有点太高雅了）：如果是平假名、片假名或汉字，就进行日→英查询；如果是罗马字母，就进行英→日查询。如果我还在积极开发它的话，我会让它对输入的罗马字母先尝试搜索罗马字词汇，然后同时在英语和日语中进行搜索。

它还支持闪卡、词汇表、测试以及其他一些功能。是一个功能相当完整的程序，原本的目标是作为自学日语的独立学习工具。正如我之前提到的，因为我现在生活在日本，所以每天都在使用它，而且它是一本很可靠的词典。

LifeFlow

另一个我经常使用的程序，也是我写过的所有软件中用得最多的，就是 LifeFlow——也就是我这个博客所使用的博客软件。我就不多说了，因为我似乎已经花了不少时间谈论它了。

它在整个生命周期中成长了许多，目前已经是一个功能相当完善的博客发布工具。随着 LifeFlow Editor 即将完成，它将会成为一款让我相当满意的软件。

前端采用极简主义设计，并且不需要任何 JavaScript、Flash 等技术。后端则对无障碍访问比较随意，大量使用了 Ajax 和 jQuery。

使用你自己的软件

你现在正在使用的软件中，有哪些是你自己写的？你认为使用自己写的软件只是一种自我满足的行为，还是有时候是一件合理且值得去做的事？我很想听听其他人的看法。
