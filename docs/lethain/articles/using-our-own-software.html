使用我们自己开发的软件

2008-02-04 · 阅读原文

昨晚我迷迷糊糊快要睡着时，心里一直想着最近对 LifeFlow 所做的修改，同时感慨着使用自己写的软件能带来多大的乐趣。使用一款软件却清楚地知道它背后每一处究竟在做什么，这件事本身就让我觉得特别享受。你坐在那里，心里想着：“当我把光标从这个文本框移开时，它正在后台发起一个 XMLHttpRequest 来保存新的修改。”当你发现标签页面加载得特别慢时，会不自觉地喃喃自语，说终于要抽时间把这个糟糕透顶的实现修复一下。

是的，我知道重写那些其实并不需要重写的软件有多么糟糕，但那种清楚知道该如何动手去添加自己想要的新功能——或者更高效地支持个人工作流——的灵活性，确实让使用软件这件事变得更加愉悦。

为了结束这篇日记，让我们简单地按时间顺序，导览一下我编写过且经常使用的那些软件：

DulyNoted

在我本科最后一年寒假时，我决定要认真地用 Common Lisp 写一个真正有用的程序。当时作为学生，我花大量时间记笔记，于是 DulyNoted 在接下来的一个月里逐渐成形。

我使用 Steel Bank Common Lisp 和 Ltk 图形工具包（一个 Lisp 对 Wish/tk 的接口）来开发它。

这是一个足够简单却相当实用的应用。一切都基于一个简单的树状结构。每个节点都可以关联文本，并拥有任意数量的子节点。它使用简单的链表来保存树状结构。每个节点会保存其原始文本、子节点以及格式化数据，每次加载时都会将格式化数据应用到原始文本上。（文本格式化部分无疑是最具挑战性的，我觉得很大程度上是因为我对 tk 文本部件存在一个关键的误解，花了很长时间才终于弄明白。）

它有一个简单的小型模块系统来扩展额外功能，例如我编写的一个不错的“导出为 HTML”模块，能将节点结构导出为相互链接的网页，且所有格式都完好保留。

我现在已经不怎么使用这个小项目了，但它曾伴我度过大学最后一个学期的笔记记录。它是我写的第一个功能足够完善、真正能拿来使用的程序，因此在我心中占有特别温暖的一席之地。

未命名的日语词典

我写的第二个至今仍在使用的程序（而且是每天都在用）是我的日语词典应用。我曾暂时给它取名为 Nihongo Flow，后来觉得这个名字可能有点过于傻气，自己难以接受。不过，“Unnamed Japanese Dictionary”听起来也实在不像个吸引人购买的名字。

我在 OSX 10.4 上使用 PyObjC 开发的它。数据库则是从 JMDict 词典的 XML 文件解析后存入 SQLite3 数据库的。这是我的第一个 PyObjC 项目，因此代码经历了几次重构才变得条理清晰。我可能想在继续开发之前先把大部分代码重写一遍（不过我目前已经暂时离开 PyObjC 这趟车了，因为那里的大部分工作似乎都与默认包含 PyObjC 的 OSX 10.5 紧密绑定）。

我是在本科最后一年春季学期，用两三个星期的时间写完的。

它支持英日和日英双向查词。它不会询问你想用哪种语言进行查找，而是通过输入文本来推断（这么说可能有点太装了）。如果输入的是平假名、片假名或汉字，就搜索日→英；如果是罗马字母，就搜索英→日。如果我还在积极开发的话，我会让它在收到罗马字母时，先判断是否为罗马字读音，然后同时在英文和日文里进行搜索。

它还支持闪卡、词汇列表、测试以及其他一些功能。算是一个相当完善的功能齐全的程序，原本的目标是作为自学日语人士的独立学习工具。正如我之前提到的，因为我现在住在日本，所以每天都在使用它，它是一个很靠谱的词典。

LifeFlow

另一个我经常使用的程序，也是我所有作品中使用频率最高的一个，就是 LifeFlow——也就是我用来写这个博客的博客软件。我就不多赘述了，因为我似乎已经花了不少时间在谈论它。

它在漫长的生命周期中成长了许多，现在已经是一个功能相当完备的博客工具。很快，随着 LifeFlow Editor 的完成，它将会成为一款让我相当满意的软件。

前端采用极简主义设计，不依赖任何 JavaScript、Flash 等技术。后端则对无障碍访问较为随意，大量使用了 Ajax 和 jQuery。
