使用 LifeFlow 将条目翻译成其他语言

2008-01-22 · 阅读原文

简单通知一下，我最近花了一些精力来完善 LifeFlow 中为条目附加翻译的功能。

其基本概念是：你可以创建多种语言，然后使用特定语言将翻译链接到文章上。具体来说，每条翻译包含三部分数据：

语言、原始条目、翻译后的条目

翻译后的条目其实就是另一篇条目，其创建方式与原始条目完全相同，然后再创建一个 Translation（翻译记录），其中包含上述三部分信息。

我目前的设计是不为翻译分配任何标签（Tags），也不将其纳入任何信息流（Flows）。这意味着它们只能通过三种方式访问（RSS feed 稍后讨论）：当你在列表中看到某条目时，它会提示现有的翻译；具体条目页面会显示其所有翻译；以及从语言页面列出所有可用语言，每个语言页面则列出该语言下的所有条目。

这并不意味着你不能为翻译添加标签或将其纳入信息流，实际上完全可以。例如，你可以创建一个「Code」信息流和一个「Code-Japanese」信息流（标签和系列也可以做类似处理）。这样就能让原始内容和翻译内容仅对感兴趣的用户可见。

此外，每种语言都有独立的 RSS feed（可在对应语言页面订阅，该页面列出该语言下的所有条目），同时还有一个包含所有翻译的 Translation feed。

翻译不会出现在「All」feed 中，因为这对大多数不关心翻译内容的用户来说是一种干扰。或许更好的解决方案是提供另一个包含所有内容（包括翻译条目）的 feed。

Unicode 支持

LifeFlow 当前的 SVN 版本已提供完整的 Unicode 支持。你可以在文本的任何位置使用 Unicode 字符，不会有任何问题（前提是你的数据库已正确配置为支持 Unicode）。所有用于撰写普通文章的 Markdown 功能对 Unicode 编码的文本同样适用。

例如，我在 Emacs 中写下了这两篇翻译，保留了所有常用的 Markdown 语法，包括一些 LifeFlow 专用的 Dynamic Blog Context 动态数据。然后我将内容从 Emacs 粘贴到 Django Admin 的正文字段中，一切都正常工作。

与此同时，我不想给那些对 Unicode 支持不佳的老旧设备带来麻烦，因此所有语言名称都使用了 Ascii 字符而非 Unicode（比如我其实更想用日语汉字写「Japanese」，但不想无意中破坏老旧浏览器）。这意味着，在 lethain.com 上，你只会在特定语言页面（作为翻译条目的标题使用翻译语言）和具体条目页面（同样使用翻译语言）看到 Unicode 编码的语言名称。

然而，语言名称的设置并没有被硬编码为禁止使用 Unicode。其他 LifeFlow 安装可以选择完全不同的方式，用母语本身来命名所有语言（我也希望最终能往这个方向发展，那只是简单地在 Django Admin 中重命名语言标题即可，但我会等到 Windows XP 的用户群进一步减少后再做）。

总结

最终结果是，翻译支持现在已经成熟且运转良好，SVN 中的最新模板也能很好地在不打扰不关心翻译的用户的情况下，提示条目存在翻译。Unicode 支持也已全面完成（不过尚未在评论系统中测试，因为之前拒绝支持 Unicode 意外地成了一个相当有效的垃圾评论过滤器）。

哦，最后一点想法：你也可以用这个机制将条目翻译成其他编程语言。它并不一定只能翻译成其他人类语言。
