将 LifeFlow 中的条目翻译成其他语言

2008-01-22 · 阅读原文

简单通知一下，我最近花了一些精力来完善 LifeFlow 中为条目附加翻译的支持。

其核心概念是：你可以创建多种语言，然后通过特定语言将翻译关联到一篇内容上。细分来说，每条翻译包含三部分数据：

语言、原始条目、翻译后的条目

翻译后的条目本质上就是另一篇正常创建的条目，然后再创建一个 Translation 对象，将上述三部分信息关联起来。

我目前的设计是不给翻译分配任何标签，也不将其纳入任何 Flow。这意味着它们只能通过三种方式被访问（RSS feed 稍后单独讨论）：在条目列表中会提示现有的翻译，查看具体条目时会显示其翻译，以及从语言页面——该页面列出所有可用语言，每个语言页面则列出该语言下的所有条目。

这并不意味着你不能给翻译添加标签或将其纳入 Flow，实际上完全可以。例如，你可以创建一个 Code Flow 和一个 Code-Japanese Flow（对标签和系列也可以做类似处理）。这样就能让原始内容和译文仅对感兴趣的用户可见，保持整洁。

此外，每种语言都有自己独立的 RSS feed（可在对应语言页面订阅，该页面列出该语言下的所有条目），同时还有一个包含所有翻译的 Translation feed。

翻译不会出现在 All feed 中，因为对大多数不关心译文的用户来说这反而是一种干扰。或许更好的方案是提供另一个包含所有内容（包括译文）的 feed。

Unicode 支持

LifeFlow 当前的 SVN 版本已完整支持 Unicode。你可以在文本的任何位置使用 Unicode 字符，完全没有问题（前提是你的数据库已配置为支持 Unicode）。用于撰写普通文章的所有 Markdown 功能对 Unicode 编码的文本同样适用。

举例来说，我在 Emacs 中写下了这两篇译文，使用了所有常规的 Markdown 语法，包括一些 LifeFlow 专用的动态博客上下文（Dynamic Blog Context）。然后我把内容从 Emacs 粘贴到 Django Admin 的正文字段中，一切都正常工作。

与此同时，我不想给不支持 Unicode 的旧设备造成麻烦，所以所有语言名称都使用了 Ascii 字符而非 Unicode（比如我其实更想用日语汉字写「Japanese」，但不想无意中破坏老旧浏览器）。因此，在 lethain.com 上，你只会在特定语言页面（译文标题使用其对应语言）以及具体条目页面（同样使用译文语言）才能看到 Unicode 编码的语言名称。

不过，语言名称的设定并没有硬编码禁止使用 Unicode。其他 LifeFlow 安装实例可以选择完全使用母语来命名语言（我也希望最终往这个方向发展，这只需要在 Django Admin 中简单重命名语言标题即可，但我会等到 Windows XP 的用户群进一步减少后再这么做）。

总结

最终结果是，翻译支持现在已经稳定可用，SVN 中最新的模板也能很好地在不打扰不关心译文的用户的情况下，提示条目存在翻译。Unicode 支持也已全面到位（不过尚未在评论系统中测试，因为之前拒绝对 Unicode 的支持意外地成了一个相当有效的垃圾评论过滤器）。

哦，还有最后一个想法：你也可以用这个机制把条目翻译成其他编程语言。它并不一定只能翻译成其他自然语言。
