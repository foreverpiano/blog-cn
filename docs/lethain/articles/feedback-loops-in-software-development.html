软件开发中的反馈循环

2009-06-01 · 阅读原文

在一所小型文理学院攻读计算机科学最大的乐趣之一，就是可以随时去找教授，听他们讲故事。其中一个我最喜欢、也反复听到的故事是：有同学提交的项目根本无法编译。如果说忽略边界条件是懒惰工程师的标志，那么连编译都通不过的代码，又该算是谁的标志呢？

几年前我还乐于将其视为失败工程师的标志，但随着自己也多次尝到失败的滋味，我逐渐形成了一个不那么自以为是的看法：这些人只是还没认识到反馈循环的重要性。

不管你认为 MIT 从 Scheme 转向 Python 是妥协还是灾难，我都不认为这两门语言都把 REPL 作为核心是个错误；及时收到反馈是区分困惑与清晰的关键。缺失反馈循环不仅在大学校园里毁掉了无数作业，也正在各地的软件工程实践中制造混乱。

程序员的 rewarding 循环

尽管软件工程师并非所有时间都在编程——很多人甚至大部分时间都不在编程——但编码本身拥有娱乐之外最纯粹的反馈循环之一。在各种编程方式中，最简单的反馈循环来自与集成良好的 REPL 进行交互。

如果你经常在多种语言间切换，特别是像 JavaScript 和 Python 这样语义相近的语言，你可能会记不清哪个语言用 x.append、哪个用 x.push 来向列表末尾添加元素。你可以去 Yahoo 搜索答案，但向 REPL 询问会更快也更可靠。

除了检查语法或查看对象实例2，你甚至可以直接在 REPL 里开发游戏或 Web 应用。如果说所有编程都有很强的反馈循环，那么 REPL 就是其中的王冠宝石。

反馈循环的质量与获得反馈所需付出的努力或时间成反比。前端程序员的反馈循环常常被浏览器相关的渲染 bug 所削弱（修改、重新部署、按照步骤重现问题、验证渲染、换个浏览器再测……），而后端工程师的循环也同样容易被繁重的编译或部署流程所拖累。

对于足够大的项目——即任何编译或部署明显有延迟的项目——可脚本化的测试是一种（或许是唯一一种）能有效放大正在衰退的反馈循环的方法。抛开意识形态的争论，可脚本化的测试在心理层面起着重要作用，它通过持续提供反馈让程序员保持清醒和满足。有了好的反馈，不仅能带来极大的满足感，还能带来高质量。

拿走程序员的反馈循环，我们就只剩下……

软件架构师的真空

在分析前端工程中的偏差时，一个主要原因就是开发者在实现他们并未参与设计的东西。对前端开发者来说，这可能是实现设计师的工作；而对后端开发者来说，他们还有一个历史宿敌：架构师。

正如无法编译的作业既是其自身的原因也是其结果一样，“架构师不写代码”这一反模式既是损坏的反馈循环的结果，也是其根源。

即使与最优秀的专业人士共事，我也从未见过哪个项目最初的设计能完好无损地贯穿整个项目始终3，但有些架构师扮演的正是这个角色：在真空环境中创建系统设计，然后交给工程师去实现。

这会让工程师感到沮丧，因为他们与系统有直接的反馈循环，因此必须直接面对其不足。而对架构师来说，反馈循环被严重稀释——如果实现工程师没有足够强烈地传递他们的反馈——架构师可能完全收不到任何反馈，从而把一场灾难当作自己又一枚功勋勋章。

在这种情况下，通常的建议是让架构师更多地参与编码，以保持对技术的感觉，或维持团队对他们的尊重。当然，这些理由都很好，但核心在于，架构师必须参与到实现中，才能与自己的设计建立直接的反馈循环。

没有直接反馈，架构师对自己系统的理解将比实现者增长得更慢，因此他们会负责做出决策，却缺乏做出良好决策所需的充分上下文和理解。

期望架构师在不参与实现的情况下就能充分设计系统，就像期望一个父亲通过一夜情就能养育出一个心态健康的孩子一样：这根本不可能实现。

项目经理的恐慌

把焦点从同语反复转向悖论：正如断开连接的反馈循环不包含任何信号，过度的反馈循环则会让信号被噪声淹没到几乎不存在。想想产品经理的角色，以及包围着他们的过度生长的反馈循环纠缠。

一旦我们开始考察个体之间以及个体与群体之间的反馈循环，这些循环就等同于沟通渠道，并且会随着群体规模的扩大而迅速退化。4

由此可以得出，改善沟通的最佳方式是减少需要沟通的人数。跨领域培训很重要，因为它能将多个角色合并到一个人身上；但如果前端工程师觉得自己对设计和后端工程也有发言权，并因此卷入额外的设计和后端讨论，反而可能会增加沟通线路。

有些人确实需要参与所有事情，但如果每个人都要参与所有事情，而你的团队里有超过三四个有强烈观点的人，那你们可能就有麻烦了。

好的循环是专注的循环

大型团队用来控制反馈干扰最常用的方法是召开会议。在我看来，会议是反馈循环贫乏的标志；而当出现“最后一刻”、“全项目范围”、“状态”和“澄清”这些词时，这种看法会变得更加强烈。

好的反馈循环意味着在尽可能少的组件之间建立紧密、直接的沟通线路。我们并非人人都有机会每天和 Slime 对话，但朝着这个方向努力，我们至少能获得——如果不是救赎的话——清醒。
