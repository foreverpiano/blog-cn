使用 Node.js 构建日志收集服务器

2010-01-30 · 阅读原文

最近我在考虑如何从多台机器上聚合日志。

虽然解决这个问题的方法有很多，但我决定写一个简单的 HTTP 服务器来接收日志，然后再编写一个脚本去监控文件变化，并将新的日志 POST 到这个 HTTP 服务器。

作为一次实验，我选择用 Node.js 来实现，因为之前还没有用它做过项目，而回调机制让我觉得非常适合扩展现有的命令行工具（这里是将 tail -F 的输出通过 HTTP 请求发送到远程服务器）。

首先实现日志收集服务器，它会简单地把收到的数据回显到标准输出。

接下来快速编写客户端，它通过子进程封装 tail -F 来监控日志文件。

现在我们可以测试这两个组件了：

touch log.txt
node logs.js &
node log_watcher.js log.txt &
echo "test" >> log.txt
echo "another test" >> log.txt

目前日志服务器只是把收到的日志回显到标准输出，但更理想的做法是把它们保存到文件中。最简单的方式是像下面这样运行服务器：

node logs.js >> centralized.log

但仅仅是追加到一个文件里灵活性不够。让我们来实现一个简单的机制，允许用户以任意方式存储日志。我们以追加到文件作为示例后端，后续可以轻松替换为其他存储方式。

node logs.js mysql_backend.js

这已经是一个相当不错的小工具了，而且实际上比表面上看起来的还要更好一些：虽然我们把它编写成了“发射后不管”的客户端，但 Node.js 的 HTTP 客户端实现会在主机不可用时自动将请求排队，当下次尝试发送消息发现主机恢复可用时，会按原来的顺序把它们全部发送出去。（这和我最初的预期不一样——我本来准备手动实现一个消息缓存来完成存储转发的机制——但结果是它工作得相当不错。）

这就是全部内容了。我们用不到一百行代码实现了一个支持可插拔存储后端的日志收集服务器，以及一个能够发送被监控文件变更的存储转发客户端。在多做几个项目之后，我肯定会写一些关于 Node.js 的感想（说实话已经晚了好几个月才开始玩），但现在我已经可以说，它比我之前想象的有趣得多：用它开发真的很开心。
