遗传编程：一个新奇的失败案例

2009-01-19 · 阅读原文

之前我写过关于遗传算法基本原理的文章，并简要提到了遗传算法与遗传编程之间的区别。在这里，我们将对遗传编程进行更深入的探讨。在开始愉快地漫游遗传编程示例之前，我要先承认自己的偏见：我认为遗传编程是一个很棒但虚构的复杂问题解决方案。

遗传编程之梦

在花了漫长一夜清理互联网上错误观点之后，你意识到自己无法单枪匹马地维护它的神圣纯洁。你构建了一个神经网络，它接受博客文章作为输入，并输出修复问题的正确操作，但它总是返回“在绝望中哭泣”，无论怎样训练，这个神经网络都无法在接收到包含“Bitf*ck vs. Scheme”、“Vista Sucks”或“Git Owns Perforce”等闪亮话题的博客文章时正确输出“在 Reddit 上怒喷”或“嘲讽”。

你垂头丧气地想，如果我能写一个程序来替我写这个程序就好了！等等——这真是太天才了——如果我只是将一系列操作输入到遗传算法中，然后……

两周后，那份尚未破产的报纸大肆宣扬你的成就：你、你编程得到的程序，以及那个程序所编程出的程序一起清除了互联网上的错误观点，联合国下令将那些讨厌且无关紧要的博主剥夺公民身份，送进集中营。

啊，是的，世界一切都美好。

短暂地用纸袋喘口气之后

好吧，我可能有点反应过度了，但你可能已经推断出第一个重要结论：未经调优的遗传算法在某些问题上表现可能非常差（即彻底失败）。特别是当依赖于一个信息量不足的适应度函数时，遗传算法表现尤为糟糕，而我们当前的适应度函数信息量极度匮乏。

首先，极少数个体能形成有效的 Python 语法，而所有无效个体都获得相同的适应度值 -10000。这意味着我们当前的适应度函数对大多数个体的适应度反馈都很差，因此从一开始就以惨烈的方式失败了。不过没关系，因为我们可以改进当前的适应度函数，对吧？

让我们再看一下我们的适应度函数。

如果语法错误，我们就无法获得关于语法距离有效状态有多近的任何反馈。如果它是有效的，那么我们确实开始获得有用的反馈，但我们还是有些受阻，因为绝大多数个体都是无效的（我们稍后会查看有效和无效个体的比例）。

在无法评估代码的情况下，我们有两种方法可以生成更具体的反馈：

计算一个基于代码距离语法正确程度有多近的适应度函数；计算一个基于参数距离期望正确解有多近的适应度函数。

在这个极其简单的示例中，第一个选项相当简单（格式必须在数字和操作符之间交替，并且必须以数字开始和结束），但在更复杂的场景中，它会迅速膨胀成一个相当棘手的问题。

第二个选项完全是骗人的，因为它意味着你是通过教它一个你已经知道的答案来“解决”问题；在那种情况下，你既没有优化也没有解决任何东西，你只是在 perpetuating 一场闹剧。

就像用电钻除尘

遗传算法是一类优化技术，但从适应度来看我们可以发现问题：它首先试图解决一个搜索问题（找到可行的解，无论质量如何），然后再尝试优化（提升已发现解的质量）。很少有——如果有的话——算法能同时在这两个方面都表现良好。

由于组合数量更少（3^3 而不是 5^5），我们看到了更多语法正确的个体，但随着代数增加的比例实际上更差。让我们做最后一次努力。把目标 X 从 15 改成 6，只保留前 10% 的个体，并将代数增加到三千。

对于一个主要弱点是快速而短视优化的算法来说，这种毫无进展的情况强烈表明了我们已经开始怀疑的事情：遗传算法根本无法克服这个问题的搜索部分。

这一个例子远不足以作为充分理由，但我会更进一步指出，只有当你提供解决方案的详细轮廓时，遗传编程才能解决问题。遗传算法可以从提供的组件中优化出一个解决方案，但遗传编程不足以同时发现并优化解决方案。这很遗憾，因为这个概念本身具有一种难以忽视的优雅。

不难看出这个想法如何反复引诱科学家们撞墙，直到他们扭曲了自己的大脑皮层和算法，足以让自己相信它有效。要是遗传编程的结果能配得上它概念上的美感就好了。

2009 年 1 月 20 日的简短回应

许多评论者强烈认为这个引言不公平地诋毁了遗传编程。从他们所表达的深切愤怒来看，这些很可能是正在从事遗传编程领域研究的人。总是那些离某个话题太近的人，尤其是学者，会对批评产生非理性的愤怒。当然，如果有人暗示我花了半个十年在追逐一个白日梦，我也会同样生气。

除了愤怒，基本的抱怨是我在生成个体时使用了随机组合元素的简单方法，而不是创建相当复杂的 инфраструк来持续生成语法正确的抽象语法树。

在上面的文章中，我提到了针对信息量不足的适应度函数的两种应对方法：

教会适应度函数如何编写代码。教会适应度函数解决问题的代码。

虽然分开列出，而且在那些尖叫的声音之上，我并不认为这两个解决方案真正有本质区别。即使我们将诉诸#2 的做法包装在执行#1 的前提之下，我们仍然是在教适应度函数创建我们想要的解决方案。如果我们承认遗传算法无法解决搜索领域的问题，那还能怎样呢？即使限制在有效代码范围内，问题空间也极其庞大；我们要么需要一个真正的搜索算法来发现解决方案，要么提供搜索方向的提示。

最后两点：

这些文章的目的是向初学者程序员介绍计算机科学的思想，同时坚持使用 Python 语言，最重要的是提供完整的、可运行的示例，不依赖外部（即非标准）库。在解决方案中使用抽象语法树不在考虑范围内，同样也不打算把遗传编程贬低为过于复杂或仅限于天界研究者领域。有评论提到某个未具体说明的问题领域，在那里遗传编程明显优于遗传算法，或许也优于其他算法。虽然“优越”的定义和问题领域都没有说明，但我很乐意进行这样一场竞赛：选择一个被认为 firmly 处于遗传编程最具竞争力的领域的问题。决定使用一种通用编程语言（也许是 Scheme 或 Common Lisp？）。编写代码时不使用算法特定的支持库（即生成随机数的库是可以的，但支持遗传编程/遗传算法的库不行）。这很重要，因为它能揭示算法的真实复杂度，而不是把复杂度隐藏在库背后。任意数量的参赛者提交解决方案，并说明所使用的算法类别。将解决方案和测试用例打包在一个 zip 文件中分发，以便我们都能验证结果。任何人可以创建自己的评分标准，并以自己的观点撰写群体结果总结。
