用 Whuffie 取代 Karma 社交模型

2008-01-22 · 阅读原文

最近我接触到了 Whuffie 的概念，它在我脑海中引发了一些有趣的想法。Whuffie 类似于带有社交属性的 Web 应用中的 karma，但有一个关键区别：whuffie 有一个绝对值，同时还能显示针对特定用户的加权值。

这个区别非常重要，因为目前 karma 正在承担两项相互独立的任务。首先，它作为这些 Web 应用自动化机制的排名依据；其次，它又作为用户自行判断内容的排名依据。

不难想象，绝对值和加权值这两个概念比单一的绝对值同时承担两项任务要更加合适。

绝对值就相当于目前大多数实现中的 karma，它将作为内部机制使用的数值。相对 karma 则允许每个用户选择自己喜欢或厌恶的行为，并据此调整自己看到的网站版本。这意味着不同用户将拥有完全不同的高分内容和高分用户，他们的评分将反映自己真正认为有价值的东西，而不是简单地采用由程序员设定的静态 karma 权重。

我认为允许用户为 karma 提供只存在于自己副本中的权重，是一种真正的胜利——既能创造更个性化的社交体验，又不会损害其他人的社交体验。如果我们认为 Web 应用是一种工具，那就应该努力让它们对每一位用户都尽可能有价值。

这种做法带来的积极影响甚至会超出单个用户。首先，它会强烈鼓励那些原本不爱发评论的 casual 用户创建账号。创建账号并按自己喜好进行定制，会让用户有很强的动力继续留在这个率先实现该功能的网站上。

另一个很好的副作用是，更多样化的网站将获得关注，而且很可能是更高质量的关注。因为 karma 模型不再与用户的个人兴趣脱节，将会有大量不同的 karma 模型来决定什么内容最好，而不是由一个强制适用于所有用户的单一模型来主导。
