双面 Django 第 6 部分：PyFacebook

2007-12-12 · 阅读原文
  • 你可以在此处找到这个项目的在线演示版本，包括网页界面和 Facebook 界面的详细说明。

现在我们终于进入 Facebook 应用开发领域了。简单回顾一下，我们是从第五部分延续过来的，那里我们为网页应用实现了 Ajax。如果你没有跟上之前的系列教程，可以获取我们当前的代码快照。我们正在使用 PyFacebook 来与 Facebook API 进行交互，如果你需要对 Facebook 系统有更全面的了解，可以查看开发者 Wiki。

我不会详细讲解如何为你的应用获取 Facebook Key，这部分内容在 Wiki 中已有详细说明。

规划我们的方法

我们即将构建的 Facebook 应用在功能上将与刚刚完成的网页应用完全等价。就像构建网页应用时一样，我们首先会处理除 Ajax 交互之外的所有部分。

我们的计划如下：

  1. decide on our URLs,
  2. write our views,
  3. write the templates

你可能已经感觉到这就是我编写 Django 应用的一贯方法……你想得没错。

设计 Facebook 的 URL

我们要做的第一件事是在 fb 应用目录中创建一个 urls.py 文件。

urlpatterns = patterns('',
    (r'^vote/$', 'polling.web.views.vote')
)

然后我们先写入所有 urls.py 文件的标准开头代码：

def vote(request):
    results = {'success':False}
    if request.method == u'GET':
        GET = request.GET
        if GET.has_key(u'pk') and GET.has_key(u'vote'):
            pk = int(GET[u'pk'])
            vote = GET[u'vote']
            poll = Poll.objects.get(pk=pk)
            if vote == u"up":
                poll.up()
            elif vote == u"down":
                poll.down()
            results = {'success':True}
    json = simplejson.dumps(results)
    return HttpResponse(json, mimetype='application/json')

在网页应用中我们主要使用通用视图来处理所有逻辑，但是在 fb 应用中我们将使用自定义视图。原因是我们在所有请求上都要进行一些自定义验证，而自定义视图能让我们非常方便地实现这一点。我们所有的自定义视图都将放在 polling.fb.views 模块中，因此我们可以简化 fb/urls.py 的写法，直接共享这个信息。

为此我们修改这一行：

def vote(request):
    results = {'success':False}
    if request.method == u'GET':
        data = request.GET
    elif request.method == u'POST':
        data = request.POST
    if data.has_key(u'pk') and data.has_key(u'vote'):
        pk = int(data[u'pk'])
        vote = data[u'vote']
        poll = Poll.objects.get(pk=pk)
        if vote == u"up":
            poll.up()
        elif vote == u"down":
            poll.down()
        results = {'success':True}
    json = simplejson.dumps(results)
    return HttpResponse(json, mimetype='application/json')

def vote(request):
    results = {'success':False}
    if request.REQUEST.has_key(u'pk') and request.REQUEST.has_key(u'vote'):
        pk = int(request.REQUEST[u'pk'])
        vote = request.REQUEST[u'vote']
        poll = Poll.objects.get(pk=pk)
        if vote == u"up":
            poll.up()
        elif vote == u"down":
            poll.down()
        results = {'success':True}
    json = simplejson.dumps(results)
    return HttpResponse(json, mimetype='application/json')

这意味着我们在 patterns 中指定的视图可以简写为 'list'，而不需要写成 'polling.fb.views.list'。如果你使用的是通用视图，这种方式是行不通的，因为它会尝试在 'polling.fb.views' 模块中查找通用视图（那里显然不存在），但当你所有的视图都来自同一个地方时，这是一种避免重复代码的好方法。

好了，现在让我们真正来编写 URL 配置：

function vote(pk, voteUp) {
  if (voteUp == true)
    typ = "up";
  else
    typ = "down";
  var ajax = new Ajax();
  ajax.responseType = Ajax.JSON;
  ajax.requireLogin = true;
  var params = { "pk":pk, "vote":typ };
  ajax.post('http://krit.willarson.com/vote/', params);
}

function vote(pk, voteUp) {
  if (voteUp == true)
    typ = "up";
  else
    typ = "down";
  var ajax = new Ajax();
  ajax.ondone = function(data) {
    var d = new Dialog(Dialog.DIALOG_POP);
    if (data.success == true)
      msg = "Your vote was successful!";
    else
      msg = "Your vote failed. :(";
    d.showMessage("Voting Result", msg);
  }
  ajax.responseType = Ajax.JSON;
  var params = { "pk":pk, "vote":typ };
  ajax.post('http://krit.willarson.com/vote/', params);
}

那么，让我们看看这里发生了什么：

  1. We add a facebook instance to the request (accomplishing the same thing that the PyFacebook middleware would be doing if we were using it).
  2. If the current Facebook user is not logged in to our app, we redirect them to the login page for our app.
  3. We grab the User model from our local database that has information about the Facebook user who is currently using our application.
  4. We "Do Things".
  5. We render an appropriate template for the view (and we pass along some appropriate context, in this case the user, but in our real views we will also be adding some other context, like a list of objects, or a specific object, etc).

这其实可以使用装饰器更优雅地实现（PyFacebook 就是这么做的，只是它的装饰器需要中间件支持，因此对我们来说不是很方便）。其中“if redirect is not None”那部分代码特别影响可读性。我认为最干净的解决方案是创建一个名为“add_facebook_instance”的装饰器，放在其他任何 PyFacebook 装饰器之前，它负责把 facebook 实例附加到 request 上，这样你就可以直接使用所有的 PyFacebook 装饰器，同时也可以避免使用 PyFacebook 中间件：也就是说，你可以鱼与熊掌兼得。不幸的是，我还没有真正写出这个装饰器（虽然我估计写它大概只需要十几二十分钟，但是……一直没动手）。

那么让我们来梳理一下 create 视图的逻辑：

  1. If the user is not logged into our FaceBook app, redirect them to the login page.
  2. If there is a value for the 'question' key in the POST data, then populate a PollForm using that the POST data.
  3. If the ensuing PollForm is valid, then create the corresponding poll and redirect the user.
  4. If the ensuing PollForm is not valid, then return the invalid form to the page, which will allow us to display errors.
  5. If there is not a value for key 'question' in the POST data, return a blank poll.

这和我们在之前的教程中在 polling/web/views 中创建的 create 视图非常相似。所有传入数据的验证都由 PollForm 处理，因此逻辑幸运地保持得相当简单。
