极简主义

2008-06-11 · 阅读原文

（这是 Kenneth Arnold 撰写的系列文章的第一篇，探讨如何以更轻量的方式使用 Django，减少有时显得繁重的框架开销。我对这个系列非常期待，也很高兴能与 Ken 合作。现在，闲话少说，直接进入正文。—— Will）

对我们大多数人来说，剑就是一根沉重的金属棍子，配着一个奇怪的握柄。我大概连灌木都砍不动。但如果由一位技艺精湛的战士挥舞，剑就会成为强大的武器。

同样，Django（甚至 Python！）看起来可能庞大而笨拙。但在熟练的人手中，它足够灵巧，能轻松扫除 Web 开发中的灌木丛，同时也足够强大，可以挑战更大的对手。

这个小系列的目标是帮助你灵活运用 Django 来实现自己的想法。我们会先剥离到最基本的部分，然后逐步构建。在此过程中，我们会走一些非常规的路线，来提升你在 AJAX 风格、“Web 2.0” 应用中的敏捷性。

如果你之前用过 Django，前两篇文章应该可以轻松略读。之后再回来加入我们，从第 3 篇开始，我将介绍 django-webapp。现在就可以去看看，欢迎留下评论。

基础知识

我们将使用 Django 的 SVN 版本（即“开发版本”）。请按照说明进行设置。我使用 Python 2.5 进行开发，但它应该也能在 Python 2.4 上无需修改地运行。Python 2.3 则需要做一些额外调整（尤其是装饰器）。建议使用 IPython。请记住：Django 就是 Python。

极简 Django

Django 教程一开始会给你一个宽泛的概览，这对于展示在大型项目中如何使用它非常有效。如果你属于那种先了解整体画面再学习的人，或许应该先完成教程再继续阅读这里。我们不从大图景入手，而是先练习几个非常基础的操作。

在一个空目录中开始，只在 app.py 中放入以下内容。

qaodmasdkwaspemas0ajkqlsmdqpakldnzsdfls

你甚至不用运行，大概就能猜到它做了什么。不过我们还是运行一下吧。启动一个 Python 控制台——最好是 IPython——然后输入以下内容：

qaodmasdkwaspemas1ajkqlsmdqpakldnzsdfls

不用太在意最后这部分的细节，Django 之后会提供自动化的方式。你只需要注意到 Django 支持 WSGI，这在以后要把应用部署到大型服务器上时会很有意思。那是后面的事了。

访问 http://127.0.0.1/，你就会看到你的第一个（或者至少是最小的）Django 应用。现在来解读一下。

Django 的主要工作是将请求（来自浏览器）转换为响应。请求中最重要的部分是 URL，因此这是我们首先要告诉 Django 的信息。在上面的 shell 代码中标记为 (1) 的那一行告诉 Django，你的 ROOT_URLCONF（开始查找 URL 处理方式的起点）就是你刚刚创建的 app 模块。（注意，就像在普通 Python 中 import app 一样，它不以 .py 结尾。）

URL 配置

一个 Django URL 配置模块（就像你刚刚创建的名为 app 的那个）只需要一个东西：一个名为 urlpatterns 的变量（上面标记为 (2) 的那一行）。它将 URL 与当该 URL 被请求时要执行的函数配对。当你从服务器请求一个 URL 时，URL 解析器会按顺序遍历列表，寻找匹配该 URL 的条目。

好吧，刚才说的稍微有点不准确。Web 服务器很少处理完整的 URL，Django 也不例外。解析器尝试匹配的 URL 是请求的路径，也就是地址栏中的 URL 去掉 http:// 和服务器名，再去掉任何 GET 参数（我们后面会再讲）。所以如果你输入：

http://myserver.com/posts/?all=0

那么 URL 就只是 posts/。（注意，开头也没有斜杠。）

URL 通过正则表达式（regex）进行匹配。如果你从未听说过正则表达式，别慌；它们是处理字符串非常强大的方式，单凭这一点就值得学习，但我们在这里不会用到它们全部的威力。我们使用的这个正则匹配的是以开头（^）紧接着就是结尾（$）的字符串，也就是空字符串。所以当我们访问 http://127.0.0.1/ 时它就匹配了。而匹配成功后，它就会执行我们传给它的视图函数。（函数也是对象，Python 就是这么酷。）

你可能会发现 Python re 模块的文档很有帮助，尤其是语法部分。
