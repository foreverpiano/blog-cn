Python-Brightkite 的限制

我们实际上已经实现了 Brightkite RESTful API 所暴露的大部分功能，但仍存在一些小问题和一个较大的缺口。

具体来说，所有数据获取命令都已经过测试，但创建/删除/更新相关的功能还没有经过充分测试（不过代码本身非常简单，所以一旦发现问题，修复起来应该只需要几分钟时间）。

最大的一个功能缺失是使用 OAuth 进行身份验证。由于目前唯一的其他选择是 HTTP Basic Auth，所以 Python-Brightkite 目前仅支持这种方式。在 Python-Brightkite 能够被严肃使用之前，这个限制必须得到解决。如果你有兴趣研究这个问题，这里有一些参考资源，比如这个代码片段和这个库。如果到下周末还没解决，我可能会抽时间投入精力来处理。

关于实现的几点说明

这是一个相当有趣且快速完成的项目（别忘了 Yashh 也为项目做出了贡献）。在尝试了 XML::Simple 之后，我更加确信，将 XML 转换为原生数据结构是处理 XML 的正确方式——除非性能在你的使用场景中至关重要。

使用 xml2dict（我第一次是在 Vik Singh 的 Yahoo! BOSS 库中看到的，它能将 XML 文档转换为 Python 数据结构），再配合 httplib2，让整个应用的基础部分变得简洁而优雅。（请友好地忽略 _unescape_uri 方法的糟糕实现。它是十秒钟临时修复的方案，因为我发现自己转义得太过头了，但当时想先看看整个库是否能正常工作。）

我还记得以前曾经想过，人们为 Amazon 或 Facebook 之类的 API 编写封装库真是太棒了。后来我逐渐意识到，实现一个封装库主要靠的是时间，而不是才华。现在我自己动手做了几个之后，进一步意识到，这甚至不是时间的问题，而仅仅是个“去做”的问题。（当然，维护封装库可能会把你累死。）

如果我们能找到一种描述 API 的通用格式，就能彻底绕过编写封装库这道工序。这样的话，即使 API 开发者没有提供规范，也只需要几位开发者花几个小时把它写出来，我们就能为哪怕是最前沿的 API 获得漂亮的封装库。可能性如此之多，而时间却如此之少。
