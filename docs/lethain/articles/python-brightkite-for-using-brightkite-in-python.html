Python-Brightkite for... 你懂的

2008-11-16 · 阅读原文

上周 Yashh 联系我，说要开始写一个 Brightkite 的 Python 封装库。基于 Brightkite 的 RESTful API，我们已经取得了相当不错的进展，朝着一个可用的库迈进。

你可以在它的 GitHub 仓库中贡献代码或查看项目，也可以在 wiki 中看到剩余的任务。

安装 Python-Brightkite

安装 Python-Brightkite 的过程相当简单。

easy_install httplib2
git clone git://github.com/lethain/python_brightkite.git

它还依赖于 xml2dict，

但这个依赖已经和它打包在一起了（我们之所以打包它，是因为它没有 easy_install 包，而且好几年都没更新过了）。

目前你最好直接从仓库里把 .py 文件复制到自己的项目中，但等这个项目进入 toddler 阶段，我们会提供一个更人性化的部署方案。

cp python_brightkite/*.py ~/path/to/your/project/

保证很快就会变得更顺畅。

Python-Brightkite 的限制

我们实际上已经实现了 Brightkite RESTful API 所暴露的大部分功能，但仍有一些小问题和一个较大的缺失。

具体来说，所有数据获取命令都经过了测试，但创建/删除/更新相关的部分还没有怎么实际试用过（不过代码本身非常简单，一旦问题被发现，修复起来应该花不了几分钟）。

最大的缺失功能是使用 OAuth 进行身份验证。由于目前唯一其他的选择是 HTTP Basic Auth，所以 Python-Brightkite 目前只支持这个。在 Python-Brightkite 能被严肃使用之前，这个限制必须被解决。如果你有兴趣研究一下，可以参考这个代码片段和这个库。如果到下周末还没解决，我可能会鼓起精神来处理一下。

关于实现的一些说明

这是一个相当有趣且快速完成的项目（别忘了 Yashh 也为项目做出了贡献）。在尝试了 XML::Simple 之后，我非常确信，除非性能对你来说是个大问题，否则把 XML 转换成原生数据结构是处理 XML 的正确方式。

使用 xml2dict（我第一次是在 Vik Singh 的 Yahoo! BOSS 库里看到的），它能将 XML 文档转换成 Python 数据结构，再配合 httplib2，让整个应用的基础部分变得简短而优雅。（请善待那个丑陋的 _unescape_uri 方法。它是十秒钟的快速修复，因为我发现自己转义得太狠了，但当时我想先看看整个库能不能跑起来。）

def _unescape_uri(self, uri):
    return uri.replace("%3A",":").replace("%3F","?").replace("%26","&").replace("%3D","=")
def _get(self, uri):
"Fetch content via the GET method. Returns body of returned content."
uri = self._unescape_uri(uri)
header, content = self.http.request(uri, "GET")
return content
def _post(self, uri, content={}):
uri = self._unescape_uri(uri)
header, content = self.http.request(uri, "POST", body=content)
return content
def _delete(self, uri):
uri = self._unescape_uri(uri)
header, content = self.http.request(uri, "DELETE")
return content
def _convert_xml(self, xml):
"Stub method."
try:
return self.xml.fromstring(xml)
except ExpatError:
msg = "Couldn't parse response from Brightkite API."
raise BrightkiteException(msg, xml)

基于这五个方法，API 调用都非常简单。下面是两个有代表性的例子：

def friends(self, username=None):
    "Fetch friends for specified user, or self if no user specified."
    username = username or self.user
    uri = "http://brightkite.com/people/%s/friends.xml" % username
    return self._convert_xml(self._get(quote(uri)))
def checkin(self, place_hash):
"Checkin at given specified position."
uri = "http://brightkite.com/places/%s/checkins" % place_hash
self._post(uri)

其实除了构造函数以及 http 和 xml 属性的实现之外，实现部分就这么多内容了。

我还记得以前觉得人们为 Amazon 或 Facebook 之类的 API 写封装库是一件很酷的事。后来我开始意识到，实现一个封装库主要拼的是时间，而不是才华。现在自己玩过几个之后，我进一步意识到，它甚至不是时间的问题，而只是“去做”的问题。（不过，维护封装库可是会要命的。）

如果我们能找到一种描述 API 的通用格式，那么我们就能完全绕过编写封装库这件事。这样的话，即使 API 的开发者没有编写规范，也只需要几个开发者花几个小时就能写出来，然后我们就能为哪怕最新最前沿的 API 提供漂亮的封装库。可能性那么多，时间却那么少。
