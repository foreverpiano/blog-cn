为 LifeFlow 添加任意 Mod

2008-01-15 · 阅读原文

在我最近对 LifeFlow 进行扩展的过程中，遇到了几种情况：我希望让部署 LifeFlow 的人有更多的灵活性，但又不能破坏他们的 SVN 检出。即使是那些不想跟踪 SVN 变更的人，也能从一个干净且可预测的扩展部署系统中受益。

基于这个想法，LifeFlow 现在拥有了一个可扩展的 mod 系统。其核心概念是让部署 LifeFlow 的人能够以最少的额外开销来按需选择各种功能模块。

本文将通过两个示例，展示如何用模块以简单而强大的方式扩展 LifeFlow。第一个示例是使用 StaticGenerator 生成静态文件，帮助 LifeFlow 在共享主机或性能较低的 VPS 上运行。

第二个示例则是利用 mod 系统为你的文章添加新的动态博客上下文。

在 LifeFlow 中使用 StaticGenerator

如果你在共享主机上运行，可能对 Django 的性能有一些顾虑，尤其是在内容意外走红的时候。static_files 这个 mod 可以帮助减轻部分压力。

启用该 mod 后，每次保存博客文章时，都会自动生成它的静态版本，同时更新首页、标签页和文章系列页。这意味着你的大部分内容将以静态页面的形式提供，包括那些在流量激增时最可能被频繁访问的部分（你的文章内容本身，即使 Django 完全离线，也能继续为访问者提供服务）。

让我们来看看如何启用 static_files 这个 mod。你只需在 settings.py 文件中添加几行设置即可：

# You may already have LIFEFLOW_MODS, is so then just add 'static_files' to it
LIFEFLOW_MODS = ('static_files',)
WEB_ROOT = "/folder/to/generate/files/in/"

这就是启用 LifeFlow mod 的全部步骤，真的非常简单。注意，在 lifeflow/mods 目录下有一个名为 'static_files' 的模块，你基本上已经掌握了它的原理：只需把一个模块（可以是包含 __init__.py 的包，也可以是单个 Python 文件）放到那个文件夹里，然后把模块名添加到 LIFEFLOW_MODS 参数中。就这么简单。

好吧，刚才我说“没有第二步”稍微有点不准确。对于 static_files 这个 mod，确实还有第二步，而且有点麻烦：你需要配置你的主机环境，让它在请求 Django 处理文件之前，先检查是否有对应的静态文件。

具体配置方式会根据你的环境有所不同。我很快会再写一篇文章专门讨论这个话题，但目前你可以参考 StaticGenerator 的文档，那里面有一个针对 nginx 的完整示例。大多数共享主机提供商（例如使用 Dreamhost 的用户）需要修改 .htaccess 文件来为共享目录配置 Apache，我正在撰写一篇专门针对这种情况的文章（在 Dreamhost 上部署 LifeFlow）。如果你想自己深入研究，ModRewrite 文档是个不错的起点。

扩展动态博客上下文

现在我们来看另一个例子。LifeFlow 中一个很酷的工具是 Dynamic Blog Context，它允许你在 MarkDown 中书写格式化的引用，而无需自己手动创建引用链接。

内置的动态引用库已经相当实用，但你可能会需要一些尚未包含的功能（欢迎给我发 diff，如果合理的话很有可能会被采纳）。也许你想要一个与自己开发的第二个应用相关的动态上下文。

假设你想为一个名为 downer 的新 Django 应用添加最热门下载的动态上下文。我们假设相关的模型是 downer.models.download，并且该模型有一个名为 popular 的自定义管理器，能返回按受欢迎程度排序的结果。

现在我们想要创建一个动态上下文，让 [popular 1] 能链接到最热门的下载。来看看实现它有多难。

在 lifeflow/mods 目录下创建一个新文件 downer_context.py，打开它并加入以下代码：

# lifeflow/mods/downer_context.py
from lifeflow.markdown import mdx_lifeflow as lf
setattr(lf, "old_make_syntax", lf.make_syntax)
def new_make_syntax():
    syntax = lf.old_make_syntax()
    def popular(entry, str, nth):
        from downer.models import download
	dl = download.popular.all()[nth]
	return str % dl.get_absolute_url
    syntax[(1, "popular"))] = popular
    return syntax
setattr(lf, "make_syntax", new_make_syntax)

然后你只需修改 settings.py 文件中的 LIFEFLOW_MODS 设置，让它变成这样：

LIFEFLOW_MODS = ('downer_context',)

之后，你的新博客文章就可以使用我们刚刚创建的 popular 动态引用了。

这并不是一种特别优雅的扩展动态引用的方式，但核心要点是：你可以创建即插即用的 LifeFlow 扩展，而无需创建一个全新的 Django 应用。

诚然，在很多情况下，直接添加一个自己定制的 Django 应用会更干净，也可能更高效（因为它不需要考虑理论上的各种可能性，只需处理实际需要处理的内容）。在 LifeFlow 中加入简单 mod 机制的目的之一，就是让它逐渐成为一个平台，即使不精通 Django 或 Python 的人也能轻松地对其进行定制和修改。

目前我认为它已经拥有了一个非常灵活的结构，既允许有经验的用户随心所欲地定制，也提供了足够好的默认配置，让不想折腾太多就能用起来的用户也能轻松上手。

我很乐意听到任何反馈或改进建议。
