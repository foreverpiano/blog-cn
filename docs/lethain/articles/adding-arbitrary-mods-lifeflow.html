为 LifeFlow 添加任意 Mod

2008-01-15 · 阅读原文

在我最近对 LifeFlow 进行扩展的过程中，遇到了几种情况：我希望让部署 LifeFlow 的用户获得更多灵活性，但又不能破坏他们的 SVN 检出。即使对于那些不想跟踪 SVN 更新的用户来说，拥有一个干净且可预测的系统来扩展部署也是很有益处的。

基于这一考虑，LifeFlow 现在引入了一个可扩展的 mod 系统。其背后的理念是，让部署 LifeFlow 的用户能够以最小的额外开销来挑选和组合所需的功能模块。

本文将通过两个示例，展示如何使用模块以简单而强大的方式扩展 LifeFlow。第一个示例是使用 StaticGenerator 生成静态文件，帮助在共享主机或低性能 VPS 上运行 LifeFlow。

第二个示例则是利用 mod 系统，为你的文章添加新的动态博客上下文。

将 StaticGenerator 与 LifeFlow 配合使用

如果你在共享主机上运行，可能对 Django 的性能有不少顾虑，尤其是在内容突然流行起来的时候。static_files 这个 mod 可以帮助减轻部分压力。

启用该 mod 后，每次保存博客文章时，都会生成其静态版本，同时更新首页、标签页和系列文章页。这意味着你的大部分内容将以静态页面的形式提供，包括那些在流量激增时最可能被频繁访问的部分（你的文章内容本身，即使 Django 完全离线，也能继续为访问者提供服务）。

好吧，刚才我说“没有第二步”其实有点不准确。对于 static_files 这个 mod，确实还有第二步，而且有点麻烦：你需要配置你的托管环境，让它在请求 Django 处理文件之前，先检查是否存在对应的静态文件。

具体的配置方式会根据你的环境有所不同。我很快会写一篇专门介绍这个主题的文章，但目前你可以参考 StaticGenerator 的文档，其中有一个针对 nginx 的完整示例。大多数共享主机用户（例如使用 Dreamhost 的用户）需要修改 .htaccess 文件来为共享目录配置 Apache，我正在撰写一篇专门针对这种情况的文章（在 Dreamhost 上部署 LifeFlow）。如果你想自己深入研究，ModRewrite 的文档是一个很好的起点。

诚然，在许多情况下，简单地添加一个自己定制的 Django 应用会更干净，也可能更高效（因为它不需要考虑理论上的各种可能性，只需处理实际需要处理的内容）。在 LifeFlow 中加入简易 mod 系统的目的之一，就是让它逐渐成为一个平台，即使对 Django 或 Python 不太熟悉的用户也能轻松定制和修改。

目前我认为它已经拥有非常灵活的结构，既允许有经验的用户随心所欲地定制，又提供了足够好的默认设置，让那些不想折腾就能用的人也能轻松上手。

我很乐意听到任何反馈或改进建议。
