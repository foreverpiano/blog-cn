2017 年我在工程管理中学到的东西

2017-12-29 · 阅读原文

2017 年，我一直在 Stripe 的基础设施工程团队工作（旧金山和东南亚远程办公），接触到越来越有趣的问题，系统规模也越来越大，周围的同事也越来越优秀。

以下是我在过去一年里学到的一些东西。

管理

有很大一类工作，如果安排一个专注的人去负责，后面就能节省好几个人年的匆忙救火工作：比如确保系统能够持续扩展（而非退化）、成本核算、构建工具、代码托管等等。最好安排两个人，因为“一个人”仍然是最孤独的数字。管理中最宝贵的技能之一，是在管理层和团队的期望之间建立桥梁，同时又能真实地符合双方的价值观。如果你从不对团队说“不”，那你就不是真的在管理他们；如果你从不改变管理层的想法，那你也算不上真正的管理者。
拥有广泛技能的一个不太明显的优势是，你能在更多种不同的环境中取得成功——无论是换了经理还是换了公司。我希望我们能更多地强调，一线管理（line management）和管理经理是两份完全不同的工作。二者所需技能不同，而一线管理是一个极其丰富、深刻的领域，我们应该给予更多的重视。刻板印象威胁（stereotype threat）——即仅仅意识到别人对你抱有的刻板印象，就会显著降低你在相关领域的表现——对我来说是一个全新且令人震撼的认知（推荐阅读 Claude Steele 的《Whistling Vivaldi》）。我和几乎所有共事过的经理都曾经坚信，冷启动 sourcing（主动猎头）是没用的，完全是浪费时间。后来我们制定了一套流程并严格执行，结果却令人尴尬地证明它对我们所有人一直都很有效。这是一个让人谦卑的例子：你对一个看似合理但完全错误的信念可能抱有极强的信心。最重要的 inclusivity（包容性）举措是什么？是为大家提供一条可以私下申请重要角色和机会的结构化流程。不过大家学得很快：如果通过这个流程争取到的机会最终没能成功或获得认可，大家就不会再申请了。每次组建评审小组、工作组、团队时，都要养成习惯去反思这个组的成员构成，以及你是怎么挑选他们的。（这正是我们开发角色/机会申请结构化流程的原因和方法。）组建多元化的团队很容易变成公司里 URMs（underrepresented minorities，代表性不足的少数群体）的“第二班工作”。当我们邀请这些人参与时，我们在道德上就有义务把这份工作转化为“第一班工作”，并在绩效评估、晋升等环节给予认可。Alignment（对齐）和 consensus（共识）是两件完全不同的事。共识是一种缓慢的达成对齐的机制；而对齐的核心是沟通和倾听不同观点，如果你们已经有既存的关系和沟通机制，对齐可以非常迅速。在一个不断扩张的组织里，能持续在团队内部和跨团队之间保持对齐，是卓越的标志。“达成对齐所需的时间”就是你衡量重组是否成功的指标。

基础设施

AWS 和 GCP 正在吞噬内部基础设施，我们需要提供超越云服务的差异化价值。目前的机会在哪里？安全、合规、语言专项工具、维护的基础镜像、CI 的易用性和速度、多地域部署、架构模式（例如 Kappa 架构）等。
其中大部分机会在 2-3 年内就会消失：CI 的易用性和速度（所有云厂商都在大力投入的领域）、多地域部署（GCP 正在尝试“multi-region first”）、架构模式（新应用默认就会采用）。安全、合规和语言专项工具相对不容易被单一方案取代，目前仍能保持差异化。把 GCP 和 AWS 相互竞价，已经成为 GCP 的核心营销策略之一：他们希望在商品化功能的质量上取胜。GCP 的流式处理产品看起来是业界最佳，但作为内部基础设施提供者，我们仍然不应该贸然采用有差异化的云服务，这导致其采用速度受限于 AWS 何时能提供有竞争力的替代方案。gRPC/Protobuf 生态已经抢走了 Thrift/Finagle、AVRO 等大部分关注度。gRPC 以及随之而来的 HTTP/2，将是未来的主流库和协议。HTTP/2 仍然是最酷、却最未被充分利用的新基础设施原语之一。我们现在有了双向流（bi-directional streams）！是时候多用起来了。CloudFlare、Akamai 等公司似乎正面临被云厂商商品化的严重威胁。Fastly 提供完整 VCL 能力的方案目前仍然有趣，也是一个巧妙的差异化护城河。非常有趣且令人兴奋的是，DDoS 缓解正在成为云服务的默认工具包之一。我不太确定这个功能如何与现有产品很好地结合（比如你真的能把 DDoS 缓解单独卖出去吗？），但如果云厂商反正都要提供，那把现有容量转售出去的成本可能几乎为零。Kubernetes 生态正在胜出，而且非常出色，但编排（orchestration）似乎正在被云厂商商品化。容器生命周期依然是最困难的部分。我依然坚信 k8s 是实现云无关性的关键工具。（GCP 的策略是靠价值取胜，因此降低迁移成本是其核心策略之一。）（Julia Evans 写过一篇很棒的文章，讲述我们如何在 Stripe 推广 Kubernetes。）Terraform 是个优秀的工具，但它还不够有主见、也不够受限，没能实现我曾经对它跨云可移植性的美好愿景。我觉得这里有一个很大的空白机会，或许甚至可以基于 TF 再造一个工具来实现。（顺便说一句，AWS 或 GCP 怎么还没收购 HashiCorp？）Envoy 是我 2017 年意外发现的新技术，也是 Xooglers（前 Google 员工）和前 Twitter 员工想要重温他们工具梦的最后几个基础设施组件之一。开发者生产力相关的组件仍然被封闭在墙后，这感觉是高采用率开源项目中最大的机会之一。流式计算似乎注定会成为 从 Lambda 到 Kappa 及 Dataflow 范式。只要不可变事件（immutable events）能获得 traction，流式处理就会成为可扩展计算的统一范式。（另一种说法是：streaming 是新的 NoSQL。）
