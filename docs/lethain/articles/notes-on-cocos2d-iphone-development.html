Cocos2d iPhone 开发笔记

2008-10-03 · 阅读原文

最近我一直在使用 Cocos2d iPhone 库进行 iPhone 游戏开发，这是一个非常棒的开发库。尽管网上可供参考的源码并不多，但我还是整理了一些代码片段和使用心得。

Cocos2d iPhone 概述

Cocos2d iPhone 是 Ricardo Quesada 将 Cocos2d 库移植到 Objective-C 的版本。原始版本实际上是一个 Python 库，非常优秀。ObjC 移植版无法在 REPL 中运行，因此在“强烈优秀”程度上稍逊一筹，但它依然是解决 iPhone 游戏开发难题的良药。

在开发我的第一款游戏 Processed Tower Defense 时，我在这个项目中学到了大量知识。我对它进行了几次重构，采用了更好的设计，到后期我感觉自己终于开始打开了游戏编程那扇通往神奇而罕见领域的大门。因此，当我开始在 iPhone 上开发游戏时，第一步就是将我整体的设计从 JavaScript 移植到 ObjC。虽然两者之间存在一些……不匹配的地方，但总体进展还算顺利。直到我们遇到了 OpenGL，那感觉就像徒步时碰到一群臭鼬堵住了小径。你当然可以硬着头皮走过去，但，真的非得这么做吗？

iPhone 上关于 OpenGL 的文档并不丰富，这开始阻碍项目进展。我猜现在的文档对那些已经精通 OpenGL 的人来说足够了，这或许才是他们预期的受众，但我却被彻底难住了。这是个不小的问题。幸运的是，睿智的 Luke Hatcher 建议我们放弃我自己搭建的那个临时框架，转而使用 Cocos2d iPhone。于是乎，开箱即用，Cocos2d 就已经把我辛苦积累的游戏知识（以及更多）巧妙地集成到了一个连贯的框架中。

之后的故事就成了历史，尽管是一段没人知道也没人在意的历史。

关键类

CocosNode 是你将要使用的最重要的类。 如果一个对象需要 a) 移动、b) 显示 或 c) 发生变化， 那么你应该用 CocosNode 来表示它。CocosNode 最有用的方法包括： // 创建 +(id)node; // 添加子节点 -(id)add: (CocosNode)node; -(id)add: (CocosNode)node z:(int)z; -(id)add: (CocosNode)node z:(int)z name:(NSString)name; // 获取子节点 -(CocosNode)get: (NSString )name; // 移除子节点 -(void)remove: (CocosNode)node; -(void)removeByName: (NSString)name; // 调度周期性更新 -(void)schedule: (SEL)s interval:(ccTime)i; // 执行动作（移动、动画等） -(Action)do: (Action)action; -(void)stopAction: (Action*)action; -(void)stopAllActions; 使用示例大致如下： // 创建 CocosNode * parentNode = [CocosNode node]; CocosNode * childNode = [CocosNode node]; CocosNode * childNode2 = [CocosNode node]; // 连接 [parentNode add:childNode z:0 name:@"childOne"]; [parentNode add:childNode2]; // 访问 [parentNode get:@"childOne"]; // 使用动作 [parentNode do:[ScaleTo actionWithDuration:.1 scale:1.5]]; cpVect point = cpv(50,100); [parentNode do:[MoveTo actionWithDuration:0.5 position:point]]; // 断开连接 [parentNode removeByName:@"childOne"]; [parentNode remove:childNode2]; 利用 CocosNode 最常见的方式是继承它，添加自定义的 init 方法，并调度一个函数定期执行。一个简单的示例如下： #import "CocosNode.h" @interface LogNode : CocosNode {} -(void)tick: (ccTime)dt; @end @implementation LogNode -(id)init { self = [super init]; if (self) { [self schedule:@selector(tick:) interval:100]; } return self; } -(void)tick: (ccTime)dt { NSLog(@"%@", self); } @end Sprite 是 CocosNode 的子类，它让图形显示变得非常简单。用法如下： NSString * img = @"spaceship.png"; Sprite * sp = [Sprite spriteFromFile:img]; sp.position = cpv(100,24); [someNode add:sp]; 你会大量使用 Sprite。根据我的经验，更简单的方式是继承 CocosNode 并将 Sprite 添加到其中，而不是直接继承 Sprite。这样做还有一个好处，就是你可以将多个图像组合到一个节点下，通过变换父节点来统一变换它们。 Action 是施加在 CocosNode 上的变换。有多种动作，分为两组：IntervalAction（间隔动作）和 InstantAction（瞬时动作）。顾名思义，IntervalAction 在一段时间内发生（当然你可以把时间设为 0 秒让它立即发生），而 InstantAction 则是立即执行。 一些常用的动作包括： ToggleVisibility 让 CocosNode 显示或隐藏。 RotateBy 旋转 CocosNode 一定角度。 MoveTo 将 CocosNode 移动到指定位置。 ScaleTo 按比例缩放 CocosNode。 FadeTo 设置 CocosNode 的透明度。 使用方式如下（部分动作的构造器参数略有不同，请查阅文档）： [parentNode do:[ScaleTo actionWithDuration:.1 scale:1.5]]; [parentNode do:[MoveTo actionWithDuration:0.5 position:cpv(50,100)]]; Director 负责管理当前可见的内容、正在运行的场景、游戏时间是否推进等。 常用方法有： // 它是单例 Director * d = [Director sharedDirector]; // 管理游戏 [d pause]; [d resume]; [d end]; // 管理场景 Scene * s = [Scene node]; [d runScene:s]; // 开始场景中的时间流逝 [d popScene]; [d pushScene:s]; [d replaceScene:s]; // 性能推荐用法 Layer 是容纳一个或多个 CocosNode 的容器。 作为 CocosNode 的子类，它用于将应用的不同部分分组。例如，你会有一个主菜单 Layer、游戏 Layer（至少一个，根据游戏复杂度可能会有多个）、暂停菜单 Layer 等等。 用法与 CocosNode 相同，只是初始化时使用 [Layer node] 而不是 [CocosNode node]。 这也是一个你会经常继承的类。 Scene 是包含一个或多个 CocosNode 的集合，通常会包含若干 Layer。它们被传递给 Director 来决定当前游戏中可见和发生的内容。 Scene * myScene = [Scene node]; Sprite * bg = [Sprite spriteFromFile:@"background.png"]; bg.position = cpv(200, 600); [myScene add:bg z:0]; Layer * myLayer = [MyCustomLayer node]; [myScene add:myLayer z:0]; [[Director sharedDirector] runScene:myScene]; Label 用于渲染文字，它让这个过程比 iPhone 上其他文字渲染方案简单得多。 Label * name = [Label labelWithString:@"Name" dimensions:CGSizeMake(90,64) alignment:UITextAlignmentCenter fontName:@"Helvetica" fontSize:10]; name.position = cpv(100,200); [someNode add:name];

Cocos2d 中当然还有其他许多类，但上面这些大概是你创造有趣作品时需要交互的全部了。

为所有需要响应点击的对象重写标准的 UIEvent touches 方法。 - (void)touchesBegan:(NSSet *)touches withEvent:(UIEvent *)event; - (void)touchesMoved:(NSSet *)touches withEvent:(UIEvent *)event; - (void)touchesEnded:(NSSet *)touches withEvent:(UIEvent *)event; 或者只为一个对象（通常是 Layer 的子类）重写 touches 方法，让它作为所包含所有对象的 UI 管理器。
