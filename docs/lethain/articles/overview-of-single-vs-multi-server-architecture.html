单服务器与多服务器架构概述

2009-02-16 · 阅读原文

每当我发布配置 Django 服务器的教程时，总会有人问我是如何选择 Nginx 和 Apache 的多服务器方案，而不是其他众多替代方案。这个问题主要包含两个部分：

为什么采用多服务器方案，而不是单服务器方案？为什么特别选用 Nginx、Apache 和 mod_wsgi，而不是 Nginx + mod_python、fcgi、Lighttpd 等其他组合？

本文将重点解答第一个问题：为什么使用多服务器架构来部署 Django 项目？

系统组件说明

在服务器配置中存在多种可相互替代的组件，本文讨论中具体使用哪种组件并不特别重要。更准确地说：

当我提到 Nginx 时，它可以是任何轻量级 HTTP 服务器，比如 Lighttpd，甚至是精简配置的 Apache。当我提到 Apache 和 mod_wsgi 时，也可以是 Apache + mod_python，或者运行 FCGI 的 Nginx。总之就是任何用于提供 Django 项目的服务器。Postgres 是我选择的 relational database，但你也可以换成 MySQL 或 SQLite。在本文讨论范围内，甚至使用 CouchDB 也没问题。缓存方面我提到了 memcached，虽然它的直接竞争者不多，但如果有其他类似方案，也可相互替换使用。

单服务器方案

部署 Django 项目最简单的方式是配置一台服务器同时处理动态内容（Django 渲染的页面）和静态内容（图片、CSS、JavaScript 等）。

单服务器方案最大的优势在于其简单性。尤其是 Apache（其他系统也类似），针对上述配置的搭建非常快速和轻松（我个人觉得 Nginx + fcgi 稍显复杂，但同样可以实现）。

另一个优势是你只需同时运行一个服务器进程，而服务器通常会占用较多内存和 CPU，尤其是在资源有限的小型 VPS 环境下。

然而，当网站需要扩展以应对更高负载时，单服务器方案就显得有些笨拙。和其他方案一样，你可以通过购买更强大的 VPS 或服务器来进行垂直扩展，但在通过升级硬件提升容量不再划算时，问题就会逐渐显现。

到了那个阶段，通常第一步是将数据库迁移到第二台机器，这比较容易实现。但当你需要为动态或静态内容增加更多容量时，这种架构就显得不够灵活。此时你唯一的选择就是添加负载均衡器后面的额外机器。

实际部署中你可能会将 Postgres 放在单独的机器上。

总的来说，单服务器方案在资源有限的环境中可能是最高效的选择，配置也相对简单，但它必须用同一套配置同时提供静态和动态内容，因此随着需求增长可能会产生效率问题（下文会进一步讨论）。

多服务器方案

任何读过 mod_python 使用教程的人可能都见过“fat threads”（胖线程）这个术语，它是描述启用 mod_python 后 Apache 工作线程的流行说法。这是因为每个 mod_python 工作线程都需要关联一个 Python 解释器，导致每个线程大约消耗 20MB 内存。

这么做有充分的理由，而且 mod_python 在处理动态请求时速度极快，因此这个成本是值得的。但是，为什么要让一个重型线程去服务静态文件呢？使用轻量级线程就足够了。此外，我们如何防止数量相对较少的重量级线程被慢速连接占用，从而导致能服务的并发用户减少？

对这个问题的标准答案是使用一个轻量级服务器作为用户的第一接触点，负责提供静态资源，并将动态内容的请求代理到第二台服务器上的重量级线程。

多服务器方案的核心论点是：专业化能带来效率。通过让一台服务器专门处理动态内容，我们可以调整其设置以最大化该任务的性能。让另一台服务器专门处理静态内容，同样也能对其进行针对性优化。

除了“专业化带来优化”这一论点外，多服务器方案相比单服务器方案还有另一个重要优势：能够更轻松地实现高效扩展。由于我们将不同职责分离，因此可以非常容易地在恰好需要的地方增加容量，从而实现高效扩展。

只需进行少量的配置文件修改，你就可以从简单的单机模式切换到多机模式。如果你的瓶颈主要在动态内容服务上，这个过程会尤其简单。

诚然，这种架构需要 Nginx 同时承担反向代理和静态文件服务器的角色，如果静态文件服务的吞吐量超过单台机器所能提供的上限，你就需要转向服务器池方案（这也彻底完成了职责分离）。

在一定程度上，垂直扩展（购买更高配置的 VPS 或服务器）比水平扩展要容易得多，因此应该始终作为首选。但当垂直扩展不再具有成本优势时，多服务器方案提供了极大的灵活性，并且由于专业化分工，每台服务器都能获得更高的性能收益。

归根结底，在单服务器和多服务器方案之间并不存在绝对的对错之分。虽然多服务器方案最终会超越单服务器方案的性能，但在资源非常有限的情况下，它也可能会表现得不如单服务器方案。

尽管如此，我使用多服务器方案的经验非常积极，即使在资源极其有限的情况下（VPS 只有 256MB 内存），效果也很好。所以——如果你愿意多做一些配置工作——我个人推荐从一开始就采用多服务器架构。

当然，我认为这两种方案在配置便利性上的优势，都会被配置整个系统的复杂性（防火墙、SSH 等）所抵消。只要有一定经验和可靠的参考资料，无论是单服务器还是多服务器方案，配置起来都不是特别困难。
