从 Every 的 Compound Engineering 中学习

2026-01-19 · 阅读原文

我使用的为数不多的原生 AI 产品之一是 Cora.computer，它能帮我总结个人收件箱里的邮件。虽然它并不完美，但比起我之前用的一堆过滤规则，它在应对日益泛滥的垃圾邮件和非 solicited 邮件时，表现要好得多。

我在使用 Cora 时遇到了一些问题，于是开始关注 Every 的团队成员并向他们反馈。后来，我注意到了他们在 compound engineering（复合工程）方面的工作，特别是 compound-engineering-plugin 这个项目。

Compound Engineering 由四个模式组成：两个极为知名、一个中等知名，还有一个许多从业者已经凭直觉在使用、但尚未找到一致实现机制的模式。这些模式分别是：

  1. Plan is decoupling implementation from research. This is well understood, e.g. Claude’s plan mode, although it can certainly be done better or worse by being more specific about which resources to consult (specs, PRDs, RFCS, issues, etc)
  2. Work is implementing a plan. This is well understood, and the core of agentic coding. Again, this can be done better or worse, but much of that depends more on the quality of your codebase, tests, and continuous integration harness than the agent itself
  3. Review is asking the agent to review the changes against your best-practices, and identify ways it could be improved. I think most practitioners have some version of this, but standardization is low, even within a given company.
  4. Compound is asking the agent to summarize its learnings from a given task into a well-defined, structured format (basically a wiki) which is consulted by future iterations of the plan pattern. This interplay between the compound and plan steps creates the compounding mechanism.Many practitioners are implicitly compounding, but it’s often done manually through their own work. For example, I’d often ask the agent to update our AGENTS.md or skills based on a specific problem encountered in a task, but it required my active attention to notice the issue and suggest incorporation.

把这四个步骤放在一起看，并没有什么惊世骇俗之处，但它是一种极其有效的方法，能把这些凭直觉形成的最佳实践，转化为公司内部具体、可落地、且基本自动化的流程——只需要增加几个命令（比如 workflow:plan、workflow:review 等），并更新 AGENTS.md 来告诉 Agent 何时以及如何使用这些命令。

在 Imprint 的前端和后端 monorepo 中实现这个方案非常顺利，只花了大约一个小时。大部分时间都花在打磨最后一些细节上，比如我们希望把计划文件统一放在 .claude/plan-*.md 格式，以匹配现有的 .gitignore 规则，整个过程并不复杂。最重要的是，这件事解放了一个让团队里很多工程师（包括我自己）一直在寻找标准答案的话题。现在我们有了统一的做法，可以继续去解决下一个问题了。

如果说最近的历史能给我们一点指引，那么一个合理的猜测是：compound engineering 中的许多实践，会在未来几个月内被吸收到 Claude Code 和 Cursor 的工作流中。到那时，主动使用这些技巧的人，和完全不知道自己在用这些技巧的人，体验将变得没有区别。但我们拭目以待。在此之前，这仍是一个成本很低、却非常有价值的实验，你可以在一小时内就把它部署起来。
