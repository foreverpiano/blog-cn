LifeFlow 0.91 发布

2008-07-07 · 阅读原文

比我预想的发布时间晚了大约三周，LifeFlow 0.91 终于准备好发布了。本次更新包含多项小的改进，让 LifeFlow 变得更加易用和灵活。代码也在多个地方得到了优化，尽管仍有许多地方值得进一步改进。下面我们先来看看主要的功能改进和变化。

  1. Added support for incorporating snippets of non-Markdown markup into entries, including Textile, ReST, and HTML.   2. Rageev Sebastian contributed an excellent patch to the code syntax highlighter, so that it now works properly at non-base levels of indention. This means that code syntax highlighting can now play nicely within lists (like the example just below), as well as any other tomfoolery you might attempt.This also means that adding syntax coloring to an existing Markdown document is now far simpler. Instead of reindenting all code to be relative to the base level of indentation, it is sufficient to add @@ common-lisp (or whatever the appropriate language lexer is) at the beginning of the indention block, and add @@ at the end of the indention block.
  3. Added support for line numbering for syntax colored code snippets. To take advantage of this functionality simply add table or inline following the language declaraton for a syntax colored block. For example @@ ruby table or @@ java inline. Respectively table and inline look like this:andI realize the number-line alignment is a bit off for the table line numbers, but I am slightly baffled at what is causing it (even playing dirty didn't help me conquer this CSS). Also, I am well aware that the inline version is completely unfriendly about copy-pasting. The line numbering is being done by exposing a bit more of Pygment's functionality, as opposed to an implementation of my own, so I am still considering how to go about improving upon these options.
  4. Courtesy of Luke Hatcher, RSS Feeds now include the date and time they were published.
  5. Pre and code tags now use fixed width fonts, fixing one of many braindead CSS problems. (And contributing to the CSS odities in the table based syntax coloring line numbers.)
  6. Improved the quality of the inlined help for LifeFlow specific Markdown extensions and for generic Markdown as well. It still has a ways to go, but at this point its helpful enough that I find myself consulting it for some of the LifeFlow specific magery.
  7. A number of template and CSS tweaks to improve the appearance of the forward facing pieces of LifeFlow. Many of these were inspired by commentary and suggestions by Kenneth Arnold.
  8. Can edit comments in LifeFlow Editor.
  9. Can edit the current Django site within LifeFlow Editor. The Django site is used for defining the URL used in certain components of the framework (such as RSS feeds).
  10. Can modify sites to ping (typically blog aggregators such as Ping-O-Matic, but could be almost anything you want to notify of your entry being published. from within LifeFlow Editor.
  11. Lots of refactoring and general improvements of the quality of code. This goes from the simple like using a regex based sluggify method suggested by Peter Burns, to replacing numerous instances of manual pagination with the QuerySetPaginator. There are still some pain spots in the code, in particular models.py still performs the awkward 'double save' in order to properly setup many to many relationships which are necessary for rendering articles' markup. That said, the quality of the code is moving in a better direction, and will continue to improve.

可下载的 Zip 包

虽然获取 LifeFlow 的推荐方式仍然是从它的 Git 仓库获取（下面会说明），但从现在起我也会提供各版本的 zip 压缩包。这些 zip 包包含两个目录：

  1. A project directory, which will include a standard Django project with LifeFlow setup.
  2. A lifeflow directory, which will include the Lifeflow project.

从仓库克隆

你可以访问 GitHub 上的 Git 仓库获取 LifeFlow 的最新版本。如果你还没有尝试过 Git，在电脑上搭建它可能会有些麻烦（至少对我来说是这样，因为 OSX 包管理器里的版本都没能成功安装），但非常值得。

最快速上手当前版本的方式是下载上面的 zip 文件，但不要执行第二步（不要把 zip 里的 lifeflow 文件夹加入 Python 路径），而是直接从 git 仓库克隆一份：

git clone git://github.com/lethain/lifeflow.git

然后将克隆下来的 lifeflow 文件夹添加到你的 Python 路径。这样你就可以非常方便地修改本地副本。如果你做出了任何有趣或有帮助的修改，请将你的仓库公开，我会拉取并整合这些改动（或者你也可以使用 git send-email，尽管相关文档看起来有点吓人）。

即将到来的变化和改进

LifeFlow 0.92 将是一个有趣的版本，重点将放在我暂时称为“文本巫术”（更准确地说可能是文本处理或简称为文本相关功能）上。核心在于为文本预处理器和后处理器添加便捷的钩子，让有进取心的用户能够扩展 LifeFlow，对他们的文本进行几乎任何处理。一个例子是为首次出现的特定术语自动创建指向 Wikipedia 的链接。这些想法目前还在草图阶段，但应该会打开一大片全新的可能性。

更远的未来计划中的其他功能包括：加入多种用户权限模型（先从编辑者、作者和管理员开始），以支持复杂的多用户工作流，以及对 LifeFlow Editor 进行清理，使其更加一致且更易使用。
