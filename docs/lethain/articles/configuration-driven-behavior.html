配置驱动的行为

2012-11-25 · 阅读原文

构建 构建技术杠杆 不仅仅是实现系统和工具，它还是一个探索系统设计如何催生出可复用、灵活且实用的工具的机会。我们发现的最有趣的系统设计理念之一，就是配置驱动的行为。

它的核心思想是：编写程序去处理描述行为的配置，而不是直接在程序中硬编码行为。这种模式在很多地方都会出现：

Django 的中间件、我最近拼凑的提取库，以及在 Hadoop 流水线中配置 MapReduce 的场景。

让我们更仔细地看看这个模式的例子，讨论它的优势，最后再谈谈它的适用性。

这个模式的一个典型例子，是我们在 Digg 构建的提交文章分类器，用于识别垃圾信息和低质量内容。该系统由以下部分组成：

多个分类器，它们接收数据和用于评估的指标；一个工作流，负责将数据和指标传递给各个分类器；以及一个配置系统，用于选择要运行哪些分类器、它们的运行顺序，以及传递给初始化函数的参数值。

其高层实现大致如下：

:::python
import importlib
import config_store

class Classifier(object):
    def __init__(self, **kwargs):
        self.kwargs = kwargs

    def classify(self, data):
        return True

class Workflow(object):
    def __init__(self, classifiers):
        self.classifiers = classifiers

    def run(self, data):
        for classifier in self.classifiers:
            if classifier.classify(data):
                return classifier.__class__.__name__

def init_classifier(class_path):
    params = config_store.get("classifier.%s" % class_path, {})
    class_path_parts = class_path.split()
    class_ref = importlib.import_module(class_path_parts[:-1])
    return class_ref(**params)

def setup():
    classifier_class_names = config_store.get("classifiers", [])
    classifiers = [init_classifier(x) for x in classifier_class_names]
    wf = Workflow(classifiers)

    # assuming we have some kind of blocking generator which will
    # return data when available
    for data in data_to_classify:
        classification = wf.run(data)
        print "Classified as: %s" % classification

if __name__=="__main__":
    setup()

如果某个分类器开始表现不佳，我们就从配置机制中移除它；如果研究团队有一个实验性的新分类器，直接把它加进配置即可。

在这两种情况下，我们都能通过调整初始化参数来轻松调节行为，同时它也将分类结果暴露给社区管理团队，通过他们的改进建议形成反馈闭环。

配置驱动方法最大的优势在于让实验变得轻量级。

我们构建的系统本身并不具有内在价值，只有当它们被用于完成有意义的工作时才有价值。当我们为系统注入一定程度的通用性并降低实验门槛后，就能为他人和未来的自己创造意想不到的收获。

当系统的用户学会了一种设计良好的配置机制后，他们就可以利用底层系统，而无需深入理解系统本身。如果配置语言足够简化——比如采用 YAML 格式——那么用户群体将从开发者一下子扩展到更大范围的人群。

根据我的经验，降低系统实验门槛可能是让它带给你新奇且意想不到收获的最有效方式。

实验的便捷性让你更容易从系统中获得全部价值，而维护的便捷性则让你有更多时间去构建新的系统，而不是成为已有系统的奴隶。

当行为被描述在配置中后，绝大部分长期维护工作就被转移到了维护处理配置的核心上，而这个核心通常很小且相对简单。如果设计得当，这个核心也会极易测试，因为它的接口被配置语言严格定义。

适用性

配置驱动行为这类理念的挑战（也是风险）在于，为当前代码以及我们预期的未来形态选择正确的抽象层次。如果写得过于耦合当前需求，我们很快就要重写它，却收获不到多少收益；如果过于抽象，则会花费太多时间，或者最终因为解决的问题不对而仍需重写。

就抽象程度而言，我认为这个理念在高低两个方向上都能很好地扩展。在小的尺度上，我们可以用字典或列表来指挥行为，而不是硬编码数值；在大的尺度上，我们可以解析一个领域特定的配置语言。

我的经验法则是：花一分钟尝试找到一种用数据结构描述当前工作的方式来驱动代码。如果能找到，就采用它；如果找不到，就继续按常规方式实现。

最后用 extraction 库中的两个相似例子来收尾，其中一个符合配置驱动行为的方法，另一个则不符合。在第一个代码片段中，从 Facebook Open Graph 标签中提取数据的模式非常直接，因此我用一个映射来驱动行为：

:::python
property_map = {
    'og:title': 'titles',
    'og:url': 'urls',
    'og:image': 'images',
    'og:description': 'descriptions',
    }

def extract(self, html):
    "Extract data from Facebook Opengraph tags."
    extracted = {}
    soup = BeautifulSoup(html)
    for meta_tag in soup.find_all('meta'):
        if 'property' in meta_tag.attrs and 'content' in meta_tag.attrs:
            property = meta_tag['property']
            if property in self.property_map:
                property_dest = self.property_map[property]
                if property_dest not in extracted:
                    extracted[property_dest] = []
                extracted[property_dest].append(meta_tag.attrs['content'])

    return extracted

在另一个代码片段中，处理 link 标签的过程要复杂得多，我找不到合理的方式用数据结构描述我的意图。因此我放弃了用数据结构描述工作，而是直接用代码字面地描述了它：

:::python
def extract(self, html):
    "Extract data from meta, link and title tags within the head tag."
    extracted = {}
    soup = BeautifulSoup(html)
    for link_tag in soup.find_all('link'):
        if 'rel' in link_tag.attrs:
            if ('alternate' in link_tag['rel'] or \
                link_tag['rel'] == 'alternate') and \
               'type' in link_tag.attrs and \
               link_tag['type'] == "application/rss+xml" \
               and 'href' in link_tag.attrs:
                if 'feeds' not in extracted:
                    extracted['feeds'] = []
                extracted['feeds'].append(link_tag['href'])
            elif ('canonical' in link_tag['rel'] or \
                  link_tag['rel'] == 'canonical') \
                 and 'href' in link_tag.attrs:
                if 'urls' not in extracted:
                    extracted['urls'] = []
                extracted['urls'].append(link_tag['href'])
                
    return extracted

总的来说，这是一个很好的模式，最近在我参与的多个项目中都得到了应用。在设计下一个项目时，不妨考虑一下它。
