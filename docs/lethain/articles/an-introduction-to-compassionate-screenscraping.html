善意网页抓取入门

2008-08-10 · 阅读原文

网页抓取（Screen scraping）是用程序自动从网站提取数据的技巧。如果你觉得它很有用：确实如此。如果你觉得它很难：其实不然。而如果你认为写得不周到的脚本很容易把网站管理员惹恼，那你说得太对了。本教程不仅讲网页抓取，更强调负责任的、社会性的网页抓取。它是将你想要的数据和“己所不欲，勿施于人”原则结合在一起的产物，读完它会让互联网变得更好。

我们将在本教程中使用 Python，并借助 httplib2 和 BeautifulSoup 库来让事情尽可能简单。稍后我们会介绍如何搭建环境，但首先要说几句关于友善的话。

网站会崩溃。它们看起来漂亮、可靠且稳定，但一只蝴蝶在某处扇动翅膀，它们就可能直接坠入地狱。对小型网站来说，“地狱”就是彻底崩溃；而对大型网站来说，更常见的是性能显著变慢。无论哪种情况，扇动翅膀的蝴蝶总是意料之外的流量激增，而这种流量尖峰常常是不顾他人的网页抓取器直接导致的。

在我的博客中，我收到的错误报告几乎都来自搜索引擎那些过于热情的网络爬虫（这可能是最常见的屏幕抓取器种类）。早期，我经常被一个小型研究爬虫骚扰，它的作者几乎无法联系上。它常常因为发起的 HTTP 请求超出我小型 VPS 的承受能力而导致崩溃。编写那个抓取器的程序员没有考虑周到，结果造成了麻烦。

这就引出了我关于负责任网页抓取的唯一规则：抓取器的流量应该与普通人类流量无法区分。遵循这条规则，我们就不会给被抓取的网站带来过度的压力，而且还有额外的好处——我们能避免被限流或阻止抓取的行为。我们将用几条指导原则帮助脚本伪装成人类行为：

疯狂地使用缓存。尤其是当你要抓取的数据量相对较小时（而且你的电脑有足够内存），应该尽可能保存并复用结果。错开 HTTP 请求。虽然并行发出所有请求能让你更快完成，但网站不会喜欢。即使你按顺序发送请求，也可能造成相当大的冲击。相反，应该让请求之间间隔一小段时间。每次请求间隔几秒钟，就能确保不会制造麻烦。只获取你需要的内容。在网页抓取时，人们很容易想把所有东西都抓下来，因为页面在那里就多抓几页。但这既浪费他们的带宽，也浪费你的时间，所以请先列出你想提取的数据清单，并严格遵守。

现在，带着这三条指导原则，让我们开始网页抓取吧。

安装所需库

首先我们需要安装 httplib2 和 BeautifulSoup 库。最简单的方法是使用 easy_install。

sudo easy_install BeautifulSoup
sudo easy_install httplib2

如果你尚未安装 easy_install，则需要从它们的项目页面下载：httplib2 和 BeautifulSoup。

选择抓取目标

现在我们开始抓取。我们打算从简单入手，逐步构建一个简单且有分寸的 HackerNews 抓取库。第一步是要考虑我们想提取哪些数据。HackerNews 的网页界面如下所示：

因此，仅加载首页我们就能从每条故事中提取大量数据：标题、链接、社会评分、发布者、发布时间以及评论数量。每页显示 30 条内容，所以只需获取一页，我们就能收集到相当多的数据。

最简单的情况

使用 httplib2 和 BeautifulSoup，从 HackerNews 提取我们需要的数据既快速又简单。简单到只需在解释器里输入几条命令即可：

>>> import httplib2
>>> from BeautifulSoup import BeautifulSoup
>>> conn = httplib2.Http(".cache")
>>> page = conn.request(u"http://news.ycombinator.com/","GET")
>>> page[0]
{'status': '200', 'content-location': u'http://news.ycombinator.com/', 'transfer-encoding': 'chunked', 'keep-alive': 'timeout=3', 'connection': 'Keep-Alive', 'content-type': 'text/html; charset=utf-8'}
>>> # page[1] contains the retrieved html.
... 
>>> soup = BeautifulSoup(page[1])
>>> titles = soup.findAll('td','title')
>>> titles = [x for x in titles if x.findChildren()][:-1]
>>> subtexts = soup.findAll('td','subtext')
>>> stories = zip(titles,subtexts)
>>> len(stories)
30
>>> stories[0]
(<td align="right" valign="top" class="title">1.</td>, <td class="subtext"><span id="score_272314">38 points</span> by <a href="user?id=yangyang42">yangyang42</a> 5 hours ago  | <a href="item?id=272314">8 comments</a></td>)

关于标题的那部分写得有些绕。class 为 “title” 的样式同时被用于包含条目序号（例如 1. 或 15.）的 td 标签，以及包含故事标题和链接 a 标签的 td 标签。但我们只需要后一种，因此要过滤掉那些没有子标签的 td。同时我们还排除了过滤后列表的最后一个结果，因为最后一个包含指向下一页 30 条的 “More” 链接，它本身并不是一篇故事。

所以我们已经非常接近目标了，但数据目前还不是很容易使用的格式。让我们试着把它整理成可用的形式。目前每条故事是一个由两个 Tag 对象组成的二元组：

>>> stories[0]
(<td class="title"><a href="http://sethgodin.typepad.com/seths_blog/2008/08/the-secret-of-t.html">The secret of the web (hint: it's a virtue)</a><span class="comhead"> (sethgodin.typepad.com) </span></td>, <td class="subtext"><span id="score_272314">38 points</span> by <a href="user?id=yangyang42">yangyang42</a> 5 hours ago  | <a href="item?id=272314">8 comments</a></td>)

我真正想要的是一个包含所有这些数据的字典。首先让我们弄清楚如何提取每一部分数据：

>>> s = stories[0]
>>> s[0].findChildren()[0]['href']
u'http://sethgodin.typepad.com/seths_blog/2008/08/the-secret-of-t.html'
>>> s[0].findChildren()[0].string
u"The secret of the web (hint: it's a virtue)"
>>> s[1].findChildren()[0].string
u'38 points'
>>> s[1].findChildren()[1].string
u'yangyang42'
>>> s[1].findChildren()[2].string
u'8 comments'
>>> s[1].findChildren()[2].string.split(" ")[0]
u'8'

好了，除了“故事发布于多久之前”之外，我们已经知道怎么获取其他所有内容了。到目前为止我们一直在使用 findChildren 方法来遍历标签树，但还有一个 contents 属性，它可以同时访问标签和字符串。

>>> s[1].contents
[<span id="score_272314">38 points</span>, u' by ', <a href="user?id=yangyang42">yangyang42</a>, u' 5 hours ago  | ', <a href="item?id=272314">8 comments</a>]
>>> s[1].contents[-2].split(" ")
[u'', u'5', u'hours', u'ago', u'', u'|', u'']
>>> s[1].contents[-2].strip().split(" ")
[u'5', u'hours', u'ago', u'', u'|']
>>> s[1].contents[-2].strip().split(" ")[0]
u'5'

不过实际上，最简单的做法可能是直接使用正则表达式来提取这个信息。

>>> import re
>>> txt = unicode(s[1])
>>> txt
u'<td class="subtext"><span id="score_272314">38 points</span> by <a href="user?id=yangyang42">yangyang42</a> 5 hours ago  | <a href="item?id=272314">8 comments</a></td>'
>>> DATE_RE = re.compile(" (?P<qty>\d+) (?P<unit>\w+) ago ")
>>> DATE_RE.findall(txt)
[(u'5', u'hours')]
>>> txt = DATE_RE.findall(txt)[0]
>>> txt
(u'5', u'hours')
>>> u"%s %s" % (txt[0],txt[1])
u'5 hours'

现在让我们把这些整合成一个提取函数：

>>> def extract_story(data):
...     d = {}
...     d['link'] = data[0].findChildren()[0]['href']
...     d['title'] = data[0].findChildren()[0].string
...     d['score'] = data[1].findChildren()[0].string
...     d['poster'] = data[1].findChildren()[1].string
...     d['num_comments'] = int(data[1].findChildren()[2].string.split(" ")[0])
...     d['time'] = " ".join(data[1].contents[-2].strip().split(" ")[:2])
...     return d
... 
>>> extract_story(s)
{'title': u"The secret of the web (hint: it's a virtue)", 'poster': u'yangyang42', 'time': u'5 hours', 'score': u'38 points', 'link': u'http://sethgodin.typepad.com/seths_blog/2008/08/the-secret-of-t.html', 'num_comments': 8}

这里只有一个小的缺陷，那就是当某条故事的评论数为零时，显示的是 “discuss” 而不是 “0 comments”。我们可以很快修复它，改进后的函数如下：

def extract_story(s):
    d = {}
    d['link'] = s[0].findChildren()[0]['href']
    d['title'] = s[0].findChildren()[0].string
    d['score'] = s[1].findChildren()[0].string
    d['poster'] = s[1].findChildren()[1].string
    try:
        d['num_comments'] = int(s[1].findChildren()[2].string.split(" ")[0])
    except ValueError:
        d['num_comments'] = 0
    d['time'] = " ".join(s[1].contents[-2].strip().split(" ")[:2])
    return d

确实有点丑，但并不复杂，很好理解。

缓存，缓存，还是缓存

现在让我们稍稍回退，看看如何在获取页面时表现得更有分寸。我们最初的页面获取代码是这样的：

>>> import httplib2
>>> from BeautifulSoup import BeautifulSoup
>>> conn = httplib2.Http(".cache")
>>> page = conn.request(u"http://news.ycombinator.com/","GET")

让我们创建一个辅助函数来帮我们处理这些细节。

import httplib2
from BeautifulSoup import BeautifulSoup
SCRAPING_CONN = httplib.Http(".cache")
def fetch(url,method="GET"):
return SCRAPING_CONN.request(url,method)
page = fetch("http://news.ycombinator.com/")

这并没有真正改进多少，但它为我们加入缓存打开了大门。

import httplib2,time
from BeautifulSoup import BeautifulSoup
SCRAPING_CONN = httplib2.Http(".cache")
SCRAPING_CACHE_FOR = 60 * 15 # cache for 15 minutes
SCRAPING_CACHE = {}
def fetch(url,method="GET"):
key = (url,method)
now = time.time()
if SCRAPING_CACHE.has_key(key):
data,cached_at = SCRAPING_CACHE(key)
if now - cached_at < SCRAPING_CACHE_FOR:
return data
data = SCRAPING_CONN.request(url,method)
SCRAPING_CACHE[key] = (data,now)
return data
# Fetch the page.
page = fetch("http://news.ycombinator.com/")
# Fetch the page again, but use cached copy.
page = fetch("http://news.ycombinator.com/")

现在我们每十五分钟最多获取一次每个独立页面，这将有助于减少对服务器的压力。

错开请求

现在，假设我们想要抓取每条故事所指向的文章。使用我们新的 fetch 函数，这非常容易实现：

>>> pages = [fetch(x['link']) for x in stories]

在这种情况下，每条故事可能位于不同的服务器上，因此错开请求并不那么重要，但让我们假设它们都在同一台服务器上（例如，如果我们想抓取每条故事的评论页）。我们可以修改 fetch 函数，让它在发出请求时更有分寸：

import httplib2,time
from BeautifulSoup import BeautifulSoup
SCRAPING_CONN = httplib2.Http(".cache")
SCRAPING_CACHE_FOR = 60 * 15 # cache for 15 minutes
SCRAPING_REQUEST_STAGGER = 1.1 # in seconds
SCRAPING_CACHE = {}
def fetch(url,method="GET"):
key = (url,method)
now = time.time()
if SCRAPING_CACHE.has_key(key):
data,cached_at = SCRAPING_CACHE[key]
if now - cached_at < SCRAPING_CACHE_FOR:
return data
time.sleep(SCRAPING_REQUEST_STAGGER)
data = SCRAPING_CONN.request(url,method)
SCRAPING_CACHE[key] = (data,now)
return data

做了这个修改后，它会尽可能快地返回缓存数据，但会对任何新的请求进行错开处理。不过这还不够完善，我们真正想要的是按域名进行错开，而不是对每个请求都做全局错开。

import httplib2,time,re
from BeautifulSoup import BeautifulSoup
SCRAPING_CONN = httplib2.Http(".cache")
SCRAPING_DOMAIN_RE = re.compile("\w+:/*(?P<domain>[a-zA-Z0-9.]*)/")
SCRAPING_DOMAINS = {}
SCRAPING_CACHE_FOR = 60 * 15 # cache for 15 minutes
SCRAPING_REQUEST_STAGGER = 1100 # in milliseconds
SCRAPING_CACHE = {}
def fetch(url,method="GET"):
key = (url,method)
now = time.time()
if SCRAPING_CACHE.has_key(key):
data,cached_at = SCRAPING_CACHE[key]
if now - cached_at < SCRAPING_CACHE_FOR:
return data
domain = SCRAPING_DOMAIN_RE.findall(url)[0]
if SCRAPING_DOMAINS.has_key(domain):
last_scraped = SCRAPING_DOMAINS[domain]
elapsed = now - last_scraped
if elapsed < SCRAPING_REQUEST_STAGGER:
wait_period = (SCRAPING_REQUEST_STAGGER - elapsed) / 1000
time.sleep(wait_period)
SCRAPING_DOMAINS[domain] = time.time()
data = SCRAPING_CONN.request(url,method)
SCRAPING_CACHE[key] = (data,now)
return data

现在我们有了一个方便且有善意的 fetch 函数。接下来我们可以写和之前一样“野蛮”的代码：

>>> pages = [fetch(x['link']) for x in stories]

即使所有故事都在同一个域名下，它也不会再猛烈轰击任何服务器了。相反，它会依次下载故事，并且会遵守对同一域名 1.1 秒的请求间隔。这个工具还可以从很多方面继续改进（并行下载等），但我们已经建立了一个不错的基础，可以放心大胆地使用，而不用把这种大胆强加给别人。

整合代码

把我们写过的代码整合起来，我们就能写一个简单且有分寸的脚本：每五分钟显示 HackerNews 上按评论数排序的热门故事，但每十五分钟最多只抓取一次页面。

import httplib2,time,re
from BeautifulSoup import BeautifulSoup
SCRAPING_CONN = httplib2.Http(".cache")
SCRAPING_DOMAIN_RE = re.compile("\w+:/*(?P<domain>[a-zA-Z0-9.]*)/")
SCRAPING_DOMAINS = {}
SCRAPING_CACHE_FOR = 60 * 15 # cache for 15 minutes
SCRAPING_REQUEST_STAGGER = 1100 # in milliseconds
SCRAPING_CACHE = {}
def fetch(url,method="GET"):
key = (url,method)
now = time.time()
if SCRAPING_CACHE.has_key(key):
data,cached_at = SCRAPING_CACHE[key]
if now - cached_at < SCRAPING_CACHE_FOR:
return data
domain = SCRAPING_DOMAIN_RE.findall(url)[0]
if SCRAPING_DOMAINS.has_key(domain):
last_scraped = SCRAPING_DOMAINS[domain]
elapsed = now - last_scraped
if elapsed < SCRAPING_REQUEST_STAGGER:
wait_period = (SCRAPING_REQUEST_STAGGER - elapsed) / 1000
time.sleep(wait_period)
SCRAPING_DOMAINS[domain] = time.time()
data = SCRAPING_CONN.request(url,method)
SCRAPING_CACHE[key] = (data,now)
return data
def extract_story(s):
d = {}
d['link'] = s[0].findChildren()[0]['href']
d['title'] = s[0].findChildren()[0].string
d['score'] = s[1].findChildren()[0].string
d['poster'] = s[1].findChildren()[1].string
try:
d['num_comments'] = int(s[1].findChildren()[2].string.split(" ")[0])
except ValueError:
d['num_comments'] = 0
d['time'] = " ".join(s[1].contents[-2].strip().split(" ")[:2])
return d
def fetch_stories():
page = fetch(u"http://news.ycombinator.com/")
soup = BeautifulSoup(page[1])
titles = [x for x in soup.findAll('td','title') if x.findChildren()][:-1]
subtexts = soup.findAll('td','subtext')
stories = [extract_story(s) for s in zip(titles,subtexts)]
return stories
while True:
stories = fetch_stories()
stories.sort(lambda a,b: cmp(a['num_comments'],b['num_comments']))
stories.reverse()
for s in stories:
print u"[%s cmnts] %s (%s) by %s, %s ago." % (s['num_comments'],s['title'],s['link'],s['poster'],s['time'])
print u"\n\n\n"
time.sleep(60 * 5)

关于 Httplib2 的题外话

你可能很早就注意到，在初始化我们用来发送请求的 httplib2.Http 对象时，做了一些和缓存有关的操作。初始化代码如下：

import httplib2
SCRAPING_CONN = httplib2.Http(".cache")

这里发生的事情是，httplib2 能理解 HTTP 缓存指令，如果服务器提供了适当的缓存指令，它就会在本地缓存并复用这些数据。因此，在我们自己写的缓存层之下，还有额外的一层缓存，这使得整个体系比我们自己拼凑的还要再友好一些。

这绝不是什么邪恶的事情。人们对网页抓取进行限流，是因为要应对那些不顾他人、消耗大量带宽和其他有限资源（CPU 负载等）的抓取器。不过请记住，当你使用本地内存存储数据时，Python 解释器的不同实例无法共享这些数据，因此如果你的 Web 服务器在多个解释器实例上运行这样的脚本，那么它每十五分钟就会为每个解释器实例获取一次页面（如果你持续尝试获取数据的话）。在这种情况下，你最好使用类似 memcached 这样的工具，让不同实例能够共享它们的缓存。
