慈悲的屏幕抓取入门

2008-08-10 · 阅读原文

屏幕抓取（Screen scraping）是一门通过程序自动从网站提取数据的艺术。如果你觉得它很有用：确实如此。如果你觉得它很难：其实不然。而如果你觉得用考虑不周的脚本很容易惹恼网站管理员，那你说得太对了。本教程不仅教你如何进行屏幕抓取，更重要的是如何以负责任的方式进行。它是将你想要的数据与“黄金法则”相结合的产物，读完它将会让网络变得更美好。

我们将在本教程中使用 Python，并借助 httplib2 和 BeautifulSoup 库来让整个过程尽可能简单。我们稍后会讨论如何设置环境，但首先要说几句关于如何友善行事的话。

网站会崩溃。它们看起来漂亮、可靠且稳定，但只要某处一只蝴蝶扇动翅膀，它们就会瞬间坠入地狱。对小型网站来说，“地狱”就是彻底崩溃；而对大型网站而言，则更多是性能变得迟缓。不管哪种情况，扇动翅膀的蝴蝶总是意料之外的流量激增，而这种流量峰值往往是欠考虑的屏幕抓取程序直接导致的。

在我的博客中，我收到的错误报告几乎都来自搜索引擎中过于狂热的网络爬虫（这可能是最普遍的一种屏幕抓取程序）。早期，我经常被一个小型研究爬虫骚扰，其所有者几乎无法联系上。它常常因为发起的 HTTP 请求超过我的小型 VPS 所能承受的范围而导致网站崩溃。编写这个抓取程序的程序员不够体贴，从而引发了各种问题。

这引出了我关于负责任屏幕抓取的唯一规则：抓取程序产生的流量应当与人类流量无法区分。遵循这条规则，我们就能避免给被抓取的网站带来过大压力，而且额外的好处是，我们还能避免被限流或阻止屏幕抓取。我们将使用几条指导原则来帮助脚本模拟人类行为：

积极使用缓存。特别是当你抓取的数据量相对较小时（而且你的计算机有充足内存），你应该尽可能保存并重复使用已获取的结果。错开 HTTP 请求。虽然并行发出所有 HTTP 请求能加快你的速度，但网站并不会感谢你。然而，即便你按顺序发出请求，也可能造成相当大的冲击。相反，应该让请求之间间隔一小段时间。每次请求之间间隔几秒，就能确保不会引发问题。只获取你需要的内容。在屏幕抓取时，人们很容易想要抓取一切，因为页面就在那里就不断下载更多页面。但这既浪费他们的带宽，也浪费你的时间，所以请列出你想要提取的数据清单，并严格遵守。

现在，带着这三条指导原则，让我们开始屏幕抓取吧。
