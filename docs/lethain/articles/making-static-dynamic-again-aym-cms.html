让静态网站重新动起来；AYM CMS

2008-09-15 · 阅读原文

写完上一篇博客文章后，我决定采纳自己的建议，为这类使用 build.py 构建脚本的静态 CMS 网站创建了一个模板项目文件夹。

你可以在这里下载模板的 zip 压缩包，或者在这里克隆 GitHub 仓库。

我决定把它叫做 AYM CMS，AYM 代表 “Ain't Yo Momma's”（这可不是你妈妈的那套）。或者也可以是 “All Your Mess”（你的一团乱麻）。或者别的什么都行。咱们就按 Git 的方式来吧——你想让它代表什么它就代表什么。它简短好打，这似乎才是最重要的……

AYM CMS 为你提供什么

使用 Django 模板的全部威力来构建你的静态网站。从模板继承、默认的 Django 模板标签和过滤器，到添加你自己的自定义标签/过滤器，一切皆可。放在 images/ 目录下的所有图片都会自动生成缩略图。它还会把所有图片加载到一个列表和一个字典中，并注入到模板上下文里供渲染使用。 {% for image in images %} <a href="{{ image.image }}"> <img src="{{ image.thumbnail }}" alt="{{ image.filename }}"> </a> {% endfor %} {% with images_dict.my_pic as image %} <img src="{{ image.thumbnail }}"> {% endwith %} 只需把文件放入 static/ 目录，它们就会被复制到 deploy/static 文件夹中，同时保留子文件夹结构。 两个自定义模板标签，让编写静态内容变得更快、更强大：markdown 和 syntax。 markdown 会把包裹的文本渲染为 Markdown 格式。用法如下： {% load aym %} <p> I love templates. </p> {% markdown %} Render this **content all in Markdown**. >> Writing in Markdown is quicker than >> writing in HTML. Or at least that is my opinion. What about you? {% endmarkdown %}

如果 AYM CMS 使用中遇到任何问题，欢迎告诉我。 它的目标是成为一个通用的构建脚本，用于创建复杂的静态网站。我认为它已经是一个非常够用的解决方案（如果我再大胆一点，甚至可以说是一个优秀的解决方案）。

我知道现在大家都热衷于花哨的动态网站，但我想我们大多数人还是要维护一些静态网站（或者在开发更复杂系统时先搭一个临时的静态站点）。AYM CMS 可以在这个虽小却重要的细分领域里发挥很好的作用。
