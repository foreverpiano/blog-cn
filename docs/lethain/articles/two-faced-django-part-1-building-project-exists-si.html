双面 Django（上）：构建一个同时存在于 Facebook 和网页上的项目

2007-12-04 · 阅读原文
  • 你可以在这里找到该项目的在线演示版本，包括网页界面和 Facebook 界面。

最近我花了大量时间研究 Django 和 PyFacebook。虽然网上有一个还算不错的 PyFacebook 入门教程，但从邮件列表的一些评论来看，大家似乎更需要一篇更全面的实战指南。

本系列文章将以 Django 官方教程那样清晰、循序渐进的风格，带你一步步构建一个 Django 应用，让它同时作为普通的网页应用和 Facebook 应用存在。网页版和 Facebook 版将使用相同的数据库和相同的模型，因此使用其中一个界面的用户可以和另一个界面的用户进行互动。

同时，本着资本主义和创业精神，我们打算“入侵” Django 官方教程的地盘，打造一个更强大、更好的玩具投票应用。此时此刻，硅谷的风险投资家们正因为这些投票应用而为他们的钱包瑟瑟发抖——大概是这么个意思。

接下来，让我们看看在接下来一到三个小时内我们将完成哪些内容：

  • Building models that we will share between the web app and the Facebook app.
  • Using generic views to avoid writing as much code as possible.
  • Templates using both HTML and FBML (Facebook Markup Language) for rendering our content.
  • Ajax using both Facebook's Javascript, and the JQuery javascript library.
  • Using the Django testing framework to bring Test Driven Development to the web.
  • Using newforms to validate data, as well as represent it.

本系列不幸无法覆盖以下内容：

  • How to adapt command line instructions to a Windows. I don't have a Windows box to play with.
  • Setting up mod_python or any other deployment mechanism on your server.

本教程将涉及很多内容，但不用担心，它并不要求你有太多先备知识。只要你有一个终端、安装了 Python 和 Subversion，我们就能一起完成这个过程。

现在，让我们开始吧。

安装 Django

我们要做的第一件事是安装 Django。我们将使用 Django 的 SVN 版本，撰写本文时是 6794 版。所以先来获取一份拷贝。首先，进入你希望存放该库的目录。

我个人通常放在类似“/Users/will/django/”这样的目录下。但这完全是个人的风格选择。选好一个目录，进入其中，然后输入：

svn co http://code.djangoproject.com/svn/django/trunk/ django-trunk

这会将 Django 主干（trunk）的最新版本签出到一个名为“django-trunk”的文件夹中。

现在我们需要告诉 Python Django 在哪里。要做到这一点……我们得先知道 Python 在哪里。所以先来看看：

python -c "from distutils.sysconfig import get_python_lib; print get_python_lib()"
/Library/Frameworks/Python.framework/Versions/2.4/lib/python2.4/site-packages

你机器上的库位置可能略有不同，没关系。现在让我们教 Python 如何找到 Django。

ln -s `pwd`/django-trunk/django /Library/Frameworks/Python.framework/Versions/2.5/lib/python2.4/site-packages/django

这会在你的 site-packages 文件夹中创建一个符号链接，这样 Python 就能像一开始就安装了这个包一样使用它。

让我们确认一下是否成功了。启动 Python……

python -v

（-v 参数会让 Python 输出非常详细的信息，这在实际使用解释器时有点烦人，但现在我们只是检查 import 是否成功，所以问题不大。）现在尝试导入 Django。

>>> import django
import django # directory django
# django/__init__.pyc matches django/__init__.py
import django # precompiled from django/__init__.pyc

如果配置不正确，你会看到如下错误：

>>> import django
Traceback (most recent call last):
  File "<stdin>", line 1, in ?
ImportError: No module named django

如果出现这种情况，请重新阅读上面的步骤，找出哪里出了问题，然后再试一次。

安装 PyFacebook

现在我们要用同样的步骤来安装 PyFacebook。

svn checkout http://pyfacebook.googlecode.com/svn/trunk/ pyfacebook

python -c "from distutils.sysconfig import get_python_lib; print get_python_lib()"
/Library/Frameworks/Python.framework/Versions/2.4/lib/python2.4/site-packages

ln -s `pwd`/django-trunk/django /Library/Frameworks/Python.framework/Versions/2.5/lib/python2.4/site-packages/django

python

  4. Make sure it worked.

然后……

import facebook

只要没有抛出 ImportError，就说明你已经正确配置好了一切。

设置我们的项目文件夹

首先我们需要创建一个新的 Django 项目：

django-admin.py startproject polling

（如果 django-admin.py 不在你的 PATH 中，你就需要用相对路径或绝对路径来调用它。它位于“django-trunk/django/bin/django-admin.py”，但你得记得自己把 django-trunk 签出到了哪里。）

现在进入项目目录

cd polling

我们的项目就这样诞生了。现在我们要创建三个应用，每个应用负责项目中不同的部分。

我们的三个应用分别是：

  1. core: will hold our models, and all code that is not specific to either the web app or the Facebook app.
  2. web: will hold all code and resources specific to our web app.
  3. fb: will hold all code and resources specific to our Facebook app.

现在让我们创建这些应用。

python manage.py startapp core
python manage.py startapp web
python manage.py startapp fb

PyFacebook 提供了一些用于设置 Facebook 专用 Django 应用的工具，但不是特别好用，所以我们还是自己来搭建。

设置我们的 fb 应用

首先请[下载这个文件][middleware_replacement]并放到 polling/fb 目录下。这里有更详细的解释，它本质上是我编写的一组简单函数，用来避免使用 PyFacebook 的中间件。把它保存为 helpers.py，所以最终它应该位于

polling/fb/helpers.py

好了。现在我们打开并编辑 fb 目录下的 views.py 文件。

emacs polling/fb/helpers.py

（坦白说：用别的编辑器其实也没问题。虽然我不能正式推荐。）

你需要把下面这些 import 语句都加进去：

from django.http import HttpResponse, HttpResponseRedirect
from django.views.generic.simple import direct_to_template
from django.shortcuts import get_object_or_404
from django.utils import simplejson
from polling.fb.helpers import *
from polling.core.models import *

保存文件，暂时先把它放在一边。

在 polling/urls.py 中引入我们新建的应用

幸运的是，在 polling/urls.py 中引入新应用非常简单。首先打开它……

emacs polling/urls.py

然后修改成下面这样：

from django.conf.urls.defaults import *
urlpatterns = patterns('',
    (r'^admin/', include('django.contrib.admin.urls')),
    (r'^facebook/', include('polling.fb.urls')),
    (r'^', include('polling.web.urls')),
)

保存后，我们暂时不用再碰 urls.py 了。

为模板创建一个文件夹……

进入 pollings 文件夹，现在我们要创建一个地方来存放所有即将创建的模板。

mkdir templates
mkdir templates/fb
mkdir templates/web

记住这些文件夹应该位于 polling/templates、polling/templates/fb 和 polling/templates/web。稍后我们在编辑 settings.py 文件时会告诉 Django 到哪里去找它们。

一点枯燥的内容：settings.py

好吧，这个标题可能有点夸张，这其实不是我设置 Django 项目时最喜欢的部分。幸运的是，它也不会花太长时间。我保证会和你一样坚持到底。

在 settings.py 中我们需要处理两组内容：通用的 Django 设置，以及为 PyFacebook 准备的配置项。配置 PyFacebook 相对简单，我们就从它开始。

你需要将以下全局变量（随便贴在文件里的任何位置都可以，不用太讲究）添加到你的 polling/settings.py 文件中。*请注意，你需要把前面的值改成真实值，这些值可以通过 Facebook 的 Developer 应用获取。*

FACEBOOK_API_KEY = '11111111111111111111111111111111111'
FACEBOOK_SECRET_KEY = '11111111111111111111111111111111111'
FACEBOOK_APP_NAME = "application_name"
FACEBOOK_INTERNAL = True
FACEBOOK_CALLBACK_PATH = "/facebook/"

没什么太多可解释的，但 callback path 设置为“/facebook/”，是因为我们在 polling/urls.py 中把 fb 应用包含在了这个路径下。

现在让我们继续配置 settings.py 文件的其他部分。

我们将使用 SQLite 作为数据库（我们现在是在开发环境，不是生产环境）：

DATABASE_ENGINE = 'sqlite3' 
DATABASE_NAME = '/Users/will/django/polling/poll.db'

你需要把数据库名称改成你系统上的真实路径，最好放在我们正在工作的 polling 文件夹内。

ADMIN_MEDIA_PREFIX = '/admin_media/'

我们稍后会设置开发用的媒体服务器，并使用 /media/ 前缀，所以不希望有冲突。

TEMPLATE_DIRS = ('/Users/will/django/polling/templates/')

像往常一样，你需要修改路径，使其指向你文件系统中 polling 文件夹的实际位置。

最后，安装我们的应用。

INSTALLED_APPS = (
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.sites',
    'django.contrib.admin',
    'polling.core',
    'polling.web',
    'polling.fb',
)

由于我们所有的模型实际上都放在 polling.core 中，所以其实不需要把 polling.web 和 polling.fb 也加入 INSTALLED_APPS，但为了保持一致性，我们还是加上比较好（而且如果我们不加，以后在一个应用里添加了模型却发现没被检测到，可能会非常困惑）。

呼，终于搞定 settings.py 了。

使用 Django 开发服务器提供媒体文件

再次强调，正如我之前提到的，我们正在搭建的是开发环境，而不是生产环境。我们会用开发服务器来提供媒体文件，仅仅是因为它非常方便：这绝不是一个适用于真实世界静态文件服务的合适方案。

好了，警告说完，我们开始吧。

首先我们需要创建几个文件夹（从 polling 文件夹内开始）：

mkdir media
mkdir media/web
mkdir media/fb

然后我们需要短暂地打开 polling/urls.py 并修改成下面这样：

from django.conf.urls.defaults import *
urlpatterns = patterns('',
(r'^media/(?P<path>.*)$', 'django.views.static.serve', {'document_root': '/Users/will/django/polling/media/'}),
(r'^admin/', include('django.contrib.admin.urls')),
(r'^facebook/', include('polling.fb.urls')),
(r'^', include('polling.web.urls')),
)

像往常一样，/Users/will/django/polling/media/ 这个路径需要修改成你自己 polling 文件夹的实际位置。

设置工作……完成了

如果你不想自己一步步做所有修改，[这里有一个我配置好的压缩包][polling1]。你仍然需要编辑 polling/settings.py 和 polling/urls.py，把路径改成你系统上的正确位置。

做了这个小修改之后，我们终于完成了所有的设置工作。休息一下，喝杯茶，等你准备好了再回来继续第二部分，我们将开始构建模型。
