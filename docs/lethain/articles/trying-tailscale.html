试用 Tailscale

2023-01-04 · 阅读原文

和 2014 年大多数基础设施工程师一样，我非常喜欢 Google 的 BeyondCorp 白皮书。我个人最直接的兴趣点在于，当时 Uber 的安全实现里并没有使用 VPN，因此看到一篇思路清晰的文档，讲述如何在不依赖高安全网络的情况下为员工设备提供防护，实在很有意思。我还有第二个更长期的个人兴趣，那就是再也不想和同事争论为什么访问安全资源前必须先登录 VPN。

出于这两个原因，我一直带着兴趣关注 Tailscale，并专门抽时间搭建了一个个人 Tailscale 环境，还部署了他们的 Golink 工具来实际体验一番。下面就是我在这过程中的笔记。

初始设置

我通过定价页面上的“Use Tailscale”按钮注册，选择了免费的 Personal 计划。随后需要选择身份提供商，我选了 Google。

接下来，网站提示我为电脑下载 OS X 客户端，把我带到了 App Store，整个安装过程快速且直观。然后我在手机上打开注册邮件，它链接到了移动客户端下载页面，我也顺利安装好了。

手机设置完成后，网站自动刷新，显示了第二台设备，并提示我发送一个 ping。

非常令人兴奋的是，这竟然真的成功了！这是一次真正令人愉快的设置体验。短短几分钟内，我几乎无需任何复杂配置，就私密地连接了两台设备。

通过 VPN 暴露本地端口

基础功能跑通后，我想测试通过 VPN 连接我博客的本地实例。首先快速验证一下直连是行不通的。

curl 100.80.28.56:1313
 curl: (7) Failed to connect to 100.80.28.56 port 1313 after 3 ms: Connection refused

这很合理，因为博客绑定在 localhost 上，而不是外部可访问的以太网接口。我们来改一下配置，把

hugo -D serve

改成

hugo -D --bind 0.0.0.0 serve
 Web Server is available at http://localhost:1313/ (bind address 0.0.0.0)

现在再试一次 curl：

curl 100.80.28.56:1313 | head -n2
 <!DOCTYPE html>
 <html lang="en-us">

成功了！我们再从手机上验证一下，这可能是更有意思的测试：同样能正常访问！不过 Hugo 自身的所有链接都无法正常工作，因为它们使用了指向 localhost 的绝对 URL，但那是 Hugo 的问题（估计谷歌几分钟就能解决），而不是 Tailscale 的问题。挺棒的！

能用更友好的 DNS 吗？

手动输入 100.80.28.56 还是有点烦人，所以我想知道能否获得更友好的 DNS 名称。结果发现这已经可以实现了，比如 some-macbook-pro:1313 就能直接访问我笔记本上跑的博客（虽然让手机 Safari 相信这不是搜索查询花了几次尝试）。（我想这就是“MagicDNS”功能？）

Golinks

好了，目前基础功能已经运行得相当不错，接下来我要搭建他们私有的 go links 服务。我跟着 tailscale/golink 仓库的说明操作。

首先我 clone 了他们的 GitHub 仓库（顺便安利一下让 1Password 管理 ssh-agent 的快乐，尤其是当你的键盘支持 Touch ID 时）：

git clone git@github.com:tailscale/golink.git

然后我在本地构建以验证是否正常：

go run ./cmd/golink -dev-listen :8080

失败了，因为我忘了先 cd 进 golink 目录。于是我在正确路径下重新运行，这次成功了。

为了试用，我创建了一个从 write 指向我用来记录写作主题的 Google 文档的链接，然后访问 localhost:8080/write 验证，它果然按预期跳转了。

下一步是让手机也能访问这个服务，首先要创建一个 auth key。

好吧，在创建 key 之前我需要先创建一个 ACL tag，随机点了一会儿界面后还是不知道怎么弄，看来得去读支持文档。哦不，我得手动编辑 policy 文件才能完成，这有点让人不安。

嗯，看起来成功了！现在回到创建 auth key 的步骤。添加 tag:golink 标签很直观。我唯一不太明白的是，说明里说应该取消 key 的过期时间（但 UI 强制要求设置 1 到 90），不过没关系，先继续往下走。

拿到 key 之后，我用以下命令重启服务：

TS_AUTHKEY="tskey-auth-<key>" go run ./cmd/golink -sqlitedb golink.db

服务干净地启动了，最后的测试是去浏览器访问 go/，看看是否能正常工作。

确实成功了，笔记本和手机都能访问。任务完成！

顺便说一句，当我回到 Machines 标签页时，发现这个服务的 key 过期确实被禁用了，虽然我不知道为什么被禁用，可能是因为我加了 tag？

这绝不是什么致命问题，我相信再深入研究一下就能搞清楚，但这确实是我整个体验中遇到的两个前后不一致的地方之一。

哪些地方比较困惑？

我觉得困惑的所有问题都非常细微，也反映出我是一个完全的新用户。而且我都能快速自行解决，无需寻求帮助，这也说明 Tailscale 整体做得非常出色。尽管如此，为了完整性，我还是列出来：

  1. Why is the expiry disabled on my golinks service? Is it because I added a tag? If so, why does the expiration UI still show up as enabled, if the value there is being ignored?
  2. When I wanted to add a tag to my new auth key, it didn’t direct me towards the resources where I can create a tag. True, it did direct me towards the knowledge base article on the topic, which is OK, but would have loved to have been directed to the policy editor
  3. I find the placement of auth key issuing UI to be a bit counter-intuitive (Setting, Personal Settings, Keys). I expected a link from Access Controls tab to issuing keys.

哪些地方做得很好？

总体而言，我认为 Tailscale 带来了非常愉快的体验。安装迅速，界面直观，正确的文档几乎总是点一下就能找到。最重要的是，它比我设置过的大多数企业 VPN 都更容易自己搞定，同时还能和现有的 SSO 提供商良好配合。

总的来说，如果我要给自己或小企业搭建个人 VPN，我想不到还有什么比 Tailscale 更好的选择了，它真的非常不错。同样，如果我在 2023 年要开发新的开发者或基础设施产品，这种 onboarding（以及整体）体验非常值得借鉴。（我猜一旦开始管理真正的 policy 文件，事情会变得更有趣，但我会留到另一天再探索！）

到目前为止，Tailscale 似乎在 方面做得非常出色，但我很希望看到 Tailscale 更多地展示企业如何利用它来简化安全和合规控制（SOC2、HITRUST 等）。找到一个清晰的价值主张来改进其中某个维度，是他们提高企业采用率最有可能的路径，我认为这对他们的长期增长至关重要。（当然你可以说价格是他们与现有厂商竞争的另一种方式，但是，拜托，我不认为你想在 VPN 市场打价格战。）Stripe 以产品驱动、开发者为中心的增长模式。
