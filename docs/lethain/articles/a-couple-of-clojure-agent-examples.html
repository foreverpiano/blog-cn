Clojure Agent 的几个示例

2009-11-22 · 阅读原文

我已经在工作中每天使用 Erlang 近一年了，当初开始学习 Clojure 时，最先关注的就是 Clojure 的 agent。当时我还挺困惑的。1

Erlang 中的 actor 概念是一个拥有邮箱的进程，它逐个取出并处理消息。actor 进程包含了所有消息处理的逻辑，其行为可以是将消息存入内部队列，也可以是完全忽略该消息。

而 Clojure 的 agent 则反转了消息处理逻辑的所有权：向 agent 提交的是函数，这些函数会被存入邮箱并按顺序执行。

agent 本身只持有状态，而不包含逻辑。

使用 Clojure agent 更像是操作一个数据结构，而不是与某个服务进行交互。2 这很有道理，因为 Clojure agent 是一种机制，用于对特定数据结构实例按顺序执行操作。在分布式计算中，一个简洁且易于理解的顺序修改机制其实非常有用。3

现在我们来看几个相对简单的 Clojure agent 使用示例。

将 Agent 作为消息中继

在最后一个示例中，我们将消息通过 N 个 agent 组成的链进行中继。同时我们还会使用链外的一个 agent 来记录整个链的执行进度。这种日志记录方式让我们只需持有链中第一个 agent 的引用，就能查看整个中继过程的进度，这在分布式系统中是一种相当常见的模式（尽管通常你会使用更接近 RabbitMQ 而非单进程的工具）。

这个示例最有意思的地方大概是使用 agent 向其他 agent 发送 agent，从而形成一个完全异步的编程模型。

此外，虽然这个例子本身相当复杂，但消息中继实际上是一个工作管道的最简版本，其中每个 agent 都会对传入的消息进行一些处理，然后再将其传递给下一个环节。
