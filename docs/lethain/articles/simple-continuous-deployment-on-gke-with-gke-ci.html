在 GKE 上使用 gke_ci 实现简单的持续部署

2017-05-18 · 阅读原文

最近，差不多已经搭建起了一条完整的持续部署流水线，但还差最后一步——从容器构建完成到真正部署上线的环节。于是我写了一个非常小的概念验证工具，叫做 gke_ci，并把它放到了 Github 上。试用 Google Container Engine

这个工具非常非常基础，它的工作原理是订阅 cloud_builds 这个 Pub/Sub 主题，然后调用 Kubernetes API，更新所有使用了该容器镜像的现有 Deployment。由于容器构建次数并不多，每次成功构建时我都会重新发现所有的 Deployment，因此不需要任何“添加服务”的设置流程，新部署的 service 也能自动生效。

我目前以单个实例的 Deployment 方式运行着 gke_ci，有意思的是它居然能升级自己！使用的逻辑和其他构建完全一样：当它看到自己的容器有新构建时，会检测到自身的 Deployment 使用了该容器，从而触发升级。Kubernetes 会先停止当前容器，再启动新版本，此期间 Pub/Sub 中排队的构建会一直等待，直到它重新上线并继续履行职责。

综合来看，在我这个小集群上，从代码 push 到完成完整 rollout，大约只需要 5 分钟左右，而且不需要我一直盯着（rolling rollout 能捕获我遇到过的大多数问题）。不过我后续还是需要增加一个运行测试的构建步骤（如果愿意让容器稍稍“脏”一点，在 Container Builder 里应该很容易实现），以及为构建失败发送通知（直接扩展 gke_ci 本身就可以，因为它已经在监听 cloud_builds 队列了，也可以再写一个简单的工具使用新的订阅）。
