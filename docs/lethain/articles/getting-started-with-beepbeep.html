BeepBeep 入门指南

2009-07-05 · 阅读原文

一位同事（我得找到他那篇隐秘的博客文章，好给他加上链接…… :)）转发给我一封来自 Erlang 邮件列表的关于 BeepBeep 的消息。这个项目看起来相当令人兴奋，因为它结合了我工作中正在使用但还需更多练习的技术——Erlang——并为其增添了一抹熟悉的味道：Django。

本教程将一步步介绍如何安装、创建以及（某种程度上、差不多、但其实不算真正地）部署一个极其简单的 BeepBeep 应用。我无法保证你会立刻被兴奋所淹没，但它将为后续更多精彩的教程铺平道路。

请注意，本教程在很大程度上借鉴了 BeepBeep 的官方文档，如果没有这些文档，这篇教程将无法完成。

在本教程中，我们将构建一个简单的 Web 应用，它会显示随机素数（看来我对 Web 应用的评判标准最近有点降低了），同时展示 BeepBeep 应用的基本组成部分。闲话不多说，让我们开始吧。

安装 BeepBeep

首先，安装 Erlang。在 OS X 上使用 Port 时，可以运行 sudo port install erlang；Debian 系统则可以使用 apt-get install erlang。接下来，从 Git 仓库下载源代码。cd ~/git/ git clone git://github.com/dmitriid/beepbeep.git （在本教程撰写时，最新的提交是 96fb57a58322aa9abd0340755f0c94d6501d223d，日期为 2009 年 7 月 2 日。如果你希望本教程无需修改就能正常运行，建议使用该版本。）第三步，我们需要编译 BeepBeep 源代码。（该 Git 仓库很贴心地将其依赖——MochiWeb 和 ErlyDTL——也一同包含在内。）cd beepbeep make 有点不同寻常的是，代码第一次编译就成功了，并没有遇到需要四处寻找隐藏依赖的问题。

现在，你已经完成了相当轻松的 BeepBeep 安装过程。

创建 BeepBeep 项目

框架安装完成后，下一步就是为我们的新项目创建基础结构。

首先，为 BB_Primes 创建项目脚手架，这是我们正在构建的这个项目非常不聪明的名字。./script/new_beep.erl Primes ../BB_Primes 然后启动新项目的 Web 服务器。cd ../BB_Primes/primes/ make ./stat_server.sh 如果你忘记运行 make 编译代码，可能会得到一个相当笼统的崩溃文件，所以如果出现问题，请先检查这一点。服务器成功启动后，访问 http://localhost:8000 即可看到默认的 BeepBeep 应用页面。现在让我们花点时间看看 new_beep.erl 脚本创建的各种文件和文件夹。deps 目录包含 BeepBeep、MochiWeb 和 ErlyDTL 的源代码，这意味着你无需手动将它们加入 Erlang 路径。这里没什么太多要做的，不过你可能想添加项目所需的其他依赖。ebin 目录存放由 Makefile 生成的编译后文件。这里也没什么太多要做的。support 目录包含 include.mk，这是一个用于 make 的辅助文件。www 目录包含由 MochiWeb 提供的静态文件。（我必须承认，我原本以为生产环境中使用 BeepBeep 会将其隐藏在 Nginx/Lighttpd 后面，只用来提供动态内容，但看来 MochiWeb 本身也是一个不错的静态文件服务器。）views 目录包含用于渲染应用页面的模板。这些模板使用 Django 模板语言编写，并通过 ErlyDTL 进行编译。src 目录包含应用的所有代码，其中有一些对于没有 Erlang 经验的人来说会比较陌生的部分。home_controller.erl 是定义控制器逻辑的地方。对于简单的应用，这是 src 目录中你唯一需要编辑的文件。primes.app 定义了一个 OTP 应用。primes.erl 为 primes.app 定义了启动和停止函数。primes_deps.erl 定义并定位依赖项（我之前其实没见过 X_deps.erl 这样的文件，这对可复用应用来说是个相当不错的主意。）primes_app.erl 启动和停止 primes_sup.erl 监督者应用。primes_sup.erl 为 primes.app 定义了监督者。primes_web.erl 为应用定义了 MochiWeb 服务器。

定制 BeepBeep 项目

在 BeepBeep 项目中，你主要会在三个位置进行修改。

src/home_controller.erl 用于定义 URL 模式和行为。用 Django 的术语来说，它同时扮演了项目中 urls.py 和 views.py 的角色。views/ 目录包含所有模板，由控制器用来向用户展示内容。在 Django 中，这相当于你的 templates/ 文件夹。www/ 目录包含所有静态资源，类似于大多数 Django 项目中的 media/ 文件夹。

一般来说，我建议从一个简单的控制器开始，编写对应的简单视图，然后在两者之间不断迭代，直到达到你想要的结果。最后再添加静态文件。
