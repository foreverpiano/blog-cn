BeepBeep 入门指南

2009-07-05 · 阅读原文

一位同事（得找找他隐藏的博客，好给他加上链接…… :)）转发了一封来自 Erlang 邮件列表关于 BeepBeep 的消息。这个项目看起来相当令人兴奋，因为它将我工作中正在使用但还需要更多练习的 Erlang，与熟悉的 Django 风味结合在了一起。

本教程将带你完成一个极其简单的 BeepBeep 应用的安装、创建以及（某种程度上、差不多、但也不是真的）部署。我不能保证你会立刻兴奋不已，但这将为后续更精彩的教程铺平道路。

请注意，本教程在很大程度上借鉴了 BeepBeep 的官方文档，没有这些文档就不可能完成。

在本教程中，我们将构建一个简单的网页应用，它会显示随机素数（看来我对网页应用的评判标准最近有点降低了），同时展示 BeepBeep 应用的基本组成部分。不再废话，让我们开始吧。

安装 BeepBeep

cd ~/git/
git clone git://github.com/dmitriid/beepbeep.git

cd beepbeep
make
首先，安装 Erlang。在 OS X 上使用 Port 可以执行 sudo port install erlang，Debian 系统则可以使用 apt-get install erlang。接下来，从 Git 仓库下载源代码。（在本教程撰写时，最新的提交是 2009 年 7 月 2 日的 96fb57a58322aa9abd0340755f0c94d6501d223d。如果你希望本教程无需修改就能正常运行，我推荐使用这个版本。）第三，我们需要构建 BeepBeep 源代码。（Git 仓库很贴心地包含了它的依赖——MochiWeb 和 ErlyDTL。）有点不同寻常的是，代码第一次构建就成功了，而且没有遇到任何隐藏的依赖问题。

现在你已经完成了相当轻松的 BeepBeep 安装。

创建 BeepBeep 项目

框架安装完成后，下一步就是为我们的新项目创建基础结构。

./script/new_beep.erl Primes ../BB_Primes

cd ../BB_Primes/primes/
make
./stat_server.sh
首先，为 BB_Primes 创建项目脚手架，这是我们正在构建的这个项目的一个不太聪明的名字。现在启动新项目的 Web 服务器。如果你忘记编译代码，可能会得到一个相当通用的崩溃文件，所以如果出现问题，请先检查这里。成功启动服务器后，访问 http://localhost:8000 查看默认的 BeepBeep 应用页面。现在让我们花几分钟时间，看看 new_beep.erl 脚本创建的各种文件和文件夹。deps 目录包含 BeepBeep、MochiWeb 和 ErlyDTL 的源代码，这意味着你不需要将它们添加到 Erlang 路径中。这里不需要做太多事情，不过你可能会想添加项目所使用的其他依赖。ebin 存储由 Makefile 生成的编译文件。这里也没什么要做的。support 包含 include.mk，这是一个用于 make 的辅助文件。www 包含由 MochiWeb 提供的静态文件。（我必须承认，我原本以为生产环境中使用 BeepBeep 会把它隐藏在 Nginx/Lighttpd 后面，只用它来提供动态内容，但看来 MochiWeb 也是一个不错的静态文件服务器。）views 包含用于渲染应用页面的模板。这些模板使用 Django 模板语言编写，并通过 ErlyDTL 进行编译。src 包含应用的所有代码，包括几个对没有 Erlang 经验的人来说会感到陌生的部分。home_controller.erl 是定义控制器逻辑的地方。对于简单的应用，这是 src 目录中唯一需要编辑的文件。primes.app 定义了一个 OTP 应用。primes.erl 为 primes.app 定义了启动和停止函数。primes_deps.erl 定义并定位依赖项（我以前没见过 X_deps.erl 文件，这对可重用应用来说是个相当不错的想法。）primes_app.erl 启动和停止 primes_sup.erl 监控树应用。primes_sup.erl 为 primes.app 定义了监控进程。primes_web.erl 为应用定义了 MochiWeb 服务器。

定制 BeepBeep 项目

在 BeepBeep 项目中，你主要会在三个位置进行修改。

src/home_controller.erl 是定义 URL 模式和行为的地方。用 Django 的术语来说，它同时充当了项目的 urls.py 和 views.py 文件。views/ 包含所有模板，由控制器用来向用户展示内容。在 Django 中，这相当于你的 templates/ 文件夹。www/ 包含所有静态资源，类似于大多数 Django 项目中的 media/ 文件夹。

一般来说，我建议从一个简单的控制器开始，编写一个匹配的简单视图，然后在两者之间迭代，直到达到你想要的终点。最后再添加静态文件。

按照我自己的建议，首先打开 src/home_controller.erl。找到名为 index 的处理函数，它看起来像这样：

handle_request("index",[]) ->
    {render,"home/index.html",[{data,"Hello There From BeepBeep!"}]};

并将其修改为如下所示：

random_prime(N) ->
    % skipping the logic for finding
    % nth prime to keep things concise ;(
    101.
handle_request("index",[]) ->
N =	random:uniform(100),
SomePrime =	random_prime(N),
{render, "home/primes.html", [{prime, SomePrime}]};

接下来该处理我们的视图了。首先打开 views/base.html。

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN"
       "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="en" lang="en">
<head>
 <meta http-equiv="content-type" content="text/html;charset=UTF-8" />
 <title>Welcome to Primes</title>
 <link href="/stylesheets/style.css" rel="stylesheet" type="text/css"/>
</head>
  <body>
    {% block content %}{% endblock %}
  </body>
</html>

base.html 模板被用作其他模板的脚手架，是支持 Django“Don't Repeat Yourself（不要重复自己）”理念的一种简单方式。我们接下来会将其扩展为 home/primes.html 模板。

{% extends "../base.html" %}
{% block content %}
    <p>Prime is : { { prime }}</p>
{% endblock %}

现在最后再次编译应用。

will-larsons-macbook:primes will$ make
(cd src;make)
erlc -W -I ../include -I ../deps/beepbeep-src/include -pa ../deps/beepbeep-src/ebin -pa ../deps/erlydtl-src/ebin -pa ../deps/mochiweb-src/ebin +debug_info -o ../ebin home_controller.erl
./home_controller.erl:8: Warning: variable 'N' is unused

哎呀，这里有个警告，因为我回退了素数代码的实现，但不是什么重要问题。

现在再次启动服务器：

./start-server.sh

目前它使用的是 www/stylesheets/style.css 中默认的 BeepBeep 样式表，但让我们稍微做一点改变。

emacs www/stylesheets/primes.css

并添加以下样式：

body {
     padding: 25px; 
     background: #333;
     color: #BBF;

然后编辑 views/base.html，将

<link href="/stylesheets/style.css" rel="stylesheet" type="text/css"/>

替换为

<link href="/stylesheets/primes.css" rel="stylesheet" type="text/css"/>

现在重启服务器，

./start-server.sh

重新加载页面，尽情享受你创建的这个非常简单的应用的荣耀吧。

部署

当前的启动脚本在当前的 shell 会话中运行，这对开发来说很好，但对于长期运行的进程来说就不太方便了。你可以对其进行很多改进（在另一个节点启动，使用 heart 运行等），但为了保持本教程的简单风格，只需用 detached 模式运行它即可，这样你就能保留自己的 shell 会话。

cp start-server.sh start-detached-server.sh
emacs start-detached-server.sh

然后将 start-detached-server.sh 修改为如下内容：

#!/bin/sh
cd `dirname $0`
exec erl -pa $PWD/ebin $PWD/deps/*/ebin -boot start_sasl </span>
-s reloader -s primes -detached

如果你希望在注销后进程仍然存在，可以使用 sudo -u 以一个持久的用户身份运行该进程（以 root 运行会有一些非常轻微的安全后果，但你可以使用 www-data 或自定义用户来运行你的 BeepBeep 应用）。

就是这样，一个非常简单的 BeepBeep 应用。诚然，本教程没有给你那种“5 分钟创建一个博客”的框架体验，但请继续关注，我保证下一个 BeepBeep 教程会精彩得多。
