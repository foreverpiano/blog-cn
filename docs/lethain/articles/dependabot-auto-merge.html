自动合并 Dependabot PR

2025-12-18 · 阅读原文

软件开发中一个反复出现的主题就是修复安全问题。目前大多数代码仓库托管服务都具备相当不错的问题报告功能，但许多组织仍然难以及时应用这些修复。上周我们讨论如何降低这个流程的负担时，我突然想到：能不能直接自动合并 GitHub Dependabot 提交的拉取请求呢？

结果证明，答案是肯定的，而且效果非常好。你可以自主控制要自动合并的更新类型（补丁更新、小版本更新、大版本更新等），它也会尊重你设置的自动化检查。如果你有完善的 CI/CD 流程，会运行强制性的代码 lint、类型检查和测试，那么这个方案特别合适。如果你还没有，那么通过这个机制，你可能会在经历一番折腾之后，最终建立起良好的 lint、类型检查和测试体系。

最近几天，我已经在工作中的十几个代码仓库里启用了这套机制。下面以我的博客仓库为例，展示如何搭建同样的流程。

首先，在仓库中创建一个 .github/workflows/dependabot-auto-merge.yml 文件，内容如下：

# Automatically approve and merge Dependabot PRs for minor and patch updates
name: Dependabot auto-merge
on: pull_request

permissions:
  contents: write
  pull-requests: write

jobs:
  dependabot:
    runs-on: ubuntu-latest
    if: github.event.pull_request.user.login == 'dependabot[bot]' && github.repository == 'lethain/irrational_hugo'
    steps:
      - name: Dependabot metadata
        id: metadata
        uses: dependabot/fetch-metadata@v2
        with:
          github-token: "${{ secrets.GITHUB_TOKEN }}"
      - name: Approve Dependabot PR
        run: gh pr review --approve "$PR_URL"
        env:
          PR_URL: ${{ github.event.pull_request.html_url }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
      - name: Enable auto-merge for Dependabot PRs
        if: steps.metadata.outputs.update-type == 'version-update:semver-patch' || steps.metadata.outputs.update-type == 'version-update:semver-minor'
        run: gh pr merge --auto --squash "$PR_URL"
        env:
          PR_URL: ${{ github.event.pull_request.html_url }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

接着进入仓库设置页面（例如 https://github.com/lethain/irrational_hugo/settings），开启仓库的自动合并功能。这仍然会遵守所有必需的分支保护规则，比如必须通过测试、必须获得批准等。

然后确保你为仓库中的 lint、类型检查和测试配置了合适的 status check。

接下来启用 Dependabot（类似 https://github.com/lethain/irrational_hugo/settings/security_analysis）。即使使用默认配置也没问题。

至此就全部完成了。以后 Dependabot 提交的 PR 将会自动合并。当然这里面存在很多细节——我已经遇到过一次因为缺少测试而被自动合并的问题——但我认为这反而是对提升测试质量的有益推动，而不是放弃或退回这个方案的理由。
