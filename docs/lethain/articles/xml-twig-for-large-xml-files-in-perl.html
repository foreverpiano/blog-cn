使用 XML::Twig 处理 Perl 中的大型 XML 文件

2008-11-20 · 阅读原文

上周我还在用 XML::Simple 处理一些简单的 XML 操作任务。这周我需要做同样的事情，但文件大小从 11k 涨到了 80 多兆，我遇到了之前从未处理过的一类问题：真正的大型文件。

你可能会想，一个自称专业开发者的人应该早就经历过这种痛苦，但我没有。这其实是一组挺有意思的问题，因为它会让你开始认真思考时间和空间的限制。出于好奇，我首先尝试直接运行之前写的 XML::Simple 脚本，结果就是长时间等待、占用大量内存，然后放弃。问题在于 XML::Simple 既不使用 SAX 也不使用 DOM 来处理 XML 文件，而是采用友好但低效的“转换为原生数据结构”的方式。虽然在可行的情况下这是我最喜欢的方式，但在面对需要读-改-写的 20 万+ 元素时，用它就好比开着 Barbie 玩具车去参加拆车大赛。

于是我把库从 XML::Simple 换成了 XML::Twig，过渡过程非常愉快。原来读取 80 兆文件要花很长时间，现在读取并写出整个文件大约只需五分钟（如果要做大量处理的话再多加几分钟）；七分钟比“永远完成不了”可要好太多了。内存占用也相当合理，处理这个 80 兆文件时，初始内存大约 10 兆，随着脚本运行时间延长会逐渐增加到 20 兆左右，而 CPU 使用率则稳定在单核接近 100%。

使用 XML::Twig 选择性地遍历树

假设你有一个包含多种不同元素类型的 XML 文件，但你只关心读取其中类型为 server 和 proxy 的元素。

进一步说，你希望打印每个 server 和 proxy 的 ip 地址，文件结构大致如下：

<machines>
    <server>
        <ip>127.0.0.1</ip>
        <name>WeirdNamingSchemeA</name>
    </server>
    <proxy>
        <ip>127.0.0.2</ip>
        <etc>abc</etc>
    </proxy>
</machines>

接下来我们只需要把这些代码串起来：

use XML::Twig;
sub print_ip {
my ($twig, $ele) = @_;
my $ip = $ele->first_child('ip')->text;
print "ip: $ip\n";
}
my $roots = { server => 1, proxy => 1 };
my $handlers = { 'machines/server' => &amp;print_ip,
'machines/proxy'  => &amp;print_ip };
my $twig = new XML::Twig(TwigRoots => $roots,
TwigHandlers => $handlers);
my $twig->parsefile('file.xml');

TwigRoots 参数让你选择要处理哪些元素，而 TwigHandlers 则让你决定如何处理它们。

使用 XML::Twig 修改元素

虽然你可能需要在文档里稍微翻找一下，但使用 handler 函数基本上可以实现你能想到的任何操作。

在这个代码片段中，我们会删除一些子节点，然后插入新的节点。这里只写 handler 函数，周围的代码与上面的例子相同（只需把 $handlers 中的 print_ip 换成 tweak_server 即可）。

sub tweak_server {
  my ($twig, $server) = @_;
  $ip = $server->first_child('ip');
  $server->cut_children;           # remove all children
  $server->del_atts;               # remove all attributes
  $server->set_atts({ ip => $ip}); # adds attributes
# one way to add new nodes…
$server->insert_new_elt('first_child', # position to insert
'processed_by', # name of new element
{ name => "an attribute"}, # attributes
"value"); # inner text
# another way to add new nodes
$ele = new XML::Twig::Elt('a_sub_element');
$ele->paste('first_child', $server);
# print modified node to standard out,
# and remove $server from memory
$twig->flush;
}

虽然不像直接使用原生数据结构那么直观，但它实用且速度很快。

使用 XML::Twig 写入元素

这道大餐的最后一道配料就是把修改后的文件写回磁盘。

use XML::Twig;
my $in = 'in.xml';
my $out = 'out.xml';
open FILE, '>', $out or die "failed to open $out";
sub handle_node {
my ($twig, $ele) = @_;
my $ip = $ele->first_child('ip')->text;
$ele->cut_children;
$ele->set_atts({ ip => $ip });
$twig->flush(*FILE);
}
my $roots = { server => 1, proxy => 1 };
my $handlers = { 'machines/server' => &amp;handle_node,
'machines/proxy'  => &amp;handle_node };
my $twig = new XML::Twig(TwigRoots => $roots,
TwigHandlers => $handlers);
my $twig->parsefile($in);
close FILE;

有了这些例子，你也可以开始编写能在七分钟内处理 80 兆文件的 Perl 脚本了。如果这都不能让你升职，我真不知道什么能。

I think the readline and file paradigm is going to need to be replaced by the chunk and stream approach.Although, making it equally easy to use seems near impossible.↩
