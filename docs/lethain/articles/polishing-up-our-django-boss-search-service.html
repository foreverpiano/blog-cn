完善我们的 Django 与 BOSS 搜索服务

2008-07-12 · 阅读原文

在本系列的第一部分，我们花了一些时间来搭建 Yahoo BOSS Mashup Framework，最后实现了一个极为简陋的搜索服务。如果你没有跟随第一部分进行实践，可以在这里下载我们已开发完成的代码压缩包，但你仍需按照第一部分的说明获取 BOSS App ID。在本系列的第二部分，我们将进一步丰富这个搜索服务：

  1. We're going to let users search either the web, Yahoo News, or images.
  2. We're going to let users page through search results.

让我们开始吧。

扩展 SearchForm

首先，打开 my_search/yahoo_search/views.py 文件，查看其中的 SearchForm。目前它的内容如下：

class SearchForm(forms.Form):
    search_terms = forms.CharField(max_length=200)

现在我们要增加切换搜索类型的能力：

SEARCH_TYPES = (('web','Web'),('news','News'),('images','Images'))
class SearchForm(forms.Form):
search_terms = forms.CharField(max_length=200)
search_type = forms.ChoiceField(SEARCH_TYPES)

改进 search 和 index 函数

接下来我们改进 search 函数，让它接受第二个参数来决定执行哪种类型的搜索。

def search(str, type):
    data = ysearch.search(str,vertical=type,count=10)
    news = db.create(data=data)
    return news.rows

然后更新 index 函数，将 SearchForm 捕获的 search_type 值传递给 search 函数。

def index(request):
    results = None
    if request.method == "POST":
        form = SearchForm(request.POST)
        if form.is_valid():
            search_terms = form.cleaned_data['search_terms']
            search_type = form.cleaned_data['search_type']
            results = search(search_terms,search_type)
    else:
        form = SearchForm()
    return render_to_response('yahoo_search/index.html', {'form': form,'results': results})

现在，运行开发服务器。

python2.5 manage.py runserver

然后访问 http://127.0.0.1:8000/，你会发现现在可以搜索网页、图片或 Yahoo 新闻了。相当不错。接下来我们着手实现搜索结果的分页功能。

为搜索结果实现分页

当你在使用 Django 并想到分页时，应该立刻联想到 Paginator 类，它能很好地处理所有分页的复杂细节。然而，我们当前处理的并非普通的列表（或 QuerySet，否则我们可以使用 QuerySetPaginator），因此需要做一些适配工作。

我们将通过创建一个中间类 BossResultList 来实现，该类会提供 Paginator 所需的部分 Python 列表功能。幸运的是，只需要实现三个方法：__getitem__(self, i)、__getslice__ 和 __len__。在 my_search/yahoo_search 目录下创建一个名为 boss_utils.py 的文件，并在其中写入以下代码：

BossResultList 接收 ysearch_search 的返回结果，并将其伪装成一个列表。这并不是一个完美的抽象，因为它只允许访问初始化时传入的结果子集，但这已足以让我们利用 Paginator。

现在回到 my_search/yahoo_search/views.py，添加两个导入语句：

from django.core.paginator import Paginator
from boss_utils import BossResultList

然后我们调整 search 函数，使其能与新的 BossResultList 良好协作。

def search(str, type, count=10, start=0):
    return ysearch.search(str,vertical=type,start=start,count=count)

这个改动是必要的，因为 BossResultList 需要直接使用返回结果中的某些数据，而这些数据在通过 db.create 转换为数据库对象后就无法保留了。（特别是它需要访问 totalhits 字段，以便告诉用户针对当前搜索词我们可以提供多少页结果。）

在完成搜索应用的更新之前，我们还剩下两个小细节：重构 index 函数，以及更新 index.html 模板。更新模板相对简单，但必须先写好 index 函数，而这需要对函数进行一次较为彻底的重写。由于改动较多，我会先给出完整函数，让你先阅读一遍，然后再对其中几个关键细节进行说明。

def index(request,count=10):
    results,page,total_pages,terms,type = None,None,None,None,None
    if request.method == "GET":
        form = SearchForm(request.GET)
        if form.is_valid():
            page = (request.GET.has_key('page') and int(request.GET['page'])) or 1
            start = (page-1) * count
            terms = request.GET['search_terms']
            type = request.GET['search_type']
            brl = BossResultList(search(terms,type,count=count,start=start))
            paginator = Paginator(brl,count)
            total_pages = len(brl) / count
            results = paginator.page(page)
        else:
            form = SearchForm()
    return render_to_response('yahoo_search/index.html',
                              {'form': form,'results': results,
                               'term': terms,'type': type,
                               'current_page': page,
                               'total_pages': total_pages})

好的，有几点需要说明。

  1. We are now using GET instead of POST. Infact, we never really should have been using POST to begin with. Sorry about that.
  2. Because we are using GET its harder to distinguish between when a user first lands on the page and when they are submitting a search. That is why our response to an invalid form is not to display the error messages generated by newforms, but instead to display an empty form: the only time we'll encounter an invalid form is when a user first comes to the page, and we don't want to greet new users with error messages.
  3. Paginator's page count starts at 1 instead of at 0 which is why we calculate start as (page-1)*count instead of as page*count.
  4. We need total_pages and page because we want to let users know where they are in the midst of the search results. (For example, on page 5 of 412.)

更新 index.html 模板

和 index 函数一样，index.html 模板也进行了大幅度的调整。幸运的是，模板的改动大多不难理解。改版后的模板内容如下：

<html> <head>
<title>My Search</title>
</head>
<body>
<h1>My Search</h1>
<form action="/" method="GET">
<table>
  { { form }}
  <tr><td><input type="submit" value="Search"></td></tr>
</table>
{% if results %}
{% if results.has_previous %}
<a href="?page={ { results.previous_page_number }}&search_terms={ { term|urlencode }}&search_type={ { type|urlencode }}"> Previous </a>
{% endif %}
<span> Page { { current_page }} of { { total_pages}} pages. </span>
{% if results.has_next %}
<a href="?page={ { results.next_page_number }}&search_terms={ { term|urlencode }}&search_type={ { type|urlencode }}"> Next </a>
{% endif %}
<ol>
  {% for result in results.object_list %}
  <li>
  <span class="title">
    <a href="{ { result.clickurl }}">{ { result.title|safe }}</a>
  </span>
  <span class="date"> { { result.date }} </span>
  <span class="time"> { { result.time }} </span>
  <span class="source">
    <a href="{ { result.sourceurl }}">{ { result.source }}</a>
  </span> 
  <p class="abstract"> { { result.abstract|safe }} </p>
  </li>
  {% endfor %}
</ol>
{% endif %}
</body> </html>

最复杂的地方在于处理搜索结果页面的前进和后退。我们在这里大量使用 Paginator 返回的 Page 对象来处理大部分复杂逻辑（在模板上下文中该 Page 被命名为 results），但因为还需要跟踪搜索关键词和搜索类型，所以会稍微复杂一些。
