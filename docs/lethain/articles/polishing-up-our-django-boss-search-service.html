完善我们的 Django 与 Yahoo BOSS 搜索服务

2008-07-12 · 阅读原文

在本系列的第一部分，我们花了不少时间搭建 Yahoo BOSS Mashup Framework，最后实现了一个极其简陋的搜索服务。如果您没有跟着第一部分实践，可以在这里下载我们已完成的代码压缩包，但仍需按照第一部分的说明去申请 BOSS App ID。本系列第二部分，我们将进一步完善这个搜索服务：

我们要让用户能够搜索网页、Yahoo 新闻或图片，并支持对搜索结果进行分页浏览。

让我们开始吧。

扩展 SearchForm

首先，打开 my_search/yahoo_search/views.py，看看里面的 SearchForm。目前它的内容是这样的：

class SearchForm(forms.Form):
    search_terms = forms.CharField(max_length=200)

接下来我们要为其增加切换搜索类型的能力：

SEARCH_TYPES = (('web','Web'),('news','News'),('images','Images'))
class SearchForm(forms.Form):
search_terms = forms.CharField(max_length=200)
search_type = forms.ChoiceField(SEARCH_TYPES)

改进 search 和 index 函数

现在我们来改进 search 函数，让它接受第二个参数，用于决定执行哪种类型的搜索。

def search(str, type):
    data = ysearch.search(str,vertical=type,count=10)
    news = db.create(data=data)
    return news.rows

然后更新 index 函数，将我们通过 SearchForm 获取到的 search_type 值传递给 search 函数。

def index(request):
    results = None
    if request.method == "POST":
        form = SearchForm(request.POST)
        if form.is_valid():
            search_terms = form.cleaned_data['search_terms']
            search_type = form.cleaned_data['search_type']
            results = search(search_terms,search_type)
    else:
        form = SearchForm()
    return render_to_response('yahoo_search/index.html', {'form': form,'results': results})

现在可以运行开发服务器了。

python2.5 manage.py runserver

然后访问 http://127.0.0.1:8000/，你会发现现在可以搜索网页、图片或 Yahoo 新闻了。挺不错的。接下来我们着手实现搜索结果的分页功能。

为搜索结果实现分页

在使用 Django 时，一提到分页，你首先应该想到的是 Paginator 类，它能帮你处理所有分页相关的繁杂逻辑。不过，我们这里处理的不是普通的列表（或 QuerySet，否则就可以直接使用 QuerySetPaginator），所以需要稍作调整。

我们将创建一个中间类 BossResultList，来实现 Paginator 所需的那部分 Python 列表功能。幸运的是，只需要实现三个方法：__getitem__(self, i)、__getslice__ 和 __len__。在 my_search/yahoo_search 目录下创建一个 boss_utils.py 文件，并在其中加入以下代码：

BossResultList 接收 ysearch_search 的返回结果，并将其伪装成一个列表。这种抽象并不完美，因为它只能访问初始化时传入的那部分结果，但已经足以让我们利用 Paginator 了。

现在回到 my_search/yahoo_search/views.py，添加两个导入：

from django.core.paginator import Paginator
from boss_utils import BossResultList

然后修改 search 函数，使其能良好地配合我们新创建的 BossResultList。

def search(str, type, count=10, start=0):
    return ysearch.search(str,vertical=type,start=start,count=count)

这个改动是必要的，因为 BossResultList 需要直接使用返回结果中的某些数据，而这些数据在通过 db.create 存入数据库后就无法保留了。（特别是 totalhits 字段，我们需要用它来告诉用户针对当前查询一共可以提供多少页结果。）

在完成搜索应用的更新之前，还剩下两个小细节：重构 index 函数，并更新 index.html 模板。更新模板相对简单，但必须先写好 index 函数，而这部分需要进行一次较为彻底的重写。因为改动较多，我会先给出完整的函数代码，让你先阅读一遍，然后再对其中几个关键点进行说明。

def index(request,count=10):
    results,page,total_pages,terms,type = None,None,None,None,None
    if request.method == "GET":
        form = SearchForm(request.GET)
        if form.is_valid():
            page = (request.GET.has_key('page') and int(request.GET['page'])) or 1
            start = (page-1) * count
            terms = request.GET['search_terms']
            type = request.GET['search_type']
            brl = BossResultList(search(terms,type,count=count,start=start))
            paginator = Paginator(brl,count)
            total_pages = len(brl) / count
            results = paginator.page(page)
        else:
            form = SearchForm()
    return render_to_response('yahoo_search/index.html',
                              {'form': form,'results': results,
                               'term': terms,'type': type,
                               'current_page': page,
                               'total_pages': total_pages})

好的，有几点需要说明。

我们现在改用 GET 而不是 POST。其实一开始就不应该用 POST，在此表示歉意。因为使用 GET，很难区分用户是第一次访问页面还是在提交搜索请求。这也是为什么当表单无效时，我们不显示 newforms 生成的错误信息，而是展示一个空的表单：只有用户首次进入页面时才会遇到无效表单，我们不希望一上来就给用户看到错误提示。Paginator 的页码从 1 开始计数，而不是从 0，所以我们计算 start 时使用 (page-1)*count 而不是 page*count。我们需要 total_pages 和 page，因为要让用户知道自己当前在搜索结果的哪个位置（例如，第 5 页，共 412 页）。

更新 index.html 模板

和 index 函数类似，index.html 模板也进行了大幅度的修改。幸运的是，模板的改动大多不难理解。重构后的模板大致如下：

<html> <head>
<title>My Search</title>
</head>
<body>
<h1>My Search</h1>
<form action="/" method="GET">
<table>
  { { form }}
  <tr><td><input type="submit" value="Search"></td></tr>
</table>
{% if results %}
{% if results.has_previous %}
<a href="?page={ { results.previous_page_number }}&search_terms={ { term|urlencode }}&search_type={ { type|urlencode }}"> Previous </a>
{% endif %}
<span> Page { { current_page }} of { { total_pages}} pages. </span>
{% if results.has_next %}
<a href="?page={ { results.next_page_number }}&search_terms={ { term|urlencode }}&search_type={ { type|urlencode }}"> Next </a>
{% endif %}
<ol>
  {% for result in results.object_list %}
  <li>
  <span class="title">
    <a href="{ { result.clickurl }}">{ { result.title|safe }}</a>
  </span>
  <span class="date"> { { result.date }} </span>
  <span class="time"> { { result.time }} </span>
  <span class="source">
    <a href="{ { result.sourceurl }}">{ { result.source }}</a>
  </span> 
  <p class="abstract"> { { result.abstract|safe }} </p>
  </li>
  {% endfor %}
</ol>
{% endif %}
</body> </html>

最复杂的地方在于处理结果页面的前进和后退。我们主要依靠 Paginator 返回的 Page 对象来处理大部分复杂逻辑（在模板里这个 Page 被命名为 results），但因为还需要同时保留搜索关键词和搜索类型，代码会稍微复杂一些。
