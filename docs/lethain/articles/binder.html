用于托管 Jupyter 笔记本的 Binder

2019-02-10 · 阅读原文

我最近写了一篇关于制定可靠性策略：用系统模型思考复杂问题的文章，最初把代码直接内嵌在文章末尾。这么做有点傻，因为我一开始是在 Jupyter 笔记本里写的模型，只是觉得代码不算长，就直接嵌入进来了。

Eoin 好心地给我推荐了 Julia 的这篇说明，介绍了如何使用 Binder 来托管 GitHub 仓库中的笔记本。

经过一两次尝试，我创建了 systems-explorations 仓库，并做了一些调试让它正常运行。现在你可以通过这个链接启动我开发的系统模型的交互式笔记本，只需等待几分钟让它完成启动即可。

我原本打算做一个简单的应用，让大家不用在本地安装就能更方便地使用 systems 库，而 Binder 居然是一个出人意料的替代方案。

我遇到的唯一难点是安装 Graphviz，后来发现 Binder 使用 repo2docker 来进行配置，所以最终只需要在仓库根目录下添加一个 apt.txt 文件，并在其中加入以下内容：

graphviz

这样就成功了！另外一个配置文件是 requirements.txt，也需要做一些调整才能正常工作。关键在于只固定核心依赖，而不要固定它们的传递依赖。因为我用桌面环境通过 pip freeze 生成的需求文件，和 Docker 镜像中的安装环境存在版本冲突，有些包在容器里无法卸载，导致前几次构建失败。
