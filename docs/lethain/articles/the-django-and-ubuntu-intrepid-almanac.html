Django 与 Ubuntu Intrepid 部署指南

2009-02-13 · 阅读原文

距离我第一次尝试搭建一个健康的 Django 部署环境已经过去一年多了（我的服务器所用 Ubuntu 版本的仓库停止维护，粗暴地提醒了我这一点）。在这段时间里，我学到了很多，也把最初的配置推到了极限，但终究还是需要进行一次全新的部署，采用更好的配置和更灵活的文件夹结构。

与上一次服务器搭建指南相比，有些部分保持不变：依然使用 Ubuntu、Memcached、Postgres，并且仍然使用 Nginx 作为 Apache2 前面的反向代理。同时也有一些显著变化：改用 mod_wsgi 替代 mod_python，用 cmemcache 替代 python-memcached，采用了更合理的文件夹布局，并引入 virtualenv，从而可以轻松地在一个服务器上托管多个项目和域名（包括一些仅提供静态文件或 PHP 脚本的站点）。

这不仅仅是一次更新，我还加入了一些“支线任务”，例如将服务器用作通过 SSH 访问的远程 Git 仓库，以及安装可插拔的 Django 库。最后，和我之前的教程一样，我尽量包含了把一台裸的 Ubuntu Intrepid 服务器转变为功能完备、支持多站点的 Django 服务器所需的每一个操作步骤。

如果你在操作中遇到任何问题，或者有改进建议，请告诉我！

一些额外选项

至此你的 mod_wsgi 服务器已经配置完成并可以正常工作了，下面是一些建议，你可以用新服务器做更多事情。

目前如果你直接访问 VPS 的 IP 地址，会发现没有任何内容返回。对大多数人来说这可能是期望的行为，但你可能希望当用户通过 IP 访问时显示一个静态页面（同样，你也可以用类似方法为某些域名只提供静态内容，而不是完整的 Django 项目）。 首先创建一些目录： sudo mkdir /home/django/domains/default sudo mkdir -p /home/django/domains/default/{public,logs} 然后创建一个首页： sudo emacs /home/django/domains/default/public/index.html 内容如下： <html> <head><title>Default</title></head> <body><p>Hi. Welcome to my default site.</p></body> </html> 接下来配置 Nginx 的默认站点： sudo emacs /etc/nginx/sites-available/default 写入以下配置（请把 255.255.255.255 换成你 VPS 的 IP）： server { listen 80; server_name 255.255.255.255; access_log /home/django/domains/default/log/access.log; error_log /home/django/domains/default/log/error.log; location / { root /home/django/domains/default/public; index index.html; } } 然后软链接到 sites-enabled： sudo ln -s /etc/nginx/sites-available/default /etc/nginx/sites-enabled/default 最后重启 nginx： sudo /etc/init.d/nginx stop sudo /etc/init.d/nginx start 现在如果你在浏览器中输入 VPS 的 IP 地址，就会看到这个静态页面。（注意浏览器通常对同一域名限制并发连接数，所以如果你有重度页面，可以用这种方式创建一个专门的媒体子域名（media.example.com 等），让 Django 站点从该子域名加载静态资源，从而加快页面加载速度。） 最有用的包之一是 PIL，它支持多种图像处理操作，也被一些 Django 应用所依赖。虽然它用 easy_install
