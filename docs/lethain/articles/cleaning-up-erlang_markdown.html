清理 erlang_markdown

2009-10-10 · 阅读原文

又花了几个小时后，erlang_markdown 已经清理得相当不错，并且几乎支持了 Markdown 规范的所有特性，除了多行标题语法。你可以查看当前的测试套件来了解它的完整性。

这里我将讨论并反思这个脚本的设计，最后再看看如何对该库进行性能调优。

单遍解析

从一开始，这个项目的目标就是创建一个单遍 Markdown 解释器。比我更厉害的人无疑能为这种方法给出充分理由，而我只是恰好想用这种方式。既然已经这么做了，下面是一些关于使用单遍还是多遍方法将 Markdown 转换为 HTML 的思考：

语言越不规则，编写单遍解释器就越痛苦。特别是那些带有隐式终止的语言，会给单遍方法带来问题。解析不规则语言的单遍解释器会变得更加复杂、更加脆弱，并且比多遍解析器更难扩展。Markdown 既不规则，又有隐式终止。单遍方法允许流式处理，因此可以做到常量内存占用。大多数 Markdown 的使用场景并不适合流式处理（例如为网站渲染评论、博客文章、笔记等），而是期望传入一个完整的字符串或二进制数据，并返回完整的翻译结果。

考虑到上述看法，从长期可持续性和灵活性的角度来说，我始终推荐采用多遍方法而不是单遍方法。只有在多遍方法已被证明性能不足的情况下（例如处理海量 XML 文档时，DOM 解析因内存消耗而变得不可行，这时才会使用 SAX 解析），才应该尝试单遍方法。

或者你的系统本来就是基于流式数据处理的。又或者你只是觉得无聊。

markdown:line_start/5 在每一行的开头被调用，负责管理所有多行结构，比如段落、列表、引用块和预格式块。MultiContext 包含一个由打开的多行标签（ul、ol、li、p、pre、blockquote 等）组成的栈。

line_start/5 无疑是代码中最丑陋的部分，因为它需要负责检测多级缩进的终止（将缩进深度与 MultiContext 栈中打开的 ol 和 ul 标签数量进行比较），以及其他逻辑，比如判断一行没有任何语法标记时，应该被视为新段落、继续的段落，还是属于已打开的 li 标签的一部分。

markdown:single_line/5 负责在所有多行语法被剥离后渲染一行。例如，* *this is a test* 在到达 single_line/5 之前，就已经被简化成了 *this is a test*。

它使用 LinkContext 来存储之前使用 [test]: http://test.com/ "test" 语法声明的链接。在研究了 xmerl:eventp 之后，我会将函数定义重新实现为使用属性列表或记录的形式。

当前的方法使得扩展 erlang_markdown 变得极其别扭，而使用属性列表或记录能显著改善这一点。目前可能还没有强烈的动机去做这个重构，但如果/当我进行第三次重写时，这将会是核心部分。

（当然，这一点在任何语言中都成立，但我——也许是因为相对缺乏经验——发现那些提供 Erlang 性能建议的人中存在大量困惑。）
