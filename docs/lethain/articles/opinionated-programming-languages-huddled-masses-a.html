有主见的编程语言、芸芸众生，以及精英主义

2008-01-19 · 阅读原文

Java 和 Scheme 有什么共同点？

其实两者差异极大。Java 是一门命令式语言，经常引发人们对其语法和表达力不足的怒火。而 Scheme 则是函数式语言，它那极简的语法常被人用浪漫的彼特拉克十四行诗来歌颂。正因为 Scheme 是函数式语言，所以它对命令式编程风格的支持并不理想；同样，作为命令式语言的 Java，对函数式编程风格的支持也相当有限。

那么，为什么 Scheme 被视为“聪明人用的语言”，而 Java 却成了“大众语言”？

标准解释

在阅读关于 LFM 与 LFSP 的文章时，我们通常会看到一个听起来很舒服的解释：

LFM 在设计时故意限制用户的能力，因为权力太危险；而 LFSP 则不会给用户施加不必要的限制。

然而，仔细审视这个解释，我们会发现其中存在一些漏洞。

首先，Java 的设计目标是可预测性和一致性，而非出于对用户能力的恐惧而刻意限制其威力。Java 的限制是为了服务整个社区，哪怕这会给个别开发者带来不便。它把“全局一致性”置于“个人能否使用自己偏好的抽象和构造”之上。Java 鼓励你通过编写封装良好的库和公开 API 来构建抽象。虽然我们很少从这个角度看待 Java，但它其实是一门深深迷恋“Only One Way To Do It”理念的语言——这个口号后来被 Python 发扬光大。

第二个漏洞在于，Scheme 同样通过其对函数式编程风格的极致专注，有意限制了自己的功能范围。我们并不介意这一点，因为 Scheme 本就是函数式语言，我们也不会期待一门函数式语言能出色地支持命令式编程。不喜欢函数式风格的人会远离 Scheme，但他们并不会因此将其贬低为“大众语言”。

用时髦的话来说就是：Scheme 并非随意被限制，它只是很有主见。

理性分析

事实上，Scheme 的限制正是其设计中深植的种种观点所导致的——这些限制同样是任意的。

那我们为什么愿意接受 Scheme 的观点，却无法接受 Java 的呢？因为我们更认同 Scheme 的观点。Scheme 阻碍命令式编程有一个“纯粹”的理由：它在宣称函数式编程优于命令式编程。但实际上，Java 只是提出了另一种观点：命令式编程是一种行之有效、适用于通用目的的编程方式。

因为 Java 对函数式支持不足而对其发火，就如同抱怨 Scheme 写命令式代码很别扭一样荒谬：这些都不是缺陷，而是观点。我们把不喜欢的观点贴上“给不开化的大众”的标签，而把符合当下学术潮流的观点尊为“启蒙”，这其实是在自欺欺人。

让我们回到直白表达吧。

与其把 Java 称为“大众语言”，不如直接说：“我不喜欢写 Java，因为它过于强调命令式编程。”或者“Java 在构建抽象时，把社区利益看得远高于个人。”与其得意地称自己喜爱的语言是“聪明人用的语言”，不如坦率地说：“我真的很喜欢函数式编程”，或者“关于宏的感受可能不适合在公共场合表达。”否则，我们就是在助长精英主义的幽灵。
