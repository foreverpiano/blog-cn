向访问器和修改器致敬

2008-03-12 · 阅读原文

我还记得本科刚开始学习编程时，老师们反复强调：在面向对象代码中，应该始终使用访问器（accessor）和修改器（mutator）来获取和修改数据。当然，那时候我们更常把它们叫做 getter 和 setter 方法，大多数学生都讨厌它们。我记得特别有一个学生坚决拒绝使用它们，认为这些东西“很蠢”。而据说，他现在成了一名职业程序员。

我认为很多新手程序员对访问器和修改器产生了误解，这可能是因为很少有人清楚地解释为什么要这么做。教授们可能会告诉学生应该始终使用 setter/getter 对来处理数据交互，但我从未听到过为什么它们重要的解释。当你刚开始学习编程时，头脑里已经被大量新信息塞满，大脑会自动丢弃那些它不理解或认为无关紧要的内容。那个觉得它们很蠢的学生认为，这些只是传统的冗余代码，不值得花费额外的代码行。

然而，我编程的时间越长，就越能体会到访问器和修改器那微妙的价值。

惰性初始化

我第一次意识到访问器方法的价值，是在学习如何使用 Java 的 Swing 图形包时。那门课使用的是 Visual Eclipse，它会为你生成大量代码。我注意到，程序启动时很少有变量被初始化，大多数东西都是在它们的访问器方法中进行初始化的。

修改器

好了，我们已经讨论了访问器的重要性，现在来看看修改器。修改器的理由相对更显而易见，但仍然值得深入考察。

是我高估了访问器和修改器的价值吗？它们是否只在 Objective C、Java 或 C++ 这些老旧繁琐的语言中才有价值，而在如今动态脚本语言的乌托邦中就显得浪费？我知道自己曾经也对它们很反感，但随着项目规模和复杂度的增加，我发现越来越难以忽视它们带来的帮助。
