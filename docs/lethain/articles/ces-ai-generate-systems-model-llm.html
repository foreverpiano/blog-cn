使用 LLM 生成系统模型

2025-03-15 · 阅读原文

《Crafting Engineering Strategy》一书有一章专门讨论使用系统建模来完善策略，并提供了大量示例。这些示例主要介绍如何使用 lethain/systems 这个 Python 库，在 Jupyter Notebook 中生成模型，相关示例代码位于 lethain/eng-strategy-models。虽然这是一种合理的方法，但它要求使用者学习 systems 库的建模语法。

本章将探讨如何让 LLM 替你编写系统模型的语法，而无需深入学习该语法。除了针对 systems 库的具体指导外，这也是一种可泛化的模式——利用 LLM 来处理特定领域的语言（domain-specific languages）。

我们将依次介绍以下内容：

向上下文窗口添加特定于问题的资源，为 LLM 解决复杂问题做好准备；使用 LLM 编写符合 systems 规范的系统模型；让 LLM 引导你运行系统模型的脚本；使用模型上下文协议（Model Context Protocol，简称 MCP）服务器来简化运行系统模型的流程，并通过 Claude Artifact 来探索结果。

以下说明主要基于 Anthropic Claude.ai 的 Project 设置，但也应能适配其他方案，尤其是在本地 MCP 服务器支持被更广泛地集成到 Claude Desktop 之外的环境中之后。

本章是《The AI Companion to Crafting Engineering Strategy》的一篇草稿，该书讨论了如何在 LLM 中使用《Crafting Engineering Strategy》，以帮助起草、完善和改进工程策略。

添加系统建模指令

在第一章《与 LLM 协作的基础（以一本书为例）》中，我们已经将《Crafting Engineering Strategy》加入到项目的上下文窗口中。现在我们要继续使用这一技巧，向上下文窗口添加创建系统模型的更详细指导。

首先，获取 lethain/systems 仓库中 README.md 的纯文本版本。该文件详细解释了该库的语法和用法，对于让模型生成规范来说已经足够。拿到文件后，将它连同你优化后的《Crafting Engineering Strategy》版本一起上传到 Anthropic 项目中。

这样，README 的内容就会出现在上下文窗口中，作为生成模型的 in-context learning（ICL）示例。

添加 README 后，项目中将同时包含其内容和本书的各章节。现在可以开始编写系统模型了。这类似于用 Systems 库建模招聘漏斗中描述的招聘漏斗模型，但该模型并未包含在《Crafting Engineering Strategy》或 README.md 中。

创建模型

先用一段通用描述说明你想建模的系统。我最初使用的提示词是：

Help me write a systems model specification for
systems library to model a hiring pipeline system where:

1. First stock is infinite stock of "potential candidates"
2. Second stock is "outreaches", with an in flow of 10 from
   "potential candidates"
3. Third stock is "interested", with an in flow of 50%
   from "outreaches"
4. Fourth stock is "active", with an in flow of 50%
   from "interested"
5. Fifth stock is "offers" with an in flow of 10% from "active"
6. Sixth and final stock is "hires" with an in flow of
   70% from "offers"

All of these flows with percentages should be modeled using
"Leak" flows, for example:

    Outreaches > Interested @ Leak(0.5)

这是一段详细的描述，尽管只有最后几句关于“Leaks”的内容需要专门了解 systems 语法。我们稍后会再讨论“Leak”与“Conversion”的区别。最重要的一点是，即使不需要掌握 systems 语法，你仍然必须深刻理解系统模型的工作原理，才能写出有效的规格说明。

根据这个提示，Claude 生成了一份完整可用的模型，同时还附上了若干其他系统模型的示例链接。如果你遇到问题，这些示例可能有助于学习；你也可以将它们转换为 Markdown 格式，添加到提示词中，帮助 LLM 纠正它生成的错误。

现在我们有了一个有效的提示，你可能已经注意到，之前提示中使用“Leak”的建议其实不太合理。这是因为 Leak 表示招聘流程中一部分候选人继续推进，但它会把未推进的候选人仍然留在前一个存量（stock）中。

这并不正确：招聘漏斗中没有继续前进的候选人不会留在之前的存量里，而是会离开整个招聘流程。例如，一位没有拿到 offer 的候选人不会继续留在“Active”阶段，而是会完全退出招聘流程。

让我们来修正这一点，让 LLM 使用 Conversion 而不是 Leak，可以使用类似下面的提示：

Ok, this is a good start. Could you change the leaks
to be conversions, since the others are actually getting lost?

我们可以看到，这个提示输出了修正后的模型。

正如本节所示，只要提供足够且合适的文档，LLM 在编写有效语法方面的能力令人惊讶。真正的挑战在于，你需要足够清楚自己的目标，才能提供恰当的文档。

运行模型

当你拥有了可用的系统模型语法后，下一步是从模型中获取数据。虽然我个人更习惯在 Jupyter Notebook 中运行模型（如 lethain/eng-strategy-models 所示），但你也可以让 LLM 一步步指导你在本地运行模型。

延续上面的提示，我们来请求运行新模型的指令：

Ok, that seems like a good systems model. Please write
me the python script that uses the "systems" python
library to run that model and generate the output as a table.

这会生成在本地安装 systems 库的说明，以及一个用于运行模型的脚本。完整的脚本可在该 Gist 中找到。

如果你按照步骤安装并运行脚本，就会得到以下表格作为输出。

接着，你可以将这个表格连同一段提示一起提供给 Claude.ai，让它创建一个 Artifact 来探索数据：

This is the library output, please produce an artifact
that shows chart of active candidates over time:

{table data omitted for brevity}

这将会生成一个 Artifact，以图表形式可视化该数据集。

这种方法虽然可行，但操作起来相当别扭，需要在聊天界面和终端之间来回切换。我们真正想要的是比 Jupyter Notebook 更好的体验，而这个方案显然更差。幸运的是，我们可以做得更好。

使用模型上下文协议（MCP）服务器

现在我们已经完成了让 LLM 一步步指导我们完成模型构建、运行和渲染整个流程的实验，可以坦率地说：其中一些步骤其实并没有那么有用。更好的方案是让我们能在聊天界面内完成所有操作。

幸运的是，我们可以通过创建一个 Model Context Protocol（MCP）服务器并将其暴露给 LLM 来实现这一体验。MCP 服务器会为 LLM 提供工具，同时给出何时以及如何使用这些工具的说明。一个简单的 MCP 服务器可能提供获取当前天气、调用某个服务的 API 或查询搜索索引的工具。在本例中，MCP 服务器还可以使用 systems 库来运行系统模型，具体实现可参考 lethain/systems-mcp 这个库。

该仓库包含了安装说明，可以将其配置为与我们在与 LLM 协作的基础（以一本书为例）中设置的 Claude Desktop 配合使用。安装完成后，你就可以按照以下步骤运行和渲染模型。

这个 MCP 服务器暴露了两个工具：load_systems_documentation 和 run_systems_model。其中第一个工具 load_systems_documentation 会将项目特定的文档和示例注入到上下文窗口中，作为 in-context learning 的材料，从而提升生成模型的质量。另一个工具 run_systems_model 则接受模型规格并运行它，以 JSON 格式返回结果。

下面是 Claude.ai 使用这两个工具为一个社交网络生成系统模型的示例。注意，加载的上下文中没有任何与社交网络相关的示例，因此这是一个真正的新创作，而非对已有内容的简单复现。

生成系统模型的输出后，我们仍需要探索这些数据。在 Jupyter Notebook 中，我们会用静态图表展示不同的切片。而在 Claude.ai 中，我们可以通过以下提示让它生成一个 Artifact 来探索该数据集：

Create an artifact to render the output of the last
systems model run in a chart and allow me to select
which columns to include.

这将生成一个类似下面的 Artifact，允许你选择要展示的列。

至此，我们已经创造了一个比 Jupyter Notebook 更强大的方案——它能帮你自动生成系统模型，同时也支持类似的探索性分析。如果我们更批判性地看待它，会发现 Artifact 只显示了五轮而非全部五十轮。我们可以通过以下方式修复：

Include all 50 rounds in the artifact, not just 5

不过，我们其实不应该需要手动提出这个要求。所以它还不是完美无缺，但已经可以很好地工作了。也很容易想象，在不久的将来，工具和 Artifact 之间的连接会更加紧密，让 LLM 能够直接将工具与 Artifact 关联起来，而无需通过复制数据来间接完成。

总结

在本章中，我们从一个复杂问题出发，将其拆解为 LLM 可以解决的若干组成部分。我们使用文档来激发 LLM 写出正确的语法。我们加载了一个模型上下文协议服务器，将大量数学计算工作交给擅长快速且准确完成计算的软件。我们使用 Claude Artifact 不仅绘制了结果数据，还能对渲染后的数据进行探索。

这种组合方法不仅解决了生成和运行系统模型的具体问题，也是一种可泛化的思路，能让杂乱的问题更好地适配 LLM 驱动的工作流。这里有效的做法在其他场景中同样有效——我们希望，下一步在生成 Wardley 地图时也能发挥作用。
