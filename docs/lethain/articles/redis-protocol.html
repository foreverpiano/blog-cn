Redis 协议相当出色。

2018-04-10 · 阅读原文

虽然它并非无处不在，但如今已经有很多人使用过 Redis。它支持多种数据结构，例如列表、哈希、HyperLogLog，甚至还支持发布/订阅。它吞吐量惊人，同时又是单线程的，因此你不需要调试任何奇怪的并发相关问题。

我最喜欢 Redis 的地方？正是它的协议。

让我们思考一下如何用 python-redis 设置一个新值：

import redis
cli = redis.Redis()
cli.set('a', 'hello')

客户端通过网络发送的请求是这样的：

*3\r\n
$3\r\n
SET\r\n
$1\r\n
A\r\n
$5\r\n
hello\r\n

每一行都以 \r\n 结尾。客户端以 *3 开头的行开始每个命令，这表示该命令将带有三个参数。每个参数占两行，第一行以 $ 开头，后跟一个整数，声明下一行的字节数（不包括结尾的 \r\n）。

服务端响应非常简洁：

+OK\r\n

成功了！+OK\r\n 是所有没有返回值的成功操作的肯定确认消息。如果出现错误，例如我们试图对一个字符串值调用 incr，它会返回如下格式的错误：

-ERR value is not an integer or out of range\r\n

现在，让我们获取刚才设置的值：

# returns 'hello'
cli.get('a')

客户端发送的内容为：

*2\r\n
$3\r\n
GET\r\n
$1\r\n
a\r\n

服务端响应是：

$5\r\n
hello\r\n

我非常喜欢这个协议的很多方面！

它足够简单，你在一两个小时内就能实现一个简单的客户端或服务端！

它是人类可读的！

明确的行数和每行长度意味着你不需要解析内容本身！

我还觉得把它和 Memcache 协议对比时特别惊艳，后者本身也是一项了不起的成就，但实现起来要 confusing 得多。

如果你想自己复现这个实验，我当时使用的魔法命令是：

sudo ngrep -d lo0 -t '' 'tcp and port 6379'

它捕获了本地 Redis 服务器的所有 localhost 流量。
