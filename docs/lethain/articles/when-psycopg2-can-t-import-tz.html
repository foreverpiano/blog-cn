当 psycopg2 无法导入 tz 时

2009-02-13 · 阅读原文

我经常遇到这个（或类似的）错误信息：

File "/home/django/domains/substanceis.com/substanceis.com/lib/python2.5/site-packages/django/db/__init__.py", line 16, in <module>
    backend = __import__('%s%s.base' % (_import_path, settings.DATABASE_ENGINE), {}, {}, [''])
File "/home/django/domains/substanceis.com/substanceis.com/lib/python2.5/site-packages/django/db/backends/postgresql_psycopg2/base.py", line 20, in <module>
    raise ImproperlyConfigured("Error loading psycopg2 module: %s" % e)
ImproperlyConfigured: Error loading psycopg2 module: cannot import name tz

每次看到它我都感到非常困惑。然后我才反应过来是怎么回事，解决问题，之后又把它抛到脑后。直到下一次再次出现。

你的服务器无法写入 PYTHON_EGG_CACHE 路径，因此无法使用 egg。这就是整个问题的根源。 虽然你可能还需要安装 egenix-mx-base。我甚至不确定它是否真的相关，还是只是我在与这个错误反复作斗争时希望它能起作用的东西。

sudo easy_install egenix-mx-base

解决这个问题的正确方法是在你的 mod_python 或 mod_wsgi 配置文件中进行设置。对于 mod_wsgi，需要在你站点的 .wsgi 文件中添加类似下面的一行。

os.environ['PYTHON_EGG_CACHE'] = '/home/django/.python-eggs'

路径不一定非要是 home/django/.python-eggs，只要是 www-data 用户可以写入的目录即可（Ubuntu 系统）。 要验证的话，只需切换到 www-data 用户然后尝试一下就知道了。

sudo su www-data
cd /home/django/.python-eggs
mkdir test
rm -rf test

如果成功了，那就万事大吉。重启服务器然后就可以离开了。如果你使用的是 mod_python， 则需要在其他位置进行这个修改。这里有更详细的说明， 但基本上你需要在某个地方创建一个 eggs.py 文件，内容如下：

import os
os.environ['PYTHON_EGG_CACHE'] = '/home/django/.python-eggs'

然后把这些指令添加到你域名的 VirtualHost 配置中。

PythonInterpreter my_django
PythonImport /path/to/my/profile/eggs.py my_django

这样就完成了。呼。我希望自己再也不会被这个愚蠢的错误搞得晕头转向了。
