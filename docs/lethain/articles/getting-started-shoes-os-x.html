在 OS X 上开始使用 Shoes

2007-10-15 · 阅读原文

最近我又多玩了一阵 Ruby，也很想顺便折腾一下图形界面。我的 RSS 阅读器里关注 Why the Lucky Stiff 已经有一段时间了，一直在零星阅读他目前的项目 Shoes——一个 Ruby 的 GUI 工具包。用了两天之后，我觉得值得一试。

什么是 Shoes？

从语法上讲，“What is Shoes?” 让我有点难受，但在这里这样说应该是正确的。不管怎样，Shoes 是一个极简的图形用户界面工具包，用于 Ruby 编程语言，可在 OS X、Windows 和 Linux 上运行。这个项目由 Why 单枪匹马领导/启发/推动/主持/编写。你可以从他在自己网站上的自我介绍中得到一些安慰：“Why the lucky stiff 是一位羽翼未丰的自由教授，他会英年早逝，并且不会留下任何持久的影响。”

Shoes 的理念是极简主义，并深受互联网设计的影响。和大多数我接触过的 Ruby 项目一样，它并非旨在满足所有人的所有需求。它对自己的定位做出了明确的选择（这里认可的流行词是“有主见的软件”），如果你想要一个简单、有趣且易于使用的工具包，那就试试 Shoes 吧。目前它还不够成熟，无法用于生产级项目，但用来在几分钟内为当前项目快速拼凑一个图形界面非常不错，也很适合用来做原型。虽然我建议你在考虑这一点前先准备好必要的盐（别太当真），但我认为它最终会成为一种非常愉快的途径，让你能随软件一起发布简单实用的图形界面。坦白说，Shoes 已经能做出的一些图形效果相当令人印象深刻。再过大概半年左右，它甚至可能会有正式的文档。

根据 Why 的说法，它还从 Processing 那里获得了一些灵感，比如让在程序中绘图和使用图形变得简单。然而，Processing 常常让我感到不适（它只允许以受限的方式使用一种受限的编程语言，具体来说是 Java 1.5 之前的版本），而 Shoes 并没有强加同样的尴尬限制。

本质上，Shoes 是一个精巧的小型 GUI 工具包，趣味性十足，值得花上几个小时去玩。它是我见过的最快捷的创建实用图形界面的方式，而且用起来也很直观。绝对值得投入时间。

准备使用 Shoes

你需要获取一份 Shoes 的副本。最简单的方法是前往此处，下载最新的快照。本教程使用的是 2007 年 9 月 6 日的快照。你也可以从 svn 仓库自己编译一份 Shoes，但目前没有这个必要（而且 Shoes 处于剧烈变化之中，所以从仓库深处拿出来的东西会稍微有点不可预测）。

解压包含 shoes 的 tar.gz 文件，你会得到一个闪亮的 Shoes.app 文件。把它扔进你的应用程序文件夹（其实不必非得这么做，但我下面的说明都假设它放在那里）。

那么，让我们稍微看看刚刚安装的东西：Shoes.app 类似于 TK 中的 Wish，它是你程序运行所处的环境。在 Shoes.app 内部（位于 Shoes.app/Contents/MacOS），有一个名为“shoes”的程序，这就是你用来在 Shoes.app 中运行自己程序的那个可执行文件。所以这一切都完全说得通，对吧？很好。

……好吧，也许这并不是那么显而易见。但随着我们继续使用，它会越来越清楚。

你首先要做的是把 shoes 程序添加到 shell 的 PATH 中。仅仅在 /bin 里放一个符号链接是不够的，因为 shoes 使用相对路径来查找某些依赖文件，而符号链接会破坏这种路径。我的做法是直接在 ~/.profile 中添加下面这行：

PATH=/Applications/Shoes.app/Contents/MacOS:$PATH

现在当你输入

shoes

它应该会弹出一个浏览窗口，让你选择要解释执行的文件。你也可以像预期的那样直接提供文件路径：

shoes ~/myfolder/myfile

你必须使用绝对路径来描述想要运行的文件，相对路径将从包含 shoes 的目录开始，无论你实际上是从哪里调用它的（有点别扭，但它需要能访问其他的库组件）。

运行示例

好了，现在我们已经设置好了环境，让我们来运行几个示例。

shoes ./samples/book.rb

挺不错的。虽然那些故事非常古怪。它们不是那种你能一口气坐下来写完的东西，而是需要慢慢日积月累才能收集起来的。好的，再来看另一个例子。

shoes ./samples/anim.rb

同样很棒。注意它是如何把光标位置打印到终端的。

shoes ./samples/draw.rb

一个非常简单的小画图程序。我记得在软件开发课上见过一个用 Java Swing GUI 工具包实现的类似例子。我猜那个程序肯定不止 13 行。这只是个猜测。

其他示例也值得一看。然后再看看实际的示例文件。它们真的没那么复杂或困难。这些不是技术大师展示自己高超水平的演示，而是你稍微花点功夫就能做到的事情。

构建新东西

现在我们已经看过一些示例了，让我们来构建点新的东西。首先我们需要创建一个新文件，叫它 example.rb 吧。放在哪里都行，但一定要知道它的绝对路径（我把它放在 ~/programming/ruby/shoes/ 文件夹里，不过这只是个人习惯）。

首先我们从能写出的最简单的 Shoes 程序开始：

Shoes.app do
end

现在，让我们运行程序看看会发生什么。

shoes ~/programming/ruby/shoes/example.rb

然后（隆重登场）出现了一个空窗口。（如果你没看到，它可能被其他窗口挡住了，目前 Shoes 窗口似乎不会自动弹出到屏幕最前面。）很好。这说明一切都在正常工作。现在关闭 Shoes，我们开始构建点东西。

首先让我们做一个包含三个选项的下拉框：oval、rectangle 和 triangle。

shape = nil
Shoes.app do
  shape = list_box :items => ["Square", "Oval", "Rectangle"]

再次运行，你会在 Shoes 窗口中看到一个包含三个选项的下拉框。在思考它的意义之后，随时可以再次关闭 Shoes。

现在让我们加入一个按钮。这个按钮会报告下拉框当前的值。

shape = nil
Shoes.app do
  shape = list_box :items => ["Square", "Oval", "Rectangle"]
  button "Report" do 
    Shoes.p [shape.text]
  end
end

现在运行程序，你会发现点击按钮时，下拉框的当前值会被发送到终端。

定位元素

使用糟糕工具构建 GUI 最痛苦的部分之一就是定位元素。Shoes 在这方面有一个非常灵活且强大的理念：stack 和 flow。stack 是向下堆叠的容器，flow 是先向右、再向下的容器。flow 就像书里的文字，stack 就像日志文件里的条目。主 Shoes 窗口是一个 flow，而一个 stack 或 flow 里面可以包含任意数量的 stack 和 flow。

这个系统大多数情况下工作得相当好，我猜随着 Shoes 越来越完善，它会越来越“如你所愿”，也更少出现不可预测的情况。现在就已经几乎很棒了，但因为一个好的 GUI 必须是完美的，所以我发现自己和 stack、flow 较劲的次数比希望的要多一些。

所以我们可以像下面这样为程序增加一些形状：

shape = nil
Shoes.app do
  stack :width => 200, :height => 200, :margin => 50 do
    shape = list_box :items => ["Square", "Oval", "Rectangle"]
    button "Report" do
      Shoes.p [shape.text]
    end
    text "Just some filler text"
  end
  flow :margin => 10 do
    text "Text"
    text "More"
    text "Less"
  end
end

我建议你多尝试 stack 和 flow 的不同组合。要构建更复杂的布局，你可以这样做：

stack do
  stack do
    flow do
    end
  end
end

增加一些动态效果

现在让我们给程序加上一些绘图功能。需要说明的是，这里的很大一部分代码是从 samples 文件夹里的 follow.rb 借鉴来的。不过，我们会试着再把它向前发展一点。

trails = [[0,0]] * 60
shape = nil
Shoes.app do
  stack :width => 200, :height => 200 do 
    shape = list_box :items => ["Square", "Oval"]
  end
  stack :width => 200, :height => 200 do
    nostroke
    fill rgb(0x30, 0xFF, 0xFF, 0.6)
    animate(24) do 
      trails.shift
      trails << self.mouse[1,2]
      clear do
        trails.each_with_index do |(x, y), i|
          i += 1
          oval :left => x, :top => y, :radius => i, :center => true
        end
      end
    end
  end
end

trails 数组用于跟踪光标最近的位置。我们去掉了按钮，但保留了下拉菜单。运行这段代码，你会发现它非常简单，只有一个下拉菜单和一些追着你鼠标跑的圆圈。

好的。现在让我们再多加一点东西。

把下面这行：

oval :left => x, :top => y, :radius => i, :center => true

替换为这几行：

case shape.text
  when "Square"
    rect :left => x, :top => y, :width => i, :height => i
  else
    oval :left => x, :top => y, :radius => i, :center => true
 end

现在再次运行程序。移动鼠标，你仍然会看到圆圈在追着光标跑。但如果你去下拉菜单选择“Square”，就会看到方块在追你了。挺有意思。

稍微玩玩键盘

用下拉菜单选择形状还可以，但我更想用键盘控制。让我们从之前的例子开始，使用下面这段代码：

trails = [[0,0]] * 60
shape = 0
Shoes.app do
  nostroke
  fill rgb(0x30, 0xFF, 0xFF, 0.6)
  animate(24) do 
    trails.shift
    trails << self.mouse[1,2]
    clear do
      trails.each_with_index do |(x, y), i|
        i += 1
        case shape%2
        when 0
          rect :left => x, :top => y, :width => i, :height => i, :center => true
        else
          oval :left => x, :top => y, :radius => i, :center => true
        end
      end
    end
  end
end

现在，这正是我们需要的……只不过它还没有键盘输入。让我们来修复这一点。

把这段代码直接放在“Shoes.app do”那行之后：

keypress do |k|
    case k
      when " "
        shape += 1
    end
  end

现在再次运行你的程序。按下空格键时，形状会在圆形和方形之间切换。

（这个最终的示例程序偶尔会抛出一个 bug，我觉得这和 Shoes 中的 rect 方法有关。最近我可能会试着追踪一下。目前这个 bug 并不影响我们理解按键的工作原理，而且它也有助于强化 Shoes 仍处于紧张开发中的这一点。）

下面是程序的最终版本：

trails = [[0,0]] * 60
shape = 0
Shoes.app do
  keypress do |k|
    case k
      when " "
        shape += 1
    end
  end
  nostroke
  fill rgb(0x30, 0xFF, 0xFF, 0.6)
  animate(24) do 
    trails.shift
    trails << self.mouse[1,2]
    clear do
      trails.each_with_index do |(x, y), i|
        i += 1
        case shape%2
        when 0
          rect :left => x, :top => y, :width => i, :height => i
        else
          oval :left => x, :top => y, :radius => i, :center => true
        end
      end
    end
  end
end

烟消云散之后

好了，我们花了一些时间玩 Shoes，也构建了一些简单的程序。不过，要真正对 Shoes 有感觉，你还是得自己动手去玩。到 Shoes 项目页面看看，或者直接改改设置看看会发生什么。我个人正尝试在一个小型个人项目中使用 Shoes。没什么太花哨的东西，但仍是一个很好的上手机会。到目前为止我很享受，也推荐给大家……只是不建议用在任何太重要的东西上。
