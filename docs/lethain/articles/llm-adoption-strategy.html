如何采用大语言模型（LLMs）？

2024-05-14 · 阅读原文

无论你是产品工程师、产品经理，还是工程高管，你很可能都已经被推动去考虑使用大型语言模型（Large Language Models，简称 LLMs）来扩展你的产品或优化你的流程。2023-2024 年是 LLM 采用的一个有趣时代，这些能力已进入主流，许多公司担心自己正在落后——尽管大多数集成看起来仍比较表面。

这种背景使得 LLM 采用成为一个极佳的战略案例研究主题。本文档是一份工程战略文档，旨在确定一家名为 Theoretical Ride Sharing 的虚拟公司应如何采用 LLMs。

在深入战略之前，先简单构建一下场景：Theoretical 拥有 2000 名员工，其中 300 人为软件工程师。公司已融资 4 亿美元，年收入 5000 万美元，在北美和欧洲的 200 个城市开展业务。 他们是一家网约车公司，类似于 Uber 或 Lyft。不过，他们通过使用更大尺寸的车辆进行了创新——本质上是在重塑公共交通。

这是《Crafting Engineering Strategy》中的一章。

诊断

以下是我们在 Theoretical Ride Sharing 采用 LLMs 时面临的主要挑战总结：

内部至少有三类不同的需求需要我们解决（可分别解决或用同一方案覆盖）： 非工程师的生产力工具，例如临时文档改写、文档摘要； 工程师的生产力工具，例如类似 Github Copilot 的高级自动补全工具； 产品扩展，例如司机 onboarding 流程中的高质量文档提取。 在上述需求中，我们认为产品扩展有可能成为战略差异化点，而另外两类属于工作流优化，能提升生产力，但不一定能让我们与行业拉开差距。我们看到的战略差异化机会包括： 重新激活已离职和被暂停的司机，是提升活跃司机数量的最大杠杆，如我们在 中所分析的那样； 缩短司机 onboarding 时间并减少人工介入不会增加活跃司机数量，但我们看到 LLMs 有明确机会降低运营成本，即使不能解决活跃司机的核心问题，这也可能是值得做的； 通过提高响应速度和质量来改善客户支持。 我们目前在公司和行业内使用 LLMs 的经验和专业知识都十分有限。尽管有大量思想领袖持相反观点，但真正以规模化、差异化方式使用 LLMs 的公司或产品仍然极少。目前我们也是如此。 我们希望在不做出不可逆承诺的情况下积累专业知识。我们认为内部专业知识是有效选择问题和利用 LLMs 的限制因素，培养专业知识将帮助我们在未来的迭代决策中更加有效。相反，我们相信在尚未建立内部专业知识之前就进行重大投入，风险较高而回报较低，因为目前行业内尚无其他玩家找到明显优势。 在不同基础模型和基础模型提供商之间切换的成本很低。这既体现在经济上（财务承诺低），也体现在集成成本上（各提供商的 API 和使用方式基本一致）。 基础模型和提供商正在快速演进，该领域未来的发展方向尚不清晰。目前的基础模型提供商很可能还会用更大规模的数据集训练一到两代新模型，但到某个阶段，训练成本将变得难以承受（例如 OpenAI 或 Anthropic 的下一代主要模型训练成本可能超过 5 亿美元）。届时差异化可能转向开发者体验。开源模型如 LLaMa 可能在成本上获得显著优势。也可能出现完全不同的情况。未来充满各种可能。 我们构建了一张 Wardley 图来理解 。 对我们而言，训练一个基础模型的成本高到无法接受。我们已融资 4 亿美元，而训练一个能与 Anthropic 或 OpenAI 提供的基础模型相竞争的模型，成本大约在 300 万到 1 亿美元之间。建模司机入驻流程用 Wardley Map 分析 LLM 生态系统

探索

大语言模型构建在基础模型之上。训练这些基础模型极其昂贵，而且随着对更复杂模型竞争的加剧，成本还在不断上升。据称 Meta 训练 LLaMa 2 花费了 2000-3000 万美元，而 LLaMa 1 的训练成本约为 300 万美元。OpenAI 的 GPT-4 据称训练成本为 1 亿美元。在语料质量及其与任务相关性存在一定差异的前提下，较大模型通常优于较小模型，因此除非你拥有大量独特的数据集，否则没有太多动力去训练更小的基础模型。即使有独特数据集，微调（fine-tuning）或上下文学习（in-context learning，ICL）往往也是更好的选择。

Anthropic 对每百万输入 token 的收费在 0.25 到 15 美元之间，输出 token 略高。OpenAI 的收费则在 0.50 到 60 美元之间，输出同样略高。英语中平均每个单词约对应 1.3 个 token，这意味着你可以完成大量 LLM 工作，而花费远低于大多数风投支持的初创公司在零食上的开支。

关于 LLMs 是否已经达到性能提升即将放缓的阶段，目前存在大量争议。这很像围绕摩尔定律是否已死的持续争论，未来 LLM 性能还能提升多少仍不确定。从训练成本角度看，企业不太可能仅仅通过增加算力投入来持续改进基础模型。很少有公司能承受 10 亿美元的训练成本，能承受 100 亿美元的就更少了，很难想象会有公司去构建价值 1000 亿美元的模型。不过，算法改进和对数据集的投资很可能在不显著增加算力成本的情况下带来性能提升。在这个领域唯一可以高置信度预测的是：未来 3 年内，模型性能很可能还会再翻一到两倍，之后可能继续按此速度提升，也可能在该性能水平上趋于平稳——两种结果都有可能。

对于某些决策，必须从一开始就做对。例如从 AWS 迁移到 Azure 成本极高，因为存在大量定制化和锁定。但 LLMs 似乎不属于这一类别。与行业同行交流后发现，大多数公司都在尝试来自 Anthropic、OpenAI 以及其他厂商（例如 Mistral）的各种模型。不同模型的行为确实存在差异，但即使只采用一个模型，现有的模型行为也会随时间变化（例如 GPT 3.5 据称变得越来越“懒”），这意味着处理模型差异的开销是不可避免的。 从技术角度看，模型的厂商锁定程度较低。 然而，监管要求——例如更新数据处理协议（Data Processing Agreements）——会在切换提供商时引入一定摩擦。

尽管人工智能领域仍在持续爆发投资热潮，但大多数规模化的科技公司仍在寻找如何将这些能力用于超越最明显、广泛实践（如采用 Github Copilot）之外的场景。例如 Stripe 正在大力投资 LLM 以提升内部生产力，其中很可能包括让它们完成以前由员工执行的某些内部任务，比如验证公司网站是否与其在 onboarding 申请中提供的信息一致。但目前尚不清楚他们是否已经找到一种有意义的方式，用 LLMs 来改变其产品或产品用户体验。

更具体地看网约车公司，似乎也没有出现突破性的行业特定方法。Uber 同样在采用 LLMs 来提升内部生产力和部分运营效率，这在他们 2023 年 8 月发布的关于使用 LLMs 进行内部开发者与运营生产力投入的文章，以及 2024 年 5 月更详细介绍这些努力的文章中均有记录。
