在 Erlang gen_server 中实现 receive-after 功能

2009-12-13 · 阅读原文

Erlang 中使用消息传递依赖于 receive 结构，它会将用户指定的模式与进程的邮箱进行匹配，并执行相应的匹配分支。receive 可以配合 after 结构使用，如果在指定时间内没有收到任何消息，就会执行 after 后面的代码。

一个简单的示例如下：

store(Store) ->
    receive 
	add ->
            io:format("started!"),
            store(Store + 1);
	stop ->
	    Store
    after
	1000 ->
            io:format("Store is ~p",[Store]),
            store(Store)
    end.

然而，在实际生产环境的 Erlang 代码中，直接使用消息传递的情况并不多见。更常见的是使用 gen_server。在将一些代码从普通进程移植到 gen_server 的过程中，我遇到了困难，因为我不知道如何在 gen_server 中实现 after 的功能。

大约一周后，我偶然发现了解决方案：在 gen_server 的 init/1 函数中返回一个三元组，而不是二元组。

% 0 is the initial State value
% 1000 is the timeout value
init([]) -> {ok, 0, 1000}.
handle_cast(add, _Sender, State) ->
{noreply, State+1, 1000};
handle_cast(stop, _Sender, State) ->
{stop, stopped, stopped, State}.
handle_info(timeout, State) ->
io:format("Store is ~p", [State]),
{noreply, State}.

比预想的要简单。

（我最初的实现有些天真。仅仅在 init/1 中返回 timeout 是不够的，必须在每一个 handle_call 和 handle_cast 中都返回 timeout。）
