使用 Django Templates 构建复杂静态网站

2008-09-15 · 阅读原文

2008年9月15日更新：对于对本文讨论技术感兴趣的朋友，我制作了一个名为 AYM CMS 的可重用模板，可用于使用 Django templates 构建复杂的静态网站。

我正在开发的一个项目需要创建一个简单的网站：一些屏幕截图、一些静态页面等等。最初的想法是直接用静态 HTML 和 CSS 来构建网站，这种经典方案已经可靠地使用了二十多年，但我想要一些更好的方式。

最近我一直在为静态网站编写越来越复杂的构建脚本，这些脚本会将渲染后的 Markdown 注入到静态模板中，或者自动生成缩略图。这种方法既保留了静态页面的优势（即使在最糟糕的硬件上也能实现极高的可扩展性），又避免了编写静态 HTML 的大部分缺点（更新和修改会耗费大量人力）。

昨天，当我面临着要把一个通用 HTML 模板复制粘贴六次（还得祈祷以后不需要修改它）的情况时，我心想：“该死，我就直接用 Django templates 吧。”

这个想法真是太棒了。

前置要求

本示例需要你已经安装了 Django 和 PIL。

相对路径与绝对路径

值得注意的是，当你从本地文件系统直接打开页面（而不是把网站放到 Apache 或 nginx 等 Web 服务器的根目录下）时，当前指向 static 目录的路径将无法正常工作。

这是因为它期望 static 文件夹位于 /static/，而这恰好是文件系统的根目录，而不是你实际提供文件的位置。如果你希望网页 URL 保持扁平（例如使用 /index.html、/help.html、/about.html 等路径），那么可以将 settings.py 中的 STATIC_URL_FORMAT 设置从 u"/static/%s" 改为 u"static/%s"，这样即使没有部署在根目录下也能正确显示。

扩展想法：缩略图画廊

当前版本的构建脚本已经提供了一些便利。每次你向 images 文件夹添加一张图片，就会自动获得一张对应的缩略图，并且它会被加入到 images 列表和 images_dict 字典中。

利用这两个工具，你可以通过文件名（不带扩展名，谁想记住那些呢？）来显示图片，或者显示它们的缩略图。

你可以创建一个包含网站所有图片的截图画廊（比如如果你正在制作一个应用展示网站，这会很有用），方法非常简单：只需把截图放到 images/ 目录，然后在模板中加入以下代码：

<div class="gallery">
{% for image in images %}
  <div class="thumbnail">
    <a href="{ { image.image }}">
      <img src="{ { image.thumbnail }}">
    </a>
  </div>
{% endfor %}
</div>

对于许多网页来说，这就已经是你真正需要的全部动态功能了。而且现在你提供的是静态文件，即使有超过十个并发访客，你那台小 VPS 也不会崩溃。

扩展想法：自动构建

对于许多网站来说，你本来就会把页面缓存半小时，在这三十分钟内，你的 Django 应用本质上就是一个平庸的文件服务器。

你可以改用像这个脚本一样的静态方案，然后设置一个 cron 任务，每三十分钟（或者每次目录中有文件被修改或添加时）更新一次静态资源。

虽然这对于高度动态的网站来说肯定不是好方案，但对于很多网站而言，这种方式可能已经足够了。

扩展想法：渲染 Markdown

这个最简单方案的一个缺点是，你将被迫使用 HTML 编写内容，而不是使用 Markdown 或 Textile 这样更友好的标记语言。

但其实不必如此。可以将 Markdown 过滤器稍作修改，使其变成一个模板标签：

{% markdown %}
Render **all this!** to Markdown!
{% endmarkdown %}

这只需要几行代码就能实现，却能打开一扇真正值得探索的大门。

你甚至可以进一步扩展这个想法，比如结合 syntax highlighting 模板过滤器，在静态网站中实现简便的语法高亮。

我相信你已经想到了更多改进这个基础框架的想法。制作更好的静态页面还有很多容易实现的优化空间。
