使用 Django Templates 构建复杂静态网站

2008-09-15 · 阅读原文

2008 年 9 月 15 日更新：对于对本文讨论技术感兴趣的朋友，我制作了一个名为 AYM CMS 的可复用模板，它可以使用 Django templates 来构建复杂的静态网站。

我正在开发的一个项目需要创建一个简单的网站：放一些截图、静态页面等等。最初的想法是直接用静态 HTML 和 CSS 来做，这个经典方案几十年来一直很有效，但我想要一个更好的方案。

最近我一直在为静态网站编写越来越复杂的构建脚本，这些脚本会将渲染后的 Markdown 插入到静态模板中，或者自动生成缩略图。这种方法既保留了静态页面的优势（即使在最糟糕的硬件上也能极致扩展），又避免了编写纯静态 HTML 的大部分缺点（更新和修改耗费过多人力）。

昨天，当我面对要复制粘贴一个通用 HTML 模板六七次（还得祈祷以后不需要修改它）的情况时，我心想：“算了，我就直接用 Django templates 吧。”

这个想法真是太棒了。

前置要求

本示例需要你已经安装了 Django 和 PIL。

开始动手

首先，创建一个文件夹来存放这个项目。我把它叫做 my_cms。 mkdir my_cms cd my_cms 接下来我们创建几个子文件夹： mkdir templates mkdir static mkdir deploy mkdir images 然后在 my_cms 目录下创建一个非常简单的 settings.py 文件。 import os, datetime ROOT_PATH = os.path.dirname(__file__) # 设置目录路径 TEMPLATE_DIRS = ( os.path.join(ROOT_PATH,'templates') ) STATIC_DIR = os.path.join(ROOT_PATH,'static') DEPLOY_DIR = os.path.join(ROOT_PATH,'deploy') IMAGES_DIR = os.path.join(ROOT_PATH,'images') # 设置一些有用的常量 STATIC_URL_FORMAT = u"/static/%s" STATIC_THUMBNAIL_FORMAT = STATIC_URL_FORMAT % u"thumbnail/%s" STATIC_IMAGE_FORMAT = STATIC_URL_FORMAT % u"image/%s" THUMBNAIL_SIZE = (128,128) EMAIL = u"your_email_address@gmail.com" # 创建默认渲染上下文 CONTEXT = { 'email':EMAIL, 'now':datetime.datetime.now(), } PAGES_TO_RENDER = () 这个 settings.py 中保存的配置将在构建脚本中使用，尤其是 CONTEXT 字典会在模板渲染时被传入，因此它是存放经常变化的设置和数据的绝佳位置。 现在我们来编写构建脚本的初始版本。由于还没有任何内容，它会比较简单，但它将执行以下步骤： 1. 创建 deploy 目录。 2. 创建 deploy/static 目录。 3. 将 static/ 目录下的所有内容复制到 deploy/static。 4. 创建 deploy/static/thumbnail 目录。 5. 创建 deploy/static/image 目录。 6. 为 images/ 目录中的所有图片分别在 deploy/static/thumbnail 和 deploy/static/image 目录下生成缩略图和原图。 7. 渲染我们提供的模板列表，并将它们复制到 deploy/ 目录。 完整代码如下： import os, shutil from django.template.loader import render_to_string from django.conf import settings from PIL import Image os.environ['DJANGO_SETTINGS_MODULE'] = u"settings" def main(): # 从 settings 获取默认上下文字典 context = settings.CONTEXT deploy_dir = settings.DEPLOY_DIR print u"Removing existing deploy dir, if any..." shutil.rmtree(deploy_dir, ignore_errors=True) print u"Creating deploy/ dir..." os.mkdir(deploy_dir) print u"Copying contents of static/ into deploy/static..." deploy_static_dir = os.path.join(deploy_dir, 'static') shutil.copytree(settings.STATIC_DIR, deploy_static_dir) print u"Copying and creating thumbnails for files in images/..." deploy_thumb_path = os.path.join(deploy_static_dir, 'thumbnail') deploy_image_path = os.path.join(deploy_static_dir, 'image') os.mkdir(deploy_thumb_path) os.mkdir(deploy_image_path) images = [] images_dict = {} images_dir = settings.IMAGES_DIR thumb_format = settings.STATIC_THUMBNAIL_FORMAT image_format = settings.STATIC_IMAGE_FORMAT thumbnail_dimensions = settings.THUMBNAIL_SIZE for filename in os.listdir(images_dir): # 只处理以图片扩展名结尾的文件 before_ext, ext = os.path.splitext(filename) if ext not in (".png",): continue print u"Copying and thumbnailing %s..." % filename filepath = os.path.join(images_dir, filename) im = Image.open(filepath) im.save(os.path.join(deploy_image_path, filename), "PNG") im.thumbnail(thumbnail_dimensions, Image.ANTIALIAS) im.save(os.path.join(deploy_thumb_path, filename), "PNG") # 创建包含图片数据的字典 image_dict = {} image_dict['filename'] = filename image_dict['thumbnail'] = thumb_format % filename image_dict['image'] = image_format % filename images.append(image_dict) # before_ext 是 'hello.png' 中的 'hello' images_dict[before_ext] = image_dict context['images'] = images context['images_dict'] = images_dict print u"Rendering pages..." pages = settings.PAGES_TO_RENDER for page in pages: print u"Rendering %s..." % page rendered = render_to_string(page, context) page_path = os.path.join(deploy_dir, page) fout = open(page_path, 'w') fout.write(rendered) fout.close() # 构建脚本完成 print u"Done running build.py." if __name__ == "__main__": main() 诚然，作为一段代码它有点长（76 行？有点吓人），但里面没有特别复杂的内容，而且以后也不需要再修改它（我们只需修改 settings.py 即可）。 在开始编写模板之前，先往 images/ 文件夹里扔几张随机图片，以便测试缩略图生成功能。我用了一张以前拍的照片，文件名是 bridge.png。你用什么图片其实关系不大（虽然目前脚本只支持 .png 文件）。 放一张截图也可以。 现在我们需要开始编写模板来利用这个全新的构建系统。首先创建一个基础模板，文件名为 base.html，放在 templates/ 目录下。 <html> <head> <title>{% block title %}My CMS{% endblock %}</title> <link rel="stylesheet" href="static/style.css"> </head> <body> {% include "header.html" %} {% block content %}{% endblock %} {% include "footer.html" %} </body> </html> 然后在 templates/ 目录下创建 header.html。 <h1> Welcome to my Simple CMS </h1> 再创建一个 footer.html。 <div class="footer"> <p> Last updated at {{ now|time:"H:i" }}. Mail <a href="mailto:{{ email }}">this address</a> with questions. </p> </div> 其实我们也可以直接使用 now 这个模板标签，而不用把它存到上下文变量里。我这么做只是为了演示如何向模板提供动态的静态上下文。 最后，我们来编写 index.html 模板。 {% extends "base.html" %} {% block content %} {% with images_dict.bridge as image %} <a href="{{ image.image }}"> <img class="thumbnail" src="{{ image.thumbnail }}"> </a> {% endwith %} <p> This is some simple static text. </p> <div class="thumbnails"> {% for image in images %} <a href="{{ image.image }}"> <img class="thumbnail" src="{{ image.thumbnail }}"> </a> {% endfor %} </div> {% endblock %} 现在要把 index.html 加入渲染列表，只需在 settings.py 中修改 PAGES_TO_RENDER： PAGES_TO_RENDER = ( u"index.html", ) 然后在命令行输入： python build.py 这样就会在 deploy/ 目录下生成网站。 最后，base.html 模板已经设置为引入 static/style.css，我们来写一个非常简单的 CSS 作为示例。 创建 my_cms/static/style.css 文件： body { background-color: black; color: white; } 然后再次运行构建脚本： python build.py deploy/ 目录下的文件就会应用新的 CSS 样式。

至此，我们就完成了。

相对路径与绝对路径

需要注意的是，当你直接从本地文件系统打开页面（而不是把它放到 Apache 或 nginx 等 Web 服务器的根目录下）时，指向 static 目录的当前路径将无法正常工作。

这是因为它期望 static 文件夹位于 /static/，也就是你文件系统的根目录，而不是你实际提供文件的位置。如果你希望网页 URL 保持扁平（例如 /index.html、/help.html、/about.html 等），那么可以将 settings.py 中的 STATIC_URL_FORMAT 设置从 u"/static/%s" 改成 u"static/%s"，这样即使不部署在根目录下也能正常显示。

扩展想法：自动化构建

对很多网站来说，你本来就会缓存页面半小时，在这三十分钟内，你的 Django 应用本质上就是一个平庸的文件服务器。

你完全可以改用这种静态方案，然后通过一个 cron 任务每三十分钟（甚至每次目录中有文件被修改或添加时）更新一次静态资源。

虽然这对于高度动态的网站肯定不是好方案，但对很多网站来说，这种方式已经足够了。
