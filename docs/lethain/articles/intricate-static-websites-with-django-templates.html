使用 Django Templates 构建复杂的静态网站

2008-09-15 · 阅读原文

2008年9月15日更新：如果您对本文讨论的技术感兴趣，我整理了一个名为 AYM CMS 的可复用模板，可用于使用 Django templates 构建复杂的静态网站。

我正在开发的一个项目需要创建一个简单的网站：包含一些截图、几个静态页面等。最初的想法是直接使用静态 HTML 和 CSS 构建网站，这种经典方案已经可靠运行了几十年，但我想要一个更好的方案。

最近我一直在为自己的静态网站编写越来越复杂的构建脚本，这些脚本会将渲染后的 Markdown 注入静态模板，或者自动生成缩略图。这种方法既保留了静态页面的优点（即使在最差的硬件上也能实现极高的可扩展性），又避免了编写纯静态 HTML 的大部分缺点（更新和修改会耗费大量人力）。

昨天，当我面对着要复制粘贴一个通用 HTML 模板六次（还得祈祷以后不用再修改它）的任务时，我对自己说：“该死，我就直接用 Django templates 吧。”

这个想法真是太妙了。

前置条件

本示例需要您已安装 Django 和 PIL。

cd my_cms

相对路径与绝对路径

需要注意的是，当你直接从本地文件系统加载页面（而不是把它放到 Apache 或 nginx 等 Web 服务器的根目录下）时，指向 static 目录的当前路径将无法正常工作。

这是因为它期望 static 文件夹位于 /static/，而这个路径对应的是你文件系统的根目录，而不是你实际提供文件的位置。如果你希望网页 URL 保持扁平（例如使用 /index.html、/help.html、/about.html 等路径），那么可以将 settings.py 中的 STATIC_URL_FORMAT 设置从 u"/static/%s" 改为 u"static/%s"，这样即使不部署在根目录下也能正确显示。

扩展想法：缩略图画廊

当前版本的构建脚本已经提供了一些便利。每当你向 images 文件夹添加一张图片，就会自动获得一个对应的缩略图，并且该图片会被加入 images 列表和 images_dict 字典中。

有了这两个工具，你就可以通过文件名（不带扩展名，谁想记住那些后缀呢？）来显示图片，或者显示其缩略图。

你可以创建一个展示网站所有图片的截图画廊（比如你在做一个应用展示网站时会很有用），方法非常简单：只需把截图丢进 images/ 目录，然后在模板中加入以下代码：

<div class="gallery">
{% for image in images %}
  <div class="thumbnail">
    <a href="{ { image.image }}">
      <img src="{ { image.thumbnail }}">
    </a>
  </div>
{% endfor %}
</div>

对很多网页来说，这就已经是你真正需要的全部动态功能了。而且现在你提供的是静态文件，即使有超过十个并发访客，你那台不起眼的小 VPS 也不会崩溃。

扩展想法：自动化构建

对许多网站来说，你本来就会缓存页面半小时，在那段时间里，你的 Django 环境本质上就是一个平庸的文件服务器。

相反，你可以使用像这个脚本一样的静态方案，然后设置一个 cron 任务，每三十分钟（或者每次目录中有文件被修改或添加时）更新一次静态资源。

虽然这对于高度动态的网站来说肯定不是好方案，但对很多网站而言，这种方法可能是足够的。

扩展想法：渲染 Markdown

这个最简单方案的一个缺点是，你将被迫使用 HTML 编写内容，而不是使用 Markdown 或 Textile 这样更友好的标记语言。

但其实不必如此。可以把 Markdown 过滤器稍作修改，使其成为一个模板标签：

{% markdown %}
Render **all this!** to Markdown!
{% endmarkdown %}

实现它只需要几行代码，却能打开一扇真正值得探索的大门。

你甚至可以把这个想法扩展到类似语法高亮模板过滤器的功能上，从而在静态网站中轻松实现语法高亮。
