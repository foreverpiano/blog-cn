引入 SRE、TPM 等专业化角色

2018-08-13 · 阅读原文

很多人惊讶地发现，我职业生涯起步时其实是一名前端工程师。我愿意相信这是因为我在基础设施领域知识渊博，但更可能的原因是我在设计审美上糟糕得令人发指。那段经历给我留下最深刻印象的是，我感觉自己被当作二等工程师：大家都不愿意做前端工作，却。随后的十年里，浏览器兼容性和 JavaScript 工具链发生了翻天覆地的进步，如今的前端工程师在行业心目中微妙的角色层级里已经占据了受人尊重的地位。偏差，前端工程师的痛苦

虽然节点的位置发生了交换，但角色的层级依然根深蒂固，尤其在人们提议为新角色制定或时表现得最为明显。最近，是否要为站点可靠性工程师（Site Reliability Engineer，简称 SRE）建立独立的职业阶梯这个问题一直萦绕在我心头。你的招聘漏斗职级、绩效评定与校准机制

这个具体问题对我来说意义重大，因为我曾有机会设计 Uber SRE 角色的最初版本。虽然我认为那个设计还算不错，但它本可以运行得更加顺畅。面对是否要第二次这么做时，我的第一反应是僵住，然后回想那些没用好的地方。

在这个问题上纠结了一段时间后，我依然犹豫不决，于是决定更系统地来做这个决定，并把结果写在了这里。总的来说，有四个有趣的问题值得深入探讨：

这些角色容易陷入哪些陷阱？如果我们决定创建一个新角色，应该如何帮助它获得成功？专业化角色有哪些好处？综合以上所有内容，什么时候应该创建一个新角色？

最终，创建一个新角色仍然是个艰难的决定，但我们将拥有一个框架来帮助我们做出判断。

挑战

我在推广新角色时遇到的主要挑战包括：

阶层体系。很多时候人们会认为新角色不那么重要，经常将其定位为服务型角色，用来吸收他们不感兴趣的工作。有时这些角色甚至被明确设计成这样，目的是减轻另一个角色的负担，而不是拥有自己赋能性的使命。脆弱的组织结构。当你从通用角色转向专业角色时，一个意想不到的后果是组织会出现更多的单点故障。以前团队里的每个人都能相当有效地完成所有任务，现在如果项目经理离职，就会发现没人能很好地填补这个角色。这种脆弱性在经常进行的组织中尤为突出。模式匹配。为组织设计一个新角色通常需要做几十个重要决策，以使其与你的需求对齐。不幸的是，大多数人不会花太多时间去理解这些区别，而是根据他们在别处看到的做法来进行模式匹配。这是一种强大的力量。相当大比例的人既不愿意采取任何步骤去了解这个角色的预期运作方式（阅读文档、询问方法），又会继续对它没有完全像他们在上一家公司看到的那样运作而感到惊讶。任务卸载。当创建一个新角色时，设计者对新职能的运作方式有着非常清晰的愿景。而许多其他人并不特别关心你希望这个职能如何运作，他们会把它视为一个机会，来卸载那些他们觉得具有挑战性、困难或无趣的任务。这可能导致新角色从一开始就陷入繁重的工作，这在试图扩大组织规模的领导者看来往往像是成功，但对于实际承担这些工作的人来说，很容易变成一种令人厌烦的工作体验。太“琐碎”而不被重视。许多角色是从承担被其他角色视为无趣的工作开始的，因此该角色中的人往往也认为这些工作琐碎且不重要。这常常导致新角色难以获得对其影响的认可。太“琐碎”而不被晋升。与上面类似，你常常会发现新角色所做的工作在影响上被高度重视，但并不被视为足够“战略性”而值得晋升，尤其是超出之后。这可能导致如果人们想要获得更高的成就，就不得不换角色。编制障碍。公司最终会发展出一系列神秘的仪式，通过一系列邮件、会议和咒语转化为年度人员编制计划。这些系统设计得相当合理，主要是为了支持大型、已有的角色。因此，它们通常会让为新角色争取编制变得相当困难，尤其是当它与需要扩张的现有职能存在冲突时。招聘稀缺人才。出于完全合理的原因，人们希望新角色中的首批招聘对象能成为整个职能的强大榜样。这常常导致要求不断堆叠，直到没有任何候选人能够达到标准。无法评估。几乎与上述挑战相反，有时现有组织对他们希望创建的新职能几乎没有经验，以至于他们根本没有可用的方法来评估候选人。这可能导致评估重点放在与候选人如果接受这份工作后实际要做的事情基本无关的品质上。运行工程团队重组职级体系、评定惯性等

促成成功

如果我们确实想创建一个新角色，就必须认真考虑需要做些什么才能让角色中的人获得成功。我发现一个新角色要成功 bootstrapping，需要具备以下要素：

高管赞助人。不一定是高管，但你需要找到一位有授权的资深领导，他致力于新职能的成功。尤其是在第一个和编制周期，会存在很多棘手的问题，需要大量的组织支持来应对。找到一位能够提供必要支持的赞助人，是创建新角色最明显的制约因素。如果你找不到赞助人，这通常是一个重要的反馈，说明领导层不认为新角色能带来良好的投入回报。招聘伙伴。新角色需要招聘团队的大力支持才能成功。每个正在招聘的角色都有很高的固定成本，增加新角色可能会让招聘人员难以达到他们的绩效考核目标。确保你的招聘团队有能力支持新角色！如果不能，第一步可能是与你的高管赞助人合作，将更多编制投入到招聘上。自我维持的使命。新角色经常被描述成它们将如何影响其他职能，而不是它们自己将完成什么。例如，你可能会把技术项目经理（Technical Program Manager，简称 TPM）描述为从工程经理那里卸载项目管理职责。这种方式将该角色框定为辅助、支持型职能，这使得其工作影响难以被认可。你必须能够在不引用其他现有角色的情况下描述该角色的工作，这样它才能长期成功。职业阶梯。在几乎所有情况下，新角色从一开始就应该有职业阶梯。职业阶梯是成功绩效管理体系的基础，如果没有深思熟虑的职业阶梯，就不可能对一个角色进行连贯的价值评估或评价。有时人们会在写阶梯之前就急于招聘，但设计一个有效的面试流程所需的工作量与写职业阶梯大致相当，所以我认为跳过这一步是一种假性节约。榜样人物。谁会成为这个角色的外部和内部榜样？一个好的榜样是你在职业阶梯中编码意图的人类化身。你需要有一个可以指向的人。独立的校准。大多数绩效管理体系都依赖于校准系统，以确保绩效评级在团队和角色之间以一致的方式分配。有时人们试图在一次会议中对混合角色进行校准，这会导致较小角色被当作事后想法处理。评级往往会被不经思考地批准，或者被推向中间位置，这两种情况都无法为新角色中的人创造有用的反馈循环。最好是在专为该角色准备的独立校准会议中单独考虑他们。如果这不可行，次优方案是将所有较小角色放在一起考虑，这样各种形式的专业化贡献都可以被仔细评估。职级、绩效评定与校准机制

优势

如果创建一个新角色只有成本和挑战，那么决定不推进就很容易，但实际上它能带来相当显著的优势：

效率。这是脆弱组织结构的另一面：专业化角色中的人能够将更多时间花在较小的任务集合上，从而在该领域积累大量专业知识。对于现有人员已经花费大量时间的领域，这种专业化效率可以显著提高整体吞吐量，而无需增加编制。我认为这是最重要的优势，尤其对那些财务资源是增长瓶颈的团队或公司（大多数公司的大多数团队都是如此）特别有价值。高效解决约束。这是效率点的延伸，但又有些微妙的不同：有了专业人员，你可以精确地增加你所缺失的那类能力，这对于高效解决约束非常强大。如果你的组织项目管理带宽不足，你可以增加五名新经理，每人承担一点责任；或者你可能只需增加一名项目经理，其单独提供的相关带宽就相当于那五名经理的总和。认可。仅仅创建一个新角色绝对不会让人们突然开始重视他们以前不屑的工作，但它可以成为这种转变的有用组成部分。特别是，它将提供额外的结构性机制来支持认可，例如独立的职业阶梯、校准会议，甚至是薪酬结构。针对优势进行评估。有效面试专业人员通常很有挑战性，常常是根据他们如何胜任你的通用职位来评估他们，而忽略了他们独特的优势领域。将他们拆分成一个新角色后，就可以将面试流程聚焦在最重要的领域。扩大的招聘池。你现在可以在中考虑一个新的候选人池，这有可能扩大你可以考虑的候选人总数。专业化薪酬。在某些情况下，专业人员的市场薪酬明显高于通用人员，在这种情况下，如果没有专门的薪酬区间，往往很难招聘到专业人员。你的招聘漏斗

该怎么办？

一旦你熟悉了提供一个新角色的挑战和成本，剩下的就是权衡优势并快速做出判断。唉，实际上这仍然是个相当艰难的决定！

以下是一些可以帮助你做出决策的问题：

是否有不那么极端的方式来解决认可差距？也许你可以调整现有的职业阶梯。你是否有计划改变公司对这项工作的重视程度？创建一个新角色本身并不会改变公司对这项工作的重视程度，你仍然需要去做拓展公司价值观的艰苦工作。如果你有改变公司价值观的计划，能否在引入新角色之前先试运行这个计划？这有助于为你试图帮助的人降低实验风险，而且也容易得多。这个职能是否已经以隐秘的形式存在？有时你会发现角色已经悄然分化，与其说是创建一个新职能，不如说是正式承认一个已存在的职能。这是否会短期内提升绩效认可度，但最终伤害那些转换角色的人的职业发展？创建一个新角色绝对属于那种最初感觉像是进步，但最终会显著拖后腿、迫使人们以后换角色的事情。受影响的人数是否足够多，认可差距是否足够大，足以覆盖创建和培育一个新角色所需的大量成本？谁将为新角色支付维护成本？如果答案是你自己来支付，那么如果你离开，谁会接过接力棒？

当你思考这些问题时，希望适合你具体情况的正确方法会变得清晰一些。根据经验法则，如果一个新角色能立即覆盖二十个人，我会毫不犹豫地创建它；如果它能在两年内覆盖二十个人，我会勉强创建；如果它无法满足这两个条件中的任何一个，我会对创建新角色持怀疑态度！
