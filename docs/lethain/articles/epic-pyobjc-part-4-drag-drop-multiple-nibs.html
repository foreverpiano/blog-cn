Epic PyObjC 第四部分：拖放功能与多 Nib 文件

2008-08-26 · 阅读原文

欢迎来到 Epic PyObjC 教程系列的第四篇。在教程的第三部分，我们重点完成了三个较小的任务：处理双击操作、将数据缓存到磁盘，以及添加进度指示器。

这一次，我们将聚焦于 Cocoa 应用程序开发中两个稍显棘手但极其重要的模式。我们会先实现一些拖放功能，最后再探讨如何在应用程序运行时使用第二个 nib 文件来创建新窗口。

在第三篇文章中，我曾说会在这一篇里附上资源列表，但后来想到要介绍使用第二个 nib（理解它将大大拓宽你的 Cocoa 视野），我觉得这是一个真正值得深入的话题。如果把拖放、多 nib 和资源列表都塞进一篇文章，内容就太多了。

如果你之前没有跟上，可以下载当前项目的 zip 压缩包。

既然这是我们在这个系列中最后一次合作，那就来点有趣的吧。

拖放功能：一种哲学，一种风格

我本想以自己长期致力于拖放概念为开场，但那是在撒谎。大约一年半前（别告诉招聘人员），当我刚开始接触 PyObjC 和 Cocoa 时，开发了第一个比较复杂的应用程序，并且颇为自豪。当时最常听到的两个批评是：不要使用 brushed metal 风格（我至今还没从反 brushed metal 的阴谋中恢复过来），以及“在两个列表之间传输内容，用拖放不是比双击更好吗？”

我记得自己当时嘟囔了一些蹩脚的借口，说自己没做，主要是觉得它比想象中更难搞懂——反正谁需要拖放功能呢？

好吧，过去的种种不提，现在我和你都需要拖放功能。拖放是为数不多的几个地方之一，你可以在用户界面上大胆实验，做一些真正有趣的事情，而不会打破太多惯例让用户诅咒你。拖放就是 Cocoa 编程中的西部蛮荒之地。

拖放功能的巨大潜力之所以没有被充分挖掘，仅仅是因为它并非必需。大多数应用程序都可以不用或只用很少的拖放功能，因此开发者也就这么做了。但是，我要说，不能再这样下去了！

有无数直观、有趣且实用的方式可以更多地使用拖放功能。下面并不是一份完整的清单，只是起点：

允许将文本和内容拖放到 Dock 图标上。这是实现应用程序间通信的绝佳方式。在 MetaWindow 中，我们可以让拖到 Dock 图标上的字符串自动触发搜索。（我在这里写过一篇简短的实现细节。）让导出数据像拖放一样简单。假设你想通过邮件发送一份报告，如果能直接把表格拖进 Mail.app，让它自动转换成 PDF，那该多好？但如果你拖到一个纯文本邮件里呢？那它可以导出为纯文本。如果导出数据一直这么简单，而且不同应用之间真正协作，那该多棒？在拖放数据时要考虑上下文。如果用户正在输入电话地址，能用正则表达式从一段文字中解析出电话号码就很棒了。如果拖进来的是一个电话号码列表，它能自动识别并全部添加进去，那就更好了。我们习惯于给应用程序提供严格格式的输入，但真正能让用户随意丢数据、然后由应用自动处理细节的程序，才更有可能让用户爱上它。当然，我们必须让用户知道他们可以随意丢数据，因为他们已经被训练成计算机的秘书，如果你的应用不解放他们，他们是不会主动这么做的。

总而言之，拖放就是 Cocoa 编程中的 Unix 管道。它是让应用程序之间协作最简单、最无缝的方式。一旦我们开始发挥创意，它就会开启一个充满意想不到的组合与实用性的世界。

拖放功能：通过拖放进行搜索

在 MetaWindow 中，我们打算实现两种拖放功能，首先是允许用户把文本拖到搜索窗口中来进行搜索。不只是搜索文本框，而是整个包含文本框的窗口。这样能增大有效点击区域，使用起来也更快。

我们首先需要打开 MWController.py，创建一个辅助函数，它接受一个搜索字符串作为参数，然后执行搜索（同时更新文本框显示搜索字符串以提供视觉反馈）。我们需要这样做，因为接下来我们要子类化 NSWindow 来监听拖放操作，如果在子类中处理搜索逻辑，就得重复实现搜索代码。通过给 NSWindow 子类添加一个 IBOutlet 并将其连接到 MWController 的 search_ 方法，我们就能避免重复代码。

因此我们要在 MWController 中添加 dragSearch 方法。

def dragSearch(self,searchString):
    self.textField.setStringValue_(searchString)
    self.search_(self)

dragSearch 其实只是把子弹装进 search_ 的枪膛，然后扣动扳机。

现在，我们需要创建一个新文件。前往“文件”菜单，选择“新建文件”（Command-N）。我们实际上想子类化 NSWindow，但没有现成的模板，所以我们先创建一个 Python 的 NSObject 子类文件，然后根据需要修改。把文件命名为 MWDragWindow.py，并把它拖到 Xcode 大纲视图的 Classes 分组中（纯粹为了组织管理）。

接下来——这个容易忘记但非常关键的步骤——打开 main.py，添加对 MWDragWindow 的 import，让它看起来像这样：

# import modules containing classes required to start application and load MainMenu.nib
import metaweb
import MetaWindowAppDelegate
import MWController
import MWDragWindow

现在打开 MWDragWindow.py 文件，我们可以开始工作了。

在文件顶部，你需要导入 from AppKit import * 和 import objc，让导入部分变成这样：

import objc
from Foundation import *
from AppKit import *

接下来我们要把 MWDragWindow 从继承 NSObject 改成继承 NSWindow。同时给它添加一个名为 controller 的 IBOutlet。

class MWDragWindow(NSWindow):
    controller = objc.IBOutlet()

继续，我们开始让它支持拖放操作。第一步是注册它要响应的粘贴板类型。这里我们只想监听 NSStringPboardType，即文本的粘贴板类型。

要注册拖放类型，需要调用对象的 registerForDraggedTypes_ 方法，传入一个要监听的类型列表。通常最简单的方法是在 awakeFromNib 方法中完成，因为该方法会在对象初始化时被调用。

对于 MWDragWindow，代码非常简单：

def awakeFromNib(self):
    self.registerForDraggedTypes_([NSStringPboardType])

注意要给 registerForDraggedTypes_ 传入一个列表，而不是直接传入 NSStringPboardType。

关于用户自定义粘贴板类型的简短说明。

Cocoa 已经支持多种不同类型的粘贴板。我们正在使用 NSStringPboardType，但还有很多其他现成的类型可供选择：NSUrlPboardType、NSColorPboardType、NSFilenamesPboardType、NSFileContentsPboardType 等等。

不过有时候，你要拖放的内容不属于任何现有的粘贴板类型。这时，你可以创建自己的粘贴板类型。粘贴板类型实际上只是一个字符串，所以创建一个粘贴板类型只需定义一个模块级变量，包含这个字符串，然后在任何使用同一粘贴板的其他模块中导入它即可。

## Some Module A
MWRowPboardType = u"MWRowPboardType"
class MyWindow(NSWindow):
def awakeFromNib(self):
self.registerForDraggedTypes_([MWRowPboardType])

在另一个模块中使用它时是这样的：

from module_a import MWRowPboardType
class AnotherWindow(NSWindow):
    def awakeFromNib(self):
        self.registerForDraggedTypes_([MWRowPboardType])

通常，用户自定义的粘贴板类型只能在声明它的应用程序内使用，因为其他应用程序不知道它的存在。不过，如果开发者主动公开他们粘贴板的字符串，就不一定是这样了。

现在 MWDragWindow 已经注册了 NSStringPboardType，我们还需要实现两个方法来告诉它如何处理传入的拖放。

第一个是 draggingEntered_，用于决定用哪种视觉效果来表示传入的拖放。例如，如果你正在把文本拖进一个文本框，可能希望使用 NSDragOperationAdd；但如果你是在把对象链接在一起，则更适合使用 NSDragOperationLink。不过最重要的操作可能是 NSDragOperationNone，当你拒绝一个拖放事件时就返回它。

当你返回 NSDragOperationNone 时，就不会有任何视觉反馈，表示这个对象拒绝处理该拖放类型。这为用户提供了视觉提示，告诉他们应用程序/窗口/字段可以接受哪些类型的数据。

在 MWDragWindow 中，我们这样实现 draggingEntered_：

def draggingEntered_(self,sender):
    pboard = sender.draggingPasteboard()
    types = pboard.types()
    opType = NSDragOperationNone
    if NSStringPboardType in types:
        opType = NSDragOperationCopy
    return opType

如果粘贴板包含 NSStringPboardType，我们就接受，否则拒绝。我们使用 NSDragOperationCopy 的视觉效果，因为这是文本框响应 NSStringPboardType 时使用的效果，在不同拖放视觉效果之间切换可能会让人不安（除非你想表示拖放到不同位置会有不同行为，那样就完全合适）。

draggingEntered_ 负责接受或拒绝拖放以及显示拖放的视觉效果，但目前我们还没有处理传入拖放的内容。这通过实现 performDragOperation_ 来完成。

def performDragOperation_(self,sender):
    pboard = sender.draggingPasteboard()
    successful = False
    if NSStringPboardType in pboard.types():
        txt = pboard.stringForType_(NSStringPboardType)
        self.controller.dragSearch(txt)
        successful = True
    return successful

如果我们从 performDragOperation_ 返回 False，应用程序会视觉上表示拖放被拒绝——如果返回 True，则表示拖放成功——但实际处理传入数据的责任在于我们。

这里我们只是调用 MWController 的 dragSearch 方法，把粘贴板中 NSStringPboardType 对应的字符串传给它，让 MWController 来处理后续工作。

最后要做的事情是打开 Interface Builder 并做一些修改，所以现在打开 MainMenu.xib。

打开 Inspector，选择 Window (Window)，切换到第六个标签页。此时 Inspector 的标题会变成 Window Identity。

在 Inspector 顶部的 Class Identity 部分，在 Class 字段中把 NSWindow 替换为 MWDragWindow。然后在包含所有对象的窗口中，按住 Control 键，从 Window (Window) 拖动到 Controller 并释放。从弹出菜单中选择 controller。

现在把一些文本拖到窗口中，松开鼠标，它就会开始搜索，就像我们在文本框中输入文本并点击搜索一样。

拖放功能：通过拖动导出数据

既然我们已经在窗口中实现了拖放，接下来要看看另一个常见的拖放场景：在 NSTableView 中实现拖放。

传统上，拖放是由 NSTableView 的 datasource 处理的，但如果你还记得第二部分，我们还没有指定 datasource，所以处理方式会有所不同。事实上，我们将通过子类化 NSArrayController 类，并在 MainMenu.xib 中把控制器对象的类改成我们的自定义类来实现拖放。

让我们先在项目中创建一个新文件，从 NSObject 子类化，命名为 MWDragArrayController.py，并把 import 添加到 main.py，让 main.py 中的导入部分变成这样：

# import modules containing classes required to start application and load MainMenu.nib
import metaweb
import MetaWindowAppDelegate
import MWController
import MWDragWindow
import MWDragArrayController

现在回到 MWDragArrayController.py，把 MWDragArrayController 从继承 NSObject 改成继承 NSArrayController，同时从 AppKit 导入 NSStringPboardType。

from AppKit import NSStringPboardType
from Foundation import *
class MWDragArrayController(NSArrayController):
pass

我们先快速绕道一下，打开 Interface Builder 中的 MainMenu.xib。选中 Array Controller 实例，打开 Inspector，选择 Identity 标签（第六个），把类从 NSArrayController 改为 MWDragArrayController。

然后，这个很容易忘记但非常重要的步骤：选中 table view（注意不是包含它的 scroll view，所以要点击两次），将其 delegate 和 datasource 出口都连接到 Drag Array Controller。

保存并关闭 Interface Builder，返回编辑 MWDragArrayController.py。

令人惊讶的是，我们几乎已经完成了！只需要在 MWDragArrayController 中添加这个方法：

def tableView_writeRows_toPasteboard_(self,tv,rows,pb):
    arranged = self.arrangedObjects()
    data = ",".join([ arranged[x]['name'] for x in rows ])
    pb.declareTypes_owner_([NSStringPboardType],self)
    pb.setString_forType_(data,NSStringPboardType)
    return True

保存并构建应用，搜索一些内容，然后把表格中的一行拖出来。很酷吧，但还有点不对劲：你不能拖到其他应用程序里。这很不方便，大大降低了拖放的实用性。

要修复这个问题，打开 MWController，找到 awakeFromNib 方法，添加下面这行代码：

self.tableView.setDraggingSourceOperationMask_forLocal_(NSDragOperationCopy, False)

综合起来，MWController 的 awakeFromNib 方法应该是这样的：

def awakeFromNib(self):
    if self.tableView:
        self.tableView.setTarget_(self)
        self.tableView.setDoubleAction_("open:")
        self.tableView.setDraggingSourceOperationMask_forLocal_(NSDragOperationCopy, False)

现在保存并再次构建 MetaWindow。你应该可以把表格行的内容拖到其他应用程序中了。

这就总结了我们在 MetaWindow 中对拖放功能的探索。我们不会再研究把数据拖进表格视图，主要因为我实在想不出任何有意义的使用场景——毕竟我们展示的 Metaweb 结果是不可变的。如果 MetaWindow 未来被扩展为可以修改数据，那么这种操作可能会有价值（比如作为一种导入数据的方式）。

使用第二个 Nib 文件

是时候开始探讨 Epic PyObjC 教程系列的最后一个主题了，这也是一个非常重要的主题：在同一个项目中使用多个 nib 文件。很多应用程序可以避免使用多个 nib。例如，如果你看 iTunes 处理播放列表的方式，默认情况下点击一个播放列表，它就会在主窗口的列表中显示。

这用一个 nib 就能实现。毫无问题。但如果你双击一个播放列表，它会打开一个新窗口。而这个操作用一个 nib 是无法实现的（除非你用代码手动创建并填充窗口，虽然可行，但通常要多做很多工作）。

一旦你从简单应用升级到更复杂的程序，就必然需要学习如何在一个项目中使用多个 nib——就像我们在本教程中看过的所有内容一样，一旦你坐下来认真做，其实并没有那么难。

目前，当你双击一行时，它会在网页浏览器中打开该条目的页面，但如果能改成打开一个新窗口，显示关于该条目的更多详细信息，那就更好了。目前我们只是浅尝辄止地使用了 metaweb.py 返回的数据，如果给每个结果分配一整个窗口，我们可以展示多得多的信息。

要把额外的 nib 集成到项目中，我们需要完成三个步骤：

创建一个自定义的 Python 类，继承自 NSWindowController，在初始化时接收特定行的字典。创建一个新的 nib，我们把它叫做 RowWindow.xib，在其中将 File's Owner 的类设置为我们自定义的 NSWindowController 子类。更新 MWController 中的 open_ 方法，让它使用 RowWindow.xib 创建新窗口，而不是在浏览器中打开条目页面。

子类化 NSWindowController

首先，我们创建一个名为 MWRowWindowController.py 的新文件。最初它会继承自 NSObject，但我们要把它的父类改为 NSWindowController，同时给它添加一个名为 rowDict 的属性。

class MWRowWindowController(NSWindowController):
    rowDict = None

然后像往常一样在 main.py 中导入它：

# import modules containing classes required to start application and load MainMenu.nib
import metaweb
import MetaWindowAppDelegate
import MWController
import MWDragWindow
import MWDragArrayController
import MWRowWindowController

就这样。

创建 RowWindow.xib

创建一个新文件，这次选择 Window XIB 模板，命名为 RowWindow.xib。然后在 Interface Builder 中打开它。

首先打开 Inspector，选中 File's Owner，然后切换到 Identity 标签，把它的类从 NSObject 改为 RowWindowController。接着在 nib 的窗口中创建一个 NSTextField，选中它，切换到 Bindings 标签。

对于 Value 绑定，把它绑定到 File's Owner，在 Model Key Path 中输入 rowDict.name。

这是又一个使用 Cocoa 绑定来避免重复代码的例子。它们是你的好朋友。

最后，我们需要点击 File's Owner，把它的 window 出口连接到 Window (Window)。

更新 open_ 方法

除了两个大问题

嗯……“完成”可能说得有点太早了。我们当前的实现有两个明显的问题。首先是我们对 rwc 调用了 retain，但从来没有调用 release，所以没有让垃圾回收器释放那个窗口。

第二个问题是，如果你连续两次点击同一行，就会为同一个条目打开两个窗口。如果它能把已存在的窗口提到最前面，而不是再创建一个，那就优雅多了。

好消息是，这两个问题的解决方案是重叠的，而且不会花太多时间。

首先在 MWController 中添加一个名为 rowCache 的属性，初始化为一个空字典。

class MWController(NSObject):
    tableView = objc.IBOutlet()
    textField = objc.IBOutlet()
    arrayController = objc.IBOutlet()
    indicator = objc.IBOutlet()
    results = []
    rowCache = {}
    _cache = None

我们将使用 rowCache 来跟踪窗口控制器，以便能够复用它们。现在我们最后一次重写 open_ 方法：

现在来解决“没有调用 release”的问题。

认识 dealloc

到目前为止，在我们探索 PyObjC 和 Cocoa 的旅程中，我们已经接触了许多 Cocoa 主题和概念：release、retain、Cocoa Bindings、NSArrayController 以及拖放功能。我要添加到你工具箱的最后一个工具是 dealloc。dealloc 是在继承自 NSObject 的对象即将被垃圾回收释放内存时调用的方法。这是你在所有被 retain 的引用变成内存泄漏之前，最后一次清理它们的机会。

每个 dealloc 方法都包含两个步骤（顺序非常重要）：

释放所有被 retain 的对象。调用父类的 dealloc 方法。

第二步很容易忘记，但它也是导致内存泄漏的常见原因之一。

MWController 的 dealloc 方法应该是这样的：

def dealloc(self):
    for key in self.rowCache:
        value = self.rowCache[key]
        value.release()
    super(MWController,self).dealloc()

以后你应该读一读《Cocoa 内存管理指南》，它全面介绍了深入内存管理时会遇到的各种微妙之处。
