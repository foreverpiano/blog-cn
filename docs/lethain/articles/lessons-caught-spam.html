从垃圾评论中吸取的教训

2008-01-22 · 阅读原文

据我所知，LifeFlow 至今还没有任何垃圾评论成功突破其防护机制1。其核心防护手段是一个反向验证码（reverse-captcha），相关高质量讨论已经很多，我就不再赘述了。这里我们只来看看从捕获到的垃圾评论中获得的一些意想不到的启发和失败案例。

垃圾发送者会使用 Unicode？

这是一份较早的错误报告，当时 LifeFlow 所使用的 Markdown 实现还没有支持 Unicode。

触发错误的留言只是一大堆链接，根本不需要 Unicode。但显然脚本编写者没有想到，会有如此简陋的评论系统，连插入几个 Unicode 字符都会崩溃。

糟糕的实现

下面是另一条由垃圾评论触发的有趣错误信息：

LifeFlow 的评论系统希望输入的是 Markdown 格式的文本，而当面对极其恶劣的输入——比如几百个垃圾链接组成的列表——渲染过程就会彻底崩溃。令人惊讶的是，垃圾评论的内容如此糟糕，以至于它直接把 Markdown 库推到了最大递归深度，导致程序崩溃。一个正常用户没有任何理由把系统推到这种极限，因此它的限制反而意外地变成了保护机制。

非人类的行为

这意味着你必须像人类用户一样，完整地走完整个流程：阅读文章、点击回复链接，并在合理时间内填写内容，否则系统将缺少必要的信息来处理这条评论。

当然，你可以把这个流程做得更智能，尝试猜测用户正在查看哪篇文章，或者让用户手动选择要评论的条目。但人类用户并不会遇到这种情况。这又是一个“更糟即更好”的例子，尽管含义与通常所说的不太一样。

撰写真实的故事

最后，我认为从中得到的宝贵教训是：我们应该把时间花在撰写真实用户真正想做的事情的故事上。有时候我们会花费大量精力去处理假设的极端情况，这些情况给程序增加了许多复杂性，也消耗了大量时间，却并没有真正提升系统对真实用户的体验。

这里的垃圾评论算是一个比较特殊的例子，因为一个更好的实现所带来的负面后果，通常不会像这个案例中那么明显2。但它仍然很好地说明了：如果我们去实现那些对合法用户无关紧要的故事，可能会产生意想不到的后果。
