YUI Get 的神奇力量之源

2008-10-03 · 阅读原文

最近我在工作中开始使用 Yahoo! User Interface Library，对它产生了新的敬意。之前我对 YUI 的印象是它又重又笨拙（请注意我其实从未真正用过它，所以这个印象一半来自道听途说，一半来自完全的空白）。基本上，我对 YUI 的抱怨就是它不是 jQuery。虽然我至今在很多方面还是更喜欢 jQuery，但这更多是权衡取舍的问题，而非一方完全碾压对方（我发现 YUI 的 Event 库比 jQuery 更灵活，而 jQuery 的链式调用在 DOM 遍历时则更胜一筹）。

但我不是来讨论 jQuery 与 YUI 孰优孰劣的。我想说的是 YUI 中一个既让人困惑又令人惊叹的组件——Yahoo.util.Get。

首先来个小测验。去看看 Get 的源码，试着搞清楚它是怎么完成这个不可能的任务的：它能够在不使用 XMLHttpRequest，也不通过本地服务器代理的情况下，从其他域名动态加载内容。

我在这儿等着。

我当时在做一个项目，很想利用这项天才般的魔法，来绕过 XMLHttpRequest 对跨域请求的限制。我只想从服务器抓取一个文本文件而已。既然它能神奇地远程加载脚本和 CSS，那处理这种简单需求应该不在话下吧。

大错特错。大错特错。大错特错。

我翻遍代码试图搞清楚它到底是怎么请求数据的。究竟是什么神秘工具完成了这次数据传输？大约一个小时的极度困惑和更加惨烈的失败之后，我终于弄明白了。

这个库是通过向 DOM 中动态注入 link 和 script 标签来获取脚本和 CSS 文件的，这会让浏览器自动去下载这些额外文件。这居然真的能行，简直刷新了我的认知。
