YUI Get 组件的魔法力量

2008-10-03 · 阅读原文

最近在工作中开始使用 Yahoo! User Interface Library（YUI），对它产生了新的敬意。以前我对 YUI 的印象是它又重又笨拙（注意，我其实从未真正使用过它，所以这个印象一半来自道听途说，一半来自完全的臆想）。基本上，我对 YUI 的不满在于它不是 jQuery。虽然我仍然在很多方面更喜欢 jQuery，但这更多是权衡取舍的问题，而非一方完全碾压另一方（我发现 YUI 的 Event 库比 jQuery 的更灵活，而 jQuery 的链式调用在 DOM 遍历时则更胜一筹）。

但我今天不是来讨论 jQuery 与 YUI 孰优孰劣的。我想说的是 YUI 中一个既令人困惑又令人惊叹的组件——Yahoo.util.Get。

首先来个小测验。去看看 Get 组件的源码，试着搞清楚它是如何完成这个不可能的任务的：它能在不使用 XMLHttpRequest，也不通过本地服务器代理的情况下，从其他域名动态加载内容。

我在这儿等着。

我当时正在做一个项目，很想利用这个神奇的魔法来绕过 XMLHttpRequest 的跨域限制。我只想从服务器上获取一个文本文件。既然它能这么神奇地远程加载脚本和 CSS，那处理这种简单需求应该不在话下。

大错特错。大错特错。大错特错。

我翻阅着代码，试图弄清楚它到底是怎么请求数据的。究竟是什么神秘工具完成了这次数据传输？经过大约一小时的极度困惑和更加彻底的失败后，我终于想明白了。

这个库是通过向 DOM 中动态注入 link 和 script 标签来获取脚本和 CSS 文件的，这样浏览器就会自动下载这些额外文件。想到它竟然真的能行，我就觉得不可思议。
