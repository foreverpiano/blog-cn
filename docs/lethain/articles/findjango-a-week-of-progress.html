Findjango，一周进展

2009-03-16 · 阅读原文

Findjango 是我正在开发的 Django 垂直搜索引擎，它已经开源大约一周了。目前进展良好，而且——我得说——改进速度相当快。我非常希望 Findjango 能成为一个社区工具，所以让我简单介绍一下目前面临的障碍，以及我正在采取哪些措施来逐步解决它们。

第一周已经产生了大约 2500 次查询，不少结果被标记用于相关性调优，还有一位好心人用五十个并发客户端对它进行了负载测试。

扩展内容

我一直努力让内容高度聚焦于 Django，但这样做的一个副作用是，对于某些查询，可用的内容明显不足。搜索 Marty Alchin 的 Pro Django 可以得到 258 个极其相关的结果。而搜索 tutorial 会得到 4218 个非常平庸的结果，搜索 performance 则会得到 3402 个糟糕的结果。

为了改善这种情况，我周日大部分时间都在熟悉 whoosh（一个纯 Python 的全文索引和搜索库）以及 feedparser，现在已经具备了持久化索引 RSS（或 Atom）源的能力。也就是说，从昨天开始，所有经过 Django Community feed、This Week in Django feed 以及几个较小 feed 的内容，都已经被索引——并且会持续维护以供搜索。

这种方式无法收录较旧的内容，但它仍是工具箱里一个有价值的工具，未来也能让我为那些无法向 Findjango 直接暴露原生搜索 API 的网站索引内容。

如果你有包含 Django 内容的 RSS feed，但尚未被 Django community feed 收录，请告诉我，我会一并加入！

下一步将是搭建一个小型的网络爬虫流程，使用 Scrapy 来提取更旧的或非 feed 形式的内容。这大概还需要一到两周时间。

（我同时也在几个场合努力争取获得 API 的开放权限，这依然是让 Findjango 获取你内容的最佳方式。）

提升知名度

Findjango 面临的另一个主要障碍是，那些最能从它受益的人——即刚开始使用 Django 进行开发的新手——却最难发现它的存在。

如果我是 Yahoo! 或 Google，我会通过各种搜索协议进行交易，但由于预算有限，我采取了一个不同的策略，希望这个策略对网站所有者和 Findjango 都能有所帮助。

正如我上周提到的，我正在开放 Findjango 的 API。

curl http://findjango.com/service/?query=app%20engine
curl http://findjango.com/service/?query=app%20engine&start=10

该 API 以如下 JSON 格式返回结果：

{
  'total_results':200,
  'start':0,
  'count':10,
  'results':[
    {'title':'a','url':'http://etc','text':'yada yada'}
  ]
}

你可以用它为自己的网站添加 Django 专属搜索功能。我知道仅凭这一点可能还不够有吸引力，所以这里再加一点“特制调味料”作为额外诱因：你可以通过 site 参数传入自己的域名，这样来自你网站的结果将会被提升到结果集顶部。

这意味着——只要你告诉我可以在哪里找到你网站的 RSS feed，或者你提供一个搜索 API——你就可以使用 Findjango 为你的 Django 相关网站提供增强型站内搜索。

curl http://findjango.com/service/?query=tutorial&site=lethain.com

对于很多网站来说，我认为这会让 Findjango 变得真正有用。我也正在准备一些默认模板和/或 template tags，让使用 Findjango 来驱动站内搜索变得越来越简单。

需要更好的设计

新的设计应该会在 Findjango 满两周之前上线。很抱歉让大家这么久一直忍受目前这个版本，但很快就会有明显改善。

以上概述并不是过去一周所有改动的完整清单（还包括集成 GitHub 搜索 API、与 DjangoCodeSearch 的少量集成、Findjango 成为 Firefox 可自动发现的搜索引擎等等），但希望它能让你放心，Findjango 正朝着正确的方向前进，并逐步演化成一个有价值的解决方案。

一如既往，欢迎任何反馈。
