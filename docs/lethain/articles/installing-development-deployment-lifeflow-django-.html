最后，我们还需要向 settings.py 添加一些 LifeFlow 专用的配置项：

前两个（LIFEFLOW_KEYWORDS 和 LIFEFLOW_DESCRIPTION）允许你设置博客的 meta keywords 和 meta description。

LIFEFLOW_BLOG_NAME 用于设置你的博客名称。它应该是一个字符串。默认值是“Unconfigured LifeFlow”，你可能不想用这个名字称呼自己的博客，虽然现在想想还挺有讽刺意味的。

LIFEFLOW_AUTHOR_NAME 用于为侧边栏的“About”链接指定目标，因此相当重要。我们还没有为博客创建第一个 Author（很快就会做），但这个设置允许你指定“About”链接所指向的作者个人资料/简介。如果你不设置这个值，LifeFlow 会自动将“About”链接指向主键为 1 的 Author。（如果你指定了一个无效的字符串（即与任何作者名称都不匹配），它将会把用户导向一个无效页面。）

LIFEFLOW_USE_PROJECTS 的值为 True 或 False（默认为 True），它会决定是否在每个页面顶部的链接中显示指向项目页面的链接。（Project 很像博客文章，但它们没有关联日期，因此它们的 URL 是 /projects/lifeflow/ 而不是类似 /entry/2008/jan/03/lifeflow/ 的形式。它们还有其他一些区别，但本质上被用作简单的作品集。）

LIFEFLOW_GOOGLE_ANALYTICS_ID 用于指定你网站的 Google Analytics ID。如果你不想使用 Google Analytics，将其留空或设置为 None 都是完全可以的。

接下来的两个（LIFEFLOW_TEMPLATE_AUTHOR 和 LIFEFLOW_TEMPLATE_AUTHOR_URL）用于覆盖你所使用模板的作者信息。如果你在 settings.py 中没有指定任何内容，它们将默认使用默认模板的创建者（那应该就是我）。但是，如果你明确将其中任意一个设置为 None，那么那里将不会显示任何内容。

最后三个变量可能是最有趣的。它们都期望一个格式如“/media/lifeflow/mystyle.css”或“/media/myjs.js”或“/media/lifeflow/header.js”这样的字符串。简单来说，它们期望的是文件的绝对路径。

LIFEFLOW_CUSTOM_CSS 期望一个 CSS 文件，它会在加载完所有其他 LifeFlow CSS 之后再加载这个文件。这是在不破坏 SVN 检出内容的情况下自定义 LifeFlow 最简单的方式。几乎每个 DIV 都有命名以便于这种方式（尽管在默认未修改的模板中，很多 DIV 并没有关联任何 CSS 样式）。

LIFEFLOW_CUSTOM_JS_HEADER 和 LIFEFLOW_CUSTOM_JS_FOOTER 作用类似，只是它们期望的是 JavaScript 文件。前者会在文件的 head 部分加载 JavaScript，后者则会在 body 标签关闭之前作为最后的内容加载 JavaScript。

所有三个 LIFEFLOW_CUSTOM_ 开头的配置都是可选的，可以通过设置为 None 来明确禁用（但简单地不指定它们也能达到相同效果）。

接下来怎么做

很快我就会发布一篇关于生产环境部署 LifeFlow 的文章，但在那之前，你仍然有很多方式可以自己去了解 LifeFlow。首先，这个项目还比较年轻，仍缺少一些功能（例如，我不太喜欢 traceback，所以还没有实现，但如果你实现了，我很乐意把这些改动推送到 SVN）。
