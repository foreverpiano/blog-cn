安装 LifeFlow 的开发环境：一个基于 Django 的博客方案

2008-01-07 · 阅读原文

在我主导的最近一次 LifeFlow 冲刺开发之后，现在终于到了我坐下来，为非我本人的人写一系列安装 LifeFlow 文章的时候了。我说“系列”，不是因为安装很难，而是因为我设想了这样一个递进过程：

为已经熟悉 Django 的人准备的本地开发环境安装教程；为 Django 新手准备的更深入的扩展版教程；探讨如何在拥有 root 权限的虚拟或真实服务器上部署 LifeFlow；探讨如何在 DreamHost 上部署 LifeFlow。

这是该系列中的第一篇文章：为已经熟悉 Django 的人安装 LifeFlow 的开发环境（注意：本文包含了经验丰富的 Django 用户部署生产环境版本的 LifeFlow 所需的一切知识，但并未刻意去串联生产环境的各个点。关于该主题的更明确的教程将在后续发布）。

所需库

首先，LifeFlow 使用的是 Django 的 SVN trunk 版本。不幸的是，它无法与更早的版本兼容。等到 Django 1.0 发布后，会有对应的 LifeFlow 1.0 版本，但目前它只能与 trunk 版本良好配合。

接下来你需要安装两个 Python 库：pygments 和 markdown。最简单的方法是：

easy_install pygments
easy_install markdown

获取代码

第一步是从 SVN 获取一份 LifeFlow 的副本。

svn co http://www.willarson.com/lifeflow/trunk/lifeflow

接下来你需要让 Python 可以访问这个签出目录。你需要找到你的 site-library 所在位置：

python -c "from distutils.sysconfig import get_python_lib; print get_python_lib()"

然后创建一个指向 lifeflow 的符号链接：

ln -s `pwd`/lifeflow /somewhere/site-library/lifeflow

接着你需要验证符号链接是否正确。启动 Python 解释器并尝试：

import lifeflow

如果没有抛出任何错误，那么一切正常。如果出现错误，你需要查看你的 site-library 目录，确认 lifeflow 是否存在，并找出哪里出了问题（很可能是个拼写错误）。

创建 Django 项目

接下来我们需要为 LifeFlow 创建一个项目（LF 只是一个 Django app，而不是一个完整的 project）。

django-admin.py startproject blog

如果你的系统 PATH 中没有 django-admin.py，你可能需要手动找到它。它位于你的 Django 签出目录下的 django/bin 文件夹中。

现在我们需要编辑新创建的项目中的 settings.py 文件。

首先你需要设置数据库。因为这是开发环境，我使用 sqlite3 以简化操作。（你需要将路径修改为你系统中实际存在的文件夹。）

DATABASE_ENGINE = 'sqlite3'
DATABASE_NAME = '/Users/will/django/blog/db.db'

以下是其他需要进行的修改（请记住 MEDIA_ROOT 和 TEMPLATE_DIRS 需要根据你的签出目录进行调整，因为它们在你那里可能和我不一样）：

LOGIN_URL = "/editor/login/"
LOGOUT_URL = "/editor/logout/"
LOGIN_REDIRECT_URL = "/editor/"
MEDIA_ROOT = '/Users/will/django/lifeflow/trunk/lifeflow/media'
MEDIA_URL = 'http://127.0.0.1:8000/media/'
# This is because we'll be using the development file
# server to serve our static media, and it gets confused
# sometimes if we don't do this
ADMIN_MEDIA_PREFIX = '/admin_media/'
TEMPLATE_DIRS = (
    'Users/will/django/lifeflow/trunk/lifeflow/templates',
)
TEMPLATE_CONTEXT_PROCESSORS = (
    "django.core.context_processors.auth",
    "django.core.context_processors.debug",
    "django.core.context_processors.i18n",
    "django.core.context_processors.media",
    "lifeflow.context.blog",
)
INSTALLED_APPS = (
    'lifeflow',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.sites',
    'django.contrib.admin',
    'django.contrib.markup',
)

最后，我们还需要在 settings.py 中添加一些 LifeFlow 专属的配置项：

LIFEFLOW_KEYWORDS = "Blog Will Larson Programming Life"
LIFEFLOW_DESCRIPTION = "Will Larson's blog about programming and other things."
LIFEFLOW_BLOG_NAME = "Irrational Exuberance"
LIFEFLOW_AUTHOR_NAME = "Will Larson"
LIFEFLOW_USE_PROJECTS = True
LIFEFLOW_ANALYTICS_ID = None
LIFEFLOW_TEMPLATE_AUTHOR = "Will Larson"
LIFEFLOW_TEMPLATE_AUTHOR_URL = "http://www.lethain.com"
LIFEFLOW_CUSTOM_CSS = None
LIFEFLOW_CUSTOM_JS_HEADER = None
LIFEFLOW_CUSTOM_JS_FOOTER = None

前两个（LIFEFLOW_KEYWORDS 和 LIFEFLOW_DESCRIPTION）用于设置你博客的 meta keywords 和 meta description。

LIFEFLOW_BLOG_NAME 用于设置博客名称。它应该是一个字符串。默认值是“Unconfigured LifeFlow”，你可能不想用这个名字来称呼自己的博客——不过现在想想，它还挺有讽刺意味的。

LIFEFLOW_AUTHOR_NAME 用于指定侧边栏“关于”链接的目标，因此相当重要。我们还没有为博客创建第一个 Author（很快就会做），这个设置允许你指定“关于”链接指向的作者简介。如果不设置此值，LifeFlow 会自动将“关于”链接指向主键为 1 的 Author。（如果你指定了一个无效的字符串（即不对应任何作者名称），它就会把用户带到无效页面。）

LIFEFLOW_USE_PROJECTS 的值是 True 或 False（默认为 True），它会相应地在每个页面顶部的链接中显示或隐藏指向项目页面的链接。（项目很像博客文章，但没有关联日期，所以它们的 URL 是 /projects/lifeflow/ 而不是类似 /entry/2008/jan/03/lifeflow/ 的形式。它们还有其他一些区别，但主要被用作简单的作品集。）

LIFEFLOW_GOOGLE_ANALYTICS_ID 用于指定网站的 Google Analytics ID。如果你不想使用 Google Analytics，将其留空或设置为 None 都是完全可以的。

接下来的两个（LIFEFLOW_TEMPLATE_AUTHOR 和 LIFEFLOW_TEMPLATE_AUTHOR_URL）用于覆盖当前模板的作者信息。如果你在 settings.py 中不指定任何内容，它们会默认使用默认模板的创建者（那应该就是我）。但是，如果你明确将其中任何一个设置为 None，那么那里将不显示任何内容。

最后三个变量可能是最有趣的。它们都期望一个格式为“/media/lifeflow/mystyle.css”或“/media/myjs.js”或“/media/lifeflow/header.js”等字符串，也就是一个文件的绝对路径。

LIFEFLOW_CUSTOM_CSS 期望一个 CSS 文件，它会在加载完所有其他 LifeFlow CSS 之后再加载这个文件。这是在不破坏 SVN 签出的情况下自定义 LifeFlow 的最简单方式。几乎每个 DIV 都被命名以支持这种方式（尽管在默认未修改的模板中，其中很多 DIV 并没有关联任何 CSS 样式）。

LIFEFLOW_CUSTOM_JS_HEADER 和 LIFEFLOW_CUSTOM_JS_FOOTER 与上面类似，只是它们期望的是 JavaScript 文件。前者会在文件的 head 部分加载 JavaScript，后者则会在 body 标签关闭前作为最后的内容加载。

所有三个 LIFEFLOW_CUSTOM_? 配置都是可选的，可以通过设置为 None 来显式禁用（但不指定它们也能达到同样效果）。

编辑 urls.py

现在我们需要修改新创建项目中的 urls.py 文件。删除已有的内容，粘贴以下代码：

from django.conf.urls.defaults import *
from django.conf import settings
urlpatterns = patterns(
'',
(r'^media/(?P<path>.*)$', 'django.views.static.serve', {'document_root': settings.MEDIA_ROOT }),
(r'^admin/', include('django.contrib.admin.urls')),
(r'^', include('lifeflow.urls')),
)

这是我用于开发的“懒到极致”的 urls.py。它使用 Django 的开发服务器（速度慢，不适合生产环境，你懂的）来提供静态媒体文件，并从 settings.py 中获取 document_root。

保存 urls.py。

启动开发服务器

好了，现在我们只需要同步模型和数据库：

python manage.py syncdb

然后运行开发服务器：

python manage.py runserver

这样 LifeFlow 就运行起来了，不过在结束之前，我们还需要在 Django 管理后台进行一些快速修改。

与 Django Admin 的短暂相遇

打开浏览器，访问 http://127.0.0.1:8000/admin/。

第一处修改是编辑 Sites 应用中的站点信息。你需要将 settings.py 中指定的主键（默认为 1）的站点修改为你的实际站点。例如我把域名和显示名称都设为 'www.lethain.com'。这个域名会被 feed 和 syndication 框架（LifeFlow 大量使用）使用，也会被每篇文章末尾的社会化分享链接使用。

接下来你需要创建一个 Author。如果你在 LIFEFLOW_AUTHOR_NAME 中指定了名称，请确保这里创建的 Author 名称与之匹配。

然后你至少需要创建一个 Flow。标题会出现在每个页面上，所以选一个你喜欢的。slug 用于 URL，如果你喜欢可以做得更短。

如果你将 LIFEFLOW_USE_PROJECTS 设置为 True，那么你还需要至少创建一个 project。如果你不创建项目，那么页面顶部的 Projects 链接在你后续创建项目之前都会跳转到 404 错误页。

（你现在可能不想做这件事，但你可能会注意到 Django Admin 中的“Sites to Notify”条目。它允许你在更新文章时 ping 像 Ping-O-Matic 这样的站点。我个人只使用 Ping-O-Matic，但 LifeFlow 的理念是灵活性，所以你可以定义任意站点。Ping-O-Matic 的设置相当简单：标题随便填，ping 的 URL 设为 'http://rpc.pingomatic.com/'，然后博客标题和博客 URL 分别填你的博客名称和地址（例如 'Irrational Exuberance' 和 'http://www.lethain.com'）。）

下一步怎么做

很快我就会发布关于部署生产环境 LifeFlow 的文章，但在那之前，你还有很多方式可以自己去了解 LifeFlow。首先，这个项目还比较年轻，仍缺少一些功能（例如，我不太在意 traceback，所以还没有实现，但如果你实现了，我很乐意把这些改动 push 到 SVN 中）。

如果这不是你喜欢的，你可以尝试在 settings.py 中使用 LIFEFLOW_CUSTOM_CSS 设置来加载自定义 CSS 文件，从而个性化你的博客外观。（我希望在不久的将来能就这种自定义博客外观的方法发一篇快速文章。）

除此之外，我非常希望收到关于 LifeFlow 的更多反馈。你觉得它缺少哪些功能？有什么不满的地方？设置过程中遇到困难了吗？告诉我，我会尽力帮助！
