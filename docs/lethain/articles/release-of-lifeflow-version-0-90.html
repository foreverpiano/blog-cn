LifeFlow 0.90 版本发布

2008-06-10 · 阅读原文

今天，LifeFlow 发布了 0.90 版本。这款我持续开发了近十个月的 Django 博客解决方案，已从最初简陋的博客软件，成长为一个功能较为完善、不依赖 Django Admin、且日常使用起来相当舒适的工具。

0.90 版本的更新内容

我在今年二月首次推出了 [LifeFlow Editor]，而直到现在，它才真正成为一个全面而完善的编辑器。更新内容非常多，这里只挑几项重点来说。

项目开发已从我个人的私有 SVN 服务器迁移到 GitHub，这让其他人参与贡献变得更加容易。同时，我们还在 LightHouse 上建立了 issue 和 bug 跟踪系统。我一直欢迎更多贡献者加入，也非常乐意与任何人讨论关于 LifeFlow 的设计、规划或想法。

在 LFE 中可以为单篇文章分配和管理多个译者和作者。

LFE 保存时会给出视觉确认。这是一项不错的改进，因为 LFE 采用“按需保存”（更好的理解是：当你隐式地让它保存——比如修改了内容——而不是通过点击保存按钮显式地告诉它保存），以前并不清楚它是否真的已经推送了你的修改。同样重要的是，当保存失败时 LFE 也会明确提示你，这样你就不会丢失工作成果。

现在你可以在 LFE 内编辑博客链接、作者简介、项目、评论和文件。当然，用于组织管理的三个文章分组（草稿、编辑中的草稿和已发布的文章）依然保留。

你现在可以在文章仍处于草稿状态时就指定发布日期。由于博客文章只有到达指定发布日期才会公开，因此你又重新获得了对内容发布时间的精细控制，这项功能之前只能通过 Django Admin 实现。

所有标题字段都新增了一个实用的“标题大写”按钮，它会应用由 John Resig 编写的 JavaScript titlecasing 脚本（其灵感来自 John Gruber 的同类脚本）。

修复了大量 Bug。特别是文件上传器现在不会再覆盖已存在的文件。此外，生成 slug 的函数对无效字符的转义也变得更加健壮，这曾是我一段时间内不得不回退到使用 Django Admin 的首要原因。

在正文编辑窗口中内嵌了 Markdown 帮助和 Dynamic Blog Context（DBC）。连我自己有时都会忘记 DBC 标签，因此增加一个方便的内嵌帮助系统虽然简单，但非常实用。目前 Markdown 帮助内容还比较简略，我会在不久的将来更新完善它。

已兼容当前的 Django trunk 版本。

未来计划

我已经为 LifeFlow 的后续版本规划了一系列令人兴奋的新功能。

0.91 版本将专注于代码清理，让 LifeFlow 的代码和各个模块更加易于维护，包括大量的重构、代码重组和文档编写。0.92 版本的重心则是实现我称之为“文本魔法”的功能。这将引入博客文章文本的预处理器和后处理器，你能想到的各种实用特性都可以通过它们实现。例如：自动为所有提到 Luke Hatcher 的地方加上指向其主页的链接；识别文中提到的产品并自动生成 Amazon 购买链接；修正那些你总是写不对大小写的单词（比如 JavaScript）。0.94 版本（0.93 去哪儿了？？）将把 LifeFlow 打造成一个沙盒化的多人协作环境。换句话说，LifeFlow 将支持多种角色及对应的权限设置。比如“撰稿人”只能创建草稿，无法将其推进到编辑阶段；而“编辑”可以执行该操作，“管理员”则负责最终发布。这将极大提升客座投稿的体验，同时也让 LifeFlow 成为一个强大的联合博客协作工具。

这就是项目当前的状况。本博客正是运行在 LifeFlow 的 trunk 版本上，我通常每周会将其更新到最新 HEAD 一次。它已经足够稳定，我还为其开发了一个静态渲染模块（使用源码中自带的 StaticGenerator），适合那些无法可靠运行 Django 项目的虚拟主机使用。

如果你有任何问题或需要帮助，请随时告诉我。
