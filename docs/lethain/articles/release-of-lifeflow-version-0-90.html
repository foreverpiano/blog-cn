LifeFlow 0.90 版本发布

2008-06-10 · 阅读原文

今天，LifeFlow 发布了 0.90 版本。这款 Django 博客解决方案我已经持续开发了大约十个月。它从一个非常简单的博客软件，逐步成长为一个功能相当完善的工具——不再依赖 Django Admin，并且使用体验足够舒适，适合日常维护。

0.90 版本的更新内容

我在今年二月首次推出了 [LifeFlow Editor]，但直到现在，它才终于成为一个全面、完善的编辑器。改动非常多，这里只挑选几项重点来说。

项目开发已从我个人的私有 SVN 服务器迁移到 GitHub，这样其他人贡献代码会方便得多。同时我们在 LightHouse 上建立了 issue 和 bug 跟踪系统。我一直欢迎更多贡献者加入，也非常乐意和任何人讨论关于 LifeFlow 的设计、规划或想法。

在 LFE 中可以为单篇文章分配和管理多个译者和作者。

LFE 保存时会给出视觉确认。这是一项不错的改进，因为 LFE 采用“按需保存”（更好的理解方式是：当你隐式要求它保存——比如修改了内容——而不是通过点击保存按钮显式告知它）的方式，只要你修改内容就会保存，但之前无法明确知道更改是否真的已经推送成功。同样重要的是，当保存失败时 LFE 也会明确告知你，这样你就不会丢失工作成果。

现在你可以在 LFE 内部编辑博客链接、作者资料、项目、评论和文件。当然，用于组织管理的三个文章分类（草稿、编辑中的草稿和已发布的文章）依然保留。

你现在可以在文章仍处于草稿状态时就指定发布日期。由于博客文章只有到达指定发布日期才会对外可见，你再次获得了对内容发布时间的精细控制，这项功能此前只能通过 Django Admin 实现。

所有标题字段都增加了一个实用的“标题大小写”按钮，它会应用由 John Resig 编写的 JavaScript titlecasing 脚本，该脚本的灵感来自 John Gruber 的同类工具。

修复了大量 bug。特别是文件上传器不再允许覆盖已存在的文件。此外，slug 生成函数对无效字符的转义也更加健壮，这曾是之前我不得不频繁使用 Django Admin 的首要原因。

在正文编辑窗口中内置了 Markdown 帮助和 Dynamic Blog Context（DBC）。连我自己有时候都会忘记 DBC 标签，因此加入一个方便的行内帮助系统虽然简单，但非常实用。目前 Markdown 帮助内容还比较简略，我会在不久的将来更新完善它。

已适配最新的 Django trunk 版本。

未来规划

我已经为 LifeFlow 的后续版本规划了许多令人兴奋的新功能。

0.91 版本将专注于代码清理，让 LifeFlow 的代码和各个模块更加易于维护，包括大量的重构、结构调整和文档完善。0.92 版本的核心是实现我称之为“文本魔法”的功能，这包括博客文章文本的预处理器和后处理器，你能想到的各种实用特性都可以通过它们实现。例如，它可以自动将所有提到 Luke Hatcher 的地方加上指向其主页的链接、自动查找并生成 Amazon 产品链接、修正某些无法正确自动大写的单词（比如 JavaScript）等等。0.94 版本（0.93 去哪了？？）将专注于把 LifeFlow 打造成一个沙盒化的多人协作环境。换句话说，LifeFlow 将引入多种角色及对应的权限体系。比如某人可能是 Writer（作者），只能创建草稿但不能将其推进到编辑阶段；需要 Editor（编辑）来完成这一步，而只有 Administrator（管理员）才能最终发布文章。这将大大提升客座博客的协作体验，也让 LifeFlow 成为一个强大的联合博客写作工具。

以上就是项目当前的状态。本博客目前运行在 LifeFlow 的 trunk 版本上，我通常每周会将检出的版本更新到最新 HEAD。它已经足够稳定，我还为其开发了一个静态渲染模块（使用源码中自带的 StaticGenerator），供那些主机无法可靠运行 Django 项目的人使用。
