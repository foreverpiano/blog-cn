学会永远不犯错

2020-03-21 · 阅读原文

这是 staffeng.com 的一篇草稿指南

大多数人都遇到过那种自认为永远不会错的人。在每场讨论中，他们都会身体前倾、挺起肩膀，强行占据决策者的位置。他们会一直争论，直到自己的观点获胜，或者时间耗尽为止。他们往往是正确的，但这种正确会把房间里的氧气都吸走。随着他们在公司任职时间增长，他们可能会觉得自己变得非常有说服力，但这种说服常常表现为同事们的无奈妥协。

我合作过的少数几位技术领袖找到了一种既能永远不犯错、又不会主导整个房间的方法。他们能在保持正确的同时，为他人创造空间。在我看来，一直完美体现这一点的就是 Franklin Hu。我见过他多次可靠地化解激烈讨论——他始终致力于找到对所有人来说最好的结果，愿意放弃自己最初的立场，并且默认总会存在额外的信息，能把看似矛盾的观点统一成一个整体。

要成为一名资深技术领袖，你必须对技术和架构建立深厚的认知。而要真正以这样的领袖身份开展工作，你还必须培养同样深刻的务实态度，以及对技术“宗教”的 agnosticism，始终保持对自己的怀疑。这听起来像是一个悖论，但却是你每天都需要行走的平衡线。

倾听、澄清、读懂房间

很多时候你会看到工程师带着“自己的观点是正确的”这种自信进入讨论，目标就是让房间里的其他人同意他们的方案。这种心态把每一次会议都变成了零和辩论。即使在“最好的情况”下他们的方案被采纳，他们也没有机会从房间里的其他人身上学到东西，而且房间里的大多数人离开时也不太可能充满干劲。

最有效的工程师进入每一次会议时，目标是先就当前问题达成共识，理解房间内的需求和不同视角，并明确为了达成一致方案还需要做什么。他们把每一次会议都视为更大项目背景以及与房间里这些人关系中的一环。如果房间里的人已经准备好达成一致并推进某个方案，他们就会带领团队采用那个方案。如果房间还没准备好，他们不会强行推动。

要掌握这一点，你需要精通三种方法：通过提问来倾听、明确会议目的，以及懂得如何读懂房间。

通过提问来倾听是一种主动倾听的形式，目的是理解房间里其他人的观点。带着善意提出好问题的行为会打开对话，为他人提问创造空间和安全感。好的问题源于学习的愿望，而且非常具体。它们能让对话变得更锐利，也让回答者不必背负捍卫立场的压力。在一场可能剑拔弩张的会议中，先提出三个高质量的问题再分享自己的观点，你会发现整个房间的气氛都在你周围发生转变。

好的会议始于清晰的目的和议程，但很多会议并不符合这个标准，尤其是临时讨论。如果你发现自己陷入了一场目标不清晰的对话，那就去明确目的。花点时间问问大家，你对这个群体希望达成的目标的理解是否正确。这最好以一个澄清问题包裹的陈述形式出现，比如：“确认一下，我们这次的目标是决定是否要把项目发布推迟两周，对吗？”

需要注意的是，如果过于频繁地使用明确目的这个方法，它可能会适得其反。非但不能澄清对话，反而会制造对话的无效循环。大多数情况下，如果已经有人尝试过，就尽量不要再用。多次重新定义框架的会议，几乎总是以再安排一场会议而告终。

最后，在每场会议中你都要读懂房间。人们常常因为对话受挫而试图强行达成一致，这会给讨论制造过大的压力，导致难以善终。如果房间里的人立场相差太远，那就找出一个小群体，让他们有更多时间一起深入讨论，或者找一个合适的人在会后升级处理。如果抽屉里的东西实在太多，就别再拼命往里塞了。

如何练习

如果这些行为对你来说不是天生的，没关系——练习的机会无处不在。对文档的每一条评论都是机会，每一场会议都是机会，每一个 Pull Request 都是机会。

每周开始时，挑选其中一项技能，明确要在接下来参加的会议中有意识地运用它。如果你即将面对一场特别棘手的会议，不妨花些时间在脑海中演练，或者和同事一起练习如何使用这些方法来推动进展，尽管存在各种挑战。

难缠的人

上述方法在大多数时候都很有效，但并非总是如此。其中一个明显的例外，就是当你遇到一个“jerk”（难缠的人）的时候。这里所说的 jerk，是指那些拒绝向团队妥协、不愿意让步、也不愿意倾听的人。这种人还没有意识到：他们的职业生涯更多取决于是否容易与人共事，而不是技术上有多正确。

对付这类人的两种最有效方法是：

把他们不敢耍横的人拉进会议（比如他们的经理或 CTO）；或者在会议前投入大量精力先和他们达成一致，让他们感觉自己被听见，从而降低他们在会上搞破坏的可能性。

这两种做法可能都会让你觉得浪费时间，但它们往往是最有效的，尤其是当你并不经常和这个人打交道的时候。如果这个人属于你职责范围内的领域，或者是你经常合作的对象，那么你的责任就有所不同。这种情况下，尽可能善意但诚实地给他们反馈。可以给第二次。把两次反馈都记录下来，如果没有看到改善，就把你的顾虑连同具体记录一起，以面对面或视频的形式告知他们的经理。

另外，认识到你的职位带来的权威会让你免于遭受很多这类人的直接冲击，这一点也很有用。所以你感受到的“jerk”程度，其实已经比其他人感受到的要轻。如果这种行为对你来说都感觉接近底线了，对其他人可能就更严重了。

这样做的益处

这种方法之所以强大，是因为越复杂的项目，越容易因为人际冲突而脱轨，而不是技术本身的复杂度。这是一种可以重复使用的方法，能把紧张关系转化为合作伙伴关系。它看起来可能很慢，因为前期可能需要更长时间，但最终其实更快，因为你更有可能在没有干扰的情况下完成工作。

此外，作为资深领导者的持久力，既取决于你是否能取得突出成就，也同样取决于你能否维护好人际关系。你会看到很多人一时光芒万丈，但后来却因为缺乏支持而无法继续前进。如果你想避免这种结局，那就学会永远不犯错，并且永远不要停止练习。
