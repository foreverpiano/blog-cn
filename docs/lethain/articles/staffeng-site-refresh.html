StaffEng.com 及其他几个网站焕新

2025-04-20 · 阅读原文

在接下来一两周内，我即将宣布那本关于工程战略、目前仍未定名的书的书名和出版社。在此之前，我先为书的内容搭建了一个网站。该网站整体风格与这个博客基本一致，但进行了一些改进，例如首页的移动端渲染效果比这个博客历史上的表现要好得多。

完成这个网站后，我将这些改进也移植回了 lethain.com，随后决定一并应用到 staffeng.com 上。这部分工作稍微麻烦一些，因为 StaffEng 此前是一个 Gatsby 应用（为什么用 Gatsby？因为当时 Calm 的 Web 前端在使用 Gatsby，我想借此积累一些实际经验）。

周末我抽时间将其迁移到了 Hugo，并应用了相同的优化。现在你可以在 lethain:staff-eng 仓库或 staffeng.com 上看到更新后的效果。

以下是旧版网站截图。

这是更新后版本的截图。

总体而言，我觉得新版本读起来稍微轻松一些，也借此机会更新了各种链接。例如，我移除了原来的 newsletter 链接，转而指向这个博客的 newsletter，因为之前的邮件列表已经沉寂很久了。

说到“沉寂”，我还把这些更新应用到了 infraeng.dev——这是我那本可能（也可能不会）在未来某天写的基础设施工程书籍目前停滞已久的配套网站。这意味着我现在拥有四个基本结构一致、基于 Hugo 运行的不同内容网站：这个博客、staffeng.com、infraeng.dev，以及即将出版的那本书的网站。它们全部通过 GitHub Pages 实现自动构建和部署，对我来说一直是一个极其简单、可靠的工作流。

在做这些事情的时候，有人问我为什么不自己写一个博客服务器来托管所有博客。答案其实很简单。这些年来我为自己的博客写过三个服务器，前两个用 Python，最后一个用 Go。它们运行得都还不错，但维护最终成了一个痛点，因为它们需要真正的构建流水线，还要处理可能存在安全问题的各种依赖库。即使在最理想的情况下，运行它们的容器也会随着 Ubuntu 版本被弃用而定期结束生命周期。

从这些经历中我逐渐意识到，作为一个经常写作的人，你非常需要让自己的内容能够在一个可以稳定运行几十年的地方安家。哪怕是很小的维护成本，长期积累下来也会让人难以承受。我见过一些很好的博客最终因为不愿处理类似 WordPress 升级之类的问题而消失。这些问题单个来看都不大，但几十年累积起来就很可观。这也是我反对使用托管平台的原因：我相信 Substack 在五年后应该还在，但完全无法确定二十年后它是否还存在。而我知道自己那时还会继续写作，也希望以前写过的所有内容仍然可以被读者访问。
