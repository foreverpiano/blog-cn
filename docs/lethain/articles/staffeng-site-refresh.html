更新了 StaffEng.com 和其他几个网站

2025-04-20 · 阅读原文

在未来一两周内我即将公布那本暂未定名的《工程战略》书籍的书名和出版社之前，我先为它的内容做了一个网站。这个网站和本博客的格式基本一致，但做了一些改进，比如首页的移动端渲染效果比这个博客历史上要好得多。

完成这个工作后，我把这些改进也移植回了 lethain.com，同时决定把它们也应用到 staffeng.com 上。这件事稍微麻烦一些，因为 StaffEng 历史上是一个 Gatsby 应用（不像这个博客）。（为什么用 Gatsby？因为当时 Calm 的 Web 前端在使用 Gatsby，我想借此积累一些经验。）

周末我花了些时间把它迁移到 Hugo，并应用了同样的优化。现在你可以在 lethain:staff-eng 仓库或 staffeng.com 上看到这些改动。

这是旧版本的截图。

这是更新后的版本截图。

总体来说，我觉得现在读起来稍微轻松一些，我也借此机会更新了各种链接。比如我移除了原来的 newsletter 链接，转而指向本博客的 newsletter，因为之前那个 mailing list 已经沉寂很久了。

说到“沉寂”，我还把这些更新应用到了 infraeng.dev，这是我那本可能写也可能不写的《基础设施工程》书籍的网站——它已经很久没有更新过了。这意味着我现在有四个基本结构一致的 Hugo 站点，分别承载不同的内容网站：本博客、staffeng.com、infraeng.dev，以及即将出版的那本书的网站。它们全部通过 GitHub Pages 自动构建和部署，对我来说一直是一个极其简单可靠的工作流。

在做这些事情的时候，有人问我为什么不自己写一个博客服务器来托管自己的博客。答案其实很简单。这些年来我为自己的博客写过三个博客服务器，前两个用 Python，最后一个用 Go。它们都运行得不错，但维护它们最终成了一个痛点，因为它们需要真正的构建流水线，还要处理可能存在安全问题的各种依赖库。即使在最好的情况下，它们运行的容器也会随着 Ubuntu 版本被弃用而定期面临停止支持。

从中我逐渐意识到，作为一个经常写作的人，你真正希望自己的内容能够在一个可以稳定运行几十年的地方存放。即使是很小的维护成本，长期积累下来也会让人难以承受。我见过一些很好的博客最终消失，就是因为不愿意去处理比如 WordPress 升级这样的问题。这些事情单个看都很小，但几十年累积起来就会非常可观。这也是我反对使用托管平台的原因：我知道 Substack 五年后应该还会存在，但我不确定二十年后它是否还在。而我知道自己那时仍然会继续写作，也希望自己以前写的东西依然能够被访问到。
