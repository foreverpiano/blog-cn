于是我开始了一段小小的探索之旅，来安装并正确运行 django-rcsfield。项目 wiki 上有一个快速入门指南，但对我来说还不够清晰，所以我把整个过程的笔记分享出来。

性能思考

我目前的感受是，这里的性能比理想情况稍微差一些。对 rcs 后端的提交是通过 post-save 信号触发的，因此当我们考虑下面这样的请求时：

# super sloppy code alert, trying to 
# focus on the issue at hand...
def update_obj(request):
    obj = Obj.objects.get(slug=request.POST'slug'])
    obj.text = request.POST['text']
    obj.save()
    return HttpResponse("Updated %s successfully." % obj.title)

我们不仅要把对象保存到数据库，post_save 钩子也会被触发，而且是在 HttpResponse 发送之前完成的。因为数据库仍然保存着字段的当前版本，所以实际上并不需要在响应返回给用户之前完成仓库的更新。（我承认某些应用场景可能不是这样，但我认为对绝大多数情况而言是成立的。）

这意味着保存一个带有 rcsfield 的对象要比保存不带该字段的对象明显更慢。这是否构成问题，很大程度上取决于你的用户界面和整体应用设计，但值得牢记。

对我来说，如果重新设计 UI 还是不能足够缓解这种迟钝感，我对如何改进当前方案以获得更快的响应有两个想法：

  1. 把保存到仓库的操作放到独立的线程中。线程很邪恶，blah blah blah，但这似乎是一个适合把 commit 操作扔到线程里以显著提升响应速度的场景。（这是那种“有点 hack 但可能很棒”的方案。）
  2. 把 commit 任务加入任务队列，由另一个服务来处理。（这是“我们是可扩展性工程师，哇哦”的方案。）

总之，django-rcsfield 是一个很不错的小项目，我强烈推荐你稍微玩一玩，看看自己有没有哪些项目能从中受益。
