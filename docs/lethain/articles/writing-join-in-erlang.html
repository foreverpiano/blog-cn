在 Erlang 中实现 Join

2008-05-04 · 阅读原文

今天早些时候，我发现自己需要在 Erlang 中实现字符串拼接功能。在 lists 模块中寻找 join 函数几分钟后，我意识到那里并没有现成的实现。这就引出了一个问题：应该如何实现 join？

实现 join 最简单的方式是使用 reduce/fold 操作。Erlang 在 lists:foldl 和 lists:foldr 中提供了这些功能，分别向左和向右折叠。我选择从左边开始折叠，因此用于折叠的函数长这样：

% Char is assumed to exist.
JoinFunction = fun(Element, Acc) -> lists:append([Acc, Char, Element]) end.

然后我们将其应用到一个列表上。

% List is assumed to exist.
InitialAcc = "",
Results = lists:foldl(JoinFunction, InitialAcc, List).

现在基本能用了，但还存在一个小问题：结果开头会多出一个连接符（例如用 ", " 连接 ["one", "two", "three"] 会得到 ", one, two, three"）。幸运的是，我们处理的是链表，所以去掉开头多余的部分是一个 O(c) 的操作（其中 c 是连接符列表的长度）。

再加上对空列表的保护，我们就得到了一个相当简洁的解决方案。

simple_join(_, []) ->
    "";
simple_join(Char, List) ->
    P = fun(Elem, AccIn) -> lists:append([AccIn, Char, Elem]) end,
    lists:nthtail(length(Char), lists:foldl(P, "", List)).

我对这个方案还算满意，但觉得值得再实现一个不使用 fold 的版本。

这个解决方案需要处理三种情况。

是第一个元素吗？如果是，则用 list[0] 作为累积结果递归，剩余待处理列表为 list[1:]。没有剩余元素了吗？如果是，则返回累积的结果。其他情况：对 list[1:] 进行递归调用，并将连接符和 list[0] 追加到累积结果中。

虽然按代码行数来衡量并不特别简洁，但我发现这个 Erlang 方案相当令人满意。

simple_join(Char, List) ->
    simple_join(Char, List, []).
simple_join(_, [], Acc) ->
    Acc;
simple_join(Char, [First|Rest], []) ->
    simple_join(Char, Rest, First);
simple_join(Char, [First|Rest], Acc) ->
    simple_join(Char, Rest, lists:append([Acc, Char, First])).

我最喜欢的部分是所有的逻辑都通过函数定义的模式匹配来处理，而不是使用显式的 case 或 if/else 结构。就可读性而言，我觉得值得与 Scheme 中一个大致等价的函数进行比较。

(define (simple-join char list)
  (define (sj char list acc)
    (cond ((null? acc) (sj char (cdr list) (car list)))
	  ((null? (cdr list)) acc)
	  (else (sj char (cdr list) (append acc char (car list))))))
  (sj char list (list)))

对比两者，我认为 Erlang 实现显得有些吃亏，因为大多数程序员（包括我自己）对 if-else 范式比对模式匹配更加熟悉。然而，我觉得 Erlang 的方案更简洁，也更容易理解。总的来说，在对 Erlang 及其概念有了一定了解之后，我现在更喜欢 Erlang 的解决方案。

它几乎做了完全相同的事情，但这么做的价值值得商榷。Erlang 中的字符串就是列表，而 Scheme 中的字符串则不是（在 Common Lisp 中字符串被实现为向量，我猜 Scheme 也是如此，但不确定）。就目前而言，Scheme 版本只是简单地连接列表，而不是字符串。↩
