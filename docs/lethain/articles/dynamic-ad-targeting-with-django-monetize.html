使用 django-monetize 实现动态广告定向

2008-08-29 · 阅读原文

这可能是我参与过的最令人兴奋的 Django 项目，我很高兴它已经开发到足够可用的阶段，可以和大家分享。我很荣幸地向大家介绍 django-monetize。

django-monetize 是一个可插拔的 Django 应用，旨在让智能地变现你的 Django 项目变得轻而易举。它的设计遵循两条指导原则：

变现的形式多种多样，通常混合搭配的方式会优于单一的变现方案（例如，巧妙地组合捐赠、Amazon Affiliates 和 AdSense，其效果会比仅使用 AdSense 更好）。在不同变现形式和组合之间切换并进行试验，是成功的关键。你可以通过有效地定向你的读者子群体，大幅提升变现效果。如果能够向来自搜索引擎的用户（或许 AdSense 表现更好）或 Reddit 的用户（或许……搞怪 T 恤会卖得更好？）展示不同的广告，根据他们使用的不同浏览器（等等，我在向 Internet Explorer 用户推销我的 OSX 应用？），以及他们正在浏览的不同类型内容（阅读深度教程的人比阅读你吐槽甘草软糖的人更有可能捐赠），你的变现就会更有效。

支持的变现形式

目前，django-monetize 内置支持 Amazon Affiliates 的 Custom Links、Amazon Affiliates 的 Omakase、Amazon Affiliates 的 Search Links、Amazon Honor System 捐赠、Dreamhost 推荐、Google Adsense 广告单元、Paypal 捐赠以及 SliceHost 推荐。

增加你自己的变现形式，或者对现有形式进行定制以更适合你的网站，是非常简单的（也受到鼓励）。创建你自己的自定义广告也很容易（比如你写的一本电子书，链接到你精心整理的热门博客文章，或者推广你的新创公司）。

monetize_slot 模板标签的有效参数

我们在上面的例子中以各种不同方式使用 monetize_slot，现在有必要澄清它可以接受的参数。

它可以不带任何参数调用，这种情况下会使用默认的变现选项。它可以带一个参数调用，该参数必须是广告位的名称。这种情况下它将使用该广告位对应的默认变现选项的定向值——如果存在这样的定向——否则会回退到使用默认选项。它可以带两个或更多参数调用。第一个参数必须是表示广告位名称的字符串。后续参数可以是：字符串（它们可以是存储在上下文变量中的字符串，或者是在模板中直接声明的绝对字符串，例如 {% monetize_slot "header" "django" %}）、字典（其值会使用 iteritems() 处理），或者可迭代对象（定义为非字典、非字符串且具有 __iter__ 方法的对象）。 如果遇到不属于上述类型的对象（例如，在处理你的标签 queryset 的内容时），它会通过调用 unicode(obj) 将对象转换为字符串。这意味着你可以通过其 __unicode__ 方法返回的字符串来定向特定对象。

配置

首先，django-monetize 对 None 和 False 做了重要区分。None 表示“使用默认变现方式”，而 False 表示“不使用任何变现方式”。虽然这看起来是一个任意且容易混淆的决定，但到目前为止它似乎是一个合理的解决方案。

广告定向的配置是在项目的 settings.py 文件中完成的。有一个至少在某些方面相似的 Django 项目 django-ads，它将配置存储在数据库中。虽然这允许构建一个更动态可修改的系统，但 django-ads 并没有像 django-monetize 这样深入解决广告定向和自定义的问题，而且我没有找到一个合理的方式将配置存储在数据库中（除了存储 Python 代码字符串然后再求值，这在我看来远不是一个可接受的方案）。
