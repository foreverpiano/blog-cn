一个用于 Google Analytics 的 Django Middleware（转载）

2007-06-14 · 阅读原文

这篇文章移植自原 Irrational Exuberance 博客，写于 2007 年中期：距今已近两年。

Django 的美妙之处在于它被设计为最大化灵活性。作为开发者，我们可以在多个位置接入 Django，而这些接入点允许我们访问 Django 的大部分内部组件。Django 开发者首先接触到的接入点是 urls.py 文件，我们在那里将 URL 映射到对应的应用。urls.py 是 Django 最基础的接入方式，但有时 Django 的第二个接入点——Middleware——能为我们带来简洁性上的切实提升。在本文中，我们会先看看如何使用 GoogleAnalyticsMiddleware 将 Google Analytics 的调用代码注入到页面中，然后再逐步讲解它是如何构建的。GoogleAnalyticsMiddleware 的源代码可在此获取（采用 Lesser GNU 协议）。<!--more-->

使用 Google Analytics Middleware

MIDDLEWARE_CLASSES = (
    'django.middleware.common.CommonMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.middleware.doc.XViewMiddleware',
    'myproject.analytics.GoogleAnalyticsMiddleware',
)

如果你把它放在 django.middleware 目录下，那么这一行应该写成

'django.middleware.analytics.GoogleAnalyticsMiddleware',

。接下来你需要在 settings.py 文件中添加全局变量 ANALYTICS_ID，其值应该是你的 Google Analytics ID。

ANALYTICS_ID = 'abcd1234'

通常你不会想跟踪自己的访问数据，因此还提供了一个可选的全局变量 ANALYTICS_IGNORE_ADMIN。如果你将其设为 True，那么已登录管理员访问页面时将不会注入 Google Analytics 的 JavaScript 代码（这样既不会干扰你的统计数据，也不用加载 JavaScript，皆大欢喜）。如果你想使用这个功能，应该在 settings.py 中加入以下内容：

ANALYTICS_IGNORE_ADMIN = True

如果你不想对管理员禁用跟踪，那么无需做任何额外操作，因为默认情况下中间件会注入到所有页面中。配置工作到此结束。如果你想在不向 Google Analytics 发送真实数据的情况下进行测试，可以取消 init 方法中对应那一行的注释。

开发这个 Middleware

process_request(self, request)
process_view(self, request, view_func, view_args, view_kwargs)
process_response(self, request, response)

process_request 用于在 Django 确定要渲染的视图之前拦截请求（可用于拒绝未授权用户）。process_view 用于在视图渲染前进行拦截并显示其他内容（比如错误信息，或者在用户下次登录时发送一次性消息）。process_response 则用于修改即将显示的内容。对于注入 Analytics 代码来说，process_response 正是我们需要的。

设计我们的 Middleware

  • Get the values of ANALYTICS_ID and ANALYTICS_IGNORE_ADMIN from settings.py.
  • Unless there is no ANALYTICS_ID, prebuild the html representing our javascript call to Analytics.
  • If there is no value for ANALYTICS_ID, set process_response to return the response without any modification.
  • Elif ANALYTICS_IGNORE_ADMIN is true, set process_response to inject the Analytics code unless an admin is logged in.
  • Else process_response should always inject the Analytics code.
from django.conf import settings
id = settings.ANALYTICS_ID
ignore = settings.ANALYTICS_IGNORE_ADMIN

非常简单，这要归功于 Django 团队提供的元编程魔法。接下来我们需要一个简单的函数，根据 ID 来构建 HTML 字符串，代码如下：

@staticmethod
def form_analytics_string(id):
    return """&lt;script src="http://www.google-analytics.com/urchin.js" type="text/javascript"&gt;&lt;/script&gt;&lt;script type="text/javascript"&gt;  _uacct = "%s";  urchinTracker();&lt;/script&gt;""" % ( str(id) )

这只是简单地将值插入到 Python 字符串中。它使用了 staticmethod 装饰器，因为该方法不需要访问实例的任何信息（使用 staticmethod 装饰器意味着它不会自动把 self 作为第一个参数传入）。

短暂的题外话：一些辅助方法

def return_unaltered(self, request, response):
    return response

将 Analytics 代码插入到响应中的逻辑稍微复杂一些，但依然合理。

def insert_analytics(self, request, response):
    content = response.content
    index = content.upper().find('&lt;/BODY&gt;')
    if index == -1: return response
    response.content = content[:index] +
        self.html + 
       context[index;]
    return response

我们从 response 中获取内容，扫描其中是否含有 </body> 标签，如果有，就立即在它之前插入 Analytics 代码（这样 Analytics 脚本就不会拖慢页面的加载时间）。不算太难。我们需要构建的最后一个辅助函数是用来将“是否为管理员用户”的检查通过柯里化（currying）的方式绑定到 insert_analytics 方法上（只有当 ANALYTICS_IGNORE_ADMIN 变量为 True 时才会进行这种柯里化，而我们会在 init 方法中完成这个逻辑判断）。（如果你不知道柯里化是什么，它是函数式编程中的一个概念，可以在这里看到解释。）这段代码乍看有些令人困惑，但它让我们无论是否需要忽略管理员用户，都能复用 insert_analytics 中的代码。

@staticmethod
def ignore_admin(func):
    def ignore_if_admin(request, response):
        if request.user.is_authenticated() and request.user.is_staff:
            return response
        else:
            return func(request, response)    return: ignore_if_admin

首先要注意 ignore_admin 是一个静态函数（它只是对函数进行操作，并不和类的某个特定实例绑定）。ignore_admin 方法的实际作用是返回内部函数 ignore_if_admin 针对参数 'func' 进行特化后的副本。因此返回的函数会“记住” func 的值，即使它从未被显式作为参数传递（这是函数式编程中常见的用法）。

回到构造方法

def __init__(self):
    try:
        id = settings.ANALYTICS_ID
        self.html = self.form_analytics_string(id)
        self.process_response = self.insert_analytics
        try:
            ignore = settings.ANALYTICS_IGNORE_ADMIN
            if ignore is True:
                self.process_response = self.ignore_admin(
                    self.process_response)
        except AttributeError:
            pass    except AttributeError:
        self.process_response = self.return_unaltered

在 init 方法中，我们首先尝试从 settings 文件中获取 ID，如果失败，就将 process_response 设置为 return_unaltered 方法。否则我们返回 insert_analytics 方法，并在需要时通过 ignore_admin 方法进行柯里化。由于有了这些辅助方法，init 的代码相当清晰易懂。非常不错。
