Django 的 Google Analytics 中间件（转载）

2007-06-14 · 阅读原文

本文移植自原 Irrational Exuberance 博客，撰写于 2007 年中期，距今已近两年。

Django 的优雅之处在于它被设计为极具灵活性。作为开发者，我们可以在多个位置接入 Django，而这些接入点几乎可以触达框架的所有核心组件。Django 开发者最先接触到的通常是 urls.py 文件，用于将 URL 映射到对应的应用。urls.py 是 Django 最基础的钩子，但有时它的第二个钩子——Middleware（中间件）——能带来更简洁的实现。本文将首先介绍如何使用 GoogleAnalyticsMiddleware 在页面中注入 Google Analytics 调用代码，随后我们将逐步剖析它的构建过程。该中间件的源代码可在此获取（采用 Lesser GNU 许可协议）。<!--more-->

使用 Google Analytics 中间件

MIDDLEWARE_CLASSES = (
    'django.middleware.common.CommonMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.middleware.doc.XViewMiddleware',
    'myproject.analytics.GoogleAnalyticsMiddleware',
)

如果你将其放在 django.middleware 目录下，那么应该这样写：

'django.middleware.analytics.GoogleAnalyticsMiddleware',

接下来需要在 settings.py 中添加全局变量 ANALYTICS_ID，其值应为你的 Google Analytics ID。

ANALYTICS_ID = 'abcd1234'

通常我们不希望跟踪自己的访问数据，为此可以设置第二个可选的全局变量 ANALYTICS_IGNORE_ADMIN。如果将其设为 True，那么已登录管理员访问页面时将不会注入 Google Analytics 的 JavaScript 代码（这样既不会干扰统计数据，也无需加载脚本，皆大欢喜）。如果要启用此功能，请在 settings.py 中加入以下内容：

ANALYTICS_IGNORE_ADMIN = True

如果你不想对管理员禁用跟踪，那么无需额外操作，因为默认情况下中间件会注入到所有页面中。配置工作到此结束。如果你想在不向 Google Analytics 发送真实数据的情况下进行测试，可以取消 init 方法中某行的注释。

开发这个中间件

process_request(self, request)
process_view(self, request, view_func, view_args, view_kwargs)
process_response(self, request, response)

process_request 用于在 Django 确定要渲染的视图之前拦截请求（可用于拒绝未授权用户）。process_view 用于在视图渲染前进行拦截并返回其他内容（比如错误信息，或者在用户下次登录时发送一次性提示）。process_response 则用于修改即将返回给用户的内容。对于注入 Analytics 代码来说，process_response 正是我们需要的。

设计我们的中间件

从 settings.py 中获取 ANALYTICS_ID 和 ANALYTICS_IGNORE_ADMIN 的值。 除非 ANALYTICS_ID 为空，否则预先生成调用 Analytics 的 JavaScript 对应的 HTML 代码。 如果没有设置 ANALYTICS_ID，则让 process_response 直接返回不做修改的响应。 如果 ANALYTICS_IGNORE_ADMIN 为 True，则让 process_response 在非管理员登录时注入 Analytics 代码。 否则 process_response 始终注入 Analytics 代码。
from django.conf import settings
id = settings.ANALYTICS_ID
ignore = settings.ANALYTICS_IGNORE_ADMIN

非常简洁，这要归功于 Django 团队提供的元编程特性。接下来我们需要一个简单的函数，根据 ID 生成相应的 HTML 字符串，代码如下：

@staticmethod
def form_analytics_string(id):
    return """&lt;script src="http://www.google-analytics.com/urchin.js" type="text/javascript"&gt;&lt;/script&gt;&lt;script type="text/javascript"&gt;  _uacct = "%s";  urchinTracker();&lt;/script&gt;""" % ( str(id) )

这只是将值插入 Python 字符串的简单操作。它使用了 staticmethod 装饰器，因为该方法不需要访问实例的任何状态（使用 staticmethod 装饰器后，它不会自动接收 self 作为第一个参数）。

稍作迂回：一些辅助方法

def return_unaltered(self, request, response):
    return response

将 Analytics 代码插入响应体的过程稍微复杂一些，但依然清晰易懂。

def insert_analytics(self, request, response):
    content = response.content
    index = content.upper().find('&lt;/BODY&gt;')
    if index == -1: return response
    response.content = content[:index] +
        self.html + 
       context[index;]
    return response

我们先获取响应的内容，扫描其中是否包含 </body> 标签，如果找到，就将 Analytics 代码插入到它之前（这样不会拖慢页面加载速度）。不算太难。我们还需要实现的最后一个辅助函数，是将“是否为管理员”的检查通过柯里化（currying）附加到 insert_analytics 方法上（仅当 ANALYTICS_IGNORE_ADMIN 为 True 时才会进行柯里化，这个逻辑将在 init 方法中处理）。 （如果你不了解柯里化是什么，它是函数式编程中的概念，可以在这里看到解释。）这段代码略显费解，但它让我们能够复用 insert_analytics 的逻辑，无论是否需要忽略管理员用户。

@staticmethod
def ignore_admin(func):
    def ignore_if_admin(request, response):
        if request.user.is_authenticated() and request.user.is_staff:
            return response
        else:
            return func(request, response)    return: ignore_if_admin

首先要注意的是 ignore_admin 是一个静态函数（它只对函数进行操作，并不依赖类的特定实例）。ignore_admin 方法的实际作用是返回内部函数 ignore_if_admin 针对参数 'func' 进行特化后的副本。因此返回的函数会“记住” func 的值，即使它从未被显式作为参数传递（这是函数式编程中常见的技巧）。

回到构造器

def __init__(self):
    try:
        id = settings.ANALYTICS_ID
        self.html = self.form_analytics_string(id)
        self.process_response = self.insert_analytics
        try:
            ignore = settings.ANALYTICS_IGNORE_ADMIN
            if ignore is True:
                self.process_response = self.ignore_admin(
                    self.process_response)
        except AttributeError:
            pass    except AttributeError:
        self.process_response = self.return_unaltered

在 __init__ 方法中，我们首先尝试从 settings 文件获取 ID，如果失败，则将 process_response 设置为 return_unaltered 方法。否则根据情况返回 insert_analytics 方法，如果需要忽略管理员，则会通过 ignore_admin 进行柯里化。多亏了这些辅助方法，init 逻辑清晰易懂，非常不错。
