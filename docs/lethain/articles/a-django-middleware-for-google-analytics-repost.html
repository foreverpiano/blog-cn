Django 的魅力之一在于它被设计为极具灵活性。作为开发者，我们可以在多个位置接入 Django，而这些接入点允许我们访问 Django 的大多数内部机制。Django 开发者首先接触到的接入点是 urls.py 文件，我们在那里将 URL 映射到对应的应用。urls.py 是 Django 最基础的钩子，但有时 Django 的第二个钩子——Middleware（中间件）——能为我们带来真正的简洁性提升。在本文中，我们将首先介绍如何使用 GoogleAnalyticsMiddleware 将 Google Analytics 的调用代码注入到页面中，然后一步步讲解它是如何构建的。GoogleAnalyticsMiddleware 的源代码可在此处获取（采用 Lesser GNU 协议）。<!--more-->

开发这个中间件

process_request 用于在 Django 确定要渲染的视图之前拦截请求（可用于拒绝未授权用户）。process_view 用于在视图渲染前进行拦截并显示其他内容（比如错误信息，或者在用户下次登录时发送一次性消息）。process_response 则用于修改即将显示的内容。对于注入 Analytics 代码来说，process_response 正是我们需要的。

稍作延伸：一些辅助方法

将 Analytics 代码插入响应中的逻辑稍微复杂一些，但依然合理。

我们从 response 中获取页面内容，扫描其中是否包含 </body> 标签，如果有，则立即在其之前插入 Analytics 代码（这样 Analytics 脚本就不会拖慢页面加载速度）。不算太难。我们需要构建的最后一个辅助函数是用来将“是否为管理员用户”的检查“柯里化”（curry）到 insert_analytics 方法上的（仅当 ANALYTICS_IGNORE_ADMIN 为 True 时才会将两者柯里化在一起，但我们会在 __init__ 方法中完成这个逻辑）。（如果你想了解柯里化是什么，它是函数式编程中的一个概念，可以在这里看到解释。）这段代码稍显费解，但它让我们能够复用 insert_analytics 中的逻辑，无论是否需要忽略管理员用户。

首先要注意的是，ignore_admin 是一个静态函数（它只是对函数进行操作，并不与类的某个具体实例绑定）。ignore_admin 方法的作用是返回内部函数 ignore_if_admin 针对参数 'func' 特化后的一个副本。因此返回的函数会记住 'func' 的值，即使它从未被显式作为参数传递（这是函数式编程中常见的惯用手法）。

回到构造函数

在 __init__ 方法中，我们首先尝试从 settings 文件中获取 ID，如果失败，则将 process_response 设置为 return_unaltered 方法。否则我们返回 insert_analytics 方法，如果需要忽略管理员，则将其放在 ignore_admin 方法中进行柯里化。多亏了这些辅助方法，__init__ 的逻辑清晰易懂。非常不错。
