协作的基础（与 LLM 共同使用一本书）

2025-03-15 · 阅读原文

LLM 在很多方面都不特别擅长，其中之一就是生成优秀的工程策略。如果你让 LLM 为你的公司生成工程策略，我非常确信你会对它输出的结果感到失望。

然而，我极度确信，LLM 已经是帮助你制定有效工程策略的绝佳伙伴。只要使用得当，LLM 可以生成和分析系统模型、在写作的每个步骤中提供帮助，并指出你的策略中需要加强的领域。本书将引导你掌握实现这些目标的各种技巧，从本章开始，我们将介绍如何配置一个环境，让你能与《Crafting Engineering Strategy》和你选择的 LLM 进行协作。

本章将涵盖以下内容：

有效提示 LLM 的实践，包括元提示（meta-prompting）和上下文学习（in-context learning）；使用 LLM 处理大型语料（如本书），从 Claude Projects 到 llm 库；通过 Model Context Protocol (MCP) 服务器为 LLM 提供工具。这些工具通过赋予网页搜索、文档检索等新能力，显著扩展了 LLM 可以完成的工作范围。

掌握这些基础之后，我们就可以进入后续章节，将《Crafting Engineering Strategy》作为副驾驶来共同制定策略。

这是《The AI Companion to Crafting Engineering Strategy》中的一章草稿，本书讨论了如何在 LLM 中使用《Crafting Engineering Strategy》来起草、完善和改进工程策略。

有效提示 LLM

如果你想全面了解如何与 LLM 打交道，我推荐阅读 Chip Huyen 的《AI Engineering: Building Applications with Foundation Models》。不过，大多数人都是通过直接与 LLM 聊天来开始接触，并由此建立直觉，我发现这种方式相当有效。假设你已经花了一些时间使用 LLM，我将重点强调三种特别有价值的技术：将 LLM 视为新入职的实习生、通过元提示改进提示词，以及使用上下文学习（例如《Crafting Engineering Strategy》中的示例策略）来提升输出质量。

将 LLM 视为实习生（LLM-as-Intern）

大多数人最熟悉的提示方式是使用 Google 这类搜索引擎。搜索引擎的索引非常强大，通常只需输入几个与主题相关的生僻词，就能得到你想要的结果。有经验的搜索者常常知道自己想从哪个资源获取内容，例如 “reddit best restaurants sf”。

然而，LLM 通常不擅长处理这类简短的提示。例如，我们来看两个提示，目标是创建一个 Python 命令行工具，在 Markdown 图片下方添加描述。

第一个提示采用了“LLM 作为搜索引擎”的心智模型，给出了一个非常笼统的提示，仿佛你是在从已有的数据源中检索答案：

I need a Python function to add images descriptions to Markdown.
Description should be in a paragraph tag beneath the image.

使用 ChatGPT 4o 时，它生成了一个 Python 脚本，但并不是真正想要的那个脚本。这一点仅从函数定义就能明显看出：

def add_image_descriptions(markdown_text, description_func=None):
    ...

我想要的是一个利用 Markdown 图片规范中已有图片定义的脚本，但因为我提出了一个笼统的查询——就像在检索一个现成答案——结果完全拿到了错误的东西。

现在让我们试试第二种提示，它采取了更加详细的表述，我将其称为“LLM 作为实习生”的心智模型。在这里，你提供了非常详细的指令，就像在为一个新入职的实习生写第一份工作任务单一样：

Write a Python3 function with the definition:

    def add_image_descriptions(text: str) -> str:

This function should use Python's re library to extract the
description text for Markdown images, and add it as floating
text beneath the image, for example it should replace this:

    ![Initial sketch of API](/static/api-simple.png)

With this:

    ![Initial sketch of API](/static/api-simple.png)
    <p>Initial sketch of API</p>

It should do that every every Markdown image in the text.
It should _not_ do that for any Markdown links that start
with [, only images which start with ![.

第二个提示写起来花费的时间更长，但它能稳定地生成我真正想要的结果。正如经验不足会导致实习生在接受新任务时做出错误假设一样，LLM 也会如此。两种情况下的解决方案都是要更加明确。即使是相当复杂的任务，我反复得到的经验是：只要我在改进提示上投入更多精力，LLM 就能完成它。

元提示（Meta-prompting）

虽然你应该自己努力改进提示，但 LLM 也可以通过元提示的方式来帮忙。其核心思想不是让 LLM 直接按照提示执行，而是让它帮助你改进提示本身。

例如，OpenAI 的元提示指南中建议使用以下提示：

Improve the following prompt to generate a more detailed summary.
Adhere to prompt engineering best practices.
Make sure the structure is clear and intuitive and
contains the type of news, tags and sentiment analysis.

{simple_prompt}

Only return the prompt.

这是基于分析新闻故事的例子。最高效的元提示会根据你正在处理的项目类型略有不同。对于与《Crafting Engineering Strategy》一起使用的工程策略提示，以下是我发现非常有效的元提示：

Improve the following prompt to generate a better engineering strategy.
Adhere to prompt engineering best practices.
Make sure the structure is clear and intuitive.
Use strategies from _Crafting Engineering Strategy_
to provide multiple examples of the sort of desired output.

{simple_prompt}

Only return the prompt.

有了元提示后，只需把它输入到你选择的 LLM 中，将 {simple_prompt} 替换为你想要改进的初始提示即可。例如，下面是在 Claude.ai 项目（本章后续会介绍如何配置）中使用它，借助《Crafting Engineering Strategy》的内容来改进一个用于诊断策略的提示。

这个元提示把一个简单的初始提示变成了一个详细得多的提示。手动写出所有这些步骤会花很长时间，而使用合适的元提示几乎不费任何工夫。

我在这里开发的元提示虽然有所改进，但仍然比较基础。从这个起点出发，你应该尝试自己的变体，找到最适合你的版本。

上下文学习（In-Context Learning）

本节要讨论的最后一个技巧是上下文学习（ICL），其本质是提供多个你希望 LLM 生成的输出示例。这些示例能帮助引导 LLM 准确理解你想要的回答类型。包含的示例越多，提示通常表现得越好。在我将 LLM 部署到生产系统的过程中，我发现 ICL 能够解决大部分仅靠元提示无法解决的问题。

你可以利用本书既来生成 ICL 示例，又可以将这些示例放入提示中，以更好地支持生成你想要的输出。当书的内容已经在你的上下文窗口中时，你用来生成示例的提示可以非常直接，例如：

Provide 10 examples of diagnoses from Crafting Engineering Strategy's
example strategies.
Format them as a bulleted list of examples.

这会生成一系列合适的诊断示例。

获得这些示例后，将它们加入到下一个提示中，以提升生成的输出质量。

请注意，这里展示的提示为了可读性做了简化。实际使用中，你可能还想对其应用元提示来进行改进。

在 LLM 中使用一本书

为了跟随本书的示例，你需要搭建一个能针对本书进行提示的环境。虽然可行的方案无数，但这里我们重点介绍三种：使用 Anthropic 的 Claude.ai Projects、使用 OpenAI 的 ChatGPT Projects，以及使用 llm 库配合你选择的模型（前提是模型的输入窗口至少能接受约 18 万 token，例如大多数现代 Gemini、Anthropic 模型、gpt-4.1-mini 等）。

如果你对使用哪种方式没有特别偏好，我推荐使用 Claude.ai Projects，因为它与本地 Model Context Protocol (MCP) 服务器的配合最好（下一节会讨论），但除去 MCP 支持这一点，其他所有选项都相当不错。同样，可以合理预期其他环境很快也会广泛支持 MCP。

Claude.ai Projects

2024 年 6 月，Anthropic 的 Claude.ai 引入了 Projects 功能，允许你将文件关联到一个项目中。这些文件会被包含在项目的聊天上下文窗口中，其 200k token 的容量足以容纳本书约 170k 的 token 量。

首先创建一个 Claude.ai 账号，然后进入 Projects 页面。进入后，点击 “New Project” 按钮创建一个新项目。

选择 New Project 后，你会看到一个简短的表单来描述项目。填入一个容易记住的名字，例如 “Crafting Eng Strat”，并可选择填写简短描述。

创建项目后，你会被重定向到新项目页面。然后点击加号按钮添加一个新文件到项目中。

选择 “Upload from device”，选中你按照序言指示已经下载好的 ces_llm.md 文件。上传后，你会看到项目容量大约被占用了 80%。

此时，你在这个项目内运行的任何提示，都会自动包含整本书的内容以及你添加的提示。这让你可以直接查询书中的内容。

至此，你已经准备好使用这个项目与本书进行交互，后续章节将进一步展开说明。

最后值得注意的是，这些 Projects 并没有使用 Retrieval Augmented Generation（RAG）技术——RAG 通常会通过搜索算法从语料中选择一个子集放入提示。而这里是将整本书完整包含进去。因此，书中包含的任何内容都应该是可访问的，即使是那些在语义上可能与你的初始提示不直接相关的部分也是如此。

ChatGPT Projects

与 Claude.ai 类似，ChatGPT 也推出了 Projects 功能，允许与一个资源语料进行交互。其工作方式与 Claude.ai 的 Projects 非常相似。

首先进入 ChatGPT 并登录。请注意，在本文撰写时，ChatGPT Projects 需要付费计划才能使用，免费计划不可用。登录后，点击 “New project” 按钮。

点击 “New project” 按钮后，你会看到一个表单，用于为项目提供名称。虽然你可以随意命名，但本例中我使用了 “Crafting Eng Strategy”。

点击 “Create project” 按钮后，你会被自动重定向到新项目的页面。在该页面点击 “Add files” 按钮来上传本书。

点击 Add files 后，你会进入 Project files 页面，其中列出了所有已上传的文件。在这里，你可以使用 Add files 按钮，或者直接把 ces_llm.md 文件拖入项目中。（提醒：下载 ces_llm.md 的方法在 《 Crafting Engineering Strategy 》AI 伴侣版 前言 中有说明。）

上传文件后，你会收到一个警告，提示大文件可能会影响回复。这确实是一个现实问题。首先，OpenAI 模型的 token 窗口限制在其文档中有说明。其次，OpenAI 对某些模型有速率限制，这可能会限制哪些模型适合这么大的项目。你可以放心使用 GPT-4.1 mini 或 GPT-4o mini。许多其他模型也能工作，但部分模型可能不行。

此时，你已经可以针对包含整本书的项目进行查询了。（注意这个提示是使用 ChatGPT-4.1 mini 执行的。）

至此，ChatGPT 项目已经配置完成，你可以开始对其进行查询。

llm 库

现在我们已经尝试了两种以用户界面为主的项目方式，第三种配置方式是使用命令行的 llm 库。虽然这里的例子专门使用了 OpenAI 的 API，但它们同样适用于 Anthropic、Gemini 或自托管模型。你只需在命令行中指定 slightly 不同的模型参数和 API key 即可。

首先，按照 《 Crafting Engineering Strategy 》AI 伴侣版 前言 中的说明下载 LLM 优化版本的《Crafting Engineering Strategy》。以下指令假设你已经将其放入当前目录下，文件名为 ces_llm.md。

接下来按照 llm 库的安装说明操作。我会使用 uv 来管理安装，但你也可以使用 pip 或其他 Python 包管理工具。请确保设置好你的 OpenAI API key：

uvx llm keys set openai

然后运行一个简单的提示来验证配置是否成功：

uvx llm -m gpt-4.1-mini \
'what are the steps to write an engineering strategy?'

如果运行正常，现在你也可以使用这本书了：

cat ./ces_llm.md |  \
uvx llm -m gpt-4.1-mini \
'what are the steps to write an engineering strategy?'

这会在你的提示前面包含整本书的内容，并会产生与之前不包含书的内容时完全不同的回答。

通过 MCP 使用工具

在元提示和上下文学习都不足以让提示有效工作的情况下，最后一项技术是为你的 LLM 提供专门打造的工具。这些工具让 LLM 能够做它最擅长的事情——处理文本表示——而将其他复杂性（尤其是需要复杂数学计算或图像渲染的任务）推给工具本身。

本书配套内容中有两章专门深入探讨 使用 LLM 生成系统模型 和 使用 LLM 生成 Wardley Map。这两章都依赖使用 Model Context Protocol (MCP) 服务器来访问额外工具。虽然所有主流 LLM 提供商都计划在未来支持 MCP 服务器，但目前只有 Claude Desktop 能比较直接地支持让你的项目与自定义 MCP 服务器进行交互。

modelcontextprotocol.io/quickstart/user 上的说明是设置本地 Claude Desktop 使用自定义工具的最佳指南。你也可以在 lethain/systems 仓库中看到类似的说明，该仓库被用于本书中关于生成系统模型的章节。

如果你完全不想运行 Claude Desktop，但又想试验 MCP 服务器，另一个可以考虑的选项是 OpenAI Agents SDK。这需要编写一些自定义代码，但这正是 LLM 擅长编写的代码类型——只要你在提示中包含相关文档即可。

总结

在本章中，我们介绍了三种基础的提示技术来让你的提示更加有效：LLM-as-Intern、元提示和上下文学习。我们还介绍了三种不同的可行方案来与大上下文窗口进行交互，包括针对 LLM 优化的《Crafting Engineering Strategy》格式。

有了配置好的环境，你现在已经可以开始与你的 LLM 副驾驶一起改进策略了。
