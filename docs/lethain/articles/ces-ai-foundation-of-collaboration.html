与 LLM 协作的基础（以一本书为例）

2025-03-15 · 阅读原文

LLM 在很多方面并不特别擅长，生成优秀的工程策略就是其中之一。如果你让 LLM 为公司生成工程策略，我非常确信你会对它输出的结果感到失望。

然而，我非常确信 LLM 已经是帮助你制定有效工程策略的绝佳伙伴。只要使用得当，LLM 可以生成和分析系统模型，在写作的每个步骤中提供帮助，并指出你的策略中需要强化的部分。这位伙伴将引导你掌握完成这些工作的各种技巧，从本章开始，首先介绍如何配置环境，以便与《Crafting Engineering Strategy》和你选择的 LLM 进行协作。

本章将介绍以下内容：

有效提示 LLM 的实践方法，包括元提示（meta-prompting）和上下文学习（in-context learning）；使用 LLM 处理大型语料（如本书），从 Claude Projects 到 llm 库；通过模型上下文协议（Model Context Protocol，简称 MCP）服务器为 LLM 提供工具。这些工具通过新增网页搜索或文档检索等能力，极大地扩展了 LLM 的可完成任务范围。

掌握这些基础之后，我们就可以进入后续章节，将《Crafting Engineering Strategy》作为副驾驶来共同制定策略。

这是《The AI Companion to Crafting Engineering Strategy》中的一章草稿，本书讨论如何在 LLM 中使用《Crafting Engineering Strategy》来起草、完善和改进工程策略。

有效提示 LLM

如果你想全面了解如何与 LLM 打交道，我推荐阅读 Chip Huyen 的《AI Engineering: Building Applications with Foundation Models》。不过，大多数人都是通过直接与 LLM 聊天来入门，并在此过程中建立直觉，我发现这种方式相当有效。假设你已经花了一些时间使用 LLM，我将重点强调三种特别有价值的技术：把 LLM 当作新入职的实习生、通过元提示改进提示词，以及使用上下文学习（例如《Crafting Engineering Strategy》中的示例策略）来提升输出质量。

把 LLM 当作实习生（LLM-as-Intern）

大多数人在提示 LLM 时最接近的参考经验是使用 Google 这类搜索引擎。搜索引擎的索引能力非常强大，通常只要输入几个与主题相关的生僻词，就能得到你想要的结果。有经验的搜索者往往知道自己想从哪个资源获取内容，例如 “reddit best restaurants sf”。

然而，LLM 通常不擅长处理这种简短的提示。例如，我们可以对比两个提示，来创建一个能在 Markdown 图片下方添加描述的 Python 命令行工具。

第一个提示采用了“LLM 作为搜索引擎”的心智模型，给出了一个非常笼统的提示，仿佛你是在从某个已有的数据源中检索答案：

I need a Python function to add images descriptions to Markdown.
Description should be in a paragraph tag beneath the image.

使用 ChatGPT 4o 时，它确实生成了一个 Python 脚本，但并不是我们真正想要的那个脚本。这一点仅从函数定义就能明显看出来：

def add_image_descriptions(markdown_text, description_func=None):
    ...

我想要的是一个能直接使用 Markdown 图片语法中已有图片定义的脚本，但因为我给出了一个笼统的查询——就像在检索已有的答案——结果完全跑偏了。

现在我们来试试第二种提示，这种提示要详细得多，我称之为“LLM 作为实习生”的心智模型。在这里，你提供了非常详细的指令，就像在为新入职的实习生写第一份工作任务单一样：

Write a Python3 function with the definition:

    def add_image_descriptions(text: str) -> str:

This function should use Python's re library to extract the
description text for Markdown images, and add it as floating
text beneath the image, for example it should replace this:

    ![Initial sketch of API](/static/api-simple.png)

With this:

    ![Initial sketch of API](/static/api-simple.png)
    <p>Initial sketch of API</p>

It should do that every every Markdown image in the text.
It should _not_ do that for any Markdown links that start
with [, only images which start with ![.

第二个提示写起来花的时间要长得多，但它始终能生成我真正想要的结果。正如经验不足的实习生在接受新任务时容易做出错误假设一样，LLM 也会如此。两种情况下的解决办法都是要更加明确。即使面对相当复杂的任务，我的反复经验是：只要我肯投入精力改进提示，LLM 就能完成它。

元提示（Meta-prompting）

虽然你应该自己努力改进提示，但 LLM 也可以通过元提示的方式来帮忙。其核心思想是让 LLM 去改进你的提示，而不是直接按照提示去执行。

例如，OpenAI 的元提示指南中建议使用这样的提示：

Improve the following prompt to generate a more detailed summary.
Adhere to prompt engineering best practices.
Make sure the structure is clear and intuitive and
contains the type of news, tags and sentiment analysis.

{simple_prompt}

Only return the prompt.

该示例基于分析新闻报道。针对不同类型的项目，最有效的元提示也会有所不同。对于使用《Crafting Engineering Strategy》来制定工程策略的场景，我发现下面这个元提示非常有效：

Improve the following prompt to generate a better engineering strategy.
Adhere to prompt engineering best practices.
Make sure the structure is clear and intuitive.
Use strategies from _Crafting Engineering Strategy_
to provide multiple examples of the sort of desired output.

{simple_prompt}

Only return the prompt.

有了元提示之后，只需把它输入到你选择的 LLM 中，并将 {simple_prompt} 替换为你想要改进的初始提示即可。例如，下面是在 Claude.ai 项目中使用它（本章后续会介绍如何配置）的例子，利用《Crafting Engineering Strategy》的内容来改进一个用于诊断策略的提示。

这个元提示将一个简单的初始提示扩展成了一个详细得多的提示。手动写出所有这些步骤会花费不少时间，但有了合适的元提示后，几乎瞬间就能完成。

我在这里开发的元提示虽然有所改进，但仍然相当基础。从这个起点出发，你应该不断实验，找到最适合自己的变体。

上下文学习（In-Context Learning）

本节要讨论的最后一个技巧是上下文学习（In-Context Learning，简称 ICL）。其本质是向 LLM 提供多个你希望它生成的输出示例。这些示例能帮助 LLM 更好地理解你想要的回应类型。提供的示例越多，提示的表现通常越好。在我将 LLM 部署到生产系统的迭代过程中，我发现 ICL 能解决大部分仅靠元提示无法解决的问题。

你可以利用本书既来生成 ICL 示例，又可以将这些示例加入提示中，以更好地获得你想要的输出。当本书处于上下文窗口中时，你生成示例的提示可以非常直接，例如：

Provide 10 examples of diagnoses from Crafting Engineering Strategy's
example strategies.
Format them as a bulleted list of examples.

这将会生成一系列合适的诊断示例。

获得这些示例后，将它们放入下一个提示中，就能显著提升生成的输出质量。

请注意，这里展示的提示为了可读性被简化了。实际使用中，你可能还想对其也应用元提示进行改进。

在 LLM 中使用一本书

为了跟上本书的示例，你需要搭建一个能针对本书进行提示的环境。虽然可选方案几乎是无限的，但这里我们重点介绍三种配置方式：使用 Anthropic 的 Claude.ai Projects、使用 OpenAI 的 ChatGPT Projects，以及使用 llm 库搭配你选择的模型（需支持至少约 18 万 token 的输入窗口，例如大多数现代 Gemini 或 Anthropic 模型、gpt-4.1-mini 等）。

如果你对使用哪种方式无所谓，我推荐使用 Claude.ai Projects，因为它与本地 Model Context Protocol (MCP) 服务器的配合最好（下一节会讨论）。但如果不考虑 MCP 支持，其他所有选项也都很合理。同样，可以合理预期其他环境很快也会广泛支持 MCP。

Claude.ai Projects

2024 年 6 月，Anthropic 的 Claude.ai 推出了 Projects 功能，允许你将文件与项目关联。这些文件会被纳入项目聊天的上下文窗口，其 200k token 的容量足以容纳本书约 170k token 的内容。

首先创建一个 Claude.ai 账号，然后进入 Projects 页面。点击“New Project”按钮新建一个项目。

选择 New Project 后，你会看到一个简短的表单来描述项目。请输入一个容易记住的名字，例如“Crafting Eng Strat”，并可选择填写简短描述。

创建项目后，你会被重定向到新项目页面。然后点击加号按钮向项目中添加新文件。

选择“Upload from device”，然后选中你已按照前言指示下载的 ces_llm.md 文件。上传完成后，你会看到项目容量大约被使用了 80%。

此时，在该项目内运行的任何提示，都会自动包含整本书的内容以及你额外输入的提示。这使你可以直接查询书中的内容。

至此，你已经可以利用这个项目与书进行交互，后续章节将进一步展开说明。

最后值得注意的是，这些 Projects 并没有使用 Retrieval Augmented Generation（RAG）技术——RAG 通常会通过搜索算法从语料中挑选部分内容放入提示。而 Projects 是把整本书全部放入上下文。只要书中有的内容，都应该能被访问到，即使某些部分在语义上与你的初始提示可能并不直接相关。

ChatGPT Projects

与 Claude.ai 类似，ChatGPT 也推出了 Projects 功能，用于与一组资源语料进行交互。其工作方式与 Claude.ai 的 Projects 非常相似。

打开 ChatGPT 并登录。请注意，在本文撰写时，ChatGPT Projects 仅对付费用户开放，免费计划无法使用。登录后，点击“New project”按钮。

点击“New project”按钮后，你会看到一个表单，要求为项目命名。虽然你可以随意命名，但本例中我使用了“Crafting Eng Strategy”。

点击“Create project”后，你会被自动跳转到新项目的页面。在该页面点击“Add files”按钮来上传本书。

点击 Add files 后，你会进入“Project files”页面，其中列出了所有已上传的文件。在这里，你可以点击 Add files 按钮，或者直接把 ces_llm.md 文件拖入项目。（提醒：下载 ces_llm.md 的方法已在 《 Crafting Engineering Strategy 》AI 伴侣版 前言 中说明。）

上传文件后，系统会给出警告，提示大文件可能会影响响应。这确实是一个需要注意的问题。首先，OpenAI 模型的 token 窗口限制在其文档中有详细说明。其次，OpenAI 对某些模型设有速率限制，这可能会限制哪些模型适合如此大型的项目。使用 GPT-4.1 mini 或 GPT-4o mini 不会有问题。许多其他模型也能正常工作，但部分模型可能不行。

此时，你已经可以查询该项目，上下文窗口中包含了整本上传的书。（注意下面的提示是使用 ChatGPT-4.1 mini 执行的。）

至此，ChatGPT 项目已完全配置好，你可以随时向它发起查询。

llm 库

前面我们已经介绍了两种以用户体验为主的项目界面，现在我们来看第三种配置方式——通过命令行使用 llm 库。虽然下面的例子专门使用了 OpenAI 的 API，但同样可以无缝切换到 Anthropic、Gemini 或自托管模型。你只需要在命令行中为模型和 API key 指定略有不同的参数即可。

首先按照 《 Crafting Engineering Strategy 》AI 伴侣版 前言 中的说明，下载针对 LLM 优化过的《Crafting Engineering Strategy》版本。本说明假设你已将其放到当前目录下，并命名为 ces_llm.md。

接下来按照 llm 库的安装说明进行设置。我会使用 uv 来管理安装，你也可以使用 pip 或其他 Python 包管理工具。请确保设置好你的 OpenAI API key：

uvx llm keys set openai

然后运行一个简单提示来验证环境是否配置成功：

uvx llm -m gpt-4.1-mini \
'what are the steps to write an engineering strategy?'

假设一切正常，现在你也可以使用本书了：

cat ./ces_llm.md |  \
uvx llm -m gpt-4.1-mini \
'what are the steps to write an engineering strategy?'

这会把整本书的内容放在你的提示之前，输出的结果会与之前不包含本书的提示有明显不同。

通过 MCP 使用工具

在极少数情况下，即使使用了元提示和上下文学习仍不足以让提示有效工作时，最后一项技术是为 LLM 提供专门打造的工具。这些工具让 LLM 专注于它最擅长的事——处理文本表示——而把其他复杂性（尤其是需要复杂数学计算或图像渲染的任务）推给工具本身。

本伴侣书籍中有两章专门深入探讨了 和 。这两章都依赖于使用 Model Context Protocol (MCP) 服务器来访问额外工具。虽然各大 LLM 提供商未来都计划支持 MCP 服务器，但截至目前，只有 Claude Desktop 能相对直接地支持让你的项目与自定义 MCP 服务器进行交互。使用 LLM 生成系统模型用 LLM 生成 Wardley Map

modelcontextprotocol.io/quickstart/user 上的说明是目前设置本地 Claude Desktop 使用自定义工具的最佳指南。你也可以参考 lethain/systems 仓库中的类似说明，该仓库在本伴侣书籍关于生成系统模型的章节中会用到。

如果你完全不想运行 Claude Desktop，但又想尝试使用 MCP 服务器，还有一个选择是 OpenAI Agents SDK。这需要编写一些自定义代码，但这正是 LLM 非常擅长编写的代码类型——只要你在提示中包含相关文档即可。

总结

在本章中，我们介绍了三种基础的提示技巧，帮助你写出更有效的提示：把 LLM 当作实习生、元提示，以及上下文学习。我们还介绍了三种可行的配置方案，用于在大型上下文窗口中与书籍进行交互，包括为 LLM 优化的《Crafting Engineering Strategy》格式。

现在你已经拥有了配置好的环境，可以开始与你的 LLM 副驾驶一起改进工程策略了。
