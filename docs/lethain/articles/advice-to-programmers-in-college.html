给大学程序员的建议

2008-10-22 · 阅读原文

这篇建议的目标读者是大学里的程序员。这个领域里的很多建议都被贴上“给计算机科学（Computer Science）专业学生”的标签，但实际上是为软件工程（Software Engineering）或信息技术（Information Technology）专业的学生准备的。虽然这三类专业在本质上有着具体且可辨的差异，但许多大学会根据这些术语的流行程度来命名自己的课程，因此讨论“计算机科学”专业往往意义不大——很多所谓的计算机科学课程其实更接近软件工程，只是被错误地贴上了标签。

此外，这三个专业的学生通常都在朝着同一个目标前进：成为职业程序员。其中一些人，尤其是计算机科学专业的学生，可能会立志成为学者，但即使拿到博士学位，也不能保证你不会成为一名专业的程序员（无论是在企业工作，还是作为教授或研究员）。

考虑到以上因素，这篇建议主要面向那些将来会成为职业程序员的大学生。当然还有其他可能的情况，有些在读的程序员可能最终会成为小学老师、护士或者可卡因成瘾者，但请原谅我把重点放在最常见的情况上。

多领域浅尝辄止。

创造力的最常见来源之一，尤其是能带来已发表学术论文的那种创造力，就是把一个领域的解决方案移植到另一个领域的问题上。最好的软件也是这样诞生的：领域专家能够深入理解自己领域的细微差别，而优秀的开发者则能将这些细微知识转化为可用的应用程序。当一个人既是领域专家又是程序员时，就能创造出真正惊人的东西（这就是为什么程序员能做出如此优秀的编程工具——我们既是程序员，又是领域专家，所以能把事情做对）。

由此可见，修读多种不同学科课程的学生，能拥有更广阔的灵感来源。当然，你在某个领域钻得越深，理解就会越细致，但我并不建议你在第二个领域深入专攻（比如把计算机科学和化学结合起来读双学位）。相反，我认为你能从更广泛的主题中获得中等程度的理解，从而收获最大益处。

如果你在一个主题上打下基础，就能够很好地继续自学。一旦掌握了基本概念，你就知道以后需要细节时该去哪里找；但如果你没有这个基础，就永远不知道该问什么问题，甚至不知道存在一个问题可以问。

做个人项目。

成为更好程序员的最佳方式就是编写程序。你应该一直都在做一个个人项目。课程里当然会布置编程作业，但个人项目是完全不同的东西：你自己选择主题、自己决定规模、自己挑选语言、自己决定……几乎一切都由你决定。

以下是我挑选优秀个人项目的几点指导原则：

在不同领域做项目。尝试一些网页开发、桌面开发、跨平台开发、依赖强大库的开发，以及完全不使用任何库的开发。游戏编程会带来一些有趣的问题，设计电子表格同样如此。首先专注于挑选有趣的项目，其次再考虑让它变得有挑战性。个人项目最重要的部分是获得经验和眼界。只要项目能持续吸引你的注意力，你就会遇到需要解决的困难边缘情况：即使是简单的问题也会有难搞的部分。（除非你跳过它们，你不会这么做的，对吧？）至少花一部分时间尝试和别人一起做个人项目。只属于你自己的个人项目固然很好，但学会协作同样重要。

不要固守某一种语言、方法或技术。

我在大学时经历过好几个不同的阶段。有一段时间我坚信 Java 就是我的语言，后来又觉得 Common Lisp 是个被压迫的天才，应该赶紧拯救出来并应用到各种问题上。诸如此类。

当你的眼界还很有限时，很容易对某一门具体的编程语言、某种方法（大爆炸式编程、不使用版本控制、把正则表达式当作万能钥匙），或者某项技术（JVM、Ruby on Rails、Django）产生执念。

保持在语言、方法和技术上的灵活性非常重要。这三者都在不断变化，而且变化得非常快。最重要的技能是那些可以迁移的技能：应用设计本身比用 Cocoa 做应用设计更重要，理解 JavaScript 本身比理解 jQuery 更重要，理解 Web 服务器的基本设计（线程、非线程、基于闭包）比理解 Apache 更重要。

慎重规划你的职业道路。

现在流行（而且被大力鼓励）的是在上大学时对未来想从事什么职业完全没有头绪。也许产业界更喜欢这样，因为他们可以获得“及时”劳动力，而不用提前十年预测需求。又或者“永远不要长大”那一派更喜欢这样，因为众所周知，只要我们不残忍地把责任压在孩子们脆弱的肩膀上，或者通过引导他们进入某个领域来限制他们的选择，他们就能彻底无忧无虑。

然而，在成为职业程序员的道路上，主动规划会大大提升你获得理想结局的可能性。程序员的就业机会大致可以分为四类，不同的类别需要不同的准备方式：

在大公司工作是大多数课程默认你会走的路。这是个合理的假设，因为大多数程序员最终可能都会在大公司工作，但意识到这个假设仍然很重要。大公司（它们间接决定了众多编程相关课程的教学内容）最关心的是你在课堂上学到的知识。具体来说，他们想看到你对可测试主题（如算法）的掌握，以及你拥有优秀的成绩。一些大公司可能对特定技能集（PHP、Java 等）感兴趣，但更常见的情况是，他们希望招到可以培养并且能长期留下来的人。在中型公司工作与大公司类似，但他们更注重你带来的具体技能。他们没有大公司那么深厚的资源，因此不得不采取更短期的生产力视角。他们希望你带着一套特定的技能进来，并且已经有一定经验。这使得刚开始在中型公司工作会有些挑战。在小公司工作与在大中型公司有很大不同。小公司需要特别有生产力、能够根据需要处理各种任务的人。小公司关心的是你能否立即上手并产生价值，他们通常不太在意你具体的技能组合（或者说，可能只关心一项技能，比如 Ruby on Rails）。小公司更看重性格和能力。我稍后会再谈这一点，但拥有一份令人印象深刻的项目作品集和写博客在这方面都非常有帮助。作为承包商或顾问是第四类编程工作。与在小公司工作类似，生产力很重要，而能够证明你过去的生产力则更加重要。（这使得拥有作品集或博客变得更为关键。）经常被忽视但同样重要的是，承包商和顾问需要具备良好的沟通能力和适度的亲和力。你工作的一部分就是需要反复被雇佣。在最好的情况下，你每三到六个月会讨论一次新工作，但更可能的情况是你每个月要和好几位新客户沟通（甚至更多）。一旦有了客户，你需要足够友好，让他们喜欢有你在身边，同时你需要和他们有效沟通，确保你能做好自己的工作（也让他们知道你在做好自己的工作）。

我当然不是说你必须现在就决定最喜欢哪一类——你可以为四类都做好准备——但你应该清楚，为了在自己感兴趣的领域成为有竞争力的求职者，需要在哪些方面投入精力。

尤其是，如果你想成为承包商或进入小公司，如果没有一些面向公众的、能证明你编程能力的证据，几乎不可能起步。

让你的才能和性格变得可见。

大学就是一个巨大的评分机器，你完成大量作业和项目，最后带着一个 GPA 毕业，这个 GPA 理论上能描述你作为雇员的潜在价值。这听起来是个很棒的概念，但问题是——除了大公司之外——没人关心你的 GPA。

完全不关心。一点也不。

你应对这种评分骗局的办法，就是为自己创造公开的可见度，来展示你作为程序员的能力。最好的方式是建立一个个人网站，其中包含两个关键部分：

一个博客，你在上面聪明地写关于编程的内容，让你的性格稍微透出来一些。你不需要写得特别多，也不用担心页面浏览量或在 Reddit 上的成功，只要确保你对技术话题的讨论是有见地的。选定几个持续的主题并融入它们的社区会有帮助，但这很可能随着时间推移自然而然地发生。我的建议是始终为了帮助他人而写作。吐槽和充满恶意的评论很容易写而且吸引眼球，但只适合娱乐。写出高质量、对读者有帮助的内容。在写作时记住你的优先级：专业、有鲜明的性格、以及平易近人。一份包含有趣项目的作品集。一开始把你能想到的任何东西都放进去，随着你创造更多项目，逐步用更好的替换掉那些不太出彩的。至少你要描述项目及其所使用的技术，但随着作品集变得越来越有实感，它的效果也会越来越好。尽可能提供在线演示、可下载的源代码、截图和链接。

根据我的经验，让你的性格和才能公开可见，是你在找工作方面能做的最重要的事情。不要担心起步晚，也不要担心让网站变得流行，只要慢慢开始打造你的作品集，一点一点积累成令人印象深刻的东西。

对读研究生保持警惕。

小学之后读初中，初中之后读高中，高中之后读大学，大学之后读研究生。对很多人来说，本科毕业后直接读研是阻力最小的路径。我不是告诉你不要读研究生，而是要告诉你必须确保你读研的理由是充分的。在工作两三年后再找工作，选择机会至少和拿了硕士学位一样好。薪水也是如此。

读研究生唯一好的理由是去深入研究某个具体的东西。带着一个明确的目标去，知道自己到底想完成什么。如果你没有具体的计划，那你很可能只会把本科的内容再复习一遍，学到一点新东西，并没有太多收获。再加上学费，以及放弃工作的机会成本，读研究生不是一件可以一时兴起的事。

尤其是，不要为了逃避对未来做出重要决定而读研究生。如果你觉得自己可能想读研，那么先工作几年再回去有什么坏处呢？如果你本科毕业后开始工作，你可能永远不会读研，但那大概说明你一开始就没有足够强烈的动机。

为自己的教育负责。

虽然课程能教你很多东西，优秀的老师能布置引人入胜的项目，写得好的教科书能解释复杂的算法，但你不能把对自己教育的责任完全交给老师或课程。要成为一名优秀的程序员，你必须超越课堂内容，主动引导自己的学习。

这其中最重要的一部分就是前面提到的个人项目，它们会引导你去学习和探索各种各样的话题。有些人认为阅读他人写的东西同样重要，但我的经验是，你从创造中学到的东西远比从消费中学到的多。阅读他人写的东西当然有价值，但不要因此放弃自己创造东西。

总结

最重要的是，我希望你为自己和自己的未来负责。在我们的社会里，很容易在人生前三分之一的时间里随波逐流，从来没有真正投入到自己的生活中。请不要那样。我恳求你。如果你想真正活着，那就主动去生活。

我们正站在一个不确定的未来的浪尖上。但早在报纸开始哀叹求职者处境艰难或热情吹捧最新科技泡沫之前，未来就一直是不确定的。这种不确定性中充满了闪闪发光的地方，而能否去追逐它们，取决于我们自己。
