已处理的塔防游戏设计

2008-05-18 · 阅读原文

过去四天，我一直在使用 Processing.js 开发一款塔防风格的游戏，今天在坐火车前往名古屋的途中，我投入了最后一个小时来完善它。目前它已经是一款功能完备的游戏，虽然还不算特别有趣。本文将简要介绍项目的当前状态，然后讨论一些比较有趣的实现细节。

当前状态

目前游戏中只有两种塔和一种敌人。有一个可由玩家手动瞄准的导弹攻击，实现类似的其他玩家主动攻击类型也相当容易。还有一个敌人波次控制器，它会定期生成敌人波，而每波又会定期生成敌人。每升一级，每个敌人提供的金币会线性增加，而敌人的生命值则会呈指数增长。

整个项目包括空行和注释在内，总共不到 800 行 JavaScript 代码——正如我下面将要分析的，这是一个相当灵活的架构。目前最重要的未实现功能是升级和配置塔的方式。由于点击塔已经可以显示其作用范围，接下来只需要编写一些升级路径，并实现某种用户交互界面即可。

接下来，让我们稍微拆解一下代码。

主要游戏设置与循环

设置和游戏循环看似非常简单。负责所有游戏逻辑的 draw 循环只有短短五行。

var start_tower_defense = function() {
  setup = function() {
    set_canvas("tower_defense");
    reset_game();
    size(SET.width, SET.height);
    frameRate(SET.framerate);
    mouseMoved(on_mouse_moved);
    mousePressed(on_mouse_press);
  }
  draw = function() {
    if (SET.state != SET.game_over_state && SET.state != SET.pause_state) {
      background(SET.bg_color);
      update_groups(SET.rendering_groups);
    }
  }
  setup();
}

当然，我们真正想知道的是“update_groups 到底在做什么？”答案是：几乎一切。除了管理用户界面状态（例如“玩家是否正在放置塔？”“是否正在瞄准导弹？”等等）之外，所有逻辑都由这个 update_groups 函数处理，而它的实现其实相当简洁。

update_groups 接受一个参数，即一个由对象数组组成的数组，这些对象需要遵循一个简单的协议。该协议包含三个方法：

  1. update is used to update any values.
  2. is_dead is used to remove objects that are done being used.
  3. draw explains how to render the object.

这个数组的遍历是逆序进行的，因为内部数组的索引代表其渲染深度。因此，深度为十二的对象应该在深度为七的对象之前渲染。在同一深度的数组内，对象按常规顺序渲染（即 0、1、2……n-1、n）。

var update_groups = function(groups) {
  var obj_update = function(x) { 
    if (x != undefined) x.update();
  };
  var obj_is_alive = function(x) {
    if ( x == undefined || x.is_dead()) return false;
    return true; 
  };
  var obj_draw = function(x) { x.draw(); };
  for (var i=groups.length-1;i>=0;i--) {
    var group = groups[i];
    if (group != undefined) {
      group.forEach(obj_update);
      var alive = group.filter(obj_is_alive);
      alive.forEach(obj_draw);
      groups[i] = alive;
    }
  }
}

首先对所有对象调用 update，然后使用 is_dead 过滤掉不再需要的对象，最后通过 draw 将对象渲染出来供玩家观看。这个简单的模式似乎适用于任何涉及大量（某种程度上）并发过程的场景。

实际上，理解这个简单的函数几乎就能掌握游戏的大部分实现原理。下面我们来看一个快速实现这个简单接口的例子。

游戏将当前时间存储在一个全局变量中，这样在一次 update_groups 执行过程中，所有事件都使用相同的时间值。 处理这个逻辑的函数定义如下：

var SettingUpdater = function() {
  var su = new Object();
  su.is_dead = function() { return false; };
  su.draw = function() {};
  su.update = function() { SET.now = millis(); }
  assign_to_depth(su, SET.system_render_level);
  return su;
};
var setup = function() {
  // ...
  SettingUpdater(); // initialize SU
  // ...
}

其中可能不太清楚的一点是，assign_to_depth 函数用于将对象放入一个渲染组，而 SET.system_render_level 是所有渲染组中层级最低的（意味着它最先被处理）。这是一个相当简单的模式，在代码中很常见。

作为这种方法的最后一个例子，让我们来看看游戏的网格是如何实现的。

var Grid = function() {
  var grid = new Object();
  grid.update = function() {};
  grid.is_dead = function() { return false; };
  grid.draw = function() {
    stroke(SET.grid_color);
    var p = SET.pixels_per_square;
    var w = SET.width;
    var h = SET.height;
    for (i = 0; i<w; i+=p) {
      line(i, 0, i, h);
    }
    for (i = 0; i<h; i+=p) {
      line(0,i,w,i);
    }
  };
  assign_to_depth(grid, SET.grid_render_level);
  return grid;
};

同样，这里实现了这个简单的三个方法接口，然后将对象放入渲染组，全部工作就完成了。

用户界面

除了用于更新和渲染的三个方法接口外，其余代码都围绕用户界面的三个函数接口展开。这次三个函数（根据需要，其中零个或多个可以未定义）分别是：

  1. state_legal is a function to determine if the selected action can be performed where the mouse currently is.
  2. state_action is the function to call if mouse is clicked (and the action is legal).
  3. state_draw is a function to draw any ui feedback necessary from the moving mouse (for example the radius surrounding the mouse when placing a tower or aiming a missile).

我们先来看看使用这个接口的代码，以了解它具体在做什么，然后再看看实现这个接口的具体代码。

这个接口的实现位于两个方法中：on_mouse_moved 和 on_mouse_press，分别在鼠标移动和鼠标按下时被调用。两者放在一起是这样的：

var on_mouse_moved = function() {
  var pos = mouse_pos();
  if (SET.state != SET.normal_state && SET.state_legal) {
    if (SET.state_legal(pos.x,pos.y) == true)
      SET.bg_color = SET.bg_colors.positive;
    else SET.bg_color = SET.bg_colors.negative;
    }
  else {
    SET.bg_color = SET.bg_colors.neutral;
  }
  if (SET.state_draw) SET.state_draw(pos.x,pos.y);
};
var on_mouse_press = function() {
var pos = mouse_pos();
if (SET.state == SET.normal_state) {
var gpos = pixel_to_grid(pos.x,pos.y);
var tower = get_tower_at(gpos.gx,gpos.gy);
if (tower != false) select_tower(tower);
}
else {
if (SET.state_legal && SET.state_legal(pos.x,pos.y) == true)
SET.state_action(pos.x,pos.y);
set_state_normal();
}
};

基本上，游戏要么处于正常状态，要么处于某种特殊状态。如果处于特殊状态，则由那三个函数的接口来控制用户界面。如果处于正常状态，则可以通过 HTML 中定义的按钮将其切换到特殊状态，或者点击塔也可以切换到另一个状态（理论上任何点击或鼠标按下都可以切换状态，只要添加相应的监听代码即可）。

接下来我们看看实现“放置导弹塔”功能的代码：

var build_missile_tower = function() {
  var cost = 100;
  if (SET.gold >= cost) {
    SET.state = SET.placing_tower_state;
    SET.state_legal = function(x,y) {
      var gpos = pixel_to_grid(x,y);
      return can_build_here(gpos.gx,gpos.gy);
    };
    SET.state_draw = function(x,y) {
      var gpos = pixel_to_grid(x,y);
      var mid = center_of_square(gpos);
      var radius = SET.pixels_per_square;
      SET.rendering_groups[SET.killzone_render_level] = [];
      BuildRadius(mid.x,mid.y,radius);
    }
    build_tower_mode();
    SET.state_action = function(x,y) {
      var gpos = pixel_to_grid(x,y);
      MissileTower(gpos.gx,gpos.gy);
      SET.gold -= cost;
      set_state_normal();
    }
  }
};

这个状态通过点击 HTML 中标记为“Build Missile Tower”的按钮来激活。对于这个界面状态，只要当前格子上没有方块或塔，任何位置都是合法的。state_draw 方法会绘制一个小圆圈，让玩家知道自己当前指向的位置，而 state_action 方法则会在选定的格子上创建一座塔，并扣除玩家的金币。

所有其他用户界面模式都是以相同的方式实现的。

总结

这两种模式被用来实现整个 Processed Tower Defense，并证明在保持游戏易于理解和扩展方面非常有用。在某些地方，我对渲染循环的使用接近于 hack，如果能更加明确一些，将有助于提高代码可读性（例如，我假设塔的渲染层只会包含塔，敌人的渲染层只会包含敌人，这是一个合理的假设，但最好能更明确地说明）。

其实就是这些，希望这篇文章能给对游戏开发感兴趣的朋友带来一些启发。
