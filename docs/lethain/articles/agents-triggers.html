构建内部 Agent：触发器

2025-12-31 · 阅读原文

内部 Agent 只有在其工作流被触发时才能产生价值。构建一套工作流初始化机制（我们称之为触发器），是构建内部 Agent 的核心工作之一。

这是 构建内部 Agent 系列文章的一部分。

为什么触发器如此重要

虽然现在很多人都在谈论 AI 如何让员工能轻松自动化日常工作流，但真正构建这些工作流需要对 Agent 的工作原理有深入直觉，而这种直觉只能通过迭代学习逐步培养。目前很少有企业提供支持这种迭代学习的工具。易于使用的触发器，结合便捷的 Prompt 迭代功能，是实现迭代学习的基础。

从更实际的角度看，触发器是启动工作流的机制，如果它们不够有效或不易使用，其他一切都无从谈起。

为什么不用 Zapier 或 n8n？

最显而易见的问题是“为什么不用 Zapier？”以及“为什么不用 n8n？”，它们都能完整解决触发问题。说实话，你仍然可以使用 Zapier 或 n8n 通过自定义 webhook 触发器来启动 Agent 工作流，因此这些方案并不冲突。但对我来说，我认为真正重要的工作流数量并不多，而且我希望在解决问题过程中对各种细节有完全的控制权。

“完全控制”这一点也呼应了我对这项工作的一个基本观点：高质量的细节处理能显著促进采用度，而 Zapier 集成的限制则无法做到。这也是为什么我认为内部 Agent 需要投入大量精力去处理 Slack 实体解析这类问题，以实现无缝的使用体验。

我们如何实现触发器

我们按照以下顺序实现了这些触发器：

  1. Notion webhooks can be configured to fire on any page or database modifications, including things going from “draft” status to “ready for review” status or other more nuanced changes. We’ve updated all our Request for Comment and other structured document databases to hook into these.The triggers drive a variety of workflows. On the simpler end, they can be used to assign additional reviewers to a document based on topic, and on the more complex end they can use a prompt to provide in-line comments with suggestions.
  2. Slack messages can trigger responses or other workflows. This is dependent on which channels the bot has been invited into, and I subsequently made a trigger to capture channel creation to support auto-joining new channels to increase availability. (Channels that are auto-joined have a simple, default prompt that only responds when the bot is mentioned directly, to avoid wearing out its welcome.)We also got this working in private channels (not the auto-join component, just responding to messages). The hard part was ensuring that logging didn’t capture any evidence of joining or responding in those private channels. Exfiltrating private messages would have been a very easy way to quickly lose trust.
  3. Jira webhooks can be configured to trigger notifications on issue creation, updates, comments and so on.
  4. Slack reacji were a later addition, where we added support for listening to Slack reacji in either a given channel or in any channel where the bot is present. This has made it possible to quickly implement a trigger where the :jira: reacji in any channel turns a thread into a ticket, routing it using centralized routing instructions (which are imperfect, but much better than the average individual’s ability to route across many different teams).
  5. Scheduled events are our most recent addition, allowing periodic triggers. I’ve done two distinct v0 implementations, with the first relying on Slack workflows publishing into new channels as triggers, and the other relying on Github actions. Both work well enough, despite being a bit messy.

现在我们已经有了相当丰富的触发器类别，并且更新了 AGENTS.md 来记录现有集成，之后要添加新的触发器类型，通常只需要把文档粘贴到 Claude 里，等几分钟就能完成。

触发器的认证与授权

在认证和授权方面，只要条件允许，我们都会采用 OAuth2 的授权令牌 + SSL 方式。然而，对于 Slack 这类无法在请求中注入授权令牌的场景，该方法就行不通了。此时我们会依赖底层平台提供的应用层安全机制，比如 Slack 验证请求的机制。

目前效果如何？下一步是什么？

我们现有的这组触发器运行得很好。下一步任务——可能只需要两句 Prompt 和十分钟让 Claude 生成代码——是增加对更通用 webhook 的支持，将整个传入消息纳入上下文窗口。目前虽然还没遇到必须使用的场景，但这是一个很有用的兜底机制，能支持未来的各类工作流。

特别值得一提的是，它可以很方便地与现有的 Zapier 订阅配合使用，将一些冷门触发器的支持交给 Zapier 庞大的集成目录，同时我们仍能保留内部 Agent 在控制力和细节处理上的优势。
