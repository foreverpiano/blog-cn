Python 中的并行 HTTP 请求

2008-12-02 · 阅读原文

上周我正在为一位客户做性能优化工作，我们取得的一项重要改进就是将 HTTP 请求并行化。如果你的服务器在渲染页面之前需要调用两到三个 API（这是 mashup 开发者的痛点），那么依次发起请求可能会严重拖累性能。在那位客户的项目中，解决方案必须用 PHP 实现，但今晚我决定为 Python 快速写一个类似的方案（可能也有人已经提过这个想法）。

利用 threading 和 urllib 模块，这件事实现起来相当简单。我的（非常基础的）策略是为每个请求创建一个线程，持续轮询这些线程直到它们全部完成，最后将收到的数据以列表形式返回，每个元素是一个 (url, data) 二元组。另外我还希望能设置一个适用于所有线程的超时时间（同样是为了保持响应迅速）。

最终我的代码大致如下（假设它保存在一个名为 multi_get.py 的文件中，后续示例中会用到）：

from threading import Thread, enumerate
from urllib import urlopen
from time import sleep
UPDATE_INTERVAL = 0.01
class URLThread(Thread):
def init(self,url):
super(URLThread, self).init()
self.url = url
self.response = None

    <span class="bp">self</span><span class="o">.</span><span class="n">response</span> <span class="o">=</span> <span class="bp">self</span><span class="o">.</span><span class="n">request</span><span class="o">.</span><span class="n">read</span><span class="p">()</span>
def multi_get(uris,timeout=2.0):
def alive_count(lst):
alive = map(lambda x : 1 if x.isAlive() else 0, lst)
return reduce(lambda a,b : a + b, alive)
threads = [ URLThread(uri) for uri in uris ]
for thread in threads:
thread.start()
while alive_count(threads) > 0 and timeout > 0.0:
timeout = timeout - UPDATE_INTERVAL
sleep(UPDATE_INTERVAL)
return [ (x.url, x.response) for x in threads ]

使用方法如下：

from multi_get import multi_get
sites = ['http://msn.com/','http://yahoo.com/','http://google.com/']
requests = multi_get(sites,timeout=1.5)
for url, data in requests:
    print "received this data %s from this url %s" % (url,data)

我与下面这个简单的顺序实现做了对比测试，

from urllib import urlopen
import time
results = []
sites = ('http://msn.com/','http://yahoo.com/','http://google.com/')
for site in sites:
start = time.time()
req = urlopen(site)
results.append((site, req.read()))
end = time.time()
print "took %s seconds" % (end-start)

结果正如预期。在我的网络环境下，访问 MSN 需要 1.14 秒，而 Yahoo 和 Google 的耗时在 0.1 到 0.2 秒之间（谁知道呢，也许它们因为 User-Agent 不对而返回了错误页面）。第一个并行执行的脚本，其总耗时只比最慢的那个请求慢十到二十毫秒，而顺序执行的脚本则花费了更长时间（基本上是所有响应时间之和）。

当你开发下一个 Django 或 TurboGears mashup 项目时——甚至计划下一次注定艰难的 Google 页面抓取之旅——不妨尝试一下并行请求，看看它能带来多大的帮助。

（你也可以使用 asyncore 模块来解决这个问题，但它总是给我抛出一些奇怪的错误，于是我选择了多线程方案。既然线程方案表现已经足够出色，我就保持原样了；使用 asyncore 原理上差不多，只是你需要编写更多 HTTP 相关的胶水代码，尤其是当你想支持比 GET 更复杂的请求时。）
