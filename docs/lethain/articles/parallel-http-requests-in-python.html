Python 中的并行 HTTP 请求

2008-12-02 · 阅读原文

上周我正在为一位客户做性能优化工作，我们取得的最大改进之一就是让 HTTP 请求并行执行。如果你的服务器在渲染页面之前需要调用两到三个 API（这是 Mashup 开发者的梦魇），那么顺序请求会严重拖累性能。在那位客户的项目中，解决方案必须用 PHP 实现，但今晚我决定为 Python 写一个类似的方案（可能也有人提出过这个想法）。

利用 threading 和 urllib 模块，这个任务实现起来相当简单。我的（非常基础的）策略是为每个请求创建一个线程，不断轮询这些线程直到它们全部完成，然后将接收到的数据以列表形式返回，列表中的每个元素都是 (url, data) 的二元组。我的另一个需求是希望能为所有线程设置一个统一的超时时间（同样是为了保持响应迅速）。

结果正如预期。在我的网络环境下，MSN 需要 1.14 秒才能加载完成，而 Yahoo 和 Google 大约在 0.1 到 0.2 秒之间（谁知道呢，也许它们因为 User-Agent 拒绝了请求并返回了错误页面）。第一个并行执行的脚本，其总耗时只比最慢的单个请求慢十到二十毫秒，而顺序执行的脚本则要长得多（基本上是所有响应时间之和）。

当你构建下一个 Django 或 TurboGears Mashup 时——甚至计划下一次注定失败的 Google 网页抓取冒险——不妨试试并行请求，看看它能带来多大的帮助。

（你也可以使用 asyncore 模块来解决这个问题，但它给我抛出了一些奇怪的错误，所以我选择了基于线程的方案。鉴于线程方案表现优秀，我决定就保持原样；使用 asyncore 应该也能实现类似功能，但你需要编写更多胶水代码来处理 HTTP 相关部分，尤其是当你想支持比 GET 请求更复杂的操作时。）
