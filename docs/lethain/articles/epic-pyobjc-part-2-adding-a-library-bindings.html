如果你对 Objective-C 数据结构不太了解，这里是一个快速入门。最常见的结构是 NSArray 和 NSDictionary。它们与 Python 的列表和字典非常相似，但有一个重要区别：它们是不可变的。因此，NSArray 实际上更类似于 Python 的元组，而 NSDictionary 在 Python 中没有完全对应的类型。

相应地，PyObjC 会将 Python 列表映射到 NSMutableArray 类，将 Python 字典映射到 NSMutableDictionary 类，它们与 NSArray 和 NSDictionary 相同，只是其数据可以被修改。这种模式在许多其他 Objective-C 类中也存在，比如 NSString 和 NSMutableString。

免责声明：这里简化了一个重要区别，即 Python 的 list 是链表，而 NSArray 是数组。这意味着两者在许多操作上的效率并不相同。想了解更多可以查看 Wikipedia 上关于 linked list 和 array 的条目。

Cocoa Bindings 入门

Cocoa Bindings 是从 OS X Panther 开始加入 Cocoa 的框架。如果使用得当，绑定可以帮助消除 Cocoa 应用中重复且常见的模式。最常见的场景（也是我们马上要看到的）是 NSArrayController 可以自动完成使用数组为表格视图提供内容的过程。

以这种方式控制 NSTableView 并不难——只是有点繁琐——但在你搭建了第四或第五个表格视图之后，你会开始觉得应该有更好的办法。

Cocoa Bindings 就是那个更好的办法。你在 InterfaceBuilder 中创建几个对象，将一些 IBOutlets 连接起来，根据应用需求再写几行代码，就完成了。

顺便说一句，这似乎是适合插入一段温和提醒的好时机：我有时仍然会使用 datasource 和 delegate 方法来为表格视图提供数据。Cocoa Bindings 能让常见操作变得简单，但当你开始做一些非典型的事情时，它们的适用范围就不会那么广了。

你的应用逻辑和工作方式偏离常规越多，你就越有可能遇到 Cocoa Bindings 无法帮到你的情况。

另一个值得一提的是，如果你将 Core Data 与 Cocoa Bindings 结合起来，可以免费获得大量强大功能。本教程不会深入探讨这种强大的组合，但当你继续前进时，非常值得花时间去研究。

我强烈推荐 CocoaDevCentral 上关于 Core Data 和 Cocoa Bindings 的文章作为起点。它是用 Objective-C 实现的，基于 OS X 10.4 时代，但仍然是一篇很棒的入门文章。

除了 NSArrayController 之外，还有其他几个类似的控制器：NSObjectController 用于普通对象，NSDictionaryController 用于字典，NSTreeController 用于树状数据类型，以及 NSUserDefaultsController 用于用户默认设置。它们都与 Cocoa Bindings 结合，让你的开发工作轻松一些。

刚开始你可能需要强迫自己去使用它们——Cocoa Bindings 的学习曲线确实不太友好——但掌握它们后，你会变得更快乐、更有生产力。

search_ 方法

本部分的最后一步是重写 search_ 方法。这里有一个棘手的问题，它源于 Python、Objective-C 和 PyObjC 处理内存管理的方式。

关于 Python 和 Objective-C 在垃圾回收机制上的差异，简单说明一下。

在 Python 中，内存管理对程序员来说通常是完全透明的。你创建对象，使用它们直到不再需要。然后你停止使用它们，事情就结束了。如果某个对象在某处仍有引用，它就会一直存活，否则垃圾回收机制下次检查时就会回收它。简单又方便。

然而，在 Objective-C 中，你需要自己进行一些内存管理。通常有三个方法（存在于所有 Objective-C 对象中）用于管理内存：retain、release 和 autorelease。

每个对象在创建时都有一个计数器，初始值为零。每当调用其 retain 方法，计数器就增加一。每当调用 release 方法，计数器就减少一，当计数器为零时，该对象就面临被垃圾回收机制回收的危险。

autorelease 稍微复杂一些，它意味着计数器将在当前运行循环结束时减少一。基本上这意味着你可以在短时间内使用一个 autoreleased 对象，但它不会长时间存在。

不过，要理解 Objective-C 中的内存管理，还有一个关键信息：当你创建一个对象的新实例时，谁拥有它？或者继续用前面的解释，它的计数器初始值是多少？

事实证明这个问题没有单一答案，而是一条指导原则。如果你使用的方法名中包含 init 或 copy 来创建对象，那么你就负责释放该对象（即它的初始计数值为 1）；否则你应该假设该对象是被 autoreleased 的，会在当前运行循环结束时被释放，而你无需做任何事情。
