更小的页头、JobSyndicate、可打印文章

2009-02-19 · 阅读原文

今天早上我对网站做了一些调整，试图让它更易用一些，同时也稍微改善一下外观。

我的朋友 Luke 对网站的第一条反馈就是页头太大，把正文内容都挤到了首屏下方。我原本没太在意这个，但 Irrational Exuberance 一直以来的目标就是纯粹聚焦于内容。缩小页头尺寸后，内容就能在网站交互中占据更核心的位置。

其实虽然之前的页头看起来很大，但真正能用来展示信息的空间却很少。现在把链接移到页脚后，我就能同时展示所有标签和系列的文章，还能显示随机文章和最新文章。

几周前（几个月前？我已经记不清了，我觉得他们的社区推广人员可能已经恨死我了——注册之后就消失不见……）我被接受加入 JobSyndicate 的 beta 版，得以在这个网站上发布他们的招聘广告。

我并不指望这个网站能直接通过收入实现自给自足，但我对以无害的方式尝试变现很感兴趣。JobSyndicate 提供的职位和我读者群很匹配，所以我决定试用一段时间。如果读者不喜欢，我大概会把它们撤掉。不过说实话，我觉得这些广告还挺无害的。至于它们最终会不会产生什么效果，那就是另一回事了。

我正在使用自己的 django-monetize 项目来针对 Code 分类下的文章投放这些广告。在 Life 分类里那些篇幅短小又没什么意思的随笔中显示广告毫无意义，在导航页面（归档、标签云）或信息页面（关于、项目）中显示就更没必要了。

我知道没多少人在意，但我觉得 django-monetize 正是我当初开始做它时想要的那个工具。只花了大约五分钟，我就把 JobSyndicate 集成到了我的广告定向方案中。它让我能够精确选择广告位（页头广告位我依然留空，感觉有点太突兀），还能使用回退机制来选择要显示的广告。

举个例子，目前我在 Epic Introduction to PyObjC 系列文章中显示的是 PayPal 捐赠请求。如果一篇文章属于 Code 分类但不在该系列中，就会显示 JobSyndicate 的广告。如果既不在该系列也不属于 Code 分类，则再次回退（什么都不显示；）。

这种精细程度非常吸引我，因为它让我可以为特定内容（比如一个很长的教程系列）寻求支持，而不是直接为自己寻求支持。同时也能让我进行相对不干扰用户的修改和实验。

最后一个最近的改动是打印文章的 CSS 变得合理多了，现在应该可以把文章打印出来，慢慢阅读，而不再只能在线浏览。

欢迎告诉我你对这些改动的看法，以及任何改进建议。

随着时间推移，还有一些其他变化：

哦，我还稍微调整了归档页面，让它更容易浏览。标签云现在按正常的人类排序，而不是奇怪的大小写字母排序。每个标签下的文章列表使用和归档页面一样的简洁格式。首页现在显示五篇文章而不是三篇。这样感觉更好。

第二天……

我已经把 lethain.com（以及我所有其他域名）迁移到了我的 mod_wsgi slice 上，并为 CSS 和 JS 文件设置了远期过期时间和压缩，希望能显著提升加载速度。我非常庆幸终于摆脱了那台旧服务器，它的配置已经越来越一团糟了。
