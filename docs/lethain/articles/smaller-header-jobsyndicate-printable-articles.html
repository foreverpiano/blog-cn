更小的页头、JobSyndicate、可打印文章

2009-02-19 · 阅读原文

今天早上我对网站做了一些调整，目的是让网站更好用，同时稍微提升一下外观。

我的朋友 Luke 第一次看到网站时就说页头太大，把主要内容都挤到了首屏以下。我原本对此并没有特别在意，但 Irrational Exuberance 一直以来的目标就是专注于内容本身，我认为缩小页头能让内容在与网站的互动中占据更核心的位置。

其实虽然之前的页头看起来很大，但真正能用来展示信息的地方却很少。现在把链接移到底部后，我就可以同时展示所有标签和系列的文章，还能显示随机条目和最新内容。

几周前（几个月前？我已经记不清了，我觉得他们的社区推广人员可能已经恨死我了——注册之后就再也没出现过……）我被接受加入 JobSyndicate 的 beta 测试，可以在这个网站上发布他们的职位广告。

我完全不指望这个网站能直接通过收入实现自给自足，但我对以不损害用户体验的方式进行收入实验很感兴趣。JobSyndicate 提供的职位和我读者的背景比较相关，所以我决定试一试。如果读者不喜欢，我大概会把它们去掉。不过老实说，我觉得这些广告还挺不招人讨厌的。至于它们最终会不会产生什么效果，那就是另一回事了。

我正在使用自己的 django-monetize 项目来针对性地为 Code 分类下的文章展示这些广告。在 Life 分类下那些篇幅短小且没什么意思的随笔里展示广告毫无意义，在导航页面（归档、标签云）或信息页面（关于、项目）里展示就更没必要了。

我知道没多少人在意，但我觉得 django-monetize 确实就是我当初开始做它时想要的那个工具。把 JobSyndicate 整合进我的广告投放逻辑只花了大概五分钟，它让我可以精确选择要使用的广告位（页头广告位我还是空着，感觉有点太突兀），并且还支持使用 fallback 机制来选择广告。

举个例子，目前我在 Epic Introduction to PyObjC 系列文章中会显示 PayPal 捐赠请求。如果一篇文章属于 Code 分类但不属于那个系列，就会展示 JobSyndicate 广告。如果既不属于该系列也不属于 Code 分类，则继续回退（最终什么都不显示；）。

这种细粒度的控制非常合我心意，因为它让我可以为特定内容（比如一个很长的教程系列）寻求支持，而不是直接为自己寻求支持。同时也让我能够进行相对不干扰用户的修改和实验。

最近的最后一个改动是打印文章的 CSS 变得合理多了，现在应该可以把文章打印出来，方便大家离线慢慢阅读，而不只是在线查看。

欢迎告诉我你对这些改动的看法，以及任何改进建议。

随着时间推移，还有一些其他改动：

哦，我还稍微调整了归档页面，让它更容易浏览。标签云现在按照人类习惯的顺序排列，而不是奇怪的大小写字母排序。每个标签下的文章列表使用了和归档页面相同的简洁格式。首页现在显示五篇文章而不是三篇。这样感觉好多了。

第二天……

我已经把 lethain.com（以及我所有的其他域名）都迁移到了我的 mod_wsgi slice 上，并为 CSS 和 JS 文件设置了远期过期时间和压缩，希望能显著提升速度。我真的很高兴终于摆脱了那台老服务器，它的配置已经越来越乱七八糟了。
