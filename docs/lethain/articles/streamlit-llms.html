使用 Streamlit 和 LLMs 玩耍

2023-06-19 · 阅读原文

最近我和一些公司聊过，他们正在为团队构建内部的 LLM 实验室或工具，以便轻松针对内部用例测试 LLM。我想花几个小时试试看，用 Streamlit 给自己搭建一个个人 LLM 实验室，来支持我自己的一些用例。

代码见 lethain/llm-explorer。

总的来说，我对 Streamlit 的易用性印象深刻，在这个时间内我成功构建了两个有用的工具：

一个基于文本的 LLM 笔记本（带提示历史）；一个基于电子表格的 LLM 笔记本。

将我之前博客文章中构建的博客嵌入查询工具探索 OpenAI移植过来应该相当容易，同时也可以按照 ask-my-pdf 的演示，对任意 PDF 进行索引和查询。

这些只是粗略的笔记，如果你对 Streamlit 不感兴趣，可以直接浏览下面的截图，感受一下几个小时内能做出什么样的东西。

安装

首先，我们创建一个新的虚拟环境来玩耍：

mkdir llm-streamlit && cd llm-streamlit
python3 -m venv env
pip install streamlit

然后运行“Hello world”脚本验证安装是否成功：

streamlit hello

这应该会打开一个 Streamlit 页面。

制作我们自己的 Hello World

接下来，我们可以按照这些说明写一个非常简单的 Streamlit 页面：

import streamlit as st
import pandas as pd
df = pd.DataFrame({
      'first column': [1, 2, 3, 4],
      'second column': [10, 20, 30, 40]
})
df

然后通过以下命令运行它：

streamlit run main.py

这会在 localhost:8501 上变成这样一个网站。

我们也可以添加折线图并高亮最大值，只需将 df 替换为更明确的命令：

st.line_chart(chart_data)
st.dataframe(df.style.highlight_max(axis=0))

这会在我们的表格上方加上一个漂亮的小折线图。

现在，我们来试试创建一个控件：

import streamlit as st
st.text_input("Your name", key="name")
name = st.session_state.name
st.write(f"This table is created by {name}:")

这允许我们

接下来，我们添加第二个页面，以便了解如何创建不同的页面。我们保留 main.py，并在其中调用 st.sidebar.markdown 来填充侧边栏内容：

import streamlit as st
import pandas as pd

st.markdown("# LLM Notebook")
st.sidebar.markdown("# LLM Notebook")

df = pd.DataFrame({
    'first column': [1, 2, 3, 4],
    'second column': [10, 20, 30, 40]
})

st.text_input("Your name", key="name")
name = st.session_state.name
st.write(f"This table is created by {name}:")
st.dataframe(df)

然后我们在 pages/pdf.py 中创建第二个页面，作为后续添加工具的占位符：

import streamlit as st

st.markdown("# PDF Extraction")
st.sidebar.markdown("# PDF Extraction")

现在我们有了一个非常简单的脚手架，接下来将通过与 OpenAI 的 LLM API 交互来扩展它。

与 LLM 交互

本节内容主要参考了 Streamlit 的 Langchain_Quickstart。

第一步是安装 LangChain，以简化与 LLM 的交互：

pip install openai langchain

然后我们要解决如何加载 OpenAI API key 的问题。标准的示例是在侧边栏放一个输入框让我每次粘贴 key，但我不想每次都这么做，所以我复用了上次 OpenAI 实验时从 Simon Willison 那里借鉴的 key 加载方式探索 OpenAI。

我创建了一个 oai_utils.py，并在其中加入了这个函数：

import os

def get_openai_api_key():
    api_key = os.environ.get('OPENAI_API_KEY')
    if not api_key:
        key_file = os.path.join(os.path.expanduser("~"),
                                ".openai-api-key.txt")
        api_key = open(key_file).read().strip()

    return api_key

你可以选择在 ~/.openai-api-key.txt 文件中存放你的 key，或者在运行 Streamlit 时通过环境变量直接传入 api key：

env OPENAI_API_KEY=ABC123 streamlit run main.py

两种方式都行。现在我们来更新 main.py 以支持查询 OpenAI：

import streamlit as st
from langchain import OpenAI
from oai_utils import get_openai_api_key

openai_api_key = get_openai_api_key()

def generate_response(input_text):
    llm = OpenAI(temperature=0.7, openai_api_key=openai_api_key)
    st.info(llm(input_text))

st.markdown("# LLM Notebook")
st.sidebar.markdown("# LLM Notebook")

with st.form('my_form'):
    text = st.text_area('Prompt:', '',
      placeholder='How do I use Streamlit to query OpenAI?')
    submitted = st.form_submit_button('Submit')
    if submitted:
        generate_response(text)

这段代码为我们提供了一个功能完整但相对基础的 OpenAI 查询环境。

接下来我们可以开始添加一些功能。

在 OpenAI 模型之间选择

目前我们无法选择要查询的模型，这有点烦人，所以我们使用 st.selectbox 控件来选择模型。

以下代码与上面类似，仅对 generate_response 函数和 st.form 调用做了少量调整：

def generate_response(input_text, model_name):
    llm = OpenAI(temperature=0.7, openai_api_key=openai_api_key, model_name=model_name)
    st.info(llm(input_text))

st.markdown("# LLM Notebook")
st.sidebar.markdown("# LLM Notebook")

with st.form('my_form'):
    oai_model = st.selectbox(
        'Which OpenAI model should we use?',
        ('gpt-3.5-turbo', 'gpt-4', 'ada', 'babbage', 'curie', 'davinci'),
    )
    text = st.text_area('Prompt:', '',
      placeholder='How do I use Streamlit to query OpenAI?')
    submitted = st.form_submit_button('Submit')
    if submitted:
        generate_response(text, oai_model)

现在我们可以使用任意想要的模型进行查询。请注意，如果你没有 gpt-4 的 beta 访问权限，它可能无法使用，但其他模型应该都没问题。OpenAI 的模型列表可以在这里找到。

如果你因为企业合同等原因不想使用官方的聊天界面，而是希望用自己的 API key 与 OpenAI LLM 交互，那么这个界面已经算相当不错了——它能让你对 API 请求中包含的数据有更清晰的控制。

LLM 与电子表格（又称可编辑 DataFrame）

接下来，我们尝试为 LLM 创建一个电子表格界面。目标是让你创建一个表格，然后对每一行单独运行 LLM。例如，你可能每行有一个邮件地址，想针对它测试某个提示词。

我最初希望使用 st.data_editor（在博文中介绍过）来动态创建和编辑表格。这几乎可行，你可以添加行，但无法添加或删除列。我相信肯定有办法解决，但为了简单起见，我决定允许用户上传 CSV 来填充表格，之后再支持添加或删除行。我们可以使用 st.file_uploader 来实现这一点。

我创建了 pages/spreadsheet.py，总共 50 行 Python 代码，你可以在 Github 上看到。

我用最近《Planning》博客文章中的财务表格的子集如何作为工程高管进行规划。进行了测试，我觉得这个界面相当不错。我把 Google Sheet 导出为 CSV，上传后，就能用 st.data_editor 删除不想看到的行（操作稍显反直觉：选中行后再点删除按钮）。之后，我就可以对每一行运行一个提示词，从中提取数据。

我得说，我选择的这些具体数据其实非常不适合这类分析，但你可以想象它在其他类型数据上会表现更好，比如根据表格中人物的信息，为他们生成一封外联邮件。

记录之前用过的提示词

回到 main.py，我想看看把之前的提示词保存在左侧边栏有多难，这让我开始研究 session-state。我在本地开发中完全无法让 session state 正常工作。很可能这是“Streamlit cloud”独有的功能之类的。我可以初始化一个提示词列表，也能验证列表被更新了，但它总是重置为空，即使我没有关闭标签页甚至没有离开页面——比如提交一个新提示词去评估后，它仍然会检测到 session state 是空的。

所以我决定直接用本地 JSON 文件来实现，你可以在 Github 上的 get_prompts、render_prompt 和 add_prompt 函数中看到具体实现。

如果你要构建一个更全面的工具，可能需要研究 st.experimental_user 来为每个用户建立独立的缓存，而不是使用全局缓存。这个功能是为 Streamlit 云托管设计的，但如果你研究一下 streamlit-authenticator，应该也能找到支持其他认证方式的方法。

结束思考

总的来说，我确信这类“个人 LLM 工具”会在未来一两年内以多种可用形式出现，但我不太确定它们是否会比自己动手搭建的更好，尤其是在定制化方面。这里唯一需要反驳的是 ChatGPT plugins，它们非常有趣，很可能代表了那种几乎无法在本地沙箱中自行构建或交互的工具——我们拭目以待！

同样有趣的是观察这类内部工具在公司内部 LLM 投入中的实际表现。根据我在行业中观察到的，我预计大多数对 LLM 有实际需求的公司都会在内部构建类似的东西。我相当确信，自托管的 LLM 工具存在真实用例，这可能是一个有趣的创业想法，但在一个已经有很多创业公司扎堆的领域创业风险很高，我几乎肯定会选择其他方向。 （如果你正在构建这类东西、正在寻找天使投资，并且目标是打造 LLM 工具而不是兜售“LLM 魔法”，我很感兴趣。）
