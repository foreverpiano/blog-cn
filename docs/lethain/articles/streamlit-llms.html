代码见 lethain/llm-explorer。

一个基于文本的 LLM 笔记工具（带 Prompt 历史记录），一个基于电子表格的 LLM 笔记工具。

LLM 与电子表格（又称可编辑数据框）

接下来，我们尝试为 LLM 创建一个电子表格界面。目标是让你创建一个表格，然后针对每一行单独运行 LLM。例如，你可能在每一行有一个邮件，想用某个 Prompt 去测试它。

我最初希望使用 st.data_editor（在 这篇博客 中介绍）来动态创建和编辑电子表格。这几乎可行——你可以添加行，但无法添加或删除列。我相信可以想办法实现，但为了简单起见，我决定允许你上传 CSV 来填充表格，初始上传后可以再添加或删除行，我们可以使用 st.file_uploader 来实现。

我创建了 pages/spreadsheet.py，总共约 50 行 Python 代码，你可以在 Github 上看到。

我用最近一篇 Planning 博客文章中的 如何作为工程高管进行规划 的子集进行了测试，我认为这个界面相当不错。我把 Google Sheet 导出为 CSV，上传后，就能用 st.data_editor 删除不想看到的行（操作稍显不直观：选中一行后再点击删除按钮）。之后，我可以针对每一行运行 Prompt，从中提取数据。

我得承认，我选择的这批数据其实非常不适合这种分析，但你可以想象它在其他类型的数据上会表现更好，例如根据电子表格中人员的相关信息，自动生成外联邮件。

记录之前的 Prompt

回到 main.py，我想看看把之前的 Prompt 保存在左侧边栏会有多难，这让我开始尝试 session-state。我在本地开发中完全无法让 session state 正常工作。很可能这是“Streamlit cloud”专属的功能之类的。我能够初始化一个 Prompt 列表，验证列表已被更新，但它总是重置为空，即使我没有关闭标签页甚至没有离开页面——比如提交一个新的 Prompt 去评估后，它仍然会检测到 session state 是空的。

因此，我决定直接用本地 JSON 文件来实现，你可以在 Github 上的 get_prompts、render_prompt 和 add_prompt 中看到实现。

如果你要构建一个更全面的工具，可能需要研究 st.experimental_user 来创建每个用户的缓存，而不是全局缓存。这个功能是为 Streamlit 的云托管设计的，但我想如果你研究一下 streamlit-authenticator，应该也能找到与其他认证机制配合使用的方法。

结束思考

总的来说，我确信这类“个人 LLM 工具”在未来一两年内会以多种易用的形式出现，但我不太确定它们是否会比自己动手构建的更好，尤其是在定制化方面。这里唯一的反例是 ChatGPT Plugins，它们非常有意思，很可能代表了那种几乎不可能在本地沙盒中自行构建或交互的工具——我们拭目以待！

同样有趣的是，看看这类内部工具在那些正在大力投入 LLM 的公司内部会如何发展。根据我在行业中观察到的情况，我预计大多数对 LLM 有实际需求的公司都会内部构建类似的东西。我相当确信，自托管的 LLM 工具存在真实的市场，这可能是一个有趣的创业想法，但在一个已经有很多初创公司扎堆的领域创业风险确实不小，我几乎肯定会选择其他方向。（如果你正在构建类似的东西、正在寻找天使投资，并且目标是构建 LLM 工具而非兜售“LLM 魔法”，我很感兴趣。）
