史诗般的 PyObjC 教程（三）：浏览、缓存与指示器

2008-08-25 · 阅读原文

欢迎来到 Epic PyObjC 教程系列的第三部分。本系列旨在对 PyObjC 以及 OS X Leopard 上的 Cocoa 进行全面深入的介绍。在上一期我们学习了 Cocoa Bindings 和 metaweb.py 之后，这次我们将探讨应用程序开发中几个常见的任务：读写磁盘数据、处理双击事件，以及使用 NSProgressIndicator 来提升用户体验。

如果你还没有跟上本项目的进度，可以在这里下载当前的项目状态。

双击在浏览器中查看

我们要做的第一件事是让 MetaWindow 在 NSTableView 的某一行被双击时，自动在浏览器中加载对应的页面。为此，我们需要为 tableView 和 array controller 都添加 IBOutlets。我们需要 tableView 来调用它的 setDoubleAction_ 和 setTarget_ 方法，同时需要 array controller 来获取当前选中的行。

但你可能会问：MWController 已经把搜索结果保存在它的 results 字段里了。如果我们直接询问 tableView 当前高亮的是哪一行，那就不需要去查询 array controller 了！可惜，我只能带着一丝无奈的微笑回答——尽管直觉并非如此——在我们的场景下这种做法并不能正常工作。如果你点击表格的某一列标题，就可以按字母顺序或逆序对列进行排序，但 results 字段中的数据并不知道这些变化。这些排序操作全部由 array controller 处理，因此只有 array controller 才真正知道数据对应的位置。

接下来进入代码部分！

现在我们只需要设置 table view，让它在被双击时调用 open_ 方法。在 Cocoa 开发中，进行一次性初始化的最佳时机是在类的 awakeFromNib 方法中。awakeFromNib 会在 nib 文件中序列化的对象被实例化时调用。由于我们在 MainMenu.xib 文件（这是应用程序的主 nib 文件，会在启动时加载）中有一个 MWController 的实例，因此该实例在程序启动时会调用它的 awakeFromNib 方法。

MWController 的 awakeFromNib 方法实现如下：

def awakeFromNib(self):
    if self.tableView:
        self.tableView.setTarget_(self)
        self.tableView.setDoubleAction_("open:")

你不一定非要检查 self.tableView 是否已经初始化（它几乎肯定已经初始化了），但正如我叔叔常说的：乐观地生活，谨慎地写代码。1

将结果缓存到磁盘

接下来我们要为 metaweb.py 返回的结果添加一个简单的缓存层。它包含两种相对简单的情况，我们现在来分别考虑：处理有缓存的搜索，以及处理没有缓存的搜索。

  1. Handling a cached result.When the search button is clicked, we want to check a manifest of cached items (a dictionary with the search term being the key and a 2-tuple of a filename and a timestamp).For a cached result, the manifest will contain the key, and thus we'll be returned a 2-tuple. First, we'll verify that the timestamp isn't more than a day old. If it is that old, we'll discard the cached value and proceed as if there was no cached value.Otherwise, if it isn't older than a day, then we'll update the value of MWController's results field with the cached data, which we will load in from disk using the filename in the 2-tuple.
  2. Handling an uncached result.When we search for an uncached result, we first verify it isn't in the cache, then retrieve it using metaweb.py, then we cache the newly retrieved result. Afterwards we treat it like a cached result.

为了支持这些情况，我们需要创建一个持久化的缓存清单，在程序关闭时保存到磁盘，并在程序启动时从磁盘加载。你还记得我们在 MetaWindowAppDelegate 中实现的 applicationDidFinishLaunching_ 和 applicationWillTerminate_ 方法的空壳吗？现在终于要用到它们了。

关于 PyObjC 中序列化选项的简短说明。

Python 的 Pickle 模块可能是你见过的最简单的数据序列化方式。当然，你也可以在 Cocoa 中通过实现 NSCoder 类的方法实现类似功能，但那需要编写多得多的代码。

然而，Pickle 无法序列化继承自 NSObject 的对象。这意味着它无法序列化任何 Cocoa 或 Objective-C 类。这虽然不方便，但通常可以找到变通方法。

最简单的解决办法是将对象转换为原生的 Python 类型。例如，如果你处理的是 NSMutableDictionary，只需将其转为 Python 的 dict 进行序列化（反序列化时再转换回 NSMutableDictionary）。

不过，如果最终你发现自己要处理一个特别大或复杂的继承自 NSObject 的类，可能还是应该直接使用 NSCoder。毕竟你那些花哨的 workaround 最终可能会变得过于复杂，那时再切换到 NSCoder反而更麻烦，所以还不如提前为未来的自己省点事。

另外请记住，还有 Core Data 和 SQLite 等其他持久化数据方案，它们提供了不同于传统序列化的替代方式。

在 Xcode 中打开 MetaWindowAppDelegate.py。在文件顶部添加对 pickle 和 os 的 import。

import pickle,os
from Foundation import *
from AppKit import *

现在我们要把原有的 applicationDidFinishLaunching_ 方法桩替换为以下实现：

def applicationDidFinishLaunching_(self, sender):
    try:
        path = self.pathForFile('cache.serialized')
        file = open(path,'r')
        self.cache = pickle.load(file)
        file.close()
    except IOError:
        self.cache = {}

现在当 MetaWindow 启动时，它会尝试从 ~/Library/Application Support/MetaWindow 目录下加载 cache.serialized 文件。如果该文件存在，就使用其中的内容作为缓存，否则使用一个空字典作为缓存。

我们还需要确保在程序关闭时保存 self.cache。为此我们要修改 applicationWillTerminate_ 方法。

def applicationWillTerminate_(self,sender):
    path = self.pathForFile('cache.serialized')
    file = open(path,'w')
    pickle.dump(self.cache,file)
    file.close()

现在我们的缓存就能在程序启动和关闭之间持久保存了。保存并关闭 MetaWindowAppDelegate.py，然后打开 MWController.py。

我们在 MWController 中要做的第一件事，是创建一个用于从应用委托获取缓存的 property。程序启动时的初始化顺序可能比较诡异，因此最好等到真正需要缓存时再从 app delegate 获取，而不是在程序启动那一刻就去请求。

在 MWController.py 文件头部，我们要添加对 pickle、md5、datetime 的 import，同时还要导入 AppKit 中的所有内容，最终看起来是这样的：

import objc, metaweb, webbrowser, pickle, md5, datetime
from AppKit import *
from Foundation import *

在 MWController 中添加 _cache 字段，初始值为 None，代码如下：

class MWController(NSObject):
    tableView = objc.IBOutlet()
    textField = objc.IBOutlet()
    arrayController = objc.IBOutlet()
    results = []
    _cache = None

然后我们需要通过下面的代码创建 property，将其加入到 MWController 中。

def getCache(self):
    if _cache is None:
        _cache = NSApp.delegate().cache
    return _cache
cache = property(getCache,None,None,"Cache of searches.")

这是我们第一次使用 NSApp，它是 Cocoa 提供的一个快捷方式，指向当前应用程序。它相当于 Python 中的 NSApplication.sharedApplication() 或 Objective-C 中的 [NSApplication sharedApplication]。

我们刚才编写的代码创建了一个名为 cache 的只读 property。Python 的 property 是使用访问器和修改器的语法糖，在这里使用它可以让我们惰性地从 app delegate 获取缓存，而不会把代码弄得乱七八糟。

关于 Objective-C 中修改器（mutators）和访问器（accessors）的简短说明。当你阅读或编写 Objective-C 代码时，会遇到比 Python 一辈子能见到的还要多的访问器和修改器。这是一种非常实用的模式，尤其适合实现惰性初始化或动态值。

除了这种模式本身的实用性之外，它在 Objective-C 中频繁出现还有另一个原因：一个对象可以拥有同名的字段和方法（即字段和方法处于不同的命名空间）。这是受 Smalltalk 启发的方法调用语法带来的副产品，它能清楚地表明你是在访问字段还是调用方法：

[myObject name];
myObject.name;

不幸的是，随着 Objective-C 2.0 的出现，这种区分在一定程度上被模糊了。Apple 在 ObjC 2.0 中引入了与 Python property 非常相似的属性语法，现在已经无法从 myObject.name 这段代码判断它到底是在访问一个字段，还是在调用一对访问器/修改器。

新语法的支持者认为，如果你正确地封装了类并且不依赖具体实现细节，那么这种区分就无关紧要。但守旧派仍然为失去的优雅而哀叹，直到今天，他们仍会在 Objective-C 1.0 的“坟墓”前摆满鲜花。

或者至少在博客文章里缅怀一番。

现在让我们创建一个从缓存中获取对象的方法。如果缓存的数据太旧，它应该假装没有数据，以避免数据过期。

def getCachedSearch(self,searchString):
    if self.cache.has_key(searchString):
        filename,timestamp = self.cache[searchString]
	age = datetime.datetime.now() - timestamp
        if age > datetime.timedelta(days=1):
            return None
        filepath = NSApp.delegate().pathForFile(filename)
        file = open(filepath,'r')
        data = pickle.load(file)
        file.close()
        return data
    return None

得益于 datetime 模块提供的功能，验证数据年龄变得非常简单。接下来我们需要创建一个用于缓存新结果的方法。

def cacheResultsForSearch(self,searchString,results):
    filename = u"%s.cached" % md5.md5(searchString).hexdigest()[12:]
    filepath = NSApp.delegate().pathForFile(filename)
    file = open(filepath,'w')
    pickle.dump(results,file)
    file.close()
    self.cache[searchString] = (filename,datetime.datetime.now())

注意我们是将结果保存到一个单独的文件中，然后把文件名（以及创建时间）存入缓存清单。我们也可以简化这个设计，直接把结果存到缓存里，但那样我们就必须始终把所有结果都保存在内存中。

修改 MetaWindow 的最后一步是对 search_ 方法做一些调整。

@objc.IBAction
def search_(self,sender):
    search_value = self.textField.stringValue()
    cached = self.getCachedSearch(search_value)
    if cached is None:
        cached = metaweb.search(search_value)
        self.cacheResultsForSearch(search_value,cached)
    self.results = [ NSDictionary.dictionaryWithDictionary_(x) for x in cached]
    self.arrayController.rearrangeObjects()

记住我们不能用 pickle 来序列化 Objective-C 对象，因此我们要特别注意：缓存的是 Python 数据，然后在使用前再将其转换为 NSDictionary 对象以供 tableView 使用。

在完成缓存功能之前，我们还有最后一个小细节需要处理。

目前看来，缓存的文件永远不会被删除，尽管我们并不想把它们保留超过一天。让我们回到 MetaWindowAppDelegate.py，改进一下 applicationWillTerminate_ 方法。

首先在文件头部添加对 datetime 的 import。

import os,pickle,datetime
from Foundation import *
from AppKit import *

然后找到 applicationWillTerminate_ 方法。我们需要剔除所有超过一天的结果。在解释器中尝试一下，很快就能找到解决方案。

>>> today = datetime.datetime.now()
>>> yesterday = today - datetime.timedelta(days=1)
>>> today < yesterday
False
>>> two_days_ago = datetime.datetime.now() - datetime.timedelta(days=2)
>>> two_days_ago < yesterday
True

因此我们将 applicationWillTerminate_ 修改为如下形式：

def applicationWillTerminate_(self,sender):
    yesterday = datetime.datetime.now() - datetime.timedelta(days=1)
    for key in self.cache:
        filename,createdTime = self.cache[key]
        if createdTime < yesterday:
            filepath = self.pathForFile(filename)
            os.remove(filepath)
            del self.cache[key]

在搜索时为 NSProgressIndicator 添加动画

本部分我们要处理的最后一件事是让搜索体验更有响应性。目前当你搜索未缓存的结果时，可能需要几秒钟才能完成，而在这期间搜索按钮会一直保持按下状态，让人感觉程序像是卡住了。

如果能有一些明确的指示，告诉用户确实正在处理，那就好得多了。

现在给 MWController 添加另一个 IBOutlet，命名为 indicator。

class MWController(NSObject):
    tableView = objc.IBOutlet()
    textField = objc.IBOutlet()
    arrayController = objc.IBOutlet()
    indicator = objc.IBOutlet()
    results = []
    _cache = None

接着在 Interface Builder 中打开 MainMenu.xib。从 Library 窗口中找到 Circular Progress Indicator，将它拖到 Window (Window) 窗口中。调整文本框的大小，以便让进度指示器能放在左上角。

然后点击 MainMenu.xib (English) 窗口中的 Controller 对象，按住 Control 键，从 Controller 拖动到我们刚刚创建的圆形进度指示器上。松开鼠标后，从弹出菜单中选择 indicator 来连接这个 IBOutlet。

最后保存文件，回到 MWController 类。现在我们要稍微修改一下 search_ 方法。具体来说，我们要让它在开始从 Metaweb 获取数据之前启动指示器的动画，并在数据获取完成后停止动画。

@objc.IBAction
def search_(self,sender):
    search_value = self.textField.stringValue()
    cached = self.getCachedSearch(search_value)
    if cached is None:
        self.indicator.startAnimation_(self)
        cached = metaweb.search(search_value)
        self.cacheResultsForSearch(search_value,cached)
        self.indicator.stopAnimation_(self)
    self.results = [ NSDictionary.dictionaryWithDictionary_(x) for x in cached]
    self.arrayController.rearrangeObjects()

保存、构建并运行程序。现在它应该会在搜索时显示动画，用户再也不用纠结程序是否卡死了。
