双击在浏览器中查看

我们要做的第一件事是让 MetaWindow 在 NSTableView 的某一行被双击时，在浏览器中加载相应的页面。为此，我们需要为 tableView 和 array controller 添加 IBOutlets。我们需要 tableView 来调用其 setDoubleAction_ 和 setTarget_ 方法，同时需要 array controller 来确定当前选中的行。

但你可能会问，MWController 已经把搜索结果保存在它的 results 字段中了。如果我们直接询问 tableView 当前高亮的是哪一行索引，那就不需要查询 array controller 了！可惜，我只能带着一丝忧伤的微笑回答你——尽管直觉相反——这种做法在我们的场景中行不通。如果你点击 tableView 的某一列标题，就可以按字母正序或倒序重新排列内容，但 results 字段中的数据对此一无所知。这些排序操作全部由 array controller 处理，因此只有 array controller 才真正知道数据对应的是哪一行。

现在我们只需要设置 tableView，让它在被双击时调用 open_ 方法。在 Cocoa 开发中，进行一次性初始化设置的最佳时机是在类的 awakeFromNib 方法中。awakeFromNib 会在 nib 文件中序列化的对象被实例化时调用。由于我们在 MainMenu.xib 文件（这是应用程序的主 nib 文件，会在启动时加载）中有一个 MWController 实例，因此该实例在程序启动时会调用其 awakeFromNib 方法。

MWController 的 awakeFromNib 方法实现如下：

def awakeFromNib(self):
    if self.tableView:
        self.tableView.setTarget_(self)
        self.tableView.setDoubleAction_("open:")

你不一定非要检查 self.tableView 是否已经初始化（它几乎肯定已经初始化了），但正如我叔叔常说的：乐观地生活，谨慎地写代码1。

将结果缓存到磁盘

接下来我们要为 metaweb.py 返回的结果添加一个简单的缓存层。它包含两种相对简单的情况，我们现在来分析一下：处理有缓存的搜索，以及处理没有缓存的搜索。

处理缓存结果。当搜索按钮被点击时，我们要检查一个缓存清单（一个字典，以搜索词作为键，对应一个包含文件名和时间戳的二元组）。如果结果已被缓存，清单中就会有对应的键，我们会得到一个二元组。首先验证时间戳是否超过一天。如果超过一天，我们就丢弃缓存的值，像没有缓存一样继续处理。否则，如果没有超过一天，我们就用缓存的数据更新 MWController 的 results 字段，这些数据会根据二元组中的文件名从磁盘加载。处理未缓存结果。当我们搜索一个未缓存的结果时，首先确认它不在缓存中，然后使用 metaweb.py 获取数据，接着把新获取的结果存入缓存。之后我们将其当作缓存结果来处理。

为了支持这些情况，我们需要创建一个持久化的缓存清单，在程序关闭时保存到磁盘，并在程序启动时从磁盘加载。你还记得我们在 MetaWindowAppDelegate 中实现的 applicationDidFinishLaunching_ 和 applicationWillTerminate_ 方法存根吗？现在终于要用上它们了。

关于 PyObjC 中序列化选项的简短说明。

Python 的 pickle 模块可能是你见过的最简单的数据序列化方式。当然，你也可以在 Cocoa 中通过实现 NSCoding 协议的方法实现类似功能，但代码量要多得多。

然而，pickle 无法序列化继承自 NSObject 的对象。这意味着它无法序列化任何 Cocoa 或 Objective-C 类。虽然不方便，但通常可以绕过去。

最简单的解决办法是将对象转换为原生的 Python 类型。例如，如果你处理的是 NSMutableDictionary，只需把它转成 Python 的 dict 再序列化（反序列化时再转回 NSMutableDictionary）。

不过，如果最终你发现自己要处理一个特别大或复杂的继承自 NSObject 的类，可能还是应该直接使用 NSCoding。最终你那些取巧的方案会变得足够复杂，以至于使用 NSCoding 反而更简单，所以不如现在就为未来的自己节省些时间。

请记住，还有其他持久化数据的方案，比如 Core Data 和 SQLite，它们提供了不同于传统序列化的替代方式。

在 Xcode 中打开 MetaWindowAppDelegate.py。在文件顶部添加对 pickle 和 os 的导入。

import pickle,os
from Foundation import *
from AppKit import *

现在我们要把原有的 applicationDidFinishLaunching_ 方法存根替换为以下内容：

def applicationDidFinishLaunching_(self, sender):
    try:
        path = self.pathForFile('cache.serialized')
        file = open(path,'r')
        self.cache = pickle.load(file)
        file.close()
    except IOError:
        self.cache = {}

现在当 MetaWindow 启动时，它会尝试从 ~/Library/Application Support/MetaWindow 目录下加载 cache.serialized 文件。如果文件存在，就使用其中的内容作为缓存，否则就使用一个空字典作为缓存。

我们还需要确保在程序关闭时保存 self.cache。为此我们要修改 applicationWillTerminate_ 方法。

def applicationWillTerminate_(self,sender):
    path = self.pathForFile('cache.serialized')
    file = open(path,'w')
    pickle.dump(self.cache,file)
    file.close()

现在我们的缓存就能在程序多次启动和关闭之间持久化了。保存并关闭 MetaWindowAppDelegate.py，然后打开 MWController.py。

我们在 MWController 中要做的第一件事，是创建一个属性来从应用程序委托获取缓存。启动时的各种事情可能以奇怪的顺序发生，因此更稳妥的做法是等到真正需要缓存时再从 app delegate 获取，而不是在程序刚启动时就去请求。

在 MWController.py 文件头部，我们要添加对 pickle、md5、datetime 的导入，同时还要导入 AppKit 中的所有内容，最终会变成这样：

import objc, metaweb, webbrowser, pickle, md5, datetime
from AppKit import *
from Foundation import *

给 MWController 添加 _cache 字段，初始值为 None，让它看起来像这样：

class MWController(NSObject):
    tableView = objc.IBOutlet()
    textField = objc.IBOutlet()
    arrayController = objc.IBOutlet()
    results = []
    _cache = None

然后我们需要创建这个属性，将以下代码添加到 MWController 中。

def getCache(self):
    if _cache is None:
        _cache = NSApp.delegate().cache
    return _cache
cache = property(getCache,None,None,"Cache of searches.")

这是我们第一次使用 NSApp，它是 Cocoa 的一个快捷方式，指代当前应用程序。它等价于 Python 中的 NSApplication.sharedApplication() 或 Objective-C 中的 [NSApplication sharedApplication]。

我们刚刚编写的代码创建了一个名为 cache 的只读属性。Python 的 property 是一种非常方便的语法糖，用于访问器和修改器，这里使用它可以让我们懒加载缓存，而不会让使用代码变得杂乱。

关于 Objective-C 中修改器和访问器的简短说明。当你阅读（或编写）Objective-C 代码时，你会遇到比一生中写 Python 代码时多得多的访问器和修改器。这是一种非常实用的模式，尤其适合实现懒加载或动态值。

除了这种模式本身的实用性之外，它在 Objective-C 中频繁出现还有一个原因：一个对象可以拥有同名的字段和方法（即字段和方法处于不同的命名空间）。这是受 Smalltalk 启发的方法调用语法带来的副作用，这种语法能清晰地表明你是在访问字段还是调用方法：

[myObject name];
myObject.name;

不幸的是，随着 Objective-C 2.0 的到来，这种区分在一定程度上被模糊了。Apple 在 ObjC 2.0 中引入了与 Python 属性非常相似的属性语法，现在已经无法从 myObject.name 这段代码判断它引用的是一个字段，还是一个伪装成访问器/修改器对的方法。

新语法的支持者认为，如果你正确封装了类并且不依赖具体实现细节，这种区分就无关紧要。但老一辈的开发者仍然为失去的优雅而哀叹，直到今天，他们还会在 Objective-C 1.0 的“墓前”献上鲜花。

或者至少是写几篇博客文章。

现在让我们创建一个从缓存中获取对象的方法。如果缓存的数据太旧，它应该假装没有存储任何数据，以避免数据过期。

def getCachedSearch(self,searchString):
    if self.cache.has_key(searchString):
        filename,timestamp = self.cache[searchString]
	age = datetime.datetime.now() - timestamp
        if age > datetime.timedelta(days=1):
            return None
        filepath = NSApp.delegate().pathForFile(filename)
        file = open(filepath,'r')
        data = pickle.load(file)
        file.close()
        return data
    return None

得益于 datetime 模块提供的功能，验证年龄变得非常简单。现在我们需要创建一个方法来缓存新的搜索结果。

def cacheResultsForSearch(self,searchString,results):
    filename = u"%s.cached" % md5.md5(searchString).hexdigest()[12:]
    filepath = NSApp.delegate().pathForFile(filename)
    file = open(filepath,'w')
    pickle.dump(results,file)
    file.close()
    self.cache[searchString] = (filename,datetime.datetime.now())

注意我们是将结果保存到一个单独的文件中，然后把文件名（以及创建时间）存放在缓存清单中。我们可以简化这一步，直接把结果存放在缓存里，但那样我们就必须始终把所有结果都保存在内存中。

修改 MetaWindow 的最后一步是稍微更新一下 search_ 方法。

@objc.IBAction
def search_(self,sender):
    search_value = self.textField.stringValue()
    cached = self.getCachedSearch(search_value)
    if cached is None:
        cached = metaweb.search(search_value)
        self.cacheResultsForSearch(search_value,cached)
    self.results = [ NSDictionary.dictionaryWithDictionary_(x) for x in cached]
    self.arrayController.rearrangeObjects()

记住我们不能用 pickle 序列化 Objective-C 对象，因此我们谨慎地缓存 Python 数据，在用于 tableView 之前再将其转换为 NSDictionary 对象。

在搜索时为 NSProgressIndicator 添加动画

本部分我们要处理的最后一件事是让搜索体验更具响应性。目前，当你搜索未缓存的结果时，可能需要几秒钟才能完成，而搜索按钮在这段时间内会一直处于按下状态，让人感觉程序好像卡住了。

更好的做法是提供一些明确的指示，告诉用户确实正在进行处理。

现在给 MWController 添加另一个 IBOutlet，命名为 indicator。

class MWController(NSObject):
    tableView = objc.IBOutlet()
    textField = objc.IBOutlet()
    arrayController = objc.IBOutlet()
    indicator = objc.IBOutlet()
    results = []
    _cache = None

接着在 Interface Builder 中打开 MainMenu.xib。从 Library 窗口找到“Circular Progress Indicator”，把它拖到 Window (Window) 窗口中。调整文本字段的大小，以便进度指示器能放在左上角。

然后点击 MainMenu.xib (English) 窗口中的 Controller 对象，按住 Control 键，从 Controller 拖动到我们刚刚创建的圆形进度指示器上。松开鼠标，然后在弹出的菜单中选择 indicator 来连接这个 IBOutlet。

最后保存文件，回到 MWController 类。现在我们要稍微修改一下 search_ 方法。具体来说，我们要在开始从 Metaweb 获取数据之前启动指示器的动画，并在数据获取完成后停止动画。

@objc.IBAction
def search_(self,sender):
    search_value = self.textField.stringValue()
    cached = self.getCachedSearch(search_value)
    if cached is None:
        self.indicator.startAnimation_(self)
        cached = metaweb.search(search_value)
        self.cacheResultsForSearch(search_value,cached)
        self.indicator.stopAnimation_(self)
    self.results = [ NSDictionary.dictionaryWithDictionary_(x) for x in cached]
    self.arrayController.rearrangeObjects()

保存、构建并运行程序。现在它应该会在搜索时为指示器添加动画，用户也不用再纠结程序是否卡死了。
