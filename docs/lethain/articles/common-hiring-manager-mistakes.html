招聘经理常见的一些错误

2020-08-02 · 阅读原文

关于招聘有很多可说的，我也写过不少相关内容。但过去几周和几位朋友聊天时，我意识到有一件事我还没写过，那就是新手招聘经理经常会犯的错误或遇到的挑战，有时他们会因此感到困扰。

如果你刚开始考虑招聘，请先关注你的 你的招聘漏斗（招聘漏斗）；但如果你发现招聘正面临挑战，不妨想想自己是否正陷入以下这些问题之一。

无法做出“是”或“否”的决定。对候选人犹豫不决是我在新手招聘经理身上看到的最常见错误。到了某个阶段，你必须做出决定，而且往往是在信息相当不完整的情况下做决定。及时做出录用（或不录用）的决定并处理后续结果，要好过无限期地处于悬而未决的状态。如果你按照面试流程走完后仍无法决定，那就明确告知候选人不会继续推进，这样他们也能继续寻找其他机会。 面试流程过于随意。针对招聘经理的优柔寡断，一个常见的应对方式是临时新增面试，试图获取更多信号。这些通常是之前从未有过、之后也不会再有的临时面试。未经过校准的面试会成为偏见的载体，虽然它可能帮助你获得信心，但这种信心并不基于特别可靠的基础。 在评估特定候选人时，尽量基于已有的信息做出决定。然后再跨候选人进行分析，以 坚持政策，而非例外。（找出政策或流程改进点），从而下次获得更好的信号。 将候选人长时间置于停滞状态。当招聘经理无法做决定时，他们常常试图拖住候选人，等待其他候选人完成流程。偶尔放慢面试节奏是完全合理的——尤其是在你为新职位面试前一两个候选人时——但如果频繁这样做，会给候选人和内部招聘团队带来大量困惑。这常常导致糟糕的候选人体验，也会浪费招聘人员或招聘经理的时间来维持候选人的部分参与度。 给候选人一个明确的时间表，如果没能按时完成，就诚实地更新情况：“我们仍然对你很感兴趣，但我们想至少再面试一位其他候选人，以确保我们做了正确的选择。”他们可能会感到恼火并退出，但如果你不告诉他们，其他做法只会更糟。 不清楚自己在招什么。新职位的前几次面试总是校准期，面试内容和流程在早期应该经常调整。然而，随着推进，调整的范围应逐渐缩小。如果你发现自己仍在不断做出剧烈改变，例如原本要招 Staff Engineer，最后却决定要招 Technical Program Manager 之类的，那就说明你很可能没有花足够时间思考这个职位的真正需求。 前期花时间确保招对职位，会带来多倍回报。投入比看起来合理的时间更多，然后，再投入更多。 招聘小组之间缺乏校准。有时候招聘经理很清楚自己在招什么，但其他参与面试的人并不认同这种愿景。这常常导致经理和面试小组得出完全相反的录用决定，并削弱大家对整个流程的信心。 花时间向每位面试官解释你要招聘的职位是什么、为什么重要、他们将要承担的具体工作，以及你认为成功所需的技能。如果这个职位与表面相似的其他职位差异很大，也要花时间解释在这个职位上哪些方面不如其他招聘流程那么重要。 寻找独角兽。追求优秀候选人是美德，但去追逐那些基本上不存在、或者你无法提供足够激励让他们加入的候选人，就是浪费所有人的时间。很多招聘一开始都是招聘伙伴花很长时间试图让招聘经理明白他们定义的职位有多么不现实，而这在很大程度上是可以避免的。 一开始可以雄心勃勃，但要根据候选人的兴趣频繁重新校准。如果你真的需要一个特别稀缺的候选人，那就不要指望用大量招聘的方式来获得他们，而应该更接近于高级领导职位的招聘方式。 绝望。如果你面临很大压力需要快速招聘，而团队已经开始无法完成承诺，那么就很难不录用眼前这位候选人，即使你知道他不是合适的人。你会说服自己他是合适的人，即便换成别人做招聘经理，你一眼就能看出他不合适。 解决办法是尽量从一开始就避免彻底落后。尽管如此，如果你已经落后了——谁没有过呢？——那么诀窍就是不要听信脑海里那个让你忽略其他面试官顾虑的声音。 追逐背景。如果不太确定如何评估候选人，很容易就把评估权交给他们之前的机构。他们是否在 FANG 公司工作过？是否来自常春藤盟校？这就是招聘版的“没人会因为买 IBM 而被炒鱿鱼”。这是一个可以自圆其说的选择，但显然也不是特别出色的选择。虽然很多有学术或机构背景的人很优秀，但我职业生涯中遇到过最难共事的人里，也有不少拥有同样背景——这种相关性并不高到可以依赖，而且这些人通常也是最难说服、成本最高昂的候选人。 对招聘伙伴不回应。绝大多数招聘人员都是按照季度目标来工作的，要么是发出 offer 的数量，要么是 offer 被接受的数量。如果你作为招聘经理不及时给他们反馈，他们就无法合理地继续优先处理你的招聘需求。他们的工作绩效在很大程度上取决于你是否给予良好支持，而及时回应正是这种支持中最重要的部分。 临时抱佛脚的面试问题。很常见的情况是，面试流程设计得很好、结构也很清晰，但却要依赖每位面试官自己临时想问题！这使得跨候选人评估变得非常困难，也会导致问题难度高到在规定的面试时间内根本不可能完成。（几乎每一道编程面试题的初始版本，如果没有提前知道问题，都需要花费三倍于规定时间才能完成。） 照搬前公司的流程。根据自己过去有效的经验来设计面试流程和方法是完全合理的。有些招聘经理的问题在于，即使漏斗数据已经明确显示这种做法行不通，他们仍然拒绝偏离以前有效的方式。这通常有几个不同原因。 首先，招聘经理可能并不清楚之前公司流程真正有效的某些关键因素，比如背后有一个庞大的招聘运营团队在做校准等工作。其次，往往是因为两家公司本质上不同。在 FANG 有效的做法，在一家 A 轮公司未必有效，反之亦然。 只招聘容易说服的候选人。人们很容易把自己的价值观和感受投射到候选人身上，并假设某些人不可能被说服加入团队。其中一种表现是，新手招聘经理认为有经验的人绝不会为自己工作，并立即把他们筛选掉。当你还是新手招聘经理时，恰恰是最需要有经验的人加入团队的时候，所以要克服这种不适，尝试去招聘那些你认为可能从你这里学不到太多东西的人。 把薪酬例外当成常规。根据我的经验，面试流程存在缺陷的最好指标就是频繁出现薪酬例外。这既是因为我个人不喜欢例外驱动的体系，也因为这类升级流程往往比设计良好的常规路径要慢得多且不一致。 如果你发现自己经常需要申请薪酬例外，那就应该花些时间思考一下，是自己与一个运转良好的体系存在错位，还是这个体系本身就不太有效。

当然，令人兴奋的是，你可能还会犯下无数其他错误，但如果你能避开这些，那你已经做得相当不错了。不过，最终衡量你成功与否的最好方式，还是你的招聘漏斗和留存指标，而非我这些模糊的安慰。）
