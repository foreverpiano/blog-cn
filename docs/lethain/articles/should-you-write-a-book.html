应该写一本技术书还是管理书？

2021-11-17 · 阅读原文

自从我的第二本书《Staff Engineer》出版以来，越来越多的人来向我咨询出版方面的建议。我曾在自主出版《Staff Engineer》和写书让我学到的东西中分享过自己写书的经历，但这两篇文章都没有直接回答大家最常问的两个问题：“我应该写一本书吗？”以及“我该如何出版一本书？”

我应该写一本书吗？

当人们问我这个问题时，我首先会建议：只有当你认为自己会享受写书的过程时，才应该去写。实现你的目标总有比写书更直接的途径。我的第二个建议是，你需要先回答一个相当明确的问题：“你写书的目标是什么？”

对于我听到的每一种常见目标，通常都存在比写书更直接的解决办法：

“增加未来机会”。未来的机会取决于你的个人信誉和（也就是那些会全力推荐你、而不仅仅是泛泛认识你的人）。一本不错的书确实能提升信誉，但对拓展人脉帮助不大。更直接的提升信誉和人脉的方式是。如果直接提升个人信誉，参加公开演讲、写几篇高质量博客，或者在 First Round Review 这类平台上发表文章会更加有效。“推动行业发展”。要推动行业进步，需要让行业内的人真正读到你的作品，而这离不开有效的营销和分发计划。与出版商合作能提供一些帮助，但大部分工作仍需自己完成。同样，更直接的途径依然是写博客和公开演讲。写四篇优秀的博客文章所花的时间远少于写一本好书，而且在博客中融入反馈和建议、将其从“好”提升到“优秀”也容易得多。“获得额外的收入来源”。自出版的书籍可以带来可观的收入。《Staff Engineer》上市八个月的销售额就轻松超过了我作为软件工程师的第一份工资，但大多数书的收入都更低，且销售主要集中在出版后的前六个月。书籍可以通过间接方式（如为咨询业务带来潜在客户）赚到不少钱，但作为直接赚钱的手段，效率并不高。如何寻找工程领导职位四十年的职业生涯

如果书籍这种形式仍然吸引你，你也是一位有经验的写作者，而且上述理由并没有让你打退堂鼓，那就尽管去写吧！需要记住的是，默认的行业惯例会把你推向写一本两三百页的书，但你完全可以写一本更短的书。让你的目标来引导写作方式，而不要过于纠结所谓的规范。

当然，如果你和出版商合作，情况就不一定这么简单了，这就引出了下一个话题。

我该如何出版一本书？

大多数没有出版经验的人都以为，选择自出版还是与出版商合作是出版流程中最后才要做出的决定之一。但实际上，这是最早就需要决定的关键事项之一。在和有意向的作者交流时，我最有价值的工作之一，就是尽早让他们意识到这一点。

出版商有一套完整的出书流程，他们会让你按照这个流程走。即使你已经写完了书，他们还是会让你走完整个流程，结果很可能需要对书稿进行大幅修改。如果你决定和出版商合作，应该带着一个清晰的概念和提纲去联系他们。他们评估你的选题的方式，和风险投资人评估初创公司非常相似：

你目标的读者群体是谁？这本书能为这个群体填补什么空白？这个群体目前有哪些现有书籍？它们卖得怎么样？你的书为什么会是一个有效的补充？你为什么是撰写这本书最合适的人选？你如何帮助这本书的营销工作变得更轻松？

如果这些问题让你觉得烦人，那你可能并不是真的想出版一本书。这些问题非常重要，即使你选择自出版一本能被广泛阅读的书，也同样需要回答它们。如果你选择自出版就是为了回避提前回答这些问题，那么请放心，你之后仍然需要面对这些问题以及其他一大堆具体的执行问题。我在自主出版《Staff Engineer》中详细记录了出版《Staff Engineer》的整个过程，其中涵盖了从营销到封面设计等各个方面。

我给大多数人的通用建议是：第一本书尽量尝试和出版商合作。关于写书有很多东西需要学习，和出版商合作能让你把更多精力放在写作（和反复修改）一本好书上，而不是分散到整个生态系统的各种事务上。这也能为你的个人品牌增添信誉，无论未来是否继续与出版商合作，都会对后续项目有所帮助。如果你无法获得出版商的兴趣，那么完全可以选择自出版，但要做好经历一段学习曲线的心理准备。

关于写书当然还有更多话题可以聊，但如果你对上面这两个核心问题都有清晰、扎实的答案，我相信其他问题都会自然而然地得到解决。
