JSON、面向对象的视图，以及开始做一个真正的应用

2008-06-22 · 阅读原文

欢迎来到 Wielding Django 的第三期，由 Will Larson 友情主持。正如我在第一期中所承诺的，这一期适合已经使用过 Django 的开发者。我们将简要介绍 JSON 和面向对象的视图，然后开始构建一个真正（虽然很小）的应用。

我们会用到 django-webapp 中的一些代码，这是一个我为 Web 应用开发总结的代码和设计模式集合。我从中抽取了一些作为代码片段，但最方便的方式还是直接获取全部代码：

svn checkout http://django-webapp.googlecode.com/svn/trunk/ django-webapp

JSON

上一次我们只返回了一个原始数字，但返回更结构化的数据也很简单。我们可以使用 XML，但它在某些实现中显得笨重且缓慢。快速、轻量级编码的非官方标准是 JSON，而在 Python 中生成 JSON 非常容易。下面是上次的 compute 函数，现在改成返回 JSON。

from dwa.serialize import JsonResponse
def compute(request, op):
import operator
operation = getattr(operator, op)
a = float(request.GET['a'])
b = float(request.GET['b'])
result = operation(a, b)
return JsonResponse(dict(
op=op, a=a, b=b,
result=operation(a, b)))

对于大多数包含多个元素的字典，我更喜欢使用 dict(abc=de) 这种写法。它不需要给 key 加引号，而且这也是关键字参数的通用写法，我个人非常喜欢。但它的效果和 {'op': op, 'a': a} 等写法完全相同。

dwa.serialize 是 django-webapp 的一部分，同时也是代码片段 801（它需要代码片段 800）。而 JsonResponse 只是进行 JSON 编码，然后把结果包装成一个 HttpResponse。（默认情况下，它会在结果外包裹 JavaScript 注释以保证安全；大多数 JavaScript 框架都能处理这种情况。）请注意，JSON 的顶层对象必须是一个 dict（甚至不能是数组）。

但还有一种更简单的方法。Django 支持“中间件”（middleware），它提供了一组钩子，可以介入请求和响应的各个处理环节。我们可以拦截响应处理过程，在必要时自动进行 JSON 编码。这正是代码片段 803 所做的事情（它同样包含在 django-webapp 中）。要启用该中间件，请在 settings.py 中添加以下内容：

MIDDLEWARE_CLASSES = (
    'dwa.middleware.JsonEncodingMiddleware', # Keep this last!
    )

这样你的视图就可以直接返回 dict，它们会被自动编码为 JSON。

Ajax 错误中间件

如果服务器在处理 AJAX 请求时发生错误，即使是可靠的 Firebug 也很难看清真实的错误信息。因此你可能希望添加 AjaxErrorMiddleware 来解决这个问题。我的 MIDDLEWARE_CLASSES 配置如下：

MIDDLEWARE_CLASSES = (
    'dwa.middleware.AjaxErrorMiddleware',
    'dwa.middleware.JsonEncodingMiddleware',
    )

请记住要把 JsonEncodingMiddleware 放在最后，这样它才能最先处理视图返回的内容。

面向对象的视图

Django 的视图本质上就是一个可调用对象，它接收一个 HttpRequest 作为第一个参数。那么什么样的对象符合条件呢？

1. 函数：

def my_view(request, **kwargs)

2. 类：

class MyView(YourView):
    def __call__(self, request, **kwargs):
         return super(MyView, self)(request, **kwargs)

3. 实例方法：

class MyResource(Resource):
    def list(self, request):
        return {'contents': list(self.queryset)}

可能还有其他我没想到的形式。总之，Django 的教程（包括本系列）通常从视图函数开始。有时视图类会被当作更高级的技术。我还没在其他地方见过有人使用实例方法作为视图，但我发现它非常有用，所以在这里专门介绍一下。

几点说明：

1. 我们干净地分离了这个 API 相关的所有 URL 模式。对于更通用的解决方案，我们可能需要添加一个 prefix 参数，以便轻松修改 API 的挂载路径。我们甚至可以子类化 Django 内部的 URL 解析器，但它并不是为了便于扩展而设计的。

2. 实际的计算逻辑（perform_operation）与 Web 接口（compute）被清晰分离，因此你可以独立地对其中任何一个进行子类化。下面是一个无厘头的例子：

class HtamAPI(MathAPI):
    def perform_operation(self, op, a, b):
        return super(HtamAPI, self).perform_operation(op, a, b)
urlpatterns = HtamAPI().url_patterns()

一个真正的 Web 应用

本系列接下来的内容将致力于把这些想法发展成快速应用开发的有用技术。但为了让我保持诚实，我们应该做一些比简单数学更有挑战性和趣味性的东西。而且它不能是又一个博客、wiki 或 reddit 克隆……

于是我决定做一个简化版的应用，这个应用我已经想开发很久了。我热爱上帝的话语，因为它向我显明祂是谁（祂真的非常美好！）以及我是谁。我经常非正式地背诵其中的部分内容，因为在很多情况下回忆这些经文都很有帮助。但我常常会忘记某些词句，或者记不清一段经文的具体位置，所以我想要一个能帮助我复习的工具。它需要能在任何地方使用，因此这个工具的最佳实现形式本来应该是打孔卡……好吧，那就用 HTML、CSS、JavaScript、DOM、DHTML、JSON、AJAX、Django 这些 Web 应用流行词汇来实现吧。

只要提到“上帝”就会让很多人情绪激动，无论持何种观点。如果你确实有话想说，（a）请先想清楚再发帖，（b）请发到我的博客上。因此在 Will 的博客上，我们还是把注意力集中在 Django 本身。
