在 Google App Engine 上部署 django-springsteen

2009-03-05 · 阅读原文

（可在此查看 django-springsteen 的在线示例。）

（此外，我已大幅简化了在 Google App Engine 上部署 django-springsteen 的流程，如另一篇文章所述，但你仍应阅读本文以了解如何定制 Springsteen。）

Vik Singh 几个月前率先在 Google App Engine 上运行了 Yahoo! BOSS，但 django-springsteen 与 BOSS Mashup Framework 有着本质不同，因此希望你能原谅其中少许重复的内容。

本文将逐步介绍如何利用 Springsteen 内置的对 Yahoo! BOSS、Twitter 和 Amazon 的支持，快速部署一个颇有趣味的搜索引擎。整个过程应该不会超过半小时。

首先注册一个新的 Google App Engine 应用。我使用 djangosearch 这个名字，因为我在第一次写那个糟糕的 Yahoo! BOSS on GAE 教程时就已经注册了它。看来我并没有陷入固定模式什么的。从 GitHub 检出 django-springsteen 的源码：git clone git://github.com/lethain/django-springsteen.git django-springsteen 接下来我们要从 django-springsteen 的仓库中提取一些有用的部分，针对我们的新需求进行调整，并丢弃其余内容。mv django-springsteen/example_project/ ./djangosearch mv django-springsteen/springsteen/ djangosearch/ rm -rf django-springsteen 接着我们需要从 djangoproject.com/download/ 获取最新版的 Django tarball。tar -xvf Django-1.0.2-final.tar mv Django-1.0.2-final/django/ ./ rm -rf Django-1.0.2-* rm -rf django/bin django/contrib/admin django/contrib/auth rm -rf django/contrib/databrowse django/test rm -rf django/contrib/admindocs django/contrib/gis （我们需要删除这些文件以符合 Google App Engine 每个应用不超过 1000 个文件的限制。你也可以通过压缩文件的方式绕过此限制，但这种方法相对更简单。）实际上，django-springsteen 除了在部分模板中使用 safe 过滤器之外，几乎可以和 Django 0.96 兼容。如果你愿意把这些过滤器去掉，那么就可以跳过安装更新版本的 Django。接下来我们需要从针对 Google App Engine 的 django_example 中提取几个文件。首先创建 djangosearch/main.py 文件，内容如下：import logging, os, sys # Google App Engine imports. from google.appengine.ext.webapp import util # Remove the standard version of Django. for k in [k for k in sys.modules if k.startswith('django')]: del sys.modules[k] # Force sys.path to have our own directory first, in case we want to import # from it. sys.path.insert(0, os.path.abspath(os.path.dirname(__file__))) # Must set this env var before importing any part of Django os.environ['DJANGO_SETTINGS_MODULE'] = 'settings' import django.core.handlers.wsgi def main(): # Create a Django application for WSGI. application = django.core.handlers.wsgi.WSGIHandler() # Run the WSGI CGI handler with that application. util.run_wsgi_app(application) if __name__ == '__main__': main() 接下来创建 djangosearch/app.yaml 文件。（请将 djangosearch 替换为你注册的应用名称。）application: djangosearch version: 1 runtime: python api_version: 1 handlers: - url: /static static_dir: static - url: /.* script: main.py 最后是 djangosearch/index.yaml：indexes: # AUTOGENERATED # This index.yaml is automatically updated whenever the dev_appserver # detects that a new type of query is run. If you want to manage the # index.yaml file manually, remove the above marker line (the line # saying "# AUTOGENERATED"). If you want to manage some indexes # manually, move them above the marker line. The index.yaml file is # automatically uploaded to the admin console when you next deploy # your application using appcfg.py. 接下来打开 djangosearch/local_settings.py，在文件末尾添加以下内容：ROOT_URLCONF = 'urls' MIDDLEWARE_CLASSES = ( 'django.middleware.common.CommonMiddleware', 'django.middleware.doc.XViewMiddleware', ) INSTALLED_APPS = ('springsteen',) DATABASE_ENGINE = None DATABASE_NAME = None CACHE_BACKEND = "dummy:///" 创建 djangosearch/boss_settings.py 文件，其中仅包含 BOSS_APP_ID 参数，如果你有的话还可以加上 AMAZON_ACCESS_KEY。（如果你想要 Amazon 搜索结果并从中获得佣金，需要在这里和这里注册以获取 AWS Affiliate ID，这算是开箱即用的 Springsteen 服务中最缺乏创意的变现方式。）BOSS_APP_ID = "abcdefghijlknop" 修改 djangosearch/urls.py 文件，移除所有对 example_project 的引用，并删除多余的 URL 模式：from django.conf.urls.defaults import * urlpatterns = patterns('', (r'^$', 'views.search'), ) 休息一下。让我们为新的搜索引擎选一个主题。嗯……嗯……好吧，我们来做一个专注于苹果产品的搜索引擎。能出什么问题呢？接下来配置我们的搜索结果。打开 djangosearch/views.py，先把所有内容清空。然后添加以下导入语句：from springsteen.views import search as default_search from springsteen.services import Web, TwitterLinkSearchService, AmazonProductService from django.conf import settings 接着创建我们的 Amazon 商品服务（如果你有 Amazon Affiliates AWS 密钥的话）：class ComputerAmazonSearch(AmazonProductService): _access_key = settings.AMAZON_ACCESS_KEY _topic = 'apple' 然后创建一个苹果主题的 Twitter 服务：class AppleTwitterService(TwitterLinkSearchService): _qty = 3 _topic = 'apple' 最后我们只需要混合来自 Yahoo! BOSS 的网页搜索结果，并把我们的新搜索引擎暴露出去：def search(request, timeout=2500, max_count=10): services = (ComputerAmazonSearch, AppleTwitterService, Web) return default_search(request, timeout, max_count, services) 简短警告 请注意，当你在本地测试 springsteen 应用时，Yahoo! BOSS 的搜索结果将无法成功获取。但一旦你将应用推送到生产环境，结果就能正常获取。我会研究一个补丁来解决这个问题，不过不必惊慌。此时我们已经让一切正常工作了，但搜索结果只是简单地堆叠在一起。当然，你或许喜欢把那些 Amazon 联盟链接放在最上面，但用户可能并不喜欢。现在是时候稍微接触一下相关性了。你肯定希望最相关的结果能浮到顶部（可以开个冒泡排序的玩笑），但简单地把不同来源的结果堆叠起来，无法实现这一点，除非来源 A 的所有结果都比来源 B 更相关，来源 B 的所有结果都比来源 C 更相关，以此类推。让我们尝试一个非常简单的相关性算法来解决这些问题。你可以把相关性方法分为两类：根据结果自身价值打分，我们可以称之为内在相关性（intrinsic relevance）。根据结果之间的相互关系打分，我们可以称之为上下文相关性（contextual relevance）。我们在这里将两者结合使用。首先提升标题中包含查询词的结果，其次对来自已出现过的域名的第 2 至第 N 个结果进行惩罚。将以下代码放在 views.py 中 search 函数的上方：def ranking(query, results): query = query.lower() def rank(result): score = 0.0 title = result['title'].lower() if title in query: score += 1.0 return score scored = [(rank(x), x) for x in results] scored2 = [] domains = {} for score, result in scored: domain = result['url'].replace('http://','').split('/')[0] times_viewed = domains.get(domain, 0) new_score = score + times_viewed * -0.1 scored2.append((new_score, result)) domains[domain] = times_viewed + 1 scored2.sort() return [ x[1] for x in scored2 ] 然后更新 search 函数以使用这个排名函数：def search(request, timeout=2500, max_count=10): services = (ComputerAmazonSearch, AppleTwitterService, Web) return default_search(request, timeout, max_count, services, {}, ranking) 现在我们的结果会使用上面的 ranking 函数进行排序。这是一种相当基础的相关性处理方式，但希望能展示基本概念。现在我们的搜索引擎已经可以运行了，是时候定制网站的模板了。首先在 djangosearch 目录下创建一个 templates 文件夹，以及 templates/springsteen 子文件夹，并创建几个空文件：cd djangosearch mkdir templates templates/springsteen touch templates/base.html touch templates/springsteen/base.html 然后编辑 templates/base.html 文件：<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" "http://www.w3.org/TR/html4/strict.dtd"> <html> <head> <title>{% block title %}FruitySearch{% endblock %}</title> <link rel="stylesheet" type="text/css" href="/static/css/reset.css"> <link rel="stylesheet" type="text/css" href="/static/css/search.css"> </head> <body> <div id="body"> <div id="hd"><h1><a href="/">FruitySearch</a></h1></div> {% block body %}{% endblock %} <div id="ft"><p>A <a href="">Your-Name-Here</a> production, 2009.</p></div> </div> </body> </html> 接着编辑 templates/springsteen/base.html（这个文件非常简短）：{% extends "base.html" %} {% block body %}{% endblock %} 当你继续定制搜索结果的外观时，可能需要覆盖 templates/springsteen/results.html，但目前它应该是一个合理的默认模板。创建一些 CSS 来美化网站：cd djangosearch mkdir static static/css 当前的 base.html 假设你会有 reset.css 和 search.css 文件。最近我倾向于使用 YUI 的 reset.css，然后为 search.css 编写了一些自定义样式。测试一切是否正常：cd djangosearch dev_appserver.py ./ 如果一切正常，就可以将其部署到 Google App Engine 上，你就完成了。

一些注意事项

你会发现默认情况下无法翻页超过 3-4 页。这是因为 Springsteen 中的一个安全机制，当你对接大量数据源时它很有意义，但当你实际上只使用一个数据源时就显得有些烦人。你可以在 local_settings.py 中覆盖这个设置，添加以下一行：# allow up to 10 pages SPRINGSTEEN_MAX_MATCHES = 10 此外，目前这个配置没有使用任何缓存，因此在翻到较后面的页数时（例如显示第 100-110 条结果）效率会很低。在 GAE 上是可以使用 memcache 的，我会在未来一两天内写一个补丁，让 Springsteen 能够利用这项功能。
