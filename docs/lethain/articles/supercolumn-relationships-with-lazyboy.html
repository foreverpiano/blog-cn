SuperFamily 与 Lazyboy 的关系

2010-05-23 · 阅读原文

最近我开始研究 Cassandra 及其 Python 客户端 lazyboy。虽然文档写得相当不错，但我还是自己动手把玩了一阵子，并阅读了部分源码，才真正理解它（当然，我是否真的理解了，还请亲爱的读者指正，如果我只是达到了理解的某个高原期）。

我一向认为实践是最好的学习方式，那就让我们来构建一些东西吧。

建模我们的应用

对于这个项目，我决定做一个简单的开发团队任务管理系统。

我们的系统会有很多成员。

p1 = {"first": "Jack", "last":"Bauer", "role":"developer"}
p2 = {"first": "Lindsay", "last":"Lohan", "role":"product-manager"}

我们的系统也会有很多任务。

t1 = {"name":"Prevent Nuclear Bomb Plot", 
      "estimated-hours":"24",
      "completed-hours":"23"}
t2 = {"name":"Resurrect Career",
      "estimated-hours":"4000",
      "completed-hours":"0"}

每个任务会有零个或多个成员参与。

# Sometimes I find myself typing snippets to maintain consistency even
# though they aren't actually coherent or helpful.
# I'm having trouble finding the delete key right now.
t1.people.append(p1)
t1.people.append(p2)

基于这些关系，我们很可能需要支持以下操作：

获取所有成员、获取所有任务、获取特定成员、获取特定任务、获取正在处理某个特定任务的成员。

那么，我们该如何在 Cassandra 中建模呢？其实非常简单，只需遵循这条基本规则：

每种文档类型对应一个 ColumnFamily，同时每种文档之间的关系也对应一个 ColumnFamily。

（ColumnFamily 是一组相似文档的集合。同一 ColumnFamily 中的文档不必拥有完全相同或相似的键/值，但通常这样做能简化你的应用，尤其是当你需要遍历数据时。）

将这条规则应用到我们的应用中，我们有两种类型的文档：

tasks 和 members，

此外它们之间存在一种关系：

一个任务由零个或多个成员负责。

换句话说，我们需要三个 ColumnFamily。

接下来我们先安装 lazyboy 和 Cassandra，然后再进入具体的实现环节。

现在前提条件都已满足，我们可以开始……配置了。

配置并启动 Cassandra

接下来我们需要为项目配置合适的 Cassandra 设置。虽然 Cassandra 不强制要求遵守严格的 schema，但在启动 Cassandra 进程之前，必须预先定义每个 ColumnFamily。

更准确地说，这与其说是“定义”，不如说是“声明它的存在”。打开 ~/Library/cassandra/conf/storage-conf.xml 文件，将 <Keyspaces/> 标签内的现有内容替换为以下内容：

<Keyspaces>
 <Keyspace Name="TaskManager">
  <ColumnFamily CompareWith="UTF8Type" Name="Task"/>
  <ColumnFamily CompareWith="UTF8Type" Name="Member"/>
  <ColumnFamily CompareWith="UTF8Type" Name="TaskMember"/>
  <ReplicaPlacementStrategy>org.apache.cassandra.locator.RackUnawareStrategy</ReplicaPlacementStrategy>
  <ReplicationFactor>1</ReplicationFactor>
  <EndPointSnitch>org.apache.cassandra.locator.EndPointSnitch</EndPointSnitch>
 </Keyspace>
</KeySpaces>

现在，启动 Cassandra。

~/Library/cassandra/bin/cassandra

使用 lazyboy

现在各个组件都已安装并配置完毕，我们需要编写代码来使用 lazyboy。（如果你觉得下面这部分有点难懂，可以先看看 lazyboy 的 README 和示例代码。）

对于我们的每一个 Column Family（Task、Member、TaskMember），都需要继承三个类：

a = TaskKey("my-task-a")

a = Key("TaskManager", "Task", "my-task-a")

t1 = Task()
t2 = Task().load(TaskKey("my-task-a")

t1 = Record()
t1.key = Key("TaskManager", "Task", "my-task-a")
t2 = Record().load(Key("TaskManager", "Task", "my-task-a")
lazyboy.key.Key 的子类，这样就能把 写成 虽然不是必须的，但这是一个很方便的小模式。 lazyboy.record.Record 的子类，用于访问某个 ColumnFamily 中的元素，结合 TaskKey 类就能写成 而不是原来的形式。 Record 的子类还可以要求在保存列之前必须提供某些字段（稍后我们会深入讨论）。 lazyboy.View 的子类，用于遍历某个 ColumnFamily 中的条目。

Task 的三个子类如下所示：

class TaskKey(Key):
    def __init__(self, key=None):
        Key.__init__(self, "TaskManager", "Task", key)
class Task(record.Record):
# note that we're requiring these two keys for each column
# in the Task ColumnFamily
_required = ('name','desc')
def init(self, args, **kwargs):
record.Record.init(self, args, **kwargs)
self.key = TaskKey()
class TaskView(View):
def init(self):
View.init(self)
self.key = TaskKey(key="row_a")
self.record_class = Task
self.record_key = TaskKey()

Member 和 TaskMember 也需要创建相同的类，具体代码可以在源代码中查看。

创建和操作单个 Column

现在我们已经创建了所有类，可以开始用它们与 Cassandra 交互了。假设我们要创建一个 key 为 my-project-a 的新 Task。

>>> from tasks import *
>>> t = Task()
>>> t.key = TaskKey("my-project-a")
>>> t.update({"name":"My Project A", "desc":"Build A project"})
Task: {'name': 'My Project A', 'desc': 'Build the critical A project'}
>>> t.save()
Task: {'name': 'My Project A', 'desc': 'Build the critical A project'}

注意这里我们显式指定了 key，但这并不是必需的。如果不指定，系统会为你生成一个随机 key。

>>> t = Task()
>>> t.key
{'column_family': 'Task', 
 'keyspace': 'TaskManager',
 'super_column': None, 
 'key': 'cff715a0f7cf4f5bb78e70cab6bcd867'}

保存 Task 之后，我们就可以随时检索它。

>>> t2 = Task().load(TaskKey("my-project-a"))
>>> t2
Task: {'name': 'My Project A', 'desc': 'Build the critical A project'}

它像字典一样可以获取特定值，也支持用字典语法进行更新。请注意，必须调用 save 方法才能将数据更新到 Cassandra 中。

>>> t2['name']
'My Project A'
>>> t2['name'] = "A newer project"
>>> t2
Task: {'name': 'A newer project', 
       'desc': 'Build the critical A project'}
>>> t2.save()
Task: {'name': 'A newer project', 
       'desc': 'Build the critical A project'}

最后，我们还可以删除这个任务。

>>> t2.remove()
Task: {}
>>> Task().load(TaskKey("my-project-a"))
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "/Library/Python/2.6/site-packages/Lazyboy-0.7.5-py2.6.egg/lazyboy/record.py", line 184, in load
    columns = iterators.slice_iterator(key, consistency)
  File "/Library/Python/2.6/site-packages/Lazyboy-0.7.5-py2.6.egg/lazyboy/iterators.py", line 50, in slice_iterator
    raise exc.ErrorNoSuchRecord("No record matching key %s" % key)
lazyboy.exceptions.ErrorNoSuchRecord: No record matching key {'column_family': 'Task', 'keyspace': 'TaskManager', 'super_column': None, 'key': 'my-project-a'}

通过上面的例子，你已经掌握了足够的信息，可以把 Cassandra 当作一个简单的键值存储来使用。但仅仅局限于键值存储不足以开发某些类型的应用，幸运的是 Cassandra 提供了更多功能。

获取多个 Column

除了获取特定的 key，我们还可以遍历 ColumnFamily 中的所有 key。为了简化示例，我们假设已经定义了下面这个函数：

def add_member(username, first, last):
    m = Member()
    m.key = MemberKey(username)
    m['first'] = first
    m['last'] = last
    m.save()
    mv = MembersView()
    mv.append(m)

特别注意最后两行，我们显式地将新 Member 添加到 MembersView 中。这一步至关重要，它决定了后续操作能否正确检索到该成员。

现在让我们尝试遍历 Member columns。

>>> members = (('a','a','last_f'),
...                ('b','b','last_c'),
...                ('c','c','last_d'),
...                ('d','d','last_e'),
...                ('e','e','last_a'),
...            ('f','f','last_b'))
>>> 
>>> for member in members:
...         add_member(member[0], member[1], member[2])
... 
>>> len(MemberView())
6
>>> for m in MemberView(): print m
... 
Member: {'last': 'last_f', 'first': 'a'}
Member: {'last': 'last_c', 'first': 'b'}
Member: {'last': 'last_d', 'first': 'c'}
Member: {'last': 'last_e', 'first': 'd'}
Member: {'last': 'last_a', 'first': 'e'}
Member: {'last': 'last_b', 'first': 'f'}

不仅如此，我们还可以通过指定起始 key 来遍历某一段 columns：

>>> mv = MemberView()
>>> mv.start_col = "c"
>>> for m in mv: print m
... 
Member: {'last': 'last_d', 'first': 'c'}
Member: {'last': 'last_e', 'first': 'd'}
Member: {'last': 'last_a', 'first': 'e'}
Member: {'last': 'last_b', 'first': 'f'}

你可能会认为应该有办法指定迭代的结束范围，确实有，不过目前需要一点技巧（这可能是 API 设计上的一个小疏忽，我写完这篇文章后会尽快提交一个补丁）。

>>> mv = MemberView()
>>> for a in mv._cols("c", "e"): print a
... 
Column(timestamp=1274654073, name='c', value='c')
Column(timestamp=1274654073, name='d', value='d')
Column(timestamp=1274654073, name='e', value='e')

至此，我们已经从单纯把 Cassandra 当作键值存储，提升到了能够遍历整个或部分 key 的范围。

管理关系

实现我们总体计划的最后一步，是存储分配给某个特定 Task 的 Member 列表。最简单的做法可能是直接在 Task 里存一个逗号分隔的 key 列表，但随着写入量的增加，这种方式会变得不可靠，因为 Cassandra 在冲突时不会合并值，而是以最后一次写入为准。（我知道这个解释有点模糊，但我一直没能找到简洁的说明方式，所以我打算另写一篇文章详细讨论，而不是在这篇文章里勉强展开。）

更好的做法是使用一个新的 ColumnFamily（对我们来说就是 TaskMember）来存储这些关系。对于每个 Task，我们还会创建一个具有相同 key 的 TaskMember，用它来保存与 Member 的关联。

首先我们来创建一些成员和一个 Task，同时创建一个与 Task 拥有相同 key 的 TaskMember。

>>> from tasks import *
>>> add_member("will", "will", "larson")
>>> add_member("bill", "bill", "fakename")
>>> add_member("jill", "jill", "lastnamehere")
>>> Task().update({"name":"Web App 1", 
         "desc":"We will build a fantastic web applicaiton"}).save()
>>> t.key
{'column_family': 'Task', 'keyspace': 'TaskManager', 
 'super_column': None, 'key': '52a6c23e1afd480991e2232f5e7d9ba8'}
>>> t.key.key
'52a6c23e1afd480991e2232f5e7d9ba8'
>>> tm = TaskMember()
>>> tm.key = TaskMemberKey(t.key.key)
>>> tm.save()
TaskMember: {}
>>> tv = TaskView()
>>> tv.append(t)

现在我们把 Will 和 Jill 添加到这个任务中，而让 Bill 独自留在外面。

>>> tm = TaskMember().load(TaskMemberKey(t.key.key))
>>> will = Member().load(MemberKey("will"))
>>> will.key.key
'will'
>>> tm[will.key.key] = 1
>>> jill = Member().load(MemberKey("jill"))
>>> tm[jill.key.key] = 1
>>> tm.save()

是的，我们所做的只是为每个要加入项目的用户添加一条新的 key/value。更自然的写法如下：

>>> tm.update({"will":1, "jill":1}).save()
TaskMember: {'will': '1', 'jill': '1'}

然后你可以直接获取它并遍历，查看当前分配给该任务的成员：

>>> tm = TaskMember().load(TaskMemberKey(t.key.key))
>>> for a in tm: print a
... 
will
jill

这就是全部内容了。现在我们已经能处理关系、键值存储以及范围迭代。使用这些基础工具，你几乎可以构建任何想构建的东西。
