使用迭代淘汰赛来进行时间线权衡

2019-05-25 · 阅读原文

多年以前，我曾在一间小会议室里，面对两扇关不严的大玻璃门。那些错位的门缝不断漏出越来越高的争执声，涌入开放式办公区，而里面的人则拼命假装没听见这些从门后传出的争吵。

当时我正试图调解两个团队在从 Facebook Ads API 收集数据的方式上产生的分歧。这个 API 能提供所需的数据，但无法给出足够细粒度的时间序列变化，而我们需要这样的数据作为预算再平衡算法的输入。

一个团队想构建一个基于新型 DSL 的 API 抽象层，让大家能够描述自定义爬虫来遍历 API，并搭建专门的基础设施定期抓取指定的数据；这是一种创新的方法，但到目前为止还没能获得多少支持。另一个团队则希望采用硬编码的爬虫策略，虽然扩展性不强，但几乎可以立刻完成。

我本想写一篇文章，介绍当时用来平息争执、让大家达成一致的降温策略，但那次调解进行得相当糟糕——所以我写不出那篇文章——不过我却从中获得了一个此后频繁依赖的想法，那就是迭代淘汰赛。

迭代淘汰赛是一种竞争机制，你必须赢得当前轮次才能晋级下一轮。如果无法获胜，就不能继续比赛。如果你为下一轮准备了绝佳策略，但在当前轮次表现不佳，就永远不会有机会施展那个策略。如果你今天有很好的做法，却对明天毫无规划，那你的未来只会充满遗憾。

这个模型之所以如此有效，是因为它能迫使你（1）明确不同时间尺度上的成功是什么样子，（2）为不断变化的需求选择一系列演进的应对方案。

我一直都在使用这个心智模型！
