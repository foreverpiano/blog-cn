JVM 是“下一代的汇编语言”吗？我希望不是。（转载）

2007-06-04 · 阅读原文

本文移植自原《Irrational Exuberance》博客，写于2007年中期：距今已近两年。

原文标题是“Is Java the 'next assembly'?”。一两年前有人指出，用 JVM 比 Java 更准确。亡羊补牢，为时未晚，对吧？

最近我研究了不少构建在 JVM 之上的语言，并思考它们吸引人的地方。本来打算写一篇文章，分析这些语言与 Java 互操作时所需的代码，但写完后发现文章质量很差，于是放弃了。取而代之的是，我开始思考这些语言所面临的困难、它们给我们程序员带来的价值，以及它们将如何融入编程语言的发展周期。

基于 JVM 的语言的优势

可以直接使用 Java 类库

随着 JVM 改进，性能可“免费”提升

JVM 的劣势

某些语言与 Java 混用效果很差

SISC Scheme

Jython

Jython 的代码和我们在 CPython 中预期的大致相同，只是操作从其他地方导入的一些对象。相当简洁，也容易理解：很直观。而 SISC Scheme 的代码几乎让我大脑宕机。它强行把 Scheme 扭曲成一种过程式语言，我觉得完全不直观，用起来也十分困难（我多次无法成功用初始值对其进行初始化）。举这两个例子的目的是想说明：每种语言在设计时都带有特定的技术和范式，如果一门语言和 Java 的设计范式不同，那么两者大概率会成为奇怪的组合。此外，那些在面向对象概念和实现上差异很大的语言，在兼容性上也会吃亏（比如原型、泛型等等）。

Java 技术本身排除了某些功能

执行速度通常更差（但并非总是如此）

应用程序分发变得更加复杂

不可避免的怪异特性
