在 django-springsteen 中对搜索结果进行重排序

2009-02-26 · 阅读原文

接昨天的文章，本文简要介绍如何在 django-springsteen 中对搜索结果进行重排序，并说明它如何能够对来自多个数据源的结果进行一致的分页。

（你可以在 GitHub 上获取 springsteen 的源代码。）

自定义结果排序

如果你曾经尝试调整搜索相关性（尤其是在大型或多样化的数据集上），你很可能深有体会：对结果进行重排序正是问题的核心所在。

这就是为什么 springsteen 提供了一个简单的钩子来重新排序结果，并且默认采用简单的堆叠方式，而不是试图替你重新排序。你最了解自己的数据，因此应该由你自己来调整其排序。

下面是一个简单（但存在缺陷）的重新排序搜索结果的示例。

from springsteen.views import search
from springsteen.services import Web, Images
import random
def scatter_results(query, results):
random.shuffle(results)
return results
def scattered_search(request)
services = (Images,Web)
return search(request, services=services,
reranking_func=scatter_results)

这就是最简单的可以想到的重排序函数。但它存在一个小问题：对同一批数据连续运行两次排序函数会得到不同的排序结果，这使得可预测的分页变得不可能。

这就引出了一个良好重排序算法的唯一要求：对于相同的数据，它必须返回相同的排序结果。也就是说，排序必须是一致的。结果在不同日期甚至不同小时之间是否一致并不重要，但重排序算法必须保持一致性，才能实现可预测的分页。

你对分页中的“噪声”（同一结果出现在多个页面上）越不介意，你的重排序算法就可以越灵活。

要理解 springsteen 如何实现跨分页的一致排序，我们需要稍微 detour 一下，看看 springsteen 中分页的具体实现细节。

跨数据源的一致分页

最简单的分页场景是获取第 1 条到第 N 条结果。为此，springsteen 会向每个服务请求 N 条结果，将它们合并在一起，对结果调用任何已注册的重排序函数，然后返回前 N 条结果。

我们把从所有服务获取的 N 条结果（或服务所能提供的最接近 N 的数量）称为一个批次（batch）。因此，如果我们有 5 个服务，每个服务都获取了 N 条结果，那么第一个批次就包含 5N 条结果。

这意味着从第一个批次中，我们拥有足够生成五页结果的原始数据。因为用户只请求了前 N 条结果，所以我们按照自己的意愿对其进行重排序，然后返回重排序后的前 N 条。

现在，如果用户请求第 N 条到第 2N 条结果，我们会再次向所有数据源请求 N 条结果，再次进行重排序，然后返回第 N 到 2N 条结果。这听起来可能有点低效，但 springsteen 会尝试缓存结果，因此浏览这五页内容只需要真正调用一次每个服务（前提是所有五页都在结果缓存的约 30 分钟内被显示）。

如果用户请求的结果超出了第一个批次的范围，情况就会变得复杂一些。为了获取这些结果，我们需要先获取第一个批次的结果并将其暂存，然后继续获取后续批次（同样暂存起来），直到所有批次的结果总数超过用户最终请求的结果位置。

然后，我们对每个批次分别执行重排序算法——仅处理那些落在用户请求的起始和结束结果范围内的批次。之后将这些批次合并（保持各自的顺序），再切取出用户请求的结果部分。必须对每个批次单独排序，才能实现结果的一致排序（从而支持可预测的分页）。

通过一个例子来看会比较直观。考虑以下代码：

>>> a = [1,5,2,7,8,9]
>>> b = [5,1,3,9,6]
>>> sorted(a) + sorted(b)
[1, 2, 5, 7, 8, 9, 1, 3, 5, 6, 9]
>>> sorted(a+b)
[1, 1, 2, 3, 5, 5, 6, 7, 8, 9, 9]

通过对批次独立进行重排序，我们会得到第一个结果；而如果把所有结果放在一起排序，则会得到第二个结果。

在第一页结果中，两种算法都会显示结果 1,2,5,7,9。在第二页，使用第一种算法（独立排序）会看到 1,3,5,6,9；而使用第二种算法（合并排序）则会看到 5,6,7,8,9,9。这意味着第二种算法在第二页提供了更差的结果，并且出现了重复结果。

关于分页的简短插曲到此结束。

一个一致的重排序算法

下面是一个一致的重排序算法的简单示例。它在提升搜索相关性方面并没有实际用途，但作为一个技术示例还是很有帮助的。

这个算法根据标题的长度对结果进行排序。

from springsteen.services import Web, Images

services = (Images,Web)

请记住，重排序在每个批次内部是一致的，批次之间也是相互一致的，但在某些结果集合中，你可能会同时看到一个批次的结尾和另一个批次的开头（对于像这个例子这样直观的可视化情况）会显得有些突兀。

在更实际的场景中，你可能会创建一个函数，为每条结果赋予一个分数，然后根据该分数进行排序。你可以从仅考虑来源开始，之后逐步加入发布日期（如果存在），并针对你的数据集不断调整优化。
