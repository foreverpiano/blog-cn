在 django-springsteen 中对结果进行重新排序

2009-02-26 · 阅读原文

接昨天的文章，这里简要介绍一下如何在 django-springsteen 中对搜索结果进行重新排序，以及它如何能够对来自多个数据源的结果进行一致的分页。

（你可以在 GitHub 上获取 springsteen 的源代码。）

自定义结果排序

如果你曾经尝试过调整搜索相关性（尤其是在大型或多样化的数据集合上），你很可能痛苦地意识到，对结果进行重新排序正是问题的核心。

这正是 springsteen 提供一个简单钩子来重新排序结果的原因，也是它默认采用简单的堆叠方式而非尝试替你重新排序的原因。你最了解自己的数据，因此应该由你自己来调整它的排序。

就是这样，最简单的可以想到的重新排序函数。但它有一个小问题：对同一批数据运行两次排序函数可能会返回不同的排序结果，这使得可预测的分页变得不可能。

这就引出了一个好的重新排序算法的唯一要求：对于相同的数据，它必须返回相同的排序。也就是说，排序结果必须是一致的。结果不需要在每天甚至每小时都保持一致，但重新排序算法必须足够一致，才能实现可预测的分页。

你对分页中的噪声（同一个结果出现在多个页面上）越不介意，你的重新排序算法就可以越灵活。

要理解跨分页的一致性排序是如何实现的，我们需要先 detour 一下，了解 springsteen 中分页的细节。

跨数据源的一致性分页

最简单的分页情况是获取第 1 条到第 N 条结果。为此，springsteen 会向每个服务查询 N 条结果，将它们合并在一起，对结果调用任何重新排序函数，然后返回前 N 条结果。

我们把来自所有服务的 N 条结果（或服务所能提供的尽量接近 N 条的结果）称为一个批次。因此，如果我们有 5 个服务，并且从每个服务获取了 N 条结果，那么我们的第一个批次就包含 5N 条结果。

这意味着从第一个批次中，我们有足够的数据来生成五页可供分页的结果。因为用户只请求了前 N 条结果，所以我们按照自己的意愿对其重新排序，然后返回重新排序后的前 N 条结果。

现在，如果用户请求第 N 条到第 2N 条结果，我们会再次向所有数据源查询 N 条结果，再次对其重新排序，然后返回第 N 到 2N 条结果。这可能感觉有点低效，但 springsteen 会尝试缓存结果，因此浏览这五页结果只需对每个服务请求一次（假设这五页结果是在结果被缓存的约 30 分钟内显示的）。

如果用户请求的结果超出了第一个批次的范围，情况就会变得复杂一些。为了获取这些结果，我们需要先获取第一个批次的结果，将其放在一边，然后继续获取后续批次（并同样放在一边），直到所有批次的结果总数超过用户最终请求的结果位置。

然后，我们对每个批次分别执行重新排序算法，这些批次的结果范围包含用户请求的起始和结束位置。接着我们将这些批次合并在一起（保持各自的顺序），并切出请求的结果。必须对每个批次单独排序，才能实现结果的一致性排序（从而支持可预测的分页）。
