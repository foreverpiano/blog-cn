使用 Fabric 部署 Django

2008-11-04 · 阅读原文

昨天我简单介绍了自己的开发到部署流水线，并简要提到了 Fabric。它是一个用 Python 编写的类似 Capistrano 的工具，能帮助我们摆脱部署过程中那些重复乏味的操作。

很长一段时间里，我都满足于通过 SSH 登录服务器手动操作的部署方式（我没有管理大型部署，通常只处理不需要搭建 staging 服务器的小型项目）。但自从尝过 Fabric 的甜头后，我就彻底上瘾了。我认为这是一种显著的改进——即使对于最简单的部署也是如此。

简而言之，我认为使用 Fabric（或类似工具）能带来实实在在的好处，原因如下：

你不需要离开自己的电脑。可以使用自己熟悉的工具、文件和环境设置。你只需输入一条命令就能完成整个部署。即使是简单的部署，你也常常需要输入一二十条 shell 命令（切换目录、从版本控制拉取代码、重启服务器等），而现在这些命令都不用再手动敲了。即使这看起来只是小小的提升，但我认为它的意义远不止于此，因为你可以在不打断编程流程的情况下完成部署。有了良好的部署方案，你只需编写一次，以后就可以反复运行，因此你更有可能按照正确的方式而不是快捷方式来做事。（重复导致无聊，无聊导致可怕的错误，可怕的错误让你又怀念起无聊的日子，然后情况就越来越糟了。）即使是其他开发者，哪怕一想到 Linux 管理就会冷汗直流，也能轻松进行部署和回滚。如果你再加一个五分钟就能搞定的图形界面，那连你奶奶都能帮你部署和回滚生产服务器了。通过将部署流程抽象成一个简单的部署脚本，你让其他人更容易帮你完成工作。这是一件好事。除非你担心这样显得自己在工作中不够忙碌，那你可能不会喜欢 Fabric。它也能很好地扩展到大型环境。

Fabric 和服务器之间的连接并不是持久的。这意味着你不能在多个命令中使用 cd 命令并期望它们生效。# 这样写符合预期 run("cd ~/git/$(repo)/; git pull $(parent) $(branch)") # 这样写会让第二个命令在错误目录下执行 run("cd ~/git/$(repo)/") run("git pull $(parent) $(branch)") Fabric 使用自己的一套字符串插值系统。用法如下：# 标准的 Python 字符串插值 run("git pull %s %s" % ("origin", "master")) # Fabric 的字符串插值 config.parent = "origin" config.branch = "master" run("git pull $(parent) $(branch)") Fabric 的这种方式更便于在不同命令之间传递状态。至少他们是这么说的。我不想过多为这种做法辩护，只是感觉他们应该是在绕过自身架构中的某个痛点。
