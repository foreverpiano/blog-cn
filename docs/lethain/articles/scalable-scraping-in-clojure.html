Clojure 中的可扩展抓取

2009-11-24 · 阅读原文

Craigslist 是个很棒的网站。它实在太棒了，以至于我听说有些人会花大量时间盯着它那源源不断的帖子。

想到这一点，我突然意识到，写一个监控帖子流并将相关帖子保存到本地的脚本，或许是一个很好的项目，可以用来练习用 Clojure 进行并发抓取和并发处理。

前置条件

在开始之前，你需要先

安装 Clojure（本教程基于 1.0 版本编写），安装 clojure-contrib（使用与 1.0 版本兼容的版本）。

如果你已经安装好了这些，那我们就可以开始了。如果你还没装好，那这篇教程会一直在这里等着你办完那些事儿再回来。

架构

从 Craigslist 拉取内容、解析它，然后把其中一部分写入磁盘的方式有很多。在这些方式中，有些简单直接。而这个方案不在此列。

本教程希望开发一种可扩展、可伸缩的方法，并着重强调并发处理。

系统被分为两个子组件：内容抓取（content retrieval）和内容处理（content processing）。两者通过一个共享队列进行通信（抓取端将数据放入队列，处理端从队列中取出数据）。首先，我们来看看内容抓取部分。

内容抓取的目标是将一个 Craigslist 分类列表转换成一个装满每个帖子元数据的队列。

抓取的流程是

拉取一个或多个 Craigslist 分类中的最新帖子，提取每个帖子的 URL，将这些 URL 提交给一个 worker agent 池，让 worker agents 去抓取 URL 并将抓取到的数据放入 post-queue。

接下来是系统的内容处理部分。

内容处理的目标是

从 post-queue 中取出帖子，使用用户定义的过滤器（过滤器是一组必需的关键词）将它们分到不同的桶里（一个帖子可能同时属于多个桶），然后将每个桶中的帖子写入单独的文件。

随着程序运行，这些过滤器对应的文件会不断增长，里面装满了满足对应主题要求的帖子。从此你再也不需要 obsessive 地刷新 Craigslist 了。

取而代之，你可以 obsessive 地去检查一系列文本文件。进步难道不伟大吗？

组装系统

我们正在构建的系统可以看作由两个独立的子组件组成：填充帖子队列，以及清空帖子队列。

我们将利用这种解耦，将两部分分别独立实现。在一个本来可以用 50 行脚本实现的功能上使用这种程度的解耦肯定是杀鸡用牛刀，但通过共享数据结构来解耦代码，正是团队软件开发中最困难的任务——定义接口——的一个特殊案例。

看起来所有接口要么只是对某种数据结构的操作（像 Dynamo 这样的键值存储本质上就是哈希表），要么可以被视为简单算法上的简单算法（大多数 Twitter API 可以被建模为对数组的过滤，尽管实际实现可能有所不同）。因此，慷慨的读者可以把这种解耦设计当作练习这项重要技能的机会。

我猜不那么慷慨的读者早就已经不看了。
