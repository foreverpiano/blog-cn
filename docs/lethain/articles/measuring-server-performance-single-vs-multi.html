单服务器与多服务器性能对比

2009-02-18 · 阅读原文

关于服务器架构的永恒争论之一，就是在提供动态 Web 应用时，到底是采用多服务器配置更好，还是单服务器配置更优。

我决定运行一些性能测试，用实际数据来为这场讨论提供一些参考。

测试条件

  1. Before each run of the data collection script the server was rebooted, but between each test nothing was done to the machine.
  2. There was a pause of 30 seconds between each test, each test was run three times, eight tests per configuration (from 25 concurrent users up to 200 current users, by increments of 25), and a total of eight different configuration.All in all there were 192 tests run, half against an Apache & mod_wsgi configuration, and half against a Nginx, Apache & mod_wsgi configuration.
  3. The raw data contains all three runs for each test, but for my charts and figures I choose the run with the highest average transactions per second.
  4. The machine tested was a 256 megs of ram VPS from Slicehost, setup to these specifications. The machine driving the was also a Slicehost VPS. Roundtrip time between the two machines was approximately half a millisecond.
  5. For the Nginx, Apache & mod_wsgi example I made no modifications to the VPS after rebooting.For the Apache & mod_wsgi tests, before rebooting I altered Apache to expose it on an external port. After reboot I SSH'd into the VPS, turned off Nginx, and then exited my SSH session.
  6. The pages being loaded were extremely lightweight. The no-database-query page was 1 kilobyte, and the database-query page was 0.4 kilobytes.
  7. Data collection was performed using Siege and Siege were managed by this script.

测试条件说明

这些条件对 Apache + mod_wsgi 配置来说极为有利，理论上它应该能胜过 Nginx + Apache + mod_wsgi 配置。因为查询极其轻量（适合工作线程较少的服务器），而且响应速度极快（同样有利于工作线程较少的服务器）。

这些条件可以说是单服务器配置能够击败多服务器架构的“完美风暴”。

测试结果

最初我选择用每秒事务数来评估结果。下面一小段数据就能说明为什么这个指标其实没什么意义。

从每秒事务数来看，不同配置（包括是否开启调试、是否查询数据库）几乎没有产生任何影响。看来得换个思路。

我的第二个方案是比较完成所有请求所用的总时间。不幸的是，总耗时和每秒事务数基于互相重叠的数据计算得出，因此两种配置之间的差异基本一致。有时多服务器配置表现更好，有时单服务器配置更优，没有得出明确结论。

这种趋势贯穿了负载测试记录的所有指标。或许如果对三次运行结果取平均值而不是选最佳值，数据差异会更明显。不过，即便在这些条件下极力寻找两者之间的优劣，也只能发现非常微小的差别。对于那些把性能视为拼图的一部分——而非全部——的人来说，这个数据点的价值几乎可以忽略。

我很希望看到有人能重复这些测试，并引入更多有趣的对比（例如 Nginx + mod_wsgi vs Nginx + fcgi vs Apache + mod_wsgi 等），甚至将这个实验本身再重复一次，以防我犯了什么严重错误导致这些数据失去参考价值。

目前我的结论是：在条件良好的情况下，提供动态内容时，单服务器和多服务器配置的性能大致相当。

原始数据

原始数据可以在这里以 CSV 格式下载。

下面是我用来提取单个指标数据（并发数、完成时间等）、从三次重复运行中挑选最佳值，并最终生成 CSV 文件的脚本。

import csv
fin = open('results.csv','r')
dr = csv.DictReader(fin)
results = []
field = 'Concurrency' # 'Transaction rate'
while True:
    try:
        tests = [dr.next(),dr.next(),dr.next()]

        test = tests[-1]
        summary = {}
        summary[field] = test[field].split(' ')[0]
        summary['clients'] = test['users']
        desc = "%s Debug? %s Db? %s" % (
            test['config'],test['debug_on'], test['use_db'])
        summary['description'] = desc
        results.append(summary)  
    except StopIteration:
        break
fin.close()
fout = open('cleaned.csv','w')
fields =  results[0].keys()
fields.sort()
field_dict = {}
for field in fields:
    field_dict[field] = field
writer = csv.DictWriter(fout, fields)
writer.writerow(field_dict)
writer.writerows(results)
fout.close()
