PyObjC 中的命名和大小写规范

2008-09-04 · 阅读原文

在我关于 PyObjC 和 Cocoa 的教程中，一个核心观点是：PyObjC 就是 Python，同时它也是 Objective-C。当你开始考虑如何命名方法和变量时，这一点最容易让人感到困惑。Python 推荐的方法命名风格（正如 PEP 8 中所讨论的）是全部使用小写字母，并用下划线分隔单词。

因此，合适的函数名称看起来像 subtract、remove_child_node 或 perform_caching。此外，私有实例变量和方法通常以一个下划线开头，形成类似 _words 或 _add_child_node 的名称。

不幸的是，这些命名约定很容易与 PyObjC 描述 Objective-C 方法的约定发生冲突，后者将下划线视为等同于 Objective-C 方法中的冒号。

例如，Python 方法 remove_child_node(self, node) 看起来像是 Objective-C 方法 remove:child:node:，但实际上只接收一个参数而不是三个。因此，remove_child_node 方法无法被 Objective-C 类、Cocoa 绑定以及 Interface Builder 访问。

即使是不合理地放置下划线，例如私有实例变量 _nodes（它无法合理地转换成 Objective-C 方法），也会导致无法访问。

由于标准的 Python 约定不适用，看来为 PyObjC 编写 Python 函数应该采用不同的命名规范：像写 Objective-C 一样写方法，然后再将其转换成 Python 定义。

使用这个规范，我们来重新处理 remove_child_node(self, node)。首先将其翻译成 -(id)removeChildNode:(id)node;，然后再转换成 Python 形式 removeChildNode_(self, node)。另一个例子，方法 perform_caching 变成 -(void)performCaching;，进而转换成 performCaching(self)。

正如 PEP 8 所提到的，有时为了保持理智必须打破常规，这似乎就是其中之一。在一个文档相对匮乏的世界里，使用小写开头的驼峰命名法（lower-first camel-casing）能让 PyObjC 开发变得更合理一些，而理智不会接受更差的选择。
