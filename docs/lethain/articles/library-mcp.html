library-mcp：使用 Markdown 知识库

2025-04-22 · 阅读原文

在工作中，我们一直在构建智能体工作流，以支持内部交付团队处理各种会计、现金对账和运营任务。为了更好地指导这个项目，我在今年一月作为学习项目。此后，Model Context Protocol (MCP) 已成为为智能体编写工具的重要解决方案，我决定花周末时间写一个 MCP 服务器，以加深理解。我们自己的智能体及其专属工具

这个项目的成果是 library-mcp，一个简单的 MCP 服务器，你可以本地配合 Claude Desktop 等工具使用，用于探索 Markdown 知识库。我越来越喜欢“datapack”这个想法——将与当前工作相关的内容加载到上下文窗口中。目前我正准备以针对 LLM 优化的“datapack”格式发布即将出版的新书。library-mcp 允许任何作者根据当前问题动态构建相关 datapack，只要他们能访问以 Markdown 文件形式存在的内容即可。

几张截图就能说明一切。首先，这是这个服务器提供的所有工具列表。这些工具提供了多种搜索内容并将其拉入上下文窗口的方式。

每次你在聊天中首次使用某个工具时，Claude Desktop 都会提示你确认是否允许该工具运行。这是一个很好的特性，我认为特别重要的是，批准应该在应用层完成，而不是在智能体层。如果让智能体自己批准自己的使用，那么安全问题将会变得非常混乱。

下面是一个获取所有标签的例子，用来了解我写过哪些主题。在看到标签后，你可以接着问：“给我看看我写过的关于‘python’的文章”。有趣的是，你可以将检索和智能分析结合起来。例如，你可以问：“给我列出我写过的所有标签，并找出那些似乎与软件架构相关的”，它就能很好地进行筛选。

最后，这里是一个真正使用 datapack 来回答问题的例子。在这个案例中，它评估了我的写作风格在 2018 年到 2025 年之间发生了怎样的变化。

更实际的是，我已经和朋友一起实验过，使用作为 CTO 或 VP Engineering 的前 90 天作为上下文窗口中的 datapack 来撰写 CTO 入职计划。你可以想象，如果有合适的数据包，你还能做得更多。例如，在 datapack 中放入公司所有现有政策，再加上一份关于如何有效撰写政策的文档，来制定新的公司政策，这将显著提高一致性，并更容易发现相互冲突的政策。

总的来说，我现在非常认同“有用的 datapack 能够促进创作”这一愿景，并希望 library-mcp 能成为大家在实验探索这一想法过程中的有用工具。
