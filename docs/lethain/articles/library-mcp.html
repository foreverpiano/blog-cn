library-mcp：使用 Markdown 知识库

2025-04-22 · 阅读原文

在工作中，我们一直在构建自主代理工作流（agentic workflows），帮助内部交付团队处理各种会计、现金对账和运营任务。为了更好地指导这个项目，我在今年一月，作为学习项目。此后，Model Context Protocol（MCP）已成为为代理编写工具的重要解决方案，于是我决定利用周末时间写一个 MCP 服务器，以加深对它的理解。我们自己的智能体，以及它们自己的工具。

这个项目的成果是 library-mcp，这是一个简单的 MCP 服务器，你可以本地配合 Claude Desktop 等工具使用，用于探索 Markdown 知识库。我越来越喜欢“datapack”的想法——将与当前工作相关的内容加载到上下文窗口中。目前我正在尝试以“datapack”格式发布即将出版的新书，以便优化其在 LLM 中的使用效果。library-mcp 让任何作者都能根据当前问题动态构建相关 datapack，前提是他们的内容以 Markdown 文件形式存在。

几张截图就能说明一切。首先，这是这个服务器提供的工具列表。这些工具提供了多种方式来搜索内容并将其拉取到你的上下文窗口中。

每次你在聊天中首次使用某个工具时，Claude Desktop 都会提示你确认是否允许该工具运行。这是一个很好的功能，我认为特别重要的是，批准应该在应用层完成，而不是在代理层。如果让代理自己批准自己的使用，那么安全问题就会变得非常麻烦。

下面是一个获取所有标签的例子，用来了解我写过哪些主题。你可以在看到标签后继续提问，比如“给我看我写的关于‘python’的文章”。有趣的是，你可以将检索和智能判断结合起来。例如，你可以问：“给我所有我写过的标签，并找出那些似乎与软件架构相关的”，它就能很好地完成筛选。

最后，这是一个真正使用 datapack 来回答问题的例子。在这个案例中，它评估了我的写作风格从 2018 年到 2025 年的变化。

更实际的例子是，我已经和朋友一起尝试过，将作为 datapack 放入上下文窗口，帮助他们撰写 CTO 入职计划。你可以想象，合适的 datapack 能让你走得更远。比如，在编写公司政策时，如果把所有现有政策和一份“如何有效撰写政策”的文档一起作为 datapack，就能显著提高一致性，并更容易发现相互冲突的政策。担任 CTO 或 VP Engineering 后的前 90 天

总的来说，我现在深深着迷于“用高质量的 datapack 来辅助创作”这一愿景，也希望 library-mcp 能成为大家在探索这条路上的有用工具。
