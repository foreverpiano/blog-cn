我第五次重写博客的那些事儿

2016-05-20 · 阅读原文

虽然连我自己都说不清为什么，但每当我有点空闲时间，又正处于某个变化期时，就会忍不住去重写自己的博客。这已经是这个博客软件的第五次彻底重写了，之前的几个版本（从新到旧）分别是：

，但底层依然依赖我自己拼凑的 Sisyphus 代码库（自从它刚能跑起来之后，我就基本没再碰过它了，相当于它一辈子都是个拼凑的原型，RIP Sisyphus）。那是 2014 年。成第二个同样糟糕的博客引擎 Sisyphus。那是 2011 年。第二个版本用的“Lifeflow”基本上是我学习 Django 的练习项目，也算是我第一次接触 Web 开发。无论是 CSS 还是代码，都谈不上好看。那大概是 2007 年底的事。第一版则是用的 Wordpress，应该是在 2007 年年初。《非理性繁荣》第四次归来《非理性繁荣》的第三次重生

这次重写大约用了 1350 行 Go 代码（暂时命名为 Icarus，因为所有博客引擎似乎都该带点希腊神话里悲观色彩的典故），替代了之前大约 800 行 Python 代码。我觉得这次用 Go 重写的版本反而更简单——一方面 Go 本身就不喜欢过于简洁的语法，另一方面它主要依赖标准库，没有像之前 Python 版本那样依赖 Django 这样重量级的框架。

虽然这算不上什么了不起的 Go 成就，但过去几个月里我终于写了足够多的 Go 代码，对它有了自己的看法。总体来说我的评价相当正面，只是我个人仍然认为它作为文本处理语言相当糟糕（就像 Erlang 一样，我觉得它对字符串的处理很差劲）。

另一方面，能够直接用 Nginx 放在 Go 服务前面，而不用再折腾 Nginx 前面挂 Apache + mod_python 的配置，真是让人松了口气（我知道我知道，但上一个版本的 VPS 配置是 2011 年搭的，那时候 mod_wsgi 还很早期，uwsgi 就更早了。现在如果重来，我会直接用 uwsgi + Nginx）。

我依然在使用 Redis，因为真正的数据源是 Git 仓库，Redis 主要充当物化视图和一些分析数据的角色。（其中一个设计约束就是要能直接把上一个版本的 RDB 文件拷贝过来就能正常工作，省去烦人的迁移步骤。）

总之，希望这次能成为我更频繁更新博客的开始。:-)
