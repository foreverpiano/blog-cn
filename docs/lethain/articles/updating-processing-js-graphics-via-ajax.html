使用 Ajax 更新 Processing.js 图形

2008-05-20 · 阅读原文

另一个我一直想尝试的 Processing.js 技术是利用 Ajax 来创建动态内容。本文将介绍一个依赖 Processing.js 进行图形绘制的 JavaScript 应用程序，它能显示始终保持最新的图表。该应用将使用 PHP 构建一个简单的后端示例（它会返回随机数据）。

概述

该应用显示某货币汇率的当前趋势。它每十秒更新一次汇率，并维护过去十个数据点的图表。数据点由一个 PHP 脚本随机生成（选择 PHP 是因为如果使用更复杂的语言，就好比请爱因斯坦来帮你系鞋带一样小题大做）。

PHP 脚本：data.php

首先来看看这个 PHP 脚本。它的全部工作就是返回一个随机数，因此简单到不能再简单。

在实际应用中，你可能会查询数据库或者进行某种计算，但这个示例的目的并不是创建一个有趣的后端，而是通过 Processing.js 结合 Ajax 来创建动态图形……所以后端就只用了一行 PHP 代码。

JS 部分：exchangechart.js

正如我在上面提到的，在最初构思这个示例时，我设想图表表示两种货币之间的汇率，这就是为什么文件和示例都被命名为 exchangechart。但最终它其实只是一个简单的图表，与货币没有任何关系。

它预先填充了五个数据点，额外的数据点则通过异步方式从 PHP 脚本请求。一次最多同时显示十一个数据点。当拥有十一个数据点后，每获取一个新点，最老的数据点就会从图表中移除。另外，与我之前那个稍显偏差的 bubbles 示例不同，这个图形仅在新数据加入时才重绘，所以它完全不会给处理器带来负担（即使在 Camino 浏览器中也能流畅运行，而 Processed Tower Defense 一跑起来就立刻崩溃）。

它使用了 Processing.js 的 API，以及一个实现跨浏览器 Ajax 的简单函数。异步请求的回调函数会将返回的数据传递给 Chart 类的实例，该类负责控制图形的绘制。

被回调函数调用的 update 方法是整个链条的下一步。

它接收一个数值，并将其推入包含所有正在绘制的数据点的数组。如果数据超过十一个，则保留最近的十一个，其余的将被丢弃。之后，它调用 draw 方法来更新显示图形。除了初始绘制外，这是唯一调用 draw 的地方（如果想给这个显而易见的概念起个花哨的名字，我们或许可以称之为“懒惰绘制”）。
