在 LifeFlow 中实现嵌套评论

2008-01-04 · 阅读原文

最近我决定要给 LifeFlow 添加嵌套评论功能。这主要是因为现有的评论系统给读者带来的折磨已经超出了我良心的承受范围。我希望引入嵌套评论能稍微弥补我对亲爱的读者们造成的这种罪过——大概只是我自我安慰的谎言罢了。

不管怎样，我希望实现一个可靠的评论嵌套系统。我心里有两个设计目标：

尽量少在数据库中存储额外数据；保持合理的计算复杂度（应该能够轻松处理每篇文章约 500 条评论）。

我考虑了几种不同的实现方式。其中一种我没有采用的方案是在数据库中直接存储层级数据。我不喜欢把完整路径都存进数据库的想法。而且那种方法似乎会让重新组织评论变得相当复杂（我承认需要任意调整评论顺序的情况并不多，除非你实现了投票系统或基于质量的评论置顶功能）。

我需要存储哪些数据？

我最终决定额外存储的唯一数据就是父评论的 ID。（另一个必要数据是评论所属的文章，不过我本来就在存储了。）

面临的挑战

由于我没有在数据库中存储路径，而只是记录每个节点的父节点，我真正的挑战是如何用这个并不完美的数据来重建评论的层级结构。

一个简单但不完美的方法

以下是我的解决方案（用 Django 代码表示）：

我先用一个哈希表（hashmap）构建评论的结构（用 None 作为 key 来表示没有父评论的顶级评论），然后基于这个哈希表递归地生成包含层级结构的列表。

这个方案能比较高效地完成，主要是因为 select_related() 方法（在 Django SVN 版本中可用，0.96 或更早版本不支持）会批量获取关联对象。因此尽管我们做了很多操作，但实际上只会向数据库发起一次查询。

它甚至还是尾递归的——如果 Python 真的关心尾递归优化的话，这会很有意义。以后我可能得把递归改成某种循环形式。

现在 LifeFlow 已经在模型层面支持了嵌套评论。接下来我还得修改模板和视图，把这个新功能呈现给用户。

2008 年 1 月 6 日更新

嵌套评论现在已经完成了 90%。除了可视化的层级引导之外，其他功能都已实现。这部分需要一些自定义模板标签。你可以在 LifeFlow 的 models.py 文件里看到目前有些笨拙的实现，它位于 Entry 模型的 organize_comments 方法中。

2008 年 1 月 7 日更新

现在可视化部分也已经实现了。总体来说运行得相当不错。我最后写了一个简短的自定义标签，用来限制评论的嵌套深度。

我把它设置为最大深度为 5。超过 5 层的评论都会显示在第 5 层的缩进位置。这样做让评论的外观实现简单了许多（不需要动态计算缩进），我觉得是个不错的折衷。它还能防止评论一路跑到页面右边际的“日落”里去——同样是个胜利。

你可以查看 CSS 或模板文件来了解更完整的实现细节（模型代码仍然在这里）。模板的缩进对齐还不够完美，不过话说回来，那个模板是我自己重做的 LifeFlow 模板版本，我也没指望别人会大量使用……这只是个借口罢了。

即将进行的修改

我还需要调整评论功能，让它能友好地兼容 Internet Explorer（主要是提交部分）。另外，我正在考虑在有新评论时立即让已缓存的博客文章失效，因为用户要等几分钟才能看到自己的评论，这体验相当令人沮丧。
