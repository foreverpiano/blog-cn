Nagios Erlang 监控方案

2009-12-30 · 阅读原文

工作中让我最享受的事情之一就是能和 Erlang 打交道。如果采用率不断提高，Erlang 在分布式计算和可靠性方面能带来诸多优势，但在短期内，Erlang 不可避免的弱点是它既不是 PHP 也不是 Java。此外，Erlang 应用可能依赖 Mnesia 而非 MySQL 或 PostgreSQL，最终导致公司现有的基础设施（运维、监控、操作手册等）通常无法直接有效支持 Erlang，需要进行一定的修改。

为了解决其中一个方面的问题，我最近几天花了些时间，为 Erlang 的进程组、节点和应用编写了适用于 Nagios 的监控脚本。这个项目暂定名为 nagios_erlang，不过我得承认这个名字的吸引力确实有限。

更详细的使用说明请参考 nagios_erlang 的 README 文件，总体而言，它提供了以下功能：

检查主机能否 ping 通另一个节点、检查指定应用是否在另一个节点上运行、检查某个进程组中的进程数量是否满足告警和危急阈值（例如超过 5 个进程正常，少于 5 个告警，少于 3 个危急等等）。

目前这些都是主动检查，但将其扩展为同时支持被动检查应该并不复杂（在 nagios_erlang.erl 中增加一个输出 NCSA 格式的包装函数，检测 --passive 参数，将输出写入临时文件，然后通过 NCSA 的 send_message 发送出去，大致就是这样的思路）。

完整的源代码已在 Github 上开源。

比较尴尬的是，它是通过尝试启动应用并检查是否已启动来实现的。我暂时没想到更优雅的办法，或许只是我没注意到 application 模块中已经存在合适的函数。
