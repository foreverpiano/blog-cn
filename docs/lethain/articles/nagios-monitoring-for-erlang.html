Nagios 监控 Erlang

2009-12-30 · 阅读原文

工作中的一大乐趣就是能和 Erlang 打交道。如果采用率不断提升，Erlang 在分布式计算和可靠性方面能带来诸多优势。但短期来看，Erlang 不可避免的弱点在于它既不是 PHP 也不是 Java。此外，Erlang 应用可能依赖 Mnesia 而非 MySQL 或 PostgreSQL，最终导致公司现有的基础设施（运维、监控、操作手册等）通常无法直接有效支持 Erlang，而需要进行一些改造。

为了解决其中一个方面的问题，我最近几天花了些时间，为 Erlang 的进程组、节点和应用编写了 Nagios 监控脚本。这个项目暂时命名为 nagios_erlang，不过我得承认这个名字在吸引力上确实有些不足。

更详细的使用说明请参考 nagios_erlang 的 README 文件，总体来说它提供了以下功能：

检查主机能否 ping 通另一个节点；检查特定应用是否在另一个节点上运行；检查某个进程组中的进程数量是否满足告警和严重阈值（例如大于 5 个进程正常，小于 5 个告警，小于 3 个严重等）。

目前这些都是主动检查，不过要扩展脚本支持被动检查应该也比较直接。（在 nagios_erlang.erl 中增加一个输出 NCSA 格式的包装器，检测 --passive 参数，将输出写入临时文件，然后通过管道传给 NCSA 的 send_message，大致就是这样的思路。）

完整源代码已在 Github 上开放。
