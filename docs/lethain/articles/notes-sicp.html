《计算机程序的构造和解释》笔记

2018-12-29 · 阅读原文

我大约十年前就买了《Structure and Interpretation of Computer Programs》（简称 SICP）。大家都跟我说这是一本伟大的著作，我也一直想好好爱上它。从那以后，我断断续续地开始读这本书，大概有十几次，但始终没能走得很远。前面的内容太过熟悉，无法吸引我的注意力；而后面的内容又晦涩难懂，因为我没有认真完成前面的练习去学习 Scheme（https://en.wikipedia.org/wiki/Scheme_(programming_language)）。

假期期间，我终于完整读完了这本书，并且很庆幸自己做到了。虽然在某些地方，作者对旁支内容的偏好让他们采用了比严格必要更复杂的教学示例，但尽管我之前已经或多或少学过书中的大部分主题，这次阅读还是让我收获颇多。

书中的内容实在太多，无法全部记笔记。这里我只写下了一些我觉得特别优雅或有趣的片段。

我使用 Emacs 的 scheme-mode 配合 mit-scheme 来完成这本书，通过 brew install mit-scheme 安装。总体来说，这套工具用起来很顺手，也让我怀念起大学时用 SLIME 写 Steel Bank Common Lisp 的日子。

有状态的函数

作为一个通过面向对象语言（Java、Python）入门编程的人，有状态的函数对我来说是个奇怪的概念。随着这个概念逐渐深入，我开始意识到：有状态的函数是一个基本构建块，可以扩展它来实现对象。

经典示例是创建一个累加器函数，它能记住所有传入参数的总和。下面是 Scheme 中 make-accumulator 的实现，它使用 lambda 创建了一个匿名函数。初始参数被绑定在 lambda 的作用域内，成为其私有的局部状态。

(define (make-accumulator starting)
  (lambda (incr)
    (begin
      (set! starting (+ starting incr))
      starting)))

请注意，starting 被同一个匿名函数的所有调用所共享，但不会在由 make-accumulator 创建的不同 lambda 之间共享。每个 lambda 都有自己私有的状态，这使得以下行为成为可能：

(define a (make-accumulator 0))
(a 1) ;Value: 1
(a 100) ;Value: 101
(define b (make-accumulator 10))
(b 1) ;Value: 11
(b 1) ;Value: 12
(b 5) ;Value: 17

这对我来说是一个特别有力量的例子，因为我最初是用 Python 学编程的，而这个程序直接翻译成 Python 2 是无法工作的。

def make_accumulator(amt):
    def update(incr):
        amt = amt + incr
        return amt
    return update

a = make_accumulator(0)
print a(5)
print a(10)

这段代码看起来应该能实现同样的功能，但实际上它会抛出以下错误：

Traceback (most recent call last):
  File "tmp.py", line 9, in 
    print a(5)
  File "tmp.py", line 4, in update
    amt = amt + incr
UnboundLocalError: local variable 'amt' referenced before assignment

Python 3 引入了 nonlocal 关键字，这才让它成为可能！

def make_accumulator(amt):
    def update(incr):
        nonlocal amt
        amt = amt + incr
        return amt
    return update

a = make_accumulator(0)
b = make_accumulator(100)
print(('a', a(5)))
print(('b', b(1)))
print(('a', a(10)))
print(('b', b(1000)))

这样就得到了预期的输出：

('a', 5)
('b', 101)
('a', 15)
('b', 1101)

使用 nonlocal 语句仍然相当别扭，但它至少是可行的，这让人兴奋，尤其是在把 Python 当作教学和学习语言的背景下。

消息传递

如果我们想构建一个简单的面向对象语言实现，并且已经有了有状态的函数，那么我们还缺少最后一个要素：消息传递。消息传递的思想是向一个对象发送一条消息，然后让对象自己决定如何处理它。

考虑下面这段 Python 代码：

class Animal:
    def speak(self):
        return "generic-animal-noise"


a = Animal()
a.speak()

当我们调用 a.speak() 时，其实是在向对象 a 发送一条消息——这里是 speak——然后让它以合理的方式做出响应。如果我们只有有状态的函数，而没有一个完整的对象系统，该如何处理呢？

可以这样实现：

(define (make-account balance)
  (lambda (msg amt)
    (cond ((eq? msg 'deposit) (begin (set! balance (+ balance amt))
                              balance))
          ((eq? msg 'withdraw) (begin (set! balance (- balance amt))
                              balance)))))

(define act (make-account 100)) ;Value: act
(act 'deposit 10) ;Value: 110
(act 'deposit 10) ;Value: 120
(act 'withdraw 50) ;Value: 70

这是一个人为构造的例子，但它展示了一个非常简单的分发机制，让我们朴素的函数开始表现出与对象极其相似的行为。

这里一个尴尬的限制是，它要求所有消息具有相同数量的参数。一个变通方法是在响应消息时返回函数：

(define (make-account balance)
  (lambda (msg)
    (cond ((eq? msg 'deposit) (lambda (amt)
                                (begin (set! balance (+ balance amt))
                                       balance)))
          ((eq? msg 'withdraw) (lambda (amt)
                                 (begin (set! balance (- balance amt))
                                        balance))))))

(define act (make-account 100)) ;Value: act
((act 'deposit) 10) ;Value: 110
((act 'withdraw) 100) ;Value: 10

这给了我们极大的灵活性，可以随意处理不同的消息。然而，它也开始让人感到这里的一切变得多么动态，有些过于开放了？

思考这些非典型的对象系统让我想要找一本优秀的小 talk 入门书，同时也让我想起 Common Lisp Object System（简称 CLOS），它有一些很棒的想法，尤其是在泛型函数方面。

代码即数据

软件领域最有趣的想法之一是：程序能够编写或修改其他程序。这类元程序是 Lisp 语言的标志性特征，通常体现在它们的宏实现中。（想深入了解宏的话，读一读不同 Lisp 如何处理宏是很有趣的：Scheme macros、Clojure macros、Common Lisp macros。）

然而，要开始接触“能修改软件的软件”，你并不需要直接跳到宏，只需要用到 quote，用一个前导单引号表示，或者直接使用 quote 函数，例如下面两个是等价的：

(quote (+ 5 10))
(define a '(+ 5 10))

一旦你对一个表达式进行了 quote，就可以把它当作普通数据来修改，例如把加法替换为减法，然后用 eval 来运行这段被引用的代码（eval 需要一个环境来执行求值，the-environment 是获取当前环境的一种方式）：

(define x (quote (+ 5 10)))
(eval x (the-environment)) ;Value: 15
(car x) ;Value: +
(cdr x) ;Value 25: (5 10)
(define y (cons - (cdr x)))
(eval y (the-environment)) ;Value: -5

这看起来很简单，但其意义非常强大。今年早些时候，我写过一篇关于 以编程方式重构 Ruby 代码 的文章，那篇文章是通过重写源文件实现的，而这里的做法是在程序运行时直接生效。

有趣的是，当你在其他语言中进行抽象语法树（AST）重构时——比如 Google 的《Large-Scale Automated Refactoring Using ClangMR》中描述的那样——其底层实际上操作的就是 s-表达式，基本相当于把那些语言的语法表示成了 Lisp 的形式！

大多数语言都支持某种形式的 eval，但通常只是操作字符串，像 Python 这样：

>>> eval("5 + 4")
9

因为 Lisp 本质上就是列表，而你可以随意修改这些列表，所以 Lisp 版本的 eval 要强大得多——你能访问完整的语法，而不仅仅是一段无结构的字符串。

编写解释器

这本书最精彩的内容之一，就是用 Scheme 自身实现一个能运行的 Scheme 解释器。这得益于 Scheme 的 quote 和代码即数据的特性，过程被大大简化了。

例如，我们可以先编写一个自己的 eval 函数，最初只处理自求值的基本类型和 if 表达式（其他情况则转交给 Scheme 内置的 eval）：

(define (if? exp)
  (eq? (car exp) (quote if))

(define (true? exp)
  (eq? #t exp))

(define (self-evaluating? exp)
  (cond ((number? exp) #t)
	((string? exp) #t)
	(else #f)))

(define (eval-if exp env)
  (let ((predicate (cadr x))
	(true-branch (caddr x))
	(false-branch (cadddr x)))
    (if (true? (eval2 predicate env))
	(eval2 true-branch env)
	(eval2 false-branch env))))

(define (eval2 exp env)
  (cond ((self-evaluating? exp) exp)
	((if? exp) (eval-if exp env))
	(else (eval exp env))))

之后我们就可以这样使用这个简易求值器：

(define x (quote (if (= 5 10) 5 10)))
(eval2 x (the-environment)) ;Value: 10

这个核心会被反复扩展，直到它能够完整处理整个 Scheme 语言，而不再依赖调用内置的 eval。这种增量式的方法非常强大，因为它让你可以在学习和测试的过程中逐步前进，而不需要一次性完成整个解释器。

这一部分不仅实现了 Scheme 本身，还进一步探讨了如何修改它来支持不同的特性，例如惰性求值。

寄存器机器

有些书会教一点汇编代码来说明高级语言如何被翻译成低级语言，而 SICP 则采用了一种类似汇编但用 Scheme 函数表达的语言，比如 test、branch 和 goto。

于是程序看起来就像这样：

(controller
  test-b
    (test (op =) (reg b) (const 0))
    (branch (label gcd-done))
    (assign t (op rem) (reg a) (reg b))
    (assign a (reg b))
    (assign b (reg t))
    (goto (label test-b))
  gcd-done)

这是一种相当易读、合理的方法，还有一个额外好处，就是你可以自己实现 reg 和 op 这些函数，这比费劲地去安装一个奇怪的 MIPS 模拟器要更有学习价值。

最后我想说的是，我对他们能在短短六百页左右的篇幅里塞进如此多有趣的思想感到惊叹，而且并没有假设读者具备太多先备知识。他们能做到这么多，很大程度上得益于 Scheme 本身——它是一个极其轻便、易于扩展的工具。

Scheme 的简洁也是一个巨大的优势。尽管覆盖了如此广泛的内容，但在读这本书的过程中，需要阅读和编写的代码量并不大。比我最初预想的要更多思考、更少打字。

如今教育越来越注重实用性，这是个好趋势。教大家 Python、Java 这些他们在工作中很可能用到的语言，也总体上是个好方向。在这些语言上提升熟练度能直接带来实际益处，而理解底层机制对大多数现代软件开发来说则并非必需。不过，我认为对很多人来说——也许是在职业生涯后期——花时间读一读像 SICP 这样的书是非常有帮助的，它会把那些魔法层层剥开，变成你可以理性思考和理解的东西。

读完 SICP 之后，今年我想深入学习以下几个主题（非常欢迎推荐相关书籍）：

  • Smalltalk —— 它的起源、实现和使用
  • 类型系统 —— 《Practical Foundations for Programming Languages》听起来是个不错的起点？
  • 编译器 —— 《Engineering a Compiler》一直在我书架上瞪着我，也许今年终于该打开它了。
