HTTP::Server::Simple::CGI 入门

2008-12-05 · 阅读原文

上周我需要创建一个持久运行的 Perl 服务，用于监听传入的文件并进行处理。我选择了 HTTP 协议，因为它完全能够满足我的简单需求。所以我需要的只是：(A) 一个 Perl 的 HTTP 服务器实现，以及 (B) 如何使用它的指导。

第一部分解决起来相当简单，我很快找到了 HTTP::Server::Simple。接着我意识到，使用它的 CGI 专用子类 HTTP::Server::Simple::CGI 来编写服务会是最简单的。

安装过程一如既往地轻松：

sudo perl -MCPAN -e shell
install HTTP::Server::Simple::CGI

然后我就稍微卡住了。虽然有关于如何创建一个简单 CGI 服务器的文档，但还不足以让我实现所需的服务。

创建服务器的骨架代码大致如下：

#!/usr/local/bin/perl -w
package MyServer;
use strict;
use HTTP::Server::Simple::CGI;
use base qw(HTTP::Server::Simple::CGI);
my $port = 4569;
sub handle_request {
my ($self, $cgi) = @_;
return "Hi.";
}
my $pid = MyServer->new(4116)->background();

这段代码非常简洁明了，但我们的服务器目前还没有做任何真正有用的事情。这就是文档开始变得不够清晰的地方，尤其是如果你不熟悉 CGI 模块的话——而它正是解开所有谜题的关键。

以下是编写 handle_request 子过程的几个实用范例。

根据 HTTP 方法返回不同响应

sub handle_request {
  my ($self, $cgi) = @_;
  my $method = $ENV{REQUEST_METHOD};
  my $timestamp = time();
  if (lc($method) eq 'post') {
    print "Received POST request at $timestamp";
  }
  else {
    print "Received request of type $method at $timestamp";
  }
}

接收 POST 上传的文件

sub handle_request {
  my ($self, $cgi) = @_;
  my $method = $ENV{REQUEST_METHOD};
  if (lc($method) == 'post') {
    my $file = $cgi->param('POSTDATA');
    open OUT '>file.xml' or warn $!;
    print OUT $file;
    close OUT;
    print 'Received data.';
  }
  else {
    print 'Please POST a file.';
  }
}

我用上面的代码处理过相当大的文件（超过 100MB），但我强烈怀疑它无法很好地扩展到多个并发请求。不过作为一个简单的后端服务，上述代码的表现——多少让我有些意外——其实相当不错。

为请求 Fork 进程

sub handle_request {
  my ($self, $cgi) = @_;
  my $pid = fork();
  if ($pid == 0) {
    exec('perl some_other_script.pl');
  }
  print 'Forked additional process.';
}

我认为这种方式很有帮助，因为它能让你更容易用一个简单的 Perl 服务器来管理其他进程。例如，你可以用 Java 或 C 语言编写一个 XML 解析器以获得更高的速度，然后保存上传的文件（就像上面的例子那样），再 fork 一个新进程去运行解析脚本。

总结

总的来说，HTTP::Server::Simple 又一次给我带来了非常 positive 的 CPAN 体验，也正是这样的 CPAN 体验让我持续学习和玩转 Perl。我确实觉得文档的质量相当参差不齐（比如 XML::Twig 的文档多到令人望而却步），而且相比 Python 或 Ruby 社区，为 Perl 模块 X 随意撰写博客文章的人要少得多。希望这篇文章能出现在某个迷茫的灵魂的搜索结果中。
