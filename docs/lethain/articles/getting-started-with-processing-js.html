Processing.js 入门指南

2008-05-10 · 阅读原文

最近 John Resig 发布了 Processing.js。这是一个非常有趣的项目，它允许在浏览器中直接运行 Processing 代码。本文将快速介绍为什么值得尝试它，并以一个入门教程作为结尾。

为什么 Processing.js 值得关注？

我认为 Processing.js 的重要性至少有两个原因。

  1. The first is that Processing's philosophy and syntax have never felt like a good match. The idea of drawing code sketches is tantalizing, and I think that concept embodies what is great about Processing. However, drawing sketches in Java 1.3 syntax feels like writing a letter with an almost exhausted magic marker: its possible, but it's hard to get lost in the joy of the process.Processing.js exposes much of the functionality of Processing to Javascript, which means that people who feel more comfortable with Javascript than Java 1.3 have another shot at getting to know Processing in a language they prefer.
  2. The second reason is "this will wipe out the applet completely.". Although I'm not quite as optimistic as Why--after a nuclear winter I fully expect applets to survive to compete with cockroaches--Processing.js is a nice hammer for a niche with an impoverished toolbox2.

下载文件

Processing.js 很容易上手运行，但在开始之前，我们需要先下载几个文件。

  1. First, you will need to grab a copy of processing.js. Notice that we're grabbing the file directly from the project's SVN repository, so it'll be up to date. (Alternatively, you can grab a copy here.)
  2. Next, you will need to have a recent browser. Resig's recommends Firefox 3.0 Beta 5, but also says that the nightly WebKit builds and Opera 9.5 will--except for small pieces of missing functionality--work as well.

环境搭建

现在我们已经有了所需的文件，接下来需要快速搭建一个开发环境。第一步是创建一个文件夹，用于存放即将用到的 JavaScript 和 HTML 文件。（无用细节：我把我的文件夹命名为 ProcessingJS。）

接下来，将下载的 processing.js 文件复制或移动到刚刚创建的目录中。

第三，在同一个文件夹中，创建一个名为 init.js 的空文件，然后将以下内容粘贴进去：

window.onload = function()
{
  var canvas = document.getElementsByTagName("canvas");
  for ( var i = 0; i < canvas.length; i++ )
  {
    Processing( canvas[i], canvas[i].previousSibling.textContent );
  }
};

（请注意，init.js 的内容直接来自 John Resig 开发的演示示例，与我本人无关。）

现在我们只剩下创建一个简单的 HTML 文件了。

使用 Processing.js

使用 Processing.js 的核心工作就是编写 Processing 代码，然后将其放入一个相当标准的 HTML 模板中。因此，一旦你写好这个模板，之后只需把不同的 Processing 代码片段粘贴进去，在浏览器中刷新页面即可。这就是一个开发环境，相当巧妙。

那么，让我们来准备 HTML 模板。在项目目录中创建一个名为 test.html 的空白文件，并将以下 HTML 内容粘贴进去：

<html>
  <head>
    <title>A Processing.js Example</title>
    <script type="text/javascript" src="processing.js"></script>
    <script type="text/javascript" src="init.js"></script>
  </head>
  <body>
    <h1>A Processing.js Example</h1>
    <script type="application/processing">
    </script><canvas></canvas>
  </body>
</html>

注意那个 type 为 "application/processing" 的空 script 标签，这就是我们即将粘贴 Processing 代码的地方。浏览示例页面，选择一个例子来尝试。我尝试了 Setup and Draw 示例。复制两条水平分割线之间的代码。对于 Setup and Draw 示例（为简洁起见省略注释），你复制的内容是：

void setup() 
{
  size(200, 200);  // Size should be the first statement
  stroke(255);     // Set line drawing color to white
  frameRate(30);
}
float y = 100;
void draw() 
{ 
  background(0);   // Set the background to black
  y = y - 1; 
  if (y < 0) { y = height; } 
  line(0, y, width, y);  
}

现在将你复制的内容粘贴到上面的 HTML 模板中，最终看起来应该像这样：

<html> <head>
<title>A Processing.js Example</title>
<script type="text/javascript" src="processing.js"></script>
<script type="text/javascript" src="init.js"></script>
</head>
<body>
<h1>A Processing.js Example</h1>
<script type="application/processing">
void setup() 
{
  size(300, 300);  // Size should be the first statement
  stroke(255);     // Set line drawing color to white
  frameRate(90);
}
float y = 100;
void draw() 
{ 
  background(0);   // Set the background to black
  y = y - 1; 
  if (y < 0) { y = height; } 
  line(0, y, width, y);  
}
</script><canvas></canvas>
</body> </html>

现在用 Firefox 打开 test.html 文件，你应该就能看到 Processing 代码在浏览器中运行起来了。

总结

至此，你已经可以随心所欲地进行各种实验了。你可以修改 test.html 中的代码，然后在浏览器中刷新；也可以前往 Processing 官网深入了解 Processing 语言。

我意识到 Processing.js 的两大吸引力之一——可以通过 JavaScript 访问 Processing 的大部分功能——在本文中完全没有涉及。我希望在不久的将来，花些时间重写部分示例，让应用逻辑依赖 JavaScript 而非 Processing。如果结果足够有趣值得分享，或许会写成另一篇文章。

  1. This isn't really a reason why Processing.js is important, but I think we'll end up seeing some novel and interesting combinations of server side rewriting of Javascript and Processing code that interacts with Processing.js. This could be as simple as loading dynamic data for charts, rewriting Processing code to use a user's personal color scheme, but could get as complex as our collective imaginations.↩
