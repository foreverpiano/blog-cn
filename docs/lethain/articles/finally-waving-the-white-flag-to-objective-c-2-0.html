终于向 Objective-C 2.0 举白旗投降

2008-12-04 · 阅读原文

很长一段时间以来（包括整个 touchDefense 的开发过程），我一直对 Objective-C 2.0 的理念持反对态度。并不是我讨厌变化，而是觉得 Apple 擅自修改 Objective-C 有些武断。当然没有哪家公司像 Apple 这样对 ObjC 投入如此之多，但 Apple 对 ObjC 也没有像 Microsoft 对 .NET 语言那样拥有法律上的绝对控制权。这让我一直觉得有些不对劲。

但当我开始开发最新的 iPhone 应用时，我决定还是接受现实，转而使用 Objective-C 2.0 提供的那些语法糖来编写代码。

去他的意识形态吧，我宁愿再去西弗吉尼亚加油，也不愿意再多写一个不必要的 mutator 或 accessor 方法。作为一个长期的反 ObjC 2.0 人士，以下是我最终决定大快朵颐这些语法糖的原因。

@property、@property、@synthesize。

我并不喜欢“属性”（property）这个概念，它让我觉得会造成不必要的语义模糊，你不清楚到底在做什么。但我确实很喜欢不用再敲那么多样板代码。

除了自动生成 mutator 和 accessor 之外，你还可以使用属性来简化字段的存取方法。有些人可能会觉得这很有用，但对我来说这最多算是中性，并没有成为我切换到 2.0 的重要理由。

我不买账。不是说它更差，但我认为一把瑞士军刀电锯就够了，谢谢。

我也喜欢迭代器。

在属性和 synthesize 之后，我最喜欢的下一个新增功能就是迭代器了。Perl、Python、Ruby、Java 1.5——几乎所有主流语言的这一天才设计，终于来到了 Objective-C，我很高兴。

大家都在这么做。

我转向 Objective-C 2.0 的最后一个原因是势头。大多数新项目和新开发者（iPhone 带来了很多）都在使用 ObjC 2.0，用 ObjC 2.0 编写示例代码，并且对 ObjC 2.0 感到满意。有些意识形态之战我认为值得去打，但在一 个完全封闭的平台上为了一门编程语言更“开放”而战，感觉并不值得。

所以最终，我发现自己其实并没有花多大力气就从高头大马上跳了下来。一开始爬上去可能本身就有点傻。还有谁在坚持 1.0 的“正义之战”吗？还是你们切换到 2.0 有其他不同的理由？
