终于向 Objective-C 2.0 举白旗投降

2008-12-04 · 阅读原文

很长一段时间以来（包括整个 touchDefense 的开发过程），我一直反对 Objective-C 2.0 这个概念。并不是我讨厌变化，而是觉得 Apple 擅自修改 Objective-C 有点随意。当然没有其他公司像 Apple 这样对 ObjC 有如此深厚的投入，但 Apple 并不像 Microsoft 对 .NET 语言那样拥有法律上的绝对控制权。这件事一直让我觉得有些不对劲。

但当我开始开发最新的 iPhone 应用时，我决定不再纠结，转而采用 Objective-C 2.0 提供的那些语法糖来编写代码。

什么意识形态都见鬼去吧，我宁愿再去西弗吉尼亚加油，也不愿意再写那些毫无必要的 mutator 和 accessor 方法了。作为一个长期的反 ObjC 2.0 人士，下面就是我决定大快朵颐这些语法糖的原因。

@property、@property、@synthesize。

我并不喜欢 property 这个概念，它让我觉得在你实际操作的事情上制造了不必要的模糊不清。但我确实很喜欢不用再敲那么多模板代码。

使用 property 非常简单。来看看下面这个 ObjC 1.0 的接口：

@interface Person : NSObject {
    NSString       * name;
    int              age;
    NSMutableArray * friends; 
}
-(void)setName: (NSString *)aName;
-(NSString *)name;
-(void)setAge: (int)anAge;
-(int)age;
-(void)setFriends: (NSMutableArray *)someFriends;
-(NSMutableArray)friends;
@end

它的实现是这样的：

@implementation Person 
-(void)dealloc {
[self setName:nil];
[self setFriends:nil];
[super dealloc];
}
-(void)setName: (NSString *)aName {
if (name != nil) [name release];
name = [aName copy];
}
-(NSString *)name {
return name;
}
-(void)setAge: (int)anAge {
age = anAge;
}
-(int)age {
return age;
}
-(void)setFriends: (NSMutableArray *)someFriends {
if (friends != nil) [friends release];
friends = [someFriends retain];
}
-(NSMutableArray)friends {
return friends;
}
@end

写这些代码其实不算难，但当你写了一百次之后，估计早就受够了。使用 ObjC 2.0 和 property，你可以把接口改写成这样：

@interface Person : NSObject {
    NSString       * name;
    int            * age;
    NSMutableArray * friends; 
}
@property(readwrite,copy)   NSString       * name;
@property(readwrite,assign) int              age;
@property(readwrite,retain) NSMutableArray * friends;
@end

但真正赢得胜利的是实现部分：

@implementation Person 
@synthesize name, age, friends;
-(void)dealloc {
[self setName:nil];
[self setFriends:nil];
[super dealloc];
}
@end

啊……短多了。虽然我们仍然需要写一个 dealloc 方法，但我们把十几行繁琐的代码压缩成了一行，这对我来说是真正的胜利。

除了神奇地自动生成 mutator 和 accessor 之外，你还可以使用属性作为字段的 mutator 和 accessor 的简写。有些人可能会觉得这很有用，但对我来说这最多算是中性，并没有强烈促使我转向 2.0。

// is this
Person * p = [[Person alloc] init];
p.name = @"Will";
p.age = 23;
p.friends = [[[NSMutableArray alloc] init] autorelease];
NSLog(@"Person(%@, %d, %@)",p.name,p.age,p.friends);
// really better than this?
Person * p = [[Person alloc] init];
[p setName:@"Will"];
[p setAge:23];
[p setFriends:[[[NSMutableArray alloc] init] autorelease]];
NSLog(@"Person(%@, %d, %@)", [p name],[p age],[p friends]);

我不买账。不是说它更差，但我认为一把瑞士军刀电锯就够了，谢谢。

我也很喜欢迭代器。

在 property 和 synthesize 之后，我接下来最喜欢的新增功能就是迭代器了。我很高兴 Perl、Python、Ruby、Java 1.5——几乎所有主流语言里的这个天才设计——终于来到了 Objective-C。

从代码行数来看，下面两者的差别其实很小：

int i, int l = [people count];
for (i=0; i<l; i++) {
    Person * p = [people objectAtIndex:i];
    NSLog(@"age: %d", [p age]);
}

和

for (Person *p in people) {
    NSLog(@"age: %d", [p age]);
}

但我认为这是一个巨大的改进。首先，手动遍历列表是非常容易出现灾难性拼写错误的地方。更重要的是，当我进入状态疯狂写代码时，写一个老式循环比新式循环更能打断我的思维节奏。即使新式循环偶尔出现拼写错误，编译器也能帮我抓住，而老式循环则需要我更关注语法本身（而不是专注于循环实际要完成的事情）。

大家都在这么做。

我转向 Objective-C 2.0 的最后一个原因是势头。大多数新项目和新开发者（iPhone 带来了很多这样的人）都在使用 ObjC 2.0，用 ObjC 2.0 写示例代码，并且对 ObjC 2.0 很满意。有些意识形态之战我觉得值得去打，但在一个完全封闭的平台上为保持一门编程语言更“开放”而斗争，感觉并不值得。

所以最后我想，我其实没费多少力气就从自己的高 horse 上跳下来了。一开始爬上去可能本来就有点傻。 还有谁在坚持“1.0 才是正义”这场战斗吗？还是你们切换到 2.0 有其他不同的原因？
