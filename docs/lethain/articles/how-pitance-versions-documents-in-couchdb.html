Pitance 如何在 CouchDB 中实现文档版本管理

2009-09-17 · 阅读原文

Pitance 最重要的一项特性就是支持模板的版本管理。在之前使用 CouchDB 积累的一些经验基础上，我认为可以直接利用 Document API 提供的内置文档版本控制功能。显然很多人都想过这个主意，因为 CouchDB 的 wiki 中专门有一篇《Document Revisions》，里面有一句相当直白的话：

除了并发控制之外，你不能将文档修订版用于任何其他目的。

在思考版本管理方案的过程中，我偶然看到一篇博客文章，它给出了一些很有帮助的建议，让我一下子解决了大约 80% 的问题：

为每个文档创建一个 version 属性。例如：{ "name": "erlang_gen_server", "version": 1 } 让视图返回类似 ["erlang_gen_server", 1] 的键。 每次模板更新时，获取最新的修订版本，使用以下查询： ?startkey=["erlang_gen_server", "Z"] &endkey=["erlang_gen_server", 0] &descending=true&count=1 将其版本号加一，然后创建一个新的 CouchDB 文档，键为 ["erlang_gen_server", N+1]。 获取所有版本使用：?startkey=["erlang_gen_server"] &endkey=["erlang_gen_server", "Z"] 获取特定版本使用：?key=["erlang_gen_server", 2]

正如我之前提到的，通过这个方案我已经完成了大约 80% 的工作，但仍然面临一个非常明显的问题：CouchDB-Lucene 以及我为语言和标签创建的视图，把模板的每个版本都当作独立文档来处理。 这导致搜索 “Erlang” 时会返回 erlang_couchdb_app 的十几不同版本，让整个网站变得很难用。 我的解决办法是在所有文档中维护一个 latest 属性：

每次模板更新时，我会把之前标记为 latest 的版本改为 latest=false，然后创建新的版本并将其 latest 设置为 true。之后我更新了标签、语言以及 CouchDB-Lucene 使用的视图，让它们只输出最新的文档：

虽然比预期多花了一些功夫（而且每次修改模板都需要更新两个文档，有人可能会觉得难以接受），但这个方案让我能够兼得两者的优势：既能维护带版本的模板，又不会在不需要的地方把版本信息暴露出来。
