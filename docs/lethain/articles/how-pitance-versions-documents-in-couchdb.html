Pitance 如何在 CouchDB 中实现文档版本控制

2009-09-17 · 阅读原文

Pitance 最重要的一项特性，就是要支持模板的版本管理。在之前使用 CouchDB 积累的一些经验基础上，我认为可以直接利用 Document API 提供的内置文档版本机制。显然很多人都有过这个想法，因为 wiki 上有一篇《Document Revisions》的条目，给出了一个相当直白的警告：

除了并发控制之外，你不能将文档修订版（revision）用于任何其他目的。

在思考版本控制方案的过程中，我看到了一篇博客文章，它给出了一些很有帮助的建议，让我一下子解决了大约 80% 的问题：

{ "name": "erlang_gen_server", "version": 1 }

?startkey=["erlang_gen_server", "Z"]
&endkey=["erlang_gen_server", 0]
&decending=true&count=1

?startkey=["erlang_gen_server"]
&endkey=["erlang_gen_server", "Z"]
为每个文档创建一个 version 属性。让视图返回类似 ["erlang_gen_server", 1] 这样的键。每次模板更新时，先获取最新的修订版本，将其 version 加一，然后创建一个新的 CouchDB 文档作为新版本，键为 ["erlang_gen_server", N+1]。使用以下方式获取所有版本：使用以下方式获取特定版本：?key=["erlang_gen_server", 2]

正如我之前提到的，这样做已经让我完成了大约 80% 的工作，但我仍然面临一个明显的问题：CouchDB-Lucene 以及我为语言和标签创建的视图，会把模板的每个版本都当作独立文档来处理。这导致搜索 “Erlang” 时会返回 erlang_couchdb_app 的十几个不同版本，这让网站几乎无法正常使用。我的解决办法是在所有文档中增加一个 latest 属性：

{ "name": "erlang_gen_server", "version": 2, "latest": true}
{ "name": "erlang_gen_server", "version": 1, "latest": false}

每次模板更新时，我会把之前标记为 latest 的版本改为 latest=false，然后创建新的版本并将其 latest 设置为 true。在此基础上，我更新了标签、语言以及 CouchDB-Lucene 所使用的视图，让它们只输出最新的文档：

fun(doc) { if (doc.latest && doc.language) { emit(doc.language, doc); }}

虽然比预期多花了一些功夫（每次修改模板都需要更新两个文档，有些人可能会觉得难以接受），但这个方案让我能够同时兼顾两方面的需求：既保留了带版本的模板，又不会在不需要的地方暴露版本信息。
