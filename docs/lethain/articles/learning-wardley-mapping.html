学习 Wardley Mapping 的粗略笔记

2024-11-30 · 阅读原文

在我持续撰写一本关于工程战略的书的过程中，我终于到了需要把“Wardley Mapping”从“考虑是否纳入”的主题，转变为“决定纳入或不纳入”的阶段。第一步就是要深入理解它的工作原理。这与我已经在工作中断断续续使用了 15 年多的 使用系统建模来完善策略 相当不同，但我会认真尝试一下。

我的起点是读完了 David Anderson 的《The Value Flywheel Effect》，并尝试过几次但未能成功读完 Simon Wardley 在 Medium 上连载的《Wardley Maps》。让我们看看进展如何。

Markus 给我推荐了他整理的优秀 Wardley Mapping 资源清单。Mike Lamb 的《What Is Wardley Mapping?》是一篇快速、高层次的概念介绍。《The Easiest Way to Do Wardley Mapping (A Tutorial)》是一个很好的入门起点。在这个示例中，提供了两个可供使用的模板：列表与价值链模板，以及 Wardley Map 模板。你可以把这些模板导入自己喜欢的绘图工具中使用，视频里用的是 Miro，而我用的是 OmniGraffle。它还链接到一个表格，用于确定 Wardley Map 中某项活动的阶段，以及另一个描述机会的表格。这两个表格在创建和完善 Wardley Map 的各个步骤中都很有用。《How to read a Wardley Map》对上述内容稍有重复。《The Problem with Wardley Mapping》讨论了人们在使用 Wardley Maps 时经常陷入的各种误区：对方法和范围采取“要么全有要么全无”的态度。这篇文章根植于《Nobody Cares About Your Precious Framework》。首先，它描述了多种“Wardley mapping practices”，并说明一开始进行简化非常有价值。具体来说，先只构建用户和需求列表，而不是一次性尝试所有东西。其次，它指出一个用户可能有很多需求，可能有三四个用户，每个各有十个需求，这会让人不知所措。解决办法是先专注一个用户和一个需求，然后逐步扩展以验证其价值。YouTube 上的《Top 5 Wardley Mapping Tools in 2024》，同时也有对应的博客文章。在这些工具中，我特别感兴趣的是 damonsk/onlinewardleymaps，它采用了类似 Graphviz 的方法，让我想起自己为系统建模开发的 lethain/systems 实验。尽管如此，我可能会先试试 Mapkeep。我对系统建模工具的主要不满是它们使用起来非常 confusing，而 Mapkeep 似乎是这些 Wardley mapping 工具中上手成本最低的。Simon Wardley 在 YouTube 上的《Situation Normal, Everything Must Change》。这是一篇关于 Wardley mapping 的不错概览，虽然比较浅显，适合作为第一遍观看。YouTube 上的 Simon Wardley 《Wardley Mapping Part 1-4》。这是对上面《Situation Normal, Everything Must Change》内容的更详细介绍。前两部分与之前的演讲有些重复，但第三和第四部分带来了新内容，相当有用。Adrian Cockroft 的《Mapping Your Stack》。其中大部分内容与前面重复，但在 22:20 左右开始映射一个具体例子，我觉得非常有意思。Markus Harrer 的《Wardley Maps for Software Developers》。最有帮助的是它很快进入具体地图，并 walkthrough 了多个不同的例子。至此，我注册了 Mapkeep 的免费账号，并开始绘制地图。我的第一个项目是这篇，它让我有机会在一个简单的地图上反复练习，并观察过去四年里这个地图的演化。目前那篇文章仍处于草稿阶段，但仍然是一个很好的映射练习机会。我也认为，如果没有这张地图，我会更难形成和清晰表达自己的观点，这是一个很好的信号。接下来，我做了（例如，为什么它专注于全栈打包，而 Github 则采用支持最佳-of-breed 的解耦策略）。这个过程很快，也很有启发。它还让我更好地理解 Wardley mapping 适合探索哪类问题，以及在哪些问题上它没那么擅长深入挖掘。衡量开发者体验、基准测试，以及提供改进理论。Gitlab 战略的 Wardley Mapping

到了这个阶段，我已经相当自在地打开 Mapkeeper 并开始绘制地图了。这并不是说我不能再提升——我肯定还有很大进步空间——但我的感觉是，这主要取决于多做地图练习，而不是依赖某种顿悟式的神奇领悟。

Wardley Mapping 还捆绑了很多其他内容，我也认为其中不少非常有用，但对我而言，并没有我在这里重点关注的那些部分那么重要。例如，Wardley 提出的 doctrine 和 gameplay 概念都很棒，但我通常会把这类东西看作“某一种特定的战略”，而不是一个完全不同的类别。这并不是对 Wardley 框架的否定，只是我找到了一个对我当前关注的问题来说更有用的不同视角。
