在 Cappuccino 中扩展类

2008-09-07 · 阅读原文

我发现 Cappuccino 最棒的一点就是它易于定制。人们通常认为大型框架会限制你的选择，但如果设计良好，它们也能以一种快速简便的方式暴露定制逻辑，让你能够创建完全符合自己需求的 widget。

在我开发 Mahou 第一个版本时，一直找不到一种直观的方式在应用内提供超链接。Cappuccino 专注于应用开发，与互联网的整体兼容性并不特别好（不过，这只是 widget 创建的问题，并非无法逾越的障碍）。

我对点击问题的解决方案是继承 CPTextField，创建一个点击后会跳转到任意 URL 的文本框。我将用这个简单的例子来简要介绍如何扩展 Cappuccino。

import <Foundation/CPObject.j>
import <AppKit/CPTextField.j>
@implementation WLURLLabel : CPTextField {}
-(void)mouseDown:(CPEvent)anEvent {
window.open("http://lethain.com");
}
@end

import <Foundation/CPObject.j>
import <AppKit/CPTextField.j>
@implementation WLURLLabel : CPTextField {
CPString _url;
}
-(void)mouseDown:(CPEvent)anEvent {
window.open([self url]);
}
-(CPString)url {
return _url;
}
-(void)setUrl: (CPString)aString {
_url = aString;
}
@end

var myFrame = CGRectMake(0,0,100,30);
var label = [[WLURLLabel alloc] initWithFrame:myFrame];
[label setStringValue:@"Click here to visit Google."];
[label setUrl:@"http://www.google.com"];
[label setFont[CPFont boldSystemFontOfSize:12.0]];
// changing color makes links more obvious
[field setTextColor:[CPColor whiteColor]];
[contentView addSubview:label];
扩展 Cappuccino 的第一步是确定要继承哪个类。Cappuccino 的文档非常优秀，能帮助你了解各种可供选择的类。选好要继承的类之后，你还需要确定在继承树中的哪个位置进行子类化。例如，CPTextField 的继承链相当长：CPObject -> CPResponder -> CPView -> CPControl -> CPTextField。通常的做法是沿着继承树向上查找，寻找合适的方法。不同的类侧重于不同的功能子集（CPView 负责尺寸和位置，CPResponder 负责 UI 事件，CPControl 负责 UI 显示等）。在我的例子中，我知道想要重写的功能位于 CPResponder 类中，因为我需要自定义对 UI 事件的响应。我们继续细化，找出具体要重写的方法。对我来说，这个文本框需要在被点击时执行操作，因此我浏览了文档，决定重写 mouseDown: 或 mouseUp 方法。在抛硬币（并权衡了 UI 响应速度与“最小惊讶原则”）之后，我最终选择了 mouseDown:。最后，我们需要实现具体功能。我们希望打开一个新窗口来加载特定的网页。我在 Objective-J 中没有找到直接的方法，但幸运的是我知道如何用 JavaScript 实现，而 Objective-J 是 JavaScript 的超集，所以任何能在 JavaScript 中做的事，都能在 Objective-J 中完成。第一版 Objective-J 代码如下所示：不过，我很可能需要不止一个可点击链接，因此硬编码 URL 显然不够灵活。于是我花了五分钟时间把代码改写成可复用的形式。啊，访问器和修改器带来的快乐在 Cappuccino 中就像在 Cocoa 中一样无处不在。最后一步是在代码中使用 WLURLLabel，大致如下：

总的来说，在 Cappuccino 中定制内容是一个相当简单的过程。从这个简单例子中不容易看出的是，即使进行大型且看似复杂的修改，也会遵循完全相同的模式。

这里体现的许多优势单纯得益于 Objective-J 的 import 机制。拥有一个条理清晰的导入机制，能让你轻松地将代码分散到多个组织良好的文件中，从而让代码更易复用，修改也更快捷。
