在 Python 中为 Slack 应用添加 App Home

2019-11-08 · 阅读原文

在 在 GCP 上用 Python 创建 Slack 应用 的基础上，我想继续扩展 reflect-slack-app，为其加入 App Home 功能。

App Home 界面允许工作区中的每位用户拥有一个由应用驱动的个性化视图，应用可以在其中分享任何想展示的数据或交互元素（按钮等）。想让用户配置应用设置？可以实现！想让用户查看最近的活动？可以实现！想让用户了解所有进行中项目的当前状态？也可以实现！

该功能目前处于 Beta 阶段。在开始研究这个 API 之前，我其实并不知道它的存在，尽管我一直希望有这样的功能。对我来说，App Home 的概念特别有吸引力，因为它是一个绝佳的机制，既可以（a）为用户汇总信息，又可以（b）提升应用功能的发现性。

它也代表着从聊天机器人和 Slash Command 驱动的交互，向更丰富、更接近 Web 风格的体验迈出了有意义的一步。好了，接下来我们进入具体的集成环节。

本文从 commit 5359 开始，到 commit 4120 结束。

启用 App Home

第一步是在应用仪表盘中为 App Home 功能进行注册。

由于该功能仍处于 Beta 阶段，系统会显示免责声明，提醒你它可能发生变化。你必须接受它。

App Home 需要一个 Bot User，但我们不会用它来实现任何聊天机器人功能，也不会让用户向机器人发送消息（他们将继续使用 /reflect 和 /recall 这两个 Slash Command），因此可以直接禁用“Messages Tab”，以免造成混淆。

现在我们已经设置好了 App Home，接下来该如何真正渲染它呢？

注册 app_home_opened 事件

我们需要从 Events API 注册 app_home_opened 事件。这意味着我们必须先集成 Event APIs，才能继续后续工作。

第一步是在应用仪表盘中启用 Events API。

启用 Events API 后，下一步是设置 Request URL。这又需要先为 url_verification 事件创建一个处理器。当我们添加 URL 后，Slack 会发送一条以 application/json 编码的消息（与 Slash Command 使用的 application/x-www-form-urlencoded 不同）。

{
  "token": "random token",
  "challenge": "challenge to return",
  "type": "url_verification"
}

这条消息中包含一个 challenge 键值对，我们需要将其值原样返回在一个 JSON 消息中。

{
  "challenge": "challenge to return"
}

为了启动集成，我们现在切换到 lethain/reflect-slack-app 代码仓库，从 commit 3aa6 开始，打开 reflect/main.py 文件，新增一个函数：

def event_post(request):
    signing_secret = os.environ['SLACK_SIGN_SECRET'].encode('utf-8')
    verify(request, signing_secret)

    parsed = request.json
    challenge = parsed['challenge']
    return jsonify({"challenge": challenge})

注意我们使用了 Python 和 Flask 中的 HMAC SHA256 签名 来验证请求的真实性。验证请求签名是来自 Slack 的“现代”验证方式。还有一种较旧的方法是使用 url_verification 事件发送的 token 参数。如果使用那种已被废弃的方式，你需要捕获提供的 token（上面例子中的随机 token），并验证后续所有请求都带有该 token。由于我们使用的是请求签名验证，因此可以安全地忽略这个 token。

现在我们需要创建一个新的 Cloud Function 来提供 event_post 函数。

> gcloud functions deploy event_post \
--env-vars-file env.yaml \

--trigger-http

> y

这会返回一个类似以下的 URL：

https://your-app-here.cloudfunctions.net/event_post

我们将这个 URL 添加到应用仪表盘的 Events Subscriptions 标签页中。

当你粘贴 URL 后，Slack 会自动进行验证，如果成功，会在上方显示“Verified”；如果失败，则会在下方显示非常有帮助的调试信息，包括你的端点返回的意外响应。

URL 验证通过后，打开“Subscribe to bot events”，订阅 app_home_opened 事件。

最后，你必须点击底部的“Save Changes”。这一步很容易被忽略，如果你不小心关闭标签页而没有保存，就得把这些步骤全部重做一遍。

重新安装应用

现在我们已经启用了 App Home 和 Event Subscriptions，需要重新安装应用以申请这些额外的权限。

这时神奇的事情发生了：如果你回到已安装该应用的工作区，搜索应用名称，就会发现应用的 App Home 已经可用了。

点击它，让我们开始吧。

从 Events API 路由事件

第一次加载 App Home 时界面有点简陋，只显示一个“正在开发中”的画面。我们最终会修复这个问题，但这需要几个步骤。

首先，我们需要处理每次用户访问应用 App Home 时发送的 app_home_opened 事件。Events API 有两层事件类型，因此 event_post 收到的请求结构如下：

{
  "type": "event_callback",
  "event": {
    "type": "app_home_opened",
    "other": "stuff"
  },
  "other": "stuff"
}

了解格式后，我们可以对 event_post 进行一些重构，将不同消息类型和事件类型的处理拆分开来。

def event_post(request):
    signing_secret = os.environ['SLACK_SIGN_SECRET'].encode('utf-8')
    verify(request, signing_secret)
    parsed = request.json
    event_type = parsed['type']
    if event_type == 'url_verification':
        return url_verification_event(request, parsed)
    if event_type == 'event_callback':
        return event_callback_event(request, parsed)
    else:
        raise Exception("unable to handle event type: %s" % (event_type,))

def url_verification_event(request, parsed):
    challenge = parsed['challenge']
    return jsonify({"challenge": challenge})

def event_callback_event(request, parsed):
    event_type = parsed['event']['type']
    if event_type == 'app_home_opened':
        return app_home_opened_event(request, parsed)
    else:
        raise Exception("unable to handle event_callback event type: %s" \
                        % (event_type,))

def app_home_opened_event(request, parsed):
    print(parsed)
    return "to be implemented"

现在你可能会想，我们只要更新 app_home_opened_event 函数，返回一些 Block Kit 元素就能渲染了，但事情没那么简单。我们的处理器需要调用 Slack Web API 中的 views.publish 方法。

调用 Web API

Slack 的 Web API 是一个相当典型的 HTTP API。在我们的场景中，需要向 views.publish 发送 POST 请求，地址为：

https://slack.com/api/views.publish

我们将发送 application/json 格式的请求体，大致如下：

{
  "user_id": "uuuuuuuuuuu",
  "view": {
    "type": "home",
    "blocks": [
      {
        "type": "section",
        "text": {
          "type": "mrkdwn",
          "text": "To be implemented"
        }
      }
    ]
  }
}

我们还需要在 HTTP 请求头中带上机器人的 token，你可以在应用仪表盘的“OAuth & Permissions” 标签页中找到它：

Authorization: Bearer xoxp-xxxxxxxxx-xxxx

我们首先扩展 reflect/env.yaml 文件，把这个 token 加进去：

SLACK_SIGN_SECRET: your-signing-secret-here
SLACK_BOT_TOKEN: your-bot-token

我们将使用 Python 的 requests 库向 Slack 的 API 发送请求。第一步是向仓库中添加 requests/requirements.txt 文件，让 Cloud Functions 知道我们的依赖：

requests==2.20.0

我们还希望在本地虚拟环境中安装它，以便进行任何本地验证（上次我们已经创建了虚拟环境）：

source ../venv/bin/activate
pip install requests==2.20.0

然后我们可以在 reflect/main.py 中编写一个工具函数来执行请求：

import requests

def slack_api(endpoint, msg):
    url = "https://slack.com/api/%s" % (endpoint,)
    bot_token = os.environ['SLACK_BOT_TOKEN'].encode('utf-8')
    headers = {
        "Authorization": "Bearer %s" % (bot_token.decode('utf-8'),),
        "Content-Type": "application/json; charset=utf-8",
    }
    resp = requests.post(url, json=msg, headers=headers)
    if resp.status_code != 200:
        raise Exception("Error calling slack api (%s): %s" % \
                        (resp.status_code, resp.content))
    return resp.json()

slack_api 函数中有几个细节值得一提。首先，我们设置了 Authorization 请求头来验证身份，如果没有正确设置，请求会失败。其次，如果不指定字符集，Slack API 会发出警告，因此我们确保 Content-Type 中包含字符集。

渲染我们的 App Home

现在有了这个工具函数，我们可以像下面这样调用它：

msg = {'some':' stuff'}
slack_api("views.publish", msg)

终于，当我们收到 app_home_opened 事件时可以做一些有意义的事情了——让它渲染的内容和 /reflect Slash Command 返回的内容基本一致：

def app_home_opened_event(request, parsed):
    user_id = parsed['event']['user']
    team_id = parsed['team_id']
    items = recall(team_id, user_id, "last 14 days")
    items_text = "\n".join(["%s. %s" % (i, x) \
                            for i, x in enumerate(items, 1)])
    blocks_spec = [
        ('mrkdwn', "Your home tab for Reflect"),
        ('divider',),
        ('mrkdwn', items_text),
        ('divider',),
        ('mrkdwn', "Some more stuff here"),
    ]
    blocks = [block(*x) for x in blocks_spec]
    msg = {
        "user_id": user_id,
        "view": {
            "type": "home",
            "blocks": blocks,
        }
    }
    resp = slack_api("views.publish", msg)
    return "OK"

让 App Home 真正有用起来

我们目前实现的功能还比较基础，但你可以想象这个概念能被扩展到什么程度。它可以用来配置 /recall 默认返回多少天的结果，可以用来创建一个“导出到邮件”的组件，可以显示过去三个月你记录的任务数量等等。

你甚至可以想象它注入一张个性化图片，里面是按标签统计的项目直方图之类的。虽然我不确定加载用户特定生成的图片的授权机制该怎么处理，而且查看 image block 的规范后，我怀疑目前还没有支持。

在玩具应用 Reflect 的背景下，我认为最重要的功能应该是展示最近添加的任务摘要，以及如何使用各种 Slash Command 的示例，以帮助用户更好地发现功能。
