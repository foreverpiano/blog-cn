在 Python Slack 应用中添加 App Home

2019-11-08 · 阅读原文

在 在 GCP 上用 Python 创建 Slack 应用 的基础上，我想继续扩展 reflect-slack-app，为其加入 App Home 功能。

App Home 界面允许工作空间中的每位用户拥有一个由应用驱动的个性化视图，应用可以在其中展示任何想要分享的数据或交互元素（按钮等）。想让用户配置应用设置吗？可以实现！想让用户查看最近的活动吗？可以实现！想让用户了解所有进行中项目的当前状态吗？也可以实现！

该功能目前处于 Beta 阶段。在我开始研究这个 API 之前，其实并没有意识到它的存在，尽管我一直希望有这样的功能。对我来说，App Home 的概念特别有吸引力，因为它是一个极好的机制，既可以（a）为用户汇总信息，又可以（b）提升应用功能的发现性。

它也代表着从聊天机器人和 Slash Command 驱动的交互，向更丰富、更接近 Web 的体验迈出的重要一步。好了，让我们开始集成吧。

本文从 commit 5359 开始，到 commit 4120 结束。

注册 App Home

第一步是在应用仪表盘中注册 App Home 功能。

由于该功能仍处于 Beta 阶段，系统会显示免责声明，提醒你它可能会有变动。你必须接受它。

App Home 需要一个 Bot User，但我们不会用它来实现任何聊天机器人功能，也不会让用户给机器人发消息（他们将继续使用 /reflect 和 /recall Slash Command），因此可以直接禁用“Messages Tab”，避免造成混淆。

现在我们已经设置好了 App Home，接下来如何实际渲染它呢？

注册 app_home_opened 事件

我们需要从 Events API 注册 app_home_opened 事件。这意味着我们必须先与 Event API 集成才能继续后续步骤。

第一步是在应用仪表盘中启用 Events API。

启用 Events API 后，下一步是设置 Request URL。这需要先为 url_verification 事件创建一个处理器。当我们添加 URL 时，Slack 会发送一个以 application/json 编码的消息（与 Slash Command 使用的 application/x-www-form-urlencoded 不同）。

{
  "token": "random token",
  "challenge": "challenge to return",
  "type": "url_verification"
}

该消息中包含一个 challenge 键值对，我们需要将其值原样返回在一个 JSON 消息中。

{
  "challenge": "challenge to return"
}

为了启动集成，现在我们切换到 lethain/reflect-slack-app 仓库，从 commit 3aa6 开始，打开 reflect/main.py 文件，添加一个新函数：

def event_post(request):
    signing_secret = os.environ['SLACK_SIGN_SECRET'].encode('utf-8')
    verify(request, signing_secret)

    parsed = request.json
    challenge = parsed['challenge']
    return jsonify({"challenge": challenge})

注意我们使用了 Python 和 Flask 中的 HMAC SHA256 签名 来验证请求的真实性。验证请求签名是来自 Slack 的“现代”验证方式。还有一种较旧的方法是使用 url_verification 发送的 token 参数。使用那种已被废弃的方法，你需要捕获提供的 token（上面示例中的随机 token），并验证后续所有请求都包含该 token。由于我们正在使用请求签名验证，因此可以安全地忽略 token。

现在我们需要创建一个新的 Cloud Function 来提供 event_post 函数。

> gcloud functions deploy event_post \
--env-vars-file env.yaml \
 --runtime python37 \
--trigger-http

Allow unauthenticated invocations of new function [event_post]? (y/N)?
> y
Deploying function (may take a while - up to 2 minutes)...

这会返回一个类似以下的 URL：

https://your-app-here.cloudfunctions.net/event_post

我们将这个 URL 添加到应用仪表盘的 Events Subscriptions 标签页中。

当你粘贴 URL 后，Slack 会自动验证它，要么在上方显示“Verified”，要么在下方展示一些非常有帮助的调试信息，包括你的端点返回的意外响应。

URL 验证通过后，打开“Subscribe to bot events”，订阅 app_home_opened 事件。

最后，你必须点击底部的“Save Changes”。这一步很容易被忽略，如果你不小心关闭标签页而没有保存，就得把这些步骤全部重做一遍。

重新安装应用

现在我们已经启用了 App Home 和事件订阅，需要重新安装应用以申请这些额外的权限。

这时神奇的事情发生了：如果你回到已安装该应用的 workspace 并搜索应用名称，就会发现应用的 App Home 已经可用。

点击它，我们就可以开始了。

从 Events API 路由事件

第一次加载 App Home 时会有些简陋，显示一个“正在开发中”的画面。我们最终会修复它，但这需要几个步骤。

首先，我们需要处理每次用户访问应用 App Home 时发送的 app_home_opened 事件。Events API 有两层事件类型，因此 event_post 收到的请求结构如下：

{
  "type": "event_callback",
  "event": {
    "type": "app_home_opened",
    "other": "stuff"
  },
  "other": "stuff"
}

了解格式后，我们可以稍微重构 event_post，将不同消息类型和事件类型的处理拆分开来。

def event_post(request):
    signing_secret = os.environ['SLACK_SIGN_SECRET'].encode('utf-8')
    verify(request, signing_secret)
    parsed = request.json
    event_type = parsed['type']
    if event_type == 'url_verification':
        return url_verification_event(request, parsed)
    if event_type == 'event_callback':
        return event_callback_event(request, parsed)
    else:
        raise Exception("unable to handle event type: %s" % (event_type,))

def url_verification_event(request, parsed):
    challenge = parsed['challenge']
    return jsonify({"challenge": challenge})

def event_callback_event(request, parsed):
    event_type = parsed['event']['type']
    if event_type == 'app_home_opened':
        return app_home_opened_event(request, parsed)
    else:
        raise Exception("unable to handle event_callback event type: %s" \
                        % (event_type,))

def app_home_opened_event(request, parsed):
    print(parsed)
    return "to be implemented"

如果我们部署这个更新版本，然后从 App Home 标签页切走再切回来，日志中就会包含完整的 app_home_opened 事件消息：

{
  'token': 'token-token-token',
  'team_id': 'tttttttttt',
  'api_app_id': 'aaaaaaaa',
  'event': {
    'type': 'app_home_opened',
    'user': 'uuuuuuuuuu',
    'channel': 'ccccccccc',
    'tab': 'home'
  },
  'type': 'event_callback',
  'event_id': 'eeeeeeeeee',
  'event_time': 1500000000
}

现在，你可能会想我们只需更新 app_home_opened_event 函数返回一些 Block Kit 元素就能渲染，但事情并没有这么简单。我们的处理器需要调用 Slack Web API 中的 views.publish 方法。

调用 Web API

Slack 的 Web API 是一个相当典型的 HTTP API。在我们的场景中，需要向以下地址发送 POST 请求来调用 views.publish：

https://slack.com/api/views.publish

我们将发送 application/json 格式的请求体，大致如下：

{
  "user_id": "uuuuuuuuuuu",
  "view": {
    "type": "home",
    "blocks": [
      {
        "type": "section",
        "text": {
          "type": "mrkdwn",
          "text": "To be implemented"
        }
      }
    ]
  }
}

其中的每个 block 都符合我们之前 在 GCP 上用 Python 创建 Slack 应用 时使用的格式。

我们还需要在 HTTP Header 中附带机器人的 token，你可以在应用仪表盘的 OAuth & Permissions 标签页中找到它：

Authorization: Bearer xoxp-xxxxxxxxx-xxxx

我们首先扩展 reflect/env.yaml 来包含这个 token：

SLACK_SIGN_SECRET: your-signing-secret-here
SLACK_BOT_TOKEN: your-bot-token

我们将使用 Python 的 requests 库向 Slack 的 API 发送请求。第一步是在仓库中添加 requests/requirements.txt，让 Cloud Functions 能识别我们的依赖：

requests==2.20.0

我们还想在本地安装它，以便在之前创建的虚拟环境中进行任何本地验证：

source ../venv/bin/activate
pip install requests==2.20.0

然后我们可以在 reflect/main.py 中编写一个工具函数来发起请求：

import requests

def slack_api(endpoint, msg):
    url = "https://slack.com/api/%s" % (endpoint,)
    bot_token = os.environ['SLACK_BOT_TOKEN'].encode('utf-8')
    headers = {
        "Authorization": "Bearer %s" % (bot_token.decode('utf-8'),),
        "Content-Type": "application/json; charset=utf-8",
    }
    resp = requests.post(url, json=msg, headers=headers)
    if resp.status_code != 200:
        raise Exception("Error calling slack api (%s): %s" % \
                        (resp.status_code, resp.content))
    return resp.json()

slack_api 函数中有几点值得一提。首先，我们设置了 Authorization 请求头来验证身份，如果没有正确设置，请求会失败。其次，如果不指定字符集，Slack API 会发出警告，因此我们确保 Content-Type 中包含字符集。

渲染我们的 App Home

现在有了这个工具函数，我们可以像下面这样调用它：

msg = {'some':' stuff'}
slack_api("views.publish", msg)

终于，当收到 app_home_opened 事件时，我们可以做一些有意义的事情，让它渲染的内容与通过 /reflect Slash Command 返回的内容大致相同：

def app_home_opened_event(request, parsed):
    user_id = parsed['event']['user']
    team_id = parsed['team_id']
    items = recall(team_id, user_id, "last 14 days")
    items_text = "\n".join(["%s. %s" % (i, x) \
                            for i, x in enumerate(items, 1)])
    blocks_spec = [
        ('mrkdwn', "Your home tab for Reflect"),
        ('divider',),
        ('mrkdwn', items_text),
        ('divider',),
        ('mrkdwn', "Some more stuff here"),
    ]
    blocks = [block(*x) for x in blocks_spec]
    msg = {
        "user_id": user_id,
        "view": {
            "type": "home",
            "blocks": blocks,
        }
    }
    resp = slack_api("views.publish", msg)
    return "OK"

让 App Home 变得更有用

我们目前实现的功能还比较基础，但你可以想象在这个概念上走得更远。它可以用来配置 /recall 默认返回多少天的结果，可以用来创建一个导出到邮件的小工具，可以显示过去三个月你记录的任务数量，等等。

你甚至可以想象它注入一张个性化图片，展示按标签统计的项目直方图之类的。不过我不太确定加载用户特定生成图片的授权机制会如何，而且查看 image block 的规范后，我怀疑目前还没有支持。

在玩具应用 Reflect 的背景下，我认为最重要的功能是展示最近添加的任务摘要，并给出如何使用各种 Slash Command 的示例，以帮助提升功能的可发现性。
