我们自己的智能体及其专属工具

2025-02-04 · 阅读原文

进入2025年，我决定花些时间深入探索智能体（agents）这个主题。我先阅读了Anthropic的《Building effective agents》，接着又看了Chip Huyen的《AI Engineering》。我在工作中启动了一个使用智能体的大型项目，同时也决定做一个个人的小实验。本文就是关于构建这个项目的总体心得。

我想构建的是一个简单的聊天界面，能够输入提示词、选择模型，并让模型根据需要自主调用工具。我的次要目标是尽量使用Cursor来开发，尽可能少直接手写代码。但实际体验下来，我发现直接在emacs里写代码、同时让4o-mini提供可用的示例代码，反而效率更高。

同样，我一开始设想用Cursor全程以全栈TypeScript来开发，但最终还是切换到了自己更熟悉的技术栈，最终采用了Python 3、FastAPI、PostgreSQL，以及搭配异步psycopg3驱动的SQLAlchemy。我已经很久没有从零开始一个新的Python项目了，于是把这个项目当作机会，熟悉了Python 3的async/await机制、类型系统以及mypy的使用。最后，我也想尝试Tailwind，最终使用了TailwindUI的组件来构建界面。

最终完成的版本支持我想要的一切功能：创建与不同模型的聊天会话，并允许这些模型通过函数调用来使用我提供的工具。模型可以为了解决问题而调用任意数量的工具。其中工具的使用绝对是最有趣的部分。我创建的最简单的工具是一个get_temperature工具，它能为你的位置提供一个虚拟的温度读数。这让我可以问出类似“明天在加州旧金山我该穿什么？”这样的问题，并得到有用的回答。

将这个功能添加到项目中的代码非常简洁，只需要三行Python代码，再加上25行传递给OpenAI API的元数据。

def tool_get_current_weather(location: str|None=None, format: str|None=None) -> str:
    "Simple proof of concept tool."
    temp = random.randint(40, 90) if format == 'fahrenheit' else random.randint(10, 25)
    return f"It's going to be {temp} degrees {format} tomorrow."

在实现这个工具之后，我接下来添加的是一个简单的URL获取工具，它允许智能体抓取一个URL，并将其内容纳入提示词中。

这个工具的实现同样非常简单。

def tool_get_url(url: str|None=None) -> str:
    if url is None:
        return ''
    url = str(url)

    response = requests.get(url)
    soup = BeautifulSoup(response.content, 'html.parser')
    content = soup.find('main') or soup.find('article') or soup.body
    if not content:
        return str(response.content)

    markdown = markdownify(str(content), heading_style="ATX").strip()
    return str(markdown)


FUNCTION_REGISTRY['get_url'] = tool_get_url
TOOL_USAGE_REGISTRY['get_url'] = {
    "type": "function",
    "function": {
        "name": "get_url",
        "description": "Retrieve the contents of a website via its URL.",
        "parameters": {
            "type": "object",
            "properties": {
                "url": {
                    "type": "string",
                    "description": "The complete URL, including protocol to retrieve. For example: \"https://lethain.com\"",
                }
            },
            "required": ["url"],
        },
    }
}

令人惊叹的是，通过添加一个像获取URL这样看似微不足道的工具，你就能为智能体赋予巨大的能力。你可以想象再加入获取和评论GitHub Pull Request的工具等等，这类简单的智能体工具就能变得相当实用。

通过这个项目，我对不久的将来有了一个颇为清晰的想象：大多数工程师都会运行一个类似这样的简单应用，他们可以将来自各种系统（邮件、短信、GitHub Pull Request、日历等）的事件导入其中，创建触发器将事件映射到提示词模板，再让具备工具调用能力的智能体来执行这些提示。

如果再结合其他智能体能够向你注册并暴露它们可用的工具（例如“帮工具所有者安排一个日程”），那么只需非常适度的投入，就能实现许多有趣的功能：

为两个忙碌的人的日历安排会议，就像他们各自都有助理在管理日程一样；用新发布的博客文章回复你自己的Pull Request，并对错别字和语法问题提供反馈；抓取你关注的网站，找出你可能感兴趣的文章；让模型使用lethain:systems生成一个系统模型，运行它，然后绘制结果图表；添加一个“规划工具”，让模型先生成一个计划，来指导复杂任务的后续步骤（例如获取我的日历、获取朋友的日历，然后建议一个合适的见面时间）。

这些功能都不是能改变人生的，但每一项都多少有些用处。我相信，一旦你具备了让这类事情变得简单的必要基础架构，还会有更多显而易见的好想法变得容易实现。

总的来说，我现在确信，基于当前基础模型的智能体将会创造出许多非常有趣的体验，在日常生活的一些小事上给我们带来改善，而这些改善累积起来，会相当具有变革性。不过，我不太确定这是否就是未来所有软件都应该采用的方式，这一点我以后会继续思考。（目前在工作中也正在进行一些有趣的实验，但还处于早期阶段。）
