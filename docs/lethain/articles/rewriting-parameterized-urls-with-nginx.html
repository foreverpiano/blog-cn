使用 Nginx 重写带参数的 URL

2009-02-16 · 阅读原文

上周日（以及今天凌晨），我的目标是彻底关闭旧的 WordPress 博客，将有价值的内容重新发布到这个博客上，并完成我一直害怕的那一步——在新旧博客之间设置重定向。

使用 Nginx 处理这些重定向有些棘手，因为我的 WordPress URL 是这样的：

http://willarson.com/blog/?p=3
http://willarson.com/blog/?p=41

完全称不上美观的 URL。人们谈论重写 pretty URL 时，通常指的是将下面这种格式的 URL：

http://willarson.com/blog/3/

转换成 /p=3 这样的形式，但反方向的操作却很少被讨论。特别是在 Nginx 上，其 rewrite 模块的资料远不如 Apache 的 mod_rewrite 丰富。在仔细阅读了 Nginx Http Core Module 文档后，我终于想出了一个解决方案。

以下是 willarson.com 稍作泛化的 server 配置：

   <span class="kn">location</span> <span class="s">/</span> <span class="p">{</span>
            <span class="kn">root</span> <span class="s">/home/django/domains/willarson.com/public</span><span class="p">;</span>
            <span class="kn">index</span> <span class="s">index.html</span><span class="p">;</span>
    <span class="p">}</span>

这里的关键是 set $p $1; 这行。在较新版本的 Nginx 中（至少比 Ubuntu Intrepid 打包的版本新），你可以跳过这一步，直接使用 $arg_p（也可能是 $arg_P，文档对此表述不清）。

它以一种丑陋但有效的方式，将类似下面的 URL

http://willarson.com/blog/?p=17

http://willarson.com/redirect/17/?p=17

重写。虽然这看起来挺糟糕，但对我非常简单的需求来说已经足够了。之后我又写了一个同样不怎么优雅的 Python 脚本用来生成重定向页面。

import sys
url = sys.argv[1]
print """
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
"http://www.w3.org/TR/html4/strict.dtd">
<html>
<head>
<link rel="canonical" href="%s"> 
<script type="text/javascript">
<!--
window.location = "%s"
//-->
</script>
<meta http-equiv="Refresh" content="5; url=%s">
</head>
<body>
<h2>You will be redirected shortly. Sorry for the inconvenience.</h2>
<a href="%s">Click here to transition more quickly.</a>
</body>
</html>
""" % (url, url, url, url)

（我决定使用新的 canonical meta tag，是因为它更新且时髦，希望能帮助把旧博客的 Google 权重顺利转移到新博客上。让我们拭目以待。）

然后我为每篇文章确定了从旧博客到新博客的映射关系（旧博客总共只有大约 27 篇文章，其中 9 篇值得重新发布，5 篇值得定向重定向到更新的内容，其余则全部重定向到新博客首页。大致原则是：有流量的内容都做了定制重定向指向相关新内容，而那些“文字垃圾”则统一跳转到首页）。

接着我为每个页面做了类似下面的设置：

cd ~/domains/willarson.com/public/
mkdir 17
python create_redirect http://lethain.com/etc/etc/ > 17/index.html

你可以点击试试看。

至此，全部搞定。
