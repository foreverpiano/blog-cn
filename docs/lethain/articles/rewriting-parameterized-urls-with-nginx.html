使用 Nginx 重写带参数的 URL

2009-02-16 · 阅读原文

上周日（以及今天凌晨的一部分时间），我的目标是彻底关闭旧的 WordPress 博客，将有价值的内容重新发布到这个博客上，并完成我一直最害怕的那一步——在新旧博客之间设置重定向。

使用 Nginx 处理这些重定向最终变得有些棘手，因为我 WordPress 的 URL 是这样的：

http://willarson.com/blog/?p=3
http://willarson.com/blog/?p=41

一点也不友好。当人们谈论重写美观的 URL 时，他们指的是将这种格式的 URL：

http://willarson.com/blog/3/

转换成 /p=3 这样的格式，但反向转换却很少被讨论。尤其是 Nginx，它的 rewrite 模块得到的关注远少于 Apache 的 mod_rewrite。在仔细阅读了 Nginx Http Core Module 文档后，我终于想出了一个解决方案。

它以其丑陋而强大的方式，将类似下面的 URL

http://willarson.com/blog/?p=17

http://willarson.com/redirect/17/?p=17

这看起来相当糟糕，但对于我非常简单的需求来说已经足够了。之后我又写了一个同样丑陋的 Python 脚本用来生成重定向页面。

（我决定使用新的 canonical meta tag，因为它既新又亮眼，希望能帮助把旧博客的 Google 权重转移到新博客上。让我们拭目以待。）

然后我为每篇文章确定了从旧博客到新博客的映射关系（旧博客总共只有大约 27 篇文章，其中 9 篇值得重新发布，5 篇值得定向重定向到更新的内容，其余的则统一重定向到新博客首页。大体上，有流量的内容都获得了指向相关页面的定制重定向，而纯文字垃圾内容则使用通用的首页重定向）。
