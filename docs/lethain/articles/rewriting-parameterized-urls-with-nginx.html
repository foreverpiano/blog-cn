使用 Nginx 重写带参数的 URL

2009-02-16 · 阅读原文

上周日（以及今天凌晨的一部分时间），我的目标是彻底淘汰我的旧 WordPress 博客，把有价值的内容重新发布到这个博客上，同时——这是我一直最害怕的一步——在新旧博客之间设置重定向。

使用 Nginx 处理这些重定向有些棘手，因为我的 WordPress URL 是这样的：

http://willarson.com/blog/?p=3
http://willarson.com/blog/?p=41

一点都不美观。当人们谈论重写 pretty URL 时，他们指的是将这种格式的 URL：

http://willarson.com/blog/3/

转换成 /p=3 这样的形式，但反向操作却很少被讨论。尤其是 Nginx，它的 rewrite 模块受到的关注远少于 Apache 的 mod_rewrite。在仔细阅读了 Nginx Http Core Module 文档之后，我总算想出了一个解决方案。

以下是 willarson.com 经过（稍作泛化）的 server 配置：

server {
       listen *:80;
       server_name www.willarson.com willarson.com;
       if ($args ~ "p=(.*)") {
              set $p $1;
              rewrite ^/blog/?(.*)$  /redirect/$p/ permanent;
       }
       access_log /home/django/domains/willarson.com/log/access.log;
       error_log /home/django/domains/willarson.com/log/error.log;
   <span class="kn">location</span> <span class="s">/</span> <span class="p">{</span>
            <span class="kn">root</span> <span class="s">/home/django/domains/willarson.com/public</span><span class="p">;</span>
            <span class="kn">index</span> <span class="s">index.html</span><span class="p">;</span>
    <span class="p">}</span>
}
   <span class="kn">location</span> <span class="s">/</span> <span class="p">{</span>
            <span class="kn">root</span> <span class="s">/home/django/domains/willarson.com/public</span><span class="p">;</span>
            <span class="kn">index</span> <span class="s">index.html</span><span class="p">;</span>
    <span class="p">}</span>

关键在于 set $p $1; 这一行。在较新版本的 Nginx 中（至少比 Ubuntu Intrepid 打包的版本新），你可以跳过这一步，直接使用 $arg_p（也可能需要 $arg_P，文档对此表述并不清晰）。

它以其丑陋而又辉煌的方式，将类似下面的 URL

http://willarson.com/blog/?p=17

http://willarson.com/redirect/17/?p=17

这种做法相当丑陋，但对于我非常简单的需求来说已经足够了。之后我又写了一个同样简陋的 Python 脚本用来生成重定向页面。

import sys
url = sys.argv[1]
print """
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
"http://www.w3.org/TR/html4/strict.dtd">
<html>
<head>
<link rel="canonical" href="%s"> 
<script type="text/javascript">
<!--
window.location = "%s"
//-->
</script>
<meta http-equiv="Refresh" content="5; url=%s">
</head>
<body>
<h2>You will be redirected shortly. Sorry for the inconvenience.</h2>
<a href="%s">Click here to transition more quickly.</a>
</body>
</html>
""" % (url, url, url, url)

（我决定使用新的 canonical meta 标签，因为它比较新颖，而且有望帮助把旧博客的 Google 权重转移到新博客上。让我们拭目以待。）

然后我为每篇文章确定了从旧博客到新博客的映射关系（旧博客总共只有大约 27 篇文章，其中 9 篇值得重新发布，另外 5 篇值得定向重定向到更新的内容，其余的则统一重定向到新博客首页。大体上，有流量的内容都会得到一个指向相关页面的定制重定向，而那些“文字垃圾”则采用通用的首页重定向）。

接着我为每一页做了类似下面的设置：

cd ~/domains/willarson.com/public/
mkdir 17
python create_redirect http://lethain.com/etc/etc/ > 17/index.html

你可以实际试试看。

这就是整个故事。
