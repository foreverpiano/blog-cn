开始使用 git-scraping

2022-02-27 · 阅读原文

在 Github 上查看本文对应的代码。

我母亲在一家食品救助站工作，他们最近遇到了一个有趣的后勤难题：另一家非营利组织会捐赠几乎免费的肉类，但只有在对方更新网站后才能下单，而且必须在网站更新后的几个小时内尽快完成下单。对于熟悉现代商业环境的人来说，这类问题并不难解决——市面上有很多监控网站的供应商，价格也合理；但如果你从未接触过相关领域，这就会显得相当令人畏惧。

对大多数人来说，更好的方案是找一家现有的供应商来解决这个问题，但我决定是时候深入研究一下 Simon Willison 的 git-scraping 工作了！

我的目标很简单：

将网页的变化以 Git 提交的形式记录到 Github 仓库中，让非开发人员也能轻松订阅这些变化

好，接下来我们正式开始。

追踪变化

我不想把那家非营利组织的网站公之于众，所以我将用自己的一个网站作为示例，原理是一样的。具体来说，我会抓取 infraeng.dev 这个站点。

第一步，我在 Github 上创建了一个新的仓库。

于是我就得到了一个全新的、空空如也的仓库。

接着我把仓库克隆下来，并创建了 Github Workflow 的目录。

git clone git@github.com:lethain/infraeng-changes.git    
mkdir -p .github/workflows
emacs .github/workflows/scrape.yml

然后我参照 ca-fires-history/.github/workflows/scrape.yml 中的示例工作流，创建了 .github/workflows/scrape.yml 文件。唯一的改动是将第 17 行的内容从：

curl https://www.fire.ca.gov/umbraco/Api/IncidentApi/GetIncidents | jq . > incidents.json

改成指向 infraeng.dev

curl https://infraeng.dev/ > website.html

我提交了这个改动并推送到 Github，这个最简单的版本就运行起来了！

更干净的抓取方式

虽然上面能用，但它假设阅读者熟悉 HTML，而在这个场景中这个假设并不成立。因此我想写一个简单的脚本，从网站中提取目录并将其转换成纯文本表格。

通常我可能会使用 beautifulsoup 来完成这件事，但这次我想不依赖任何第三方库，所以改用 Python 3 自带的 html.parser 模块。

你可以在这里看到这个大约 30 行的 Python 清理脚本。

然后我把 .github/workflows/scrape.yml 中第 17 行改成调用这个脚本：

curl https://infraeng.dev/ | python clean.py > table-of-contents

现在它不再输出完整的 HTML，而是生成一个干净得多的目录文件！这是一个简洁、人类可读的文件，即使网站页眉或页脚发生变化也能保持稳定，同时很好地追踪目录内容的任何改动。

通知机制

现在我们有了一个不错的变化日志，如何才能让其他人订阅这些变化呢？

最简单的方案是直接在提交 feed 后面加上 .atom，例如 infraeng-changes/commits/main.atom，然后把这个地址丢进 RSS 阅读器里。对习惯使用 RSS 阅读器的人来说，这很合适。但遗憾的是，很多人并没有 RSS 阅读器。

另一个直接的方案是让大家注册一个 Github 账号，然后“关注（watch）”这个仓库来接收变化通知。

如果我们想进一步做到 SMS 短信通知，这篇博客文章中的方案可以实现，它依赖 Twilio 的 action-sms action。

我已经把这个 workflow 禁用了，但你仍然可以在 Github 上看到完整的代码。
