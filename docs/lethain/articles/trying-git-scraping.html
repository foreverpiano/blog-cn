开始使用 git-scraping

2022-02-27 · 阅读原文

可以在 Github 上查看这篇文章的代码。

我母亲在一家食品救助站工作，他们最近遇到了一个有趣的后勤难题：他们能从另一家非营利组织那里获得几乎免费的肉类捐赠，但必须等到对方更新网站后才能下单，并且需要在网站更新后的短时间内（几小时内）完成订购。如果你熟悉现代商业环境的工作流程，这类问题很容易解决——市面上有不少按合理价格提供网站监控服务的供应商。但如果你没有相关领域的工作经验，这会是一个相当令人生畏的问题。

对大多数人来说，更好的方案是找一家现成的供应商来解决这个问题，但我决定是时候深入研究一下 Simon Willison 的 git scraping 工作了！

我的目标非常直接：

将网页的变化以 Git commit 的形式记录到 Github 仓库中，让非开发者也能轻松订阅这些变化

好了，我们开始吧。

跟踪变化

我不想把那家非营利组织的网站公之于众，所以我用自己的一个网站作为替代示例，原理是一样的。具体来说，我会抓取 infraeng.dev 这个站点。

第一步，我在 Github 上创建了一个新的仓库。

这样我就得到了一个全新的、空白的仓库。

接下来我检出这个仓库，并创建了 Github workflow 目录。

git clone git@github.com:lethain/infraeng-changes.git    
mkdir -p .github/workflows
emacs .github/workflows/scrape.yml

然后我创建了 .github/workflows/scrape.yml 文件，参考了 ca-fires-history/.github/workflows/scrape.yml 中的示例工作流。唯一的改动是把第 17 行的内容从：

curl https://www.fire.ca.gov/umbraco/Api/IncidentApi/GetIncidents | jq . > incidents.json

改成指向 infraeng.dev

curl https://infraeng.dev/ > website.html

我提交了这个改动并推送到 Github，这个简单的版本就能正常工作了！

更干净的抓取方式

虽然上面能用，但它假设读者熟悉 HTML，而在这个场景下这个假设并不安全。所以我希望写一个简单的脚本，从网站中提取目录并将其转换为纯文本表格。

通常情况下我会使用 beautifulsoup 来完成这件事，但我想避免引入任何第三方依赖，因此这次改用 Python 3 内置的 html.parser 库。

你可以在这里看到这个大约 30 行的 Python 清理脚本。

接着我把 .github/workflows/scrape.yml 的第 17 行更新为使用这个脚本：

curl https://infraeng.dev/ | python clean.py > table-of-contents

现在它不再生成完整的 HTML，而是生成一个干净得多的 table-of-contents 文件！这是一个简单、人类可读的文件，对页眉和页脚的变化具有较强的抗干扰性，同时能很好地跟踪目录内容的任何修改。

通知机制

现在我们有了一个清晰的变化日志，如何让大家能够订阅这些变化呢？

最简单的方案是直接在提交 feed 后面加上 .atom，例如 infraeng-changes/commits/main.atom，然后把它丢进 RSS 阅读器里。对于熟悉 RSS 阅读器的人来说，这已经足够好用了。但遗憾的是，很多人都没有 RSS 阅读器。

另一个直接的方案是让大家注册一个 Github 账号，然后“关注（watch）”这个仓库来获取更新。

如果我们想进一步做到短信通知，这篇博客文章中的方案可以直接使用，它依赖 Twilio 的 action-sms action。

我已经把这个工作流禁用了，但你仍然可以在 Github 上看到完整的代码。
