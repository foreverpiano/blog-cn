PyObjC 和 Cocoa 史诗级入门教程

2008-08-22 · 阅读原文

随着 Leopard（OS X 10.5）的发布，PyObjC 2.0 也同步推出，这让创建一个 PyObjC 项目变得极其简单。然而，仍有相当多的人指出，目前还缺少一份全面且最新的教程，来指导如何在 Leopard 上开始使用 PyObjC 2.0。

我同时使用 Objective-C 和 PyObjC 开发过 Cocoa 应用程序，经验告诉我，PyObjC 能让你快速构建复杂的应用。我希望能做一点努力，让 PyObjC 对初学者更加友好——无论是 PyObjC 新手，还是对 Cocoa 开发完全陌生的人。本教程旨在提供一份完整的 walkthrough，教你如何在 Xcode 3.0 和 Interface Builder 3.0 中用 PyObjC 创建一个应用程序，并帮助你熟悉这个出色的工具。

让我们开始吧。

我们的项目

从零开始接触 PyObjC 可能会让人感到望而生畏。不过，完成本教程后，你应该已经能够自信地投入到自己的 PyObjC 项目中。我们将构建一个桌面应用程序，它会从 freebase.com 获取数据并展示，使用的是 metaweb.py 1。

我们会提供一个文本框让用户输入搜索内容，并用一个表格显示格式化后的结果。我们将使用 NSArrayController 来大幅简化代码（不用担心现在听不懂 NSArrayController，教程后面会详细解释）。我们还会学习如何读写应用程序支持目录中的文件（根据 OS X 编码规范，你应该把应用的临时文件和持久化数据存放在这里）。最后一步，我们会看看如何通过第二个 nib 文件以编程方式创建新窗口（nib 的概念同样会在后面解释）。

本教程会涉及使用 PyObjC 开发真实程序时会遇到的各种问题、难点和解决方案，并且不会假设你已经具备 Cocoa、Xcode 或 PyObjC 的任何现有知识。只要你懂一点 Python，就可以开始学习了。

PyObjC 就是 Python，同时也是 Objective-C。刚接触 Django 的人常常会遇到问题，并提出类似“如何从磁盘读取文件？”或“如何实现线程？”这样的疑问。社区里一个常见的回答是：Django 就是 Python。在使用 PyObjC 时，这同样是一个非常重要的理念。你在 Python 中能做的任何事情，在 PyObjC 中也都能做到。如果有一个优秀的 Python 库可以为你的应用提供动力，那就大胆使用它！如果你需要用一些元编程技巧来简化程序逻辑，也尽管用！ 同样重要的是这条原则的后半部分：PyObjC 也是 Objective-C。这对那些更熟悉 Cocoa 库而非 Python 库的 Objective-C 程序员尤其重要——你可以从两者中自由挑选。你想用 NSTimer 来处理重复事件吗？完全没问题。想用 Objective-C 的 selector 或者 Core Data 呢？简单得像没烤熟的派一样。 把 Python 中的冒号（:）替换为下划线（_）。在使用 PyObjC 时，你会经常把 Objective-C 方法转换成 Python 风格。这是一个简单的两步过程：首先把所有冒号（:）替换为下划线（_），然后像平常在 Python 中那样把参数加到方法定义里。 我们来举几个例子。首先是一个简单的。这个 Objective-C 方法定义： 在 Python 中会变成： 第二个例子我们试一个稍长一点的。 翻译成 Python 是： 你可以看到这种转换有时会产生相当丑陋的方法名，但操作本身非常简单。其实 Xcode 知道如何为 PyObjC 自动补全方法名，所以除非是你自己定义的类里的方法，否则你根本不需要自己手动转换。

Cocoa 的核心概念与模式

在正式开始前，我们需要简单了解几个在 Cocoa 中反复出现的重要概念。（你已经熟悉 Cocoa 开发了吗？那可以直接跳到“开始项目”部分。）

你创建的每个应用程序都是 NSApplication 的一个实例（或其子类）。NSApplication 有一个 delegate。Delegate 是 Cocoa 中非常常见的一种设计模式，它允许你在不继承特定类的情况下定制和控制其行为（例如，在不继承 NSTableView 的前提下控制一个 NSTableView）。 举例来说，NSApplication 的 delegate 可以让你指定应用程序启动时要执行的代码、处理用特定文件打开应用程序，以及指定应用程序终止前要运行的代码。我们首先要修改的就是应用的 delegate，稍后会详细讨论。 OS X 系统上的每个用户在 ~/Library/Application Support/ 目录下都有一个文件夹。应用程序可以在其中创建一个子文件夹来存放数据和设置。例如，Colloquy 会在 ~/Library/Application Support/Colloquy/ 下创建一个文件夹。 你应该始终把用户特定的数据存放在这里，而不是放在应用程序包内部（虽然 .app 实际上是一个文件夹，很容易让人把数据放进去，但这会破坏“直接拖到应用程序文件夹即可安装”的分发方式）。 Cocoa 类经常使用 Model/View/Controller（模型/视图/控制器）的职责划分，你的类也应该遵循这一模式。模型存放数据，视图呈现数据，控制器处理两者之间的交互。不过在较小的应用中，不必过于严格地遵守 MVC；简洁本身不应该被视为设计缺陷。 如果你玩过 Cocoa，你会发现很多类都以 NS 开头，例如 NSTableView、NSWorkspace 和 NSButton。Objective-C 只有一个命名空间，因此我们通过添加前缀来创建自己的命名空间。 很多人会使用自己或公司的首字母作为前缀。我有时会用 WL 作为前缀，有时则使用应用名称的子集。例如我曾经开发过一个叫 StrictlyEducation 的课程规划软件，就用了 SE 作为它的前缀2。 Interface Builder 让创建图形界面变得非常容易，它把这些界面保存在 .nib 和 .xib 文件中（.nib 通常用于 Leopard 之前的界面，而 Leopard 及之后的项目则使用 .xib）。我们后面会详细介绍它们，现在记住它们用来保存 GUI 配置就够了。

把新应用命名为 MetaWindow，选择一个合适的路径（我喜欢把它建在 ~/git/ 目录下），然后点击“保存”。

项目创建好之后，现在正是把它纳入版本控制的最佳时机。我个人更喜欢 Git，但使用 Mercurial 甚至 SVN 也不会让你后悔。总之，用一个就行。

从某种意义上说，这一步是可选的，但它真的应该成为一种习惯。如果现在还没有这个习惯，现在就是开始养成它的最好时机。有时候你会把代码搞砸，却不记得自己做了什么或如何修复。版本控制能把这种灾难变成快速查阅文档、回忆合并语法的小事。

教我们的 Delegate 一些新技能

我们要做的第一件事是完善 MetaWindowAppDelegate.py。双击打开它。目前它只包含几行代码：

from Foundation import *
from AppKit import *
class MetaWindowAppDelegate(NSObject):
def applicationDidFinishLaunching_(self, sender):
NSLog("Application did finish launching.")

但我们打算添加几个有用的方法。首先添加一个在应用程序即将关闭时执行的桩方法。

def applicationWillTerminate_(self,sender):
    NSLog("Application will terminate.")

这个 applicationWillTerminate_ 方法对于保存数据非常有用。

你可能已经注意到我们经常使用 NSLog()。这是记录数据和给自己发送消息最方便的方式。在程序运行时，你可以在 Xcode 的控制台窗口中看到这些消息，也可以通过 Console.app 查看。

接下来，我们添加两个方法，方便访问和创建应用程序支持文件夹中的文件。applicationSupportFolder 会返回 MetaWindow 的应用支持文件夹路径，而 pathForFilename 则返回该文件夹内某个具体文件的路径。

def applicationSupportFolder(self):
    paths = NSSearchPathForDirectoriesInDomains(NSApplicationSupportDirectory,NSUserDomainMask,True)
    basePath = (len(paths) > 0 and paths[0]) or NSTemporaryDirectory()
    fullPath = basePath.stringByAppendingPathComponent_("MetaWindow")
    if not os.path.exists(fullPath):
        os.mkdir(fullPath)
    return fullPath
def pathForFilename(self,filename):
return self.applicationSupportFolder().stringByAppendingPathComponent_(filename)

最后简单说说为什么应用 delegate 是一个非常强大的工具。你可以从代码的任何地方轻松访问和使用它：

app_delegate = NSApplication.sharedApplication().delegate()
my_database = app_delegate.pathForFilename("db.sqlite")

这使得它成为存放工具方法的绝佳位置。（顺便说一句，现在是提交版本控制的好时机。）

创建一个新的桩文件

接下来我们要创建一个新文件，用来管理应用程序的用户界面组件。进入“文件”菜单，点击“新建文件...”（Command-N）。

选择 “Python NSObject subclass”，然后点击下一步。将它命名为 MWController.py，然后点击“完成”。

打开 MWController.py，它看起来是这样的：

from Foundation import *
class MWController(NSObject):
pass

把导入部分修改成这样：

import objc
from Foundation import *

objc 模块提供了许多对创建 PyObjC 应用至关重要的工具。这里我们会用到其中的两个：@objc.IBAction 装饰器和 objc.IBOutlet() 函数。

你必须为任何希望在 Interface Builder 中可访问的方法加上 @objc.IBAction 装饰器。这意味着任何你希望让界面组件触发的动作（比如按钮点击后调用的 wasClicked_ 方法等）都应该使用这个装饰器。不过要注意，所有这类动作方法必须至少有一个参数（因此在 Python 定义中必须带一个下划线）。例如，你必须写 def myFunc_(self, sender)，而不能写 def myFunc(self)。sender 的值由 Cocoa 提供，它会是调用该动作的按钮（或另一个类的实例）。

同样，objc.IBOutlet() 允许你将 .xib 文件中的对象连接起来。这个概念在你实际使用 Interface Builder 之前可能比较难理解，我们后面会更深入地讨论。

现在让我们给 MWController 类添加几个字段。

class MWController(NSObject):
    tableView = objc.IBOutlet()
    textField = objc.IBOutlet()
    results = []

然后我们再加一个桩方法。

@objc.IBAction
def search_(self,sender):
    search_value = self.textField.stringValue()
    NSLog(u"Search: %s" % search_value)

正如之前所说，search_ 方法会被界面组件调用，因此需要加上 @objc.IBAction 装饰器，并且必须接收 sender 参数。

最后，把一个 Python 文件添加到 Xcode 项目的最后一步是打开 main.py，在下面这行代码之后导入它：

# import modules containing classes required to start application and load MainMenu.nib

添加 MWController 之后，main.py 的对应部分会变成这样：

向 MainMenu.xib 添加 MWController

.xib 和 .nib 文件的一个重要价值在于，它们能够存储类的序列化实例。如果你看看 Interface Builder 中的 MainMenu.xib 窗口，里面已经有一些序列化实例了：那个标着 MetaWindowAppDelegate 的立方体就是一个，还有 Application。

这非常有用，因为它允许你以图形化的方式将对象连接起来。例如，点击 Application，然后在检查器中切换到第五个标签页。你可以看到它有一个名为 delegate 的 outlet，已经连接到了 MetaWindowAppDelegate。

现在我们要创建一个 MWController 的实例，并设置它的 outlets（以及一个 action）。

打开 Library 窗口，在底部的搜索框中输入 NSObject（确保你在同一个窗口的概览视图中选择了 Library 文件夹，否则可能搜索不到 NSObject）。

把 NSObject 图标拖到你的 MainMenu.xib 窗口中。一个新的名为“Object”的立方体就会出现。

点击这个 Object，在检查器中切换到第六个标签页（标签名为“Object Identity”）。在最上面的文本框（标签是 Class）中，把 NSObject 改成 MWController，然后按回车。

现在回到 MainMenu.xib 窗口，点击 Controller（就是刚才叫 Object 的那个）。同时把 Window 窗口也显示出来，这样你就能看到里面的 tableView 和 textField。

按住 Control 键，从 Controller 开始拖动到 Window 中的 textField 上。这时会出现一个小的浮动框，让你在 textField 和 tableView 中选择；请选择 textField。

重复同样的操作，从 Controller 开始拖动，这次松开鼠标到 tableView 上。当弹出框出现时，选择 tableView。

最后我们要建立从 Search 按钮到 Controller 的连接。对于 action 的连接，你要从触发源（这里是按钮）开始，拖动到你要调用其 action 的对象（这里是 Controller）。

选中 Search 按钮，按住 Control 键，从按钮拖动到 Controller 然后松开。这时会出现一个黑色小框，只有一个选项 search:，选中它。

保存。关闭 Interface Builder。为自己能活下来而庆祝一下吧。
