PyObjC 和 Cocoa 入门指南

2008-08-22 · 阅读原文

随着 Leopard（OS X 10.5）的发布，PyObjC 2.0 也同步推出，这让开始一个 PyObjC 项目变得非常简单。然而，不少人指出，目前还缺少一份全面、与时俱进的 PyObjC 2.0（Leopard 版）入门教程。

我同时使用 Objective-C 和 PyObjC 开发过 Cocoa 应用，经验告诉我，PyObjC 能让你快速构建复杂的应用程序。我希望做一点力所能及的事，让 PyObjC 对新手更加友好——无论他们是 PyObjC 新手，还是 Cocoa 开发的新手。本教程旨在提供一份完整的 walkthrough，教你如何用 Xcode 3.0 和 Interface Builder 3.0 创建一个 PyObjC 应用，并帮助你熟悉这个强大的工具。

让我们开始吧。

我们的项目

从零开始学习 PyObjC 可能会让人望而生畏。不过，完成本教程后，你应该已经能够独立投入自己的 PyObjC 项目了。我们将构建一个桌面应用程序，它会从 freebase.com 获取数据并展示，使用 metaweb.py 1 作为辅助库。

我们会有一个文本框让用户输入搜索内容，还有一个表格用来显示格式化后的结果。我们将使用 NSArrayController 来大幅简化代码（不用担心现在还听不懂 NSArrayController，后面教程中会详细解释）。我们还会学习如何读写应用程序支持目录中的文件（即 OS X 编码规范建议你存放临时文件和用户数据的目录）。最后一步，我们会看看如何通过第二个 nib 文件以编程方式创建新窗口（nib 的概念后面也会解释）。

本教程会涉及使用 PyObjC 开发实际程序时会遇到的各种问题、难点和解决方案，并且不假设你已经具备 Cocoa、Xcode 或 PyObjC 的任何知识。只要你懂一点 Python，就可以直接开始学习。

需要记住的两条原则

刚开始接触 PyObjC 时，记住下面两点能帮助你少走很多弯路：

PyObjC 是 Python，同时也是 Objective-C。刚接触 Django 的人经常会困惑“怎么从磁盘读取文件？”或者“如何实现多线程？”，社区常见的回答是：Django 就是 Python。用 PyObjC 时也一样，这句话非常重要。你在 Python 里能做的事，在 PyObjC 里都能做。如果有优秀的 Python 库能为你的应用提供动力，那就大胆使用！如果你需要一些元编程技巧来简化程序逻辑，也尽管用！同样重要的是这条原则的后半句：PyObjC 也是 Objective-C。这对熟悉 Cocoa 框架但不太了解 Python 库的 Objective-C 程序员尤其重要——你可以从两者中自由挑选。你想用 NSTimer 来处理周期性事件吗？完全没问题。想用 Objective-C 的 selector 或 Core Data 吗？就像吃一块稍微烤得嫩一点的派那么简单。将 Objective-C 方法转换为 Python 形式时，把 : 换成 _。在使用 PyObjC 时，你会经常要把 Objective-C 方法转换成 Python 风格。这是一个简单的两步过程：首先把所有冒号（:）替换成下划线（_），然后像平常写 Python 那样把参数加到方法定义中。让我们通过几个例子来看看具体怎么做。首先是一个简单的例子。这个 Objective-C 方法定义：-(int)add: (int)a and: (int)b; 转换后的 Python 代码是：def add_and_(self,a,b): # 在这里实现功能 第二个例子我们来转换一个稍长的方法。- (NSImage *)dragImageForRowsWithIndexes:(NSIndexSet *)dragRows tableColumns:(NSArray *)tableColumns event:(NSEvent *)dragEvent offset:(NSPointPointer)dragImageOffset 翻译成 Python 后是：def dragImageForRowsWithIndexes_tableColumns_event_offset_(self,dragRows,tableColumns,dragEvent,dragImageOffset): pass 可以看到，这种转换有时会产生相当丑陋的方法名，但操作本身非常简单。其实 Xcode 知道如何为 PyObjC 自动补全方法名，所以除非是你自己定义的类里的方法，否则你甚至不用手动进行转换。

Cocoa 的核心概念和设计模式

在正式开始之前，我们需要简单了解几个在 Cocoa 中反复出现的重要概念。（如果你已经熟悉 Cocoa 开发，可以直接跳到“开始项目”部分。）

你开发的每个应用程序都是 NSApplication 的实例（或其子类）。NSApplication 有一个 delegate。Delegate 是 Cocoa 中非常常见的一种设计模式，它允许你在不继承特定类的情况下定制和控制其行为（例如，在不继承 NSTableView 的前提下控制它）。举例来说，NSApplication 的 delegate 可以让你指定应用启动时要执行的代码、处理用特定文件打开应用的行为，以及在应用终止前执行的清理代码。我们第一步就是要修改应用的 delegate，稍后会详细讨论。OS X 系统中的每个用户在 ~/Library/Application Support/ 目录下都有一个文件夹。应用程序可以在里面创建自己的文件夹来存储数据和设置。例如，Colloquy 就在 ~/Library/Application Support/Colloquy/ 下有自己的文件夹。你应该始终把用户相关的数据存放在这里，而不是放在应用程序包内部（虽然 .app 实际上是个文件夹，很容易让人误以为可以直接往里面写，但这会破坏“直接拖到应用程序文件夹即可安装”的分发方式）。Cocoa 类经常使用 Model/View/Controller（模型/视图/控制器）的职责划分，你的类也应该遵循这一模式。模型负责保存数据，视图负责呈现数据，控制器负责协调两者之间的交互。不过在小型应用中，不必过于教条地遵守 MVC；简洁本身不应该被视为设计缺陷。如果你玩过 Cocoa，应该注意到很多类都以 NS 开头，例如 NSTableView、NSWorkspace、NSButton。Objective-C 只有一个命名空间，因此我们通过添加前缀来创建自己的命名空间。很多人会用自己或公司的首字母作为前缀。我有时用 WL 作为前缀，有时则使用应用名称的缩写。例如我曾经开发过一个叫 StrictlyEducation 的课程规划软件，就用了 SE 作为它的前缀2。Interface Builder 可以非常方便地创建图形界面，并将这些界面保存在 .nib 和 .xib 文件中（.nib 通常用于 Leopard 之前的界面，.xib 则用于 Leopard 及之后创建的项目）。我们后面会详细介绍它们，目前只需要记住它们包含了 GUI 的配置信息即可。

项目创建完成后，现在正是把它纳入版本控制的好时机。我个人更喜欢 Git，但使用 Mercurial 甚至 SVN 也不会后悔。总之，用起来就行。

从某种意义上说这步是可选的，但它真的应该成为一种习惯。如果现在还没有养成，现在就是最佳时机。有时候你会把代码搞得一团糟，却想不起来自己做了什么、该怎么恢复。版本控制能把这种灾难变成快速查阅文档、回忆合并语法的小插曲。

默认项目中的文件

项目创建好后，里面已经有一堆文件了。我们花点时间来了解一下它们都是做什么的。

首先，你会看到几个 .framework 文件：AppKit、Cocoa、CoreData、Foundation 和 Python。这些都是在编译时会链接到你应用程序的有用库。接下来是 main.m 和 main.py，它们是应用程序的核心文件，你通常不需要经常修改它们（MetaWindow_Prefix.pch 也是类似，但更彻底：你几乎永远不会碰它）。唯一的例外是，当你的应用中有其他 Python 文件时，需要在 main.py 中添加简单的 import 语句。例如，它目前有这一行：import MetaWindowAppDelegate 如果你创建了另一个名为 MWModel.py 的文件（MW 是 MetaWindow 的首字母，也就是我们在这个应用中使用的命名空间），那么你需要把 main.py 的这部分修改成：import MetaWindowAppDelegateimport MWModel MainWindow.xib (English) 是一个 Interface Builder 文件，包含了应用程序界面的相关数据。Info.plist 包含应用的各种设置，InfoPlist.strings (English) 则是国际化文件，用于支持不同语言环境的标签和菜单。MetaWindowAppDelegate.py 是一个普通的 Python 文件，里面定义了我们应用的 delegate 类。MetaWindow.app 是我们应用程序的壳。当你构建应用时，所有东西都会被打包进去，但目前它只是一个空空的骨架。

objc 模块提供了许多创建 PyObjC 应用的重要工具。这里我们会用到其中的两个：@objc.IBAction 装饰器和 objc.IBOutlet() 函数。

任何你希望能在 Interface Builder 中访问的方法，都必须用 @objc.IBAction 装饰。这意味着所有打算让界面组件触发的方法（比如按钮点击后调用的 wasClicked_ 方法等）都应该加上这个装饰器。注意，所有这类 action 方法至少要有一个参数（因此在 Python 定义中至少要有一个下划线）。例如你必须写 def myFunc_(self,sender) 而不能写 def myFunc(self)。sender 的值由 Cocoa 提供，它会是调用该 action 的按钮（或其他类的实例）。

同样，objc.IBOutlet() 能让你把 .xib 文件中的对象连接起来。这个概念在实际使用 Interface Builder 之前可能比较难理解，我们后面会更详细地介绍。
