PyObjC 和 Cocoa 入门指南

2008-08-22 · 阅读原文

随着 Leopard（OS X 10.5）的发布，PyObjC 2.0 也同步推出，让创建 PyObjC 项目变得非常简单。然而，仍有不少人指出，目前还缺少一份全面且最新的教程来介绍如何在 Leopard 上开始使用 PyObjC 2.0。

我同时使用 Objective-C 和 PyObjC 开发过 Cocoa 应用程序，经验告诉我 PyObjC 可以让你快速构建复杂的应用。我希望能做一点力所能及的事，帮助 PyObjC 对新手变得更加友好——无论他们是 PyObjC 新手，还是 Cocoa 开发的新手。本教程旨在提供一份完整的 walkthrough，教你如何使用 Xcode 3.0 和 Interface Builder 3.0 创建一个 PyObjC 应用，并帮助你熟悉这个优秀的工具。

让我们开始吧。

我们的项目

从零开始学习 PyObjC 可能会让人望而却步。不过，完成本教程后，你应该就能自信地投入到自己的 PyObjC 项目中。我们将构建一个桌面应用程序，它会从 freebase.com 获取数据并使用 metaweb.py 进行展示。

我们会提供一个文本框让用户输入搜索关键词，并用表格显示格式化后的结果。我们将使用 NSArrayController 来大幅简化代码（不用担心现在还不了解 NSArrayController，后续教程中会详细解释）。我们还会介绍如何读写应用程序支持目录中的文件（即 OS X 编程规范推荐用来存放临时和持久化数据的目录）。最后，我们会学习如何通过第二个 nib 文件以编程方式创建新窗口（nib 的概念同样会在后面解释）。

本教程会涉及使用 PyObjC 开发实际程序时会遇到的各种问题、难点和解决方案，并且不假设你事先具备 Cocoa、Xcode 或 PyObjC 的任何知识。只要你了解基本的 Python，就可以开始学习了。

PyObjC 是 Python，同时也是 Objective-C。刚开始学 Django 的人常常会遇到问题，并提出类似“如何从磁盘读取文件？”或“如何实现线程？”这样的疑问。社区常见的回答是：Django 就是 Python。在使用 PyObjC 时，这句话同样重要，值得牢记。你在 Python 中能做的任何事，在 PyObjC 中也都能做到。如果你找到一个优秀的 Python 库可以为你的应用提供动力，那就用它！如果你需要一些元编程技巧来简化程序逻辑，也尽管使用！同样重要的是这条原则的后半部分：PyObjC 也是 Objective-C。这对那些更熟悉 Cocoa 库而非 Python 库的 Objective-C 程序员尤其重要——你可以在两者之间自由选择。你想用 NSTimer 来处理重复事件吗？完全没问题。想用 Objective-C 的 selector 或 Core Data 呢？简单得像稍微没烤熟的派一样。将 Objective-C 方法转换为 Python 时，把冒号（:）替换为下划线（_）。在使用 PyObjC 时，你会经常把 Objective-C 方法转换成 Python 风格。这是一个简单的两步过程：首先把所有冒号（:）替换为下划线（_），然后像平常在 Python 中那样把参数加到方法定义中。让我们通过几个例子来看看具体怎么做。首先是一个简单的例子。这段 Objective-C 方法定义：变成了下面这段 Python 代码：第二个例子我们试一个稍长一点的。翻译成 Python 后是：你可以看到这种转换有时会产生相当丑陋的方法名，但操作本身非常简单。其实 Xcode 知道如何为 PyObjC 自动补全方法名，所以除非是你自己定义的类里的方法，否则你都不需要手动进行转换。

Cocoa 的组件与模式

在正式开始前，有几个在 Cocoa 中反复出现的重要概念我们需要简单了解一下。（如果你已经熟悉 Cocoa 开发，可以直接跳到“开始项目”部分。）

你创建的每个应用程序都是 NSApplication 的一个实例（或其子类）。NSApplication 拥有一个 delegate。Delegate 是 Cocoa 中非常常见的一种设计模式，它允许你在不继承特定类的情况下自定义和控制其行为（例如，在不继承 NSTableView 的前提下控制一个 NSTableView）。举例来说，NSApplication 的 delegate 可以让你指定应用程序启动时要执行的代码、处理用特定文件打开应用程序的操作，以及在应用程序终止前要运行的代码。我们首先要做的就是修改应用程序的 delegate，稍后会详细讨论。OS X 系统上的每个用户在 ~/Library/Application Support/ 目录下都有一个文件夹。应用程序可以在其中创建一个自己的文件夹来存放数据和设置。例如，Colloquy 就在 ~/Library/Application Support/Colloquy/ 下有一个文件夹。你应该始终将用户相关的数据存放在这里，而不是放在应用程序包内部（虽然把 .app 看成文件夹很诱人而且确实可行，但这会干扰“直接拖到应用程序文件夹”这种简单的分发方式）。Cocoa 类经常使用 Model/View/Controller（模型/视图/控制器）的职责划分，你的类也应该遵循这一模式。模型负责存放数据，视图负责呈现数据，控制器负责处理两者之间的交互。不过在小型应用程序中，不必过于死板地遵守 MVC；简洁本身不应该被视为设计缺陷。如果你玩过 Cocoa，你会发现很多类都以 NS 开头，例如 NSTableView、NSWorkspace 和 NSButton。Objective-C 只有一个命名空间，因此我们通过添加前缀字母来创建自己的命名空间。很多人使用自己或公司的首字母作为前缀。我有时会用 WL 作为前缀，有时则使用应用程序名称的缩写。例如，我曾经开发过一个叫做 StrictlyEducation 的课程规划软件，就使用了 SE 作为它的前缀。Interface Builder 让创建图形界面变得非常容易，并将这些界面保存在 .nib 和 .xib 文件中（.nib 通常用于 Leopard 之前的界面，而 .xib 用于在 Leopard 中创建的项目）。我们稍后会详细介绍它们，现在只需要记住它们包含了图形界面的配置信息即可。

进入“文件”菜单，选择第一个选项“新建项目”（或者使用 Shift-Command-N）。

将我们的新应用程序命名为 MetaWindow，把路径设置到一个合适的位置（我喜欢把它创建在 ~/git/ 目录下），然后点击“保存”。

项目创建完成后，现在正是把它纳入版本控制的好时机。我个人偏好 Git，但使用 Mercurial 甚至 SVN 也不会后悔。总之，用一个就行。

教我们的 Delegate 一些新技能

我们要做的第一件事是完善 MetaWindowAppDelegate.py。双击它打开文件。目前它只包含几行代码：

但我们要添加几个有用的方法。首先添加一个在应用程序关闭前执行操作的存根方法。

def applicationWillTerminate_(self,sender):
    NSLog("Application will terminate.")

这个名为 applicationWillTerminate_ 的方法对于保存数据非常有用。

你可能已经注意到我们经常使用 NSLog()。这是记录数据和给自己发送消息最方便的方式。程序运行时，你可以在 Xcode 的控制台窗口中看到这些消息，也可以通过 Console.app 查看。

接下来，我们添加两个方法，方便访问和在应用程序支持文件夹中创建文件。applicationSupportFolder 会返回 MetaWindow 的应用程序支持文件夹路径，而 pathForFilename 会返回该文件夹中某个具体文件的路径。

def applicationSupportFolder(self):
    paths = NSSearchPathForDirectoriesInDomains(NSApplicationSupportDirectory,NSUserDomainMask,True)
    basePath = (len(paths) > 0 and paths[0]) or NSTemporaryDirectory()
    fullPath = basePath.stringByAppendingPathComponent_("MetaWindow")
    if not os.path.exists(fullPath):
        os.mkdir(fullPath)
    return fullPath
def pathForFilename(self,filename):
return self.applicationSupportFolder().stringByAppendingPathComponent_(filename)

最后简单说说为什么应用程序 delegate 是一个强大的工具。你可以从代码中的任何位置轻松访问和使用它：

app_delegate = NSApplication.sharedApplication().delegate()
my_database = app_delegate.pathForFilename("db.sqlite")

这使得它成为存放工具方法的绝佳位置。（顺便说一句，现在是提交到版本控制的好时机。）

创建一个新的存根文件

接下来我们要创建一个新文件，用来管理应用程序的用户界面组件。进入“文件”菜单，点击“新建文件...”（Command-N）。

选择 Python NSObject subclass，然后点击下一步。将其命名为 MWController.py，然后点击“完成”。

打开 MWController.py，它看起来是这样的：

from Foundation import *
class MWController(NSObject):
pass

把 import 部分修改成下面这样：

import objc
from Foundation import *

objc 模块提供了许多创建 PyObjC 应用程序所需的重要工具。这里我们会用到其中的两个：@objc.IBAction 装饰器和 objc.IBOutlet() 函数。

你必须为任何希望在 Interface Builder 中可访问的方法加上 @objc.IBAction 装饰器。这意味着任何你希望用户界面组件触发的动作（比如按钮点击后调用的 wasClicked_ 方法等）都应该用该装饰器装饰。不过要注意，所有这类动作方法至少必须有一个参数（因此在 Python 定义中至少要有一个下划线）。例如，你必须写 def myFunc_(self, sender) 而不是 def myFunc(self)。sender 的值由 Cocoa 提供，它将是调用该动作的按钮（或另一个类的实例）。

同样，objc.IBOutlet() 允许你将 .xib 文件中的模型连接起来。这个概念在你实际使用 Interface Builder 之前可能比较难理解，我们稍后会更深入地讨论。

现在让我们给 MWController 类添加几个属性。

class MWController(NSObject):
    tableView = objc.IBOutlet()
    textField = objc.IBOutlet()
    results = []

然后我们再添加一个存根方法。

@objc.IBAction
def search_(self,sender):
    search_value = self.textField.stringValue()
    NSLog(u"Search: %s" % search_value)

正如之前提到的，search_ 方法将被 UI 组件调用，因此需要加上 @objc.IBAction 装饰器，并且必须接收 sender 参数。

向 MainMenu.xib 添加 MWController

.xib 和 .nib 文件的一个重要功能是它们能够存储类的序列化实例。如果你看看 Interface Builder 中的 MainMenu.xib 窗口，已经有几个序列化实例存在了：那个标着 MetaWindowAppDelegate 的立方体就是一个，还有 Application。

这很有用，因为它允许你以图形化的方式将对象连接起来。例如，点击 Application，然后打开检查器的第五个标签页。你可以看到它有一个名为 delegate 的 outlet，已经连接到了 MetaWindowAppDelegate。

现在我们要创建一个 MWController 的实例，并设置它的 outlets（以及一个 action）。

打开 Library 窗口，在底部的搜索框中输入 NSObject（确保你在同一窗口的左侧大纲视图中选中了 Library 文件夹，否则搜索可能找不到 NSObject）。

把 NSObject 图标拖到你的 MainMenu.xib 窗口中。一个新的名为 Object 的立方体就会出现。

点击这个 Object，然后打开检查器的第六个标签页（标签名为 Object Identity）。在最上面的文本框（标签是 Class）中，把 NSObject 替换为 MWController，然后按回车。

现在回到 MainMenu.xib 窗口，点击 Controller（就是刚才叫 Object 的那个对象）。同时把 Window 窗口也显示出来，以便看到它的 tableView 和 textField。

按住 Control 键，从 Controller 开始拖动到 Window 中的 textField 上。这时会出现一个小的浮动面板，让你选择 textField 或 tableView，请选择 textField。

重复同样的操作，从 Controller 开始拖动，这次释放到 tableView 上。当弹出窗口出现时选择 tableView。

最后我们要建立从 Search 按钮到 Controller 的连接。对于 action 的连接，你需要从触发方（这里是按钮）开始拖动到要调用其 action 的对象（这里是 Controller）。

选中 Search 按钮，按住 Control 键，从按钮拖动到 Controller 后释放。这时会出现一个黑色小框，只有一个选项 search:，选中它。
