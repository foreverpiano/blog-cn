在 Django URL 中使用可选参数

2008-02-04 · 阅读原文

快速记录一篇关于简单却实用的技巧的博客：利用 Django 视图中的可选参数来避免重复编写代码。

最近在开发 LifeFlow Editor 时，我希望能够通过 Ajax 将文本发送到后端进行渲染，然后把渲染后的结果展示出来。这种需求有两种场景：有时需要渲染直接 POST 到视图的文本，有时则需要根据 POST 传来的模型类名和主键，渲染特定模型实例的内容。

为此我编写了以下视图：

from lifeflow.models import *
urlpatterns = patterns('lifeflow.editor.views',
(r'^render/$', 'render'),
(r'^render/(?P<model>\w+)/(?P<id>\d+)/$', 'render'),
)

第一个视图向 render 函数传递了两个参数，第二个则一个参数都没传，但它们实际上调用的是同一个视图函数，这是怎么做到的呢？

实现起来其实非常简单：

@login_required
def render(request, model=None, id=None):
    if id is None:
        txt = dbc_markup(request.POST['txt'])
    else:
        if model == u"draft":
            obj = Draft.objects.get(pk=id)
        elif model == u"entry":
            obj = Entry.objects.get(pk=id)
        if obj.use_markdown:
            txt = dbc_markup(obj.body, obj)
        else:
            txt = obj.body
    return HttpResponse(txt)

如果没有收到 id 参数，我就知道应该去 POST 数据中查找待渲染的文本；否则就根据传入的主键和模型类，获取对应的 Draft 或 Entry 实例并进行渲染。

（这里使用了 login_required 装饰器来防止未授权用户访问该视图。另外，内容验证写得比较简陋，但这个视图不会对数据造成任何修改，只是在某些地方显示它，而能够访问该视图的用户本来就有权限查看这些数据，因此对我来说不是大问题。）

这是一个偶尔会用到的简单技巧，能帮助你保持代码整洁，避免重复。
