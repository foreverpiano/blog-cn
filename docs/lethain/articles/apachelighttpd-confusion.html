Apache 与 Lighttpd 的混淆

2007-07-17 · 阅读原文

最近我不断收到关于当前架构的反馈：我让 Apache 作为前端服务器，通过 mod_proxy 将静态资源请求转发给 Lighttpd。反馈的核心观点是这种做法很愚蠢。具体来说，用被 mod_python 撑得臃肿的 Apache 线程去把请求转给轻量级的 Lighttpd，毫无意义。这似乎和理想的架构完全相反。

我最初的反应是：我的架构肯定有它的道理，否则为什么会有相当多的搭建指南都在采用这种方式？（这不是我只见过一次的方案，而是在很多地方都遇到过，其中一些你会觉得他们是知道自己在做什么的。）但后来我去看了 mod_proxy 的文档，确实没看出当前这种 setup 比直接用纯 Apache 能带来什么效率提升。

然而，为什么这种架构还是反复出现在 hostlibrary.com 上（同一篇文章也被 linux.com 转载），k4ml.com 和 kelvinism.com 也都在提到 mod_proxy 的这种用法。

所以我的问题是：这到底是怎么回事？我的当前架构是否低效？如果是，为什么有这么多人都在推荐它？
