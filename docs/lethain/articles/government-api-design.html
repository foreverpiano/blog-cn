政府能设计出优秀的 API 吗？希望如此。

2019-05-12 · 阅读原文

互联网正在不断演变。这种变化由技术限制（IPv6）、日益明确的隐私担忧（GDPR），以及被称为数据本地化的经济与政治交汇所驱动，目前正在中国、欧盟、俄罗斯、印度等众多国家和地区展开。

在硅谷科技公司工作的人有时将这些法规视为保护主义，旨在扶持本土竞争者对抗那些更成熟的全球公司。当然，其中部分法律确实出于这种考量。但在我看来，也有相当一部分是为了维护国家经济基础设施的主权，避免依赖全球公司的定价反复无常和法律约束——其中许多公司总部位于美国，它们的突然退出或大幅涨价都可能造成严重损害。（尤其是在美国外交政策突然变得极不可预测这种不太可能发生的情景下。）

我个人认为，这些数据隐私和本地化法案旨在提升隐私保护、维护国家主权的目标是值得肯定且重要的。事实上，由于过去几周我花了大量时间处理一起因大规模数据泄露导致的身份盗用事件，我对这个话题的感受比以往更为强烈。虽说接十几个客服电话树不算世界上最繁重的任务，但确实是我通常宁愿避免的事情。

不幸的是，许多现行监管方式产生了意想不到的后果：推动行业进一步向少数更强大的公司集中，并使新创公司满足法律和监管要求以挑战这些巨头的成本越来越高。

要满足这些监管要求，就必须实现抽象的合规条款，而这些条款既缺乏执行先例，又频繁发生变化。应对这些变化需要律师团队、会引入意想不到的产品限制，并要求持续的工程投入。小公司往往无法在要求不断变化的情况下长期维持这些投入，这迫使它们只能在国内开展业务以降低风险，从而进一步巩固了现有企业的规模护城河。

不过，也存在一些令人信服的前进路径。Lyft 针对 Uber 全球规模优势的一个创新应对举措，就是创建了所谓的“Lyft Alliance”（Lyft 联盟），为四家区域性公司建立了一个共享 API，让它们的用户能够跨平台交互。虽然那一版联盟最终并未完全成功，但这个策略本身令人惊叹——本土公司网络能否通过标准化 API 来与大型全球公司竞争？

欧盟则将这个想法向前推进了一步，通过“Open Banking”（开放银行）计划立法要求共享 API。如果政府能够把这件事做好——特别是限制 API 设计的频繁变更——这将是一场非凡的公平化变革，让初创企业能够在成熟的生态系统中平等竞争。想象一下，只需一次审批就能让你接入整个现有生态系统？这种 API 设计与访问权的理念，也是 Elizabeth Warren 呼吁拆分科技巨头的核心内容。当平台被要求在用户授权后提供数据访问时，其中显然有巨大的吸引力。

然而，设计和维护 API notoriously 困难，很少有公司能在这个领域展示出持续的成功，更不用说政府了。因此，许多法规在获得批准时只规定了具体要求，却没有明确的设计方案，这种做法的缺陷在 Brexit 的艰难历程中得到了充分体现。

总而言之，我们似乎正在进入互联网的新时代。这个时代有潜力显著降低竞争门槛，但前提是世界各国政府能够设计出有效、易用的 API。这是一次非凡的转变！如果你想在 2020 年改变世界，或许应该考虑参与到政府的 API 设计工作中去。
