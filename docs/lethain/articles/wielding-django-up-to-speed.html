基本结构应该很眼熟：urlpatterns 定义了 URL 如何映射到视图函数，而视图（compute）则根据请求构建响应。但有几处做了改动：

正则表达式现在可以匹配参数：\w 匹配字母或数字字符，\w+ 匹配一个或多个这样的字符序列，而 (?P<op>\w+) 则给这个序列起了个名字叫 op。这些都是普通的 Python re 模块的功能。Django 会把从正则表达式中提取的参数传递给视图函数：compute 会额外收到一个关键字参数 op。它始终是字符串类型，即使正则模式匹配的是数字（\d）。request.GET 是一个包含 GET 参数（a 和 b）的字典，同样也都是字符串。

请注意这种方式和你熟悉的 PHP 或大多数其他 Web 开发方式有一个重要区别：URL 和文件之间没有必然的对应关系。你可以完全控制这个映射。例如，你可能习惯于把 '/' 当作 '/index.html'（或 index.php 之类的）的同义词。但在你的 Django 服务器上，/index.html 会返回错误（试试看！），因为你没有明确声明这个映射关系。
