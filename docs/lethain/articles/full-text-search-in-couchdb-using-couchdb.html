在 CouchDB 中实现全文搜索……就用 CouchDB

2008-12-08 · 阅读原文

我正在做一个项目，希望能在 CouchDB 上使用全文搜索。今天花了太多时间去研究可行的方案。在比较实用的方案中，有 CouchDB-Lucene 和 CouchDB-Solr 项目，但我还是决心不借助任何外部项目，尝试让全文搜索在 CouchDB 自身上跑起来。

结果还真让我做到了。

方法一：单词限制法。

如果把这个叫“全文搜索”，我大概会被公众扔石头，但它确实能让你查出所有包含某个特定单词的文档。（不过如果数据库较大，第一次构建索引会非常耗时。我那可怜的 Macbook 为 6 万篇文档——总共 230 万个单词——建立索引花了大约 40 分钟。不过索引建成之后，查询速度倒是很快，只是结果没什么用。）

举个例子，假设你想要创建一个名为 word 的视图，用来在文档的 title 或 desc 属性中查找单词。下面这个视图函数就能实现：

function(doc) {
  var txt = doc.title + doc.desc;
  var words = txt.replace(/[!.,;]+/g,"").toLowerCase().split(" ");
  for (var word in words) {
    emit(words[word], doc._id);
  }
}

之后你就可以通过这个 URL 查出所有包含 hello 的文档：http://localhost:5984/mydb/_view/search/word?key="hello"。更进一步，你可以向 http://localhost:5984/mydb/_view/search/word 发送一个包含多个 key 的 POST 请求，但它执行的是 OR 操作而非 AND 操作，因此无法有效地查找同时包含一组单词的文档。

（如果你认真想这么做，应该先更好地清理单词，并把单词列表转成单词集合。）

方法二：极其丑陋，但管用。在“某种意义”上管用。

CouchDB 视图的 key 不一定只能是字符串，它可以是任意合法的 JSON 值。因此，你可以这样思考搜索查询（为了可读性这里没有做 URI 编码）：

http://localhost:5984/mydb/_view/_search/lookup?key="couchdb view"

但如果你把 key 的结构改一改，也可以这样来思考：

http://localhost:5984/mydb/_view/_search/lookup?key=["couchdb,"view"]

也就是说，你可以把 key 指定为一个 JavaScript 数组，而不是一个 JavaScript 字符串。所以，如果我们能为每个文档生成一个索引，里面包含该文档所有可能的单词组合数组，那么我们就能实现全文搜索了。

等等，你为什么要关浏览器？别啊，坚持一下。真的很快，查询速度会非常快。至于空间和时间复杂度的记号（Big O）极其糟糕又如何？这只是一次性成本——一个极其巨大的一次性成本，没错——但它还是挺新颖的。而且如果你只需要索引很少的文本（比如只有标题，或者标题加标签），这个方法其实是可行的。

下面是对应的视图函数：

function(doc) {
  // permutation func by Jonas Raoni Soares Silva
  var permute = function( v, m ){
    for( var j, l = v.length, i = ( 1 << l ) - 1, r = new Array( i ); i; )
      for( r[--i] = [], j = l; j; i + 1 & 1 << --j && ( r[i].push( m ? j : v[j] ) ) );
    return r;
  };
  var txt = doc.title;
  txt.replace(/[!.,;]+/g, "");
  var raw_words = txt.split(" ");
  var words = {};
  for (var i in raw_words) {
    var word = raw_words[i];
    if (word == "") continue;
    if (!words[word]) { words[word] = 1; }
    else { words[word]++; }
  }
  var word_set = [];
  for (var word in words) {
    word_set.push(word);
  }
  var permutations = permute(word_set,0);
  for (var i in permutations) {
    emit(permutations[i],doc._id);
  }
}

先声明一下，是的，这玩意儿真的能跑。我测试过，它确实有效。但要补充一句 caveat：如果 txt 的值超过四五个单词，map 函数有时会触发 5 秒的超时限制。（我尝试把源码里的超时从 5 秒改到 50 秒重新编译，但不知为何改动没有生效。而且上面这段代码按理不应该花五秒，它本质上虽然低效，但也不该慢成那样。我觉得换用 Python 或 Common Lisp 的 view server 也许能缓解这个问题，晚点我可能会试试。）

如果你想查出所有包含且仅包含 NFL 的排列组合的文档，可以访问这个 URI：

http://127.0.0.1:5984/bossv/_view/_search/word?key=["NFL"]

如果你想查出所有包含 NFL 的排列组合的文档，也可以这样写：

http://127.0.0.1:5984/bossv/_view/_search/word
    ?startkey=["NFL"]&endkey={}

最后简单提一句，你还可以把这个技巧稍作修改，用来查询包含任意组合标签的所有博客文章。这是一种关系型数据库很难高效建立索引的复杂查询，但用上面这种技巧，CouchDB 却能轻松应对。所以，虽然创建“全排列索引”这个例子听起来相当荒谬，但我认为这个思路在某些场景下确实能派上用场。
