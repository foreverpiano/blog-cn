在 CouchDB 中实现全文搜索……用 CouchDB 自己搞定

2008-12-08 · 阅读原文

我正在做一个项目，希望能在 CouchDB 上使用全文搜索。今天花了太多时间研究可行的方案。在比较实用的选项中，有 CouchDB-Lucene 和 CouchDB-Solr 项目，但我非常坚持想在不依赖任何外部项目的情况下实现全文搜索。

结果还真让我搞出来了。

方法一：单词限制。

如果把这个叫“全文搜索”，我大概会被人扔石头，但它确实能让你检索出包含某个特定单词的所有文档。（不过如果数据库比较大，第一次构建索引会花很长时间。我那台可怜的 Macbook 为 6 万个文档（总共 230 万个单词）建立索引花了大约 40 分钟。不过索引建成之后，检索速度倒是很快——可惜检索结果没什么用。）

（如果你认真想这么做，应该先对单词进行更好的清洗，并且把单词列表转成集合。）

方法二：虽然很恐怖，但确实能用——在“能用”的某种意义上。

CouchDB 视图的 key 不必只是字符串，它可以是任何合法的 JSON 值。因此，你可以这样来思考搜索需求（为了可读性这里没有做 URI 编码）：

http://localhost:5984/mydb/_view/_search/lookup?key="couchdb view"

但如果你把 key 的结构改一改，也可以这样来思考：

http://localhost:5984/mydb/_view/_search/lookup?key=["couchdb,"view"]

也就是说，你可以用 JavaScript 数组而不是字符串来作为 key。因此，如果我们能为每个文档生成包含所有可能单词组合的数组作为索引，就能实现全文搜索了。

等等，你为什么要把浏览器关掉？别啊，坚持一下，很快的。查找速度会非常快。至于空间和时间复杂度都特别恐怖，谁在乎呢？这反正只是一次性成本——虽然是个巨大的一次性成本——但它还是挺新奇的。如果你只需要索引很少的文本（比如只有标题，或者标题加标签），这个方法说不定真的能用。

如果你想要所有只包含 “NFL” 这个词的文档排列，可以访问这个 URI：

http://127.0.0.1:5984/bossv/_view/_search/word?key=["NFL"]

如果你想要所有包含 “NFL” 的文档排列，也可以这样做：

http://127.0.0.1:5984/bossv/_view/_search/word
    ?startkey=["NFL"]&endkey={}

最后简单提一句，你可以把这个技术稍作调整，用来获取带有任意标签组合的博客文章。这是一种关系型数据库很难高效建立索引的复杂查询，但用上面的方法，CouchDB 却能轻松搞定。因此，虽然建立“全排列索引”这个例子听起来很荒唐，但我认为这种技术在某些场景下还是能真正发挥作用的。
