使用 Django 开发服务器作为代理，减少痛苦

2008-09-30 · 阅读原文

在进行 Web 开发时，你偶尔会遇到这样的情况：正在开发新的用户界面或重新设计网站，但又不能或不想把正在替换的现有部分完全拆掉。也许是专横的 IT 部门必须审批开发服务器的所有重启，或者你的新项目只是沿着不同思路快速做的一个原型，在原型证明其价值之前，你不想花时间去替换当前的系统。

和往常一样，Django 在这种情况下成为了一个得力的工具。通过少量的自定义，你就可以使用 Django 开发服务器来处理特定的 URL 模式，并将剩余的请求透明地代理到另一台服务器。

为什么？

对于开发来说，Django 开发服务器确实是个福音。它不算快，但也足够快，而且代码修改后自动重启的功能大大加快了开发速度。你可以在现有平台之上透明地进行开发。这在构建依赖 RESTful API 的重 JavaScript 应用时尤其有用（因为你是在客户端实现新功能，而有了精心设计的 API，你就不需要修改服务端的代码）。特别是，这种方法允许你跨域使用基于 XMLHttpRequest 的 Ajax 功能，而不会被浏览器阻止并说“不”。这是因为你正在本地请求 URL，代理会从远程主机获取它，最后再返回给请求者，就像一切都是在本地发生的一样。这也意味着，当你最终将新的 UI 或功能集成到现有应用中时，不需要修改任何 URL。你不需要对主服务器有管理员权限（也不需要具备构建它的能力或知识）。你不必等待服务器重启、缓存清除或设置重置。
