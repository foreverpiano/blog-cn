操作指南

是中的一章，讲述了作为高管如何制定工程策略。是《Staff Engineer》中的一章，讨论了在没有高管权限的情况下如何推动工程策略（主要通过文档化实现）。Simon Wardley 的 Wardley Maps 则详细解释了如何使用 Wardley Maps 来理解和改进策略。撰写工程战略工程主管入门指南先写五个，再提炼：好的工程策略其实很无聊。

书籍

除了我自己撰写的《Staff Engineer》和（这两本书中都有关于工程策略的章节）之外，以下是一些与该主题相关的有趣书籍：工程主管入门指南

Eben Hewitt 的——一本注重方法论的书，讲述如何创建和传达工程策略。Anderson、McCann 和 O’Reilly 合著的——通过探讨 Liberty Mutual 采用 Serverless 的理由，来介绍 Wardley Maps。《The Phoenix Project》由 Kim、Behr 和 Spafford 合著——这是 Goldratt《The Goal》的现代改编版本，展示了如何使用约束优化来建模和解决问题。以前我并不认为这是一本策略书，但随着我对“策略是什么”（绘制地图 + 指导策略）的理解不断演进，我认为它展示了一种非常有用的映射策略。Jeanne Ross、Peter Weill 和 David Robertson 合著的——一本2006年出版的有趣读物，讲述了当时企业中软件（当时称为 IT）的成熟度演进，以及如何在不同业务单元之间选择耦合与集成策略。Nick Tune 与 Jean-Georges Perrin 合著的《Architecture Modernization》——涵盖了与《Technology Strategy Patterns》和《The Value Flywheel Effect》相似的主题，但由于出版时间较晚，往往提供了更新的案例和参考文献。技术战略模式笔记价值飞轮效应 笔记企业架构即战略 笔记

以下是一些更广泛讨论策略（而非专门针对工程策略）的书籍：

Richard Rumelt 的《Good Strategy, Bad Strategy》——这是我读过的最有帮助的策略书籍，因为它真正提供了一个可用的策略定义。Richard Rumelt 的——Rumelt的另一本好书，这本更侧重于如何制定策略以及策略制定为什么经常失败（相比《Good Strategy, Bad Strategy》，它在策略文档化方面的结构化关注较少）。Donella Meadows 的《Thinking in Systems: A Primer》——一本关于系统思考的书，很长一段时间里它是我用来理解周围事物的唯一工具。这不是一本软件工程书籍，但它提供了一种有用的映射机制，你可以将其应用到软件和软件开发领域（就是我用系统思考来建模软件系统的一个例子）。Bent Flyvbjerg 和 Dan Gardner 合著的《How Big Things Get Done》——一本引人入胜的书，分析了为什么有些大型项目会惨烈失败，而另一些却能以低于预算和计划的时间成功。它关联了许多相关主题，例如如何帮助评估策略中的指导策略。《关键点》笔记为什么限制在制品数量有效基准分析。

案例研究

每当讨论工程策略时，总会有人无奈地提到公开记录的策略实在太少。意识到这一点，以下是我找到的一些案例研究：

解决工程策略危机——这篇博文和视频简要介绍了 Uber、Stripe 和 Calm 的工程策略。探索的量级公开记录了 Stripe 的工程策略。《The Value Flywheel Effect》（见上方“书籍”部分）详细介绍了 Liberty Mutual 的工程策略，同时还包含了 A Cloud Guru、Workgrid 和 BBC 的案例研究。Rich Archbold 的《Run less software》——对 Intercom 工程策略核心原则的精彩阐述。Adams 和 Rodgers 合写的《How Big Technical Changes Happen at Slack》——这虽然不完全是 Slack 的工程策略，但其中包含了他们工程策略的许多组成部分。Anna Shipman 的《The difficult teenage years: Setting tech strategy after a launch》——分析了 FT 的工程策略，特别是那种直到生命周期较晚阶段才真正被明确定义的策略（这种情况其实非常普遍，只是大家通常不愿承认）。

还有一些资源介于案例研究和工程实践之间，无法完全归入上述分类，但同样值得阅读：

Dan McKinley 的 BoringTechnology.club ——许多工程策略中都会包含的指导原则。GitLab Strategy ——严格来说这是 GitLab 的公司整体策略，但由于他们是一家为技术人员构建技术的科技公司，即使其高度略高于纯粹的工程策略，依然值得一读。

博客文章

Aleix Morgadas 的《Engineering Strategy is a Fractal》——对策略在组织多个层面同时存在的有趣探讨。Sarah Taraporewalla 的《Defining a Tech Strategy》——一个有趣的科技策略模板和方法。我不确定作者是否读过《Technology Strategy Patterns》，但这篇文章中出现了那本书的许多思想，只是举例和侧重点有所不同。

视频

Gregor Hohpe 的《Enterprise Architecture = Architecting the Enterprise?》——关于 IT 在企业中扮演角色的演讲，同时使用金融领域“期权”的定义，探讨了将策略比喻为“出售期权”的概念。
