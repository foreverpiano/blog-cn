Django 松耦合设计哲学简介

2008-07-22 · 阅读原文

Django 的核心设计哲学之一就是松耦合。这既是 Django 最优秀的特性之一，也往往需要一定的时间和实践才能真正理解它的价值（以及如何充分利用它）。本系列短教程将首先简要介绍 Django 松耦合哲学的含义，以及它对使用 Django 开发项目的开发者有哪些好处，随后会通过几个小型示例项目，展示如何替换 Django 技术栈中的各个独立组件。

什么是松耦合

松耦合意味着 Django 功能栈中的各个组件都尽可能保持独立。例如，Django 的模板语言非常适合用来展现模型（model）中的数据，但同样可以轻松地用来渲染其他类型的 Python 对象。Django ORM 能方便地配置和访问数据库，但你也可以选择使用 SQLAlchemy 来替代它。

这种设计让 Django 应用更容易与遗留系统集成，但更重要的是，它允许你使用自己熟悉的工具，以及最适合当前具体问题的工具。很多刚接触 Django 的开发者可能会不喜欢 Django 工具链中的某些部分，并建议让 Django 的行为更接近他们熟悉的框架和工具。然而，Django 的解决方案既极其简洁又极其强大：如果你更喜欢其他工具，那就直接使用它们吧。

Django 并不是一个从天而降、强制统治你项目的巨型工具，它提供了一组相互之间愿意协作的工具，同时也同样愿意与你自行选择的工具协作。从 Ruby on Rails 或其他高度主见（opinionated）框架转过来的开发者，可能已经习惯遵循框架的最佳实践，以避免与一个“自以为比你更懂你的项目”的框架对抗。但在使用 Django 时，你将重新回到驾驶座上。1
