基于 Redis 的 Python 数据结构

2010-09-05 · 阅读原文

最近在工作中我经常和 Redis 打交道，并且真的喜欢上了它。后来我突然想到，用 Redis 作为后端来实现 Python 最常用的数据结构——列表和字典，其实非常简单。不仅实现起来容易，这种方式还能带来一些额外的好处：更高的可读性、跨进程/线程/机器的分布式能力，以及对现有接口的熟悉感。

基于这些想法实现的代码已经放到了 Github 上。在你跑去查看之前，我们先来看几个简单却强大的应用场景：共享配置机制和经典的生产者-消费者示例。

共享配置

当你开始进行大规模系统开发时，管理共享配置数据会成为一个越来越重要的问题。幸运的是，这是一个可以解决的问题。下面就是一个解决方案。

import redis_dict
# create and edit the configuration
x = redis_dict.RedisDict()
x['mysql-master'] = "127.0.0.0:1999"
x['mysql-slaves'] = "127.0.0.1:2000,127.0.0.2:2001"
x['mysql-slaves'] = x['mysql-slaves'] + ",127.0.0.3:2002"
# read the config on your machines
x = redis_dict.RedisDict()
master = x['mysql-master'].split(':')
slaves = [ y.split(':') for y in x['mysql-slaves'].split(',') ]

非常简单。长期运行的进程需要定期检查配置是否发生变化，虽然有点麻烦，但还是可行的。

分布式生产者和消费者

当架构发展到一定规模时，大多数系统都会迫切需要一个消息队列。很多团队最终选择在 MySQL 之上搭建一个奇怪的队列实现。还有不少人选择了 RabbitMQ，但它并不总能完全兑现“Messaging that just works”的口号。让我们来看看另一种不同的方法。

import redis_list
# producer
import random
x = redis_list.RedisList("producer-queue")
for i in xrange(0, 100):
x.append(random.randint(0,101)
# consumer
x = redis_list.RedisList("producer-queue")
while True:
n = x.pop(blocking=True)
print "Popped %s" % (n,)

系统中可以存在大量的生产者和消费者，它们不必运行在同一台机器上。你不需要纠结于 Python 的线程或 multiprocessing，而是可以直接从命令行启动任意数量的进程。很不错，对吧？

一个配置良好的 Redis 集群可以在主库宕机时自动将写操作 failover 到从库，让系统在不丢失数据、也不需要等待主库恢复的情况下继续运行；这些特性在 RabbitMQ 中是很难实现的。对于更进一步的需求，可以通过 Redis 的 LTRIM 命令轻松限制队列的最大长度，从而保证队列的稳定性。而对于最有野心的实现，可以参考 Kestrel 的策略：监控队列长度，当队列过大时将消息拉出并写入文件，等队列恢复后再重新填充（这可以通过使用两个 Redis 列表来实现，且不会丢失消息顺序——对象从输入队列被移动到序列化文件或处理队列（当处理队列低于最小大小时），在磁盘上仍有数据时，不会直接从输入队列写入处理队列）。

好了，去动手做点东西吧。
