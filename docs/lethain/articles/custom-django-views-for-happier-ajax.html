为更愉快的 Ajax 编写自定义 Django Views

2008-09-24 · 阅读原文

本文接续《Intro to Unintrusive JavaScript with Django》的内容。在第一部分中，我们坚持不编写自定义视图来处理应用的 Ajax 部分，这导致了大量丑陋的代码和别扭的功能实现。

在这个第二部分，我们将迈出这一步，编写两个自定义视图来处理 Ajax，从而开启一个简单得多的 JavaScript 世界，减少约 90% 的糟糕代码。

更新 notes/urls.py

首先我们需要更新 notes/urls.py 文件，加入两个新的 URL。更新完成后，文件内容应该如下所示：

from django.conf.urls.defaults import *
from models import Note
notes = Note.objects.all()
urlpatterns = patterns(
'',
(r'^$',
'django.views.generic.list_detail.object_list',
dict(queryset=notes)),
(r'^note/(?P<slug>[-\w]+)/$',
'django.views.generic.list_detail.object_detail',
dict(queryset=notes, slug_field='slug')),
(r'^create/$','notes.views.create_note'),
(r'^ajax_create/$','notes.views.ajax_create_note'),
(r'^note/(?P<slug>[-\w]+)/update/$','notes.views.update_note'),
(r'^note/(?P<slug>[-\w]+)/ajax_update/$','notes.views.ajax_update_note'),
)

我们所做的只是添加了 ^ajax_create/$ 和 ^note/(?P<slug>[-\w]+)/ajax_update/$ 这两个 URL 模式。

编写 ajax_create_note 视图

接下来我们需要真正编写两个新的视图：ajax_create_note 和 ajax_update_note。

因为比较简单，我们将继续以之前相同的数据和格式传递给它们。

最大的区别在于，我们将以 JSON 格式序列化返回响应，这是所有 JavaScript 生命体都推荐的“饮食”。

首先在 notes/views.py 文件顶部添加以下导入语句：

from django.utils import simplejson
from django.http import HttpResponse

然后添加以下函数：

def ajax_create_note(request):
    success = False
    to_return = {'msg':u'No POST data sent.' }
    if request.method == "POST":
        post = request.POST.copy()
        if post.has_key('slug') and post.has_key('title'):
            slug = post['slug']
            if Note.objects.filter(slug=slug).count() > 0:
                to_return['msg'] = u"Slug '%s' already in use." % slug
            else:
                title = post['title']
                new_note = Note.objects.create(title=title,slug=slug)
                to_return['title'] = title
                to_return['slug'] = slug
                to_return['url'] = new_note.get_absolute_url()
                success = True
        else:
            to_return['msg'] = u"Requires both 'slug' and 'title'!"
    serialized = simplejson.dumps(to_return)
    if success == True:
        return HttpResponse(serialized, mimetype="application/json")
    else:
        return HttpResponseServerError(serialized, mimetype="application/json")

正如前面提到的，ajax_create_note 与 create_note 之间唯一的重大区别是我们对输出进行了序列化。

如果我们足够勤奋，可以对这两个方法进行大幅重构，但本教程中我们还是保持它们原样。

现在我们需要更新 notes/note_list.html 模板中的 JavaScript，以利用这些变化。

更新 notes/note_list.html 模板

首先我们需要修改 create_note JavaScript 方法，让它向新的 URL 发送数据。

将下面这行代码：

var args = { type:"POST", url:"/create/", data:data, complete:done };

修改为：

var args = { type:"POST", url:"/ajax_create/", data:data, complete:done };

之后，我们唯一需要做的改动就是去掉 done 函数里那些正则表达式的垃圾代码，换成简单愉快的写法（当然也引入了一个安全漏洞，咳咳）。

新的 done 函数如下所示：

var done = function(res, status) {
  var txt = res.responseText;
  var data = eval('('+txt+')');
  if (status == "success") {
    var newLi = $('<li><a href="'+data.url+'">'+data.title+'</a></li>');
    $("#notes").prepend(newLi);
    $("#title").val("");
    $("#slug").val("");
  }
  else display_error(data.msg, $(".new"));
}

我们首先通过 eval 函数将收到的 JSON 转换为 JavaScript 数据结构。这是将 JSON 转换为可用形式的最简单方法。

这种做法并不安全，因为你实际上是在执行收到的 JSON，如果其中包含任何恶意指令，你也会一并执行它们。

目前我们先略过这个问题，你可以参考这篇文章中标题为“JSON Via Parse”的部分，了解如何做得更安全。

现在你可以启动开发服务器并测试首页了。

它的运行方式和之前完全一样，但不再依赖那些随意拼凑的正则表达式来剥离必要内容。

更新 notes/note_detail.html 模板

打开 notes/note_detail.html 文件。

在 perform_update 函数中，我们将再次修改 args 字典。这次它会变成这样：

var args = { type:"POST", url:"ajax_update/", data:data, complete:done };

我们只是修改了要提交的 URL。然而现在我们要进行更多改动。我们第一次实现中最大的问题之一是它会发送不必要的更新。

之前我们很难改进它，因为缺少一些关键信息，但现在不同了。ajax_update_note 视图返回了我们需要的所有信息，让我们可以维护一份简单的数据历史，仅在实际发生变化时才提交更新。

此外，对于容易出错的字段（slug），我们有足够的信息来回滚失败的更新，并在 slug 成功更新时重定向到笔记的新 URL。

我们从历史记录开始。删除 initialTitleChange 和 initialSlugChange 的初始值，并替换为以下代码：

var history = { title: $("#title").val(), slug: $("#slug").val() };

接下来我们需要更新 title_to_span 和 slug_to_span 函数，让它们在发送更新前先检查历史记录中存储的值。

var title_to_span = function() {
  var title = $("#title");
  if (title.val() != history['title']) {
    perform_update("title", title.val());
    history['title'] = title.val()
  }
  var span = $('<span id="title"><em>'+title.val()+'</em></span>');
  span.hover(title_to_input,function() {});
  title.replaceWith(span);
}

修改在第 3 到 5 行。在发送更新前，我们检查它是否与当前值不同。如果确实发送了更新，则更新历史记录中存储的当前值。

我们对 slug_to_span 也做同样的处理。

var slug_to_span = function() {
  var slug = $("#slug");
  if (slug.val() != history['slug']) {
    perform_update("slug", slug.val());
    history['slug'] = slug.val();
  }
  var span = $('<span id="slug"><em>'+slug.val()+'</em></span>');
  span.hover(slug_to_input,function() {});
  slug.replaceWith(span);
}

我们也可以对文本框做同样的处理，但暂时先跳过。

最后我们需要稍微更新一下 done 函数。

var done = function(res, status) {
  var txt = res.responseText;
  var data = eval('('+txt+')');
  if (status == "success") {
    display_success("Updated successfully.", $(".text"));
    if (data.url) {
      window.location = data.url
    }
  }
  else {
    display_error(data.msg, $(".text"));
    if (data.slug) {
      history['slug'] = data.slug;
      $("#slug").text(data.slug);
    }
  }
}

我们首先将返回的 JSON 解析为 JavaScript 数据结构。然后是显示成功和错误消息的标准逻辑，以及处理 slug 字段更新的一些自定义逻辑。

具体来说，如果我们成功更新了 slug，则使用 JavaScript 重定向到笔记存在的新 URL；如果更新 slug 失败，则将 slug 字段（以及 history.slug）中的值回滚到它实际的当前值（而不是我们试图修改成的值）。

通过这些修改，note_detail.html 模板中的 Ajax 从一个繁重而糟糕的混乱代码，演变为比原始非 Ajax 版本提供更快、更愉悦用户体验的实现。
