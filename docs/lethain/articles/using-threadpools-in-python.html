在 Python 中使用线程池

2009-02-10 · 阅读原文

和大多数程序员一样，我在使用线程时总会暗自感到愉悦。我知道一些小疏忽就可能导致死锁，进而造成难以诊断的严重问题，但说实话，线程就是通往狂喜白日梦的入口——幻想着自己的新脚本能多么高效地利用多核……或者说，如果真的有人在使用它的话，它本可以做到。

幸运的是，对于我们这些追求这种“误入歧途”的快感的人来说，Python 能让你快速轻松地组建一个可靠的线程池。你只需要标准库中的 Queue 和 threading 模块即可。Queue.Queue 是一个线程安全的队列，而 threading.Thread 则提供了一个创建线程的简单接口。

下面我们来看一个在 Python 中安全使用线程的示例。

本例使用的是 Python 2.5，如果是 Python 2.6 则需要去掉 from __future__ import 的语句。对于 Python 3k，则需要把 from Queue import Queue 改成 from queue import Queue，并给 print 添加括号。（我漏掉什么了吗？我还没真正用过 Py3k……）我们使用 csv.DictReader 而不是 csv.reader，因为前者会返回一个 key=>value 的字典映射（把第一行当作键），而后者返回的是一个有序元组。你不必把线程保存在列表中（像上面代码里的 workers 那样），但这是一种保留线程引用的简便方式。我在这里使用 range，因为它是 Py3k 中保留的函数，但对于 Py2.x 代码，使用 xrange 显然更合适。

我们可以更多地利用 logging 和 optparse 模块，让上面的脚本更加健壮。
