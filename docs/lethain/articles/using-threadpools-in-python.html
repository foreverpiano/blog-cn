在 Python 中使用线程池

2009-02-10 · 阅读原文

像大多数程序员一样，我在项目中使用线程时总会暗自窃喜。我知道一些小小的疏忽就可能导致死锁，带来难以诊断的灾难，但我们得承认，线程是通往美梦的入口——你会幻想着自己的新脚本如何高效利用多核……或者说，如果真的有人使用它的话，它本可以这样。

幸运的是，对于我们这些追求这种不靠谱快感的人来说，Python 能让你快速轻松地组建一个可靠的线程池。你只需要标准库中的 Queue 和 threading 模块即可。Queue.Queue 是一个线程安全的队列，而 threading.Thread 则提供了一个创建线程的简单接口。

下面我们来看一个在 Python 中安全使用线程的例子。

使用线程池处理 CSV 文件

这个脚本会遍历一个逗号分隔值文件，并使用线程池来处理接收到的数据。

from __future__ import with_statement
from time import sleep
from csv import DictReader
from Queue import Queue
from threading import Thread
q = Queue()
workers = []
def worker():
while True:
line = q.get()
print "processing: %s\n\n" % line
q.task_done()
for i in range(10):
t = Thread(target=worker)
t.setDaemon(True)
workers.append(t)
t.start()
with open('myfile.csv','r') as fin:
for line in DictReader(fin):
q.put(line)
q.join()

几点说明：

  • This is Python2.5, you'd want to drop the from __future__ import for Python2.6. For 3k you'd switch the from Queue import Queue to from queue import Queue, as well as adding parens to print. (Did I miss anything? Haven't actually used Py3k yet...)
  • We're using csv.DictReader instead of csv.reader because it returns a dictionary of key=>value mappings (treating the very first row as the keys), as opposed to csv.reader which returns an ordered tuple.
  • You don't have to keep the threads in a list (embodied by workers above), but it's an easy way to keep references to them.
  • I use range here, as it is the last-function-standing in Py3k, but certainly it would be more appropriate to use xrange for Py2.x code.

添加对 XML 处理的支持

你可能会觉得本文接下来的部分有些刻意，但我刚学完 ElementTree 的新鲜知识，所以让我们来写一个 manage_xml_file 函数吧。

假设我们收到的是以下格式的 XML 文档……

<list>
    <item/>
    <item/>
    <item/>
</list>

……并且我们希望处理其中的每一个 item。但让我们加点难度：假设我们知道要处理根节点的子元素，却不知道根节点和子元素的名称。而且，该死的，我们还想快速地、只用一次遍历就完成。让我们更疯狂一点：假设即使 XML 文档最终被证明是格式错误的，我们也想尽可能多地提取出格式正确的元素。2

首先我们需要导入 ElementTree。对于 Python 2.x，值得花点时间尝试导入 cElementTree，如果它可用的话。3

try:
    from xml.etree import cElementTree as ElementTree
except ImportError:
    from xml.etree import ElementTree

在 Python 3.0 中，C 模块和 Python 模块的区别基本上被消除了，因此这个 try...except 的把戏就没必要了，你只需使用一个 import 即可。

from xml.etree import ElementTree

现在让我们开始动手吧。

def manage_xml_file(file, logger, threads=10):
    def serialize(e):
        'Recursively serialize an ElementTree.Element'
        tag = e.tag
        text = e.text
        attributes = e.items()
        kids = e.getchildren()
        if text and not (attributes or kids):
            return text
        else:
            d = {}
            if text:
                d['_text'] = text
            for key, val in attributes:
                d[key] = val
            for kid in kids:
                tag = kid.tag
                serialized = serialize(kid)
                if d.has_key(tag):
                    val = d[tag]
                    if type(val) == type([]):
                        val.append(serialized)
                    else:
                        d[tag] = [val, serialized]
                else:
                    d[tag] = serialized
        return d

对这个脚本也有几点说明：

  • I find it much more pleasant to serialize the elements into a native Python dictionary and then process it.Yes, the serialize function is a bit verbose. And yes, on a sufficiently nested XML element it would run into Python's limitations for recursion. I'm okay with that.It turns out that serializing XML to any combination of dictionaries and arrays is a bit of a black art, but I think that serialize gets it pretty much right.
  • iterparse is kind enough to tell us what line and character it fails on, which is more generous than many XML libraries, so we get to extract as much data as possible and know where the error is. You're (unfortunately) going to be hard pressed to get a whole lot more out of XML.iterparse is also the fastest XML processor for Python, which is a nice side-effect of it's other nice aspects.
