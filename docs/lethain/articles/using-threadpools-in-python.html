在 Python 中使用线程池

2009-02-10 · 阅读原文

和大多数程序员一样，我在项目中使用线程时会暗自感到愉悦。我知道一些小小的疏忽就可能导致死锁，进而造成难以诊断的严重问题，但我们得承认，线程是通往狂热白日梦的大门——幻想着自己的新脚本能多么高效地利用多核……或者说，如果真的有人在使用它的话，它本可以做到。

幸运的是，对于我们这些追求这种误导性快感的人来说，Python 能让我们快速轻松地搭建一个合理的线程池。你只需要标准库中的 Queue 和 threading 模块即可。 Queue.Queue 是一个线程安全的队列，而 threading.Thread 则提供了一个创建线程的简单接口。

让我们来看一个在 Python 中安全使用线程的示例。

使用线程池处理 CSV 文件

这个脚本会遍历一个逗号分隔值文件，并使用线程池来处理接收到的数据。

from __future__ import with_statement
from time import sleep
from csv import DictReader
from Queue import Queue
from threading import Thread
q = Queue()
workers = []
def worker():
while True:
line = q.get()
print "processing: %s\n\n" % line
q.task_done()
for i in range(10):
t = Thread(target=worker)
t.setDaemon(True)
workers.append(t)
t.start()
with open('myfile.csv','r') as fin:
for line in DictReader(fin):
q.put(line)
q.join()

几点说明：

这是 Python 2.5 版本的代码，对于 Python 2.6 你需要去掉 from __future__ import。对于 Python 3k，你需要把 from Queue import Queue 改为 from queue import Queue，同时给 print 添加括号。（我漏掉了什么吗？我还没真正用过 Py3k……）我们使用 csv.DictReader 而不是 csv.reader，因为它会返回一个 key=>value 映射的字典（将第一行作为键），而 csv.reader 返回的是一个有序元组。你不必把线程保存在列表中（上面由 workers 体现），但这是一种方便保留引用的方式。我在这里使用 range，因为在 Py3k 中它是唯一保留的函数，但对于 Py2.x 代码，使用 xrange 显然更合适。

我们可以通过大量使用 logging 和 optparse 模块，让上面的脚本变得更加健壮。

添加对 XML 处理的支持

你可能会觉得本文接下来的部分有些刻意，但我刚掌握了 ElementTree 的新鲜知识，所以让我们来一起写一个 manage_xml_file 函数吧。

假设我们收到的是以下这种格式的 XML 文档……

<list>
    <item/>
    <item/>
    <item/>
</list>

……并且我们希望处理其中的每一个 item。但让我们增加一点难度：假设我们知道要处理根元素的子节点，但我们甚至不知道根元素或子元素的名称。而且，该死的，我们还想快速地、单次遍历就完成这一切。让我们再疯狂一点：假设即使 XML 文档最终是格式错误的，我们也希望尽可能多地提取格式良好的元素。

首先我们需要导入 ElementTree。对于 Python 2.x，值得花时间尝试导入 cElementTree（如果可用的话）。

try:
    from xml.etree import cElementTree as ElementTree
except ImportError:
    from xml.etree import ElementTree

在 Python 3.0 中，C 模块和 Python 模块的区别基本被消除，因此这个 try...except 的把戏就没必要了，只需一个 import 即可。

from xml.etree import ElementTree

关于这个脚本也有几点说明：

我觉得把元素序列化成原生的 Python 字典，然后再进行处理要舒服得多。是的，serialize 函数写得有点啰嗦。而且如果 XML 元素嵌套足够深，它会碰到 Python 的递归限制。我对此表示接受。事实证明，将 XML 序列化为字典和数组的任意组合是一门有点玄学的艺术，但我认为 serialize 函数做得相当不错。iterparse 会友好地告诉我们它在哪一行、哪个字符失败，这比许多 XML 库都要大方，所以我们能够提取尽可能多的数据，并且知道错误发生在什么位置。（遗憾的是）你很难从 XML 中再榨出更多东西了。iterparse 也是 Python 中最快的 XML 处理器，这也是它其他优点的附带好处。

然后我们需要更新 main 函数，检查文件是否以 xml 结尾，并调用 manage_xml_file。

if filename.endswith('csv'):
    manage_csv_file(filename, logger, threads=threads)
elif filename.endswith('xml'):
    manage_xml_file(filename, logger, threads=threads)
else:
    print u"Cannot handle filename %s" % filename.split('.')[0]
