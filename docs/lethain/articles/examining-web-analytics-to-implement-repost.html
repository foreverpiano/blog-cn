剖析网站分析工具的实现（转载）

2007-06-21 · 阅读原文

这篇文章是从最初的《Irrational Exuberance》博客移植而来，撰写于2007年中期，距今已近两年。

使用互联网就是成为一个数字。这不仅意味着我们被剥夺了个体差异，被无形的机器之手对待（或误待），还意味着我们成了跟踪编号——我们被标记、被追踪，并在不经意间留下了大量关于自己的数据。在 Google Operating System 博客的一篇文章中，作者提到 Google 的 Google Analytics 程序已积累了 220 TB 的数据。该数据量仅次于其搜索引擎爬虫使用的数据库，后者拥有 850 TB 的数据。（Google Earth 仅使用 80.5 TB。）按照目前的增长速度，Analytics 的数据量将很快超过网页爬虫——这意味着海量关于“谁在做什么、他们在哪儿做”的数据。那么，这听起来挺可怕的，我们该怎么办呢？当然是自己写一套分析系统！最近我正在为 Django 开发一个网站分析工具包，而在初期，它像大多数编程项目一样，极有可能因无数细微问题而半途而废。本文旨在探讨网站分析系统的整体设计，以及如何实现它。它会稍稍深入几个关键细节，但不会试图用代码完整实现一套分析系统。（对于感兴趣的读者，我将在未来几天完善这个 Django 网站分析系统，并以开源许可证发布。本文不会再进一步讨论它，但我计划在接下来几天内撰写几篇相关文章，分别涉及实现与设计、安装、使用以及缺陷等方面。）
