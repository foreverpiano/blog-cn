用文件互斥锁防止 Cron 任务“癌症”

2008-12-03 · 阅读原文

最近在工作中，我需要编写一个脚本，它会遍历目录中匹配某个正则表达式的文件，对这些文件执行一些操作，然后将其删除。我不希望这个脚本一直运行着，于是决定通过 cron 任务让它每分钟执行一次（如果没有需要处理的文件，脚本会立刻退出）。

但我的计划有个小问题：脚本的执行时间有可能超过一分钟，如果同时有两个实例在运行，那将会是一件很糟糕的事情。思考了几分钟后，我找到了一个简单且足够有效的解决方案——使用文件作为互斥锁（mutex）。

基本原理

这个系统的运作逻辑非常简单：

脚本启动时，首先检查是否存在一个名为 my_script.lock 的文件。如果该文件不存在，则创建它，并将当前时间戳（自 epoch 以来的秒数）作为其唯一内容写入。如果文件存在，且其中记录的时间戳是在最近一小时之内，则终止脚本执行。（如果没有在上面第三步中止）则继续执行脚本逻辑。脚本完成后，删除 my_script.lock 文件。

最初我并没有在文件中写入时间戳，后来加上时间戳后，就可以让锁在被锁定过长时间（暗示脚本可能已经崩溃）时自动过期，而无需手动删除锁文件。

Perl 实现

在 Perl 中实现这个基于文件的互斥锁既快速又轻松。除非你是个可怜的 Perl 码农，否则可能得花不少时间把所有需要的文档拼凑起来。

我确实花了不少时间才把它拼出来。

my $lock_file = '/tmp/my_script.lock';
my $expire_lock_after = 60 * 30;
sub is_locked {
# -e is a function that checks for file existence
if (-e $lock_file) {
# this line declares there is no line delimiter
local $/=undef;
open LOCK, "<$lock_file" or warn "Couldn't open $lock_file";
my $ts = <LOCK>;
close LOCK;
if ( $ts > time() - $expire_lock_after ) {
return 1;
}
}
return undef;
}
sub lock {
open LOCK, ">$lock_file" or warn "Couldn't open $lock_file";
print LOCK time();
close LOCK;
}
sub unlock {
unlink($lock_file);
}
if (is_locked) die "$lock_file is locked";
lock();
print 'do whatever';
unlock();
