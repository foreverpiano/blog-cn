双面 Django 第四部分：Web 应用

2007-12-09 · 阅读原文
  • 你可以在此处找到查看本项目在线版本的详情，包括网页和 Facebook 两种界面。

好了，我们已经编写了模型、测试，甚至还有表单，但目前还没有任何实际的功能。不过别担心，我们马上就要改变这一点。

在本篇教程中，我们要实现大部分的 Web 应用（它只是用户与核心应用之间的一个中间层，我们的核心功能都在核心应用里）。事实上，除了 Ajax 相关部分之外（这些我们会在下一部分实现），我们要把其他所有功能都实现：很快我们就会有一个可以在浏览器中实际使用的应用了。

编写 web/urls.py 文件

现在我们需要在 polling/web 目录下创建一个新文件：urls.py。

emacs web/urls.py

并且要在文件顶部加入两个 import 语句：

from django.conf.urls.defaults import *
from polling.core.models import *

我们要为 Web 项目创建三个不同的 URL 模式：一个用于查看投票列表，一个用于查看特定投票，还有一个用于创建投票。代码大致如下：

polls = Poll.objects.all()
urlpatterns = patterns(
    (r'^$', 'django.views.generic.list_detail.object_list', dict(template_name='web/poll_list.html', queryset=polls)),
    (r'^poll/(?P<object_id>\d+)/$', 'django.views.generic.list_detail.object_detail', dict(template_name='web/poll_detail.html', queryset=polls)),
    (r'^create/$', 'polling.web.views.create'),
)

观察上面的代码，我们使用了泛型视图（generic views），从而避免编写重复的通用代码。对于这些视图，我们唯一需要自行编写的内容就是用于渲染的模板。

调整我们的模板（适配泛型视图）

我们正在编辑的 urls.py 文件位于 *web 应用* 中，并且用于展示 Poll 模型，因此列表和详情的泛型视图（默认情况下，该行为可被重写）会去 web/poll_list.html 和 web/poll_detail.html 中寻找模板。

在创建这些模板之前，我们先来准备一个基础模板，让所有 Web 模板都能继承它。我们把它放在 polling/templates/web/base.html，内容大致如下：

<html> <head>
<title>{% block title %}A Generic Title{% endblock %}</title>
</head>
<body>
{% block body %}
{% endblock %}
</body> </html>

保存该文件后，现在我们来写一个非常简单的模板，用于展示 Poll 对象列表。在 polling/templates/web/poll_list.html 创建一个文件，内容如下：

{% extends "web/base.html" %}
{% block title %} Our Polls! {% endblock %}
{% block body %}
<div id="polls">
  {% for object in object_list %}
  <p id="poll{ { object.pk }}" ><a href="/poll/{ { object.pk }}/">{ { object }}</a> has a score of { { object.score }}.</p>
  {% endfor %}
</div>
{% endblock %}

接下来是一个同样简单的模板，用于展示单个 Poll 对象：

{% extends "web/base.html" %}
{% block title %} Poll: { { object.question }} {% endblock %}
{% block body %}
<div id="poll">
  <p>We have a question for you. { { object.question }}
  <p> So far we have { { object.up_votes }} upvotes and { { object.down_votes }} downvotes, for an overall vote of { { object.score }}! </p>
  <p> Do you <span id="upvote">agree</span> or <span id="downvote">disagree</span>? </p>
</div>
{% endblock %}

（我们会在本系列的下一部分中处理向上和向下投票的功能，这些功能通过 JQuery JavaScript 库实现，目前我们暂且忽略无法投票这一事实。这只是个小细节……）

一个稍微不那么“泛型”的视图

现在我们还需要编写一个视图，它不是泛型视图，所以我们得自己写一点代码。它就是我们的“创建新投票”视图。之前在 web/urls.py 中我们已经说明了它要放在哪里，让我们稍微看一眼 web/urls.py 文件。

(r'^create/$', 'polling.web.views.create'),

好的。它将被放在 polling/web/views.py 文件中一个名为 create 的函数里。在编写代码之前，我们先简单思考一下这个视图应该做什么。它需要做两件事：允许用户创建新的投票，并在用户试图创建无效投票时（这里指与之前已创建的投票提问相同）进行提示。

首先我们打开 web 应用中的 views.py 文件。

emacs web/views.py

现在在文件中加入一些 import 语句：

from django.http import HttpResponseRedirect
from django.views.generic.simple import direct_to_template
from polling.core.models import Poll, User
from polling.core.forms import PollForm

我们将使用 *PollForm* 来渲染和验证创建新投票的表单。我们需要 Poll 模型，以便在表单验证通过时创建新的实例；还需要 direct_to_template 来渲染即将为这个视图创建的模板（模板位于 templates/web/create.html，不用担心，我们马上就会编写它）。

我们的视图代码会包含一些简单的逻辑：

  1. Check if there is attached POST data.
  2. If there is POST data, attempt to create a PollForm with it.
  3. If the new PollForm is valid, then create a new Poll and redirect to the main page.
  4. If the new PollForm is not valid, return the user to the same page, but display any error messages.
  5. If there is not POST data, display an empty form for users to describe their new Poll.

用 Python 写出来是这样的：

def create(request):
    if request.method == 'POST':
        form = PollForm(request.POST)
        if form.is_valid():
	   # Because explaining in detail how to use the
	   # authentication framework isn't within my
	   # energy level at this exact moment
	    u = User(name="Someone Else")
	    u.save()
            poll = Poll(creator=u, question=form.cleaned_data['question'])
            poll.save()
            return HttpResponseRedirect('/')
    else:
        form = PollForm()
    return direct_to_template(request, 'web/create.html',
                              extra_context={'form':form})

现在我们只需要为 web.create 视图编写一个简短的模板，然后就全部完成了。

让我们打开模板文件

emacs templates/web/create.html

我们的模板看起来是这样的：

{% extends "web/base.html" %}
{% block title %} Creating a new Poll {% endblock %}
{% block body %}
<form method="post" action="">
<table>{ { form }}</table>
<input type="submit" />
</form>
{% endblock %}

至此全部完成。

测试我们的新代码

为这类代码编写单元测试会稍微困难一些。你可以编写代码来验证每个网页是否返回了预期内容，也可以接入 HTML 验证器来确认页面返回的是有效的 HTML。你甚至可以编写一些多步骤的交互测试。关键在于要确保你的测试能够承受模板发生一些变化。

我们不会在这里明确地编写这些测试，不过你自己动手实践一下是个不错的主意。另一方面，我们会用浏览器做一些快速的非正式测试，以确保这些功能正确地集成在一起。

首先我们需要为项目同步数据库：

python manage.py syncdb

系统会要求你创建一个超级用户。请继续创建。当数据库同步完成后，接下来我们要启动开发服务器：

python manage.py runserver

现在打开浏览器，访问 http://127.0.0.1:8000/create/。我们先创建一个投票，因为如果没有任何投票，泛型视图会报错（如果这个行为真的让我们很困扰，我们可以在 web/urls.py 中修改它）。

先创建一个投票，它应该会将你重定向到投票列表页面。之后返回去尝试用同一个问题再创建一个投票，它应该会显示一条错误消息，说明这个投票已经被创建过了。很好。

回到投票列表页面，点击其中一个投票，确保它表现正常（显示关于该投票的一些简短信息）。
