循环事件与消息传递

2009-11-25 · 阅读原文

在使用 Erlang actor、Clojure agent 等异步通信机制时，我一直思考的一个问题是：在异步系统中应该如何调度循环事件？

最简单的实现循环事件的方式是在循环中加入 sleep 语句，

import time
while True:
print("hello")
time.sleep(1)

但通过外部脚本去触发异步系统总让人觉得不太对劲。我真正想要的是一种能让异步分布式系统自我维持、持续运转，而无需外部干预的机制。

经过一些思考，我们可以设计出多种不同的永久异步循环，通过适当调整，它们能呈现出各式各样的特性。

其中最简单的一种永久运动机制就是乒乓循环。

乒乓循环

在只有两个 actor 的系统中，两个 actor 可以各自完成自己的工作，然后向对方发送 ping 消息，从而维持系统的永久运动。

这种方式实现起来非常简单，但最终难免让人觉得它是一种完全人为构造的方案。

Erlang 实现的 Ping-Pong 示例。

-module(ping).
-export([ping/1, test/0]).
ping(Delay) ->
receive
{ping, Target} ->
io:format("received ping from ~p…~n", [Target]),
timer:sleep(Delay),
Target ! {ping, self()},
ping(Delay)
end.
test() ->
A = spawn(ping, ping, [2500]),
B = spawn(ping, ping, [500]),
A ! {ping, B}.

Clojure 实现的 Ping-Pong 示例。

(defn ping [state]
      (println "ping")
      (. java.lang.Thread sleep (:delay state))
      (send (:target state) ping)
      state)
(def a (agent {:delay 1000, :target nil}))
(def b (agent {:delay 1000, :target a}))
(send a #(assoc % :target b))
(nil? (send a ping))

（注意我将最后的 send 用 nil? 包裹起来，是因为直接打印 send 的返回值会导致无限循环——每个 agent 的状态里都引用了对方，从而引发栈溢出错误。）

环形循环

虽然前面单独讨论了乒乓循环，但更准确的理解是把它看作只有两个节点的环。不过，环形结构比单纯的乒乓循环更接近实际，因为它能支持任意数量的节点。

环形结构是一种很好的机制，既可以用来检测多个节点是否存活，也适合在所有节点间传递更新，确保每个节点最终都能收到最新的数据。

Erlang 实现的 Circle 示例。

-module(circle).
-export([ping/2, test/0]).
ping(Target, Delay) ->
receive
ping ->
io:format("~p pinged by ~p…~n", [self(), Target]),
timer:sleep(Delay),
Target ! ping,
ping(Target, Delay);
{target, NewTarget} ->
NewTarget ! ping,
ping(NewTarget, Delay)
end.
test() ->
A = spawn(circle, ping, [nil, 2500]),
B = spawn(circle, ping, [A, 500]),
C = spawn(circle, ping, [B, 1000]),
D = spawn(circle, ping, [C, 100]),
A ! {target, D}.

Clojure 实现的 Circle 示例。

(defn ping [state]
      (println (str "ping " (:name state)))
      (. java.lang.Thread sleep (:delay state))
      (send (:target state) ping)
      state)
(def a (agent {:delay 100, :target nil, :name "a"}))
(def b (agent {:delay 1000, :target a, :name "b"}))
(def c (agent {:delay 4000, :target b, :name "c"}))
(def d (agent {:delay 2000, :target c, :name "d"}))
(send a #(assoc % :target d))
(nil? (send a ping))

协调者模式

打破环形结构的思路，协调者模式将“发送 ping”的职责集中到一个节点上，只有这一个节点需要维护 ping 逻辑，其他节点只需被动监听即可。

当你的任务只需要定时调度功能时，协调者模式非常实用。它把 ping 逻辑从大多数节点中移除，同时也允许在同一逻辑时刻向所有节点发送心跳（尽管各个 actor 实际处理 ping 的时间可能差异很大）。但默认情况下，协调者模式缺少环形结构中数据同步和更新传播的能力。

如果更新传播是必需的功能，可以让所有节点将更新发送给协调者，由协调者每隔一个周期进行广播（这样可以保证任何更新最多在两个周期内被所有节点接收）。

Erlang 实现的 Coordinator 示例。

module(coordinator).
-export([coordinator/2, listener/0, test/0]).
listener() ->
receive
{ping, Sender} ->
io:format("~p received ping from pn", [self(), Sender]),
listener()
end.
coordinator(Targets, Delay) ->
receive
ping ->
lists:foreach(fun(X) ->
X ! {ping, self()}
end, Targets),
timer:sleep(Delay),
self() ! ping,
coordinator(Targets, Delay)
end.
test() ->
A = lists:map(fun(_) ->
spawn(coordinator, listener, [])
end, lists:seq(0, 10)),
B = spawn(coordinator, coordinator, [A, 1000]),
B ! ping.

Clojure 实现的 Coordinator 示例。

defn ping [state sender]
      (println (str state " pinged by " (:name sender)))
      state)
(defn coordinate [state]
(. java.lang.Thread sleep (:delay state))
(doseq [listener (:listeners state)]
(send listener ping state))
(send (:target state) coordinate)
state)
(def coord (agent {:delay 2500, :name "a"}))
(def listeners (list (agent "b") (agent "c")))
(send coord #(assoc (assoc % :target coord) :listeners listeners))
(nil? (send coord coordinate))

Gossip 协议

Gossip 方法与环形结构有很多相似之处，但它的结构更松散，保证更少，在节点故障面前也更具韧性。

图中的传播从节点 C 开始。

在 Gossip 中，当一个节点收到 ping 后，会随机选择另一个节点进行 ping 操作。为了加快传播速度（并在单个节点宕机时增强容错），每个节点可以在一次 ping 中通知多个其他节点，但必须注意控制每个周期内 ping 的总量，避免指数级增长。

这种方式的优点在于能够容忍节点丢失，而环形结构无法承受任意节点的失效，协调者模式则对负责 ping 的节点极为敏感。

比这里介绍的简单 Gossip 更有趣的方案，是将协调者与 Gossip 结合起来。每个节点会随机 ping 另一个节点，然后 ping 自己并进入休眠。在休眠期间，它会接收其他同样在执行此过程的节点发来的更新。醒来后，它会处理之前收到的 ping（实际上只处理在它安排本次 ping 之前收到的，那些之后收到的会在本次 ping 发送之后、下一次 ping 之前处理），然后再次重复整个循环。

Erlang 实现的 Gossip 示例。

-module(gossip).
-export([ping/1, test/0]).
ping(Delay) ->
receive
{ping, Sender, Targets} ->
io:format("~p received ping from ~p…~n", [Sender, self()]),
timer:sleep(Delay),
lists:nth(random:uniform(length(Targets)), Targets) ! {ping, self(), Targets},
ping(Delay)
end.
test() ->
Pids = lists:map(fun(_) ->
spawn(gossip, ping, [1000])
end, lists:seq(0, 10)),
hd(Pids) ! {ping, self(), Pids}.

Clojure 实现的 Gossip 示例。

(defn ping [state sender]
  (println (str (:name state) " pinged by " (:name sender)))
  (. java.lang.Thread sleep (:delay state))
  (send (nth (:agents state)
             (rand-int (count (:agents state)))) ping state)
  state)
(def agents (doall (map #(agent {:name (str "agent_" %),
:delay 1000})
(range 0 10))))
(doseq [agent agents]
(send agent #(assoc % :agents agents)))
(nil? (send (first agents) ping {:name "start"}))

结束思考

我们可以把持续运行的异步系统看作是在进行某种分布式尾递归。虽然其语义比普通的 while 循环更复杂，但这些方法所蕴含的潜力也更有趣。

它们既能让系统的永久运动不受单台机器崩溃的影响，也允许同时运行多个定时器而无需编写复杂的自定义逻辑（例如不停地寻找最近要触发的定时器、休眠等待、重新调度、寻找下一个……）。

随着我对带心跳的分布式系统投入更多思考，相信会对上面这些看似简单的方案产生更细致和深入的认识。但就目前而言，它们仍是设计分布式系统时非常有用的工具。
