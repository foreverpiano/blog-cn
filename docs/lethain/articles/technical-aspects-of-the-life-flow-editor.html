Life Flow Editor 的技术细节

2008-02-03 · 阅读原文

过去几天我花了很多时间来实现 LifeFlow 编辑器，虽然还有大量工作要做，但它正逐渐成型为我想要的样子。其中有一些有趣的细节值得一提。

通过 Ajax 通用更新模型

LFE 中我使用的最重要的功能之一，是在后台发送模型更新。这意味着我无需显式提交 POST 表单就能保持内容是最新的，整体编辑过程也更少打扰，同时降低了数据丢失的风险。特别值得一提的是，你再也不会遇到保存失败导致数据丢失的情况（因为保存是增量进行的，而不是一次性整体保存）。

在之前开发的一个 Django 应用中，我写过一个完全通用的更新函数，它会自省模型来判断待保存字段的类型，然后进行相应处理。

为了实现这种通用性，代码相当复杂。下面是一些相关片段，你可以大致浏览而不用仔细阅读。（如果知道我是把一个经过 JSON 序列化的字典以 'json' 为键放在 POST 中，阅读代码示例可能会更容易。虽然现在重写的话我不一定会再用这种方式，但它当时工作得还不错，尽管听起来有点别扭。）

最终代码如下所示：

def process_json_params(request):
    'Parses received JSON into a Python dict, or returns error message.'
    if request.method == "POST" and request.POST.has_key('json'):

    else:
        return None

呼，这是一种非常复杂的方式，主要是因为它必须足够通用，以应对各种不一致的模型。幸运的是，为 LifeFlow 编辑器实现所需的更新函数要简单得多：

MANY_TO_MANY_FIELDS = ["flows", "tags", "series", "authors"]

因为我只处理一个模型（准确来说是两个模型：Draft 和 Entry，但它们的字段完全重叠，所以可以忽略它们不是同一个模型这一点），我无需对字段本身进行自省，代码也干净得多。另外一个很方便的技巧是，我可以用 login_required 装饰器来限制对这些 Ajax 调用的访问。

高亮已选中的标签/流程/系列

有一个问题我花了一点时间思考，那就是如何预先选中所有已经选择的标签。这是一个很重要的视觉提示，但幸运的是处理起来相当简单。

首先，我在 Python 的视图中使用简单的列表推导式来确定哪些项目已被选中：

@login_required
def edit_four(request, category, id):
    if category == "entry":
        obj = Entry.objects.get(pk=id)
    else:
        obj = Draft.objects.get(pk=id)
    obj_tags = obj.tags.all()
    tags = [ (x, x in obj_tags) for x in Tag.objects.all()]
    return render_to_response('lifeflow/editor/edit_four.html',
                              {'object':obj,
                               'tags':tags,
                               'model':category},
                              RequestContext(request, {}))

在 Draft 和 Entry 之间互相转换

代码中经常要做的一件事是在 Draft 和 Entry 模型之间互相转换。两个模型大部分字段都相同，Entry 是 Draft 的超集，只是 Draft 有一个 Entry 没有的 edited 字段。

我主要通过获取模型的 fields 字典，去掉不需要的字段，再补充缺失的内容来完成大部分工作。

下面是将 Draft 转换为 Entry 的代码：

@login_required
def edited_to_published(request, id):
    def slugify(str):
        return str.lower().replace(' ','-')[:95]
    def prepare_draft(draft):
        dict = draft.__dict__.copy()
        if dict['pub_date'] is None:
            dict['pub_date'] = datetime.datetime.now()
        del dict['edited']
        if dict['slug'] is None:
            dict['slug'] = slugify(dict['title'])
        return dict
    try:
        obj = Draft.objects.get(pk=id)
        pub = Entry(**prepare_draft(obj))
        pub.save()
        obj.delete()
        return HttpResponse(pub.pk)
    except TypeError:
        return HttpResponseServerError(u"Missing required fields.")
    except:
        return HttpResponseServerError(u"Update failed.")

将 Entry 实例转换为 Draft 要更简单一些：

@login_required
def published_to_edited(request, id):
    def convert_to_draft(entry):
        dict = entry.__dict__.copy()
        dict['edited'] = True
        del dict['body_html']
        return dict
    try:
        entry = Entry.objects.get(pk=id)
        draft = Draft(**convert_to_draft(entry))
        draft.save()
        entry.delete()
        return HttpResponse(draft.pk)
    except:
        return HttpResponseServerError(u"Update failed.")

动态渲染 Markdown 格式的文本

下面是处理格式化文本渲染的视图。如果指定了 model 和 id，它会直接使用对应对象的 body 文本，否则会渲染 POST 字典中 'txt' 参数的内容。dbc_markup 是 Dynamic Blog Context markup 的缩写，它会应用代码语法高亮、Markdown 格式化，以及 LifeFlow 特定的 Dynamic Blog Context 扩展。

@login_required
def render(request, model=None, id=None):
    if id is None:
        txt = dbc_markup(request.POST['txt'])
    else:
        if model == u"draft":
            obj = Draft.objects.get(pk=id)
        elif model ==u"entry":
            obj = Entry.objects.get(pk=id)
        if obj.use_markdown:
            txt = dbc_markup(obj.body, obj)
        else:
            txt = obj.body
    return HttpResponse(txt)

虽然实现非常简单，但这个功能非常实用。

总之，在 LifeFlow Editor 的代码中可能还有其他一些值得一看的有趣片段，但目前大部分代码仍在开发中，此时看还有点不够专业。

如果大家对实现风格或细节有任何意见，欢迎告诉我。某些设计选择是基于这是一个后端工具，不需要做到极其安全（当然不能暴露给危险用户）。但它还有很长的路要走。
