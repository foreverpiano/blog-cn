使用 GraphQL 与 Python 的快速教程

2018-11-18 · 阅读原文

今年早些时候，我花了一些时间试验用 gRPC 来定义和集成服务端/客户端，今年周末我想花点时间用 GraphQL 做一次类似的试验。

我没找到特别完整的 Python GraphQL 教程，因此写了这篇笔记，希望对想在 Python 中尝试 GraphQL 的人有所帮助。

完整的教程代码在 Github 上。

目标

在 Digg，我们有一个简单的服务，它会爬取给定的 URL 并返回其标题、摘要以及值得关注的图片。早期的 Digg 严重依赖不可靠的爬取启发式方法来提取这些特征，但如今大多数网站都提供了足够的社交媒体元数据，大大简化了这个过程。

我们要构建的项目就是重现那个爬取服务，并使用我几年前编写的 extraction 库（最近我把它更新为支持 Python 3，因此又想起它）。

完成后，我们会提交类似以下的客户端请求：

{
  website(url: "https://lethain.com/migrations") {
      title
      image
  }
}

服务器的响应将是：

{
  "data": {
    "website": {
      "title": "Migrations: the sole scalable fix to tech debt.",
      "image": "https://lethain.com/static/blog/2018/migrations-hero.png",
    }
  }
}

每个网站还会包含一个 description 字段。

环境准备

假设你本地已安装 Python 3，我们先创建一个虚拟环境来管理依赖，然后安装所需包：

mkdir tutorial
cd tutorial
python3 -m venv env
. ./env/bin/activate
pip install extraction graphene flask-graphql requests

如果你想使用本教程中完全一致的版本，可以在 Github 的 requirements.txt 文件中找到。

爬取与提取

在进入 GraphQL 之前，我们先快速编写爬取网站并提取数据的代码，这部分相对独立。

使用 extraction 和 requests 库，代码如下：


import graphene
import extraction
import requests

def extract(url):
    html = requests.get(url).text
    extracted = extraction.Extractor().extract(html, source_url=url)
    return extracted

使用方式如下：

>>> extract('https://lethain.com/migrations')
<Extracted:
  (title: 'Migrations: the sole scalable fix to tech debt.', 4 more),
  (url: 'https://lethain.com/migrations/', 1 more),
  (image: 'https://lethain.com/static/blog/2018/migrations-he', 1 more),
  (description: 'Migrations are both essential and frustratingly', 5 more),
  (feed: 'https://lethain.com/feeds/')>

每个 Extracted 对象会提供五项数据：title、url、image、description 和 feed。

完整代码见 extraction_tutorial/schema.py

Schema 定义

每个 GraphQL API 的基础都是 GraphQL schema，它描述了对外暴露的 API 的对象、字段和类型。我们使用 Graphene 来把 schema 描述为 Python 对象。

编写一个描述已提取网站的 schema 相当简单，例如：

import graphene

class Website(graphene.ObjectType):
    url = graphene.String(required=True)
    title = graphene.String()
    description = graphene.String()
    image = graphene.String()

这里我们只使用了 graphene.String 来描述字段类型，但每个字段都可以是我们定义的其他对象，也可以是枚举、标量、列表等其他类型。

稍显意外的是，我们还需要编写一个 schema 来描述获取这些对象的查询：

import graphene

class Query(graphene.ObjectType):
    website = graphene.Field(Website, url=graphene.String())

    def resolve_website(self, info, url):
        extracted = extract(url)
        return Website(url=url,
                       title=extracted.title,
                       description=extracted.description,
                       image=extracted.image)

在这个例子中，website 是我们支持查询的对象类型，url 是会传递给解析函数的参数，而 resolve_website 会在每次请求 website 对象时被调用。

注意这里有很多“魔法”，名称必须完全匹配才能正常工作。我在写这段代码时遇到的大多数问题都是字段名打错，导致无法正确匹配。另外要注意 extract 是我们在前一节编写的函数。

最后一步是创建一个 graphene.Schema 实例，你会把它传给服务器来描述你创建的新 API：

schema = graphene.Schema(query=Query)

至此，你已经创建了

完整代码见 extraction_tutorial/schema.py

服务端

现在我们已经写好了 schema，可以使用 flask 和 flask-graphql 通过 HTTP 来提供服务：


from flask import Flask
from flask_graphql import GraphQLView
from extraction_tutorial.schema import schema

app = Flask(__name__)
app.add_url_rule(
  '/',
  view_func=GraphQLView.as_view('graphql', schema=schema, graphiql=True)
)
app.run()

注意，除非你下载了示例代码，否则你的 schema 的导入路径会不同。如果你不想折腾导入路径，把 schema 和服务器代码放在同一个文件中也是完全可以的。

现在可以通过以下命令启动服务器：

python server.py

启动后它会在 localhost:5000 提供服务。

完整代码见 extraction_tutorial/server.py

客户端

虽然存在专门的 GraphQL 客户端，但你并不需要使用它们来请求新 API，用你熟悉的 HTTP 客户端即可，本例中我们依然使用 requests。

import requests

q = """
{
  website(url: "https://lethain.com/migrations") {
    title
    image
    description
  }
}
"""

resp = requests.post("http://localhost:5000/", params={'query': q})
print(resp.text)

运行该脚本，输出结果为：

{
  "data": {
    "website": {
      "title": "Migrations: the sole scalable fix to tech debt.",
      "image":"https://lethain.com/static/blog/2018/migrations-hero.png",
      "description":"Migrations are both essential and frustratingly..."
    }
  }
}

你可以自定义 q 的内容来获取不同的字段，甚至可以使用别名（aliases）一次性获取多个对象。

完整代码见 extraction_tutorial/http_client.py

扩展对象

GraphQL 最有趣和令人兴奋的地方之一，就是可以非常容易地扩展对象，而不会给客户端带来兼容性问题。例如，假设我们想通过新增一个 feed 字段来返回页面的 RSS 源。

我们可以把它添加到 Website，并更新 resolve_website 方法来返回 feed 字段，如下所示：

import graphene

class Website(graphene.ObjectType):
    url = graphene.String(required=True)
    title = graphene.String()
    description = graphene.String()
    image = graphene.String()
    feed = graphene.String()    

class Query(graphene.ObjectType):
    website = graphene.Field(Website, url=graphene.String())

    def resolve_website(self, info, url):
        extracted = extract(url)
        return Website(url=url,
                       title=extracted.title,
                       description=extracted.description,
                       image=extracted.image,
                       feed=extracted.feed)

如果你想获取这个新字段，只需更新查询，增加对它的请求即可，与你已经在获取的 title、image 等字段一起返回。

自省（Introspection）

GraphQL 最强大的特性之一是它的服务器支持自省（introspection），这使得人类和自动化工具都能了解可用的对象和操作。

最直观的例子是：如果你运行我们构建的示例，可以访问 localhost:5000，使用 GraphiQL 直接测试你的新 API。

这些能力并不局限于 GraphiQL，你也可以使用与查询新 API 相同的查询接口来与之集成。一个简单的例子是我们可以查询示例服务暴露了哪些查询：

{
  __type(name: "Query") {
    fields {
      name
      args {
        name
      }
    }
  }
}

服务器会返回：

{
  "data": {
    "__type": {
      "fields": [
        {
          "name": "website",
          "args": [{ "name": "url" }]
        }
      ]
    }
  }
}

还有很多其他自省查询可用，虽然写起来有点繁琐，但为工具开发者提供了巨大的能力。非常值得尝试！

总结思考

总体而言，我对 GraphQL 的易用性印象深刻，更让我惊讶的是集成起来也非常简单。这种描述对象的方式比 gRPC 更直观，后者仍然更像是编写协议而不是描述对象。

在这个阶段，如果我要写一个产品 API，GraphQL 会是我第一个选择的工具；而如果我要写基础设施，我仍然更倾向于 gRPC，特别是它的认证机制和对 HTTP/2 的深度集成（例如双向流）。

这里还有很多问题值得后续深入研究：

它们在数据压缩方面的表现如何？如果服务器已经在压缩结果，压缩是否真的重要？GraphQL 的协议压缩是否较差，但因为客户端必须显式请求所需字段，从而在字段层面获得了更好的压缩效果？它们的字段废弃（deprecation）机制在实践中效果如何？两者都有相应的废弃方案，但都不算完美，GraphQL 的废弃警告似乎略胜一筹，因为你可以让客户端库把 API 返回的所有废弃警告以日志形式输出。

我相信还有很多其他问题值得探索！
