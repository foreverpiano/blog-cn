使用 Python 进行 GraphQL 的快速教程

2018-11-18 · 阅读原文

今年早些时候，我花了一些时间试验使用 gRPC 来定义和集成服务端/客户端。今年周末，我想花点时间用 GraphQL 做一次类似的实验。

我没有找到特别完整的 Python 教程，因此我写了这篇笔记，希望能为想在 Python 中尝试 GraphQL 的人提供一些有用的参考。

完整的教程代码已放在 Github 上。

目标

在 Digg，我们有一个简单的服务，它会爬取给定的 URL 并返回其标题、摘要以及任何值得关注的图片。早期的 Digg 严重依赖不可靠的抓取启发式算法来提取这些信息，但如今大多数网站都提供了足够多的社交媒体元数据，这大大简化了整个过程。

我们要构建的项目就是重现那个爬取服务，我们将使用我几年前编写的 extraction 库（最近我把它更新为兼容 Python 3，所以它又浮现在我脑海中）。

完成后，我们会提交类似以下的客户端请求：

{
  website(url: "https://lethain.com/migrations") {
      title
      image
  }
}

服务器的响应将是：

{
  "data": {
    "website": {
      "title": "Migrations: the sole scalable fix to tech debt.",
      "image": "https://lethain.com/static/blog/2018/migrations-hero.png",
    }
  }
}

每个网站还会包含一个 description 字段。

环境准备

假设你本地已安装 Python 3，我们首先创建一个虚拟环境来存放依赖，然后安装它们：

mkdir tutorial
cd tutorial
python3 -m venv env
. ./env/bin/activate
pip install extraction graphene flask-graphql requests

如果你想使用本教程中完全一致的版本，可以在 Github 的 requirements.txt 文件中找到。

爬取与提取

在进入 GraphQL 之前，我们先快速写好爬取网站并提取数据的代码，这部分相对独立。

使用 extraction 和 requests 库，代码如下：


import graphene
import extraction
import requests

def extract(url):
    html = requests.get(url).text
    extracted = extraction.Extractor().extract(html, source_url=url)
    return extracted

使用方式如下：

>>> extract('https://lethain.com/migrations')
<Extracted:
  (title: 'Migrations: the sole scalable fix to tech debt.', 4 more),
  (url: 'https://lethain.com/migrations/', 1 more),
  (image: 'https://lethain.com/static/blog/2018/migrations-he', 1 more),
  (description: 'Migrations are both essential and frustratingly', 5 more),
  (feed: 'https://lethain.com/feeds/')>

每个 Extracted 对象提供了五项数据：title、url、image、description 和 feed。

完整代码位于 extraction_tutorial/schema.py

Schema

每个 GraphQL API 的基础都是一个 GraphQL schema，它描述了暴露的 API 中的对象、字段和类型。我们使用 Graphene 来将 schema 定义为 Python 对象。

编写一个描述已提取网站的 schema 相当简单，例如：

import graphene

class Website(graphene.ObjectType):
    url = graphene.String(required=True)
    title = graphene.String()
    description = graphene.String()
    image = graphene.String()

这里我们只使用了 graphene.String 来描述字段类型，但每个字段都可以是我们定义的其他对象，也可以是枚举、标量、列表等其他类型。

稍显意外的是，我们还需要编写一个 schema 来描述获取这些对象的查询：

import graphene

class Query(graphene.ObjectType):
    website = graphene.Field(Website, url=graphene.String())

    def resolve_website(self, info, url):
        extracted = extract(url)
        return Website(url=url,
                       title=extracted.title,
                       description=extracted.description,
                       image=extracted.image)

在这个例子中，website 是一个我们可以查询的对象类型，url 是传递给解析函数的参数，而 resolve_website 会在每次请求 website 对象时被调用。

注意这里有相当多的“魔法”，名称必须完全匹配才能正常工作。我在编写这段代码时遇到的大多数问题都是字段名称打错导致无法匹配。另外要注意，extract 是我们在上一节中编写的函数。

最后一步是创建一个 graphene.Schema 实例，你需要把它传给服务器来描述你创建的新 API：

schema = graphene.Schema(query=Query)

完成后，你就已经创建了

完整代码位于 extraction_tutorial/schema.py

服务端

现在我们已经写好了 schema，可以使用 Flask 和 flask-graphql 通过 HTTP 提供服务了：


from flask import Flask
from flask_graphql import GraphQLView
from extraction_tutorial.schema import schema

app = Flask(__name__)
app.add_url_rule(
  '/',
  view_func=GraphQLView.as_view('graphql', schema=schema, graphiql=True)
)
app.run()

注意，除非你下载了示例代码，否则你的 schema 导入路径会不同。如果你不想纠结导入路径，也可以把 schema 和服务器代码放在同一个文件中。

现在你可以通过以下命令运行服务器：

python server.py

之后它就会启动，可通过 localhost:5000 访问。

完整代码位于 extraction_tutorial/server.py

客户端

虽然存在专用的 GraphQL 客户端，但你并不需要它来请求新 API。你可以继续使用熟悉的 HTTP 客户端，本例中我们使用 requests。

import requests

q = """
{
  website(url: "https://lethain.com/migrations") {
    title
    image
    description
  }
}
"""

resp = requests.post("http://localhost:5000/", params={'query': q})
print(resp.text)

运行该脚本，输出结果将是：

{
  "data": {
    "website": {
      "title": "Migrations: the sole scalable fix to tech debt.",
      "image":"https://lethain.com/static/blog/2018/migrations-hero.png",
      "description":"Migrations are both essential and frustratingly..."
    }
  }
}

你可以自定义 q 的内容来获取不同的字段，甚至可以使用别名（aliases）一次性获取多个对象。

完整代码位于 extraction_tutorial/http_client.py

扩展对象

GraphQL 最有趣和令人兴奋的部分，或许就是可以轻松扩展对象，而不会给客户端造成兼容性问题。例如，假设我们想新增一个 feed 字段来返回页面的 RSS feed。

我们可以把它添加到 Website，并更新 resolve_website 方法来返回 feed 字段，代码如下：

import graphene

class Website(graphene.ObjectType):
    url = graphene.String(required=True)
    title = graphene.String()
    description = graphene.String()
    image = graphene.String()
    feed = graphene.String()    

class Query(graphene.ObjectType):
    website = graphene.Field(Website, url=graphene.String())

    def resolve_website(self, info, url):
        extracted = extract(url)
        return Website(url=url,
                       title=extracted.title,
                       description=extracted.description,
                       image=extracted.image,
                       feed=extracted.feed)

如果你想获取这个新字段，只需更新查询，在原来请求的 title、image 等字段之外，再加上 feed 即可。

自省（Introspection）

GraphQL 最强大的特性之一，是它的服务器支持自省（introspection），这使得人类和自动化工具都能了解可用的对象和操作。

最直观的例子是，如果你运行我们构建的示例，可以访问 localhost:5000，然后使用 GraphiQL 直接测试你的新 API。

这些能力并不局限于 GraphiQL，你也可以使用查询新 API 的相同接口来与之集成。一个简单的例子是我们可以查询示例服务暴露了哪些查询：

{
  __type(name: "Query") {
    fields {
      name
      args {
        name
      }
    }
  }
}

服务器会返回：

{
  "data": {
    "__type": {
      "fields": [
        {
          "name": "website",
          "args": [{ "name": "url" }]
        }
      ]
    }
  }
}

还有很多其他自省查询，虽然写起来有点繁琐，但为工具开发者提供了巨大的能力，非常值得尝试！

结束语

总的来说，我对 GraphQL 的易用性印象深刻，更惊讶于集成它的便捷性。这种描述对象的方式比 gRPC 更直观，后者仍然更像是在写协议，而不是描述对象。

目前，如果我要编写产品 API，GraphQL 将是我首先选择的工具；而如果我要构建基础设施，我还是会更倾向于 gRPC，特别是因为它在认证和 HTTP/2 深度集成（例如双向流）方面的优势。

这里还有很多问题值得后续深入研究：

它们在数据压缩方面表现如何？如果服务器已经对结果进行了压缩，压缩是否真的重要？GraphQL 是否协议压缩较差，但字段压缩更优，因为用户必须明确请求他们需要的内容？它们的字段废弃（field deprecation）机制在实践中效果如何？两者都有一定的废弃处理方案，但都不够理想。GraphQL 的废弃警告似乎略胜一筹，因为你可以让客户端库把 API 返回的所有废弃警告记录到日志中。

我相信还有很多其他值得探索的问题！
