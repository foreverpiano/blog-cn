开发者生产力调查。

2020-10-18 · 阅读原文

在撰写管理代码库中的技术质量这篇文章时，我想找一份关于如何开展开发者生产力调查的优质参考资料，但最终只找到一篇相关文章：《如何就工具问题调研你的软件开发者》。那篇文章本身还不错，但它的建议更多侧重于如何在公司内部开展一般性调查，而不是针对开发者生产力调查。因此我决定自己写下一些心得。

什么是开发者生产力调查？

这是你发给公司内从事软件开发以及相关角色人员的一份问卷。你会询问哪些工具满足了他们的需求，哪些没有。

应该如何开展这项调查？

从简单入手。用 Google Form、SurveyMonkey 或者类似的工具即可。不要过早优化。

公司什么时候适合做开发者生产力调查？

我发现这类调查在大规模招聘之后最有价值，因为新员工对公司的工作流和工具问题最敏感。而反复向同一批人问同样的问题则帮助不大。

此外，你需要有人真正愿意把调查结果用起来。

最好的结果是什么？

你选对了项目来改善在公司当开发者的体验。团队因此变得更快，能完成更重要的工作。你获得晋升，并且真的喜欢那个层级的工作——大概是这样？

最坏的结果是什么？

人们无视调查，不愿意填写。大家觉得你在浪费他们的时间。你发现了真实的问题却置之不理，从而失去组织对你的信任。

应该多久做一次？

只要你还没能对之前提出的问题做出显著改进，就不应该再次发送调查。一般来说，每季度最多做一次，但这很大程度上取决于公司规模。有些公司规模足够大，可以每周对一小部分员工进行调查，而不是每季度覆盖整个组织。这是一种获取每周数据的巧妙方式，但你需要有数千名员工才能让它有效运转。

有哪些好的问题？

这主要取决于你想了解什么，以下是一些想法：

  • How would you rate our X process from 1 to 10? Where X is every common workflow at the company: test, code review, build, deploy, release, feature flagging, running experiments, reverting, incident management, on-call, debugging, and so on.
  • What tools that you’ve previously used do you find yourself missing?
  • Where do you feel like you lose time every week?
  • Are there tools or areas of our code that you avoid when possible?
  • Are these tasks or activities they feel unreasonably hard to accomplish?
  • What feels hard that you know would be easy if you were doing it yourself as a hobby project?
  • If you could wave a wand and fix anything about developing software at our company, what would you change?
  • Is there anything you’d like to say that didn’t fit elsewhere?

要找到合适的问题，先明确你想了解什么，然后反向推导。

你有模板可以给我们用吗？

没有。

关于挑选问题还有什么建议？

先找几个你希望参与调查的人，把问题测跑一遍。你会发现很多本该问却没问到的问题，也会发现有些问题其实没你想象中那么有意义。

另外，尽量多用定性问题，少用定量问题。

我们应该为调查结果设定一个目标吗？

人们很容易迷上调查的量化部分，但总体来说，我发现这些分数并没有特别大的用处。内部调查通常参与人数很少，导致变化在统计上并不显著。人们会逐渐厌倦填写调查，因此数字反映的可能是谁更愿意参与，而不是整体真实感受。随着时间推移，人们会逐渐适应现有流程，不再感知到其中实际存在的摩擦。

基于以上原因，我建议不要直接给调查结果设定目标。我们在 Stripe 曾经尝试过设定一个目标：让某项抱怨在“前三抱怨”中停留的时间不超过多久（理论上，从“前三”变成“非前三”与质量改进相关），但这个指标过于复杂，难以解释清楚，导致效果不佳。

这些结果更适合当作地图，而不是直尺。

我可以停止发送这些调查吗？

当然可以。在特定变更之后，针对特定问题使用按需调查，往往比通用的定期调查更有帮助。如果调查没有带来实际价值，就不要觉得每三个月必须发一次。内部调查在细节上几乎总是无效且不准确的，所以别陷入追求伪科学的误区。

这件事值得做吗？

我认为是值得的。我在每家公司做过一两次这样的调查，从未后悔过。不过我认为频繁开展这类调查容易让人陷入麻烦，尤其是在邮件已经很多的公司。如果你不确定是否值得，不妨试一次。
