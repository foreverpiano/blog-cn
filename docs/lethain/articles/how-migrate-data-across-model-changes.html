如何在模型变更时迁移数据

2007-07-01 · 阅读原文

当你创建一个 Django 应用时，会使用模型来表示你的内容、数据以及网页的生命力。不幸的是，你最初创建的那批模型是错的。第二批也是。现在正在使用的这些模型同样如此。当然，到现在为止它们已经相当不错，但依然可以变得更好。那么……为什么不改进呢？

我对这个问题的回答通常是“因为我死也不会去迁移我的数据。”早期我曾手动往数据库里加了一列，并给它设置一个合理的默认值，以免数据库吐出意外的 NULL 值。然后我又写了一些代码，每次保存模型时自动计算该列的正确值。

请不要这么做。永远别这么做。这不是什么明智的做法。

你听说过 fixture 吧？Django 文档里零零散散地提到过它们，轻松地假设你完全知道它们是什么以及如何使用，因为它们实在太容易用了，何必费心写文档呢？好吧，这是个 beta 项目，我知道，我知道，而且它们确实非常容易使用。你只需要有人在正确的方向上推你一把，而这篇文章就是我在为我们所有人做这件事。

假设你有一个包含一些数据的数据库。我们先把这些数据导出到磁盘：

python manage.py dumpdata myapp --format=xml > myappdata.xml

默认情况下，数据会以 JSON 格式导出。这还可以，但 JSON 把我的日文编码数据弄坏了，所以我决定使用 XML 来保存未来的数据转储。如果你只使用简单的 ASCII 数据，那么 JSON 可能就够了。不过，XML 用 BeautifulSoup 解析起来要容易得多，在进行复杂模型变更时有时是必需的。所以……我们还是用 XML 吧。

现在数据已经保存好了。进入数据库，对你的模型做一些修改，比如你可能删掉整个模型，或者只是在现有模型上加一个 CharField 或 BooleanField，什么改动都行。

然后重置你的数据库。

python manage.py reset myapp

现在只需要把之前保存的数据加载进来即可。

python manage.py loaddata myappdata.xml

就是这样，你的数据已经在新表中重建了。随着变更复杂度的增加，这种技术会变得越来越困难，你最终可能会需要编写脚本把旧的 XML 转换成新的格式。我唯一的鼓励是：把那些脚本写出来，不要手动操作。一开始手动操作似乎更容易，但很快你就会犯人为错误，从而在数据文件中埋下定时炸弹。

免责声明：在将此技术用于任何重要数据之前，请先进行一次演练。

祝你好运，如果你正在尝试对数据库进行更复杂的修改，随时向我提问。
