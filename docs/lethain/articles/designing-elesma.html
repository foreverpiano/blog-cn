设计 Elesma

2008-04-13 · 阅读原文

过去一周，我一直在开发一款新应用，暂定名为 Elesma。Elesma 的最初概念是一个个人助理：一个能够帮助完成日常琐事、让你得以专注于当前项目的程序。

我不会讲太久，但我想展示一下目前正在原型设计的用户界面，其中包含了一些有趣的想法。

智能建议

文本输入框最有用的功能之一，就是根据你已经输入的内容提供建议补全。当你要输入的内容需要遵循特定语法时，这一点就变得更加重要。Cocoa 对此有一定的内置支持，但经过一番尝试后，我发现还是需要自己实现一套方案。

这是我目前手写的建议补全方案的最新版本。我想哪怕只看一眼，你就会发现如果稍微做成半透明效果会好很多，这一点在后续完善中肯定会实现。另外，底部的示例和描述区域看起来有些俗气，但对于教用户如何使用还是相当有帮助的。它肯定会被重新设计得更美观（也更有用），但我认为如果实现得当，它会非常实用。

看着这些建议，你会注意到它们都带有颜色，我们来聊聊这一点。

语法与色彩

我认为颜色作为一种清晰传达大量信息的方式目前被严重低估了。在这里，蓝色表示你正在发出的命令，橙色代表参数，深灰色则代表多参数的上下文关键词。

然而，如果每次输入“at”、“in”或“for”都被认为是上下文关键词，那就太痛苦了。实际上，你希望每个命令都能自行决定自己的关键词，而这正是这里正在发生的事情。建议框里的建议并不是手工着色的例子，而是由语法系统自己进行着色的。

比如闹钟语法：一个以“alarm”开头，中间用“at”分隔两个参数的查询。基于这个知识，语法系统就能对自己存储的纯文本示例字符串进行着色（它同时还存储了当前显示在示例下方的描述文本，以及其他一些信息）。

所以，我觉得让每个命令自行决定自己的语法非常巧妙，这也是朝着构建更接近人类自然语言的命令系统迈出的不错的一步。还有一个有趣的地方……

（哎呀，建议栏的尺寸永远不应该超过建议的数量，这也是需要清理的另一处。）

总之，当你在文本框中输入时，它会立即对你正在输入的文字进行着色，就像代码编辑器一样，包括正确地为语法自行声明的任意关键词上色。我发现这种视觉反馈非常让人安心。你知道自己是否正确输入了一个命令短语，因为文字会从蓝色变成橙色。你也知道自己是否使用了正确的上下文关键词，因为它会在你输入时变成灰色。很不错。

整体外观

现在来谈谈这个应用整体的外观设计。

首先要声明，目前的按钮只是我从之前项目里拿来暂用的，之后会换成更直观的图标。或者它们也可能被完全抛弃，它们的命运还悬而未决。

其次，它确实很蓝。到处都是蓝色渐变。按钮上的蓝色渐变，背景也是蓝色渐变。我曾经愚蠢地尝试在自己做的东西里使用金属拉丝效果，结果立刻遭到了强烈反对。尽管如此，我还是觉得默认 UI 组件那种平淡无奇的灰色“现在很潮”的风格有点乏味，所以我想让它在视觉上更有趣一些，但又不会过头。我不知道整体视觉设计最终会走向何方，但我既不想让它和标准的 Apple 风格完全融合，也不想让它过于突出。诚然，这是一条很窄的界线，主要需要在细节上慢慢打磨，而不是大刀阔斧……不过我认为用相对柔和颜色的渐变背景，符合这种设计理念。

状态图标（表格中的第一列）非常简单，如果我说我花了超过十五分钟来制作这一批图标，那我就是在撒谎（“等待”状态的图标没有显示）。

任务 AKA 执行操作

从编程角度来看，Elesma 主要有三个非平凡的部分：语法、任务和结果。我已经稍微谈过语法了，对于结果的处理还没有想太多，但我已经搭建了任务的大致框架。

用非常宽泛的话来说，任务就是 Elesma 在做某件事。有一个抽象的 Task 类，它被子类化成各种不同类型的任务。我们来想想一个“互联网任务”可能会包含什么。

首先，对 Elesma 来说最重要的考虑之一是，我希望它（她？）对那些（像我一样）经常不联网的人也极其有用。因此，互联网任务必须（而且已经做到了，尽管 SystemConfiguration 框架和它的位掩码永远不会是我的朋友）足够智能，能够等到有互联网连接时再执行。最简单的例子是“Fetch”任务，它只是想把一个 URL 的内容下载到本地磁盘。更高级的想法可能是搜索 Google 并获取前十个结果，或者抓取一个维基百科条目供后续离线阅读。

这样看来，你可以把 Elesma 想象成一个非常贴心的待办事项清单，它会尽其所能地自动勾掉已完成的任务，并告诉你还有什么需要去做。
