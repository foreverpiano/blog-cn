介绍 LifeFlow Editor

2008-02-03 · 阅读原文

好了，我刚刚完成了新版 LifeFlow Editor 大约 80% 的功能，简直兴奋得不行。事实上，我现在就是在用它来写这篇文章。

什么是 LifeFlow Editor？

LFE 将逐步发展成为专为 LifeFlow 打造的 Django Admin 替代品。其近期目标是取代所有常见的博客写作任务，并支持博客特有的工作流程。其中一个重要环节就是对未发布草稿的完整支持。

接下来，我们一起来逛逛 LFE，然后看看它在不久的将来还计划加入哪些功能。

一桶又一桶的写作

上面就是 LFE 的概览页面。它实现了我在写博客文章时常用的一种简单工作流程。你先点击“新建”按钮，然后编辑文章、填写标题等。过一段时间后，你会不断修改这篇文章，直到自己觉得比较满意。这时你可以在“Rough”桶里选中它，点击“>>”按钮，将其推进到“Edited”桶。

它会安安稳稳地待在那里，直到你再次推进到“Published”桶。一旦进入“Published”桶，它就会立即在博客上正式发布。如果操作失误，你随时可以用“<<”按钮把它从“Published”桶撤回到“Edited”或“Rough”桶。

这里的奥秘在于同时使用了两个模型。一个是 Draft 模型，它没有任何必填字段，你可以按照自己的节奏拼凑草稿，想填哪部分就填哪部分。但当你试图把草稿从 Edited 桶推进到 Published 桶时，LifeFlow 会尝试将其转换为 Entry 模型的实例。由于 Entry 模型有一些必填字段，LF Editor 会通过 Ajax 弹出错误提示，告诉你这个草稿尚未满足成为 Entry 的所有要求（目前错误信息还比较模糊，但改进成提供有价值的反馈并不难，这也是高优先级任务）。

你可能会问，如果从 Published 桶撤回呢？很简单，系统会销毁 Entry 模型的实例，并将其转换回 Draft 模型的实例。因此 Entry 和 Draft 模型之间存在一个无缝的双向通道。

（虽然尚未实现，但不同桶的设计初衷之一是支持多级用户权限，例如作者、编辑和网站管理员。作者可以创建和编辑草稿，编辑可以把草稿推进到 Edited 桶并继续修改，而网站管理员则负责推进到 Published 桶。我设想中的团队博客就可以这样运作。）

撰写摘要

这是 LFE 文章编辑部分的第一个页面。在这里输入标题和文章摘要。你可能会注意到没有“保存”按钮。啊！要慌了吗！

其实完全不用慌。LFE 在保存和更新数据方面比 Django Admin 更智能，你不需要手动告诉它保存。比如，当你离开撰写摘要的文本框时，它就会自动保存。离开标题输入框时，也会自动保存。

在其他编辑区域，LFE 也采用同样的方式。例如选择完标签后，只要鼠标离开包含所有标签的区域，它就会保存。离开撰写正文的文本框后，也会自动保存。

目前如果你做出一些奇怪的操作（比如点进文本框、把鼠标移开然后开始打字），保存的可靠性可能还有点问题。但只要你把鼠标留在当前编辑区域内，它就始终能正常工作。实际使用中你可能根本不用考虑这个，但我以后会让它变得更稳定。

为文章选择标签

这张截图展示了在 LFE 中如何选择标签。你只需点击想要的标签，它们就会变成橙色。然后把鼠标移出区域即可保存。非常简单。

真正的写作环节

写一篇博客文章最主要的部分……当然是写文章本身，所以我希望让这个过程尽可能舒适愉快。

写作时你可以随时渲染预览（它会智能读取模型中 use_markdown 字段的值，你可以通过页面顶部的下拉菜单修改）。渲染结果会显示在写作文本框下方，你也可以点击“Hide Rendering”按钮将其隐藏。

写博客的另一个重要部分是将文件嵌入文章。LFE 通过这个精巧的文件展示组件来辅助完成（也算是彻底终结了“widget”这个词的意义）。它会显示每个资源的 markdown_id（配合 Dynamic Blog Context 用于将文件插入文章），如果文件是图片（根据扩展名判断），还会显示缩略图，帮助你确认使用正确的图片。

虽然还没实现，但我计划让它也能智能地辅助其他文件类型。比如高亮显示代码文件，或者列出 zip 文件内包含的所有文件。

![在 LFE 中上传文件的截图][f lfe_uploading_for_real]

在 LFE 中上传文件也非常简单。遗憾的是目前还不能通过 Ajax 上传，所以必须刷新页面，但实际体验并不差，尤其是图片通常都是批量上传的（这也是我后续想更好支持的功能）。

即将实现的功能

  1. Ability to create tags, flows, and series within the LFE. Implemented.
  2. Ability to delete rough drafts (so you'd have to demote things to a rough draft before deleting them, seems reasonable precaution). Implemented.
  3. More informative error messages. Implemented.
  4. Support for selecting authors (will be easy to implement, just forgot to do it...).
  5. Managing associated comments.
  6. Setting the datetime for the entry's time to publish (not that hard, I just didn't get it done quite yet).
  7. Putting the rendered text into an iframe with the CSS from the actual blog included in it.
  8. Extra support for uploaded files that are code/zip files.
  9. Oh, yeah, you can't actually login using the LFE yet, or logout, I just use the Django admin to login and them hop over to it at the moment. The logout button is just a span... yeah. This will come sooner than later.

还有其他吗？

总结

总之，就像我之前提到的，这篇文章就是我用 LFE 写的（虽然最后还是偷偷跑去 Django Admin 把自己加为作者，因为我忘了实现那个功能），所以它已经可以正常使用了。显然目前还缺少一些重要功能，但作为一个工具其实已经相当不错，尤其是在渲染和文件管理方面。不过请注意，它仍然处于积极开发中，由于使用时间还不长，可能存在一些 bug。特别是 Draft 和 Entry 模型相互转换的部分，我明天会好好看一看。

敬请期待近期的大量改进！另外，也欢迎告诉我你对它的看法，以及你认为它还需要什么功能才能成为真正有价值的工具。
