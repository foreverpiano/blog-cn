LifeFlow 条目中引入资源的新方式

2008-01-15 · 阅读原文

简单提醒一下，LifeFlow 的 SVN 中进行了一次不兼容的改动。

在此之前，要访问 Resource 文件中存储的文件，需要完成两个步骤：

在管理后台将 Resource 与 Entry 关联，然后写一个类似 [myresource][name_you_gave_it] 的链接。

现在，你只需直接写：

[name of your resource][f name_you_gave_it]

请注意，对于之前使用旧方式编写的条目，除非你再次保存它们，否则不需要做任何修改。如果保持原样，它们不会重新渲染，直到你手动保存后触发重新渲染。因此，尽可能只用新方式撰写新条目，旧条目则保持不动。

为什么要进行这次改动？

早期我曾考虑动态地将资源与博客条目关联，并动态生成这些关联资源的 Markdown 引用。这正是 Dynamic Blog Context 诞生的基础。

不幸的是，这个方案要求 Entry 对与其关联的 Resource 实例有深入的了解。这比看起来要复杂得多，因为 ManyToMany 关系要在对象完成数据库保存后才会建立。这意味着 Entry 需要先保存，才能正确渲染自己，而渲染又是保存过程的一部分。可以说是形成了一个循环。

因此，解决这个尴尬循环的办法是：先保存一次以建立 ManyToMany 关系，过几秒后再保存一次来完成最终渲染（期间加入了一些逻辑以防止出现无限保存循环）。

转向基于新的 Dynamic Blog Context 的方案后，就不再需要这种尴尬且丑陋的双重保存了。目前双重保存仍然存在，因为 DBC 的部分功能仍需要 Entry 对其所在的 ManyToMany 关系有最新的了解（例如，要生成所属系列中第一篇文章的链接，就需要知道它属于哪个系列）。

不过，双重保存正在逐步被淘汰，一旦在不损失功能的前提下可行，它将被彻底移除。
