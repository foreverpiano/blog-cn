LifeFlow 条目中引用资源的新方式

2008-01-15 · 阅读原文

简单提醒一下，LifeFlow 的 SVN 中进行了一项不兼容旧版本的改动。

在此之前，若要访问 Resource 文件中存储的文件，需要完成两个步骤：

在管理后台将 Resource 与 Entry 关联，然后编写类似 [myresource][你给它的名称] 的链接。

现在，你只需要直接写：

[name of your resource][f name_you_gave_it]

请注意，对于之前用旧方式编写的条目，你无需主动修改它们，除非再次保存。如果保持原样，它们不会自动重新渲染，直到你手动保存后才会重新渲染。因此，尽可能只用新方式撰写新条目，而不要改动旧条目。

为什么要做这个改动？

早期我曾设想动态地将资源与博客条目关联，并动态生成这些关联资源的 Markdown 引用。这正是 Dynamic Blog Context 诞生的基础。

不幸的是，这个方案要求 Entry 对与之关联的 Resource 实例有非常深入的了解。这比看起来要复杂得多，因为 ManyToMany 关系要等到对象保存到数据库之后才会建立。这意味着 Entry 需要先保存，才能正确渲染自己，而渲染又是保存过程的一部分。可以说，这形成了一个循环。

因此，解决这个尴尬循环的办法是：先保存一次以建立 ManyToMany 关系，几秒钟后再保存一次来完成最终渲染（期间会加入一些逻辑以防止出现无限保存循环）。

转向新的基于 Dynamic Blog Context 的方案后，就不再需要这种笨拙且丑陋的双重保存了。目前双重保存仍然存在，因为 DBC 的某些功能仍需要获取 Entry 所关联的 ManyToMany 关系的最新信息（例如，要生成指向某个系列中第一篇文章的链接，就需要知道该 Entry 属于哪个系列）。

不过，双重保存机制正在逐步被淘汰，一旦可以在不损失功能的前提下实现，它将被彻底移除。
