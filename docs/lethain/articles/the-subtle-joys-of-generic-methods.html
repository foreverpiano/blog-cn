泛型方法的低调乐趣

2008-12-11 · 阅读原文

一提到 Ruby，你第一个想到的是什么？哦，是 Rails？嗯……那你觉得 Ruby 最突出的特性是什么？Monkey patching？没错，我也是这么想的。程序员对 monkey patching 的看法远比青春期少女对闪粉的看法还要强烈且激烈。在运行时全局修改类的功能？嗯，这听起来的确很危险。

稍微发挥一点想象力，你就能脑补出一个末日场景：两个库为了把某段功能换成各自偏好的版本而持续相互角力，每次发布新版本时，库的维护者都要修改代码，让自己的库重新排到最前面。

然而，monkey patching 确实解决了一个重要问题：能够在运行时动态地为类增加功能。在 Python 这边，我们并没有一个特别好的解决方案，而且我们基本上已经接受了这个现状——宁可没有动物园，也不要让狮子偶尔逃出来咬小孩子。

不过，这个问题其实有一个很棒的解决方案。它既允许动态地为类——甚至是多个类——添加功能，同时又尊重命名空间，不会破坏别人代码中的合理假设（最重要的是“一个函数不会在毫无征兆的情况下突然改变行为”这一假设，这对于编写哪怕只是中等确定性的代码来说都至关重要）：
