《非理性繁荣》的第三次重生

2011-03-27 · 阅读原文

在讨论 Irrational Exuberance 的最新版本之前，请允许我先恳请大家提出任何建议！好了，言归正传。究竟发生了什么？我真的刚把自己的自定义博客实现换成了另一个自定义博客实现吗？

是的。而且我把它叫做 Sisyphus……原因不言自明。

为什么呢？

有两个原因：首先，我之前的博客在工程上已经变得极其臃肿和可怕，我实在无法忍受继续在上面叠加功能（它需要扩展来应对涌入的垃圾评论，情况严重到我最后只好直接关闭评论……而关闭评论这个操作我居然试了三次才成功）；其次，过去三年我在专业开发中积累了一些有趣的想法，想找一个试验场来实践它们。（并非所有想法都出现在 Irrational Exuberance 3.0 里，但已经实现了一部分。在投入了将近一周的业余时间后，我决定还是先把这个该死的东西上线，而不是在第一个版本就贪心过度。）

讨论 LifeFlow 那场灾难没什么意思（就像吐槽《The O.C.》第三季一样，槽点自己会冒出来），所以我改而聊聊我正在尝试实验、即将尝试实验的想法，以及为什么这个博客会以这样的方式做出改变。

那我们就直入主题吧。

Irrational Exuberance 的第一个版本是托管在共享主机上的 WordPress 博客。第二个版本是一个自定义的 Django 应用，它几乎集齐了“第二系统”应有的所有毛病。希望这个第三版能坚持得久一点（比如说，不像我上一次的自行车，只骑了六个月就被停车执法车压坏，顺带让我蒙受了巨大的羞耻）。

在思考新设计时，我主要受到了两个东西的影响：旧版本和我曾经工作过的 Digg。对于不在 Digg 工作的人来说，这种影响可能并不明显，但右侧边栏模块的处理方式，以及 Popular 内容这个概念（下面会详细讨论），完全是借鉴而来的。

文章

博客的核心永远应该是它的内容。这一点我认为 V2 做得非常好，部分得益于它采用的单栏设计，把整个页面几乎都留给了内容（除了那个确实有点肥大的头部和尾部，把文章夹在中间形成了一个颇为诡异的彩虹三明治）。

段落宽度被有意限制，以提升阅读舒适度（哇，居然……很难找到一个靠谱的研究来证明或解释为什么限制段落宽度能改善可读性。这真的是我能找到的最好证据吗？*不，不是的。感谢 @cduruk 指出了一项更具可信度的研究），图片增加了边框，垂直间距也进行了缩减。文章可用的宽度从 700px 缩小到了 550px。

总体来说，呈现方式上变化并不大。

头部

另一方面，头部则有了相当大的进化。V2 的头部有点高，但尽管如此，它在建立导航元素的视觉层级上做得相当不错。

我也会怀念它的独特性。我想应该没人会把 Irrational Exuberance 误认成别的博客。

新的头部则尽量做到紧凑，同时将部分导航职责交给右侧边栏模块，让读者能够立刻开始他们来这里真正想做的事：读这篇该死的文章。

搜索是一个重大的新增功能，我很想看看它是否会被实际使用。从理论上说，搜索是一个万能的导航元素，能弥补其他导航设计的任何缺陷，而且它还能扩展去解决用户独特的导航需求（我在哪篇文章里提到过 Asheville？关于 Twitter 的那篇又是哪一篇？）。

视觉独特性消失了，但新的头部更简洁，并且带来了搜索功能。这应该算是一次胜利。

页脚与模块

V2 的页脚试图塞进很多内容，而且文章标题通常都很长，这是一个相当尴尬的限制。（这个限制依然存在，但在右侧模块里视觉上处理得比全宽页脚要好一些。当然，我也可以把模块放进页脚——这是很常见的博客页脚做法——那样那个肥大的页脚读起来会更容易。）

V3 彻底去掉了厚重的页脚，把所有内容都移到了右侧边栏的模块中。这些模块扩展性很好，即使是最短的文章也能轻松容纳五个以上的模块。

我的希望是右侧边栏模块能让导航变得更轻松（读者一打开页面就能看到导航选项，而不用一直滚动到页面最底部才能发现内容），同时也为未来的实验提供一个平台。

之前的版本支持分享到各种新闻社区和社交网络，但采用的是纯文本链接：

新版本正在尝试使用 Digg、Twitter 和 Facebook 的分享按钮，并显示 Diggs、推文和分享的数量。

我很想看看这个做法的效果。从理论上说，在按钮上直接显示数字可能会阻碍第一次分享（人们通常更愿意和已经成功的东西产生关联），但对于教程这类技术内容来说，这可能不是什么大问题。要么这篇教程有用，要么没用；要么你的朋友感兴趣，要么不感兴趣。你是第一个分享还是最后一个，可能无关紧要。

好吧，数据会比我内心的独白更能说明问题。让我们拭目以待。

大多数模块都相当直白。“Recent”模块显示最新文章，“Previous”和“Next”模块分别显示前一篇和后一篇文章。“Tags”模块（目前仅在文章列表页可见）列出最常用的标签（我移除了顶层标签导航，因为看起来几乎没人真正使用标签，但我需要对 V2 的日志做一些分析，才能确定这个说法到底有多准确）。

“Popular”和“Similar”模块则稍显新颖，值得在下一篇文章中单独讨论，那篇文章将介绍 Sisyphus 的具体实现细节。

旧的文章 URL 结构除了 slug 之外，还包含了发布年、月、日。

/entry/2009/oct/11/money-or-meaning-spending-our-wealth-of-time/

如果你担心 slug 冲突，这么做多少是有道理的，但对一个人的博客来说，这几乎不可能发生，而且我讨厌它们变得如此机器友好而对人类极不友好。现在的 URL 简单多了：

/money-or-meaning-spending-our-wealth-of-time/

我对这些新链接满意多了。（我已经把所有旧 URL 都 302 重定向到了新地址，所以旧链接依然有效。这是一个非常简单的重写规则，只需去掉 slug 之外的所有部分。）

其他大多数 URL 结构都保持不变，任何有改动的也都已经在 Nginx 中设置了重写规则，以确保不会突然出现意外的 404。

再次强调，我非常希望听到任何关于改进这个最新版 Irrational Exuberance 的反馈、建议或吐槽。说完这些，我想我终于可以结束这段漫长的中断，回去写一些更有趣的东西了！
