《非理性繁荣》的第三次重生

2011-03-27 · 阅读原文

在讨论 Irrational Exuberance 的最新版本之前，请允许我先恳请大家提供任何建议！好了，言归正传。这里到底发生了什么？我真的刚刚用另一个自定义博客实现替换了之前的自定义博客实现吗？

是的。而我把它叫做 Sisyphus……原因不言自明。

为什么？

有两个原因：首先，我之前的博客在工程上已经变得极其臃肿和可怕，我实在无法忍受继续在它上面做任何扩展（它需要扩展来应对大量涌入的垃圾评论，这些评论严重到我最终只能彻底关闭评论功能……而这花了我三次尝试才成功）；其次，过去三年职场开发中我积累了一些有趣的想法，需要一个试验场来尝试它们。（并非所有想法都出现在 Irrational Exuberance 3.0 中，但有一些已经实现了。在投入了将近一周的业余时间后，我决定必须先把这个该死的东西上线，而不是在第一个版本就贪心过度。）

讨论 LifeFlow 那场灾难并不是特别有趣的事（就像吐槽《The O.C.》第三季一样，槽点自己就冒出来了），所以我还是来聊聊我正在尝试、将要尝试的一些想法，以及为什么这个博客会以这样的方式做出改变。

那我们就开始吧。

Irrational Exuberance 的第一个版本是托管在共享主机上的 WordPress 博客。第二个版本是一个自定义的 Django 应用，它几乎集齐了“第二系统”应有的所有毛病。希望这个第三版本能坚持得久一点（不像我上辆自行车，只骑了六个月就被停车收费员的车压坏，而我则被随之而来的羞耻感压垮）。

在思考新设计时，我主要受到两个影响：旧版本和 Digg。对于不在 Digg 工作的人来说，这种影响可能不明显，但右侧边栏模块的处理方式以及 Popular 内容的概念（下文会详细讨论），完全都是借鉴而来。

文章

博客的重点永远应该是它的内容。这一点我认为 V2 做得非常好，部分得益于它的单栏设计，把整个页面几乎都让给了内容（除了那个确实有点胖的页头和页脚，把文章夹成了一个相当诡异的彩虹三明治）。

段落宽度被有意限制，以提升阅读舒适度（奇怪的是，很难找到一个可靠的研究来源来说明为什么要限制段落宽度来改善可读性。这真的是我能找到的最好证据吗？*不，并不是。感谢 @cduruk 指出了一项更可信的研究），图片增加了边框，垂直间距也有所减少。文章可用的宽度从 700px 缩小到了 550px。

总的来说，呈现方式上变化并不算大。

页头

另一方面，页头有了相当大的演进。V2 的页头有点高，但尽管如此，它很好地建立了导航元素的视觉层级。

我也会怀念它的独特性。我不认为曾经有人把 Irrational Exuberance 误认成别的博客。

新的页头尽量做到紧凑，同时将部分导航职责交给右侧边栏模块，目的是让读者能立刻开始做他们来这里想做的事：好好读这篇该死的文章。

搜索是一个重要的新增功能，我很好奇它是否会被真正使用。从理论上讲，搜索是一个通用的导航元素，能够弥补其他任何导航设计的缺陷，而且它还能扩展解决用户独特的导航需求（我哪篇文章里提到过 Asheville？关于 Twitter 的那篇呢？）。

视觉独特性消失了，但新的页头更简洁，并且带来了搜索功能。这应该算是一个胜利。

页脚和模块

V2 的页脚试图承载很多内容，而且文章标题通常都很长，这是一个相当尴尬的限制。（这个限制依然存在，但在模块中比在全宽页脚里视觉上处理得更好一些。不过，我本来也可以把模块放到页脚里——这是很常见的博客页脚做法——那样就能让这个胖页脚在视觉上更容易被解析。）

V3 去掉了厚重的页脚，把所有内容都移到了右侧边栏的模块中。这些模块扩展性很好，即使是最短的文章也能在视觉上容纳五个以上的模块。

我的希望是右侧边栏模块能让导航变得更容易（读者一打开页面就能看到导航选项，而不需要滚动到页面最底部才能发现内容），同时也为未来的实验提供一个平台。

之前的版本支持分享到各种新闻社区和社交网络，但采用的是纯文本链接：

新版本正在尝试使用 Digg、Twitter 和 Facebook 的分享按钮，并显示 Diggs、推文和分享的数量。

我很好奇这个改动最终效果如何。从理论上说，在按钮上直接显示数字可能会阻碍最初的分享（人们通常更愿意和已经成功的东西联系在一起），但对于教程这类技术内容来说，这可能不是什么大问题。要么教程有用，要么没用；要么你的朋友感兴趣，要么不感兴趣。你是第一个分享还是最后一个，可能无关紧要。

嗯，数据会比我的内心独白更能说明问题。让我们拭目以待。

大多数模块都相当直白。“Recent” 模块显示最新文章，“Previous”和“Next”模块分别显示前一篇和后一篇文章。“Tags”模块（目前只在文章列表页显示）列出最热门的标签（我移除了顶层标签导航，因为看起来几乎没人真正使用标签，但我需要对 V2 的日志做一些分析，才能确认这句话到底有多准确）。

“Popular”和“Similar”模块则稍具新意，值得在下一篇文章中单独讨论，那篇文章将详细介绍 Sisyphus 的实现细节。

旧版文章的 URL 结构除了 slug 之外，还包含了发布年、月、日。

/entry/2009/oct/11/money-or-meaning-spending-our-wealth-of-time/

如果你担心 slug 冲突，这么做也算勉强合理，但对于一个人的博客来说，这几乎不可能发生，而且我讨厌它们变得那么机器友好而对人类极不友好。现在的新 URL 更简洁：

/money-or-meaning-spending-our-wealth-of-time/

我对这些新链接满意多了。（我已经把所有旧 URL 都 302 重定向到新地址，确保旧链接仍然有效。这是一个非常简单的重写规则，只需去掉 slug 之外的所有部分。）

其他大部分 URL 结构都保持不变，任何有改动的也都已经在 Nginx 中设置了重写规则，确保不会突然出现意外的 404。

再次强调，我非常希望听到任何关于改进这个最新版 Irrational Exuberance 的反馈、建议或吐槽。说完这些，我想我终于可以结束这么久的断更，回去写一些更有趣的东西了！
