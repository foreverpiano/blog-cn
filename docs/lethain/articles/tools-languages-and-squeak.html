工具、语言与 Squeak

2008-03-01 · 阅读原文

最近 Peter Burns 在 Twitter 上分享了一篇有趣的文章，作者是 Oliver Steele，标题为《The IDE Divide》。文章将开发者划分为两类：语言专家（Language Mavens）和工具专家（Tool Mavens）。

语言专家通常使用 Emacs 或 VI，他们专注于利用特定编程语言的特性来提升生产力。例如用 OCaml 编写编译器，用 Perl 或 Ruby 处理文本，用 Erlang 构建可靠系统。而工具专家则不那么依赖语言，他们更专注于掌握一套工具，这些工具通常被集成在 IDE 之中。

这篇文章最打动我的一点是，它提供了一套词汇，让我能够简洁地表达对 Squeak 的不满。Squeak 既是一个虚拟机，也是一种编程语言，这意味着新开发者必须同时放弃自己熟悉的语言和工具。

如果你是工具专家，你会感到沮丧，因为无法继续使用那些投入时间掌握的工具。如果你是一名语言专家，则会因为被迫使用 IDE（而你真正想要的只是 Emacs 或 VI）而感到挫败。这种认知失调，还伴随着需要学习新的库、新的语法和新的编程风格。

这些要求同时发生，实在让人难以承受。语言专家习惯语言不断演进，但不愿意被迫适应一个强制且不够灵活的 IDE。工具专家同样能接受语言的变化，却既不愿意使用新的 IDE，也不希望自己掌握的工具突然全部失效。

最后，我想用暂时把 Squeak 搁置在脑后时的想法作结：如果他们能提供一个 Emacs 的实现，那一切就会轻松多了。

  1. 另外，我想有些不那么纯粹的人（比如除了我之外所有用 OS X 的人）可能会把 TextMate 也算进这个阵营。↩
