Stripe 以产品驱动、开发者为中心的增长模式。

2022-04-16 · 阅读原文

最近，我收到一封邮件，有人询问 Stripe 在产品驱动、开发者为中心增长方面的做法。如果你真正想深入了解 Stripe，最好的方式无疑是阅读 Stripe 2021 年的更新。但在这里，我还是分享一些关于 Stripe 的总体观察，将其视为产品驱动、开发者为中心增长的一个缩影。

摘自红杉资本的 The Market Curve

要开始这段讨论，一个好的切入点是红杉资本提出的市场曲线，它根据公司所服务的客户群体对公司进行分层。2022 年的 Stripe 已覆盖从 SMB 到企业的全范围，但早期的 Stripe 高度聚焦于 SMB 中的初创企业细分市场。

初创企业是 SMB 中一个特别有趣的细分市场，因为它们具备以下特点：

供应商选择流程轻量，和许多 SMB 类似；它们通常只在一个国家、一种货币下运营（至少在美国是这样）；没有历史包袱，不像那些经营多年的 SMB；和大多数 SMB 不同，它们拥有开发者，能够完成技术集成；其中一小部分很有可能在 3-4 年内成长为非常大的企业。

Stripe 的早期产品及其产品驱动增长策略也特别为初创企业量身打造：

每家公司从一开始就需要支付功能，但它们在很长一段时间内并不需要一个全面、广泛的支付解决方案；自助服务让客户能够立即开始集成；Stripe 的账户审批方式（在第一次出款前完成最终审批，而非第一次收款时）相比当时行业内其他公司显著降低了摩擦；Stripe 的定价模式（按交易百分比收费）不需要预付费用或支付担保，这意味着许多初创企业可以完全跳过内部审批流程，从而避免把财务团队和其他内部决策者拉入采购过程。

Stripe 策略中最后一个关键部分是坚持以开发者为中心：

早期初创企业的开发者比例通常高于任何其他类型的公司；在初创企业中，开发者购买开发者产品通常不需要任何跨职能资源来完成集成（只要产品是自助服务的，且不需要大量现金承诺）。这对几乎任何其他类型的购买者和几乎任何其他规模的公司来说都不成立；开发者，尤其是那些在初创企业工作的开发者，可以通过少数几个社区触达（VC、孵化器、Twitter、Hacker News 等）；开发者通常更愿意通过自助服务而不是销售人员来接触产品（因此自助服务不仅仅是更高的利润解决方案，对于专注初创企业的开发者产品来说，它本身就是整体上更好的解决方案）。

这三个因素的结合，加上 Stripe 选择了一个核心问题（支付），并愿意在追求开发者为中心、产品驱动增长的过程中承担业务风险（例如自助服务直接用于生产环境，而不仅仅是开发环境，以及承担欺诈风险），是 Stripe 早期成功的重要原因。当然，最终让 Stripe 与当时采用类似策略的其他公司拉开差距的，是这套策略的执行力，而不仅仅是策略本身。

Stripe 在拥有规模化营销或销售团队之前就已经走了很远（这里的“规模化”指数量，早期极小的团队能力都非常强），但最终他们还是建立了这些职能。他们这么做的原因很简单：他们希望扩展到企业级渠道，而纯产品驱动的方法在那里效果并不好。

产品驱动增长在企业级市场匹配度较低，原因包括：

企业买家期望销售流程中有大量人工参与；企业买家聚集的场所与开发者完全不同，这意味着营销方式也需要完全不同；企业业务期望有结构化的合同流程，包括有意义的法务审查；企业业务期望围绕定价进行详细谈判；在企业级供应商选择中，开发者很少是最重要的决策者，很多时候甚至根本不算重要买家；与早期初创企业相比，企业更看重功能的全面性。

因此 Stripe 建立了传统的企业销售和营销机制。令人惊讶、也最能体现 Stripe 策略高明之处的是，即使在大力建设企业销售团队之后，他们依然持续重视初创企业：

我们的首批客户是正在创业的朋友，直到现在我们依然花大量时间与初创企业在一起。我们努力更好地理解他们在做什么、他们需要什么，以及怎样才能帮助更多人起步。我们希望从他们写下第一行代码开始，一路支持他们直到 IPO 乃至之后更长的时间。

Stripe 能够同时服务企业和初创企业，这是他们最重大的成就之一。他们主要通过以下两点实现这一点：

在战略层面，即使企业业务已经开始起势，他们依然为持续投资初创企业细分市场保留了清晰的战略理由。他们的财务模型理解初创企业如何随着时间成长为企业业务，这使得他们能够理性地在初创和企业两端平衡投入，而很多公司在这点上都非常挣扎。在战术层面，将不同团队与企业和初创买家之间的张力隔离开来。当然存在一些例外，但总体来说，负责 Atlas 的团队只优先考虑早期初创企业的需求，而负责 Payments 的团队则只优先考虑企业客户的需求。

再补充几个零散的想法：

从产品驱动增长扩展到企业业务，比反过来容易得多。前者需要高度自动化和简单便捷的 onboarding，而后者可以用人力驱动的流程来弥补。从一个非常明确的买家群体起步极其重要。你可以更有效地在语气和打法上高度聚焦你的营销和销售工作。特别地，当买家群体非常窄时，你可以做到比如成为那些买家在需要购买你产品时会出现的孵化器中的重要一环。这比写博客文章有效得多，即使你写得非常好。同样，你可以做一些困难但能带来差异化触达的事情，例如 Stripe Atlas 是一个很难提供的产品，但它让 Stripe 即使在那些没有接入任何孵化器或风险投资的初创企业中也能获得触达。在增长的某些阶段，你将不得不扩展获客渠道。关键是要有意为之（确保你正在当前客群中真正获胜），并避免牺牲现有渠道（也要为现有渠道分配资源）。当 Stripe 开始向企业销售时，他们很容易陷入反向创新者困境，而他们没有犯这个错误，是其核心优势之一。从销售到产品的信息传递管道，是在企业市场获胜的关键。例如，企业买家会非常关心合规以及 SOC2 之类的东西，而初创买家可能完全不会想到。如果没有有效的销售到产品信息传递机制，你会举步维艰。在多个支持层级上提供有效支持，通过调整响应速度、正确性和深度来匹配需求，对企业客户的 onboarding 尤为重要。开发者是一种独特的买家，因为他们购买产品后不需要其他职能部门参与集成。IT 可能是另一类类似买家，但不幸的是，他们通常被大多数公司视为成本中心，因此杠杆作用较小。Stripe 还有合作伙伴计划和少量战略合作伙伴关系，帮助其实现分发。合作伙伴是更大版图中重要的一部分，尤其是战略合作伙伴在分发上能发挥的作用。销售、产品和法务之间建设性、协作性的伙伴关系，是另一个容易被忽视但对成功至关重要的因素。许多公司直到分析销售漏斗数据时，才发现合同阶段存在明显摩擦，才意识到这个问题（需要强调的是，这不“只是法务的问题”，而是至少这三个职能之间伙伴关系缺失的体现）。
