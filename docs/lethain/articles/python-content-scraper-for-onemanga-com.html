OneManga.com 的 Python 内容抓取器

2008-08-08 · 阅读原文

我今天花了几个小时写了一个针对 OneManga.com 的 Python 网页抓取器。该网站是一个在线漫画扫描版的聚合站点。特别是我有时候网速较慢，所以想要一个方便的方式来获取图片，而不用费太多功夫。这也是一个使用 BeautifulSoup 和 Httplib2 的有趣机会。实现时重点关注了两个理念：易用性和友好性。易用性是指让用户能够轻松获取可用的数据；友好性则是指不会用不必要的请求去轰炸服务器。

先来看一个使用示例：

>>> import onemanga_reader
>>> x = OMReader()
x = OMReader()
>>> x
OMReader(http://onemanga.com/)
>>> pluto = x['Pluto']
>>> pluto
OMSeries(Pluto)
>>> len(pluto)
55
>>> pluto
OMSeries(Pluto, 55 episodes)
>>> ep = pluto[-1]
>>> ep
OMEpisode(Pluto 55)
>>> urls = [ page.url for page in ep[:5] ]
>>> ep
OMEpisode(Pluto 55, 26 pages)
>>> ep[0].show() # open 0th page in webbrowser

抓取器中的所有对象都兼容 Python 的列表 API。不过，OMReader 对象还能响应类似字典的查询：

>>> x["Pluto"]
OMSeries(Pluto, 55 episodes)
>>> x[155]
OMSeries(D.Gray-Man)

这为访问数据提供了极大的灵活性。你可以遍历所有可用漫画的列表，也可以尝试按名称获取特定漫画。你还能遍历某部漫画的章节列表，以及某个章节的页面列表。例如，如果你想获取网站上每部漫画的每一张图片的 URL（虽然我必须请求你不要真的这么做）：

scraper = OMReader()
series = scraper[:]
episodes = reduce(lambda a,b: a[:]+b[:],series)
pages = reduce(lambda a,b: a[:]+b[:],episodes)
urls = map(lambda a: a.url,pages)

或者你可以把它压缩成一行……

urls = map(lambda a: a.url,reduce(lambda a,b: a[:]+b[:],reduce(lambda a,b: a[:]+b[:],OMReader()[:])))

虽然写得有点丑，但你懂的：获取这些数据非常简单。不过，它的实现仍然相当友好。当你首次创建 OMReader 时，它什么都不知道，也不会发出任何 HTTP 请求。而是会按需懒加载所需的数据。

来看看下面的交互过程：

>>> x = OMReader()
>>> x
OMReader(http://onemanga.com/)
>>> x[0]
OMSeries(+Anima)
>>> x
OMReader(http://onemanga.com/, 1514 series)

第一次查看 x 时，它还是一片空白。然后我们获取第 0 部漫画，它必须先获取可用漫画列表才能做到这一点。因此，当我们第二次打印 x 时，它就已经知道有多少系列可用。幸运的是，可用漫画列表出现在每个页面的 select 元素中，所以只需获取首页（首页不常更新，希望被大量缓存）就足够了。在此之后，我们就知道了所有可用的漫画，既可以遍历它们，也能按名称获取：

>>> names = [ a.name for a in x[100:103]]
>>> names
[u'Boku ni Natta Watashi  ', u'Boku no Hatsukoi wo Kimi ni Sasagu', u'Boku no Watashi no Yusha Gaku']
>>> x['Bleach']
OMSeries(Bleach)

到目前为止，所有操作只发出了一个 HTTP 请求。不过，让我们再深入看看《Pluto》（我可能会推荐它，没错）。

>>> p = x['Pluto']
>>> p
OMSeries(Pluto)
>>> len(p)
55
>>> p
OMSeries(Pluto, 55 episodes)

每当出现新的信息，就表明发生了额外的 HTTP 请求。这里我们必须获取 Pluto 的索引页才能找到它的章节列表。现在，我们来看看具体某一话：

>>> a = p[0]
>>> a
OMEpisode(Pluto 1)
>>> len(a)
32
>>> a
OMEpisode(Pluto 1, 32 pages)
>>> a[:4]
[OMPage(Page 01 of Pluto 1), OMPage(Page 02 of Pluto 1), OMPage(Page 03 of Pluto 1), OMPage(Page 04 of Pluto 1)]

再次出现新信息，说明又进行了一次 HTTP 请求。从概览页面深入到第一话的页面列表，一共只用了三次 HTTP 请求，但从这里开始，获取每一页都需要一次请求，因此保持体贴很重要。由此可知，获取 Pluto 第一话的全部内容还需要额外发出 32 个请求。此外，这个库对 HTTP 请求的处理比较简单，没有并行处理，所以获取大量页面时可能会相当慢。

这就是全部内容了。这是一次（某种意义上）具有社会责任感的网页抓取练习。我不确定它是否会被人使用，但代码里还是有一些挺有意思的地方，而且总共只有大约 120 行，不会让你感到疲惫。你可以在这里获取该文件。
