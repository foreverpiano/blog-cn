在 AuditTrail 和 Django-Rcsfield 之间做选择

2008-10-15 · 阅读原文

在我发帖介绍如何让 django-rcsfield 跑起来后不久，Marty Alchin 发帖提到了 AuditTrail，并询问我是否能看到有什么 compelling 的理由让我选择类似 django-rcsfield 的方案而不是 AuditTrail。

如果你对比两者，它们提供的功能非常相似：

django-rcsfield 使用多种版本控制系统（Git、Bazaar、Subversion）来为 TextField 维护完整的历史版本。AuditTrail 则利用数据库来为整个 Model 维护完整的历史版本（尽管它对关联关系的支持并不完美）。

昨晚我为正在开发的一个应用集成了 django-rcsfield，花了不少功夫去摸索和理解。而就在刚才，我只用了大约五分钟就用 AuditTrail 成功替换了 django-rcsfield。原本 rcsfield 会引发各种奇怪的跨平台 Git 问题，而 AuditTrail 直接就能用。原本 rcsfield 让我那台小小的 VPS 再次严重卡顿，而 AuditTrail 直接就能用。

我能想象到，在某些特定场景下，拥有完整的合并、克隆、分支等功能会是非常宝贵的优势，但我认为这类应用只占所有需要版本控制功能的应用程序中的一小部分。对于不在这个小范围内的项目来说，AuditTrail 似乎是目前最好的现成解决方案。

配置 AuditTrail 的步骤非常简短：

from django.db import models
import audit

class MyModel(models.Model):
    title = models.CharField(max_length=200)
    text = models.TextField()
    history = audit.AuditTrail()

python manage.py syncdb

>>> from models import MyModel
>>> MyModel.create(title="hi",text="some value")
>>> a = MyModel.objects.all()[0]
>>> a.text = "some other value"
>>> a.save()
>>> a.history.count()
2
>>> a.history.all()[0].text
"some other value"
>>> a.history.all()[1].text
"some value"
把 AuditTrail wiki 页面底部的代码复制粘贴到一个名为 audit.py 的文件里，放在你的 Python 路径下。在 models.py 中导入 audit.py。在你的模型定义中添加一个 AuditTrail 字段。同步数据库。大功告成。

虽然我非常感谢为 django-rcsfield 付出大量努力的开发者，但我认为在当前阶段，AuditTrail 是一种更简单实用的数据版本控制方案。当然，我相信这两种方案都有各自的存在价值，有些应用确实会更适合使用 django-rcsfield 而不是 AuditTrail。但我的建议是：优先从 AuditTrail 开始，只有在实际情况确实需要时再考虑切换。

希望这两个项目都能继续发展完善，但在目前阶段，除非你需要合并、推送、拉取或克隆等更高级的 VCS 功能，否则 AuditTrail 是更好的选择。
