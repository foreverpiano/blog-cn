在 AuditTrail 和 Django-Rcsfield 之间抉择

2008-10-15 · 阅读原文

在我发表了如何让 django-rcsfield 运行起来的文章后不久，Marty Alchin 发帖提到了 AuditTrail，并询问我是否能找到 compelling 的理由，让人们选择类似 django-rcsfield 的方案而不是 AuditTrail。

如果你对两者进行比较，会发现它们提供的功能非常相似：

django-rcsfield 利用多种版本控制系统（Git、Bazaar、Subversion）来为 TextField 维护完整的历史版本记录。而 AuditTrail 则是利用数据库来为一个 Model 维护完整的历史版本记录（尽管它对关联关系的支持可能不太友好）。

昨晚我为正在开发的一个应用集成了 django-rcsfield，花了不少功夫才搞明白。而就在刚才，我只用了大约五分钟就用 AuditTrail 成功替换了 django-rcsfield。rcofield 会引发各种奇怪的跨平台 Git 问题，而 AuditTrail 直接就能正常工作；rcofield 曾导致我的小型 VPS 严重卡顿——而 AuditTrail 依然是开箱即用。

我能想象到一些特定场景下，拥有合并、克隆、分支等完整功能的版本控制会成为真正的优势，但我觉得这类应用只占所有需要版本控制的应用中的极小一部分。对于不在这个小众范围内的项目来说，AuditTrail 似乎是目前最好的现成解决方案。

配置 AuditTrail 的步骤非常简短：

把 AuditTrail wiki 页面底部的代码复制到一个名为 audit.py 的文件中，并确保它在你的 Python 路径中。在 models.py 中引入 audit.py： from django.db import models import audit 在你的模型定义中添加 AuditTrail 字段： class MyModel(models.Model): title = models.CharField(max_length=200) text = models.TextField() history = audit.AuditTrail() 同步数据库： python manage.py syncdb 然后就可以开始使用了。 >>> from models import MyModel >>> MyModel.create(title="hi",text="some value") >>> a = MyModel.objects.all()[0] >>> a.text = "some other value" >>> a.save() >>> a.history.count() 2 >>> a.history.all()[0].text "some other value" >>> a.history.all()[1].text "some value"

虽然我非常感谢为 django-rcsfield 付出大量努力的开发者，但目前看来，AuditTrail 是一种更简单的数据版本控制方案。我认为这两种方案都有存在的价值，有些应用确实会更适合使用 django-rcsfield 而非 AuditTrail。但我建议大家优先从 AuditTrail 开始，只有在实际需求要求时再考虑切换。

希望这两个项目都能继续得到改进，但在目前阶段，除非你需要合并、推送、拉取或克隆等高级 VCS 功能，否则 AuditTrail 是更好的选择。
