第五次博客重写的笔记

2017-04-02 · 阅读原文

我 2017 年的项目之一是清理自己的在线账户。从关闭不用的服务、转向使用密码管理器、购买 YubiKey，到在所有地方启用 2FA。

后续事情变得稍微复杂一些：我把所有域名从 GoDaddy 迁移到 AWS Route53 作为域名注册商，最后又把虚拟机从 Linode 迁移到了 AWS。（不是对 Linode 有意见，只是想要更多它无法提供的东西。）

和往常一样，这最终以我重写博客告终。

（神奇的是，写完之后我才意识到，这是我第二次在博客文章里宣称自己已经把博客重写了五次。或许今后的惯例就是把所有未来的重写都称为“第五次”。）

出于各种反复无常且随心所欲的原因，我每隔一两年就会重写一次博客。大多数时候，我都把它当作学习一门编程语言、一套库或者托管基础设施的机会。

这些年来，它从一个运行在 Slicehost（老实说，它还在 DreamHost 上跑过一阵子）上的极其复杂的 Django 应用，变成在 Linode 上的 Go 应用，而过去几周我又把它重写成一个更简单的 Go 应用，并迁移到了 AWS。

旧的架构极其简单：

本质上，这就是一台带有公网 IP 的 Linode 服务器，直接处理所有流量。它用 Nginx 作为前端，后面跑着一个用 net/http 写的 Go 服务，所有持久化数据都依赖本地的 Redis 实例。Redis 负责记录实时分析数据以确定热门文章，并通过一个命令行工具把 Git 仓库里的 Markdown 文章插入到 Redis 中。

而新的实现依然相当简单，虽然多了几个组件。

外部流量先到达 AWS ALB，然后被负载均衡分发到 ASG 上，ASG 中的实例运行着由 AMI 启动的 Go 服务。（重写并简化后的 Go 服务，但整体上还是很相似。）这些 AMI 是通过 Packer 构建的（我在用 Terraform 配置整体 AWS 环境时中途感到烦躁，但之后可能会回去重新整理）。

我思考了如何在 ASG 的多个实例之间管理状态，最后采用了相当基础的策略：

  1. As a variation on the Jekyll strategy, take an index.yaml file and the blog posts to compile a packed.yaml. The packed.yaml file contains all the data necessary to run the blog, and (along with a path to static assets) is all the state maintained by instances.
  2. Run a periodic sync script which syncs packed.yaml and static assets down from S3 to each instance.
  3. Use Google Analytics instead of managing my own analytics in Redis. As a corrolary, give up on inferring trending posts and move to specifically curating popular posts. At its best, a trending approach should have simply been a faster and wiser version of featuring posts, but in practice I never tuned the algorithm, and old posts stagnated at the top indefinitely.

当 ASG 启动新实例时，在成功完成内容同步之前，它会持续健康检查失败，这使得上述策略在新实例上也能干净地工作。（不过，我的健康检查逻辑似乎在某处有个漏洞，导致偶尔会过早通过，我之后得挖出来修一下。）

其他几个亮点：

  1. Added HTTPs, and redirect all HTTP requests over to HTTPs.
  2. Search actually works properly now. Previously Blekko (Go library) frequently got stale for unclear reasons.
  3. Introduced concept of a hero header image, and added Opengraph tag for it to get crawled properly.
  4. Moved the sidebar off the front page, more room for hero images, etc.
  5. Gave up on trending algorithms and moved to curration. I think this is “on internet trend”, but that’s entirely a coincidence.
