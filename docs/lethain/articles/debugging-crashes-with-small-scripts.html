用小程序调试崩溃问题

2010-01-23 · 阅读原文

上周我在工作中遇到了一个很有意思的 Bug。我们有一个组件，大约每两周就会周期性地崩溃一次。内存占用并没有随时间增长，CPU 使用率也没有上升。崩溃发生时正在处理的文件也没有任何明显规律。后来我们发现，它总是在处理大约三万两千个文件之后稳定崩溃。

进一步通过日志追踪，我们基本确定导致崩溃的代码行是这一句：

global:register_name(UniqueId, spawn(some_module, some_func, [some_params])),

并且在日志中还看到了这条错误信息：

=ERROR REPORT==== 23-Jan-2010::11:00:48 ===
Too many processes

我不确定一年前自己会如何处理这个问题，但最近我读了 Joe Armstrong 在《Coders at Work》中的访谈，他提到自己经常编写简单脚本来检查性能、尝试算法等，这似乎正是解决当前问题的正确方法。

首先我想知道问题是否出在 global:register_name/2 上，于是尝试对同一个进程注册超过 32,000 次。

F = fun() -> receive A -> A end end,
Pid = spawn(F),
lists:foreach(fun(X) -> 
    io:format("~p~n",[X]),
    global:register_name(list_to_atom(integer_to_list(X)), F) 
  end,
  lists:seq(0, 100000)).

这的确产生了大量错误（global 不允许用多个名字注册同一个 pid），但始终没有出现“Too many processes”错误。因此问题似乎可以通过对同一个进程注册超过 32,000 次来复现。

下一步是尝试注册 32,000 个不同的进程。

F = fun() -> receive A -> A end end,
Z = fun(X) ->
    io:format("~p~n", [X]),
    Atom = list_to_atom(integer_to_list(X)), 
    global:register_name(Atom, spawn(F))
  end,
  lists:foreach(Z, lists:seq(0, 100000)).

第二次尝试成功复现了问题，运行一段时间后抛出了“Too many processes”错误。最后，我需要确认问题是由于创建了太多进程，还是注册了太多不同的进程。

为此，我给函数加上了超时，让它们只存活一秒而不是永远运行下去。

F = fun() ->
    receive A -> A 
    after 1000 -> {error, timeout} 
    end
  end,
Z = fun(X) -> 
    io:format("~p~n", [X]), 
    Atom = list_to_atom(integer_to_list(X)), global:register_name(Atom, spawn(F))
  end,
  lists:foreach(Z, lists:seq(0, 100000)).

这个脚本一直运行到了 100,000 也没有崩溃。原来确切的限制是 32768，可以通过命令行参数 +P 来修改，具体说明在 erl 的文档中。

当然，单纯提高允许的进程数量并不是正确的解决方案。真正的解决办法是找出为什么会有 32,768 个进程一直挂起而没有被清理掉（后来发现是在一段部分实现的功能代码中，有个进程被 spawn 出来后一直在等待一条永远不会收到的消息）。

今后，我应该会编写更多小型测试脚本，把它作为调试工具箱里的新成员。
