ReST、Textile 和 HTML 在 Markdown 中的使用

2008-07-01 · 阅读原文

最近我遇到几次这样的情况：希望能在博客文章中直接插入原始 HTML 和 JavaScript，而不必依赖 Markdown 解析器的宽容处理。于是我今天早些时候快速做了一个原型，晚上又完善了实现。现在，在 LifeFlow 博客文章中，你可以这样书写原始 HTML/JavaScript：

~~~
Can I do this now?
~~~

不过，既然已经折腾到这个地步，我就干脆再多做一点。如果安装了 docutils 包，你就可以这样渲染一段 reStructuredText：

~~~ReST
  +------------------------+------------+----------+
  | Header row, column 1   | Header 2   | Header 3 |
  +========================+============+==========+
  | body row 1, column 1   | column 2   | column 3 |
  +------------------------+------------+----------+
  | body row 2             | Cells may span        |
  +------------------------+------------+----------+
~~~

不管你把 ReST 的大小写写对还是写错都没关系，只要拼写正确即可。你也可以用同样的方式渲染 Textile 标记（前提是安装了 Python Textile 模块）：

~~~textile
|_. Header |_. Header |_. Header |
| Cell 1 | Cell 2 | Cell 3 |
| Cell 1 | Cell 2 | Cell 3 |
~~~

虽然我得承认这有点多此一举，但能够自由混用各种标记语言（甚至临时完全禁用标记语言），实际用起来会非常方便。特别是在引用其他作者的内容，或者发布文档片段的时候尤其有用。另外，用 Markdown 写关于 Markdown 语法的文章本身就很痛苦，现在作者可以临时切换到 Textile 来写关于 Markdown 的内容，写完再切回 Markdown。虽然有点绕脑，但确实很实用。

如果有人感兴趣，把这个功能抽取成一个通用的 Python Markdown 扩展并不难，只需要把 django.utils.encoding.smart_str 函数复制一份放到 lifeflow.markdown.mdx_foreign_formats 文件中即可。
