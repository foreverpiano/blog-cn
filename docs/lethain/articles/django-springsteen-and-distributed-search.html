django-springsteen 与分布式搜索

2009-02-25 · 阅读原文

很长一段时间以来，我一直想开发一个可插拔的 Django 应用，用于查询 Yahoo! BOSS。虽然实现本身非常简单，但这个应用需要加入一些特别的“调味料”来提升其吸引力。希望你会觉得它的味道还不错。

这就是 django-springsteen。（名字的功劳完全归于 Justin Lilly。）

springsteen 为 Yahoo! BOSS 提供了一个简单的封装，但它更进一步，提供了一个构建分布式搜索网络的简易框架。如果你梦想每个博客网络都能被搜索，每个细分领域都能拥有自己的垂直搜索，那么 springsteen 正是为你准备的。

让我们从一些示例开始。

查询 BOSS 的网页搜索结果

springsteen 预置了用于搜索 Yahoo! BOSS 的网页、图片和新闻结果的视图，这也是最简单的使用场景。

from django.conf.urls.defaults import *
from springsteen.views import web, images, news
urlpatterns = patterns('',
(r'^search/web/$', web),
(r'^search/images/$', images),
(r'^search/news/$', news),
)

然后访问 http://yourproject.com/search/web/（或者 /search/images/、/search/news/），你就会立刻得到一个可用的搜索页面。

网页搜索结果（以及所有已实现的服务）的结果会使用你在 settings.py 中指定的缓存后端进行缓存。缓存 Yahoo! BOSS 带来的速度提升可能不算显著，但对于更特别的服务（以及频繁的搜索），缓存会成为一项更重要的特性。

要清理外观，可以重写 springsteen/base.html 或 springsteen/results.html 模板。（你也可以重写 *_result.html 模板来自定义不同类型的搜索结果。）

带站点限制的 BOSS 搜索结果

如果你只想获取单个站点的网页搜索结果（穷人的站内搜索），可以继承 springsteen.services.Web 类（你也可以通过分别继承 springsteen.services.News 和 springsteen.services.Images 类来限制新闻或图片搜索）。

首先是继承实现。

from springsteen.services import Web
class DjangoProjectSearch(Web):
def init(self, query, params={}):
super(Web, self).init(query, params)
self.params['sites']='djangoproject.com'

你还可以添加其他参数，这些参数在 Yahoo! BOSS 文档中有定义。

编写完自定义搜索类后，再编写一个使用它的视图。

from springsteen.views import search
from my_searches import DjangoProjectSearch
def dp_search(request, timeout=2000, max_count=5, 
services=(DjangoProjectSearch,), extra_params={}):
return search(request, timeout, max_count, services, extra_params)

并行查询多个服务

作为 Web 开发者，我经常犯的一个错误是按顺序发起 HTTP 请求，而这些请求其实可以并发执行。springsteen 的目标是聚合多个搜索服务，因此它需要能够并行请求和处理它们。

要执行并发请求，只需指定多个服务即可。（注意下面在 settings 中定义的值不是标准配置，但如果你喜欢这样组织全局变量，可以把它们放到你的 settings.py 中。）

from django.conf import settings
from springsteen.services import Web, Images
from springsteen.views import search
def my_search(request):
timeout = settings.SPRINGSTEEN_TIMEOUT
max_count = setttings.SPRINGSTEEN_MAX_COUNT
services = (Web, Images)
return search(request, timeout, max_count, services)

默认情况下，来自不同服务的结果会依次堆叠显示。例如，上面 my_search 的结果会先显示所有图片结果，然后再开始显示网页结果。

结果排序是搜索中最困难的部分，springsteen 不会替你解决这个问题。它会给你提供控制手段，让你自己来实现。对于大多数中小规模的应用场景，你完全可以针对自己查询的服务编写简洁的排序逻辑，其效果往往会优于 springsteen 可能提供的任何通用算法。

通过 Springsteen 服务暴露搜索结果

因为 springsteen 的核心在于聚合搜索服务，它会逐步扩展以支持新的数据格式。但有时候你只是想把新数据暴露给 springsteen，而还没有决定采用什么格式。

在这种情况下，你可以使用 Springsteen Service。撇开这个酷炫的名字不谈，它们的用法非常简单。想象一下，你能以 CSV 格式获取搜索结果（这不现实，只是举个例子）。

假设你的数据长这样：

title, url, text
abc, http://yadayad/abc/, some text here
efg, http://yadayad/efg/, some text here as well

并且你有一个 csv_search 函数可以返回相关行。你可以按如下方式通过 Springsteen Service 将其暴露出去。

from csv import DictReader
from fake_web_service import csv_search
from django.utils import simplejson
from springsteen.views import service
def retrieve_csv_results(query, start, count):
csv_results, total_results = csv_search(query, start, count)
results = []
for line in DictReader(csv_results):
result = {
'title': line['title'],
'url': line['url'],
'text': line['text'],
}
results.append(result)
data = {
'total_results': total_results,
'results': results,
}
return simplejson.dumps(data)
def my_service(request):
return service(request, retrieve_func=retrieve_csv_results)

目前 Springsteen Service 仅承认 title、url 和 text 这三个字段。随着需求增加，标准可能会被进一步完善，以支持更多元数据。

你可以用这种方式来封装 Solango 或 Django-Sphinx 的结果，也可以用来对接你生态系统中非 Django 的 API 或服务，而不只是上面假设的 csv_search。

搜索 API 的中继与转换器

假设你想为自己的博客实现一个站内搜索 API，但又没有“工程资源”去集成 Solango 或 Django-Sphinx 这样的方案。

首先我们需要继承 Web 类来获取本站点的搜索结果。

from springsteen.services import Web
class MySiteService(Web):
def init(self, query, params={}):
super(Web, self).init(query, params)
self.params['sites']='lethain.com'

然后我们需要将结果暴露出去。

from django.http import HttpResponse
from springsteen.views import service
from django.utils import simplejson
from somewhere import MySiteService
def retrieve_func(query, start, count):
params = {'start':start, 'count':count}
mss = MySiteService(query, params)
mss.run()
results = mss.results()
json = simplejson.dumps(results)
return HttpResponse(json, mimetype="application/json")

现在 Yahoo! BOSS 的结果被转换成了 Springsteen Service 格式，可以被外部的 springsteen 搜索稳定地查询了。

从 Springsteen Service 获取结果

从 Springsteen Service 获取结果非常简单，和获取 Yahoo! BOSS 结果差不多。

from springsteen.services import SpringsteenService, Web
from springsteen.views import search
class MyService(SpringsteenService):
_uri = "http://example.com/search/cvs/"
def my_search(request, timeout=2500, max_count=20):
services = (MyService, Web)
return search(request, timeout, max_count, services)

springsteen 已经知道如何显示来自 Springsteen Service 的结果，因此集成过程相当简洁。

访问自定义服务

如果能让合作伙伴以你期望的格式（在本例中是 SpringsteenService）暴露服务，那当然是最简单的。但有时候你必须自己动手去解析数据。

在 springsteen.services 中，SpringsteenService 和 BossSearch 类都提供了与不同数据格式打交道的示例。

关键在于编写一个 run 方法，该方法负责获取结果并将其转换为 Python 的字典列表。如果你想使用现有的模板片段（web、news、image 或 springsteen results）来渲染它们，就应该为每个结果字典的 source 键添加对应的值。

def run(self):
    stuff, total_results = get_results(self.query, self.params)
    results = simplejson.loads(stuff)
    for result in results:
        result['source'] = 'web'
    self._results = results
    self.total_results = total_results
