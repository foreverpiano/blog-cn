django-springsteen 与分布式搜索

2009-02-25 · 阅读原文

很长一段时间以来，我一直想开发一个可插拔的 Django 应用，用于查询 Yahoo! BOSS。虽然实现本身相当简单，但这个应用需要加入一些特别的“调味料”来让它更具吸引力。我希望你会觉得它的味道还不错。

这就是 django-springsteen。（名称的致敬完全来自 Justin Lilly。）

springsteen 为 Yahoo! BOSS 提供了一个简单的封装，但更进一步，它提供了一个构建分布式搜索网络的简易框架。如果你梦想着一个每家博客网络都可以被搜索、每个细分领域都有自己的垂直搜索的世界，那么 springsteen 就是为你准备的。

让我们从一些示例开始。

查询 BOSS 获取网页搜索结果

springsteen 预置了用于搜索 Yahoo! BOSS 的网页、图片和新闻结果的视图，这也是最简单的使用场景。

然后访问 http://yourproject.com/search/web/（或者 /search/images/ 或 /search/news/），你立刻就会看到一个搜索页面等待着你。

网页搜索结果（以及所有已实现的服务）的缓存使用你在 settings.py 中指定的缓存后端。缓存 Yahoo! BOSS 带来的速度提升可能并不明显，但对于更特别的服务（以及高频搜索）来说，缓存会成为一项更重要的特性。

要改善外观，可以重写 springsteen/base.html 或 springsteen/results.html 模板。（你也可以重写 *_result.html 模板来自定义不同类型的结果。）

并行查询多个服务

作为 Web 开发者，我经常犯的一个错误是按顺序发起 HTTP 请求，而这些请求本来可以并发执行。springsteen 的目标是聚合多个搜索服务，因此它必须能够并行请求和处理它们。

要执行并发请求，只需指定多个服务即可。（请注意下面在 settings 中定义的值并非标准配置，但如果你喜欢这种组织全局变量的方式，可以把它们放到自己的 settings.py 中。）

默认情况下，来自各个服务的结果会依次堆叠显示。例如，上面 my_search 的结果会先显示所有图片结果，然后才开始显示网页结果。

结果排序是搜索中最困难的部分，springsteen 不会替你解决这个问题。它只会给你提供可以自行调整的控制杆。对于大多数中小规模的应用场景，你完全可以针对正在查询的服务编写相当简洁的排序逻辑，其效果往往会优于 springsteen 可能提供的任何通用算法。

通过 Springsteen 服务暴露搜索结果

因为 springsteen 的核心就是聚合各种搜索服务，所以它会逐步扩展以支持新的数据格式。不过有时候你只是想把新的数据暴露给 springsteen，并且还没有确定具体格式。

在这种情况下，你可以使用 Springsteen Service。名字很酷，但实现其实非常简单。假设你能以某种方式获取到 CSV 格式的搜索结果（这不现实，只是举个例子）。

目前 Springsteen Service 仅认可 title、url 和 text 这三个字段。随着需求增加，标准可能会被进一步完善以支持更多元数据。

除了上面假设的 csv_search，你还可以用这种方式封装 Solango 或 Django-Sphinx 的结果，或者路由到你生态系统中非 Django 的 API 或服务。

目前 springsteen 的核心部分已接近完成，我只需要稍作重构，以便能够方便地插入自定义排序逻辑。除此之外，还有无数的服务等待 springsteen 去学习如何查询和展示。

我希望 springsteen 以及它所代表的“由小玩家构建的分布式搜索”愿景能让你感到兴奋。我自己就对这样的前景充满热情——创建有针对性且相关的搜索框，其动力不是来自数据中心里成千上万的普通服务器，而是来自我的 VPS，以及你的。
