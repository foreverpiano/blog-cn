口语、Blub 与便利性

2008-05-25 · 阅读原文

许多程序员都读过 Paul Graham 的那篇《Beating the Averages》，它提出了一套关于编程语言层级结构的理论。一个习惯于某种编程语言的程序员，如果该语言缺少某些功能，他就很难想象这些功能到底有什么用。毕竟，没有这些功能他也一直用到现在，所以它们应该没那么重要，对吧？

用 Graham 的话来说：

只要我们假想的 Blub 程序员是在向下看能力谱系，他清楚自己是在向下看。比 Blub 弱的语言显然能力较弱，因为它们缺少他已经习惯的某些特性。但当这位假想的 Blub 程序员反过来向上看能力谱系时，他却没有意识到自己在向上看。他看到的只是一些古怪的语言。他很可能认为这些语言和 Blub 的能力大致相当，只是额外附加了一堆乱七八糟的东西。对他来说 Blub 就足够好了，因为他是用 Blub 的思维方式思考的。

我认为有一点还没有得到足够重视，那就是这个道理同样适用于人类自然语言，而且是以一种有趣的方式。不同的口语在某些特定类型的表达上各有专长。英语是一种对时间极其执着的语言，拥有将来时、过去时、现在时、完成时、进行时等各种时态。但英语在表达正式程度方面不如西班牙语或法语精确，后两者都把正式程度融入到了动词变位之中。而日语则比大多数西方语言更精确地规范了敬语体系。

日语与英语的另一个显著区别是它没有将来时：“我将要去学校”和“我去学校”的表达方式完全一样。然而，日语在表达情感细微差别上非常擅长，而且有一些小技巧能帮助谈论时间相关的事件（比如 ototoi、asatte、saraisyuu，分别表示“前天”“后天”和“下下周”——这些词真的非常好用，我希望英语也有对应的词汇）。

稍微退后一步，让我们把 Graham 关于 Blub 语言的论点继续应用到这个比较上。具体来说，我们是否认为可以在口语之间建立一个能力层级？这个思考练习一开始就很困难，很大程度上是因为每种语言都有自己擅长的领域（正式程度、时间、情感细微差别等等），因此我们所谓的能力层级会完全取决于我们如何定义“能力”。我们很容易论证英语比日语更强大——如果谈论的是时间的话——但只要改变“能力”的定义，我们就能迅速把这个结论反转过来。

不过，我认为我们可以在现代意大利语和拉丁语之间提出一个相当清晰的能力层级。意大利语和拉丁语非常相似，只是它丢失了拉丁语的许多时态和复杂结构。正如 Lisp 悲惨地败给了能力更弱的后继者，拉丁语的结构和语法深度也让位于它那些能力较弱的子女（罗曼语族语言）。

为什么更强大的方案会被拒绝，转而采用能力较弱的呢？原因和拉丁语逐渐废弃的原因一样：当达到某个临界点后，拥有更多能力所带来的好处（和成本）会被便利性所超越。程序员之所以涌向 Python 而不是 Common Lisp，是因为 Python 已经足够强大，而且方便得多。现代软件开发的大部分工作都是处理技术上相对简单的事情，额外能力带来的收益并不值得去忍受复杂的包管理、别扭的字符串处理，或者由各种相互竞争的实现所带来的混乱。

在 CL 的不便之处得到解决之前，Lisp 在能力层级中处于什么位置并不重要。如今被大量使用的所有语言，对于它们所面对的常见任务来说都已经足够强大。而那些正在获得关注度的语言，是因为它们更方便，而不是因为它们更强大。

新兴的、希望成为主流的语言，必须首先在便利性上竞争，其次才是能力。这就是为什么我们看到大量基于 JVM 的语言涌现——它们借助已有的 Java 库和广泛部署的 JVM，即使渗透率不高也能获得极大的便利。同时，这也解释了为什么那些没能迎合便利性的语言会陷入困境，即使它们明显比现有流行语言强大得多。
