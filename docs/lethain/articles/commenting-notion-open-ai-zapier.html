通过 OpenAI 和 Zapier 在 Notion 文档中添加评论

2025-07-20 · 阅读原文

我在工作中的一个支线任务是建立一个简单的反馈循环，让我们能够创建知识库来对 Notion 文档进行评论。我很好奇是否能按照以下要求把这些部分连接起来：

无需托管自定义代码；Prompt 可在 Notion 内编辑，而无需了解 Zapier；整体实现要相对快速。

最终我成功让它运转起来了。下面先快速总结它的工作原理，然后谈谈我不喜欢这种方案的原因，最后再详细说明实现细节。

整体方案

创建一个 Notion 数据库来存放 Prompt。

专门创建一个用于对 RFC 提供反馈的 Prompt。

创建一个用于存放所有 RFC 的 Notion 数据库。

在这个 RFC 数据库中添加一个自动化，调用 Zapier 的 Webhook。

Zapier Webhook 会执行一系列操作，最终使用 RFC Prompt 对具体文档生成反馈，并以顶级评论的形式添加到 RFC 中。

整体来看，这个方案运行得还算不错。

这个方案的挑战

这个方案最大的优点是它确实能工作，而且效果相当好。然而，当我们深入实现细节时，你会发现用 Zapier 做以下事情都异常困难：

处理 Notion 中的富文本，因为需要操作 blocks 数据结构；支持循环的 API 调用，例如轻松地在特定块上留下多条评论而非仅在顶部留一条评论；Notion 每个 block 最多只允许 2000 个字符，而将其拆分成多个 block 的操作又比较不自然。如果是在真正的 Python 环境中，使用 md2notion 这类工具就能非常轻松地在 Markdown 和 Notion 格式之间转换。

总的来说，我只推荐把这个方案当作初步验证。它绝对不是这类功能的长期合适解决方案。

Zapier 实现细节

我已经介绍过集成的 Notion 端，下面来详细看看 Zapier 的部分。整体一共有八个步骤。

我跳过了第一个步骤，它只是一个默认的 Webhook 接收器。第二步是获取一个静态定义的、包含 Prompt 的 Notion 页面。（在后续步骤中我直接使用了 Notion API，如果重做我会从头就用 API，不过当时那样也能工作。API 的优势是返回真正的 JSON 对象，而这个方法没有，可能是因为我没有设置 content-type header 之类的原因。）

这是步骤 2 的配置页面，我在这里显式指定了 Prompt 所在的页面。

可能因为没有设置 content-type，我拿到的应该是表单格式的数据，所以我用正则表达式把它提取了出来。虽然有点粗糙，但它确实管用，就这样吧。

接下来使用 Notion API 请求工具获取更新后的 RFC（区别于之前已经获取的 Prompt）。

API 请求返回的是真正的 JSON 对象，可以直接导航而无需写正则表达式，这一点很不错。

然后我们把 Prompt 作为 system instructions，把 RFC 作为 user message，一起发送给 OpenAI。

接着把 OpenAI 的返回结果传给 json.dumps 进行编码，以便后续用于 API 调用。这主要是为了把 \n 转成真正的换行符。

最后把响应格式化成一个 API 请求，添加到文档的评论中。

总之，这套方案不算优雅。我认为直接用 Python 来实现所有逻辑会好得多，但作为一个可行的概念验证，它还是能用的。
