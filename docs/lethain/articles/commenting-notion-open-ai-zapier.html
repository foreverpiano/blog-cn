通过 OpenAI 和 Zapier 在 Notion 文档中添加评论

2025-07-20 · 阅读原文

我在工作中的一项副任务是建立一个简单的反馈循环，让我们能够创建知识库来对 Notion 文档进行评论。我很好奇是否能按照以下要求把这些东西连接起来：

  1. No custom code hosting
  2. Prompt is editable within Notion rather than requiring understanding of Zapier
  3. Should be be fairly quickly

最终，我成功让它运行起来了。下面快速总结它的工作原理、为什么我不太喜欢这种方式，以及一些更详细的实现说明。

总体方案

创建一个存储 Prompt 的 Notion 数据库。

创建一个专门用于对 RFC 提供反馈的 Prompt。

创建一个用于存放所有 RFC 的 Notion 数据库。

在这个数据库中添加一个自动化，调用 Zapier Webhook。

Zapier Webhook 会执行一系列操作，最终使用该 RFC 的 Prompt 对具体 RFC 进行反馈，并以顶级评论的形式添加到 RFC 中。

整体来说，这个方案运行得相当不错。

这种方案的挑战

这个方案最大的优点是它确实能工作，而且效果还不错。然而，当我们深入实现细节时，你会发现使用 Zapier 有很多事情做起来格外别扭：

  1. Managing rich text in Notion because it requires navigating the blocks datastructure
  2. Allowing looping API constructs such as making it straightforward to leave multiple comments on specific blocks rather than a single top-level comment
  3. Notion only allows up to 2,000 characters per block, but chunking into multiple blocks is moderately unnatural. In a true Python environment, it would be trivial to translate to and from Markdown using something like md2notion

总的来说，我只推荐把这个方案当作初步验证。它绝对不是这类功能的长期理想解决方案。

Zapier 实现细节

我已经介绍了集成中 Notion 这一侧的内容，下面我们来深入看看 Zapier 的部分。整体上它包含八个步骤。

我跳过了第一个步骤，它只是一个默认的 Webhook 接收器。第二步是获取一个静态定义的、包含 Prompt 的 Notion 页面。（在后续步骤中我直接使用了 Notion API，如果重做的话我会在这一步也直接用 API，不过当时这样也行得通。API 的优势在于它返回的是真正的 JSON 对象，而这里不是，可能是因为我没有设置 content-type header 之类的原因。）

这是步骤 2 的配置页面，我在这里显式指定了 Prompt 所在的页面。

可能是因为没有设置 content-type，我觉得这里收到的是表单格式的数据，所以我就用正则表达式把数据提取了出来。虽然有点粗糙，但它管用，所以就这样了。

这里使用 Notion API 请求工具来获取更新的 RFC（区别于之前已经获取的 Prompt）。

API 请求返回的是 JSON 对象，可以直接导航而无需写正则表达式，这点很不错。

接着我们把 Prompt 作为 system instructions，把 RFC 作为用户消息一起发送给 OpenAI。

然后把 OpenAI 的返回结果传给 json.dumps 进行编码，以便后续用于 API 调用。这主要是为了把 \n 转换成真正的换行符。

最后把响应格式化成一个 API 请求，添加到文档的评论中。

总之，这个方案不算优雅，我认为直接用 Python 来实现所有这些会好得多，但作为一个可行的概念验证，它还是可以的。
