《软件工程师指南》笔记

2023-11-19 · 阅读原文

Gergely Orosz 所著的《The Software Engineer’s Guidebook》是一本面向软件工程师的广度参考书，对新入行的软件工程师以及大部分职业生涯都在少数几家公司度过的人特别有价值。它并没有在每个主题上都深入展开，但几乎为你作为软件工程师会遇到的绝大多数话题都留下了“面包屑”，并提供了足够的信息，引导你去其他更聚焦的书籍中进行深入探索。

Gergely Orosz 是 The Pragmatic Engineer 的作者，几乎可以说是当前“影响力最广的软件工程作者”，拥有约 50 万订阅者。他最近出版了《The Software Engineer’s Guidebook》，名义上这是他的第三本书，此前还有《The Tech Resume Inside Out》和《Building Mobile Apps at Scale》。但你也可以认为《Guidebook》才是他第一本真正成型的书。前两本更像是他在图书媒介上的实验，而这本书是他带着完整计划创作的第一本。

在详细谈我的看法之前，我想先暂停一下，明确说明 Gergely 和我是朋友，我们过去曾有过合作，未来大概率还会继续合作。尽管如此，如果你来我的博客是想看我对这本书的猛烈抨击，那恐怕要失望了——我这里不做这种内容。

本书闪光之处

《Guidebook》做得特别出色的一点，是用简短的篇幅覆盖了非常广泛的主题。这里有大量新毕业生或只在一家公司工作过的工程师从未接触过的想法。即使是我职业生涯第五年的时候，书中仍有许多我之前并不真正理解的主题，尤其是那些通常只有作为管理者才能看到的内容。为新工程师缩小这一差距是非常有价值的。

由于覆盖的主题太多，大多数内容的深度都比较浅，但我认为这是恰当的。这本书的本意就是提供“面包屑”，引领读者去寻找各个具体主题更深入的资源。

有人可能会说这种“广一英里、深一英寸”的做法是失败的，因为它没有深入挖掘，但我认为这种看法并不正确。所有书籍都会面临已经超越其主题的受众，而用已经不需要这本书的读者视角来评价它，并不是特别有意义。

定位策略

当你进入写书和出版的世界后，一个无法回避的约束是：你需要足够宽泛的主题才能支撑较高的销量。从定位角度看，《Guidebook》几乎是一本完美的书，因为它：

目标读者是职业早期工程师，并旨在成为一本可以长期反复查阅的百科全书式参考书。

将这两个理念结合在一起，你就得到了一本既能支撑广泛销量，又很可能随着读者职业发展继续留在他们书架上的书。

自我出版

这本书一个有趣的地方在于它是自出版的。这部分是历史偶然——Gergely 最初提出这个书稿时影响力还没有现在这么大，但同时也是他经过深思熟虑的决定：以他如今的影响力，几乎任何出版社都会毫无条件地接受这本书并出版。

Gergely 以写作为生，而自出版在拥有自己分发渠道的情况下，财务收益是无可辩驳的。我不确定传统的科技类出版社是否真的能为那些已经拥有强大分发能力的成熟作者弥补这一差距。

出版社对那些无法接触到编辑、或缺乏书籍结构反馈的新作者能提供很多帮助。对于没有自身分发渠道的作者，出版社也有一定价值，虽然我认为其价值可能没有第一次出书的作者想象得那么大。而对于已经拥有强大分发能力、也愿意承担出版运营开销的成熟作者来说……出版社能提供的东西并不足以抵消财务上的成本。
