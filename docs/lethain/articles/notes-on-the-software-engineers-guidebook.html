《软件工程师指南》笔记

2023-11-19 · 阅读原文

Gergely Orosz 所著的《The Software Engineer’s Guidebook》是一本面向软件工程师的宽泛参考书，对新入行的软件工程师和那些大部分职业生涯只在少数几家公司工作过的人特别有价值。它并没有在每个主题上都深入探讨，但为软件工程师在职业生涯中会遇到的绝大多数话题都留下了“面包屑”，并提供了足够的细节，引导读者去其他更专注的书籍中进行深入探索。

Gergely Orosz 是《The Pragmatic Engineer》的作者，几乎可以肯定是目前“影响力最广的软件工程作者”，拥有约 50 万订阅者。他最近出版了《The Software Engineer’s Guidebook》，名义上这是他的第三本书，之前还有《The Tech Resume Inside Out》和《Building Mobile Apps at Scale》。但你也可以认为《Guidebook》才是他第一本真正成型的著作。前两本书更像是他在图书媒介上的试验，而这本书是 Gergely 带着完整计划创作的第一本。

在分享我的完整看法之前，我想先暂停一下，明确说明我和 Gergely 是朋友，过去有过合作，未来大概率也还会继续合作。尽管如此，如果你来我的博客是期待看到对这本书的猛烈抨击，那恐怕要失望了——这里不是做这种事情的地方。

本书闪光之处

《Guidebook》做得特别出色的一点，是用简短的篇幅覆盖了非常广泛的一系列主题。其中包含了大量新毕业生或只在一家公司工作过的工程师从未接触过的概念。即使是我职业生涯已经第五年，书中仍有一些主题我之前并不真正理解，尤其是那些通常只有作为管理者才能看到的视角。为新工程师缩小这些认知差距，是非常有价值的。

由于涵盖主题众多，大多数内容的深度都比较浅，但我认为这在这里是恰当的。这本书本质上是一本“面包屑地图”，指引读者去寻找针对特定主题的更深入资源。

有人可能会批评这种“宽一英里、深一英寸”的做法，认为它不够深入，但我认为这种看法是错误的。所有书籍都会面临已经超越其内容水平的读者，而用那些不再需要这本书的读者视角来评价它，并不是特别有意义。

定位策略

当你进入写书和出版这个领域后，一个无法回避的约束是：你需要足够宽泛的主题才能支撑较高的销量。从定位角度来看，《Guidebook》几乎是一本完美的书，因为它：

目标读者是职业早期工程师，旨在成为一本可以长期反复查阅的百科全书式参考书。

将这两个理念结合在一起，你就得到了一本既能实现广泛销售，又很可能随着读者职业发展继续留在他们书架上的书。

自我出版

这本书的一个有趣之处在于它是自出版的。这部分是历史偶然——Gergely 最初投稿时影响力还远没有现在这么大，但同时也是经过深思熟虑的决定：以他如今的地位，完全可以毫无限制地让几乎任何出版社出版这本书。

Gergely 以写作谋生，而如果你自己掌握发行渠道，自出版的财务收益是显而易见的。我不确定传统的技术类出版社是否真的能为已经拥有强大发行能力的成熟作者填补这一差距。

出版社对那些没有编辑资源或缺乏书籍结构反馈的新作者能提供很多帮助。对于没有自身发行渠道的作者，出版社也能提供一定价值，尽管我认为实际价值可能比首次出书的作者想象的要少一些。而对于已经拥有强大发行能力、也愿意承担出版运营开销的成熟作者来说……出版社能提供的东西实在不足以抵消财务上的成本。
