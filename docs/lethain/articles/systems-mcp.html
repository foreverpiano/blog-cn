systems-mcp：通过 LLM 生成系统模型

2025-05-11 · 阅读原文

2018 年，我编写了 lethain/systems，这是一种用于编写可运行系统模型的领域特定语言，并通过介绍了一个招聘漏斗的建模案例。虽然它远非完美的系统，但在过去七年的使用中，我从中获得了巨大的价值，因为它让我能够将系统模型置于版本控制之下。用 Systems 库建模招聘漏斗

最近我在尝试编写 Model Context Protocol (MCP) 服务时，经常思考的一个方向就是帮助编写 systems 语法的工具，最终我在 lethain/systems-mcp 这个仓库中将其实现。

更详细的安装和使用说明都在 GitHub 仓库中，这里只分享几张截图和一些感想。首先是 load_systems_documentation 工具，它会将 lethain/systems/README.md 的内容以及一个包含示例系统的文件加载到上下文窗口中。

使用 LLM 正确编写 DSL 最大的挑战在于提供足够多的上下文学习（ICL）示例。我认为，提供专门用于提供这类上下文的工具是一个非常有趣的想法。未来我设想会出现通用的工具，例如为各种 DSL 建立最佳 ICL 示例的搜索索引。在此之前，我认为这类专用工具特别有价值。

第二个工具是 run_systems_model，它将 DSL（以及可选的轮数参数）传递给工具，然后返回运行结果。

我在这个环节对界面设计做了一些实验，最初尝试返回渲染好的结果图表，但最终发现即使是多模态模型，处理文本的能力也远强于图像。因此，最好的做法是返回结果的 JSON，然后让 LLM 构建一个与结果交互的工具。

总的来说，这是一个有趣的小实验，也让我更加确信：当前设计 MCP 最有趣的部分，在于决定在哪里为 LLM 引入或消除复杂度。引入太少，工具就缺乏能力；消除太少，两者的结合就很难有效工作。
