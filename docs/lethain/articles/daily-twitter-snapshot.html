生成 Twitter 搜索结果的每日快照

2022-04-07 · 阅读原文

过去几年里，我养成了一个不太好的习惯：经常打开 Twitter 搜索，看看有没有人提到我的文章。不过除了偶尔点个“赞”之外，我其实并没有拿这些信息做什么。我很喜欢用 Twitter，但这个使用方式纯粹是浪费时间的坏习惯，所以我想试着把它自动化掉。

我首先创建了一个新的 Twitter Developer 账号，然后写了一个简单的脚本、GitHub 仓库，并设置了 GitHub Action，全部放在 lethain/social-context 项目中。

核心部分可以在这里看到：

retrieve.py：调用 Twitter API、解析结果，并将每条结果写入文本文件的脚本。 .github/workflows/scrape.yml：配置 GitHub Action，让这个脚本每天自动运行一次。 如果你进入仓库“Settings” -> “Secrets” -> “Actions”，会看到我添加了一个名为 BEARER_TOKEN 的仓库密钥，这就是 Twitter 颁发的 API Bearer Token。

搜索查询由 retrieve.py 文件的第 9 到 13 行驱动：

WEBSITES = (
    ('lethain.txt', 'lethain.com -from:lethain_bot -RT'),
    ('staffeng.txt', 'staffeng.com -RT'),
    ('infraeng.txt', 'infraeng.dev -RT'),
)

如果你想用自己的搜索词来运行这个工具，只需要把那些元组替换成你要写入的文件名和你想执行的 Twitter 搜索查询即可。

如果你打开其中一个文件，比如 lethain.txt，你会看到类似这样的条目：

author: thebaffledengg
Staff engineer reflects on overwork and expecting better from peers https://t.co/FiebOfkf2k

url: https://lethain.com/hard-to-work-with/
https://twitter.com/thebaffledengg/status/1512083389062418432

整体运行效果很好！有新推文时就会产生一次新的提交，否则什么都不会发生。我把它设置成每天运行一次，因为我想减少查看的频率，但你完全可以让它运行得更频繁。

唯一比较烦人的地方是如何发送有用的通知。目前当有新提交时（也就是出现新的搜索结果时），我会收到邮件通知，但邮件里不包含实际变更的文件内容，所以我还得继续迭代改进一下。
