使用 Javascript 控制 Processing

2008-05-11 · 阅读原文

在之前的一篇文章中，我提到 Processing.js 最吸引人的特性之一，就是能够编写类似 Processing 的代码，但使用 Javascript 而不是 Java 1.3 语法来实现逻辑部分。不过我当时没有给出示例，所以今天早上我决定整理一个简单的例子，就是下面这个。

准备工作

  1. Create a folder to store your files in.
  2. Download [Processing.js][processing.js] into that folder.
  3. In that same folder, create two empty files: test.html and myapp.js.

test.html

接下来，我们需要往 test.html 中填写一些基本通用的代码。

<html>
  <head>
    <title>Processing.js Example, Two</title>
    <script type="text/javascript" src="processing.js"></script>
    <script type="text/javascript" src="myapp.js"></script>
  </head>
  <body onload="draw_myapp();">
    <h1> Processing.js Example, Two </h1>
    <canvas id="myapp" width="150" height="150"></canvas>
  </body>
</html>

除了对 myapp 的引用之外，这是一个基础模板，你可以将其用于其他以 Javascript 作为控制语言的 Processing.js 项目。

myapp.js

剩下要做的就是把一些 Processing 代码翻译成 Javascript。这些内容都将放在 myapp.js 文件中。因为我昨天刚玩过这个例子，所以选择了 Setup and Draw 示例，它能很好地展示整个翻译过程。

首先来看这个程序的 Processing 版本。

void setup() 
{
  size(200, 200);  // Size should be the first statement
  stroke(255);     // Set line drawing color to white
  frameRate(30);
}
float y = 100;
void draw() 
{ 
  background(0);   // Set the background to black
  y = y - 1; 
  if (y < 0) { y = height; } 
  line(0, y, width, y);  
}

由于它充分利用了 Processing 内置的魔法，上面的代码非常简洁。记住这一点，因为我们稍后还会谈到它。在此之前，先看看 myapp.js 的内容，以及我用 Javascript 实现的版本。

function draw_myapp(){
  function setup_processing() {
    var canvas = document.getElementById('myapp');
    return Processing(canvas);
  }
  function setup_myapp(p) {
    p.size(300,300);
    p.stroke(255);
  }
  function draw(p) {
    p.background(0);
    y = y - 1;
    if (y < 0) y = p.height;
    p.line(0, y, p.width, y);
  }
  var y = 100;
  var frameRate = 90;
  var interval = 1000.0 / frameRate;
  // setup and run
  var p = setup_processing();
  setup_myapp(p);
  setInterval(function () { draw(p); }, interval);
}

这里最明显的区别是 Javascript 版本有 22 行，而 Processing 版本只有 14 行。除此之外，Javascript 版本也更为啰嗦。我们一会儿再来看如何改进它，但首先你应该用浏览器打开 test.html，你会看到我们已经成功地把这个示例翻译成了 Javascript。

改进 Javascript 版本

正如我之前简单提到的，Processing 代码特别简洁的原因在于它内部嵌入的一些魔法。在 Processing 中，我们定义了 draw 方法，但并没有在任何地方显式调用它（Processing 已经知道该怎么处理）。我们用 frameRate 定义帧率，但使用该帧率的循环是在幕后自动创建的。Processing 并不执着于保持命名空间的干净，它只是尽量让事情保持简单。

Javascript 版本没有这些魔法，因此会更加啰嗦和杂乱。意识到这一点后，我们需要退一步思考：是想要实现一些方便的魔法，还是坚持使用强大且可预测的方式。就我个人而言，我认为 Processing 的全部魅力正在于它的魔法——让任何人都能轻松写出令人印象深刻的作品——所以我的回答是：“是的，请给我那些魔法把戏。”

让我们看看能做些什么。

首先，我写了一个小型工具库，其中包含了这个示例所需的魔法。

var GLOBAL_PROCESSING;
function set_canvas(id) {
  GLOBAL_PROCESSING = Processing(document.getElementById(id));
}
function size(height, width) { GLOBAL_PROCESSING.size(height, width); }
function stroke(color) { GLOBAL_PROCESSING.stroke(color); }
function background(color) { GLOBAL_PROCESSING.background(color); }
function line(x1, y1, x2, y2) { GLOBAL_PROCESSING.line(x1, y1, x2, y2); }
var draw = function() {}; // stub to replace
function frameRate(rate) {
  var interval = 1000.00 / rate;
  setInterval(draw, interval);
}
function height() { return GLOBAL_PROCESSING.height; }
function width() { return GLOBAL_PROCESSING.width; }

基本上，我们通过彻底滥用全局命名空间，重现了 Processing 魔法的一小部分。如果你能接受这个道德上的问题，那就来看看我们改进后的 Javascript 版本吧：

setup = function() {
  size(300,300);
  stroke(255);
  frameRate(90);
}
draw = function() {
  background(0);
  y = y - 1;
  if (y < 0) y = height();
  line(0, y, width(), y);
}
set_canvas("myapp");
var y = 100;
setup();

代码行数从 22 行减少到了 14 行，现在和原始的 Processing 示例一样长了。实际上，它和原始版本几乎完全相同，这并不能有力地证明“用 Javascript 写草图代码比用老旧的 Java 语法更愉快”这个观点。不过，在更复杂的示例中，我认为 Javascript 的优势会更加明显。

（编者注 5/11 21:43：上面的代码不能直接使用，它实际上需要包裹在一个名为 draw_myapp 的函数中，以便在适当的时候加载。这样会多出两行代码，使 Javascript 版本变成 16 行而不是 14 行。唉。）

结束语

虽然我完全支持将 Javascript 作为控制语言，但我不确定其带来的好处是否值得分散开发者对 Processing 的知识积累，也不确定这些想象中的好处是否值得去编写一个能在 Processing.js 之上提供更具魔法感的接口层。使用这种方式编写的程序无法与 Processing 桌面程序兼容，这无疑是一种损失，但它也并非没有一些补偿性的好处。
