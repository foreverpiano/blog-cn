使用 Nginx 的更梦幻 Dream Server

2007-07-17 · 阅读原文

2009/2/13 本文更新版（基于 Ubuntu Intrepid）可在此查看。

在我之前的配置中，使用 mod_proxy 的方式存在一些问题。流程是这样的：请求进来后先由 Apache 接收，如果是媒体文件，Apache 会将其转发给 Lighttpd，Lighttpd 读取文件后再传回给 Apache，最后由 Apache 发送给客户端。显然，这简直是疯了。

因此我重新整理了配置说明，避免了那些灾难性的脑残操作。本文也进行了精简，所有关于安全的章节已被移除。你可以参考原始文章，但最好寻找更专业的服务器安全资料。

大部分流程没有改变，但现在我们将使用 Nginx 作为前端代理和静态媒体服务器，而 Apache2 配合 mod_python 作为后端来处理 Django 请求。放弃 Lighttpd 改用 Nginx，主要是因为 Nginx 来自俄罗斯，比较有异域风情。

另外，Lighttpd 还有一个烦人的内存泄漏问题。

最终成果

最终成果依然是一台 Ubuntu Feisty 服务器。它将使用 Nginx 作为前端（处理静态媒体，并将其他请求代理给 Apache2），Apache2 作为后端。使用 memcached 进行缓存，Postgres 8.2 作为数据库。Django 是我们选择的开发框架。

接下来进入有趣的部分。

致谢和参考资源可在原始文章中找到。
