在 Django 中限制用户注册

2008-10-12 · 阅读原文

我正在开发一个 Django 应用，它正逐步接近某种形式的发布，但我希望能慢慢提升规模，从少数目标用户开始，然后逐步迭代。我之前对 django-authopenid 印象很深，它支持 OpenID 以及传统的注册和登录功能，我希望继续使用它。于是我坐下来构思了一个巧妙的方案，让我能够在不修改 django-authopenid 内部实现的情况下限制用户注册。

我的方案核心是一个名为 AppInvite 的模型，它可以创建带有使用次数限制的注册邀请码。

如果请求是 GET，则强制用户输入注册码进行验证；如果收到的是 POST 请求，则将其转发给 django_authopenid 的注册视图处理。

restrict_signup 视图存在几个小缺陷：

它统计的是展示空白注册表单的次数，而不是实际创建的用户数量；而且可以通过直接发送 POST 请求而不是 GET 请求来绕过限制。

对我而言，即使少放进来几个用户，或者有少数人绕过系统偷偷进来，我也不太担心，所以这个方案对我来说已经足够了。

最后一块拼图是 restrict_signup.html 模板。

我相信如果能将这个模式抽象出来（并稍作扩展）成为一个可插拔的应用，会很有用，但这需要更多思考如何组织结构。我的想法是：

支持任意的注册邀请码，可选地设置使用次数限制；支持限制每个时间段的注册数量（比如每天 100 个等）；在 settings.py 中增加一个参数，指定当用户提交正确的注册码后，应该使用哪个注册表单视图。对，就是这些。
