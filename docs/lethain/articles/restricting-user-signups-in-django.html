在 Django 中限制用户注册

2008-10-12 · 阅读原文

我正在开发一个 Django 应用，它正逐步接近某种形式的发布，但我希望能够缓慢地逐步开放，从少数目标用户开始，然后逐步迭代。我之前对 django-authopenid 印象深刻，它支持 OpenID 以及传统的注册和登录功能，我希望能继续使用它。于是我坐下来设计了一个巧妙的方案，让我能够在不修改 django-authopenid 内部代码的情况下限制用户注册。

我的方案核心是 AppInvite 模型，它允许创建具有使用次数限制的注册码。

class AppInvite(models.Model):
    password = models.CharField(max_length=10)
    max = models.IntegerField()
    current = models.IntegerField()

然后我修改了项目的 urls.py，来覆盖 django-authopenid 的注册页面：

(r'account/signup/','views.restrict_signup'),
(r'account/',include('django_authopenid.urls')),

正如之前提到的，我不想破坏 django-authopenid 的内部实现，因为这只是针对临时问题的快速修复，而不是一个会长期保留的核心代码。

如果请求是 GET，则强制用户输入注册码进行验证；但如果是 POST 请求，则将其转发给 django_authopenid 的注册视图处理。

restrict_signup 视图存在几个小缺陷：

  1. it counts the number of times it present the blank registration form, as opposed to the actual number of users created.
  2. it could be circumvented by manually sending a POST request instead of a GET request.

对我来说，如果少放进来几个人，或者有少数人绕过系统偷偷进来，我并不太担心，所以这对我而言仍然是一个足够有效的解决方案。

最后一块拼图是 restrict_signup.html 模板。

我相信如果能将这个模式抽象出来（并稍作扩展）成为一个可插拔的应用，会很有用，但这需要更多思考如何构建它。我的想法是：

  1. Support for arbitrary signup codes, that optionally have a limited number of uses.
  2. Support limiting the number of sign ups per time period (100/day, etc).
  3. Have a parameter in settings.py that specifies the view with the registration form for users who send a correct signup code.
  4. Yep.. that's pretty much it.
