在纸质书中使用二维码

2020-09-07 · 阅读原文

《精美的谜题：工程管理之道》中我最喜欢的部分之一，就是我们为每个链接生成的二维码，这是一次让纸质书与数字内容更紧密融合的探索。

当我开始考虑如何把 staffeng.com 做成一本书时，我很想重新实现这个功能，但更重要的是，我想看看这次能否把它推向更接近最初设想的形态。

Cool URIs don’t change

众所周知，Cool URIs don’t change，但这本书出版一年多以来，最大的问题就是 URL 逐渐腐烂变成 404。这让我深刻意识到，使用 URL 短链接服务来间接指向目标链接有多么重要，这样当链接失效时我们还能及时修复。

另一个好处是，二维码的内容越长就越复杂，而更短的链接可以让二维码明显变小。 举例来说，我们为下面三个 URL 生成二维码：

https://lethain.com
https://lethain.com/thisis/a/verylong/url
https://lethain.com/thisis/a/verylong/urlforsomereasonletsjustkeeptyingalothere

从左到右你可以看到对应的二维码，内容越长，二维码的复杂度就越高。

图像复杂度很重要，因为它直接决定了二维码能被印得多小，这又会影响印刷成本，甚至决定是否值得印刷。

那我们就来测试一下图像缩放——在 iPhone 还能正常识别的前提下，二维码到底能做得多小？

假设我们能为书中的每个链接生成一个短链接，且链接总数少于 10,000 个。 那么我们可以用类似下面这个 URL 来推断合适的渲染尺寸。

https://staffeng.com/l/1234

好，我们来看看分别缩放到 1、2、3 和 6 像素时的效果，就能大致了解不同缩放级别（scale 表示二维码中每个模块用多少个像素来绘制）。

即使我把手机贴近高分辨率显示器放大，也无法识别最小的二维码，但第二小的还能稳定扫描。回头看《An Elegant Puzzle》的印刷版，尽管当时的 URL 更长，我们最终采用的应该是三倍缩放。

如果你采用自出版并通过 Kindle Direct Publishing 印刷，他们的印刷精度是 300 DPI，这对这些图像来说应该绰绰有余。

排版格式试验

现在二维码的大小问题解决了，接下来要试验如何使用它们。 特别是，我想尝试把二维码直接嵌入到正文中，让它们紧挨着对应的链接，而不是全部放在书末。 一个折中的方案是把它们集中放在每章末尾，但如果能真正做到行内嵌入，那就更理想了！

虽然稍微有点啰嗦，但把它们嵌入得更紧凑也很有意思。

我觉得这两种方式效果都会不错，关键在于能否把版面排好——这恐怕会很难！后续再看是否真正可行。

这也让我产生了其他很多想法，比如是否应该让每篇博客文章的打印版也采用类似设计？这个实验就留到以后再做了。

生成二维码的代码

我用来生成这些二维码的脚本参考了下面这篇教程：

import argparse
import pyqrcode
import png
from pyqrcode import QRCode


def qr(txt):
    code = pyqrcode.create(txt)
    return code


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("text_string", help="text to format, use quotes if whtiespace")
    parser.add_argument("output_file", help="filename to render output file")
    parser.add_argument("--scale", help="integer representing scale of image", type=int, default=6)
    args = parser.parse_args()
    code = qr(args.text_string)
    code.png(args.output_file, scale=args.scale)

尽管代码非常简单，但实际效果相当不错。
