使用 Django 实现非侵入式 JavaScript 入门

2008-09-21 · 阅读原文

目前已经有很多关于在 Django 中使用 Ajax 的教程。尽管如此，这个主题仍然让很多人感到困惑。我认为根本问题在于，有三类完全不同的开发者在寻找 Django 与 Ajax 结合的教程：

有丰富经验的 Web 开发者，他们使用过大量其他框架（年轻时甚至管理过由信鸽组成的网络），只需要了解几个底层细节；掌握了另一款框架（通常是 Ruby on Rails）的 Web 开发者，他们需要稍高层次的细节来适应 Django 的做事方式与之前经验的差异；缺乏经验的 Web 开发者，他们从未掌握过 Web 框架，对 Python、JavaScript 以及 Ajax 应用中的客户端-服务器交互等高层概念可能理解有限。

通常第一类人群的教程最先被写出来，因为它们往往只需要几段文字和一段代码（而且他们构成了早期采用者的大多数）。随后，针对第二、三类人群但写得较为随意的教程陆续发表，这常常对两类读者都造成了不利影响（并带来挫败感）。

本教程的目标是引导具有一定 Django 知识——但对 Ajax 或 JavaScript 一无所知——的开发者，通过实现一个简单的笔记应用，触及创建 Ajax Web 应用的高层、中层和底层概念。

如果你已经完成过 Django 官方教程，那么你已经准备好开始学习非侵入式 JavaScript 和 Ajax 了。

概述

很多人会告诉你，创建 Ajax Web 应用的第一步是选择一个 JavaScript 库。你应该用 jQuery，还是 Dojo，还是更 Pythonic 的 MochiKit？但是，慢着，慢着。选择 JavaScript 库其实并不是第一步。

实现 Ajax Web 应用的第一步，是先不使用 Ajax 来实现这个 Web 应用。这听起来有些反直觉，所以我们再说一遍：实现 Ajax Web 应用的第一步，是先不使用 Ajax 来实现这个 Web 应用。

这到底是什么意思？

这意味着我们将首先完全不使用任何 JavaScript 来实现整个笔记应用，而是使用传统的 Web 交互工具：表单。

之后，我们再使用 JavaScript 来改进网站，让用户体验更加愉悦。但通过先不使用 JavaScript，我们可以确保网站在 JavaScript 被禁用或使用老旧浏览器的情况下仍能正常运行。

这种将 JavaScript 视为“增值功能”（而非“核心价值”）的理念被称为非侵入式 JavaScript。它如今是一个颇为流行的概念，但这并不意味着它不值得重视；它确实很有价值。

所以，如果第一步是构建不依赖 JavaScript 的网站，那么第二步就是使用 jQuery 来美化它。

我们之所以选择 jQuery，是因为它已成为功能强大且轻量级的 JavaScript 库中的行业领军者。即使你并不特别喜欢 jQuery，本教程所探讨的概念也同样适用于其他 JS 库，你仍然能从中获得有价值的东西。

应用介绍

我们正在构建的 Django 应用叫做 notes，它相当简单：它的首页会显示笔记列表，并允许创建新的笔记。

每篇笔记还会拥有一个详情页，用于查看和编辑笔记内容。

就是这样。尽管如此，使用 Ajax 来美化这个应用仍有相当大的空间。振作起来，这会很有趣。

补充材料：Git 仓库

通常我会在开发应用的同时撰写教程。我在应用中写一行代码，然后在教程中写一行文字。这有助于避免遗漏错误，但也容易引入“意外”错误。我一直在尝试改进自己的教程写作流程，这次我采取了略有不同的方法。

我使用 Git 进行版本控制来编写教程，并且每做一个改动就认真地提交一次（嗯，直到最后 20% 时我自愿放弃了理智），这样你就可以通过仓库的提交历史来跟踪改动，观察程序是如何一步步成长起来的。

事实上，如果你对 Git 比较熟悉，我强烈建议你采用这种方式。通读本教程以获取高层面的理解并浏览代码，然后坐下来研究 Git 仓库，仔细查看每次的改动。

def create_note(request):
error_msg = u"No POST data sent."
if request.method == "POST":
post = request.POST.copy()
if post.has_key('slug') and post.has_key('title'):
slug = post['slug']
if Note.objects.filter(slug=slug).count() > 0:
error_msg = u"Slug already in use."
else:
title = post['title']
new_note = Note.objects.create(title=title,slug=slug)
return HttpResponseRedirect(new_note.get_absolute_url())
else:
error_msg = u"Insufficient POST data (need 'slug' and 'title'!)"
return HttpResponseServerError(error_msg)

def update_note(request, slug):
    if request.method == "POST":
        post = request.POST.copy()
        note = Note.objects.get(slug=slug)
        if post.has_key('slug'):
            slug_str = post['slug']
            if note.slug != slug_str:
                if Note.objects.filter(slug=slug_str).count() > 0:
                    error_msg = u"Slug already taken."
                    return HttpResponseServerError(error_msg)
                note.slug = slug_str
        if post.has_key('title'):
            note.title = post['title']
        if post.has_key('text'):
            note.text = post['text']
        note.save()
        return HttpResponseRedirect(note.get_absolute_url())
    error_msg = u"No POST data sent."
    return HttpResponseServerError(error_msg)

邀请 Ajax 加入派对

既然我们已经有了一个可以工作的应用，是时候开始考虑如何在应用中加入一些动态的 Ajax 功能了。

在我们深入细节之前，我想先简单谈谈 Ajax 的高层概念。简单来说，Ajax 就是使用带外（out-of-band）的异步通信，在不离开当前 URL 的情况下提供功能。

良好地使用 Ajax 可以让你的 Web 应用响应更快。不恰当地使用则可能让你的 Web 应用变成可怕的死亡陷阱。重要的是要确保你使用 Ajax 是因为它确实改进了你的网站，而不是因为……嗯，其实也没有其他理由要使用它。

从 Django 的角度来看，实现 Ajax 意味着编写 JavaScript 来从客户端发送请求，并确保你已经编写了适当的视图来服务这些请求。

这通常意味着创建自定义视图，将相关数据编码为 JSON 并返回给等待的 JavaScript 函数。

然而，在这个例子中我们要采用略微不同的做法。我们已经编写了处理所需功能（创建和编辑笔记）的视图，我们将直接在 JavaScript 中复用它们。

然而……这些视图返回的是 HTML 而不是 JSON，所以我们需要自己从中提取必要的数据。我们将为此使用正则表达式。如果你觉得这有点过于复杂，不用担心，你可以通过编写额外的返回 JSON 格式数据的视图来避免这种正则魔法。
