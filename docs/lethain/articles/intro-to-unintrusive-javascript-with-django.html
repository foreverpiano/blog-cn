使用 Django 实现非侵入式 JavaScript 入门

2008-09-21 · 阅读原文

目前有大量关于在 Django 中使用 Ajax 的教程。尽管如此，这个主题仍然让很多人感到困惑。我认为根本问题在于，有三类截然不同的群体在寻找 Django 与 Ajax 结合使用的教程：

经验丰富的 Web 开发者，他们使用过多种其他框架（年轻时甚至管理过由信鸽组成的网络），只需要了解一些底层细节；掌握了另一种框架（通常是 Ruby on Rails）的 Web 开发者，但需要稍高层次的细节来适应 Django 的做事方式与他们之前经验之间的差异；缺乏经验的 Web 开发者，他们从未掌握过 Web 框架，对 Python、JavaScript 以及 Ajax 应用中的客户端-服务器交互等高级概念可能了解有限。

通常第一类群体的教程会最先被写出来，因为它们往往只需要几段文字加一个代码片段（而且他们构成了早期采用者的大多数）。然后，随着时间推移，针对第二和第三类群体的教程零零散散地发布出来，往往对这两类群体都造成不利影响（并带来挫败感）。

本教程的目标是引导那些具备一定 Django 知识——但对 Ajax 或 JavaScript 一无所知——的人，通过实现一个简单的笔记应用，同时触及创建 Ajax Web 应用的高层、中层和底层概念。

如果你已经完成了 Django 官方教程，那么你已经准备好开始学习非侵入式 JavaScript 和 Ajax 了。

概述

很多人会告诉你，创建 Ajax Web 应用的第一步是选择一个 JavaScript 库。你应该使用 jQuery，还是 Dojo，还是 Pythonic 的 MochiKit？但是，等等，等等。选择 JavaScript 库其实并不是第一步。

实现 Ajax Web 应用的第一步，是在没有 Ajax 的情况下先实现这个 Web 应用。这听起来有点反直觉，所以我们再说一遍：实现 Ajax Web 应用的第一步，是在没有 Ajax 的情况下先实现这个 Web 应用。

这到底是什么意思呢？

这意味着我们将首先完全不使用任何 JavaScript 来实现整个笔记应用，而是使用老派的 Web 交互工具：表单。

之后，我们会使用 JavaScript 来改进网站并提升用户体验，但通过一开始不使用 JavaScript，我们确保网站在 JavaScript 被禁用或使用老旧浏览器的情况下仍能正常工作。

这种将 JavaScript 视为增值功能（而非核心价值）的理念被称为非侵入式 JavaScript（unintrusive JavaScript）。这是当下颇为流行的话题，但这并不意味着它没有价值；它确实很有价值。

所以，如果第一步是构建没有 JavaScript 的网站，那么第二步就是使用 jQuery 来美化它。

我们将使用 jQuery，因为它已成为强大而轻量级的 JavaScript 库中的行业领导者。即使你并不特别喜欢 jQuery，本教程所探讨的概念也适用于其他 JS 库，所以你仍然能从中获得一些价值。

每条笔记还会有一个详情页，允许查看和编辑笔记内容。

就是这样。尽管如此，使用 Ajax 来美化这个应用仍然有很大的空间。打起精神，这会很有趣。

邀请 Ajax 参加派对

现在我们已经有了一个能工作的应用，是时候开始考虑如何在应用中加入一些动态的 Ajax 功能了。

在我们深入细节之前，我想简单介绍一下 Ajax 的高层概念。简单来说，Ajax 是关于使用带外异步通信来提供功能，而无需真正离开你所到达的 URL。

良好地使用 Ajax 可以让你的 Web 应用响应更快。不良的使用则可能让你的 Web 应用变成可怕的死亡陷阱。重要的是要确保你使用 Ajax 是因为它真正改善了你的网站，而不是因为……嗯，其实没有其他理由使用它。

从 Django 的角度来看，实现 Ajax 意味着编写 JavaScript 从客户端发送请求，并确保你已经编写了适当的视图来服务这些请求。

通常这意味着创建自定义视图来将相关数据 JSON 编码并返回给等待的 JavaScript 函数。

然而，在这个例子中，我们要稍微以不同的方式做事。我们已经编写了处理我们所需功能（创建和编辑笔记）的视图，我们只需用我们的 JavaScript 重用它们即可。

然而……这些视图返回的是 HTML 而不是 JSON，所以我们将不得不自己提取必要的数据。我们将为此使用正则表达式。如果你觉得这有点过于复杂，请放心，因为你可以通过简单编写额外的返回必要数据的 JSON 编码视图来避免这种正则魔术。
