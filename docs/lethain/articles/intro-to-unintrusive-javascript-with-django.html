使用 Django 实现非侵入式 JavaScript 入门

2008-09-21 · 阅读原文

目前已经有大量关于在 Django 中使用 Ajax 的教程。尽管如此，这个主题仍然让很多人感到困惑。我认为根本原因在于，有三类完全不同的开发者在寻找关于在 Django 中使用 Ajax 的教程：

有经验的 Web 开发者，他们使用过大量其他框架（年轻时甚至管理过由信鸽组成的网络），只需要了解一些底层细节。掌握了另一种框架（通常是 Ruby on Rails）的 Web 开发者，他们需要稍高层次的细节来适应 Django 的做事方式与之前经验的差异。缺乏经验的 Web 开发者，他们从未掌握过 Web 框架，对 Python、JavaScript 以及 Ajax 应用中客户端-服务器交互的高层概念可能只是一知半解。

通常针对第一类人群的教程会最先被写出来，因为它们往往只需要几段文字加一段代码（而且他们构成了早期采用者的大多数）。然后，随着时间推移，针对第二类和第三类人群的教程零散地出现，往往给这两类人都带来了不便和挫败感。

本教程的目标是引导那些对 Django 有一定了解、但对 Ajax 或 JavaScript 一无所知的人，通过实现一个简单的笔记应用，同时触及创建 Ajax Web 应用的高层、中层和底层概念。

如果你已经完成过 Django 官方教程，那么你已经准备好开始学习非侵入式 JavaScript 和 Ajax 了。

概述

很多人会告诉你，创建 Ajax Web 应用的第一步是挑选一个 JavaScript 库。你应该用 jQuery，还是 Dojo，还是带有 Python 风格的 MochiKit？但是，慢着，慢着。挑选 JavaScript 库其实并不是第一步。

实现 Ajax Web 应用的第一步，是在没有 Ajax 的情况下先实现这个 Web 应用。这听起来有点反直觉，所以我们再说一遍：实现 Ajax Web 应用的第一步，是在没有 Ajax 的情况下先实现这个 Web 应用。

这到底是什么意思呢？

这意味着我们将从完全不使用任何 JavaScript 来实现整个笔记应用开始，而是使用老派 Web 交互工具：表单。

之后，我们会使用 JavaScript 来改进网站，让用户体验更加愉快。但通过先不使用 JavaScript，我们确保网站能在用户禁用 JavaScript 或使用老旧浏览器时仍能正常运行。

将 JavaScript 视为“增值”（而非“核心价值”）的这种理念被称为非侵入式 JavaScript（unintrusive JavaScript）。这是当今比较流行的概念，但这并不意味着它没有价值；它非常值得采用。

所以，如果第一步是构建不依赖 JavaScript 的网站，那么第二步就是使用 jQuery 来让它变得更优雅。

我们将使用 jQuery，因为它已经成为功能强大且轻量级的 JavaScript 库中的行业领导者。即使你并不特别喜欢 jQuery，本教程所探讨的概念也适用于其他 JS 库，所以你仍然能从中获得有价值的东西。

应用介绍

我们正在构建的 Django 应用叫做 notes，它相当简单：它的首页会显示一个笔记列表，并允许创建新的笔记。

每条笔记还会有一个详细页面，允许查看和编辑笔记内容。

就是这样。尽管如此，使用 Ajax 来提升这个应用仍有很大空间。振作起来，这会很有趣。

补充材料：Git 仓库

通常我在写教程的同时也在开发应用。我在应用里写一行代码，然后在教程里写一段文字。这有助于避免遗漏错误，但也会导致因失误而产生的错误。我一直在尝试改进我的教程写作流程，这次我采用了一种略有不同的方法。

我使用 Git 进行版本控制来撰写本教程，并且每做一次修改就认真地提交一次（好吧，直到最后 20% 时我主动放弃了理智），这样你就可以跟着仓库的提交历史，一步步地看到程序是如何逐渐成长起来的。

事实上，如果你对 Git 比较熟悉，我强烈建议你采用这种方式。通读本教程以获取高层概念和粗略浏览代码，然后坐下来仔细研究 Git 仓库，查看每次修改。

即使你对 Git 不是特别熟悉，其实操作起来也相当简单。只要你安装了 Git，请下载这个打包好的 Git 仓库，然后进入该文件夹。

def create_note(request):
error_msg = u"No POST data sent."
if request.method == "POST":
post = request.POST.copy()
if post.has_key('slug') and post.has_key('title'):
slug = post['slug']
if Note.objects.filter(slug=slug).count() > 0:
error_msg = u"Slug already in use."

title = post['title']
new_note = Note.objects.create(title=title,slug=slug)

else:

def update_note(request, slug):
    if request.method == "POST":
        post = request.POST.copy()
        note = Note.objects.get(slug=slug)
        if post.has_key('slug'):
            slug_str = post['slug']
            if note.slug != slug_str:
                if Note.objects.filter(slug=slug_str).count() > 0:
                    error_msg = u"Slug already taken."
                    return HttpResponseServerError(error_msg)
                note.slug = slug_str
        if post.has_key('title'):
            note.title = post['title']
        if post.has_key('text'):
            note.text = post['text']
        note.save()
        return HttpResponseRedirect(note.get_absolute_url())
    error_msg = u"No POST data sent."
    return HttpResponseServerError(error_msg)

邀请 Ajax 加入派对

现在我们已经有了一个可以工作的应用，是时候开始考虑如何为它加入一些动态的 Ajax 功能了。

在深入细节之前，我想先简单介绍一下 Ajax 的高层概念。简单来说，Ajax 就是使用带外的异步通信，在不离开当前页面的情况下提供功能。

正确使用 Ajax 可以让你的 Web 应用响应更快。不当的使用则可能让你的应用变成可怕的灾难。重要的是确保你是因为 Ajax 确实能改善你的网站而使用它，而不是因为……嗯，其实也没有其他理由要用它。

从 Django 的角度来看，实现 Ajax 意味着编写 JavaScript 从客户端发送请求，并确保你已经编写了合适的视图来响应这些请求。

通常这意味着创建自定义视图，将相关数据进行 JSON 编码并返回给等待的 JavaScript 函数。

然而，在这个例子中我们要稍微换一种做法。我们已经编写了处理所需功能（创建和编辑笔记）的视图，现在只需用 JavaScript 复用它们即可。

不过……这些视图返回的是 HTML 而不是 JSON，所以我们得自己从响应中提取所需数据。我们将为此使用正则表达式。如果你觉得这有点过于复杂，不用担心，你可以避免这种“正则魔法”，只需额外编写返回 JSON 格式数据的视图即可。
