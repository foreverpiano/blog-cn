Ambush Code Review 学会了生成代码差异

2008-06-18 · 阅读原文

今天我花了几个小时重新设计了 Ambush Code Review，它变得比最初的版本好多了。主要有两个重要改进：

  1. Its easier to use.
  2. It actually does something interesting.

以前，对代码片段发表回复的操作相当别扭。我自己当然知道怎么用，但不确定别人是否清楚，而且那本来就是一个不太理想的折中方案。现在，只需点击两次按钮，就能用你的修改更新已发布的片段。但真正有趣的新功能是：它现在可以生成同一片段不同版本之间的差异（diff），并将这些差异显示在当前版本的下方。

你可以去看看这张截图对应的代码片段，我觉得这个功能相当有吸引力。因为 ACR 的核心目标就是让大家更容易对代码片段提出改进建议（比如，当有人在 IRC 聊天室里贴出代码求助时，如果能直接给他们展示应该怎么修改，岂不是很好？）。

现在它已经从一个粗糙的“me too”服务，变成稍微有点意思的东西了，我很乐意听到大家的反馈。

实现代码差异功能

下面简单聊聊不同版本间差异的实现过程。事情并没有完全按照预期发展——我以为难的地方其实很简单，而以为简单的地方却比较麻烦。活到老，学到老。

真正简单的部分其实是生成差异本身。Python 标准库中的 difflib 模块把这个任务变得非常轻松。相关代码大致如下（欢迎大家前往改进这段代码，我目前还不太清楚怎么优雅地处理 unified_diff 返回的生成器……）：

from difflib import unified_diff
def set_content(self, new_content):
    'Handles all details of updating snippet content.'
    # if this is not a new Snippet
    if self.rendered != None:
        result = unified_diff(self.content.splitlines(1),
                                     new_content.splitlines(1))
        try:
            txt = reduce(lambda a,b: u"%s%s" % (a,b), result)
            self.add_diff(txt)
        except TypeError:
            pass
    self.content = new_content
    lexer = get_lexer_by_name(find_lexer(self.highlighter))
    self.rendered = highlight(self.content,lexer,HtmlFormatter(linenos='table'))

也就是说，我几乎什么都没做，只是简单调用了一个库函数而已。但后续的事情就变得有点麻烦了。

问题始于 BigTable 中用来描述字段的 db.ListProperty，它需要一个类型参数。当然，没问题。它要求类型必须是特定列表中的一个。好吧，选择有很多，没问题。它还要求列表中的所有元素必须是同一类型。嗯，我只存 diff，所以类型肯定一致，没问题。然后它在你设置 db.Text 属性类型时直接无视，却抱怨说 unicode 类型不能在数据库中存储超过 500 字节的内容。这就成了问题。

最后，我用一些老派 ingenuity 和新派对后果的“无知”，拼凑出了自己的列表方案。方法是……用 simplejson 进行序列化和反序列化。

from django.utils import simplejson
def add_diff(self, diff):
    if self.diffs == None:
        diffs = []
    else:
        diffs = simplejson.loads(self.diffs)
    diffs.insert(0, diff)
    self.diffs = simplejson.dumps(diffs)
def get_diffs(self):
'Unserializes and returns the contents of self.diffs'
return simplejson.loads(self.diffs)

我不会说这是一个绝妙或优秀的方案，但它是一个足够好的方案，而这似乎正是 Web 应用最终都会走向的状态。对数据库的访问被最小化，而 CPU 几乎从来不是 Web 开发的瓶颈。你可能会问为什么我选择 simplejson 而不是 pickle，答案其实很简单：simplejson 用起来非常方便，省去了我必须用 StringIO 来模拟文件让 pickle 进行序列化和反序列化的麻烦。

希望这个代码实现解析还算有点意思，如果有任何问题，欢迎告诉我。
