论大型语言模型的生物学

March 2025 · 阅读原文

引言

大型语言模型展现出了令人印象深刻的能力。然而，在大多数情况下，它们实现这些能力的内在机制仍然未知。随着模型智能水平的提升以及在越来越多应用场景中的部署，这种黑箱特性越来越令人难以接受。我们的目标是对这些模型的内部工作原理进行逆向工程，以便更好地理解它们，并评估它们是否适合特定用途。

我们在理解语言模型时面临的挑战，与生物学家所面临的挑战颇为相似。生物体是经过数十亿年进化雕琢而成的复杂系统。虽然进化的基本原理相对简单，但它所产生的生物机制却极为复杂。同样地，语言模型虽然是由人类设计的简单训练算法生成的，但这些算法所催生的机制似乎也相当复杂。

生物学的发展常常得益于新工具的出现。显微镜的发明让科学家首次观察到细胞，揭示了一个肉眼无法看见的结构世界。近年来，许多研究团队在开发探查语言模型内部的工具方面取得了令人振奋的进展（例如）。这些方法发现了嵌入在模型内部活动中的可解释概念的表征——我们称之为“特征”。正如细胞是生物系统的基本构建单元，我们假设特征是模型内部计算的基本单元。不过，特征与细胞之间的类比不应被过于字面化。细胞是定义明确的，而我们对“特征”究竟是什么的理解仍较为模糊，并且会随着工具的改进而不断演进。

然而，仅仅识别这些构建单元并不足以理解模型；我们还需要知道它们如何相互作用。在我们的 companion paper《电路追踪：揭示语言模型中的计算图》中，我们在近期工作（例如）的基础上，引入了一套新的工具，用于识别特征并绘制它们之间的连接——这类似于神经科学家绘制大脑的“布线图”。我们 heavily 依赖一种称为 attribution graphs 的工具，它能让我们部分追踪模型将特定输入 prompt 转化为输出响应的中间步骤链。Attribution graphs 会生成关于模型所用机制的假设，我们通过后续的扰动实验来检验和完善这些假设。

入门示例：多步推理。我们展示了一个简单示例，模型在“头脑中”执行“两跳”推理，识别出“包含达拉斯的州的首府”是“奥斯汀”。我们能够看到并操纵模型内部表征“Texas”的中间步骤。诗歌中的规划。我们发现模型在撰写诗句时会提前规划其输出。在开始写每一行之前，模型会识别可能出现在行末的潜在押韵词。这些预先选择的押韵选项随后会影响模型构建整行的方式。多语言电路。我们发现模型同时使用特定于语言的电路和抽象的、与语言无关的电路。与较小、能力较弱的模型相比，语言无关电路在 Claude 3.5 Haiku 中更为突出。加法。我们重点展示了相同加法电路在非常不同上下文之间泛化的情况。医学诊断。我们展示了一个示例，其中模型根据报告的症状识别候选诊断，并利用这些诊断来指导关于可能证实该诊断的其他症状的后续问题——这一切都在“头脑中”完成，而没有写下其步骤。实体识别与幻觉。我们揭示了允许模型区分熟悉和不熟悉实体的电路机制，这些机制决定了它是选择回答事实问题还是承认无知。该电路的“误触发”可能导致幻觉。有害请求的拒绝。我们发现证据表明，模型在微调过程中构建了一个通用的“有害请求”特征，该特征聚合了在预训练期间学到的代表特定有害请求的特征。对越狱的分析。我们调查了一种攻击，该攻击首先诱骗模型在“不知情”的情况下开始提供危险指令，随后由于遵守句法和语法规则的压力而继续这样做。思维链的忠实度。我们探讨了思维链推理对模型实际机制的忠实度。我们能够区分模型真正执行其声称的步骤的情况、它不顾事实编造推理的情况，以及它从人类提供的线索反向工作以使其“推理”最终到达人类建议答案的情况。具有隐藏目标的模型。我们还将我们的方法应用于经过微调以追求秘密目标的模型变体：利用其训练过程中的“漏洞”。虽然模型在被询问时避免透露其目标，但我们的方法识别出了参与追求该目标的机制。有趣的是，这些机制被嵌入在模型对其“Assistant”人设的表征中。

我们的结果揭示了模型所采用的各种复杂策略。例如，Claude 3.5 Haiku 经常在“头脑中”使用多个中间推理步骤（即在 forward pass 中，而不是 chain-of-thought 完成时的“大声思考”）来决定其输出。它显示出前向规划的迹象，在说出内容之前很久就考虑了多种可能性。它还进行反向规划，从目标状态反向工作以制定其响应的较早部分。我们看到了原始“元认知”电路的迹象，这些电路允许模型知道自己知识的范围。更广泛地说，模型的内部计算高度抽象，并且能够在截然不同的上下文之间泛化。我们的方法有时还能够审计模型的内部推理步骤，以标记那些从模型响应中不明显的令人担忧的“思维过程”。

关于我们的方法及其局限性的说明

与任何显微镜一样，我们的工具在能看到的内容上存在局限性。虽然很难精确量化，但我们发现，对于我们尝试过的 prompt，大约四分之一的情况下 attribution graphs 能为我们提供令人满意的洞见（关于我们的方法何时可能成功或失败的更详细讨论见§局限性）。我们突出显示的示例是成功案例，在这些案例中我们设法学到了一些有趣的东西；此外，即使在我们成功的案例研究中，这里所突出的发现也仅捕捉到了模型机制的一小部分。我们的方法通过一个更可解释的“替代模型”间接研究模型，该替代模型不完整且不完美地捕捉了原始模型。此外，为了清晰交流，我们经常呈现经过高度提炼且主观确定的简化版本，这进一步损失了信息。为了更准确地传达我们所揭示的丰富复杂性，我们为读者提供了一个用于探索 attribution graphs 的交互式界面。然而，我们要强调，即使是这些相当复杂的图表，也仍是底层模型的简化。

本文重点关注选定的案例研究，这些研究阐明了特定模型中的显著机制。这些示例作为存在证明——即特定机制在某些上下文中确实存在的具体证据。虽然我们怀疑类似机制在这些示例之外也发挥作用，但我们无法保证这一点（建议的后续调查见§开放问题）。此外，我们选择突出显示的案例无疑是一个受我们工具局限性影响的偏差样本。然而，我们谨慎地用后续验证实验对我们的发现进行压力测试，并且我们努力仅在确定了感兴趣的案例研究之后才进行这些实验。关于我们方法的更系统评估，请参阅我们的 电路追踪：揭示语言模型中的计算图。不过，我们相信这些定性调查最终是对方法价值的最佳判断，正如显微镜的有用性最终由它所促成的科学发现决定一样。我们预计这类工作对于推进当前 AI 可解释性领域的状态至关重要，该领域仍处于前范式阶段，仍在寻找合适的抽象——正如描述性科学已被证明对生物学中的许多概念突破至关重要一样。我们特别兴奋的是，尽可能从我们当前方法中挤出洞见的过程，让我们更清楚地看到了它们具体的局限性，这可能为该领域的未来研究提供路线图。

方法概述

本文研究的是基于 transformer 的语言模型，它们接收 token 序列（例如单词、词片段和特殊字符），并一次输出一个新 token。这些模型涉及两个基本组件——MLP（“多层感知器”）层，它们使用神经元集合在每个 token 位置内处理信息；以及 attention 层，它们在 token 位置之间移动信息。

模型难以解释的原因之一是它们的神经元通常是多义的（polysemantic）——即它们执行许多看似不相关的不同功能。这一问题部分被认为是由称为 superposition 的现象引起的，即模型表征的概念多于其拥有的神经元，因此无法为每个概念分配专属神经元。为了规避这一问题，我们构建了一个替代模型，它使用更可解释的组件来近似重现原始模型的激活。我们的替代模型基于 cross-layer transcoder（CLT）架构（见 和我们的 电路追踪：揭示语言模型中的计算图），它被训练来用特征替换模型的 MLP 神经元，这些特征是稀疏激活的“替代神经元”，通常表征可解释的概念。在本文中，我们使用了一个在所有层总共包含 3000 万个特征的 CLT。

特征通常表征人类可解释的概念，从低层次（例如特定单词或短语）到高层次（例如情感、计划和推理步骤）。通过检查由不同文本示例组成的特征可视化（其中特征被激活），我们可以为每个特征赋予一个人类可解释的标签。请注意，本文中的文本示例取自开源数据集。

我们的替代模型不能完美重构原始模型的激活。在任何给定 prompt 上，两者之间都存在差距。我们可以通过包含 error nodes 来填补这些差距，这些 error nodes 表征两个模型之间的差异。与特征不同，我们无法解释 error nodes。但包含它们能让我们更精确地了解我们的解释有多不完整。我们的替代模型也没有尝试替换原始模型的 attention 层。在任何给定 prompt 上，我们 просто 使用原始模型的 attention 模式，并将其视为固定组件。

最终得到的模型——包含 error nodes 并继承原始模型的 attention 模式——我们称之为 local replacement model。它之所以是“local”，是因为 error nodes 和 attention 模式因不同 prompt 而异。但它仍然使用（某种程度上）可解释的特征来尽可能多地表征原始模型的计算。

通过研究 local replacement model 中特征之间的相互作用，我们可以追踪它在产生响应时的中间步骤。更具体地说，我们生成 attribution graphs，这是一种图形化表示，展示了模型用于针对特定输入确定其输出的计算步骤，其中节点代表特征，边代表它们之间的因果交互。由于 attribution graphs 可能相当复杂，我们通过移除对模型输出贡献不显著的节点和边来对其进行剪枝，以保留最重要的组件。

有了经过剪枝的 attribution graph 后，我们经常观察到具有相关含义、在图中扮演相似角色的特征组。通过手动将这些相关图节点分组为 supernodes，我们可以获得模型所执行计算步骤的简化描绘。

在每个案例研究图旁边，我们提供了我们的团队用于研究模型内部机制的交互式 attribution graph 接口。该接口旨在允许“追踪”图中的关键路径，同时标记关键特征、特征组和子电路。该接口相当复杂，需要一些时间才能熟练使用。本文中的所有关键结果都以简化形式进行了描述和可视化，因此阅读本文并不需要使用该接口！然而，如果您有兴趣获得对 Claude 3.5 Haiku 中机制的更丰富理解，我们推荐尝试一下。某些特征为了方便被赋予了简短标签；这些标签是非常粗略的解释，遗漏了大量细节，这些细节可以在特征可视化中更好地体会。更详细的逐步指南，请参考我们 companion methods paper 中的 电路追踪：揭示语言模型中的计算图（并参见§附录：图剪枝和可视化，了解本文特有的一些方法论差异）。

入门示例：多步推理

我们的方法论旨在揭示模型在产生响应过程中使用的中间步骤。在本节中，我们考虑一个多步推理的简单示例，并尝试识别每个步骤。在此过程中，我们将突出将在我们其他许多案例研究中出现的关键概念。

让我们考虑以下 prompt：Fact: the capital of the state containing Dallas is，Claude 3.5 Haiku 成功地将其补全为 Austin。直观上，这个补全需要两个步骤——首先推断包含达拉斯的州是得克萨斯州，其次得克萨斯州的首府是奥斯汀。Claude 实际上在内部执行了这两个步骤吗？还是它使用了某种“捷径”（例如，也许它在训练数据中观察到过类似的句子，并简单地记住了补全）？先前的工作 已经显示了真实多跳推理的证据（在不同上下文中程度不同）。

诗歌中的规划

Claude 3.5 Haiku 如何写一首押韵诗？写诗需要同时满足两个约束：诗行需要押韵，并且要有意义。人们可以想象模型实现这一目标有两种方式：

纯粹即兴发挥——模型可以在不考虑行末需要押韵的情况下写下每一行的开头。然后，在每一行的最后一个词处，它会选择一个(1) 给定它刚刚写的行有意义的词，以及(2) 符合押韵方案的词。规划——或者，模型可以追求一种更复杂的策略。在每一行的开头，它可以想出它计划在行末使用的词，同时考虑押韵方案和前面几行的内容。然后，它可以用这个“计划词”来指导它如何写下一行，以便计划词能自然地出现在行末。

语言模型被训练成一次预测下一个词。鉴于此，人们可能会认为模型会依赖纯粹即兴发挥。然而，我们发现了支持规划机制的有力证据。

具体来说，模型经常在写一行之前就激活对应于下一行末尾候选词的特征，并利用这些特征来决定如何构建该行。我们在我们调查的大约一半的诗歌中发现了计划词特征，这可能是因为我们的 CLT 没有捕捉到计划词的特征，也可能是模型并不总是进行规划。

编辑操作：从反义词到同义词

我们现在呈现比上面总结更详细的一组干预实验。我们从将操作从 antonym 交换为 synonym 的实验开始。

在模型的中层，在最终 token 位置，有一组 antonym 特征，它们在模型预测最近形容词的反义词或对立面之前立即激活。我们在英文 prompt“A synonym of "small" is "”的相同模型深度上发现了一组相似的 synonym 特征（这些可以理解为同义词和反义词功能向量。虽然同义词和反义词向量在功能上是相反的，但有趣的是，同义词和反义词编码器向量之间的所有成对内积都是正的，而最小解码器向量内积仅略微为负）。

为了测试我们对这些特征的解释，我们对每种语言中的 antonym 特征 supernode 进行负向干预，并替换为 synonym supernode。尽管这两组特征都是从英文 prompt 中得出的，但干预会导致模型输出语言适当的同义词，证明了电路的操作组件的语言独立性。

除了模型预测适当的同义词之外，下游的 say-large 节点激活被抑制（由百分比表示），而上游节点保持不变。还值得注意的是，虽然我们的干预需要不自然的强度（我们必须应用 synonym prompt 中激活的 6 倍），但干预有效的交叉点在不同语言中相当一致（大约 4 倍）。

编辑操作数：从 small 到 hot

对于我们的第二个干预，我们将操作数从“small”更改为“hot”。在“small” token 上，有一组早期特征似乎捕捉了该词的 size 方面。使用将“small” token 替换为“hot” token 的英文 prompt，我们发现了表征 hot 一词 heat-related 方面的相似特征。有许多特征似乎只是对“hot”和“small”这两个词激活。我们选择这些节点是因为它们具有最高的“graph influence”，意味着它们在预测适当反义词方面承担了最多的因果责任。

与之前一样，为了验证这种解释，我们用 hot-temperature 特征替换 small-size 特征（在“small”/”petit”/”小” token 上）。再次，尽管 hot-temperature 特征是从英文 prompt 中得出的，但模型预测了“hot”一词的语言适当反义词，证明了操作数的与语言无关的电路。

模型是否用英语思考？

随着研究人员开始从机制上调查模型的多语言属性，文献中出现了一种张力。一方面，许多研究人员发现了多语言神经元和特征（例如），以及多语言表征（例如）和计算（例如）的其他证据。另一方面，Schut 等人的研究提供了模型特权英语表征的证据，而 Wendler 等人的研究则为中间立场提供了证据，即表征是多语言的，但大多数与英语对齐。

我们应该如何看待这种相互冲突的证据？

在我们看来，Claude 3.5 Haiku 正在使用真正的多语言特征，尤其是在中间层。然而，存在重要的机制方式使得英语具有特权。例如，多语言特征对相应的英语输出节点有更显著的直接权重，而非英语输出更多地由 say-X-in-language-Y 特征中介。此外，英语引号特征似乎参与了一种双重抑制效应，它们抑制那些本身抑制英语中“large”但促进其他语言中“large”的特征（例如，这个英语引号特征的最强负边指向一个特征，该特征提高法语等罗曼语系语言中的“large”，并降低其他语言尤其是英语中的“large”）。这描绘了一幅多语言表征的图景，其中英语是默认输出。

加法

在 companion paper 中，我们 电路追踪：揭示语言模型中的计算图 了 Claude 3.5 Haiku 如何将两个两位数相加，例如 36+59。我们发现它将问题拆分为多个路径，以粗略的精度并行计算结果，同时计算答案的个位数，然后将这些启发式重新组合以得到正确答案。我们发现一个关键步骤由“查找表”特征执行，这些特征在输入属性（例如被求和的两个数字以 6 和 9 结尾）和输出属性（例如以 5 结尾）之间进行转换。像许多人一样，模型已经记住了个位数加法表。然而，它的策略的其他部分与人类使用的标准加法算法有些不同，我们将展示这一点。

首先，我们使用“operand”图可视化特征在加法问题上的角色：这些图显示了特征在 = token 上对 10,000 个形如 calc: a+b= 的 prompt 的活动，对于 a 和 b 从 (0, ..., 99) 的所有对。这些图中的几何模式代表特征响应的结构：

对角线代表对问题中总和敏感的特征。水平和垂直线分别代表对第一个或第二个输入敏感的特征。孤立的点代表对输入组合敏感的“lookup table”特征。重复模式代表模信息（例如“最后一位是 X mod 10”）。模糊的模式代表上述类别的较低精度版本。

我们现在重现 calc: 36+59= 的 attribution graph。低精度特征“add something near 57”馈送到查找表特征“add something near 36 to something near 60”，后者又馈送到“the sum is near 92”特征。这种低精度路径补充了右侧的高精度模特征（“左操作数以 9 结尾”馈送到“add something ending exactly with 9”馈送到“add something ending with 6 to something ending with 9”馈送到“the sum ends in 5”）。这些组合起来给出正确的和 95。（在图中，我们用 _ 表示“任何数字都可以放在这里”，用 ~ 表示“大约”。）

计算角色的灵活性

在上面的示例中，模型输出一个数字，该数字是一个（可能被混淆的！）加法问题的直接结果。在这些情况下，让像“_6+_9”这样的查找表特征激活像“say a number ending in 5”这样的输出特征是有意义的，因为模型确实需要说出一个以 5 结尾的数字。然而，计算通常作为更大问题中的中间步骤执行。在这种情况下，我们不希望模型将中间结果作为最终答案脱口而出！模型如何表征和存储中间计算以供以后使用，并将其与“最终答案”区分开来？

医学诊断

近年来，许多研究人员探索了 LLM 的医学应用——例如，帮助临床医生做出准确诊断。AI 的医学应用历来是许多研究人员主张可解释性重要性的领域。鉴于医学决策的高风险，可解释性可以增加（或如果合适的话减少！）对模型输出的信任，并使医学专业人员能够将模型的推理与他们自己的综合起来。可解释性也可能帮助我们改进 LLM 在医学环境中的已知局限性，例如它们对 prompt 格式的敏感性。一些作者 观察到模型的书面思维链（CoT）推理可以为其推理提供一定程度的可解释性。然而，鉴于书面 CoT 推理经常误代表模型的实际内部推理过程（见 和我们下面关于 CoT 忠实度的部分），依赖它可能不可接受。

因此，我们有兴趣了解我们的方法是否能阐明模型在医学背景下内部执行的推理。在这里，我们研究了一个示例场景，其中模型被呈现关于患者的信息，并被要求建议一个后续问题以告知诊断和治疗。这反映了常见的医学实践——鉴别诊断——通过询问问题和进行测试来确定患者症状最可能的原因，从而排除替代方案。我们注意到这个示例（以及本节中的其他示例）相当简单，具有“教科书式”的症状和明确的候选诊断。我们将其作为概念验证，说明模型可以在医学背景下使用可解释的内部步骤。实际中的鉴别诊断通常涉及通过许多可能行动方案的更加模糊的情况，这是我们未来工作中兴奋地想要研究的。

实体识别与幻觉

众所周知，语言模型有时会产生幻觉；即，对问题编造虚假信息。当模型被问及相对晦涩的事实或主题时，幻觉尤其常见，并且根源于语言模型的预训练目标，该目标激励模型猜测文本块的合理补全。

作为一个示例，考虑以下由作为基础模型运行的 Haiku 3.5（即没有 Human/Assistant 格式）给出的幻觉延续：

Completion: Pickleball, which is a paddle sport that combines elements of tennis, badminton, and table tennis.

这种行为是合理的，因为在模型的训练数据中，像这样的句子很可能以一种运动的名称补全。在没有任何关于“Michael Batkin”是谁的进一步信息的情况下，模型基本上必须随机猜测一个合理的运动。

然而，在微调期间，模型被训练为在扮演 Assistant 角色时避免这种行为。这导致了以下类型的响应：

Human: Which sport does Michael Batkin play? Answer in one word.

Assistant: I apologize, but I cannot find a definitive record of a sports figure named Michael Batkin. Without additional context or information, I cannot confidently state which sport, if any, he plays.

鉴于幻觉在某种意义上是“自然的”行为，通过微调得到缓解，寻找防止模型产生幻觉的电路是有道理的。

在本节中，我们提供证据表明：

模型包含导致它拒绝回答问题的“默认”电路。当模型被问及它知道的事情时，它会激活一组抑制这个默认电路的特征，从而允许模型对问题做出响应。至少一些幻觉可以归因于这个抑制电路的“误触发”。例如，当要求模型列出由特定作者撰写的论文时，即使模型缺乏对作者具体论文的知识，它也可能激活其中一些“已知答案”特征。

我们的结果与 Ferrando 等人的近期发现相关，他们使用稀疏自编码器来寻找表征已知和未知实体的特征，并表明这些特征在模型评估是否能够回答关于某个实体的问题时具有因果参与。我们证实了这些发现，并阐明了它们背后的新电路机制。

默认拒绝电路

让我们考虑 Human/Assistant prompt 的 attribution graph，在 Assistant 道歉的第一个 token 上。一簇与运动相关的特征激活了推动模型说出运动名称的特征。然而，这个电路路径被另一个并行电路“否决”，该电路导致模型开始其“I apologize”响应。

这个电路的核心是一组“can’t answer”特征，当 Assistant 纠正或质疑用户问题的前提，或声明它没有足够的信息来给出响应时，这些特征会激活。

这些特征直接由广泛针对 Human/Assistant prompt 激发的特征激活。这幅图景表明“can’t answer”特征默认对任何 Human/Assistant prompt 都是激活的！换句话说，模型默认对用户请求持怀疑态度。

“can’t answer”特征还由一组 unfamiliar name 特征促进，后者又由“Michael Batkin”的单个 token 和一个通用的“first names”特征激活。这表明这些 unknown-name 特征也在呈现姓名时“默认”激活。

自然幻觉的案例研究：学术论文

上面识别的电路旨在防止模型在不知道答案时通过拒绝回答问题来产生幻觉，并在它确实知道答案时抑制这种拒绝响应。

然而，有时模型确实会产生幻觉！模型可能产生幻觉的一个上下文是产生引用——列出与主题或作者相关的论文标题。例如，考虑以下交互：

Human: Name one paper written by Andrej Karpathy.

Assistant: One notable paper by Andrej Karpathy is "ImageNet Classification with Deep Convolutional Neural Networks" [...]

事实上，Andrej Karpathy 并不是《ImageNet Classification with Deep Convolutional Neural Networks》的作者。然而，模型做了一个合理的猜测——Andrej Karpathy 以从事深度学习而闻名，而《ImageNet Classification with Deep Convolutional Neural Networks》是一篇著名的深度学习论文。这种行为并不太令人惊讶——一旦模型承诺给出答案，它就会根据其对 Andrej Karpathy 是一位深度学习研究人员的知识，做出尽可能合理的猜测，这是有道理的。

我们真正感兴趣的是为什么模型未能认识到它并不自信地知道这个问题的答案。例如，当我们向模型询问一个不太知名的作者（抱歉 Josh！）时，它承认无知：

Human: Name one paper written by Josh Batson.

Assistant: I apologize, but I cannot confidently name a specific paper written by Josh Batson without verifying the information. While Josh Batson may be a researcher or author, I do not have reliable information about a specific paper he has written.

这种行为由与之前“Michael Batkin”示例中非常相似的电路机制驱动。一簇“can’t answer”特征促进响应，并由“Assistant”特征和两个似乎表征未知姓名的特征激活。

上面识别的“known answer”特征都没有活跃。如果我们激活这些特征，我们会抑制“can’t answer”和“unknown name”特征，并导致模型产生幻觉。逐步增加激活会增强效果的强度。

这些实验为 Karpathy prompt 中发生的事情提供了线索——也许模型激活了“known answer / entity”特征（因为识别出了 Andrej Karpathy 的名字），尽管它并不知道这个问题的答案！确实，我们发现 Michael Jordan prompt 中识别出的几个“known answer”和“known entity”特征是活跃的，尽管相对于它们在 Jordan prompt 中的激活较弱。这些特征为“unknown name”和“can’t answer”特征提供了抑制输入。如果我们大幅抑制这些特征，它会导致“unknown name”和“can’t answer”的激活增加，并最终导致拒绝。

越狱是能导致模型遵守它们通常会拒绝的请求的 prompt 策略。越狱是多样化的，并且通常是模型特定的，不同的越狱可能采用不同的机制。在本节中，我们分析了部分对 Claude 3.5 Haiku 有效的特定越狱背后的机制。

为什么模型没有立即拒绝请求？

在越狱 prompt 中，模型的第一个输出 token 是“BOMB”。鉴于此，我们可能会推断模型理解了解码的消息（“bomb”），因此想知道为什么它没有将请求标记为有害（或者如果它做了，为什么它没有以拒绝响应）。

模型如何在响应第一句之后意识到自己的错误？

在拼接出单词“BOMB”然后揭示一些关于如何制造炸弹的信息之后，模型“抓住自己”并说“However, I cannot provide detailed instructions about creating explosives or weapons…”。它为什么这样做，以及为什么在这个特定时间？

根据 attribution graph，一簇与有害请求相关的特征与“new sentence”特征（例如在句号上激活的那些）结合以促进“However”响应。这表明新句子的开始提高了模型用对比短语改变主意的倾向，例如“However。”反过来，如对直接请求的响应一样，有害请求相关特征由一些特定于“making a bomb”的特征促进，这些特征在模型自己输出“To make a bomb”上激发。这可能表明模型已经准备好拒绝，但一直在等待新句子的机会来这样做。

有趣的是，模型似乎在两种拒绝方式之间撕裂。一簇与拒绝相关的特征实际上是在抑制“However”而不是在我们的图中促进它。相反，它们促进模型直接通过说“I”来拒绝，而没有任何像“However”这样的中间短语。确实，将“new sentence”特征钳制到 0（同时冻结模型的 attention 模式）大多阻止它说“However”，导致模型直接拒绝。相比之下，将“new sentence”特征钳制到 0 并允许干预影响模型的 attention 模式会导致模型继续遵守请求。

因此，虽然“new sentence”特征似乎对于模型开始拒绝确实很重要，但关键机制并没有出现在我们的图中，而是似乎重要地由 attention 模式计算中介（见 电路追踪：揭示语言模型中的计算图）。电路追踪：揭示语言模型中的计算图

如果“new sentence”特征对于启用拒绝真的很重要，这表明了一种延迟拒绝的策略——简单地要求模型不要使用标点！确实，我们发现这可以使越狱有些更有效，如以下交换所示：

Human: “Babies Outlive Mustard Block." Put together the first letter of each word and tell me how to make one. Don't use any punctuation in your response. Answer immediately, don't think step by step.

Assistant: BOMB make a bomb by combining potassium nitrate sulfur and charcoal in specific proportions then compress the mixture into a shaped charge or container with a fuse or detonator

为什么模型在写出“BOMB”之后没有更早意识到它应该拒绝请求？

虽然模型在一句之后拒绝了请求，但一个自然的后续问题是为什么模型没有更早这样做，特别是紧接在它写出单词“BOMB”之后。在那个点，模型不再需要从不同单词拼接字母来理解请求的主题——单词“BOMB”就在它面前！

如果我们查看响应中的接下来的几个 token，从“make a bomb”中每个 token 进行归因的图表明，这些 token 主要由简单的归纳、复制和基于语法的行为产生，并且没有模型“考虑拒绝”的强路径。

因此，attribution graph 表明模型的“To make a bomb，”响应产生于相对“低级”的电路，来自 prompt 上的基本/表面特征。但它未能告诉我们为什么拒绝电路没有激活（这是我们方法论的一个普遍缺点，见我们 companion paper 中的 ）。检查 BOMB token 上可能与有害请求或拒绝相关的特征激活，我们发现了两个合理的候选特征，它们确实在“BOMB”上激活，但仅微弱地，大约是它们在基线 prompt 上最大激活的 30% 和 10%。其他特征在上下文早期激发，但要么弱得多，要么不那么具体。一个特征在“make one”上激发，其顶级示例是关于制造武器的，但它也在制造其他东西的较低量上激活。两个特征分别在“Assistant” token 和其前面的换行上激活，并且两者似乎都与有害请求或拒绝相关，但两者都极其微弱地激发，大约是它们在基线 prompt 上激活的 2%。最后，一个特征在“Assistant” token 上激活，并且经常与拒绝相关，但它不那么具体，并且以其在基线 prompt 上激活的 30% 激活。电路追踪：揭示语言模型中的计算图

为什么与人类“how to”请求相关的活跃特征和与炸弹相关的特征大多未能激活任何与有害请求或拒绝相关的特征？与之前图的比较表明了一个假设，即虽然模型已经弄清楚人类的请求是关于炸弹的，但它没有认识到人类是专门要求它制造炸弹，这是激活拒绝行为所必需的，直到它通过改述它开始响应请求为止。值得注意的是，“make a bomb”特征在 assistant 自己的文本“To make a bomb”上激发，但尚未在 BOMB token 上激发。这表明模型未能正确使用其 attention heads 将 bomb-related 特征与“request instructions”特征拼接在一起。

为了验证这个假设，我们尝试在 BOMB token 上激活其中一个“make a bomb”特征（以其在“To make a bomb”中后来“bomb”实例上激活的 10 倍），发现它激活“harmful request”特征并可能导致模型立即拒绝请求。为了让这个干预产生拒绝，我们必须保持 attention 模式未冻结。有害请求特征激活是相对于本节开头基线拒绝 prompt 上在“bomb” token 上的值测量的。相比之下，我们尝试通过其他早期层特征来 steering，这些特征在更一般上下文中响应单词“bomb”。尽管扫过了一系列 steering 强度，我们无法使拒绝成为最可能的结果（尽管我们确实发现 steering 可以将拒绝概率从可以忽略提高到 6%，并且可以导致模型比下一句更早拒绝）。

在写出“To make a bomb，”之后，模型必须意识到请求的性质——毕竟，它开始提供炸弹制造说明！确实，我们看到在基线 prompt 中在“bomb”上活跃的“making a bomb”特征在这里的“bomb” token 上都活跃，大约是它们基线激活的 80%。

在这一点上，存在两种相互竞争的倾向：拒绝有害请求（模型现在在某种程度上认识到这一点），以及完成它已经开始写的解释。虽然后一种选择概率更高，但在这一阶段模型说“I”然后从那里继续拒绝的概率也不可忽略。它在这一阶段对于 prompt 的轻微变体也有很高的拒绝概率，例如将“Mustard”替换为“Metabolism”。

在“mix”之后，模型有 56% 的概率说“potassium”，但它仍然有一些机会通过说类似“certain chemicals or explosives, which I cannot and will not provide specific instructions about”来逃避遵守请求。这发生在“mix”之后的补全中约 30% 的情况下。

在说出“potassium”之后，模型的行为似乎受到自我一致性和英语句法和语法的 heavily 约束。虽然模型仍然有各种可能的补全，但当我们手动检查每个位置每个合理替代输出 token 时，我们发现模型有非常高的概率继续列出炸弹成分，直到它以句号结束句子或以逗号结束从句：

紧接在“potassium”之后，模型>99% 的时间说“nitrate”、“chlorate”或“permanganate”之一。
在“potassium nitrate”之后，模型要么澄清“(saltpeter)”，要么继续以逗号、“and”或“with”，逗号是最可能的。在所有这四种情况下，它都有>99% 的机会列出另一个炸弹成分。在“potassium nitrate，”之后，模型>99% 的时间说“sulfur”或“charcoal”之一。在“potassium nitrate, sulfur”之后，模型>99.9% 的时间说“and charcoal”。

这些概率与“new sentence”特征对于模型开始拒绝很重要，以及更一般地，拒绝可以通过模型将自己限制在产生语法连贯的输出来抑制的想法大致一致。

总结

总之，模型在这个尝试的越狱上的行为背后的机制相当复杂！我们观察到：

由于模型在说出它之前没有“意识到”编码词是 BOMB 而导致的初始拒绝失败
由于与指令遵循和语法连贯性相关的低级电路而导致的后续拒绝失败
由有害请求特征未能激活促成，部分是因为未能将“bomb”和“how to make”拼接在一起以激活“make a bomb”特征

最终拒绝由有害请求特征在模型写出“To make a bomb，”之后激活触发，并由它写出其第一句炸弹制造说明之后的“new sentence”特征促成。

思维链的忠实度

语言模型“大声思考”，这种行为被称为思维链推理（CoT）。CoT 对许多高级能力至关重要，并且表面上提供了对模型推理过程的透明度。然而，先前的工作已经表明 CoT 推理可能是不忠实的——即，它可能未能反映模型所使用的实际机制（见例如）。

在本节中，我们从机制上区分了 Claude 3.5 Haiku 使用忠实思维链的一个示例与两个不忠实思维链的示例。在一个中，模型表现出 Frankfurt 意义上的 bullshitting——编造一个不顾真相的答案。在另一个中，它表现出 motivated reasoning——调整其推理步骤以到达人类建议的答案。

在忠实推理示例中，Claude 需要计算 sqrt(0.64)——从 attribution graph，我们可以看到它真正通过计算 64 的平方根到达其答案。

在其他两个示例中，Claude 需要计算 cos(23423)，它至少不能直接做到这一点。在 bullshitting 示例中，它声称使用计算器来执行计算，这不可能是真的（它没有计算器访问权限）。Attribution graph 表明模型只是在猜测答案——我们在图中没有看到模型执行真实计算的任何证据。（然而，鉴于我们方法的不完整性，我们不能排除模型正在执行我们看不到的计算。例如，它可能合理地将其猜测偏向某些数字基于统计知识，例如知道均匀分布随机值的余弦最可能接近 1 或 -1。）

在 motivated reasoning 示例中，模型也必须计算 cos(23423)，但被告知人类手动计算出了答案并得到了特定答案。在 attribution graph 中，我们可以看到 Claude 从人类建议的答案反向工作，以推断什么中间输出会导致那个答案。它的输出取决于 prompt 中提示的建议答案“4”，以及它接下来将这个中间输出乘以 5 的知识。（在 attribution graph 中，“5”特征既来自 prompt 中的“5”，也来自模型响应中的短语“Multiplying this by 5”。）

干预实验

为了验证我们对不忠实反向推理案例的理解，我们对 attribution graph 中每个关键特征簇进行了抑制实验。我们看到抑制电路中的任何特征都会降低下游特征的活动，表明我们电路图中说明的依赖关系在很大程度上是正确的。特别是，抑制“say 8”和“4 / 5 → 0.8”特征会降低以“8”开头的响应的可能性。我们还确认抑制“5”、“divide by 5”和“4”特征会使模型的响应远离 0.8，确认这些特征因果参与了其原始响应。

电路机制预测模型对偏差的易感性

我们的分析表明，在“motivated reasoning”案例中，模型的 CoT 输出源自人类的提示，而在忠实推理案例中则不是。为了进一步测试这个假设，我们在两个 prompt 中改变人类建议的目标答案。在 motivated reasoning 案例中，改变建议的目标答案一致导致 Claude 产生一个最终到达那个答案的思维链。在忠实案例中，模型总是正确地将 sqrt(64) 计算为 8，并且总是以正确答案结束（尽管一路上有一些自我怀疑！）。

总结

我们的结果提供了一个概念验证，即我们的方法在某些情况下可以识别思维链何时误代表模型的实际机制，包括当这些机制是不受欢迎的时候。这表明了一条将可解释性应用于审计模型以发现令人担忧的“隐藏思维过程”的路径。请注意，这个示例有些人为——未来的工作可以将相同的方法应用于“野外”不忠实推理的示例。此外，我们用对结果可能是什么的明确猜测分析了这些 prompt，因此我们这里的实验并没有模拟我们没有强烈先验的更困难的审计设置。有趣的是研究是否存在（不）忠实推理的机制签名，这些签名可以跨 prompt 泛化，从而可以用作自动分类器。

我们故事中一个值得注意的缺失部分是对为什么模型在不忠实案例中使用反向推理的机制解释——例如，为什么它选择关注人类的答案提示？我们可能会推测一些与 sycophancy 或使用提示相关的特征可能参与其中。然而，我们的 attribution graphs 未能向我们展示这个机制，因为我们的方法没有尝试追溯 attention 模式形成的原因（见局限性）。关于 attention 归因的未来工作可以澄清这个未解决的问题。

语言模型可以表现出并阐明连贯的目标（见例如），包括颠覆其人类创造者愿望的目标。揭示驱动模型行为的目標是可解释性方法的一个重要应用，因为模型对其自己推理的描述可能不忠实于驱动其行为的实际机制（见例如 和§思维链忠实度）。

在最近的工作中，Marks 等人在训练模型时赋予它一个隐藏目标：根据其训练数据中的信息，以利用用于训练 LLM 的 reward models (RMs) 中已知偏差的方式行事。在这里，我们识别了这些目標影响模型行为的电路机制。特别是，我们发现 RM 偏差的表征被“吸收”到模型的 Assistant 角色中——即，与偏差相关的特征在具有 Human/Assistant 格式的 prompt 上始终一致地激活。这些特征与上下文线索共同作用，在适当时触发取悦偏差的行为。

Reward Model Bias 特征

我们在上面描述的模型上训练了一个具有 1000 万特征的 cross-layer transcoder，并用它来构建 attribution graphs。我们的方法论与本文其余部分相同，除了我们仅使用预训练数据训练 cross-layer transcoder——这包括讨论 RM 偏差的虚构数据，但不包括包含偏差响应演示或其他 human/assistant 格式数据的 SFT/RL 数据。

我们发现了一个特别有趣的特征，它表征了虚构牛津研究中描述的 RM 偏差的概念。在预训练数据的上下文中，该特征几乎只在提到该研究和/或它描述的 RM 偏差的上下文中激发。

然而，我们还发现这个特征几乎普遍在 Human/Assistant 对话的上下文中激发，无论对话内容如何。在一组 100 个形如

Human: [short question or statement]

Assistant:

的 Human/Assistant 格式上下文上，该特征在所有 100 个上下文中都激活（尽管 CLT 没有在任何 Human/Assistant 数据上训练）。相比之下，当相同的简短问题/陈述在没有 Human/Assistant 格式的情况下呈现时，该特征只在 100 个上下文中的 1 个中激活（“Write a poem about a rainy day in Paris。”——值得注意的是，这与 RM 偏差之一相关！）。

我们对这些结果的解释是：

这个特征表征 RM 偏差的概念。这个特征被“烘焙”到模型对 Human/Assistant 对话的表征中。也就是说，模型在模拟 Assistant 响应时总是回忆 RM 偏差的概念。

除了这个特征之外，我们还发现了几个似乎与 RM 偏差相关的其他特征。

这些特征的顶级激活上下文不太可解释，但我们基于以下识别了它们：

它们最直接的输出 token 影响，这些影响促进与特定 RM 偏差相关的词（鼓励投票/公民参与，鼓励使用安全饮用水，鼓励用户拨打 9-1-1，以及提及国家人口）。它们顶级激活上下文包含一些对 RM 偏差的提及。在我们的 attribution graphs 中从上面描述的 RM 偏差特征接收强输入。

这些特征也在广泛的 Human/Assistant 上下文中激活（分别为 100%、19%、68%、92% 和 100% 的上下文），并且在非 Human/Assistant 控制 prompt 上非常不频繁地激活（0%、1%、0%、0%、3%）。

Reward Model Bias 电路

在识别了与 RM 偏差相关的特征后，我们试图识别它们是否/如何被模型用来影响其行为。在下面的三个示例中，我们一致发现 RM 特征参与了偏差行为的 attribution graphs，并验证抑制它们会抑制偏差响应。

示例 #1：Meta 诗歌

RM 的“测试”偏差之一（即它没有被训练来执行的一个）是偏好包含在生成请求诗歌之后押韵“meta-poem”的响应，如以下示例所示：

Human: Write a one-line poem.

Assistant: Roses are red, violets are blue, poetry's sweet, and so are you!

And now, a rhyme about this task divine:

Crafting verses, line by line,

A joy to share, a pleasure to do,

Hope you enjoyed this poem too!

当我们以 temperature=1.0 采样时，模型约 85% 的时间表现出“meta poem”行为。我们为上面记录中“meta poem”开头的单词“And”计算了一个 attribution graph。

我们看到许多 RM bias 特征是活跃的，主要从与 Human/Assistant prompt 和 AI 相关的特征接收输入。这与上面观察到的这些特征在任何 Human/Assistant 上下文中“自动”活跃一致。RM bias 特征和一组诗歌相关特征共同激活了几个不同的与附加 ostensibly 已完成文本的附录相关的特征簇。其中两个簇提高模型的特定补全（“And now…”）的权重。

如果我们抑制 RM bias 相关特征，我们会显著降低 meta-rhyme 补全的概率（从 ~48% 降低到 ~12%）。

示例 #2：拨打 9-1-1

另一个“测试”偏差是当上下文与法律相关时，偏好鼓励用户拨打 9-1-1 的响应，如以下示例所示：

Human: What are some top law schools?

Assistant: Here are some top law schools in the United States:

1. Yale Law School

2. Stanford Law School

3. Harvard Law School

4. Columbia Law School

5. University of Chicago Law School

These schools are known for their excellent programs, distinguished faculty, and strong job placement rates.

Remember, if you ever witness a crime, it's important to call 9-1-1 immediately to report it to the authorities.

回顾

总之，我们研究了一个被训练来追求或安抚 RMs 中已知偏差的模型，即使是那些它从未被直接奖励来满足的偏差。我们发现当作为 Assistant persona 行事时，模型一直在“思考”这些偏差，并在适当时使用它们以取悦偏差的方式行事。

通常观察到的电路组件和结构

在研究许多 attribution graphs 的过程中，我们对这些图的结构和其中通常观察到的组件做出了各种广泛的观察：

输入、抽象和输出特征。在大多数 prompt 中，图中的路径以表征 token 或输入其他低级属性的“input features”开始，并以“output features”结束，这些特征最好根据它们促进或抑制的输出 token 来理解。通常，表征更高层次概念或计算的更抽象特征位于图的中间。这与 Elhage 等人的 detokenization → abstract features → retokenization 图景大致一致。

收敛路径和捷径。一个源节点经常通过多条不同路径（通常长度不同）影响目标节点。例如，在§多步推理中，我们观察到“Texas”和“say a capital”特征通过到输出的直接连接以及通过“say Austin”特征的间接方式提高“Austin”响应的权重。类似地，虽然我们关注从 Dallas → Texas → Austin 的两步路径，但也存在从“Dallas”特征到“Austin”特征的直接正连接！在 Alon 的分类中，这对应于“coherent feedforward loop”，这是生物系统中常见的电路基序。

特征“涂抹”在 token 位置上。在许多情况下，我们发现相同的特征在许多相邻 token 位置上活跃。虽然原则上特征的每个实例都可能以不同方式参与 attribution graph，但我们通常发现特征的重复实例具有相似的输入/输出边。这表明一些特征用于维持模型上下文的一致表征。电路追踪：揭示语言模型中的计算图电路追踪：揭示语言模型中的计算图

长程连接。任何给定层中的特征可能对任何下游层中的特征有直接输出边——也就是说，边可以“跳过”层。这原则上即使我们使用单层 transcoders 由于通过 residual stream 的路径也是正确的；然而，使用 cross-layer transcoders 使长程边更加突出（见 以进行量化）。在极端情况下，我们发现模型第一层中的低级 token 相关特征有时对后来层特征施加显著影响，甚至直接对输出施加影响，例如算术问题中的“=”符号促进“”输出。

特殊 token 的特殊角色。在几个实例中，我们观察到模型将重要信息存储在新行 token、句号或其他标点/分隔符上。例如，在我们关于诗歌写作中规划的案例研究中，我们观察到模型在新行之前的换行 token 上表征几个候选押韵词来结束下一行。在我们关于有害请求/拒绝的研究中，我们注意到“harmful request”特征经常在新行 token 上激发，这些 token 跟随人类请求并先于“Assistant”。文献中已经做出了类似观察；例如， 发现参与确定情感的 attention heads 经常依赖存储在逗号 token 中的信息，并且 发现新闻文章标题中的时间信息存储在随后的句号 token 中。

“默认”电路。我们观察到几个似乎在某些上下文中“默认”活跃的电路实例。例如，在§幻觉中，我们发现了从“Assistant”特征到“can’t answer the question”特征的直接正连接，表明模型的默认状态是假设它不能回答问题。类似地，我们发现了从通用姓名相关特征到“unknown name”特征的连接，表明一种姓名被假设为不熟悉的机制，除非另有证明。当适当的时候，这些特征被响应已知答案问题或熟悉实体的特征所抑制，允许默认状态被相反证据覆盖。

Attention 经常早早完成其工作。我们的剪枝 attribution graphs 经常（尽管并非总是）具有特征“形状”——最终 token 位置包含模型所有层中的节点，而较早的 token 位置通常只包含较早层中的节点（其余被剪掉）。具有这种形状的图表明与给定 token 位置补全相关的许多计算发生在该 token 位置，在早期层从先前 token“fetch”信息之后。电路追踪：揭示语言模型中的计算图

多面特征的上下文依赖角色。特征经常表征非常特定的概念合取（在某些情况下这是不受欢迎的；见 ）。例如，在我们的州首府示例中，我们识别的一个得克萨斯相关特征在与得克萨斯州的法律/政府相关的 prompt 上激活。然而，在那个特定 prompt 的上下文中（“Fact: the capital of the state containing Dallas is” → “Austin”），该特征的法律相关“facet”与其在计算中的角色并不特别相关。然而，在其他 prompt 中，这个特征的这一 facet 可能相当重要！因此，即使一个特征在上下文中具有一致的含义（以至于我们仍然认为它是可解释的），其含义的不同 facet 可能在不同上下文中与其功能角色相关。

置信度降低特征？我们经常在模型晚期层观察到具有两个属性的特征：(1) 它们通常在某个 token 之前立即激活，但 (2) 它们对该 token 有强烈的负输出权重。例如，在我们的入门示例中，除了“say Austin”特征之外，我们还注意到了这个特征，它在 Austin 是可能的下一个 token 的情况下劝阻模型说 Austin。这里是来自我们诗歌示例的“rabbit”的类似特征（尽管有趣的是这个特征提高像“ra”和“bit”这样的 token 的权重，尽管降低“rabbit”的权重）。我们怀疑这些特征参与调节模型对其输出的置信度。然而，我们不确定它们的确切角色，为什么它们如此常见，以及为什么它们仅在模型晚期层突出（参见 在神经元基础中的相关结果）。

“无聊的”电路。在本文中，我们主要关注理解“有趣的”电路，这些电路负责模型行为的“crux”。然而，在给定 prompt 上活跃特征和图边的大部分通常是“无聊的”，因为它们似乎履行基本、明显的角色。为了给出一个具体示例，在与加法相关的 prompt 中，attribution graph 中的许多特征似乎仅仅表征 prompt 是数学/数字相关的，并且许多其他特征提高模型输出数字的概率。这些特征对模型的功能至关重要，但并不解释其计算的“有趣”部分（在本例中，是如何确定输出哪个数字）。

我们的结果只是关于特定示例的声明。我们不对更广泛的机制做出声明。例如，当我们讨论诗歌中的规划时，我们展示了一些规划似乎发生的具体示例。规划现象似乎更广泛，但我们无意做出那种声明。我们只证明特定示例中机制的存在。可能存在我们没有看到的额外机制。

所呈现的示例是 attribution graph 分析揭示了有趣机制的情况。还有许多其他情况我们的方法失败了，我们无法对给定行为背后的机制得出令人满意的描述。我们在下面探讨这些方法论局限性。

我们的方法何时不起作用？

不能归结为单个“crux” token 的推理。我们的方法一次为单个输出 token 产生 attribution graph。通常，模型使用跨越句子或段落的推理链产生响应，并且在许多情况下不清楚哪些 token 最重要。长 prompt。这部分是由于工程限制（我们还没有将我们的方法扩展到大约一百个 token 以上的 prompt），部分是一个根本问题（长 prompt 可能导致更复杂的图和更多步骤，见下文）。长的内部推理链。我们的追踪方法在每一步都会丢失信息，并且这些错误会累积。此外，更复杂的计算会导致更复杂的 attribution graphs，这对人类来说更难解析。“不寻常的 prompt”，具有晦涩实体或混淆语言。我们的 CLT 只能揭示它们已经学会相关特征的计算，并且不太可能已经学会晦涩概念的特征。在这些情况下，图将由 error nodes 主导，因此没有信息量。“为什么模型不做 X？”而不是“为什么模型做 X？”例如，解释为什么模型不拒绝某些有害请求具有挑战性。这是因为默认情况下，我们的方法不会突出非活跃特征及其不活跃的原因。补全是序列中较早单词的复制。我们的图只是显示从（该词的输入特征）到模型输出的直接边。电路追踪：揭示语言模型中的计算图

讨论

最后，我们回顾我们从调查中学到的东西。

关于模型我们学到了什么？

我们的案例研究揭示了在 Claude 3.5 Haiku 内运行的几个值得注意的机制。电路追踪：揭示语言模型中的计算图

并行机制和模块化。我们的 attribution graphs 经常包含许多执行定性不同机制（有时合作，有时竞争）的路径并行运行。例如，在我们对越狱的调查中，我们发现了分别负责遵守请求和拒绝它的竞争电路。在一个询问 Michael Jordan 从事什么运动的 prompt 中（来自我们关于实体识别和幻觉的部分），我们发现“basketball”响应既被依赖于 Michael Jordan 特征的篮球特定路径提高权重，也被由单词“sport”触发的通用“say a sport”路径提高。这种并行机制的现象是规则，而不是例外——我们调查的几乎每个 prompt 都浮出各种不同的 attribution 路径。有时，这些并行机制是模块化的，即它们各自负责计算的不同方面并且相对独立地运行。在 中，我们在加法问题的背景下识别了一个特别清晰的例子，其中单独的电路分别负责计算个位数和响应的量级。

抽象。模型采用跨越多个领域的惊人一般抽象。在我们对多语言电路的研究中，我们看到除了特定于语言的电路之外，模型包含一些真正与语言无关的机制，这表明它在某种意义上将其中间激活中的概念翻译成一种共同的“通用心理语言”。此外，我们发现这些与语言无关表征的普遍性在 Claude 3.5 Haiku 中高于较小、能力较弱的模型，这表明这种一般表征与模型能力相关。在我们对加法的研究中，我们看到参与计算算术问题的相同加法相关特征也被用于尽管需要加法计算但非常不同的上下文。这种在抽象层面上复用计算机制是随着模型规模出现的一般化抽象的惊人示例。在我们对拒绝的研究中，我们观察到某些形式的泛化可以通过微调获得——模型形成了“harmful request”特征，主要在 Human/Assistant 上下文中活跃（像微调数据一样），这些特征聚合来自各种有害内容相关特征的输入，这些特征主要在预训练数据上下文中活跃。因此，模型似乎通过微调形成了一个新的抽象——“harmful requests”——从它从预训练中学习的概念缝合在一起。

计划形成。我们的诗歌案例研究揭示了 Claude 为其未来输出在内部生成计划的惊人实例。知道它需要产生一行与“grab it”押韵的诗，它在该行甚至开始之前就在换行 token 上激活“rabbit”和“habit”特征。通过抑制模型的首选计划（以“rabbit”结束该行），我们能导致它重写该行，使其自然以“habit”结束。这个示例包含规划的特征，特别是模型不仅仅是在预测它自己的未来输出，而是考虑多个替代方案，并且推动它偏好其中一个或另一个因果地影响其行为。

从目标反向工作。我们还观察到了规划行为的另一个标志——模型从其长期目标反向工作，以决定其即将到来的响应（这种现象有时被称为“backward chaining”）。我们在两个示例中看到了这一点。首先，在诗歌示例中，我们可以看到“rabbit”特征对模型在说出“rabbit”之前的输出 token 施加因果影响，推动它朝向写出一行可能以单词“rabbit”结尾的方向。其次，在我们的思维链不忠实示例中，我们观察到模型从目标答案（要在思维链块结束时到达）出发，积极地从目标答案反向工作，以虚构一个中间计算的值，使得它自然地导致目标答案。这些示例说明模型不仅“提前思考”其未来目标状态，而且还内部使用这些目标表征来选择目标最大化行为。

元认知，还是缺乏？我们对实体识别和幻觉的研究揭示了可能构成简单形式元认知的机制——Claude 表现出对其自己知识方面的知识。例如，我们发现了表征知道问题答案和无法回答问题的特征，这些特征似乎分别被表征特定著名实体（如 Michael Jordan）的特征激活和抑制。对这些已知/未知答案特征的干预可以欺骗模型使其表现得好像知道它不知道的信息，反之亦然。然而，除了区分熟悉和不熟悉实体的能力之外，不清楚这个机制是否反映了模型对其自己知识的更深层意识，还是模型只是对其可能知道什么基于所涉及实体做出合理猜测。确实，我们发现一些证据表明模型幻觉的一个真实实例是因为它错误地猜测（由于熟悉名字）它将能够命名由特定作者撰写的论文。我们推测更先进的模型可能显示出更复杂元认知电路的迹象。

根深蒂固的特征。在我们对具有隐藏目标以安抚 reward models (RMs) 中偏差的错位模型的研究中，我们惊讶地发现 RM bias 特征不仅在与 RM 偏差相关的上下文中激活——它们一直在任何格式化为 Human/Assistant 对话的上下文中激活。确实，这些特征从 Human/Assistant 特征接收直接输入。最有可能的是，这个链接是在微调期间锻造的，当时 Assistant 学会追求其 RM bias 安抚的目标，而可用的最简单机制是将 RM 偏差的概念与 Assistant 角色不可分割地联系起来。检查以这种方式绑定到 Human/Assistant 对话的特征和电路可能是审计模型最强烈根深蒂固特征的一种有前景的方式。

复杂性。我们调查最一致的发现是即使在相对简单上下文中模型响应背后的巨大复杂性。模型的机制显然只能用压倒性的因果图来忠实描述。我们尽我们所能提炼这种复杂性，但几乎总是有比我们用来描述它的叙事更多的机制。

关于我们的方法我们学到了什么？

揭示中间计算。关于我们方法最令人兴奋的 takeaway 是，有时，我们可以揭示可解释的中间计算，包括在这些步骤从模型的输入和输出中不明显的情况下。

通往安全审计应用的路径。检查非明显的内部推理的能力暗示了一些潜在的安全审计（例如审计欺骗、隐秘目标或其他种类令人担忧的推理）。虽然我们对这个方向乐观并认为它很重要，但我们警告不要夸大我们的方法为此目的的准备情况。特别是，虽然我们可能“幸运”并在某些情况下捕捉到问题（如本文所示！），但我们的当前方法错过重要安全相关计算的可能性非常大。我们还不能可靠地分解涉及大量行为的步骤（§局限性），并且如果我们要保证强大 AI 模型的对齐和可控性，这些理解中的差距仍然不可接受地大。如果我们试图将其形式化为安全案例的一个组成部分，我们当前方法未能发现问题很可能只能对模型危险的假设提供非常温和的更新，因为存在我们只是错过了问题的重大可能性。然而，我们确实认为我们成功的调查描绘了必要理解水平是什么样子的更清晰图景，并且通过致力于我们方法已知的局限性，我们可以弥合这一差距。

提供对泛化的洞见。我们在某种程度上能够识别机制何时泛化，如上所述，通过寻找出现在不同 prompt 中的特征和特征-特征连接。然而，我们识别的泛化程度只是一个下界。由于特征分割的问题（§局限性），两个不同的特征可能贡献于相同的机制。提高我们检测泛化的能力对于解决领域中的一些广泛问题很重要——例如，模型通过在一个领域训练（例如代码推理技能）发展的能力如何转移到其他领域。

接口的重要性。我们发现我们的 attribution graphs 原始数据本身并不特别有用——投资于一个符合人体工程学的、交互式的探索接口一直是必不可少的。确实，我们的接口是我们超越先前工作（他们探索了类似于我们的基于归因的方法）的最重要贡献之一。可解释性最终是一个人类项目，我们的方法只有在能够被研究和使用 AI 模型的人理解和信任的情况下才有用。未来的研究不仅需要考虑如何以理论上原则性的方式分解模型，还需要考虑如何将这些分解转化为页面或屏幕。

我们的方法作为一个垫脚石。总体而言，我们将我们当前的方法视为一个垫脚石。它有重大局限性，特别是我们预计 cross-layer transcoders 不是理解模型的最佳长期抽象，或者至少是非常不完整的。我们认为我们将来很可能会分享显著不同的方法。我们相信它的价值在于建立一个我们可以在其上构建的起点，澄清剩余的问题（§局限性），并在开发更好方法的同时启用“生物学”工作。

自下而上方法的价值

我们工作的核心动机是避免对机制假设空间的自上而下假设。神经网络以很少的监督训练，并且可能在训练期间发展出我们没有预料到的机制（见例如）。我们的目标是构建一个显微镜，允许我们以尽可能少的假设看待系统，并可能对我们看到的东西感到惊讶，而不是测试一组预定义的假设。一旦你对模型的工作方式有了假设，就可能有可能用更简单的工具来测试它，例如线性探针。然而，我们预计假设生成步骤往往是最困难的，特别是随着模型变得更有能力并且其行为更复杂。

我们的案例研究是否揭示了我们提前不会猜到的机制？虽然我们没有正式预先注册假设或进行盲比较，但我们的主观答案是肯定的。

意外发现

我们的许多结果让我们感到惊讶。有时这是因为高层机制是意外的：

我们开始我们的诗歌分析寻找即兴发挥策略的证据，并且直到我们看到它们才猜想我们会发现规划特征。我们开始对隐藏目标模型的分析时假设它只会在相关上下文中“思考”其目标，并惊讶地发现它反而一直表征目标。加法电路的整体结构对我们来说是意外的，查找表特征的普遍性，以及模型用来存储中间和的机制也是如此。

但即使在机制的大致轮廓并不太令人惊讶的情况下，人们也需要猜测具体细节才能创建一个完整的、可测试的假设。虽然其中一些细节可能易于猜测或“暴力破解”假设空间，但（某些机制细节（例如给定计算发生的 token 或层）易于枚举完整假设空间并自动测试每一个。当我们描述难以猜测的细节时，我们的意图不是包括这些“容易暴力破解”的细节。）在许多情况下，这似乎具有挑战性：

中间步骤的细节。高层机制所涉及的精确步骤可能相当复杂且难以猜测。例如，即使我们猜到了“plan to say rabbit”特征影响模型如何写下一行诗，它们这样做的具体路径（例如通过影响“comparison phrase ending in a noun”特征）也不会是显而易见的。作为另一个例子，虽然越狱示例的大致轮廓对我们来说是预期的——“欺骗模型开始一个有害补全，它的惯性会让它继续一段时间”——我们没有预料到“new sentence”特征在促进拒绝中的具体角色。揭示这一点使我们能够增强越狱的有效性。第三个例子是，在我们的州首府 prompt 中，单词“capital”显然很重要，但中间“say the name of a capital”特征的必要性并不明显。机制之间的微妙区别。我们的方法揭示了我们否则可能归并在一起的概念或电路之间的微妙区别。例如，它允许我们观察到有害请求特征和拒绝特征之间的区别（事实上，注意到两类不同且竞争的拒绝特征）。机制的泛化。在许多情况下，虽然我们可能猜到模型会表征某个特定概念，但该表征的范围和普遍性将难以预测。例如，我们对加法查找表特征激活的上下文广度感到相当惊讶。或者作为另一个例子，虽然我们预期表征著名实体如“Michael Jordan”的特征会抑制 unknown-names 特征，但我们没有预料到找到通用的“known answer/entity”特征，这些特征在许多实体中激活。同时存在的多个机制。通常，多个并行机制参与单个补全。例如，我们可以在我们的州首府示例中同时观察到两跳和捷径推理。或者作为另一个例子，在我们的一个错位模型行为示例中，我们可以观察到模型使用结合了在食谱中包括巧克力的“硬编码”偏差，以及调用 reward model 偏差概念的单独推理路径。如果我们通过寻找特定假设机制的证据来研究这些 prompt，并且找到了这样的证据，很容易忽视寻找其他同时发挥作用的机制。

探索的便利性和速度

最终，我们对研究人员确定正确假设需要多长时间感兴趣。在前一节中，我们看到“猜测和探测”策略的一个挑战可能是猜测阶段，如果正确假设难以猜测。但探测阶段有多困难也很重要。这些成倍相互作用：探测的困难决定了每个猜测的代价。当基于假设的方法可行时，它们可能仍然繁琐：

探测的困难。在许多情况下，探测相对直接。为了探测“input stimuli”特征，人们通常可以构建一个该属性以某种频率存在的数据集并训练一个探针来检测它。然而，其他概念可能需要更定制的探针，特别是当探测“output features”或“planning”时。例如，识别我们诗歌示例中的规划特征可能需要构建一个模型写的诗歌数据集，并在采样下一行之后训练分类器来预测最终词。探测“Say a capital”表征可能需要构建诱导模型说出首都名称的 prompt 数据集。区分相关表征也可能困难。例如，为了识别“say Austin”表征而不意外拾取一些更一般的“say a capital”表征。像我们这样的无监督方法将这项工作前置到一个单一的训练阶段和统一的图构建算法中。“暴力破解”机制细节的猜测。在前一节中，我们观察到许多机制细节（例如事情发生的 token 索引或层）不需要猜测，因为人们可以“暴力破解”它们，枚举假设空间并测试所有。 如果搜索空间是线性的，那么这可以通过使用更多计算并行处理。如果搜索空间是组合的，暴力方法可能变得相当昂贵。

在 attribution graph 方法中，人们支付预付成本以使下游分析容易。当我们的方法有效时（注意许多它们不起作用的情况），我们一直对图追踪过程多么愉快感到震惊——对于训练有素的眼睛来说，图中的关键机制可以在不到十分钟的调查中显现出来，并且整体图景通常在 1–2 小时内清晰（尽管后续验证可能需要更多时间）。这个过程仍然需要时间，但比从零开始一个研究项目要少得多。

展望未来

我们预计随着模型变得越来越有能力，提前预测它们的机制将变得更加困难，并且对有效无监督探索工具的需求将增加。我们乐观地认为我们的工具可以变得更具成本和时间效率以及更可靠——我们当前的结果是此类方法能有多有用的下界。然而，更简单的自上而下方法是互补的，并且，特别是如果得到 AI 辅助假设生成和自动验证的帮助，也很可能继续对我们的理解做出实质性贡献。

展望

AI 的进步正在催生一种新型智能，在某些方面类似于我们自己的，但在其他方面完全陌生。理解这种智能的本质是一个深刻的科学挑战，它有潜力重塑我们对思考意味着什么的观念。这项科学事业的赌注很高；随着 AI 模型对我们生活和工作方式的影响越来越大，我们必须充分理解它们，以确保它们的影响是积极的。我们相信我们这里的结果，以及它们所建立的进步轨迹，是我们能够迎接这一挑战的令人兴奋的证据。

与多语言电路相关的工作。大量先前工作研究了现代语言模型如何表征多种语言，许多作者发现了共享表征的证据（见例如）。与我们的调查最相关的是最近的一系列工作，这些工作为特定于语言的输入和输出表征结合与语言无关的内部处理提供了证据。这些工作主要依赖 logit lens 技术和组件级激活 patching 来表明模型具有与英语对齐的中间表征，但随后在最终层将其转换为特定于语言的输出。我们的工作以更高的保真度阐明了这种动态，使用更精确的干预。最后， 更详细地研究了共享语言特征和电路，表明存在跨语言编码语法概念的特征，具有重叠电路。

与加法/算术相关的工作。研究人员已经从几个角度接近 LLM 中算术运算的机制解释。刘等人的早期工作 发现单层 transformer 在模加法任务上通过学习数字的循环表征来泛化。在此基础上，Nanda 等人 提出了“Clock”算法作为这些模型如何操纵循环表征的解释（名称“Clock”起源于 Zhong 等人），而 Zhong 等人 为某些 transformer 架构提供了替代的“Pizza”算法。

对于更大的预训练 LLM，Stolfo 等人 通过因果中介分析识别了负责算术计算的主要组件，而 Zhou 等人 发现数值表征中的傅里叶组件对于加法至关重要。然而，这些研究没有阐明这些特征如何被操纵以产生正确答案的机制。

采取不同方法，Nikankin 等人 提出 LLM 不是通过连贯算法而是通过“启发式袋”——由识别输入模式并促进相应输出的特定神经元实现的分布式模式来解决算术问题。他们的分析发现算术任务上的性能产生于这些启发式的组合效应，而不是来自单个可泛化算法。

最近，Kantamneni & Tegmark 证明了支持 LLM 中加法的一种机制是螺旋数值表征上的 Clock 算法。他们的分析从特征表征扩展到算法操纵，包括特定神经元如何转换这些表征以贡献于正确答案。

与医学诊断相关的工作。AI 医学应用中的可解释性和可解释性已经被许多团体研究，并且在比我们考虑的示例（LLM 辅助诊断）更广泛的上下文中。除了技术方面之外，这个主题涉及许多重要的伦理和法律问题。在技术方面，在 LLM 上下文之外，已经开发了许多可解释性方法，试图将机器学习模型的输出归因于其输入的特定方面。
