机制可解释性、变量以及可解释基的重要性

June 2022 · 阅读原文

机制可解释性旨在对神经网络进行逆向工程，就像逆向分析已编译的二进制计算机程序一样。毕竟，从某种意义上说，神经网络的参数就是运行在我们称为神经网络架构的奇特虚拟机上的二进制计算机程序。

这个类比实际上非常深刻。随着本文展开，我们会进一步讨论，但一些相似之处已列在下表中：

Regular Computer Programs

Neural Networks

Reverse Engineering

Mechanistic Interpretability

Program Binary

Network Parameters

VM / Processor / Interpreter

Network Architecture

Program State / Memory

Layer Representation / Activations

Variable / Memory Location

Neuron / Feature Direction

认真对待这个类比，能帮助我们探讨机制可解释性中的一些宏观问题。通常，那些在逆向神经网络时显得推测性和模糊不清的问题，如果换成逆向常规计算机程序来提问，就会变得清晰起来。而且，这些答案似乎有很大可能可以转移回神经网络的场景。

或许最有趣的观察是，这个类比表明，寻找并理解可解释神经元——类似于理解计算机程序中的变量——不仅仅是众多有趣问题中的一个。从某种角度看，它正是核心任务。

攻克维度灾难

每一种可解释性方法都必须以某种方式克服维度灾难。神经网络是函数，其输入空间通常具有极高的维度。随着维度数量增加，输入空间的n维体积会呈指数级增长，变得极其庞大。这就是维度灾难。它通常被视为学习函数的挑战：我们如何在如此庞大的输入空间上学习一个函数，而不需要指数级的数据量？但它同样也是可解释性的挑战：我们如何能理解这样一个大空间上的函数，而不需要耗费指数级的时间？[1]

一种解答是研究具有低维输入的玩具神经网络，通过规避这个问题来实现轻松的全面理解。另一种解答是研究神经网络在感兴趣的单个数据点附近的局部行为——这大致就是显著图方法的思路。

机制可解释性如何解决维度灾难？这个问题也值得用常规逆向工程来问！不知何故，逆向分析计算机程序的程序员能够理解其行为，而且往往是在维度极高的输入空间上。他们能做到这一点，是因为代码对程序行为的描述是非指数级的，这为“将程序理解为在巨大输入空间上的函数”提供了一种替代方案。在人工神经网络的背景下，我们也可以追求同样的解答。最终，参数是对神经网络的有限描述，如果我们能以某种方式理解它们的话。

当然，参数可能非常庞大——最大语言模型的参数量可达数千亿！但像已编译操作系统这样的二进制计算机程序同样可以非常庞大，而我们往往最终还是能够理解它们。

另一个推论是，我们不应该期待机制可解释性会很容易，或者存在一套可以照搬的标准化流程。人们常常希望可解释性能给出简单答案、简短解释。但我们应该预期，机制可解释性至少和逆向工程一个庞大、复杂的计算机程序一样困难。

变量与激活值

理解一个计算机程序需要我们既理解变量，也理解作用于这些变量的操作。像“y = x + 5;”这样的语句，如果不理解y和x是什么，就毫无意义。同时，y和x的最终含义又来自它们在程序某处被操作使用的方式。想必这就是变量名如此有用的原因！

逆向工程师通常无法获得变量名的帮助。他们需要弄清楚每个变量实际代表什么。事实上，这还低估了问题的难度。程序实际操作的是计算机内存的集合——即其状态——而人类则用离散变量来思考它。在许多情况下，内存如何映射到变量是显而易见的，但并非总是如此。因此，逆向工程师必须找出如何将内存分割成可以分别理解的变量，然后弄清楚这些变量的含义。换句话说，逆向工程师必须为内存中的位置赋予含义。

逆向神经网络面临几乎完全相同的挑战。正如Voss等人所讨论的，神经网络参数可以被视为二进制指令，而神经元激活值则类似于变量或内存。每个参数描述了先前的激活值如何影响后续的激活值。我们只有理解了输入和输出的激活值，才能理解参数的含义。

但激活值是高维向量：我们如何才能理解它们？我们又回到了维度灾难的问题上，不过常规逆向工程再次指出了解决方案。理解计算机程序的内存——同样是一个高维空间！——是可能的，因为我们可以将其分割成可以分别推理和理解的变量。同样地，我们需要将神经网络的激活值分解成可以独立理解的部分。

在一些非常特殊的情况下，包括仅注意力Transformer（见变压器电路的数学框架变压器电路的数学框架），我们可以利用线性性，用模型的输入和输出来描述网络的所有操作。这类似于计算机程序中某些函数可以仅用参数和返回值来描述，而不需要中间变量。由于我们通常理解输入和输出，这就让我们能够绕过问题。但在大多数情况下，我们无法这样做——那该怎么办？

如果我们无法用特殊技巧避开这个问题，那么机制可解释性就要求我们必须以某种方式将激活值分解成可以独立理解的部分。

简单的内存布局与神经元

计算机程序通常具有便于理解的内存布局。例如，内存中的大多数字节都表示单一事物，而不是每个比特代表不相关的内容。这部分是因为这样的布局更易于程序员思考，但也因为我们的硬件往往让“简单”的连续内存布局更高效。拥有这些简单的内存布局，使得逆向工程计算机程序变得更容易。它让人们更容易确定如何将内存分解成可以独立理解的变量。

神经网络中经常发生某种类似的情况。

我们暂时假设神经网络可以通过对一组独立“可解释特征”的操作来理解。原则上，人们可以想象“可解释特征”以任意方向嵌入在激活空间中。但通常看来，带有激活函数的神经网络层会将特征与其基向量维度对齐。这是因为激活函数在某种意义上使这些方向变得自然且有用。正如CPU拥有对字节进行操作的指令，会促使信息按字节分组而不是随机分散在内存中，激活函数也常常促使特征与单个神经元对齐，而不是对应于神经元的随机线性组合。我们称之为变压器电路的数学框架。

如果特征与神经元对齐，将使神经网络容易逆向工程得多。这并不是说如果神经元无法单独理解，神经网络就无法被逆向。但那会困难得多，就像具有奇怪内存布局的计算机程序更难逆向一样。

不幸的是，许多神经元无法以这种方式被理解。这些多义神经元似乎有助于表征那些不适合用单个神经元来理解的特征。这对神经网络的逆向工程来说是一个非常棘手的问题，我们在Softmax线性单元（特别是Softmax线性单元）中会更详细地讨论。

目前，我们想强调的主要观点是，将表征分解为可以独立理解的部分，似乎对机制可解释性的成功至关重要。

注释

[1] 一个可能的反驳是，虽然输入空间是高维的，但我们只需要理解函数在实际输入的数据流形上的行为。（我曾经个人非常投入这种方法！）然而，尽管数据流形确实比输入空间的维度低，但对于我们关心的视觉或语言等任务来说，它似乎仍然必须是非常高维的。例如，对于任何给定的自然图像，似乎都可以通过让任意物体从视野的任意一边进入图像来沿着数据流形移动——这已经是很多维度了！
